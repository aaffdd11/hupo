# 终端 UI 设计（L1）：悬浮聊天

> 目标形态（主人原话）：
> 「我的聊天功能，是**悬浮于一切之上**的。最小化的时候，是一个聊天窗口，在最底下。
>  聊天的时候，聊天内容会**打开覆盖**。」

本文是 L1 的界面设计稿，配套可视化在 `docs/ui-terminal.html`（可切档位与场景）。
**没动代码**，所有数值都是从现有实现里量出来的（`apps/mobile/lib/screens/chat_screen.dart`），改动点单独标出来。

---

## 〇、一句话

**聊天是一条永远浮在最上面的层。** 收起时它是贴底的一条（抓手 + 最新一句 + 输入条）；
一开口就展开、把下面的东西盖住；但**四边永远留一圈边距**——所以"盖住"不等于"铺满整块屏幕"。

---

## 一、先看冲突：现在的 z 序和这条要求是**反的**

`chat_screen.dart` 的 `build()` 里，Stack 自下而上是：

```dart
Stack(children: [
  Positioned.fill(child: GestureDetector(... AppDesktop ...)),   // ① 桌面
  Positioned(left: 10, right: 10, bottom: 10, child: _floatingPanel(...)), // ② 聊天
  if (open != null) Positioned.fill(child: MiniAppContainer(...)), // ③ 小程序 —— 盖在最上面
]);
```

⇒ **打开一个小程序，会把聊天整个盖住。** 而主人的要求是反过来的：聊天在一切之上。

这不是 bug，是上一版"应用像 APP 一样盖上来"的设计残留。本稿的核心改动只有一句话：

> **把聊天浮窗挪到 Stack 的最上层（小程序之上）**，小程序改为"在聊天下面保持存活"。

---

## 二、层级与 z 序（新）

```
（最上）
  ④ 开发者卡片        仅 dev 模式；画在浮窗**之上**，浮窗按**量出来的卡片高度**让位
  ③ 聊天浮窗          ← 永远在最上，永远在；收起/半开/最大化三档
  ② 小程序容器        被盖住时【不销毁、不重建】，只是退到后面
  ① 桌面 / 背景        点它 = 点浮窗外面 = 收起聊天
（最下）
```

三条不可破的规则：

| # | 规则 | 为什么 |
|---|---|---|
| **Z1** | 聊天浮窗**永远**在 z 序最上，任何页面（含小程序）都不能盖住它 | 主人的原话：悬浮于一切之上 |
| **Z2** | 被盖住的小程序**不销毁、不重建、不 reload** | 它可能是 H5/WebView（L1 要支持小程序）。"被盖住"不等于"被杀"，reload 会丢用户正在做的事 |
| **Z3** | 盖住不是铺满：四边永远留着边距（左 10 / 右 10 / 下 10 / 上 12） | 留着边缘才看得出"它浮着"、"下面还有东西" |

> Z2 的落地提醒：Flutter 侧先保持 `MiniAppContainer` 挂载（`Offstage` / `IndexedStack`），
> **只是把 Ticker 关掉省电**（`TickerMode(enabled: false)`）；等 H5 运行时接进来时，
> 同一个 slot 里放的 WebView 也**不允许 reload**。

## 三、三档高度与触发规则

### 三档（数值沿用现有实现，它们是量出来的）

| 档 | 高度 | 里面有什么 |
|---|---|---|
| **收起** | `124px`（= 抓手 14 + 标题行 32 + 输入条 + 内边距） | 抓手、最新一句话、（忙碌转圈）、（任务小标）、输入条 |
| **半开** | 屏幕高 50% 附近 | 消息列表 + 输入条 |
| **最大化** | `maxH − 上12 − 下10`（≈ 铺满但四边留缝） | 同上，列表更高 |

高度用**系数**表达：`h = 124 + (maxH − 12 − 10 − 124) × factor`，`factor ∈ {0, 0.5, 1}`。

### 谁让谁（触发规则）

| 事件 | 结果 | 备注 |
|---|---|---|
| 用户按下发送 | → **最大化** | 发就拉满 |
| 助手**开口说话**（有新的一条调度器消息） | → **最大化** | 现状已实现，且**包括它主动开口** |
| 只有 `status` 变化（thinking / working） | **不动** | 状态不是"开口"；否则每次状态跳变都会抽动窗口 |
| 用户点浮窗外面 / 点桌面空白 | → 收起 | 现状已实现 |
| 用户双击抓手 | 收起 ⇄ 回到上次档位 | 现状已实现 |
| **打开一个小程序** | → 聊天**自动收起**（把屏幕让给小程序），但**仍在最下面那条** | 新规则：不消失、不遮住小程序内容（见 §四） |
| **小程序开着时助手主动开口**（任务完成 / 打断） | → 聊天**升起覆盖**小程序 | 这正是"覆盖"的主场景 |
| 400ms 内的连续触发 | 合并成一次 | 防抖：助手连发多段不该让窗口抖 |

## 四、小程序 × 聊天：共存规则（本文最重要的一节）

这是"悬浮于一切之上"和现有实现的真正分歧点，必须逐条定死。

### 4.1 收起时：**不许压住小程序里可点的东西**

底部那条浮在小程序之上，所以小程序的内容要**为它让位**：

```
┌──────────────────────────┐
│  小程序内容（可滚动）        │
│                          │
│  ┌────────────────────┐  │  ← 小程序内容整体抬高：
│  │ 小程序最后一个按钮     │  │     contentPadding.bottom
│  └────────────────────┘  │    = 124 + 下边距(10)
├──────────────────────────┤  ← 这条是聊天的收起态，压在上面
│ ═══ 抓手                 │
│ 🎙 最新一句话      ⏱1 ⚙  │
│ [说点什么            ↑]  │
└──────────────────────────┘
```

- **内容内缩**（padding）而不是简单覆盖：否则小程序最后一行永远点不到。
- 同时给列表加**滚动安全区**：滑到底时最后一条能停在浮窗上沿，
  用户**看得见"它浮在上面"**——但要保证最后一个可点元素不被压住。

### 4.2 展开时：小程序被盖住，并且要**看得出来被盖住了**

不是简单遮住，而是让被盖的那层"退让"，一眼就知道上面还有一层：

| 效果 | 数值 |
|---|---|
| 压暗 | 黑色 `alpha 0.35` 覆盖在小程序层上（不遮住聊天） |
| 轻微缩小 | `scale 1.0 → 0.98`，`origin: bottomCenter` |
| 圆角加大 | 小程序层圆角 `12 → 16` |
| 时长 | `180ms · easeOutCubic` |

### 4.3 半开时：露出来的那半**可以点，但点是"收起"**

- 点小程序**可见区域** = 点浮窗外面 = **收起聊天**，且**不把这次点击传给小程序**。
  理由：半开状态下用户看到小程序的那半块，第一反应是"我想回到小程序"，
  而不是"我要点某个按钮"——把点击解释成"收起"更符合意图，也避免误触。
- 小程序**完全可见时**（聊天收起），它的按钮正常响应。

### 4.4 状态保持

- 小程序**被盖住期间照常运行**（不许 pause 逻辑、"被盖住"≠"退到后台"），只关 Ticker 省电。
- 从盖住回到可见，**不许重建**：滚动位置、表单内容、正在进行的请求都要还在。

## 五、手势优先级（写死，避免打架）

| 手势 | 命中层 | 结果 |
|---|---|---|
| 竖向拖抓手 / 标题行 | 聊天 | 改高度（跟手，松手吸附） |
| 甩（速度 >650px/s） | 聊天 | 下甩收起 / 上甩拉满 |
| 双击抓手 | 聊天 | 收起 ⇄ 上次档位 |
| 点浮窗**内部** | 聊天 | 无（`HitTestBehavior.opaque` 挡住，不许漏到下面） |
| 点**收起态底部条** | 聊天 | 展开到上次档位 |
| 点桌面空白 | 桌面层 | 收起 |
| 点小程序可见区域（聊天半开时） | 聊天（拦截） | 收起聊天，**不穿透** |
| 点小程序按钮（聊天收起时） | 小程序 | 正常交互 |
| 键盘 Esc（桌面/网页） | 全局 | 收起 |
| 键盘 Cmd/Ctrl+K | 全局 | 聚焦输入框 |

> ⚠ 现有实现里"点浮窗自己不该有任何反应"是靠 `HitTestBehavior.opaque` 挡的
> （注释在 `_panelBody`）。这条**必须保留**：`deferToChild` 挡不住，点空白会漏到桌面。

这样既不破坏 124 这个量出来的高度，又满足可点性。

## 八、三种屏幕形态

客户端是 Flutter（手机 / 桌面 / 网站），浮窗在三处的规则：

| 形态 | 宽度 | 浮窗 | 理由 |
|---|---|---|---|
| **手机竖屏** | < 600 | 左右各留 10，跟随屏宽 | 现状 |
| **手机横屏 / 小窗** | 600–900 | 同上，但**最大宽 720 居中** | 横屏里聊天行长过宽会难读 |
| **桌面 / 网页** | > 900 | **居中，最大宽 760**；收起条同样居中 | 一行 1400px 的文字读不了；桌面也要"浮"的观感 |

**不做侧栏 / 停靠**：主人明确要"打开覆盖"，所以宽屏也只是限宽居中，不改语义。

## 九、状态与文案

| 状态 | 界面 | 文案 |
|---|---|---|
| 空（还没有消息） | 收起条显示"助手"；展开显示一句引导 | **不许写**"你好，我能帮你做什么"——人格硬规则禁止留客式追问 |
| 通着 | 正常 | — |
| **服务重启中** | 整块**抽掉颜色**变灰（`ColorFilter.matrix` 亮度矩阵，不是调透明度）+ 罩"正在恢复连接…" + `IgnorePointer` **不可触达**（看得见、点不动，输入的字不丢） | 「正在恢复连接…」 |
| 恢复后 | 自动变回，出现一句 | 「我已经升级好了。」 |
| 有任务在跑 | 标题行小标 `⏱N`（**收起态也在**） | 不显示百分比（伪精确） |
| 发送失败 | 气泡留在时间线上 + 可点重试（`messageId` 保证幂等不重发） | 保留原话 |
| 截断 / 失败收尾 | 作为**正常气泡**显示（协议已有） | 「这条我没能给出结论，你再说一次…」 |
| 助手主动打断 | 升起覆盖（含小程序场景） | 「对了，我打断一下，前面那件事做完了」 |

## 十、动效

| 动效 | 时长 / 曲线 | 原则 |
|---|---|---|
| 档位切换 | 200ms · easeOutCubic | 已经很快，不再加快 |
| 拖拽期间 | **0ms 跟手** | 手指按下的东西必须跟着手指 |
| 覆盖小程序 | 180ms · easeOutCubic | 被盖层退让（压暗+缩小+圆角） |
| 覆盖层压暗 | 180ms · linear | |
| 新消息插入 | 120ms · easeOut | 只做淡入，不做位移（位移会让"时间线"看起来在动） |
| 服务重启灰化 | 200ms | 变灰是"抽色"，不是"变淡" |

**减少动效**：`MediaQuery.disableAnimations == true` 时全部改成瞬时切换（不做动画）。

## 十一、无障碍与键盘

- **语义标签**：抓手 = "调整聊天窗口高度"；收起条 = "展开对话"；任务小标 = "还有 N 件事在处理"。
- **触控目标 ≥44×44**（见 §七的修正）。
- **对比度**：正文与浮窗底色 ≥ 4.5:1；来源（11px）与底色 ≥ 4.5:1。
- **键盘**（桌面 / 网页）：`Esc` 收起、`Cmd/Ctrl+K` 聚焦输入、`Enter` 发送、`Shift+Enter` 换行。
- **字号放大**：系统字号放大到 1.3× 时，收起高度**按内容撑开**（不能用固定 124 硬裁）。

## 十二、实现落点与测试影响

### 要改的地方（就一处结构 + 两处参数）

| # | 改哪 | 怎么改 |
|---|---|---|
| 1 | `chat_screen.dart` 的 `Stack` 顺序 | 把 `_floatingPanel` 挪到 `MiniAppContainer` **之后**（z 序最上） |
| 2 | 小程序的生命周期 | 用 `Offstage` / `IndexedStack` 保持挂载 + `TickerMode(enabled:false)`；**不许重建** |
| 3 | 小程序底部让位 | `MiniAppContainer` 接一个 `bottomInset = 124 + 10`，内容 padding 用它 |
| 4 | 覆盖退让 | 小程序层包 `AnimatedScale` + `AnimatedOpacity`（§4.2 的数值） |
| 5 | 半开时点小程序 = 收起 | 在聊天层之下、小程序之上加一个透明拦截层（只在聊天展开时存在） |
| 6 | 触控目标 | 输入条按钮的命中区撑到 44（视觉不变） |
| 7 | 防抖 | 400ms 合并连续的最大化触发 |

### 测试影响（别照抄旧断言）

现有 `test/widget/floating_panel_test.dart` 断言的三条**必须继续成立**：

1. 最大化时高度 > 屏高 80%，且**四边都留边距**（左右对称）；
2. 阴影 **≥2 层**、圆角非空；
3. 助手一开口也拉满。

**要新增的测试**：

| 新测试 | 断言 |
|---|---|
| 聊天永远在最上 | 小程序打开后，对浮窗中心的坐标做 hit test，命中的是**聊天**而不是小程序 |
| 被盖住不重建 | 小程序里放一个自增计数器 State，聊天展开→收起，计数**不变** |
| 收起态不压住可点元素 | 小程序最后一个按钮的 rect 与浮窗 rect **不相交** |
| 半开时点小程序 = 收起 | 点小程序可见区域后 `_collapsed == true`，且小程序**没收到**这次点击 |
| 覆盖退让数值 | 展开时小程序层 `scale ≈ 0.98`、压暗 `alpha ≈ 0.35` |
