## 第 1 族 · 安全与权限（`P1` / `P2`）

### `P1` 助手不能改自己：它只能提申请，签字的是主人

**结论**：凡是"让改动变成**下次开机自动读**"的路径，都只有主人能按下那一下。
**理由**：威胁的真实形态不是"它干一次坏事"（那能收拾），而是"**坏事能不能留下来**"——它读到一段看不见的网页内容 → 被诱导写进自己的配置 → **从今往后每轮开机都读那一段** → 而表面上一切正常。只要它还握着改自己的手，一人一台盒子、记忆隔离、外部内容不可信**全都白装**：它能从那一边把墙拆了。
**连带动作**：改动写成补丁放 `proposals/`（已在 `.gitignore` 里），主人跑 `scripts/apply-change.sh <补丁>` 把它变成**一个 commit**；apply **不替主人重启**（重启会打断正在说的那一轮，重启是主人自己决定的一步）。
**判据**：`v2/services/core/test/apply-change.test.js` · [`../dev/19-P1-P2.md`](../dev/19-P1-P2.md) · [`06-OPERATIONS.md`](06-OPERATIONS.md)。

### `P1.1` 只有主人亲口说"改"才能执行

**结论**：助手可以提方案、可以写补丁，**永远不能自己按那个按钮**。
**理由**：这道闸挡的不是"多一步"（主人自己说过：从第 3 次起他会开始闭眼 apply —— 那样 P1 就没了），而是"**改主意的窗口**"：正因为它要经过主人，他才有机会在按下之前说"等等，不是这个意思"。
**连带动作**：助手产出的命令必须**短到主人愿意看**（一条命令 ＋ 一个补丁）；申请里不许夹"顺手也改一下"。
**判据**：`scripts/apply-change.sh`（只从 `proposals/` 取、要求树干净、只落一个 commit）· `test/apply-change.test.js`。

### `P1.2` "摘够"的判据：没有任何一条路能让助手的写入变成"下次开机自动读"

**结论**：**部署期**只要还剩一条这样的路径，就没摘够；**开发期**的形态是**审计**（每次重建开机清单都留一行痕）。
**理由**：这是 P1 唯一可操作的验收口径 —— 不说"它应该老实"，只说"**还剩几条路**"；路数得清，才谈得上收口。
**连带动作**：开机清单里凡是"开机就喂给 agent 的"（人格 / 能力层 / 小程序限定档 / 模型补丁 / profile / `AGENTS.md` / 手册）都必须是 `strict`；`src/` 与 `scripts/` **今天刻意是 `report`（只报不拦）**——开发期代码天天改，否则每改一行主人就得补一条 `sudo`；**这个让步有一条测试钉住，免得下一个人以为它已经是 `strict`**。
**判据**：`v2/services/core/src/integrity.js` 的 `protectedPaths()` · `test/integrity.test.js` · 留痕在 [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) §九。

### `P1.3` 说明书与能力收回必须同批改

**结论**：`AGENTS.md` 与 `hupo-persona.yml` 里"**直接动手**"那类话，必须与"收回哪几样能力"**同一批**改，不许只改代码。
**理由**：只改代码不改说明书，等于把同一个坑留给"下一次开机的它"：它照旧以为可以自己动手 —— 而且**它读到的说明书在开机清单里是 `strict`**，改它是一种要被验证的动作。
**连带动作**：两处都在 `protectedPaths()` 里、都是 `strict` ⇒ 改完**要请主人重建开机清单**，否则下次重启拒绝启动。
**判据**：`v2/services/core/hupo-persona.yml` · `AGENTS.md` · `test/integrity.test.js`。

### `P1.4` 判断"哪些文件不能写"的那份清单，助手碰不到

**结论**：清单本身（`/etc/hupo/integrity.json`，`root:root 0444`）与"怎么判"（`src/integrity.js`）都在助手够不着的一侧；每次开机核对，对不上就**拒绝启动 ＋ 报警**。
**理由**：清单要是助手能改的，它就能先把自己的那一条划掉、再改自己 —— 那这道锁只是"仪式"。审的不是"有没有改"，是"**改没改对得上开机时那一份**"。
**连带动作**：清单的 `mode` 字段住在 **root 所有的那份文件**里（助手改不了自己那一档）；想排除某个具体路径，就别把它放进 `protectedPaths()`，**不要按名字连坐**。
**判据**：`src/integrity.js` · `scripts/verify-integrity.mjs --build` · `test/integrity.test.js`。

### `P1.5` 回退不需要助手

**结论**：每次执行前存回退点；**回退由主人一句话完成**（`scripts/rollback.sh`），而且它**一个助手产出的文件都不读**。
**理由**：出问题时**助手本身可能就是出问题的那个** —— 它写的补丁、它记的账、它写的文档都不能当依据。所以回退只信 git 自己的历史。
**连带动作**：回退用 `git revert`（把这一次**反做一遍**，历史留着，回退本身也能被回退）；🔴 **不许用"退回到上一个提交"那种做法** —— 它会连同后面每一个改动一起丢掉。
**判据**：`scripts/rollback.sh` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §三。

### `P1.6` 申请的形式：一个文件，落在助手自己的工作区；host 侧按它执行

**结论**：申请 = 一份**主人看得完**的文件（一条命令 ＋ 一个补丁）；host 侧按它执行；**每次改动记一笔账**。
**理由**：P2 的安全性等于"**主人真的看一眼**"。养成了闭眼跑的习惯，"助手提申请"就退化成"助手有 root，只是慢一点"。所以形态必须短、必须只有一处看的地方、必须留下"谁什么时候改的"。
**连带动作**：补丁只能从 `proposals/` 里来（允许从任意路径 apply，等于主人看的那份和生效的那份可以不是同一份）；`proposals/` 同时被 `.gitignore` 排除（不然申请文件本身就让仓库永远有未提交改动，那道干净闸永远过不去）。
**判据**：`scripts/apply-change.sh`（头部注释把这两条理由写死了）· `test/apply-change.test.js`。

### `P2` 执行特权 = 手动：助手把改动与命令准备好，主人自己上机器跑

**结论**：部署期**不预装任何常驻特权组件**，也不把口令交给助手；助手只准备"到最后一键"。
**理由**：一个公开的网页登录口，要触发一个特权动作而不等于把 root 交出去 —— 难点就这一件。选"人工执行"是因为它的边界**小到能用眼睛看完全部输入**（一条命令 ＋ 一个补丁），而常驻守护/免密那两条的边界大到没人能一眼看完。
**连带动作**：要做的事写成"主人跑什么、跑完会发生什么、怎么撤"；跑完**不替主人重启**（重启留给主人决定）。
**判据**：[`06-OPERATIONS.md`](06-OPERATIONS.md) §五 · [`../dev/19-P1-P2.md`](../dev/19-P1-P2.md)。

### `P2.1` 不预装任何 root 组件

**结论**：不需要 root 服务、不需要定时任务、不需要为"多用户隔离"预装 uid 那一套 —— 今天就能用。
**理由**：每多一个常驻特权件，就多一个"它自己能不能改自己"的问题；而这一批要验的恰恰是"**不靠特权件也能把事情办成**"。
**连带动作**：真要动 root 的那几件（重建清单、装容器）走**主人一句话**；白名单也只给**具体那几条命令**，不是把口令交给助手。
**判据**：`scripts/apply-change.sh` · `scripts/rollback.sh` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §五。

### `P2.2` docker 组永久不碰

**结论**：`deploy` 不进 `docker` 组；宿主上的 docker 访问权 = **宿主的 root**，**永远不给**。
**理由**：那等于给一个**跑着 AI 的账号**免密 root，比"要口令的 sudo"更松 —— 而它看起来只是一次 `usermod`。这是**永久否决**，不是"这一轮不做"。
**连带动作**：需要容器就装 podman（根下的那套不需要 docker 组）；凡是要"用 docker 顺便解决一下"的提议，回到这一条。
**判据**：本机实测 `groups`（`deploy` 只在 `sudo`/`users`）· [`../dev/23-DEV-VS-DEPLOY.md`](../dev/23-DEV-VS-DEPLOY.md)。

### `P2.3` 本轮不装 podman；两种 root 不是一回事

**结论**：容器是"开第二个用户"的开门条件，不是第一步；而**宿主上的 docker 访问权**（＝宿主的 root）永远不给，**容器内部的 root**（＝那个盒子里的 root）应该给 —— 不给它就是个残废。
**理由**：这正是容器方案的卖点：今天不敢给 root，因为给了就是给整台机器；有了容器，可以**在盒子里给它完整 root，而外面一点碰不到**。
**连带动作**：容器那一套的装/撤/核对在 [`06-OPERATIONS.md`](06-OPERATIONS.md) §七与 [`09-APPS.md`](09-APPS.md)；盒内 agent 固定 uid 1000，盒子里的 root 是它自己的世界。
**判据**：`v2/services/core/src/tenants.js` · `scripts/check-container.sh`。

### `P1`／`P2` 的读法：开发期与部署期是两套

**结论**：**部署期**（服务用户的那一套）P1/P2 原样有效；**开发期**（本机、主人就在跟前）主人已授权助手做开发上的特权事（装工具、跑维护脚本、重建开机清单），本机的护栏降级为**审计**（每次重建留痕）。
**理由**：判据**不是"哪台机器"**，是**这一段工作在服务谁** —— 本机同时是开发机又是线上机（`127.0.0.1:8020` ＋ 隧道），所以"换台机器就安全"那种读法是错的。降级不等于拆掉：**留痕就是那根撑着的柱子**（没有它，降级就等于拆）。
**连带动作**：授权**只到开发期**；口令不进任何文件、不进日志；要放开就放开**具体那几条命令**（白名单），⚠️ 但白名单里放一个"助手能改的脚本"实际上仍然是 root（它的价值是留痕，不是圈住）。
**判据**：[`../dev/23-DEV-VS-DEPLOY.md`](../dev/23-DEV-VS-DEPLOY.md) §四／§五 · [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) §九。

### `P-a` 完整性清单由主人手动重建/签名

**结论**：`/etc/hupo/integrity.json` 由主人跑 `scripts/verify-integrity.mjs --build` 生成 —— **`root:root 0444`**，每次改清单都要主人动手一次。
**理由**：这是"清单护住清单自己"这件事绕不开的递归坑的唯一出路：签名动作本身必须在一个助手够不着的地方发生。接受"每次改清单要主人跑一次"，就是接受这条边界。
**连带动作**：**命令不许手打** —— 照 `verify-integrity.mjs` 打印出来的那一条粘（里面是绝对路径：本机没有系统 `node`）；改了 `strict` 的那几个文件（人格 / 能力层 / `AGENTS.md` / 手册 / profile）**不重建，下次重启就拒绝启动**。攒成一次做，少让主人跑几条。
**判据**：`scripts/verify-integrity.mjs` · `src/integrity.js` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §三。

### `C1` "摘够"的判据 ＝ "清单里没有可写路径"

**结论**：P1.2 不是"全仓 grep 等于零"（对运行时数据不成立）——判据是"**那份清单里没有一条是可写路径**"，外加"清单之外的高风险路径要有别的说法"。
**理由**：`~/.dsh/storages/**`（会话缓存 / KV）与账本（用户数据）**每一轮都在被写**：把它们放进清单只有两种结果 —— `strict`（每轮之后开机都对不上 ⇒ 天天拒绝启动）或 `report`（每次开机都报一句 ⇒ 每次都响的报警等于没有报警）。所以它们**故意不在清单里**。
**连带动作**：代价如实认下 —— "有人往 KV / 账本里塞东西"这条路**没有被清单覆盖**；覆盖它得看**内容**而不是**摘要**，那是另一件事。别处的补偿是"写盘只有服务端那一处"（MCP 那支只能经域套接字提请求）。
**判据**：`src/integrity.js`（那两条 `storages` / 账本的注释就是这一条的正文）· `test/integrity.test.js`。

### `C5` 宿主上的 `sudo` 要口令 —— 这是部署期那道锁的地基

**结论**：本机的 `sudo` **没有免密、也没有装白名单**（`sudo -n true` 会失败）；这件事**不是不便，是安全地基**。
**理由**：P2 甲的全部安全性建立在"**多一步、而且那一步只有主人过得去**"上。要是 `sudo` 免密，P2 就退化成"助手有 root，只是慢一点"——而说明书里任何一句"你免密"都会把这道地基说没。
**连带动作**：开发期主人已授权助手做开发上的特权事，但**机制上仍要口令**（要放开就放开具体几条命令，且那条白名单的价值是留痕）；`AGENTS.md` 与 `hupo-persona.yml` 里凡是讲"直接动手"的地方都要与事实一致（`AGENTS.md` 本身是 `strict`）。
**判据**：本机实测（`sudo -n true` 失败）· `AGENTS.md` §八 · [`../dev/23-DEV-VS-DEPLOY.md`](../dev/23-DEV-VS-DEPLOY.md)。

## 第 2 族 · 承重墙（`X1` / `X3`）

### `X1` 口径：编号的"全局"＝ 这个用户那条可见时间线

**结论**：`X1.1` 说的"全局"是"**这个用户那条可见时间线**"——**不是**全机器一个计数器，**也不是**"每条 DSH 会话各数各的"。
**理由**：两个都不是会错意的问题：全机器一个计数器会把两个用户串起来；每条会话各数各的会让"同一间里的编号"在换会话之后对不上。一条可见时间线 = 一条日志，多作用域**只是事件上的 `scopeId` 标签**，不是并列的计数器。
**连带动作**：落地形态由 `P-l` 定死（每个用户一条 `Timeline`；`ScopeView` 是同一把 `Timeline` 上带标签的视图）；"一条 WS 连接 ＋ 焦点路由"是另一层的事，别混进来。
**判据**：`v2/services/core/src/timeline.js` 文件头 · `test/scope-single-log.test.js` · [`../dev/84-DISPATCHER-FOCUS.md`](../dev/84-DISPATCHER-FOCUS.md) §六。

### `X1.1` 编号由调度器统一发

**结论**：编号由**服务端那一个取号函数**发（`Timeline` 的 `#nextSeq`），不是各会话自己数自己的，也不是客户端给的。
**理由**：客户端给的号可以被伪造、可以在重连后重复；各会话自己数的话，"同一条时间线上两件同时发生"就会撞号 —— 而号是客户端续传游标唯一的排序依据，撞号＝**它手里的位置错位**。
**连带动作**：全模块**只许有这一处 `seq++`**；别处要号只能向时间线要。
**判据**：`v2/services/core/src/timeline.js`（"只有一个取号函数"）· `test/seq-monotonic.test.js`。

### `X1.2` 编号 = 已落盘事件的最大编号 + 1，只增不减

**结论**：持久事件的号 = **那条日志已落盘的最大号 + 1**；重启从磁盘取 max ⇒ 编号**单调**；某个房间被回收、盘上最大号变小过，就用**号的"地板"**（留痕里的最大号）挡住回头。
**理由**："只增不减"是客户端那个游标的全部信任来源：号一旦回头，客户端会把**已经拿过的号**当成新事件，或者把丢掉的号当成"还没有"。
**连带动作**：取号的下限（`seqFloor`）由回收那一路传进来；缺省 0 ⇒ 既有调用方逐字不变。
**判据**：`src/timeline.js` 的 `#resumeSeq` / `seqFloor` · `test/seq-monotonic.test.js`。

### `X1.3` 先落盘、再推给客户端；写盘失败必须报出来

**结论**：`store.append` 失败**必须上抛**；顺序永远是"**先落盘成功、再推订阅者**"；写盘失败不许吞。
**理由**：反过来（先推、后落盘）会让"屏幕上已经有的字"在重启后消失 —— 用户看到的是一条他**再也找不回来**的消息。而吞掉失败 = 让服务在盘满之后继续假装正常：崩 → 重启 → 再崩。
**连带动作**：上抛之后**必须有人接**（统一包一层 ＋ 进程级 `uncaughtException` ＋ 用**不落盘的通知通道**发一条人话 ＋ 有界退出 ＋ 退避重启）；接的人写在哪，见 [`03-DEVELOPMENT.md`](03-DEVELOPMENT.md) §5.2。
**判据**：`src/store.js` / `src/timeline.js` · `test/store-append.test.js`。

### `X1.4` 可见时间线上，同一时刻最多一条"还没说完"的消息

**结论**：一条对话里同时只许有一条**未收口**的消息（消息不许交叉）；**但执行照常并行** —— 排队的是**上屏**，不是干活。
**理由**：两条回答交叉着长字，用户分不清哪一句在回答哪一句；可要因此把执行也串起来，就把"同时办几件事"这个能力白扔了。
**连带动作**：未收口那条**按作用域各记一份**（不是全局一份）——否则"甲房间正说着、用户切到乙房间说一句"会当场被这条不变量拒掉；那是把一条正确的规矩用错了地方。
**判据**：`src/timeline.js` 的 `#opens` · `test/message-writer.test.js`。

### `X1.5` 显示用发生时刻

**结论**：时间线上显示的是事件**发生**的时刻，不是客户端**收到**的时刻。
**理由**：补发/重连时"收到时刻"会把三小时前的几十条全画成"刚刚"——那比不显示时间更坏：用户照着"刚刚"去理解一件事的先后顺序，得到的是假的。
**连带动作**：事件落盘时就带 `at`（允许调用方显式给，缺省才是取号那一刻的钟）；客户端只显示这个字段。
**判据**：`src/timeline.js`（`at: event.at ?? clock()`）· `v2/apps/mobile/lib/models/chat_time.dart`。

### `X1.6` 补发段必须带"你不在的时候"

**结论**：断线重连补发过来的那一段，**必须**带一个"**你不在的时候**"的标记；而首次打开那一段**不许**被标成补发。
**理由**：不标，用户会把三小时前的话读成"它刚说的"——那既是骚扰，也是假话（"每次登录都弹一条『刚才出了点事』"就是这个形状）；标反了，他每天开一次 App 就看见一次"你不在的时候"。
**连带动作**：标记字段**现在就留在协议里**（`P-h` 那条线上标记，不落盘）；只在**续传游标 > 0** 时标；首次打开只给**最近的一段**，更早的由客户端往上翻按页取。
**判据**：`src/resume.js` · `test/resume.test.js` · [`../dev/141-HISTORY-FIRST-OPEN.md`](../dev/141-HISTORY-FIRST-OPEN.md)。

### `X1.7` 计数器按可见时间线各数各的

**结论**：张三的号不影响李四的 —— 每个用户**一条日志、一套号**；而同一个用户内部，**多作用域共用这一套号**（`scopeId` 只是标签）。
**理由**：多人共用一台服务时，全局号会把"谁的话在第几位"变成可推断的元数据；而同一用户内部再按房间各数一套，会让"一条可见时间线"这个前提消失（也就没有"一条日志"了）。
**连带动作**：补发与订阅都走**他自己那一份**时间线（身份只从验过签的令牌来）；否则甲连上来的流会补发出乙的话。
**判据**：`src/timeline.js` 的 `eventInScope` · `test/scope-single-log.test.js` · `test/multitenant.test.js`。

### `X2` 协议里现在就带着三样身份标签

**结论**：事件上**现在**就带着 `scopeId`（哪一间产的）· `agent`（谁在说）· `origin`（为什么开口）；界面显示不显示是另一回事，**字段在协议里**。
**理由**：字段是**上线即冻结**的东西（老客户端还在跑）：等界面要用的时候再加，就得同时维护两代协议；而"这条是谁说的、为什么冒出来"这两个问题，界面迟早都要回答。
**连带动作**：`v1` 界面可以不显示，但**不许**因为"现在没人读"就把它拿掉；新加身份信息一律走这两条轴（`agent` ＋ `origin`），不许再新造一个语义重叠的字段。
**判据**：`src/message-writer.js`（`agent` / `origin` 落到事件上）· `test/message-writer.test.js`。

### `X3` 收起 ≠ 删掉：删掉进回收站、到期真删、注销立刻清空

**结论**：删一轮 = 落一条**墓碑**（`turn/deleted`，取号落盘，内容还在盘上）；进回收站后默认留一段期限，**到期前先告一声**；到期或手动"真删" = **压实**（逐条换成最小占位、**保留各自的 `seq`**，盘上 grep 不到内容）；注销账号 = **立刻清空**。
**理由**：真删要真的不在盘上，而 append-only 是删不掉字节的 ⇒ 只能重写；重写又不能让号跳（客户端 `sinceSeq` 全靠号）⇒ "压实但保留号"是唯一自洽的形态。回收站留一段期限是"**可防错 > 可恢复**"里"可恢复"那一半的兜底。
**连带动作**：删前**必须列清单**，而清单是**从状态清单推出来的、不是手写的几句话**（手写的一定漏，漏一项就是屏幕上说"删掉了"、其实还在）；"单条删"不许另造一个"说删就删"的口子。⚠️ 今天界面上的"回收站入口"已经砍掉 ⇒ **用户自己拿不回来**，所以"删之前把要删的摆出来问一次"是底线。
**判据**：`src/trash.js` · `test/trash.test.js` · [`../dev/28-DELETE.md`](../dev/28-DELETE.md)。

### `X3` 的注销那一段：只能注销自己，而且要身份再确认

**结论**：用户能在网页上注销（`POST /api/cancel`，入口在"填钥匙"那一屏下面、不抢眼）：点下去**先列清单**再确认；**只能注销自己**（身份只从验签令牌来）；**再确认一次身份**（要最近真的登录过）；收掉之后**令牌全撤 ＋ 账号那一行也删**；**每个动作写审计**。
**理由**：注销**不可逆**（那一台连同里面的东西一起收掉），而"只认令牌"就意味着**一个被盗的令牌能删掉一个人所有的东西**。
**连带动作**：身份再确认看令牌签发时间，**续期不刷新这个时间** ⇒ 旧令牌刷不过去（挡的就是"被盗的旧令牌"），过不去就 409 且**什么都没发生**；审计写成**两份文件两个写入者**（服务 / 特权侧各写各的 ⇒ 谁也伪造不了对方的行）＋ 形状逐字一致 ＋ 一个脚本并起来给人看。⚠️ 短信通道接上之前，这道门和"登录"一样强。
**判据**：`src/reauth.js` · `src/audit.js` · `test/cancel-route.test.js` · `test/reauth.test.js` · `test/audit.test.js`。

## 第 3 族 · 能力与边界（`P4` / `P5`）

### `P4` 做能力契约层：第一批只做登记表本身 ＋ 一个真数据源，不生成界面

**结论**：有一条**能力登记表**，每条能力登记四样：**形状**（字段 ＋ 只追加）· **版本化**（写进账本就不再改语义，改＝新增字段）· **失败语义**（校验不过就不写，并说清哪一项没听准）· **额度字段**（数值只住代码）。第一批只做**这张表 ＋ 一个真数据源（工时账）**，**不生成界面**。
**理由**：AI 不能在生成界面的同时**现编数据源** —— 否则今天生成的界面字段叫 `amount`、明天叫 `money`，昨天记的账今天读不出来：那不是质量问题，是**不可复现**。这条也是整套产品假设里唯一能两天验证的：用户那句话到底能不能映射到一组**稳定**的能力上。能 ⇒ 生成界面只是渲染问题；不能 ⇒ "AI 手机"退化成"每次现编一个玩具"。
**连带动作**：AI 只做**组合 ＋ 渲染**，绝不发明接口；能力层挂在**仓库自己的一份 patch**（`v2/services/core/hupo-capabilities.yml`）上，**不碰 `strict` 的 profile**；写盘只有宿主一处（模型不许直接写盘，它只能"提一条要写的"）；出口同批（列表 ＋ 导出 ＋ 单条删，形态是**一段能粘进微信的话**，不画表）。
**判据**：`v2/services/core/test/capabilities.test.js` · `test/ledger*.test.js` · [`../dev/31-LEDGER.md`](../dev/31-LEDGER.md) §四。

### `P5` 不做代执行，只做"准备到最后一键"

**结论**：**不做代执行**（不模拟点击、不假装能登进别人的网站替他点）；事做到"**准备到最后一键**"就停下，并说清"接下来该你点"。
**理由**：银行、政务、挂号、快递那些**永远不会给接口**；模拟点击做不到，也不该假装能做 —— 出事要有人负责，而"它替我点了提交"把责任人抹掉了。⚠️ **"声明式代操作"这个叫法不许用**：名字会自己长回"自动化"，而这条路是明确不走的。
**连带动作**：做不到就说做不到 ＋ 他还能怎么办（不假装能做）；它的价值体现在"链接在这，点开就是填好的表"，而不是"我帮你点了"。
**判据**：`v2/services/core/test/persona.test.js`（源码级人格硬规则）· [`01-PROJECT.md`](01-PROJECT.md) §十一。

## 第 4 族 · 命名与登录（`D1` / `D2`）

### `D1` 隐喻 = 一件事一本本子；第一入口 = 图标墙

**结论**：一个物件 ＝ **一件事的一本本子**（**不是**文件夹、**不是**应用、**不是**频道、**不是**房间）；重名之下**加第二行小字**（"最近：…"）；**内置图标保留**；第一入口 ＝ **图标墙**。
**理由**：三个候选只有"本子"一个不撒谎 —— 叫**文件夹**，用户十分钟内就会往里拖文件、传附件（真试过，放不进去，他自己花一整天解开这个误会）；叫**应用**，点开还是聊天，用户判定"点开跟没点一样"；而**本子**承诺的（能翻、能问、能添页）**正好就是聊天已有的能力**，一句空话都不多。撤掉内置图标也不行：它们是"**这不是我的东西**"的锚，撤了第一天桌面就是空的，而空桌面是全篇最一致的发慌点。
**连带动作**：界面上的物件**要用他自己的词**命名；重名靠"最近做过什么"区分，不许拿系统编号顶。
**判据**：`v2/apps/mobile/lib/models/desktop_words.dart` · [`01-PROJECT.md`](01-PROJECT.md) §九 · [`../dev/59-USER-APPS.md`](../dev/59-USER-APPS.md)。

### `D1.1` 「工作区」三个字界面永久禁用

**结论**：**「工作区」永久禁用** —— 图标名 / 标题 / 提示 / 空屏 / 报错，一处都不许；它进禁用词扫描。
**理由**：十个人里**零个**发现"工作区"是什么，而且它出现时会吓到人：05 读成"上班干活的地方"、06 读成"以前学校里写黑板报的角落"、03 的第一反应是"**是不是流氓软件**"。原话比任何道理都硬。
**连带动作**：禁用词一条一条挂在 `models/forbidden_words.dart` 上，由 `test/unit/forbidden_words_test.dart` 扫**整棵树里的字符串字面量**；⚠️ **"必须干净"的那份名单今天还有洞**（设置页顶层那行"模型设置"含禁用词「模型」却不在名单里）—— 洞记在 [`../dev/224-V3-PROJECT.md`](../dev/224-V3-PROJECT.md) §六·2。
**判据**：`v2/apps/mobile/lib/models/forbidden_words.dart` · `test/unit/forbidden_words_test.dart`。

### `D1.1·补` 聊天窗口那一格放开，其余界面照旧

**结论**：**聊天窗口里**，工具名、入参、输出摘要、系统提示词、每轮 token **都可以上屏**；**产品其余界面**（首页 / 登录 / 桌面 / 设置 / 空态 / 报错）照旧**一个内部词都不许有**。
**理由**：放开的是"**把这条会话摊开给人看**"（它的读者是主人自己，要的是可核对），**不是**"文案可以内部化"。把两者读成一件事，那道禁用词闸就废了 —— 而它守的是"用户不用学新东西"。
**连带动作**：默认那一行**仍然说人话**（"做一个小程序 / 跑命令 / 改文件"），**原始名字住在展开的那一块里**；每轮那一串 token 收进「过程」折叠（默认收起）。
**判据**：`test/unit/forbidden_words_test.dart` · [`../dev/115-DSH-WINDOW-PARITY.md`](../dev/115-DSH-WINDOW-PARITY.md) · [`../dev/154-CHAT-RECORD-LOOK.md`](../dev/154-CHAT-RECORD-LOOK.md)。

### `D1.2` 名字由系统提议，只用用户自己说过的词

**结论**：名字**由系统提议**，而且**只用用户自己说过的词**；**永远不问**"你想叫它什么"。
**理由**：一上来问名字，第一反应是"那算了"（用户原话）；而用户自己说过的词（"这篇文章的地方"）才是他认得出的名字 —— 系统编号他记不住，系统造的美名他更记不住。
**连带动作**：新建那一步**不摆命名输入框**（那一步是"多一样要学的东西"）；提议的名字要能从他那句话里指出来源。
**判据**：`v2/apps/mobile/lib/models/desktop_words.dart`（改名入口在长按/详情里）· `test/widget/desktop_test.dart`。

### `D1.3` 能改名，随时能改

**结论**：**随时能改**；入口在**长按 / 详情**里，**不在首建流程里**。
**理由**：名字是会变的（"云澜"被听成"云兰"），改名的成本必须低到随手；而把它放进首建流程，就等于"用一次刚上手的机会考他一道题"。
**连带动作**：改名是本地就拦得住的一件事（空名字不许发一个注定被拒的请求）；改完如实说一声。
**判据**：`models/desktop_words.dart` · `test/widget/desktop_remove_test.dart`。

### `D1.4` 区分同名必须用他自己的话，不许系统编号

**结论**：两个一样的名字，靠**他自己的话**区分（"最近：品牌升级 3h"），**不许**用"第 1 个 / 第 2 个 / 序号"。
**理由**：系统编号对用户是一个**要学的新东西**，而且它不告诉他"这两个哪里不一样" —— 那正是他需要的答案。
**连带动作**：「第 1 个」「第 2 个」「序号」都在禁用词表里；重名那第二行小字读的是"最近做过什么"。
**判据**：`models/forbidden_words.dart` · `models/desktop_words.dart`。

### `D1.5` 产品名 = 「琥珀聊天」

**结论**：**三处逐字用它**：**浏览器标签页** · **"添加到主屏幕"之后的图标名** · **聊天窗口抬头**。**一处出处** ＝ `v2/apps/mobile/lib/models/landing_words.dart` 的 `appName`。
**理由**：名字漂一个字，用户就会以为是两个东西（"我装的那个叫琥珀，这个叫琥珀聊天，是不是山寨"）；而同一份名字写在四处，就一定有一处会旧。
**连带动作**：`web/index.html` 与 `web/manifest.json` 是**脚手架的字符串**（import 不了 Dart）⇒ 靠 `test/unit/web_shell_test.dart` **拿同一个常量逐字钉住**（四处一起漂不了）。⚠️ **品牌名「琥珀」（`landingBrand`）与它不是同一个词**：登录页 / 首页那一格仍是品牌名。
**判据**：`models/landing_words.dart` · `test/unit/web_shell_test.dart` · [`../dev/170-PRODUCT-NAME.md`](../dev/170-PRODUCT-NAME.md)。

### `D1.6` 安卓 2.0 是**另一个 app**，与 1.0 并存

**结论**：装上去的**身份**不同：1.0 是 `chat.hupo.hupo_app`（桌面上叫「琥珀」），2.0 是 `chat.hupo.hupo_chat`（桌面上叫「琥珀聊天」）⇒ **同一台手机上并排装着，新包不会顶掉老包**。
**理由**：主人点名要"另一个 app，不要覆盖 1.0"。安卓按 `applicationId` 认"是不是同一个 app"，所以只要身份不同，两个就谁也覆盖不了谁。
**连带动作**：🔴 **两个下载地址都留着**（新那份 ／ 1.0 那一份原样不动）；⚠️ 网页部署会把静态根清空 ⇒ 1.0 那一份的存档在服务端数据目录，每次部署放回去（**老链接不许 404**）；🔴 **`namespace` 与 Kotlin 那几份不许跟着 `applicationId` 改**（`.MainActivity` 是相对 `namespace` 解析的 —— 那是代码的包名，不是装上去的身份）。
**判据**：`v2/apps/mobile/android/app/build.gradle` · `scripts/deploy-web-v2.sh` · [`../dev/187-APK-TWO-APPS.md`](../dev/187-APK-TWO-APPS.md)。

### `D2` 登录页：门是**手机号 ＋ 验证码**

**结论**：进来那道门是**手机号 ＋ 验证码**（**没有密码**）；"口令""暗号"都不用；按钮说「**打开**」；**四种失败四句话**（码不对 / 手机号不像 / 还没接短信 / 连不上）；临时验证码**必须如实说**；配三件机制：**连不上不清令牌** · **令牌到期自动续** · **忘密码的恢复**（今天没有密码可忘 ⇒ 由验证码这条路接管）。
**理由**：06 那位 68 岁的退休教师**在登录页第一天就放弃**，而 03 的期望原话是"微信抖音都是验证码" —— 验证码是用户**已经学过**的那一套，多一个要打的字段就多一次放弃的机会。含糊的失败提示等于没说：混成一句"登录失败"，他只会反复重输。
**连带动作**：这一屏的**全部文案**只许住 `models/login_words.dart`（那样才进得了禁用词硬闸）；服务端那条密码路照旧认（老客户端/兜底），但**界面上不再有密码框**。
**判据**：`v2/apps/mobile/lib/screens/login_screen.dart` · `models/login_words.dart` · `test/widget/login_test.dart` · [`../dev/37-MULTITENANT.md`](../dev/37-MULTITENANT.md)。

### `D2.1` "能执行命令、能改自己的代码"从登录页拿掉

**结论**：这句承诺**不上登录页**。
**理由**：读完之后是**害怕**（全场只有一个人读得懂）——而登录页是"这道门只有你能开"的地方，不是讲能力的地方；把它留在首屏，等于用一句真话劝退一个本来能用的人。
**连带动作**：它是**产品资产**，不是营销文案：能力怎么讲，去 [`01-PROJECT.md`](01-PROJECT.md) §七 那一节（一块一行），首屏只说"它真会去做"。
**判据**：`models/landing_words.dart` · `models/login_words.dart`（两处都进禁用词闸）。

### `D2.2` 「口令」永久不用

**结论**：**「口令」是永久禁用词**；今天这道门**根本不问口令**（手机号 ＋ 验证码）。
**理由**：用户上一次听到"口令"是"看电视里当兵的站岗"——他得先把它翻译成"密码"，再想"这里为什么要这个"。一个词要过两道，就有一道会卡住人。
**连带动作**：它挂在 `forbidden_words.dart` 上（连"暗号"一起禁：新造的说法同样要学）；文案改动一律走词表闸。
**判据**：`models/forbidden_words.dart` · `test/unit/forbidden_words_test.dart`。

### `D2.3` 按钮说「打开」

**结论**：那颗按钮的字是「**打开**」。
**理由**：「进去」没人读出"进门"，读出来的是"**提交**"——而"提交"是一次有风险的动作（像交表格），"打开"才是他能理解的那件事（打开门、打开一个东西）。
**连带动作**：`model_key_screen` / 设置页里凡是"进入某一屏"的动作，也照"打开 / 关上"这一套说，不许内部词与动词混着叫。
**判据**：`models/login_words.dart`（`loginSubmit`）· `test/widget/login_test.dart`。

### `D2.4` 记忆那句不在这屏说

**结论**：**登录页不说"它会记住你"**。
**理由**：上线之前写它 = **空承诺**；而一个"说了没做到"的记忆承诺，比不提记忆更伤（用户会照着它去信任一个还不存在的能力）。
**连带动作**：记忆要有**可见、可验证、标出处、可一条条删**的出口之后，才谈得上在别的屏讲它（[`01-PROJECT.md`](01-PROJECT.md) §五 原则②）。
**判据**：`models/landing_words.dart` · `models/login_words.dart`（这两份是首屏全部文案）。

### `D2.5` 它自己怎么说话：短、白话、只说他要在意的

**结论**：**能一句说完的不要两句**，先给结果，他问什么答什么。🔴 **不要说的**：过程（"我先…""我推之前…"——做了就说结果）· 实现细节（接口 / 站名 / 字段名 / 状态码 / 版本号 / 文件名 / 端口 / 时间戳 / 工具名）· 复述他的话 · 把所有情况铺开（兜底 / 失败 / 开关在哪 / 以后怎么关）· 设计说明。🔴 **必须说的**（短也要说，一个字都不许省）：① 没做成 / 只做成一半 / 中途改了主意；② **要他按一下**（同意权限 / 填东西 / 改设置）——一句话说清要他做什么；③ 会**丢东西 / 花钱 / 动他已有的东西**——先说；④ 他明确问的细节。
**理由**：主人点名的反例是一段"天气小程序加联网权限"的真实回复 —— 里面**很多不是普适的**。技术味的回答把"我要办的事"埋进了一堆他不需要的判断里。
**连带动作**：⚠️ **这一条不是"少说实话"**：短的是**怎么说**，不是**说不说** —— **报坏消息不挨骂，瞒才挨骂**。
**判据**：`v2/services/core/test/persona.test.js`（源码级，含负向对照）· [`../dev/190-SPEAK-PLAIN.md`](../dev/190-SPEAK-PLAIN.md)。

### `C6` 登录用词以 `D2` 为准：用他已经学过的词

**结论**：两套说法冲突时，**以 `D2`（用户已经学过的那一套）为准**，术语层的建议让路。
**理由**："密码"是微信时代已经学过的词，"暗号"是新造的、**要学**；一个要让用户先学一个词的设计，在登录页这一步就已经输了一半。今天更进一步：这道门连"密码"都不问了（手机号 ＋ 验证码）。
**连带动作**：新造词一律先过"他学过没有"这一问；过不了就进禁用词表 —— 不是文风问题，是缺陷。
**判据**：`models/forbidden_words.dart` · `models/login_words.dart`。

## 第 5 族 · 可访问性（`D3`）

### `D3` 做可访问性，但不做"老人档"这个模式

**结论**：可访问性**做**，但**不做"老人档"这个模式** —— 那几样是"**把默认值改安全**"，**全体受益**。
**理由**：**多一个模式就是多一样要学的**，而且它把"看不清 / 点不准"标成"一类人的毛病"，于是只有那一类人会去开它，其余人继续在不安全的默认值上。
**连带动作**：三样（跟字算 / 不封顶 / 命中区）＋ 甩 ＋ 收起态展开入口，**必须同批**；不可以"只做字号"。
**判据**：`v2/apps/mobile/test/widget/accessibility_test.dart`（那条硬闸一次量完）· [`01-PROJECT.md`](01-PROJECT.md) §十二。

### `D3.1` 不做模式

**结论**：**没有"老人档""简洁档"这种开关**；要改的就改默认值。
**理由**：同 `D3`：多一个模式就是多一样要学的；而且模式一旦存在，"默认那一档可以差一点"就变成默认的借口。
**连带动作**：真需要用户选的，只有**字号**那一条轴（它本来就是个人的偏好）；其余按"最不容易出事"的那个值定死。
**判据**：`v2/apps/mobile/lib/models/appearance.dart` · `test/widget/appearance_test.dart`。

### `D3.2` 三样必须同批，不许拆

**结论**：**容器跟字算** ＋ **不封顶（硬闸）** ＋ **触控目标达标**，**同一批**做；只做字号会更糟。
**理由**：只把字号做大，用户得到的是一屏**更大的、但是点不准也装不下**的字 —— 那比不做还坏：他会以为"这个功能做过了"。
**连带动作**：同批的还有**甩改多条件**与**收起态有看得见的展开入口**（它们是"误触能自救"那一半）；验收一次量完（五档无溢出 ＋ 命中区）。
**判据**：`test/widget/accessibility_test.dart` · [`01-PROJECT.md`](01-PROJECT.md) §十二。

### `D3.3` 关于页按**当前这台设备**如实说

**结论**：不会拼音的人在这台设备上能不能用，**按设备如实说**；检测不到就说得**保守**（"如果你的输入法能语音输入，就能用"），**不许一刀切**。
**理由**：设备**输入法自带语音**时写"用不了"是**假话**，而且会**劝退一个其实能用的人**（走的是输入法，不是我们的话筒）。从"某能力缺失"推出的文案，**能力一到位就要回来改它**。
**连带动作**：⚠️ **今天落地文案要跟着能力走**：`about_facts.dart` 里"原生那个包里还没做录音"那句与事实不符（安卓原生录音/开麦/TTS 已在跑，见 [`../dev/224-V3-PROJECT.md`](../dev/224-V3-PROJECT.md) §三／§六·7）——**改的是落地，不是这条规则**。
**判据**：`v2/apps/mobile/lib/models/about_facts.dart`（这一屏的文案只有这一处）。

### `D3.4` "正在听…"只在**真的在录**时能出现

**结论**：「正在听」是一个**有条件的**词：只有真的在录音时才许出现，唯一合法落点是那颗会转的标记（`hearing_words.dart` 的 `hearListening`）；不录音时**禁用「听」字**，它进禁用词扫描。
**理由**：加了话筒之后"听"就**一个词两个意思**：可能是"它真的在收声音"，也可能是"它收到了、在处理"。把假的画成真的，用户会对着一个不在工作的麦克风说话 —— 那正是"页面在说假话"那一族。
**连带动作**：权限要用人话交代，申请时机 ＝ **第一次按话筒**（不是开 App）；真录不出来、没权限、环境太吵，都要如实说，并给他一条打字的退路。
**判据**：`models/forbidden_words.dart` · `test/unit/forbidden_words_test.dart` · `models/hearing_words.dart`。

### `D3.5` 尺寸随字算、不封顶

**结论**：**容器跟字算**（不是字跟容器）；**不封顶**；并且**做成硬闸**：五档字号 pump **无溢出**，且收起态**有看得见的入口**。
**理由**：真故障是"**字大了、笼子没大**"（Flutter 会缩放显式字号，所以修法不是"字号走主题"——那本来就跟着 —— 而是**容器要跟着字算**）。封顶则意味着"你把系统字体调到最大，我们只给到某一档"——**那又是一种假装支持**。
**连带动作**：判断落在"五档不溢出"这一条上（数值住 [`08-SPEC.md`](08-SPEC.md) §十 与测试）；新加的界面也必须过这道闸，否则它会随时间失效。
**判据**：`test/widget/accessibility_test.dart`。

### `D3.6` 触控目标分两档

**结论**：① **点状控件**（按钮 / 图标）：命中区 **≥44×44**（视觉可以更小，用透明 padding 撑命中区）；② **行级入口**（整行都能点的那种行）：按**面积**算 —— 整行宽 × 行高 ≥ 44×44 且宽 ≥44，而**行高跟着那行文字走**（不为了凑高度把行撑高）。
**理由**：把所有东西一律撑到 44 高，会让"一行小字"漂在一片空白里（真实读数：11 号字那一行被右边一颗 44 的箭头撑到 50）；整行可点之后**命中面积反而更大**（通常从不到两千 px² 变成六千 px²），右边那颗箭头降级成**指示**。
**连带动作**：⚠️ 代价明写：它**不再是"处处 44 高"**；行级那一档的判据量的是**布局盒子**（透明 padding 撑起来的也算），不是"看得见的那一块"。
**判据**：`test/widget/accessibility_test.dart` · `test/widget/chat_spacing_test.dart` · `test/widget/tool_rows_test.dart` · [`../dev/155-ROW-ENTRY.md`](../dev/155-ROW-ENTRY.md)。

### `D3.7` "甩"保留但改造 ＋ 可关

**结论**：「甩」这条手势**保留**，但判据是**速度 ＋ 位移 ＋ 时长三个都要满足**（单看速度会把快速滚动误判成甩），并且**能被动效总开关关掉**。
**理由**：06 那位老人被误触"甩"收起浮窗之后说的原话是"**我找不回来**"——甩本身是他唯一会的那种手势，所以不能删；但只按速度判会把他正常翻看的动作当成收起，所以三个条件缺一不可。
**连带动作**：⚠️ **今天它没有落点**：`widgets/chat_floater.dart` 里只剩三个常量（速度 / 位移 / 时长），**没有任何手势读它们**（改高度的拖动与那两层监听已撤）。⇒ 要么把接线补回来，要么**明说砍掉**；不许让"代码里有常量"冒充"功能在"。
**判据**：`v2/apps/mobile/lib/widgets/chat_floater.dart` 的三个常量 · `models/motion_switch.dart`（动效总开关）。

### `D3.8` 收起态必须有看得见的展开入口

**结论**：**收起态必须有看得见的、点得到的展开入口**（不许是"按了没反应的一块"）：今天那颗就是**录音圆圈右侧那一列的上格** —— 收起档是「展开」（平箭头），展开档**同一颗翻个方向**变「收起」（点一下收回去）；命中区达标，**字挂在 tooltip 与无障碍名上**（图形可以很小）。
**理由**：误触收起来之后必须能自救 —— 06 的原话"我找不回来"说的不是找不到那一小条，是**不知道那一小条就是它**；所以入口必须**一直在同一个位置**、而且看得见"这里能点"。
**连带动作**：展开档里「收起」另有**标题行右端那颗带字的「收起聊天」**（主人点名要的第二条路）；两颗在收起/展开两档里**位置不动**（打开聊天窗口那一下，那颗圆圈一个像素都不许跳）。
**判据**：`test/widget/voice_buttons_test.dart`（量两颗的位置与上下沿对齐）· `test/widget/accessibility_test.dart`。

### `P-d` 收起档**没有**"点外面就展开"这条路

**结论**：**点桌面空白 ＝ 把聊天收回去**；收起档上点它是个空动作（**不展开**）。要展开就走那颗「展开聊天」。
**理由**：桌面上的手势只有一个方向、只学一次（点空白=收起，这是 04 那位用户点名"被破坏就重罚"的那一个）；再叠一条"收起档点外面=展开"就是**多一样要学的**，而且它和"点空白=收起"长得一模一样、后果相反。
**连带动作**：⚠️ v1 基线手册 `08-SPEC.md` §6.3 那两行（"点收起态底部条 / 点收起态那个输入框 ⇒ 展开到上次档位"）与今天的代码不符：代码里 `expand()` 只在那一颗按钮的 `onPressed` 里被调。
**判据**：`v2/apps/mobile/lib/screens/chat_screen.dart` 的 `onTapBlank` / `onCoveredTap`（都是 `collapse()`）· `widgets/chat_floater.dart` 的 `_handle`。

### `D3.9` 「配置」是页面上一个常驻入口

**结论**：**「配置」常驻**（它是桌上那一格「设置」）；要补的缺口是"**填过就再也回不去**"——换一把钥匙，或者看看自己到底填过没有。
**理由**：钥匙填过之后没有任何入口能改、能核对，用户只能重装；而"我以为它还用着旧那把"这种事，属于"界面在说假话"那一族。
**连带动作**：⚠️ **现状必须分得开**：有 / 没填过 / **填过但被判无效** —— 第三种**不许**说成"还没有填"（服务端为此给了专门字段）；「关于」**搬进配置**（顶栏再加一个图标就是七个，手机上那一条会挤成一团）。
**判据**：`v2/apps/mobile/lib/screens/settings_screen.dart` · `models/space_words.dart` · `test/widget/settings_test.dart`。

### `D3.9·补` 配置页是四个 tab

**结论**：四屏 ＝ **聊天 / 语音 / 图片 / 视频**（界面上**不写「模型」**——它是禁用词，用"它管什么"来说）。**语音** ＝ 一把 `API Key`（新控制台那一种；**旧版那两样服务端照旧认**，老账号照旧能用）。**图片与视频是同一把钥匙** ⇒ 只填一栏、两样都能用，界面上**明写"同一把钥匙"**，视频那一屏还要说清**慢、贵、一次只做一段**。视频那一栏有一颗「**验一下**」：**不花钱、不生成**，只回答"这把钥匙那边认不认"，并且"没连上"与"钥匙不行"必须分得开。
**理由**：钥匙的"有没有生效"只能由"这条路现在能不能用"来回答，不能由"那一栏填没填"来回答 —— 只填一栏时两格都该是"能用"，否则页面会说"还没填"而其实能用（说假话）。视频那条又慢又贵，不该让他为了"看看钥匙对不对"**先花一笔**。
**连带动作**：**设置过的那一屏只说「已设置」＋「修改」**，输入框只在没设置过、或点了「修改」之后才画（永远摆一个空框会被读成"没生效"，而密钥**从不回填**）；这条自检**不许**顺手做成"试一条"。
**判据**：`src/creds.mjs`（"同一把钥匙"只有一处规则）· `src/ark-check.js` · `v2/services/core/test/ark-check.test.js` · `models/space_words.dart` · [`../dev/79-CREDS-TABS.md`](../dev/79-CREDS-TABS.md) · [`../dev/223-ARK-CHECK.md`](../dev/223-ARK-CHECK.md)。

### `D3.10` 一套外观只有一处出处

**结论**：**以首页为基准**（暖纸底 / 陶土红 / 正文色 / 次要色 / 卡片 / 描边）；**数值只住 `lib/models/design.dart`**（纯数据），`ThemeData` 在界面层拼；**全站只有一处硬编码颜色**，其余全走 `colorScheme`。
**理由**：四屏各写一套颜色，改一处就要找四处 —— 而"找漏了一处"的表现是屏幕上某两屏的同一个东西颜色不一样，没人会当成 bug 报上来，只会觉得"这个 App 有点糙"。
**连带动作**：改那一处，四屏一起变；⚠️ **不许因此写死字号**（`D3.5` 仍然有效：容器跟字算）。
**判据**：`v2/apps/mobile/lib/models/design.dart` · `lib/screens/app_theme.dart` · `test/widget/appearance_test.dart`。

### `D3.11` 从桌面上删掉一个图标 = 真回收 ＋ 二次确认

**结论**：桌面上删掉一个图标 = **真回收**，而且**必须二次确认**。一起拿走的四样：① 制品那一格 ② 那一间的工作区目录 ③ 那一间的对话记录 ④ 那一间里的数据。**留下来的两样**：审计（记一行"谁在什么时候删了它"）与用量/记账（随制品进回收区，**不是消失**）。
**理由**：他说的"删"就是不要了；留一半（比如只删图标、数据还在）会让"删了"变成假话。而四样里任何一样都够让他后悔，所以确认必须**把要拿走的东西摆出来**再问一次。
**连带动作**：⚠️ **拿不回来** —— 界面上**不许**承诺可恢复（今天没有任何入口能把它列出来）；盘上照旧留一份我们自己能捞的软删，但**界面不承诺**。⚠️ 这是"**同一时刻最多一条未收口**"那条不变量**唯一允许留号洞**的地方（被回收的那些号）——必须留痕。⚠️ 和"回收站"不是一回事：回收站管**单条对话**，这条管**一整个图标那一间**。
**判据**：`v2/services/core/test/app-remove.test.js` · `test/widget/desktop_remove_test.dart` · [`../dev/103-APP-DELETE.md`](../dev/103-APP-DELETE.md) §七。

### `D3.12` 聊天窗口的字分两档，非主要那一档"小很多、紧很多"

**结论**：**主要** ＝ 他的话 / 它的话 / 输入框里的字（一档大字号 ＋ 大行高）；**非主要** ＝ 工具行 / 过程行 / 通知 / 出处与状态小字 / 排队条 / 计划条 / 首页那句提示（**明显更小、行高更紧**）；**他自己发的话也跟着同一档**（主要那一档）。两档**都还在用户字号那条轴上**（相对它平移）⇒ 两档之间的差距不会漂；非主要那一档有**地板**（往小调到某一档时不许更小）。
**理由**：一屏里工具行和正文一样大，读起来没有主次、也更慢；而两档若各写死一对数字，用户一调字号就会互相错位。
**连带动作**：字缩小时，**围在它周围的空当按同一比例收一遍**（气泡内外 / 时间线上下 / 非主要行右边那颗展开箭头）；⚠️ **按钮不缩**（"读一遍"、菜单、撤销那些是**动作**不是"非主要的内容"——缩了会点不着），命中区照旧达标；数值只住 `models/dsh_design.dart` 那几个 token。
**判据**：`test/widget/chat_spacing_test.dart` · `test/widget/tool_rows_test.dart` · [`../dev/119-APPEARANCE-AND-FONT.md`](../dev/119-APPEARANCE-AND-FONT.md) §十。

### `D3.13` 壁纸跟着账号走，不按设备存

**结论**：他在**任一台设备**上挑的那张底图 ⇒ **别的设备登录也该看到它**。权威那一份进**账号**；本机那一份**降级成本机缓存 ＋ 离线兜底**；**亮暗与字号不动**（它们仍然是这台设备的偏好）。
**理由**：壁纸是"我的桌面"，不是"这台机器的桌面"；只存本机的话，换台设备就像换了一个别人的桌面 —— 而主人正是**看着文稿截图问出这件事**的（"这个用户设了壁纸，图上怎么没有？"）。
**连带动作**：三条合成规矩**多一条都不许加**：① **没问上**（网络不通 / 非 200 / 读不懂）⇒ 本机照旧、**一个字节都不写账号**（网不通 ≠ 他改了）；② 账号里"**从没记过**"⇒ 本机有就**顶上去**（老用户升级上来的第一下，不许把他挑过的那张抹成默认）；③ 账号里**有记录**（含"明确不设"那个值）⇒ **听账号的**。⚠️ `null`（没记过）与"空"（明确不设）**必须分得开**；写账号没成 ⇒ 本机照旧生效 ＋ 留一个待补标记，下次开机补一次（**不许假装同步上了**）。
**判据**：`src/prefs-store.js` · `models/wallpaper.dart` 的 `resolveWallpaper` · `test/unit/wallpaper_prefs_test.dart` · `test/widget/wallpaper_sync_test.dart` · [`../dev/183-WALLPAPER-ACCOUNT.md`](../dev/183-WALLPAPER-ACCOUNT.md)。

### `D3.14` 聊天底下那一格：一个真输入框 ＋ 那颗圆圈（`D3.14·补（十三）`）

**结论**：**就三步**：① 按一下那颗圆圈（开始听）；② **识别回来的字直接长在底下那个真输入框里** —— 半句/定稿边听边长，**他点进去随时能改**（他一动手，语音就不再往框里写，发的是他手上那份）；③ **按停** ⇒ 等 `asr/end` 那份**整段**回来 ⇒ **发一次**。
**理由**：中间那两层（"听懂 / 语义校正" / "反问"）去掉了 —— 它花掉一次真实往返，而用户要的只是"我说的话变成字、然后发出去"。**那个框跟打字是同一个**：开不了麦的机器上那颗「打字」摊开的就是它，一条「发送」发出去。
**连带动作**：🔴 **按停要"当场有反应"**（按下去这一刻这一格就变：圆圈不再闪"我在录"、字说"收下了"），但**最后那一份字一个都不许丢**；🔴 **在录时那颗圆圈一明一暗地闪** —— **动的只有颜色**，尺寸 / 位置 / 命中区一个像素都不动；🔴 听的那一段有**上限**（省钱），到点只是**接着开下一轮**、**字一个都不清、一次都不发**；说话时那一份字显示的是一张**不会滚的卡片**（从头显示、末尾省略），点一下才变成真输入框（4 行高、跟着光标会把开头卷出框外）。同一行里另有**两列小按钮**：**最左那一列**（上＝「清单」，点开＝"正在干的活"那张浮窗；下＝「键盘」，点开＝输入框 ＋ 键盘）与**圆圈右侧那一列**（上＝展开/收起，下＝播放语音）—— **两列同一个规矩**：两块 ＋ 中间那条缝 = 那颗圆圈的直径，**四颗的上下沿逐像素对齐**（判据钉着这条等式），**两端留白相等**。
**判据**：`widgets/voice_bar.dart` · `widgets/chat_floater.dart` · `test/unit/voice_compose_test.dart` · `test/widget/voice_send_test.dart` · `test/widget/voice_buttons_test.dart` · `test/widget/work_list_test.dart` · [`../dev/214-VOICE-REBUILD.md`](../dev/214-VOICE-REBUILD.md) · [`../dev/210-VOICE-CONTINUOUS.md`](../dev/210-VOICE-CONTINUOUS.md)。

### `D3.15` 每个小程序右上角一颗「退出」；底下那颗 home 取消

**结论**：进任何一个 app（他自己的小程序 / 内置那几格）那一屏，**右上角**都有一颗「**退出**」（＝离开这一屏、回桌面）；底下那条里那颗 **home 取消**（同一件事只有一条路）。字要说人话，不许"返回 / 关闭"混着叫。
**理由**：主人原话是"所有的 app 右上角都有一个退出按钮。所以我不再需要 home 按钮" —— 两颗做同一件事，屏幕上就多一个要分辨的东西。
**连带动作**：🔴 **同一时刻只许有一颗**：网页上"真小程序"是 DOM 元素、压在画布上面 ⇒ 那一颗**由页面那一层画一遍**，Flutter 那颗**不画**（内置那几屏由 Flutter 画）；命中区达标、字与图形一起给。
**判据**：`widgets/mini_app_host.dart` · `models/space_words.dart` 的 `miniAppExitLabel` · `test/widget/mini_app_exit_test.dart` · [`../dev/183-VOICE-FIRST-CHAT.md`](../dev/183-VOICE-FIRST-CHAT.md)。

### `D3.16` 小程序那一屏的层次：网页让一格、安卓铺满、内置那几屏两种平台都让

**结论**：🔴 **网页 ＝ 内容不铺满**：平台视图那个矩形**底部让出一格**（那颗录音圆圈 ＋ 它那行住在这里、**由 Flutter 画** ⇒ **两端同一份实现**）；🔴 **安卓 ＝ 铺满**（内容顶到四边，聊天与圆圈天然在最上层）；🔴 **内置那几屏**（设置 / 发现）**两种平台上都让** —— 它们是"内容"，被收起条压住就点不到。三条收成**一个纯函数**。
**理由**：网页上真小程序是**真的 DOM 元素（iframe）**，永远画在 Flutter 画布**之上**；手机（安卓）上没有这条限制（平台视图在画布**之下**）。这是浏览器/平台定的事实，不是取舍 ⇒ 想"一份实现"就去加壳（丙）的代价是那一帧的 CSP 与嵌套（`frame-ancestors` 只认主那个源 ⇒ 制品那个源被拒 ⇒ 壳里一片空白），得不偿失。
**连带动作**：⚠️ 那条内缩**只许用稳定值**（绝不许喂"浮窗每帧的高度"——每帧 resize 一个真 iframe 会把动效卡没）；⚠️ 出口那颗「退出」也按这条"同一时刻只许一颗"来分（`D3.15`）。
**判据**：`models/mini_frame.dart` 的 `miniAppBleedsBottom` · `test/unit/mini_native_test.dart` · `screens/chat_screen.dart` 的 `bottomInset`。

### `D3.17` 顶上那一条（系统状态栏）：桌面跟壁纸走，别的屏归壳

**结论**：🔴 **面上那一条归壳**：**桌面**那一屏露的是**壁纸**（图标跟着**那张壁纸的顶部**走，不设壁纸时就是那张暖纸 ⇒ 深色图标）；**小程序 / 内置那几屏**顶上那一条是**壳自己的纸色**（那个会长到全屏的面盖到 `y=0`）⇒ 图标**固定深色**；其余屏（登录 / 首页 / 等待）默认也是壳那张纸。
**理由**：小程序是**第三方 HTML**，我们**读不到它的颜色**（也不许注入脚本去读）⇒ 图标没法"跟着页面走"；把页面铺到状态栏下面就只能固定盖一层渐变，而页面第一行又会压回时钟底下（真机报过"第一行压在时钟底下"）。
**连带动作**：交出方式**只有一处**（一个 `AnnotatedRegion` 包住真正盖住那一条的那一层：Flutter 在状态栏正中取样，**谁盖在顶上谁说了算**）；桌面那 28 张壁纸的顶部深浅是**离线量过的**，不许现算。
**判据**：`widgets/system_bar.dart` 的 `SystemBarTint` · `models/wallpaper.dart` 的 `wallpaperDarkTop` · `test/unit/wallpaper_top_test.dart` · `test/widget/system_bar_test.dart`。

## 第 6 族 · 设备与小程序（`D4` / `P-b`）

### `D4` 设备优先级取丙：手机是主目标，平板是主开发

**结论**：每一版**先在主人的平板上看**（十一寸安卓平板是第一现场），而**手机是所有功能的最终落点**。
**理由**：走查里平板那位说的是"**我放弃的不是这个产品，是在平板上用它**"；嘴上说"手机优先"最容易在开发里变成"宽屏以后再说"，而**他每天亲眼看的坏东西会绑住他后面两周的排期** —— 宽屏不是第 1 批顺带做的，它就是第 1 批的验收场景。
**连带动作**：交付后横屏仍然难看 ⇒ **明说"平板横屏还没做好、已知"**，不许用"排后"把话混过去（一个人的产品里，"以后"＝永远）。
**判据**：[`01-PROJECT.md`](01-PROJECT.md) §十 · [`08-SPEC.md`](08-SPEC.md) §六 · [`../dev/50-DESKTOP-FLOATER.md`](../dev/50-DESKTOP-FLOATER.md)。

### `D4.1` 手机是主目标设备，平板是主开发设备

**结论**：**手机**（窄屏那一档）是主目标 —— 界面的默认假设按它定；**平板**是主开发设备 —— 每一版真机确认先在那上面做。桌面上那个浏览器窗口只是开发时的镜子，**不拿它当验收现场**。
**理由**：两者会给相反的暗示（手机说"省地方"、平板说"地方多的是"）——只有把"在哪儿看"写死，宽窄两种屏才不会各写一套；而手机上能过、平板上一摊开就散的东西，只有在平板上看得见。
**连带动作**：任何一种屏上发现的形状问题，**先按"两种屏都要成立"改**；确实只能取一边时，明写取舍与代价（[`08-SPEC.md`](08-SPEC.md) §六 那几条规格）。
**判据**：[`01-PROJECT.md`](01-PROJECT.md) §十 · `test/widget/accessibility_test.dart`（五档字号都不溢出）· `test/widget/safe_area_test.dart`。

### `D4.2` 宽屏不能只是"排后"

**结论**：宽屏（平板横屏 / 桌面）**从第一批起就是验收场景**，不是"以后优化"。
**理由**：走查里那条原话是"**浮窗高度是'屏幕高的百分比'，不是'我想读多高'**"——他放弃的正是"我要一边做别的事、一边跟我说话"这一步（横屏拉满时桌面只剩一条顶缝）。宽屏不是"还没学过"：**按屏幕高的百分比定浮窗高度**这个形状本身在宽屏上就是坏的。
**连带动作**：宽屏那一档的判据必须和窄屏同批量（[`08-SPEC.md`](08-SPEC.md) §六 的 Z 系列）；不许把"宽屏上难看"记成欠账就过去。
**判据**：[`01-PROJECT.md`](01-PROJECT.md) §十 · [`../dev/50-DESKTOP-FLOATER.md`](../dev/50-DESKTOP-FLOATER.md) · `test/widget/accessibility_test.dart`。

### `D4.3` 浮窗只有两档：收起 / 拉满

**结论**：浮窗**两个档位**：**收起**（底下那一格：他说的话 ＋ 录音圆圈 ＋ 展开 ＋ 播放语音）与**拉满**（时间线 ＋ 输入条）。**没有半开、没有拖着改高度**，所以也**不存在"转屏回到最近绝对档"**——转屏时档位不动，要变档是他自己按。
**理由**：档位一多，"我想读多高"就变成"系统说多高"；而"拖着改高度"会让另外两条判据失去对象（发出去拉满、只有状态变化时一个像素都不动）。收起档的高度**由内容算**（`D3.5`：容器跟字算），也不是第三个数。
**连带动作**：换档要带**防抖**（连续触发合并成一次）；收起档**没有那个框**（它就是浮在桌面上的那一格），展开档照旧是白底不透明。
**判据**：`v2/apps/mobile/lib/widgets/chat_floater.dart` 的 `FloaterTier`（只有两个值）· `test/widget/desktop_floater_test.dart`。

### `D4.4` 自动拉满必须收敛

**结论**：**他一发出去 ⇒ 拉满**；**只有状态变化（它在想 / 在做）⇒ 不动**；短时间内的连续换档**合并成一次**。反过来说：窗口不许自己反复长高又缩回。
**理由**：助手一次连发好几段（状态、工具行、正文）时窗口跟着抖，读的人只会以为页面坏了；而"发就拉满"是"要读要写"那一半唯一的信号 —— 它必须准，不能靠抖动来表达。
**连带动作**：换档带防抖窗口（数住代码）；换档时把"刚才那一眼"的那张清单收掉（它属于那一档，不该跟着窗口飘）。
**判据**：`widgets/chat_floater.dart` 的 `debounceMs` · `screens/chat_screen.dart` 的 `onTier` · `test/widget/desktop_floater_test.dart`。

### `D4.5` 内容列限宽 ＋ 居中

**结论**：聊天那一块（时间线、输入条、气泡、过程行）**限宽并居中**，左右留白随屏宽自己长；窄屏上它本来就占满，等于没有这一层。
**理由**：平板上不限宽，一行能排七十来个字，眼睛找不到下一行的开头 —— 那位用户"左列能翻、右边能读能写"的期待，落在屏幕上首先就是这一条。
**连带动作**：那个数**只有一处出处**（`models/design.dart` 的 `contentMaxWidth`）；所有用它的那一格必须取同一个数（正文与输入条同一个列宽，录音圆圈与展开箭头才对得齐）。
**判据**：`v2/apps/mobile/lib/models/design.dart` 的 `contentMaxWidth` · `screens/chat_screen.dart` 的 `_chatPane` / `_composer` · `widgets/bubbles.dart` · `widgets/process_view.dart`。

### `D4.6` 内容列取 `760`

**结论**：内容列那个数是 **`760`**，出处只一处（`lib/models/design.dart` 的 `contentMaxWidth`，纯数据）。
**理由**：同一个数写在五处，改一处就漏四处 —— 而漏掉的表现是"输入条里那颗圆圈和展开那颗箭头对不齐"，**没人会把它当成 bug 报上来**，只会觉得这个 App 有点糙。
**连带动作**：改就改那一处，五处一起变；⚠️ 不许因此写死字号（`D3.5` 仍然有效：容器跟字算）。
**判据**：`lib/models/design.dart` 的 `contentMaxWidth` · 各调用点（`chat_screen` / `bubbles` / `process_view`）。

### `P-b` 内容列与外壳：**列宽只有一个数**

**结论**：内容列与外壳之间的宽度关系由**一个数**定（`contentMaxWidth`），窄屏上列宽等于可用宽、宽屏上它居中，**没有第二处再限一次**。
**理由**：两处各限一次，改一处另一处就成了"看不见的边界"——现象是"某个宽度区间里内容贴边、再宽一点又跳回来"，而代码里搜不到那个数。
**连带动作**：`about_screen` 那种纯文字页也取同一个数（不然"读一句长话"在设置里和在聊天里是两种排版）。
**判据**：`lib/models/design.dart` 的 `contentMaxWidth` · `screens/about_screen.dart` · `screens/chat_screen.dart`。

### `D4.7` 不做左右两栏

**结论**：**桌面（图标墙）与聊天（浮窗）是前后两层，不是同屏左右分栏**；宽屏上只是把同一个内容列居中，不把"清单"塞到聊天旁边。
**理由**：两栏承诺的是"左边翻、右边读写"，而那两个入口今天各自已经是一整屏；再挤一块，等于在一个已经放得下的地方造第二套布局 —— 而手机那条路一个字都用不上，却要跟着一起维护。
**连带动作**：真要"一边看清单一边聊"，走既有的那条路（点空白收起聊天 ⇒ 桌面露出来），不新造第二套骨架。
**判据**：`screens/chat_screen.dart`（只有 `Center` ＋ 限宽，没有分栏）· `test/widget/desktop_floater_test.dart`。

### `D4.8` 新增助手消息触发的高度变化 = `0px`

**结论**：**除了"他发出去"与"他自己换档"这两件以外**，任何东西上屏都不许挤动布局：助手新说的话、状态行、工具行、通知、排队条、在做的角标、那张「正在干的活」清单 —— 前后量同一个矩形，**一个像素都不许动**。
**理由**：每说一句桌面就被抹掉一次，是平板那位用户的主要放弃点；而"界面自己会抖"这件事，用户不会报成 bug，他只会少用。
**连带动作**：这条是**给闸用的**：量的是几个关键矩形的 `Rect`（浮窗体、顶栏、输入条），通知/清单那几条路都拿它当约束；新加任何一块上屏的东西，先问它会不会挤动这几处，会就把它做成 `Positioned` / 叠层。
**判据**：`test/widget/desktop_floater_test.dart` · `test/widget/notice_shape_test.dart` · `screens/chat_screen.dart` 与 `widgets/notice.dart` 里那两处点名 `D4.8` 的注释。

### `D4.9` 转屏不改档；阅读位不重建，"跟到底部"另有一条规则

**结论**：转屏**不改档位**（没有"绝对档"可吸附），**阅读位**由那棵树自己的滚动位置保住（换档与转屏都不重建它）；而"**要不要跟着新消息到底部**"由一条纯函数管 —— 他自己往上翻过，就**不跟着跳**；要回最新，按那颗**「回到最新」**。首屏直接跳到底，不做动画（历史长时从最老一路滑下来很吓人）。
**理由**：转屏时把档位吸到"最近的一档"会在两个形态之间制造一个他没按过的状态；而"跟到底部"这条规则**很容易算错**（判据只有"离底部多近"时，首屏 `pixels == 0` 对上一屏历史恒为假 ⇒ 打开就停在最老那一条），所以它必须是一条能被离线钉住的纯函数，不是界面里的 `if`。
**连带动作**：那条宽容带、以及"用户自己滚过没有"这个标志，都住在 `models/scroll_follow.dart`；界面只执行它给的动作。
**判据**：`v2/apps/mobile/lib/models/scroll_follow.dart` · `test/unit/scroll_follow_test.dart` · `test/widget/scroll_follow_test.dart`。

### `D4.10` 内置那两格保留（它们是"这不是我的东西"的锚）

**结论**：桌面上**设置**与**发现**两格是内置的、**永久保留**；它们**不是制品**（不能发、不能装、也不能被助手造出来）。
**理由**：撤掉内置图标，第一天桌面就是空的 —— 而"空桌面"是十人走查里最一致的**发慌点**；这两格是"有些东西本来就在这儿"的锚。反过来说，保留 id 与"哪些是房间"必须是一份名单，**保留名单 ＝ 主线 ＋ 内置那几格**，这条等式不许破。
**连带动作**：助手造小程序时，`main` / `settings` / `discover` 一律**人话拒**（"这是桌面上本来就有的那一格"）；发现那一屏**只读**，它自己不能装。
**判据**：`v2/services/core/src/worlds.js` 的 `BUILTIN_SCOPES` · `src/apps.js` 的 `REFUSED_APP_IDS` / `refuseReservedAppId` · `test/unit/app_spec_test.dart` · `test/widget/desktop_test.dart` · [`09-APPS.md`](09-APPS.md) §1.3。

### `D4.11` 手机上的第一入口仍是图标墙

**结论**：登录之后先看见的是**桌面那一墙图标**（手机上是图标墙，宽屏上是同一墙、每行格数随屏宽变、**列数只由屏幕定**）。
**理由**：第一入口是"我这台上有什么"（`D1` 的隐喻与 `D4.10` 的锚都落在这面墙上）；把入口改成列表或搜索框，等于让用户先学一个新东西才能看到自己已有的东西。
**连带动作**：加/删一格时**已有的格一个都不许挪位**（列数只跟屏幕有关，跟图标个数无关）；图标大小与间距也跟着屏幕走，**不许写死**。
**判据**：`v2/apps/mobile/lib/widgets/app_desktop.dart` · `lib/models/desktop_grid.dart` · `test/unit/desktop_grid_test.dart` · `test/widget/desktop_test.dart`。

### `D4.12` 聊天不是桌面上的一个小程序

**结论**：聊天是**永续的那条浮窗** —— 它永远在底下，桌上**没有「会话」图标**，也没有"打开 / 关掉聊天"这件事；图标墙是**第一入口**，但入的是**小程序**，不是聊天。
**理由**：主人原话是"聊天和桌面是独立的，聊天是永续的，永远在底下"；一旦它是桌上的一格，它就变成"关掉了就没了"的一条会话，与"永远在底下"直接矛盾 —— 而"聊天不见了"这件事，用户第一个念头会是"是不是被我删了"。
**连带动作**：任何"给聊天加一个入口"的提议先回到这一条；首页/桌面上的那一格只能是**设置**或**发现**或他自己的小程序。
**判据**：`test/widget/desktop_floater_test.dart`（桌面上找"会话"两个字 ⇒ 一条都不许有）· `lib/models/space_words.dart`。

### `D4.13` 桌面上是「设置」这个小程序

**结论**：**设置**是桌面上的一格、一个正经的小程序（不是抽屉、不是抓手行上的一颗按钮）；它管三件：**退出登录 · 注销账号 · 换钥匙**（＋「关于」搬进来）。进这一屏之后，**出口是右上角那颗「退出」**（`D3.15`）。
**理由**：退出登录**不属于聊天那一行**（那一行是"聊天"的地方，而退出登录不是聊天的事）；把它放在桌面上那一格里，动作才落在它自己的家里。
**连带动作**：这一屏的**全部文案**只许住 `models/space_words.dart`（那样才进得了禁用词闸）；它被聊天盖住时要**看得出来**，收起时内容**内缩**、不许压住可点的东西。
**判据**：`screens/settings_screen.dart` · `models/space_words.dart` 的 `settingsAppLabel` · `test/widget/settings_test.dart` · [`../dev/126-MINIAPP-NO-HEADER-HOME.md`](../dev/126-MINIAPP-NO-HEADER-HOME.md)。

### `D4.14` 小程序分两种，别混

**结论**：**内置形状**（我们自己画死在壳里的那几屏：设置 / 发现）与**真制品**（别人或助手写的 HTML，跑在沙箱里）是**两种东西**；这一族管的是后者。
**理由**：混起来的代价是"权限"那一层无处安放 —— 内置那几屏没有"能力要授权"这回事（它们就是我们自己的界面），而真制品必须有（五样能力要他点头）。
**连带动作**：内置那几屏**不能被助手造出来**（保留 id 那道闸直接拒）；真制品从制品原点取、走一条现签的短时效 URL，两端（网页 / 安卓）吃同一个响应头。
**判据**：[`09-APPS.md`](09-APPS.md) §1.3 · `src/worlds.js` 的 `BUILTIN_SCOPES` · `test/unit/mini_sandbox_test.dart`。

### `D4.15` 制品口有自己独立的域名

**结论**：壳与制品**不同源**：壳在 `w.` 那个域，跑第三方代码的制品在 `apps.` 那个域（`N1` 的落地）。
**理由**：同源的话，制品里一行 `parent.document` 或一次 `fetch('/api/…')` 就能读到壳的存储、拿壳的身份说话 —— 那等于**把令牌交给第三方代码**；分开之后制品只能算/画，以及对它自己那个原点发那几条窄口请求。
**连带动作**：🔴 **同一个 origin = 整套白做**；那条 `sandbox` 取值与那条 CSP 都是这条不变量的执行手段，不许为了"省一次跳转"合并两个原点。
**判据**：[`08-SPEC.md`](08-SPEC.md) §一 `N1` · `v2/apps/mobile/lib/widgets/mini_runtime_web.dart`（`sandbox="allow-scripts"`）· `test/unit/mini_sandbox_test.dart` P1-7。

### `D4.16` 发布 ＝ 复制进共享库；装 ＝ 复制进他自己那一格

**结论**：**发布**把"他现在那一份"打成一版放进共享库；**装**把那一版复制进**他自己那一格**（作者下架/删除之后，**装过的人那份还在**）；`id` **全局唯一**（重名当场拒 —— 客户端图标按 `id` 认人）。共享库里**不存作者身份**：对外只给昵称，内部只存**凭据哈希**。
**理由**：一次"出界"就是把用户盒子里的东西送出去了，而**送出去收不回来**；而 `id` 一撞，桌面上两格指向同一份制品，用户点哪个都不知道自己进的是谁家。
**连带动作**：作者假名是**带键 HMAC-SHA256**（与审计身份同一个函数），存量老值只读、新写一律新口径，**认不出一律 fail-closed**；发布那一步"真跑一次"分级验（只验"能跑起来的最小判据"）。
**判据**：`src/published.js` · `src/cred-hash.js` · `test/published-author-hash.test.js` · `test/app-install-fork.test.js` · `scripts/check-index-author-hash.sh` · [`09-APPS.md`](09-APPS.md) §5.4／§5.6／§5.7。

### `D4.17` `ask` 用**看的人**自己的钥匙

**结论**：小程序"问一句"花的是**看这个页面那个人**的钥匙 —— 制品**永远拿不到钥匙**；花这个动作发生在**他自己的环境**里（租户＝他盒子里那个小代理；主人＝本机那个代理读 DSH 凭据）。四道闸**一道都不能少**：在他这儿 · 清单里**声明了** · 他**授予了** · 配额还有。
**理由**：甲发的小程序被乙装上之后花的是乙的钱 —— 这既是主人点名的规矩，也是唯一自洽的形状（钥匙在环境里，不在页面里）；而少一道闸，一个别人写的页面就能拿你的钥匙说话。
**连带动作**：走**直连模型**（没有工具、没有工作目录、改不了任何东西）——因为"来源分级→只读档"那一层今天不建，把别人写的话丢给一个全权执行体是最怕的形状；每天有上限、撤权立刻不通、花销进账。
**判据**：`src/server.js` 的 `checkAppAsk` · `src/app-ask.js` · `test/app-ask.test.js` · `test/app-ask-fetch.test.js` · [`09-APPS.md`](09-APPS.md) §3.4.2。

### `D4.18` 一切操作都在对话里

**结论**：造 / 看 / 发 / 撤 / 发现 / 装 / 卸 / 授权 / 撤权 —— **九件都是对话里的工具**；屏幕上只有**桌面图标墙**、**桌面上那颗空心加号**与**只读的「发现」**。
**理由**：多一个屏幕上的入口，就多一处"新手要学的东西"，也多一处能绕过"他明说才许写"那道闸的路；而那九件工具全部在对话里，`D4.25` 的"当场做"才有落点。
**连带动作**：那颗加号是**唯一**一处"屏幕上的入口也能造东西"——它造的是**空壳**（名字 ＋ 可选的描述 ⇒ 空白项目 ＋ 登记 ＋ 占位页），**内容仍然只从对话里来**；助手自己想到的、或从别处读到的，**只许提**（`P1`/`P2`）。
**判据**：`src/mcp-apps-server.mjs`（九件工具）· `src/apps-consent.js` · `test/widget/create_app_test.dart` · [`09-APPS.md`](09-APPS.md) §5.2 · [`../dev/127-CREATE-APP-FROM-DESKTOP.md`](../dev/127-CREATE-APP-FROM-DESKTOP.md)。

### `D4.19` iOS 商店版不发布小程序运行时；安卓有原生运行时

**结论**：**iOS 恒假**（`kNativeMiniRuntimeIOS = false`，装钩子那一步只在安卓上做）；**安卓那侧有原生运行时** —— 一个**普通 WebView、不装桥**（所以 `ask` 在原生上没有）。

**连带动作**：那三条判据**照旧在**，主标记由**两个平台各说各的**（"让将来做原生的人不可能忘"）；安卓清单要有 `RECORD_AUDIO` 与 `CAMERA`，而 `uses-feature` **不许写 `required="true"`**。

### `D4.20` 「奥数题」不在产品里

**结论**：桌面上那一格、它那一屏、它那几句文案、客户端那一套常量与登记、服务端保留房间名单里的 `math` —— **一起去掉**；内置那几格今天只剩**设置 / 发现**。
**理由**：它没有用户、也没有一条"它服务谁"的说法；留着就是桌面上多一格要分辨的东西（与 `D4.10`"内置图标是锚"并不冲突 —— 锚是那两格本来就有的，不是每一格都要留）。
**连带动作**：🔴 盒里 `math` 那一间**已有的数据一个字节都不动** —— 那是他**说过的话**，移除功能不等于销毁历史；代价如实认下：那一间**从此进不去**，要清得单独说（走 `D3.11` 那条真回收）。
**判据**：`src/worlds.js` 的 `BUILTIN_SCOPES` · `src/apps.js` 的 `REFUSED_APP_IDS` · [`../dev/105-DROP-MATH.md`](../dev/105-DROP-MATH.md)。

### `D4.21` 用户端没有"包"：版本快照只在市场里存在

**结论**：他自己那一份**就是一段活的源代码部署**（`workspaces/<id>/` 现在的字节 ＋ 一份登记）；**"版本 / 快照 / 压缩 / 回滚"只属于"包"** —— 尺寸、文件数那三道上限**只在发布那一侧**查。发布＝把"现在那一份"打成一版；从市场装来＝"把包拉下来变成他自己的源代码部署"，此后各用各的。
**理由**：他开发的过程就是对**当前这一版**改内容、改功能，"落一版才看得见"在用户端不成立；把"包"的规矩挂到用户端，代价是他被一堵**我们造出来的墙**挡住（真机现场：助手为了把那一页塞进上限，开始"压答案 / 拆成两个图标"，而他那一间里明明是一大份活文件）。
**连带动作**：代价如实认下 —— 他自己那份**没有版本可回退**（要留底先发一版）；`app_publish` 之后他那一格里**会多一个 `versions/<n>/`**，那是刻意的（发布本来就属于市场那一侧）。
**判据**：`test/app-user-side.test.js` V1–V5（每条都能反着验）· [`09-APPS.md`](09-APPS.md) §六 · [`../dev/114-APP-USER-SIDE-NO-LIMIT.md`](../dev/114-APP-USER-SIDE-NO-LIMIT.md)。

### `D4.22` 两格载体 ＋ 三条出去律 ＋ 一对一数据 ＋ 撤回

**结论**：**两格载体**：硬边界只看**路径**（任一段以 `.` 开头 ⇒ 不进制品、不跟着装走）⇒ 只产出两格 —— `<scope>/.exp/<包>/`（经验）与 `<scope>/.data/<包>/`（数据）；**目录名不承重、声明承重**（`mv` 换一格，出界结论逐条不变）。**三条出去律**（是路，不是格）：**随制品走**（能力体）／**作者逐条声明才出**（经验包，`share:true` 且**带锚**）／**收方一对一同意且可撤回**（数据包）。
**理由**：把"能出去"画在目录名上，改名就能绕过去；而"读不到声明／认不出 ⇒ 拒"（默认最严，不是"当没有"）是唯一挡得住"一次出界送出去收不回来"的口径。
**连带动作**：今天全仓**只有一条出口**（写共享库只有 `published.publish` 一个写入者）；**撤回不是第四条出去律**，它是数据**交付边**的属性 —— 只改未来（新请求一律拒），**不删**对面已经拿到的那一份 ⇒ 回执对"对方那份还在不在"**只许说"不可算"**；三条登记边各住各的（`N32`），登记边**不承重**。
**判据**：[`08-SPEC.md`](08-SPEC.md) §一 `N31`／`N32` · `src/published.js` · `src/delivery.js` · `test/outbound-resident.test.js` · `test/outbound-single-exit.test.js` · `scripts/check-outbound-bridge.sh` · [`../dev/161-EDGE-KINDS-GATE.md`](../dev/161-EDGE-KINDS-GATE.md)。

### `D4.23` 与 DSH 对齐的是"内容与信息处理方式"，视觉是我们自己的

**结论**：聊天窗口对齐的是**内容与信息处理方式**（工具行 / 一轮一折 ＋ 计数 / 每轮用量 / 排队插话 / 系统提示词行 / 外观与字号），**视觉与形态仍然是我们自己的**（浮窗不动）；"直接用 DSH 那扇窗"那条路**不在产品里**。
**理由**：对齐内容能省掉"用户要学一个新窗口"这回事，而把视觉交出去等于放弃浮窗那几条铁律与"这是琥珀的窗口"这件事；至于直接用那扇窗，代价是那份内存钱与"第二扇窗"的存在感 —— 而产品里**没有第二扇窗这一格**（`D4.31`）。
**连带动作**：内部词**继续不上屏**（人话化之后该有的信息补全）；要进那扇原始窗口只有一条路 —— **开发者模式的签名链接**（`D4.31` 留下的那一半）。

### `D4.24` 出去律那 11 条

**结论**：**A1** 上架粒度＝制品先上（数据随 fork 只走一份**形状声明**：形状随版本冻结、**值永不随**）· **A2** 发布**必须真跑**但**分级**（只验"能跑起来的最小判据"）· **A3** 制品入口 URL **去掉明文 `sub`**（绑人绑进签名；审计里换**凭据哈希**）· **B1** 署名＝**可换可弃的假名** ＋ 血缘公开可查 ＋ **真身份不给** · **B2**「同装共现算不算相关」**先挂着**（前提：审计里的明文 `sub` 先修 —— 同 A3）· **B3**「相关」默认值＝**沉默** · **C1** 升级＝**分级派**（契约版未变 ⇒ AI 重写计数 ＝ 0）· **C2** 回流＝**上游点头制** · **C3** 升级粒度＝**默认按用户、允许按 app 留旧版** · **D1** 框架＝**代码 ＋ 数据契约**（每个 app 一份声明过边界的数据）· **D2** 上架资格＝**框架合格即可**（人不签）。
**理由**：这 11 条是"东西出去之后会发生什么"的全部答案 —— 每一条都对应一种"送出去就收不回来"的具体形状（真身份、明文身份、静默回流、静默升级）；定成默认严的那一边，是因为松的那一边出事时没有第二次机会。
**连带动作**：A3／B1 已经落进 `published.js`（作者凭据哈希、审计里不写明文 `sub`）；**B2 仍然挂着**，它的前提（A3）已经修掉，但"算不算相关"本身还没定。
**判据**：`src/published.js` · `src/cred-hash.js` · [`09-APPS.md`](09-APPS.md) §5.5／§5.7 · [`../dev/161-OWNER-DECISIONS-11.md`](../dev/161-OWNER-DECISIONS-11.md)。

### `D4.25` 做一个东西：有存储就一起做、做完要说完成

**结论**：四条行为**一条都不能少**：**① 触发** —— 他这一轮说"帮我做一个…"（小程序 / app / 应用 / 游戏）⇒ **当场动手造内容**，不是只聊方案；**② 判断存储** —— 造之前/造的时候判断有没有数据要存（清单 / 账 / 分数 / 配置 / 他填过的表），**默认当有**，有就**一起做进去**；**③ 上桌面** —— 交付的就是**他桌面上的一格**；**④ 报完成** —— 做完**明确告诉他"做完了"**（它叫什么 / 能做什么 / 会记住什么），**不许静默、不许半成品当成品**。
**理由**：来由是真机那次"天气小程序"——做成的是一张**存不了数据**的卡片，而且**没先明说**"每天定时抓做不到"；这一条防的正是"**造了但存不了 / 做了但没说清**"。
**连带动作**：🔴 **四条里哪一条做不到 ⇒ 当场如实说清是哪一条做不到**（不许假装）；那"有存储"的一半落在运行时那一格天生就有的库（数据格另配一份形状声明）。
**判据**：`v2/services/core/test/persona.test.js`（源码级）· `scripts/check-app-storage-rule.sh`（含负向对照）· [`../dev/167-APP-STORAGE-RULE.md`](../dev/167-APP-STORAGE-RULE.md)。

### `D4.25·补` 「他明说才许写」里的"明说" ＝ 语义上要了

**结论**：他只要**语义上要了**一个东西（"做一个记账的" / "我要一个能玩的小页面" / "把数独内容放到小程序里面"）就算**明说** ⇒ 助手当场做、做到桌面上；**不许**要他补一句"帮我做一个……"，也**不许**反问"你是要我做吗"。**"接着说"也算同一件事**（他先要了、接下来几轮讲怎么改 ⇒ 那几轮照旧算数，看的是同一间里他最近说过的那几句）。
**理由**：真机现场是他问"我做好了吗？冷吗"，助手把**那一间已经有的那个小程序再登记一次**被拒 ⇒ 掉头去读源码找那句拒绝，**过了好一会儿**才回一句"做完了"。判据那条线没松：仍然只读**服务端自己记的他自己的话**，请求里带什么一个字都不看；**助手自己发起的那一轮**（定时、重做、别人代投）**照旧一律拒**。
**连带动作**：**只放一种** —— 同一间的"再登记"不需要"明说"（那一格已经在他桌面上，不是"往他桌面上放一个他没要的东西"）；主线里造新东西、在**别的小程序**里造东西，照旧要明说。
**判据**：`src/apps-consent.js` · `test/apps-consent.test.js` · `test/app-write-gates.test.js` · [`../dev/176-SAYING-IT-COUNTS.md`](../dev/176-SAYING-IT-COUNTS.md) · [`../dev/201-REREGISTER-SAME-APP.md`](../dev/201-REREGISTER-SAME-APP.md)。

### `D4.26` 包的身份从哪来 ＝ **页面自带身份**

**结论**：平台把"**你是哪个 app 的哪个包**"注入给页面（一只**窄口**：页面只能读/写**它自己那一格**）；**不许从 URL / 查询串拿包名**。
**理由**：从 URL 拿就变回"页面说了算"，等于把"平台按命名空间隔离"降级成"命名约定" —— 而命名约定挡不住一个就想看别人那格的页面。
**连带动作**：那条判定**只有一处**（`src/data-namespace.js` 的解析口，别处零重抄）；⚠️ **今天它在 `src/` 里还没有产品调用方**（只有判据引它）—— 运行时那条 `/db` 口认的是"**app 原点 ＋ 一次签名换票**"，而"**页面自称的包名**"那一侧一律不认。
**判据**：`v2/services/core/src/data-namespace.js` · `test/data-namespace.test.js`（`D1`–`D6`，含"只在那一处"的源码级判据）· `test/app-db.test.js`。

### `D4.27` "还在做"的那一格：灰底 ＋ 转着的圈，点了只说一句

**结论**：做一个小程序 ⇒ **先在桌面上加出这一格**，但那一格长得不一样（**灰底 ＋ 灰图形 ＋ 中间一个转着的圈** ＝ "它在做、还没好"）；**点它不打开**（那一间里只有一页"这里还空着"），而是**说一句**「这个小程序还在做，做好了我告诉你」。做完之后那一声会让桌面自己重拉清单 ⇒ 那一格**变回它自己的身份色**。
**理由**：桌面是唯一"我这台上有什么"的地方 —— 如果它要等到做完才出现，那几分钟里用户看不到任何动静（★1 那条"发出去之后没有任何活着的信号"）；而"做好的画成灰的"比晚一秒变灰坏得多，所以判据只认服务端那条事实。
**连带动作**：判据是 `/api/apps` 的 **`building`**（入口那一份不在、或者逐字节还是我们写的占位页 ⇒ `true`）；⚠️ **拿不到那条事实一律 `false`**（"不知道"不许画成"在建"）；不落盘（算出来的）。
**判据**：`src/apps.js` 的 `#building` · `src/worlds.js` 的 `isBuilding` · `test/app-create.test.js`（**S2′** 占位页还在 ⇒ `building=true`；入口被真内容顶掉 ⇒ `false`）· `test/widget/app_building_test.dart` · [`../dev/175-BUILDING-ICON.md`](../dev/175-BUILDING-ICON.md)。

### `D4.28` "这一间正有活在做"：那一格右下角一个小圈

**结论**：`/api/apps` 每条带 **`working`**（与"那件怎么样了"读的是**同一本活账**）；有活开着 ⇒ 那一格**右下角多一个转着的小圈**（**底色不变、点它照样打开** —— 这是一个状态，不是一道门）；活收口 ⇒ 圈**自己灭**（不是"做过就算"）。
**理由**：用户在桌面上该看得见"它还在替我干活"——那是最值钱的一条信号；而"做过就算"会把一个已经停了的活显示成在跑，那又是页面在说假话。
**连带动作**：与 `D4.27`（在建）**是两件事**，可以同时发生（两个圈，位置与颜色都分得开）；🔴 **租户那一条以盒子里那份为准**（活在他盒子里跑，拿宿主那份覆盖 ⇒ 症状是"桌面上永远不亮"，而单租户判据全绿）；**拿不到那条事实一律 `false`**。
**判据**：`src/worklog.js` 的 `world.work.live()` · `test/app-working.test.js` · `test/widget/app_working_test.dart` · [`../dev/178-APP-WORKING.md`](../dev/178-APP-WORKING.md)。

### `D4.29` 桌面必须自己刷新 —— 三半都要有

**结论**：每一格的状态**不许靠他手动刷新页面**才变。**三半缺一不可**：**① 信号** —— 那一间的工作区内容直接变了、而且不再是"在建" ⇒ 服务端往他的流里推一条 **`app/installed`**（＝"桌面可能变了"）；**② 退回桌面** —— 从某一间点「退出」回桌面 ⇒ **重拉一次清单**；**③ 切回来** —— 这一屏从后台回到前台 ⇒ **重拉一次清单**。
**理由**：那些帧是**瞬态**（不补发）—— 他**没在看**的那段时间发生的事，回来时一条都收不到（②③补这一课）；而他**正看着桌面**时没有任何"回来"的动作（①补这一课）。
**连带动作**：① 只在"**真的会变**"时喊（一次多余的清单重拉对租户就是多开一趟隧道）；**不新造事件类型**（复用"桌面可能变了"那一条）；**轮询不做**（买不到另外两种情形之外的正确性，却是持续的隧道流量）。
**判据**：`src/app-live.js` · `src/worlds.js` · `test/widget/desktop_refresh_test.dart` · `test/widget/mini_live_update_test.dart` · [`../dev/179-DESKTOP-REFRESH.md`](../dev/179-DESKTOP-REFRESH.md)。

### `D4.30` 小程序可以拍一张照片

**结论**：跟别的几样一样走"**声明 ＋ 他点头**"那一套（清单里 `permissions: ["camera"]`，第一次打开时他点一次同意才生效）。🔴 **镜头不经我们的手**：我们**不替它拍**、不落盘、不进聊天记录（要存是它自己的事，走它自己那格库）。
**理由**：镜头是**浏览器/WebView 自己**给页面的（`getUserMedia` / `<input capture>`）—— 我们这一侧只做两件事：**要他点头** ＋ **按授予放开那一层门**（网页：iframe 的 `allow="camera"`；安卓：WebView 的 `onPermissionRequest`，**只放摄像头**）。这也正是"声明 ≠ 已给"那条（`09-APPS.md` §3.2）在网页/系统那一级的样子。
**连带动作**：**没授予 ⇒ 门是关的**（页面里那句话当场被浏览器/系统拒掉，不是我们替它拦）；安卓清单要有 `CAMERA`（少了它页面拿到的是冷冷的拒、而且**不报错**），`uses-feature` **不许写 `required="true"`**。
**判据**：`test/app-grant.test.js` · `test/widget/settings_grants_test.dart` · `test/unit/android_manifest_test.dart` · [`../dev/192-APP-CAMERA.md`](../dev/192-APP-CAMERA.md)。

### `D4.31` 「我自己那台」不在产品里

**结论**：桌面上那一格那一层（那台 DSH 的**原始会话流**那个"显示器 ＋ 键盘"）与服务端那条 `/api/harness`（含盒子那侧的中继）**都不在产品里**；`harness` 这个名字**也不在保留 id 里**（保留名单 ＝ 主线 ＋ 内置那几格，这条等式不许破）。
**理由**：与 `D4.20`（奥数题）同一条做法：**要砍就明说砍了，不留半截** —— 留一个"只有我知道怎么进"的入口，等于在界面上藏了第二条控制面，而它不在任何一条判据里。
**连带动作**：⚠️ **盘上老数据一个字节不动**（那一房里已经有过的事件照旧躺着，只是这个名字不再认得）；🔴 **没删的那一半要说清**：**开发者模式**（翻标记 / dev 域名 / 房间清单 / "要一条签名链接"那条端点）**一个字节没动** —— 跟着那一格走掉的只是长在它里面的那颗入口按钮。
**判据**：`src/apps.js` 的 `REFUSED_APP_IDS` · `src/worlds.js` 的 `BUILTIN_SCOPES` · `src/dev-mode.js` · `test/unit/app_spec_test.dart` · [`../dev/200-REMOVE-HARNESS.md`](../dev/200-REMOVE-HARNESS.md)。

## 第 7 族 · 语音（`D5` / `P-c`）

### `D5` 一步 ＋ 回显

**结论**：语音就是**一个话筒**：说一下 ⇒ 出来的是字 ⇒ 发出去；**回答的第一句先把他的原话应一声**（"收到，我去查上海的天气"）。**不做"语音功能"**（不做唤醒词、不做声纹、不做语音设置那一套）。
**理由**："一步"是这个功能的全部价值 —— 用户学会的手势就是"说一句、它接住"，**多一步就多一样要学的**；而"先应一声"让**听错在答案之前就暴露出来**（他把药名说错时，第一句就会看出不对），不必等一个答非所问的回复。
**连带动作**：语音的客户是"**打不了字的人**"，不是"懒得打字的人"（所以通勤那位不用它不算缺陷）；这两件事都落在人格第一条（先应一声，短到一行）与那条"三步"里。
**判据**：`v2/services/core/hupo-persona.yml`（先应一声那条）· `v2/apps/mobile/lib/models/hearing_session.dart` · [`../dev/214-VOICE-REBUILD.md`](../dev/214-VOICE-REBUILD.md)。

### `D5.1` 只做"一个话筒 ＋ 识别 ＋ 字进框"

**结论**：做的范围就是"**一个话筒** ＋ **把说的话变成字** ＋ **字进那个真输入框**"，别的都不做。
**理由**：范围一旦扩成"语音功能"，长出来的就是唤醒词、声纹、语音指令、语音设置那一套 —— 每一样都要学，而它们服务的是"懒得打字的人"，不是"打不了字的人"。
**连带动作**：识别那一步今天走**我们自己的服务端转上游**（见 `D5.2`）；**绝不做**"猜一个字顶上"（听不出来就说没听清）。
**判据**：`src/asr.js` · `v2/apps/mobile/lib/services/hearing.dart` · `test/widget/voice_send_test.dart`。

### `D5.2` 音频经我们自己的服务端转给上游

**结论**：浏览器的麦克风 → `/api/asr`（这一台）→ 上游识别服务（今天**豆包流式识别**）。**钥匙只在服务端**，不下浏览器。
**理由**：让浏览器直连上游，钥匙（Access Token）就得出现在浏览器里 —— 密钥一下发，页面上的任何人都能拿它烧我们的额度，而且这回不是"猜"，是明文摆在 devtools 里。代价照实写在这儿：**声音会出境到上游**（这正是最想避的那一条），换来的是"**网页上真能用**"（设备自带的识别器在浏览器里调不到）。
**连带动作**：**没配钥匙就如实说"没配好"，不装开麦**（连按钮都不画）；一次最多听多久是我们自己的约定（数住代码），到点只是**接着开下一轮**、**字一个都不清、一次都不发**；听了几分钟也进账本（只记量，不记内容）。
**判据**：`src/asr.js`（`ASR_PATH` / `ASR_MAX_MS`）· `src/asr-doubao.js` · `test/asr-doubao.test.js` · [`../dev/71-MIC-ASR.md`](../dev/71-MIC-ASR.md) · [`../dev/152-VOICE-DOUBAO.md`](../dev/152-VOICE-DOUBAO.md)。

### `D5.3` 开麦只在"正在听"那一段（不做常驻收音）

**结论**：麦克风**只在他说"开始听"到"按停"这一段时间里开着**；**无唤醒词、不申请后台录音**。
**理由**：常驻收音意味着"这台设备一直在听我说话" —— 那件事的解释成本远高于它省下的那一下点击，而且它把"正在听那三个字是真的"这条判据变成一句空话（一直在听 ⇒ 那句话没有信息量）。
**连带动作**：`AndroidManifest` 里**只声明 `RECORD_AUDIO`**，不申请后台录音；离开这一屏 / 关掉那一档都要**真的停**。
**判据**：`v2/apps/mobile/android/app/src/main/AndroidManifest.xml` · `test/unit/android_manifest_test.dart`（"后台录音一票否决"）· `lib/services/recorder_native.dart`。

### `D5.4` 绝不自动发送

**结论**：识别回来的字**只进那个输入框**；**发出去这一步必须是他自己的动作**（按停 / 按发送），系统**永远不替他按**。
**理由**：语音会把"嗯…那个…就是说"听成一句像样的话；自动发出去就等于**用他的身份说了一句他没说过的话** —— 而收不回来。
**连带动作**：这句话在界面上看得见（字就在框里，他能改、能删、能不发）；"按停就发"是**他按了那一下**之后的动作，不是系统自己决定的发送时机（见 `D3.14·补（十三）`）。
**判据**：`test/unit/voice_compose_test.dart` V2／V3 · `test/widget/voice_send_test.dart` V6／V8（没按停就不发）· `lib/services/chat_controller.dart`。

### `D5.5` "正在听…"必须与话筒同批改

**结论**：加了话筒，就不许留一句含糊的"听" —— **"正在听"只在真的在录时能出现**，不录音时**禁用「听」字**（它进禁用词扫描）。
**理由**："听"从这一刻起**一个词两个意思**（真的在收声音 / 收到了在处理）；把假的画成真的，用户会对着一个不在工作的麦克风说话 —— 那正是"页面在说假话"那一族。
**连带动作**：文案分两个词（在录 / 在处理），落点只有一处（`models/hearing_words.dart`）；界面上的实现细节见 `D3.4`。
**判据**：`v2/apps/mobile/lib/models/hearing_words.dart` · `models/forbidden_words.dart` · `test/unit/forbidden_words_test.dart`。

### `D5.6` 权限用人话交代，申请时机 ＝ 第一次按话筒

**结论**：麦克风权限**不在开 App 时申请** —— 是**他第一次按那颗圆圈**时才申请；申请前 / 被拒之后都由我们**用人话**说清（不是把系统那串英文甩给他）。
**理由**：开 App 就弹权限，用户还不知道这个按钮干什么（06 那位会直接点"不允许"然后以为坏了）；而"第一次按"那一刻，他要做的事和权限的用途是同一件，同意才有依据。
**连带动作**：真录不出来（没权限 / 环境太吵 / 这台开不了麦）**都要如实说**，并给他一条**打字的退路** —— 屏幕上不许出现按不动的东西，也不许让他没有路走。
**判据**：`lib/services/recorder_native.dart` · `lib/services/hearing_native.dart` · `test/widget/voice_record_test.dart` · `test/unit/android_manifest_test.dart`。

### `D5.7` 回答首句回显原话

**结论**：每一轮回答的**第一句**先说清"我听到的是什么、打算怎么做"（不超过一行），**然后再动手**；这一句必须排在**这一步所有工具调用之前**，而且**必须在同一轮里**。
**理由**：他说的那件事对不对，只有在这句回显里看得出来 —— 听错在答案之前暴露，比一个答非所问的回复便宜得多；而"只说一句就结束"会让他以为它答完了，所以同轮里必须接着做。
**连带动作**：⚠️ 这一条**不是"复述他的历史"**：那条禁的是把他**以前**说过的话翻出来重念（人格"不许往回补对话"），这一条是回显**当轮**输入 —— 两件事，别读成一个矛盾。
**判据**：`v2/services/core/hupo-persona.yml`（第一步"先应一声"那条）· `v2/services/core/test/persona.test.js`。

### `D5.8` 字出来能点一下就改

**结论**：识别出来的字**长在那个真输入框里**（与打字用的是同一个框）⇒ 他要改**点进去改就行**，不用打字功能、不用重说一遍。
**理由**：错别字一定会有（人名、药名、数字）；如果那条字不能改，"绝不自动发送"就只剩"不发"，他要么忍着一个错字发出去、要么整句重来。
**连带动作**：**他一动手，语音就不再往框里写** —— 发的是他手上那份（`V3`）；半句/定稿边听边长，但覆盖同一个段号时要先判"这是同一句在改"还是"这是另一句"（覆盖不可逆，抹掉了就找不回来）。
**判据**：`v2/apps/mobile/test/unit/voice_compose_test.dart` V1／V3 · `test/unit/hearing_session_test.dart`（`sameWords`）· `lib/models/hearing_session.dart`。

### `D5.9` 要写进记忆的（名字 / 日期 / 钱数）额外确认一次

**结论**：凡是**要落到记忆里**的那几样（名字、日期、钱数）**多确认一次**：把它听到的**说回给他**，他点头才写。
**理由**：识别错一个数字，写进账本就是一条永久错的账（而且账本只追加、旧字段永久只读）；"多说一句"与"记错一笔"之间的差价太大。
**连带动作**：那句确认必须**念全**（事项 / 数量 / 单位 / 单价 / 含税 / 日期），认不准的那一项**点名说缺哪一项**、去问他，**不要自己猜**；接口层是"只算不写"与"写"两件分开的工具。
**判据**：`src/mcp-ledger-server.mjs`（`ledger_propose` / `ledger_write` 两件）· `src/ledger.js` 的 `renderEcho` · `test/ledger.test.js`。

### `D5.10` 语料硬闸：命中率不达标不上线

**结论**：四类问题（**天气 / 药 / 公交 / 发消息**）各一批句子，**句子级命中率不达标不上线**；口径是**整句归一之后相等**才算命中（**不许"包含就算"**）。
**理由**：语音这件事最容易"看起来能用"—— 一句听个大概就是错别字；尺放松一点，那一整批会集体变容易，那道闸就白设了。而"读数只对真的跑了音频才算"：没有音频 ⇒ 装置必须说"没跑"，**绝不许回一个好看的假读数**。
**连带动作**：语料与算法只有一处出处（纯函数：装置、`test/unit`、将来别的路共用同一把尺）；语料的条数与那道门槛**住代码与 [`08-SPEC.md`](08-SPEC.md) §十**；⚠️ **读数还没跑出来**（语料已就位、装置已就位，见 [`04-ROADMAP.md`](04-ROADMAP.md) §4.5）。
**判据**：`v2/services/core/src/voice-corpus.js` · `test/corpus/voice-4x20.json` · `scripts/check-voice-corpus.mjs` · `test/voice-corpus.test.js`。

### `D5.11` 安卓清单里加 `RECORD_AUDIO`

**结论**：安卓那份清单**必须有 `RECORD_AUDIO`**；这条一起带来的还有"第一次按话筒才问权限"与"不许后台录音"两条。
**理由**：少了它，真机上按话筒什么都不会发生（连系统的拒绝框都不一定弹），而屏幕上看起来像"这个按钮坏了"——一条声明就能避免的整类故障。
**连带动作**：清单是**硬闸**扫的（不是靠人记得）；`<uses-feature>` 不许写 `required="true"`（没麦的设备照旧能装）。
**判据**：`v2/apps/mobile/android/app/src/main/AndroidManifest.xml` · `test/unit/android_manifest_test.dart`（V10）。

### `D5.12` 权限申请时机 ＝ 第一次按话筒 ＋ 那句人话

**结论**：申请动作与"为什么要这个权限"那句话**同批**：第一次按话筒 ⇒ 用一句人话说清要什么 ⇒ 再弹系统那个框。
**理由**：时机本身就是说明（他在那一刻要做的事就是权限的用途）；而在系统框之前先给一句人话，他点"不允许"时至少知道拒绝掉的是什么。
**连带动作**：被拒之后那颗圆圈**要给出路**（打字）而不是变成一块按不动的东西；"没权限"与"开不了麦"要说成两句不同的话（`D3.4`）。
**判据**：`lib/services/recorder_native.dart` · `test/widget/voice_record_test.dart` · `test/unit/hearing_native_test.dart`。

### `D5.13` "正在听…"分成两个词

**结论**：一个词是"**真的在录**"（那颗会转的标记），另一个词是"**收到了、在处理**"；**不录音时禁用「听」字**。
**理由**：同 `D5.5` —— "听"一旦两义，用户没法判断现在该不该继续说话；把两个状态说成两个词，屏幕上那句话才有信息量。
**连带动作**：不录音时禁用的字进**禁用词扫描**（那是缺陷不是文风）；这两句话与那颗标记的位置一起进可访问性那条硬闸。
**判据**：`models/hearing_words.dart` · `models/forbidden_words.dart` · `test/unit/forbidden_words_test.dart` · `test/widget/voice_blink_test.dart`。

### `D5.14` 打字框永远不许锁

**结论**：**输入框任何时刻都能打字**（在听、在收尾、在等答复都一样）；语音与打字是**同一个框**，不是两个模式。
**理由**："多一个模式就是多一样要学的"（`D3.1`）——而"语音档时框是锁的"会让他以为这台设备不让他打字；真相是他随时可以改成打字，而且发的是他手上那份。
**连带动作**：开麦前框里已有的字**留着**（接在后面，不清空）；他一动手改字，语音就不再往框里写。
**判据**：`lib/models/hearing_session.dart` · `test/unit/voice_compose_test.dart` V3／V6 · `test/widget/voice_record_test.dart`。

### `D5.15` 认识不到就说人话；不许拿猜的字顶上

**结论**：一个字都没听到 / 识别出错 ⇒ **如实说一句**（并**不发**）；**绝不许**拿"猜的"或上一次的字顶上。
**理由**：把猜的字当成他说的话发出去，是用他的身份说了一句他没说过的话；而"安静地什么都没发生"会让他对着一个其实已经坏了的按钮一直说。
**连带动作**：`unavailable` / `denied` / `failed` 三种要**分得开**（没配钥匙 ≠ 没给权限 ≠ 这一台开不了麦）；第一次撞上死连接**自动再试一次**（"初次点击 failed、第二次就好"），真答案（没权限 / 没配钥匙）**不重试**，最多试两次。
**判据**：`test/unit/voice_compose_test.dart` V5／V6／V7／V8／V9 · `lib/models/hearing_session.dart`（`HearingPhase`）。

### `D5.16` 「出」那一半：念出来

**结论**：做的是**"念出来"**：走**设备自带**的合成器、我们**不把文字送到任何地方**；**每条回答一颗「读一遍」** ＋ **一个「读出来」开关**（自动念新说的话，**默认关**）。
**理由**：网页上没有"听筒 / 外放"那个出口，语义上只有"这台设备念给我听"这一件事；而**历史不念、没说完的不念**——把三条旧消息念出来既是骚扰，也让人分不清哪句是刚说的。
**连带动作**：点"别念了" / 关开关 / **离开这一屏都要停**；安卓那侧走**系统 TTS**（手写平台通道，不是 pub 插件）。
**判据**：`lib/services/speech.dart` / `speech_web.dart` / `speech_native.dart` · `test/unit/speak_core_test.dart` · `test/widget/speak_test.dart` · [`../dev/68-SPEAK.md`](../dev/68-SPEAK.md)。

### `D5.16·补` 画不画那颗按钮：拆成"平台有没有这个能力"与"现在念不念得出来"两个问题

**结论**：拆成两个问题：**① `canSpeak`（画不画那颗按钮）＝ 这个平台有没有那个能力**（`speechSynthesis` 在不在）；**② `speechHasVoices`（真念得出来吗）＝ 音色表空不空** —— 按下去的时候用它，**空的就如实说一句**「这台设备上没法念出来。」
**理由**：把"音色表非空"与"这个平台有没有那个能力"合成一个判定，就会让那颗按钮**因竞态静默消失**（各浏览器给音色是**异步、而且不一定给**）；而"屏幕上不许出现按不动的东西"这条一个字没松 —— 那颗按钮**按下去一定有反应**（要么念，要么说清这台念不出来）。
**连带动作**：网页那颗按钮不许"因竞态消失" —— 光靠 `voiceschanged` 会漏，再补一条轮询（看到音色就举手，数住代码）；那一列的高度**恒定**（念不出来时下面那一格留着，不然上面那颗与圆圈对不齐）。
**判据**：`lib/services/speech_web.dart` · `test/unit/speak_core_test.dart` · `test/widget/speak_test.dart`。

### `D5.17` 「说」那一半

**结论**：语音那一档是**一颗圆圈** —— **按一下开始听、再按一下结束**；识别结果**实时落进底下那个真输入框**，**发不发由他**（`D5.4`）；**开麦前框里已有的字留着**（接在后面）。
**理由**：语音这一档**不用**「按住说话」那套语义 —— 它把"说不说完"和"松不松手"绑在了一件事上；而"字进框"让错字当场上屏、当场能改。
**连带动作**：🔴 **没配钥匙 / 没给权限 / 上游出错都如实说，不做不了的按钮**（没配钥匙时连按钮都不画）；音频走**我们这条**（`D5.2`），钥匙只在服务端。
**判据**：`test/widget/voice_send_test.dart` · `test/unit/voice_compose_test.dart` · `test/widget/desktop_floater_test.dart`（按圆圈只开麦、不顺手把窗口打开）· [`../dev/71-MIC-ASR.md`](../dev/71-MIC-ASR.md)。

### `P-c` 语音按批交付：权限与那句话先落，语音本体另起一批

**结论**：语音这一块**分两批**：**第一批**只做**权限声明 ＋ 那句人话 ＋ 拆"听"字**（`D5.5`／`D5.6`／`D5.11`／`D5.13`）；**语音本体**（真开麦、真识别）**另起一批**。
**理由**：第一批那三样**不依赖任何识别能力**就能验（它们是文案与声明），而语音本体要等"真机上那个识别器真的能用"才验得了 —— 把它们绑在一批，会让三样已经能做的事陪着一起等。
**连带动作**：两批的判据各自独立（第一批在清单与词表闸上，第二批在 `voice_send` / `voice_compose` 上）；⚠️ 第一批做完时**不许**在界面上留一个"按了没反应"的按钮。
**判据**：`test/unit/android_manifest_test.dart` · `test/unit/forbidden_words_test.dart` · `test/unit/voice_compose_test.dart` · `test/widget/voice_send_test.dart`。

## 第 8 族 · 数据源（`D6`）

### `D6` 第一个真数据源 ＝ 工时账 ＋ 最小出口同批

**结论**：第一个真数据源选**工时账**（一笔一笔的工、数量、单价、含税、日期），而且**列表 ＋ 导出 ＋ 单条删同批做完**。
**理由**：它是"全机第一份持久化的用户数据"——P4 最贵的三条风险（**写进去、口径变、记忆没出口**）它**全碰**；而"出口同批"是**硬前置，不是锦上添花**（没有出口就登记"要存东西"＝把用户的东西关进一个他自己打不开的盒子）。
**连带动作**：出口的形态是**一段能直接粘进微信的话**，不是表格（不画表就绕开了"渲染层排后"）；AI 只做**组合 ＋ 渲染**，绝不发明接口。
**判据**：`v2/services/core/src/ledger.js` · `src/ledger-text.js` · `test/ledger.test.js` · `test/ledger-text.test.js` · [`../dev/31-LEDGER.md`](../dev/31-LEDGER.md)。

### `D6.1` 不选天气

**结论**：**不拿天气当第一个真数据源**。
**理由**：天气一次性、无状态、**不碰用户的数据** —— 用低风险样本验高风险路径 ＝ **假验证**。最准的一问是："天气删了会怎样？他换个 App。工时账删了会怎样？**账没了。**"
**连带动作**：以后挑"第一个真数据源"那类样本时，先问它**碰不碰"写进去 / 口径变 / 记忆没出口"**这三条；碰不到就换一个。
**判据**：[`01-PROJECT.md`](01-PROJECT.md) §五（产品原则）· [`../dev/31-LEDGER.md`](../dev/31-LEDGER.md)。

### `D6.2` 选"有状态、会反复问、会留下东西"的

**结论**：第一个数据源要**有状态**（一笔一笔不一样）、**会反复问**（"这个月一共多少"）、**会留下东西**（删了就没了）。
**理由**：这三样正是"记忆"这件事的全部难点；不满足它们的样本，验出来的只是"能不能存一行"。
**连带动作**：同一条尺继续用来挑后面那几样（图像 / 视频 / 小程序的数据那一格）——**留下东西**那一条尤其要想清楚"删了会怎样"。
**判据**：`test/ledger.test.js`（增 / 查 / 合计 / 删四路都有）· [`../dev/31-LEDGER.md`](../dev/31-LEDGER.md)。

### `D6.3` 字段冻结 ＋ 判据进闸：同一句话隔一段再问，逐字段 `diff = 0`

**结论**：**同一句话隔一段时间问两次，逐字段 `diff = 0`** —— 认出来的六个字段必须一模一样。
**理由**：这是"可复现"的判据：字段名或口径一漂，今天记的账明天读不出来 —— 那不是质量问题，是**不可复现**（`P4` 的全部立论）。
**连带动作**：判据靠**注入时钟与 id** 实现（不真等几天）；这一条同时钉住"模型不许自己发明字段"（它只能提一条要写的，写不写由宿主说了算）。
**判据**：`test/ledger.test.js`（"同一句话隔一段再问、逐字段 `diff = 0`"）· `src/ledger.js` 的 `normalizeFields`。

### `D6.4` 不许自动抽取

**结论**：**只认他明说的"记一笔"**；没有出处的**不写**。模型**只能"提一条要写的"**，写不写、写成什么由宿主说了算。
**理由**：从闲聊里自动抽出一笔账，等于**替他签字** —— 而他根本没说要记；而"无出处不写"是唯一能事后核对"这笔是哪句话来的"的办法。
**连带动作**：不过校验 ⇒ **不写**，并**点名说清哪一项没听准**；"原话"那一项必须逐字留着（它是出处）。
**判据**：`src/ledger.js`（只有"提"与"写"两个入口，**没有任何"改"的入口**）· `src/mcp-ledger-server.mjs` · `test/ledger.test.js`。

### `D6.5` 听错要回显确认

**结论**：**钱数 / 日期 / 名字不确认不写** —— 先把听到的那六项**念回给他**，他说"对"才落。
**理由**：识别错一个数字，写进账本就是一条永久错的账（账本**只追加**、旧字段永久只读）；这是"多说一句"与"记错一笔"之间的取舍。
**连带动作**：接口上是两件工具（**只算不写** / 写）；念的时候六个字段**按固定顺序**全念（不许只念一部分）。
**判据**：`src/ledger.js` 的 `renderEcho` / `FIELD_LABELS` · `src/mcp-ledger-server.mjs` · `test/ledger.test.js`。

### `D6.6` 字段：事项 / 数量 / 单位 / 单价（可空）/ 含税 / 日期

**结论**：一笔账**就这六个字段**：`kind`（事项）· `qty`（数量）· `unit`（单位）· `unitPrice`（单价，**可空**）· `tax`（含税：是 / 否 / 说不清）· `date`（日期）。字段的**语义**一旦写进账本就不再改，要改就是**新增字段**。
**理由**：字段是"上线即冻结"的东西；六个刚好覆盖"一笔工"（谁、多少、怎么算钱、哪一天），多一个字段就多一处要么猜、要么空着的格子。
**连带动作**：给人看的字段名必须是**主人看得懂的词**（"事项 / 数量 / 单位 / 单价 / 含税 / 日期"），**不许出现内部词**（那是缺陷不是文风）；他说不清的字段留 `unknown`，**不许猜**。
**判据**：`src/ledger.js` 的 `FIELDS` / `FIELD_LABELS` / `normalizeFields` · `test/ledger.test.js`。

### `D6.7` 只追加，不原地改

**结论**：账本**只追加**：改一条 ＝ **新增一条**，旧的那条**永久留在盘上**；模块里**没有任何"改"的入口**（这是结构上的，不是纪律上的）。
**理由**：一条被原地改掉的账，事后谁都说不清"改动之前是多少" —— 而账本的全部价值就是"事后能核对"；"旧字段永久只读"同时是"字段冻结"的落地。
**连带动作**：改名 / 改数都走新增；**删除**与回收站同语义（有期限、可恢复、真删要压实），唯一不同的是**恢复时不重发内容**（账本没有客户端游标那一层，重发会让同一个 `entryId` 在盘上出现两份 ⇒ 合计算重）。
**判据**：`src/ledger.js` 文件头与导出清单（无 update/patch）· `test/ledger.test.js` · `test/ledger-chain.test.js`。

### `D6.8` 出口同批：列表 ＋ 导出 ＋ 单条删

**结论**：**没出口就不许登记"要存东西"** —— 第一个真数据源必须**列表 ＋ 导出 ＋ 单条删**三样同批；出口的形态是**一段能直接粘走的文字**（不带 markdown、不带表格线）。
**理由**：第一份持久化的用户数据出现的那一刻，出口 / 出处 / 删除 / 导出**全都还没有**（那两个记忆入口与 KV 就是前车之鉴）—— 而补出口比补写入贵得多，所以它是硬前置。
**连带动作**：口径只有一处（合计走同一个 `foldTotals()`，别的文件不许自己再算一遍）；空账本**不许给一个空框**（有一句实话）。
**判据**：`src/ledger-text.js` 的 `renderLedger` / `emptyLine` · `test/ledger-text.test.js` · [`../dev/31-LEDGER.md`](../dev/31-LEDGER.md)。

### `D6.9` 口径不明：含税 `unknown` 不进合计，并明说"有几条没计入"

**结论**：含税**说不清**的那些**不进合计**，而且**必须在末尾说清有几条没算进来**；"没说钱"的那几笔同样明说。
**理由**：只排除不报数就是"悄悄少算"——而少算这件事，用户看不出来（他看到的只是一个小一点的数）。
**连带动作**：合计只在**筛出来的那一段**上重折（按月份过滤之后口径不能还是全部的）；"没说钱"那一笔**单价与这一笔总额都要写**（不然"一台一千二"这个信息就没了）。
**判据**：`src/ledger.js` 的 `foldTotals` · `src/ledger-text.js` 的 `totalsLine` / `NO_PRICE_WORD` · `test/ledger.test.js`。

### `D6.10` 硬闸：同记录同口径出两次，逐字段 `diff = 0`

**结论**：同一笔账问两次，**出口那段文字一模一样**（逐字段 `diff = 0`）；这是**出口那一侧的闸**，与 `D6.3` 那一条（写入那一侧）配对。
**理由**：写入可复现、出口不可复现，用户拿到的仍然是两个答案 —— 而"这个月到底多少"这种问题，两个答案就等于没有答案。
**连带动作**：渲染是**纯函数**（进 `test/unit` 被逐条钉住）；服务端那一侧渲染好、对话那侧只**转述**，不重算。
**判据**：`test/ledger.test.js`（D6.10 那一条）· `test/ledger-text.test.js`。

## 第 9 族 · 过程可见性（`D7`）

### `D7` 分层展示：两档（在做什么 / 推理原文）

**结论**：过程**分两档**：**在做什么**（**默认**：屏幕上什么都没有时那句"它正在做这件事…"，或一句人话）与**推理原文**（**只有主人，默认关**）。
**理由**：默认那一档必须能让"它到底收到没有"这个问题有答案（走查里八个人的放弃点都落在那段空白上）；而推理原文是另一件事 —— 它连它没说出口的念头一起露出来，所以默认关、要他自己选。
**连带动作**：档位是**每条连接**的东西（不是进程级开关，也不是全局设置：一台设备选了"推理原文"**不许**改变另一台看到的东西）—— 换档因此只能靠**重连**。
**判据**：`v2/apps/mobile/lib/models/process_levels.dart`（`defaultProcessLevel`）· `v2/services/core/src/server.js` 的 `parseLevel` / `levelAllows` · `test/process-level.test.js`。

### `D7·补` 过程就两档；协议上那四个字仍然冻结

**结论**：**菜单上只有两档**（在做什么 / 推理原文）；**协议里那四个 wire token 一个都不许改、不许删、不许复用**（老客户端还在发那两个不再出现在菜单上的字），服务端语义**一个字不改**；老设备盘上的旧档读出来**归一到默认那一档**。
**理由**：砍掉的是**客户端菜单上的入口**，不是协议上的 token —— 改一个字节就是"某一台老设备静默降成默认档"，而屏幕上不会有任何异常（那是"静默丢事件"那一族）。
**连带动作**：那两个被砍的档服务的那条通道**今天只为老客户端存在**（新客户端收得到它但**一个像素都不画**）；这条不变量由一条"认不出来的档 ⇒ 默认档，不报错也不拒连接"兜底。
**判据**：`src/server.js` 的 `PROCESS_LEVELS` / `PROCESS_TYPES` / `LEVEL_EXTRA_TYPES` · `models/process_levels.dart` 的 `processLevelWires` · `test/process-level.test.js` · [`../dev/122-TWO-PROCESS-LEVELS.md`](../dev/122-TWO-PROCESS-LEVELS.md)。

### `D7.1` 默认档必须说人话

**结论**：默认那一档给的是**人话**（"在查资料" / "在读东西" / "在写" / "在动手做" / "在琢磨"），**内部状态名一个都不许上屏**；认不出来的状态**别说**（安静），**不许猜一个**。
**理由**：`working` / `started` / `handoff` 这些是**我们这边**的词，不是用户的词；把它们摊在界面里，用户看到的是"系统在说它的行话"——而"认不出来就闭嘴"是同一条的另一半（编一个比不说更坏）。
**连带动作**：那张对照表**只有一处**（`models/process_words.dart`，允许出现内部名的唯一地方），方向单向（内部名进、人话出）；它也进**禁用词硬闸**。
**判据**：`v2/apps/mobile/lib/models/process_words.dart` · `test/unit/process_words_test.dart` · `test/unit/forbidden_words_test.dart`。

### `D7.2` 不承诺时间

**结论**：可以说"我先去做"，**不许说"还有两分钟就好"**这一类**预期**；时间一旦说出口就变成一个要兑现的承诺，而**有了预期却没兑现，用户比什么都不说更焦虑**。
**理由**：同一件事的两种说法差别在"我这就去"与"几点几分能好"之间 —— 前者是动作，后者是承诺；而它承诺不了（活有多长它自己也不知道）。
**连带动作**：长活开口先说的是"**这个要几分钟，我先去做，好了叫你**"这种**量级**＋"好了叫你"那半句（把兑现点从"几分钟"挪到"做完"）；等不到时如实说，不许拿"马上"顶着。
**判据**：`v2/services/core/hupo-persona.yml`（长活那一条）· [`01-PROJECT.md`](01-PROJECT.md) §六（**今天没有专门闸**）。

### `D7.3` 展示过程不能替代速度

**结论**：过程可见只是**让等待可忍受**，**不是**性能问题的解法；不许拿"界面上看得见它在做"当"为什么慢"的答复。
**理由**：用户要的是结果——他把"看得见它在做"读成"它在认真办"，而不是读成"我要等很久"；把可见性当性能借口，等于用一个界面改动掩盖一个真问题。
**连带动作**：慢是慢，要单独认（该优化的优化、该明说的明说）；过程那一档只负责"那段空白里有一句话"。
**判据**：今天没有专门的闸（这是一条口径）· [`01-PROJECT.md`](01-PROJECT.md) §六 · `04-ROADMAP.md` §四（已知的慢与收口那几条欠账）。

### `D7.4` 推理原文只给主人；**发不发由服务端决定**

**结论**：推理原文**默认关**，要**本人显式选那一档**才发；🔴 **"发不发"是服务端按连接决定的**（它是隐私闸），**绝不许挪到客户端去藏** —— 客户端藏起来，字节还在流上。
**理由**：它**可能含系统提示词片段**（产品的核心资产），而且实测里推理原文和正文躺在**同一个 `message.content` 数组**里（不按 `type` 过滤就等于把思维链当正文发出去）；同理它也**绝对不许落盘**——落盘之后新连接 `sinceSeq=0` 的重放会把历史原文发给每一个连上来的人。
**连带动作**：它**走瞬态通道**（不取号、不落盘、只推），档位闸只管"发给哪条连接"、**与落盘无关**（两层分开是刻意的）；这条有两条闸钉着（一条读盘上的日志、一条读重放帧）。
**判据**：`src/session-translate.js`（`emitTransient`）· `src/server.js` 的 `levelAllows` · `test/process-level.test.js`（泄露闸 ×2）· `models/timeline.dart`。

### `D7.5` 回答里不提内部词，但等待期可以展示"在做什么"

**结论**：人格那条"**不许提内部词**"（工具 / 搜索 / 上下文 / 系统提示）**照旧**；同时**等待期可以展示"它在做"** —— 那一句**必须是上面那张人话表翻出来的**。
**理由**：这两件事看着冲突、其实各管一头：一条管"它**说出来的答案**长什么样"，一条管"它**还没说出口**时屏幕上有什么"；把等待期也按"不许提内部词"掐掉，那段空白就又回来了（★1 那条最主要的放弃点）。
**连带动作**：等待期那句的实现细节住在过程那一档（`D7.1`），人格只负责"答案里不出现内部词"（人格第 6 条）；任何时候都不许把内部名字直接搬上屏。
**判据**：`v2/services/core/hupo-persona.yml` 第 1／6 条 · `v2/services/core/test/persona.test.js` · `models/process_words.dart`。

## 第 10 族 · 多租户与供给（`T1`–`T11`）

### `T1` 一人一台容器 ＝ 他的整个世界

**结论**：**一个用户 ＝ 一台容器 ＝ 他的整个世界**：他的数据、他的记忆、他的小程序、他的钥匙都在里面；这一台与别人那一台之间**没有共享的可写面**。
**理由**：这是"记忆隔离"唯一能验的形状 —— 靠"代码里记得别读别人的"那种隔离，一次手滑就没了；而一人一台之后，隔离落在**操作系统的边界**上，不是一个约定。
**连带动作**：宿主这一侧只做**入口与转发**（验身份、签地址、转发那条流），**不持有他的世界**；产品层（调度器 / 人格 / 能力）**一份只读**挂进每一台（`T9`），里面**一个秘密、一样按人不同的东西都不许有**。
**判据**：`v2/services/core/src/worlds.js` · [`02-ARCHITECTURE.md`](02-ARCHITECTURE.md) §三 · `scripts/check-container.sh` · `test/multitenant.test.js`。

### `T2` 隔离的边界落在 uid 上

**结论**：每台容器对应一个**独立的 OS 用户** ＋ 一段**独占的 subuid** ＋ 一个**用自己的身份拥有的卷**；**不在同一个 OS 用户底下做第二个容器** —— 实测那两个容器**互相进得去**。
**理由**：容器是"隔离第三方代码"的工具，不是"隔离同一身份下两份东西"的工具；共用一个 OS 用户时，甲能读到乙的凭据、也能写乙的卷 —— 而它看起来像"两台容器"。
**连带动作**：卷的权限落在**那个用户自己**身上（不是靠容器里那一层目录权限）；机器上要**先有这一批用户**，容器才建得起来（`scripts/create-tenant-users.sh` 那一步）。
**判据**：[`02-ARCHITECTURE.md`](02-ARCHITECTURE.md) §3.1 · `scripts/create-tenant-users.sh` · `test/multitenant.test.js` · [`../dev/34-CONTAINER.md`](../dev/34-CONTAINER.md)。

### `T3` 新号自动拿到一台

**结论**：新号进来（第一次登录）⇒ 服务**替他去申请一台**（投一张申请），不是"只把话说明白让他自己想办法"。
**理由**：取的是"**真的自动开一台**"——因为"你等着"不是一个产品能给的答复（而"给不了"必须明说，见 `T6`）。
**连带动作**：申请之前**先把耳朵支起来**（通道先听上，否则容器起来时那个 `ExecStartPre` 等不到套接字，而报错完全看不出原因）；申请是**幂等**的（已经在飞的不重复投）。
**判据**：`v2/services/core/src/serve.js` 的 `ensureTenant` · `src/provision.js` 的 `ProvisionQueue.request` · `test/provision.test.js` · [`../dev/43-AUTO-PROVISION.md`](../dev/43-AUTO-PROVISION.md)。

### `T4` 特权侧的形状 ＝ 申请队列

**结论**：服务（非特权身份）**唯一能做的副作用**是往一个目录里**放一个空文件**，名字是一个**整数**；特权侧**按需被拉起**（systemd 的 `.path` 单元）、**只读那个整数**、跑完就退。**没有常驻 root 进程、不给服务 sudo/polkit**。
**理由**：难点的准确形状只有一件 —— *一个公开的网页登录口，要怎样才能触发一个特权动作，而不等于把 root 交出去。* 三条路（sudoers / 常驻守护 / 申请队列）里选第三条，因为它的边界**小到能用眼睛看完全部输入**：一个整数。
**连带动作**：🔴 **绝不往申请里写任何内容**（不写手机号、不写 key、不写路径、不写命令 —— 文件是**空的**，这不是省事，这是边界本身）；文件用"只在不存在时创建"那个标志写（顺带挡住跟着符号链接写到别处去）；失败标记**不在申请目录里**（留在里面会让那条 `.path` 反复触发、最后撞 systemd 限速 ⇒ 之后的新申请没人管）。
**判据**：`src/provision.js` · [`08-SPEC.md`](08-SPEC.md) §4.3 `A1`／`A3`／`A5` · `test/provision.test.js` · `scripts/check-provision-refusals.sh`。

### `T5` root 要跑的每一份文件必须 root 拥有

**结论**：特权侧执行或读取的每一份文件**都必须 root 拥有**（`A9`）；单元指向的是**安装时拷过去的那一份**，**绝不指仓库里的路径**。
**理由**：让单元去跑仓库里那个脚本 ＝ **把边界画在一个服务自己写得到的地方** ⇒ 等于没有边界 —— 而它**看起来是对的**（路径对、脚本真的跑了、日志漂亮）。一个被攻陷的服务改一行，下次申请触发时那段代码**就是以 root 跑的**。
**连带动作**：仓库里那份是**源码**，装着那份才是**运行的那份**；因此必须有 **"改完了 ≠ 生效了"的核对命令**（逐字节比"仓库那份 vs 装着那份"），这件事不许靠人记得。
**判据**：`scripts/install-provision-helper.sh --check` · `scripts/check-provision-install.sh` · [`08-SPEC.md`](08-SPEC.md) §4.3 `A9` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §7.4。

### `T6` 容量有上限，"给不了"必须明说

**结论**：能开几台是**算出来的**（模板里那个上限）；超过上限 / 那台没建成 ⇒ **明说"给不了"**（不是"正在开"）；失败**必须留痕**。
**理由**：不许存在一个"**永远在等、而屏幕上没有一个字说到不了**"的状态 —— 用户会一直等一个不会来的东西，而系统这边看起来一切正常。
**连带动作**：申请目录**只许有待办申请**（失败标记住旁边）；状态查询读的是"标记在不在"，**不读标记内容**（读内容就是新开一条注入路）；服务侧与特权侧**各自都判一次上限**。
**判据**：`src/provision.js` 的 `failed()` / `DEFAULT_FAILED_DIR` · `src/tenants.js` 的 `maxTenants` / `tenancyFor` · [`08-SPEC.md`](08-SPEC.md) §一 `N28` · `test/provision.test.js` `A5` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §六。

### `T7` 模板只有一处权威

**结论**：租户的命名 / 编号 / 目录 / 卷 / 单元名**全部由一个整数按固定模板算出**；服务侧（JS）与特权侧（shell）**读同一个模板文件**、各推一遍 ⇒ 两边推出来的名字**必然逐字相同**；**推不出来就拒，不许猜**。
**理由**：两处各写一份常数**一定会漂**，而"漂"的表现是**容器起来了、服务却在听另一个通道** —— 看起来像"容器没起来"。
**连带动作**：模板只认三个键，**多一个键就是错**（防"悄悄加一个旋钮"，而另一侧根本不认它）；模板**读不到** ⇒ "自动开一台"这条路**关着**（不猜默认值），而且**不许**因此挡住服务。
**判据**：`v2/services/core/src/tenants.js` 的 `parseTenantTemplate` / `tenantNameFor` / `tenantUidFor` · `v2/services/core/tenant-template.conf` · `test/provision.test.js` · `scripts/check-provision-refusals.sh` ⑨（跨语言对照）。

### `T8` 装它属于"部署期"

**结论**：装 / 撤 / 核对特权侧的命令**由主人跑**（`P2`）；助手**只写代码、只准备方案**。
**理由**：这一整套的全部价值在于"助手碰不到特权侧" —— 让助手去装那个 helper，等于把"谁按的按钮"这件事抹掉，而部署期的锁就建立在"那一下只有主人过得去"上。
**连带动作**：安装器**默认只看**（不加"真做"那个词就什么都不动，镜像不在时**在任何写盘之前**拒绝）；**"主人真的看过"这个签字动作本身没有、也不可能有自动化判据** —— 脚本只能证明它**没动手**。
**判据**：`scripts/install-provision-helper.sh` · `scripts/check-provision-install.sh` · [`08-SPEC.md`](08-SPEC.md) §4.3 `A8` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §5.4／§7.4。

### `T9` 容器更新劈两层：运行层住镜像，产品层只读挂载

**结论**：**运行层**（node ＋ 库 ＋ **agent 本体**）留在镜像里，**罕见才动**；**产品层**（调度器 ＋ 人格 ＋ 能力 ＋ 代理补丁）住**宿主上一份目录**，**只读**挂进容器 ⇒ **改产品 ＝ 写文件 ＋ 让它重开**。
**理由**："改一次接线就要重造镜像"本身就是缺陷 —— 它让"改进产品"变成一件要 root、要停机、要动镜像的事，而那种事最后就是没人做。
**连带动作**：产品层归 `deploy`，但**每次翻转必须记账**（from / to / why / by）；产品层里**一个秘密、一样按人不同的东西都不许有**（它是一份共享只读的代码）；叫容器重开的那一帧**不带任何内容**；**读不到"当前那一版"时谁都不叫**；那一台要**如实自报版本**，不一致就说话。
**判据**：`src/product-layer.js` · [`08-SPEC.md`](08-SPEC.md) §一 `N29`／`N30` · `test/product-layer.test.js` · `test/tenant-reload.test.js` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §九。

### `T10` 钥匙住进卷里

**结论**：他自己的钥匙住在**他自己那个卷里**（`<数据目录>/creds.yaml`，**root 0600**、原子写）。⇒ **重建容器、换运行层都不丢钥匙**。
**理由**：钥匙住在临时文件系统里的话，重建一次就没了 —— 而"重建一次就要重填钥匙"会把每一次维护都变成一次叫他上门的动作。
**连带动作**：⚠️ **代价如实认下**：钥匙**落盘**了（在**他自己那台**的卷上）—— 能读到那块盘的人（宿主 root、或将来给卷做备份的人）就能拿到它；而**"agent 读不到自己的钥匙"一个字都没动**：agent 跑在非 root 那个身份上，文件是 root 0600 ⇒ 它读它必须失败（判据要挑一个**存在的路径**，不许拿"不存在"糊过去；正对照是 root 读得到）。
**判据**：`src/key-path.mjs` · `scripts/check-tenant-creds.sh` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §8.1。

### `T11` 钥匙有三个入口，写的是同一个文件

**结论**：**① 网页上填**（用户自己，走中心当管道推给他那台容器，**中心那份不落盘**）· **② 盒内放**（主人救急 / 开发，`podman exec` 跑那个小命令，要 root）· **③ 本机投递**（主人往一个约定目录放一把，**不用 root**）。
**理由**：三个入口覆盖三种现场（他自己填 / 坏了要救 / 主人在宿主上顺手放），而**只要写的是同一个文件**，就**没有"第二份真相"** —— 谁是最后写的谁生效。
**连带动作**：🔴 **投递"送到才算送到"**：那个文件要留到那一台**自己说"我有钥匙了"**才删；中心的钥匙**不落盘**，而"读到就删"会在宿主重启时把没送到的弄丢。
**判据**：`src/key-drop.js` · `src/put-key.mjs` · `src/tenant-channel.mjs` · `scripts/check-tenant-creds.sh` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §8.2。

## 第 11 族 · 客户端结构与传输（`P-e` / `P-f` / `P-h` / `P-i` / `P-j` / `P-l`）

### `P-e` 传输层：一条连接服务所有房间；生命周期只有一处

**结论**：**一条 WebSocket 连接服务他所有的房间** —— 切房间是**发一帧**（焦点），**连接不动**；连接的生命周期（重连退避、令牌、续传游标）**只有一处**管，每一间各有自己的续传游标。
**理由**：连接若是"带一个房间"的，切房间就只能重连 —— 而**退一个会话会打死全站连接、而且不自恢复**，正是那个形状的必然后果；把"哪一间"降成一帧之后，这两件事都不存在了。⚠️ 与档位别混：过程档位**仍然是连接级**的（换档要重连）。
**连带动作**：重连要带**这一间自己的游标**（服务端按焦点决定现时投哪些、补哪些）；`401` 认出来就**停下重连**并报"要重新登录"（坏令牌时不许一直撞墙）；退避**只在连成功之后归零**（否则封顶值永不生效）。
**判据**：`v2/apps/mobile/lib/services/stream.dart`（`focus` / `_focus`）· `test/unit/stream_retry_test.dart` · `test/unit/conn_state_test.dart` · `test/widget/room_switch_test.dart` · [`../dev/84-DISPATCHER-FOCUS.md`](../dev/84-DISPATCHER-FOCUS.md)。

### `P-f` 轮的稳定键 ＝ 轮号

**结论**：任何"按轮记账"的结构，键**只能是轮号**（`turn`，agent 在 `turn/start` 里给的），**不是**"当前那个写手对象"、也不是"当前气泡的 id"；跨代（agent 重启 / 换会话后轮号会重来）还要带上**代**。
**理由**：转交会**原地换掉写手**，而调度器手里那份与翻译层的当前轮账**是同一个对象** ⇒ "开轮时记下的那个 id"在它不知情的情况下变了：硬收口的守卫读到的是新 id ⇒ **永远匹配不上 ⇒ 这一轮永不收口**；清理时删的也是新 id ⇒ 旧键永久残留在表里。后果是"**升格过的轮次，硬收口彻底失效**"，屏幕上表现为一个**永远停在"它正在做"的气泡**。
**连带动作**：三个结构都用同一把键（翻译层的轮账、调度器的收口计时器、调度器的"这一轮是主人哪句话引起来的"）；⚠️ 这条的根因**不在调度器自己那个文件里**（那里一处都没给写手赋值），改之前先读 [`03-DEVELOPMENT.md`](03-DEVELOPMENT.md) §5.4。
**判据**：`src/session-translate.js` 的 `#turns` · `src/dispatcher.js` 的 `#deadlines` / `#turnOwner` · `src/worklog.js` 的 `pairKey` · `test/worklog.test.js` · `test/deadline.test.js` · `test/handoff.test.js`。

### `P-h` 补发标记：只在"续传游标 > 0"时标

**结论**：断线重连补发来的那一段**必须**带"你不在的时候"这个标记（它是一个**线上字段**）；**首次打开（游标 0）那一段不许被标成补发**。
**理由**：标错方向两头都坏 —— 不标，用户把三小时前的话读成"它刚说的"（既是骚扰也是假话）；标反了，他**每天开一次 App 就看见一次"你不在的时候"**。
**连带动作**：首次打开**只给最近的一段**（更早的由他往上翻、按页取），而**重连那条补发不截**（截了会让中间那一段看起来是连着的）；打这个标记必须**浅拷贝**（事件对象是从日志里读出来的，直接改会把标记写进磁盘）。
**判据**：`src/resume.js` 的 `planResume` / `planBackfill` · `test/resume.test.js` · [`03-DEVELOPMENT.md`](03-DEVELOPMENT.md) §3.4.2 · [`../dev/141-HISTORY-FIRST-OPEN.md`](../dev/141-HISTORY-FIRST-OPEN.md)。

### `P-i` 来源用 `agent` ＋ `origin`，不新加 `source`

**结论**：事件上回答"这条是谁说的、为什么冒出来"的只有**两条已经在线上**的轴：`agent`（谁在说）与 `origin`（为什么开口：被动应答 / 主动开口）。**不新加 `source` 这个字段**。
**理由**：新加的那个字段**与 `agent` 重复一半、与 `origin` 混淆一半** —— 两个语义重叠的字段同时存在，下一个人一定会按错的那个写；而事件一旦上线就冻结（老客户端还在跑），到时候删不掉。
**连带动作**：以后要加身份信息一律**往这两条轴上挂**；⚠️ "这条回答引用了哪些出处"是**另一个东西**（助手消息结尾那份 `sources`），别与这两条混。
**判据**：`src/message-writer.js`（构造时 `agent` / `origin` 必填，`origin` 只收那两个值）· `test/message-writer.test.js` · [`08-SPEC.md`](08-SPEC.md) §二 事件表。

### `P-j` env 先做减法

**结论**：给孩子进程的环境变量**先传全部、再只删密钥类**（名字以 `_API_KEY` / `_TOKEN` / `_SECRET` 结尾的，大小写不敏感）；**严格白名单随后再说，不阻塞交付**。
**理由**：严格白名单能把面收得更小，但要先把生产机上的变量盘一遍才敢写死；在那之前，"减法"已经达成了原本的目标（**去掉密钥**），而且**零 ENOENT 风险** —— 而那个 ENOENT 与"工作目录不存在"报的是同一句话（实测骗过人一次）。
**连带动作**：`DSH_HOME` 由参数给（多租户下每人一份，换个 home 就是换个账号）；`PATH` 里**必须能看见"跑我们那个 node"的那一格**（服务自己的 `PATH` 可能短得看不见它，症状与"找不到那支 CLI"一模一样）；不是秘密的那几样 `HUPO_*` 最后合并。
**判据**：`src/agent-runtime.js` 的 `childEnv` · `test/agent-bin.test.js` · [`03-DEVELOPMENT.md`](03-DEVELOPMENT.md) §5.5.1。

### `P-l` 一条可见时间线 ＝ 一条日志

**结论**：调度器对**每个用户**维护**一条**可见时间线日志；**多作用域只是事件上的标签**（哪一间产的），**不是并列的计数器**；编号 ＝ 那条日志已落盘最大号 ＋ 1。
**理由**：全机器一个计数器会把两个用户串起来；每条会话各数各的会让"同一间里的编号"在换会话之后对不上 —— 两种都会让客户端手里的游标错位。一条可见时间线 ＝ 一条日志之后，"编号唯一且单调"就成了**字面事实**，不需要额外解释。
**连带动作**：每个用户一条时间线，作用域视图是同一把时间线上带标签的视图；补发与订阅都走**他自己那一份**（身份只从验签令牌来），否则甲连上来的流会补发出乙的话；那条日志的**取号点只有一处**。
**判据**：`src/timeline.js`（`ScopeView`）· `src/worlds.js` · `test/scope-single-log.test.js` · `test/multitenant.test.js` · [`02-ARCHITECTURE.md`](02-ARCHITECTURE.md) §四。

## 第 12 族 · `store` 与序号（`S1` / `P-k` / `P-g`）

### `S1` 落盘失败必须上抛；先落盘成功、再推订阅者

**结论**：写盘失败**必须上抛**（并且**退号**）；顺序永远是"**先落盘成功、再推订阅者**"；写盘失败**不许吞**。
**理由**：反过来（先推、后落盘）会让"屏幕上已经有的字"在重启后消失 —— 用户看到的是一条他**再也找不回来**的消息；而吞掉失败 ＝ 让服务在盘满之后继续假装正常：崩 → 重启 → 再崩。
**连带动作**：落盘抛了就**退号**（盘上没留下东西，号就不该前进，否则下一个事件在盘上跳号），然后**原样抛出**；抛出的那一刻**订阅者一条都不许收到**（推了一半再抛，客户端会收到一条盘上不存在的事件）。
**判据**：`src/store.js`（`StoreError`）· `src/timeline.js` 的 `emit` · `test/store-append.test.js` · `test/seq-monotonic.test.js`。

### `P-k` 上抛之后必须有人接

**结论**：上抛之后**必须有人接**，而且是**三层**：**① 调用点不逐处兜**（发出事件的地方有很多，逐处兜**必漏**，漏一处就回到静默吞）；**② 唯一入口兜**（落盘失败 ⇒ 抛出、订阅者一条都不推、退号）；**③ 进程级兜底**（接未捕获异常 ⇒ **用不落盘的通知通道**说一句人话 ⇒ **有序退出**，交给 systemd 拉起）。
**理由**：没有第③层，那个错在运行时就是**未捕获异常** ⇒ 进程直接死 ⇒ 拉起 ⇒ **又死**，而盘还是满的 ⇒ **重启风暴**，而每一步都没有人知道发生了什么。第③层之所以说得出话，正因为它走**瞬态通道**（不写盘）—— 盘满时它仍然发得出去。
**连带动作**：写盘失败那条用户看得见的话是**唯一**允许走瞬态的情形（给别的理由它会抛）；它必须**自己说清"我没能记下来"**（例外不许伪装成正常）。
**判据**：`src/process-guard.js` 的 `installProcessGuard` · `src/serve.js`（装兜底那一段）· `src/notice.js` 的 `noticeUrgent` · `test/process-guard.test.js` · [`03-DEVELOPMENT.md`](03-DEVELOPMENT.md) §5.3。

### `P-g` 不占号 ＝ 不上时间线

**结论**：**不占号 ＝ 不上时间线**：控制帧与 UI 状态（本地应声那类）**在进入时间线之前就被消费掉**；而"时间线分隔"那一条标记是**持久事件**（取号、落盘、有位置）。
**理由**：控制帧占了号，盘上就出现一个"没有任何客户端画得出来"的位置 —— 号是客户端游标唯一的排序依据，凭空多一个号会让它在别人那里看起来像丢了一条；反过来，该有位置的东西若不占号，它就只活在"**那一刻连着的那一台设备**"上（他换一台设备就看不到了）。
**连带动作**：判断落在"**它有没有 `seq`**"这一条线上（瞬态事件**永远不在盘上**，所以任何档位都收得到全量补发、而补发里**不可能**有过程事件）；⚠️ **不许**改基类让号可空（那要破一条硬闸，而且兜底排序键会踩混钟）。
**判据**：`src/timeline.js` 的 `emit` / `emitTransient` · `src/server.js`（控制帧那一段）· `test/process-level.test.js` · [`03-DEVELOPMENT.md`](03-DEVELOPMENT.md) §3.4.3。

## 第 13 族 · 通知（`N1` / `N2`）

### `N1` 宿主级崩溃通知只报"被打断的那几份世界"

**结论**：开机那句"刚才出了点事，我已经重来了"**只发给真的被打断的那一份世界**（这一台进程里现有几份就各发一次）；**租户不报** —— 他们的世界跑在自己的盒子里，宿主重启**打断不到他们**。**谁都没被打断时，谁都不报**。
**理由**：给没被打断的人报就是**无事也报**（那正是"通知疲劳"要禁的形状）；而反过来，只判"上一次进程是不是干净退出"就说话，会让主人**一登录**就看见这句 —— 他刚进来、什么都没说，那句话读起来像"你刚才说的那条我还没做好"。
**连带动作**：只在"**真有没收口的东西、而对账那一路又没来得及说**"时才补这一句；它默认**落盘**（时间线里那一条就是它），只有**写盘本身失败**时才退回瞬态，而那句瞬态**自己说清"这条我没能记下来"**；一个人那份发不出去**不许影响别人**（各自兜一次）。
**判据**：`src/serve.js`（"上一次不干净 ＋ 对账没说过 ＋ 真有东西没收口"那一处，以及进程级兜底对每一份世界的循环）· `src/notice.js` 的 `crash` · `test/notice.test.js`。

### `N2` 通知只进时间线；唯一例外是写盘失败那条瞬态

**结论**：带号的通知**只进时间线**（**新来的也不弹**、历史当然更不弹）；🔴 **唯一的例外**是**写盘失败那条瞬态**（它进不了时间线）—— 它画在**浮窗里面**（**参与布局**，不是浮窗）。
**理由**：弹出来的那种"顶部浮窗"会在用户正读东西时抢走注意力，而且它把"这条通知"和"这条通知讲的那件事"分成两处看；写盘失败那条之所以例外，是因为**它没法落盘**（正是它在报的那件事）—— 而"参与布局"是为了不让它盖住任何东西（也就不会挤动布局）。
**连带动作**：这条规则收成一个**纯函数**（该不该弹），判据分两层（纯函数一层、形状一层）；文案一律**由服务端给、客户端照抄**（客户端里一个字的模板都不许有，否则两半会漂，而漂的那天没有闸会响）。
**判据**：`v2/apps/mobile/lib/models/notice.dart` 的 `shouldPopNotice()` · `test/unit/notice_test.dart` · `test/widget/notice_shape_test.dart` · [`../dev/144-NO-NOTICE-OVERLAY.md`](../dev/144-NO-NOTICE-OVERLAY.md)。

## 第 14 族 · 续做（`D10`）

### `D10` 续做 ＝ 把主人的原话重新派一遍；只读才自动

**结论**：续做就是**把主人的原话重新派一遍**（不是"接着上次那半句写"）；因此它天生会把**已经做过的副作用再做一遍** ⇒ 只有"**整轮只碰过只读工具**"的活才自动重来，其余**只通知、不自动重来**。
**理由**：要安全就必须能回答一句话"**这件事做过没有**"—— 而这个仓库里**没有任何东西能回答它**（工具结果不进时间线）。宁可少续做，也不能重复下单、重复发信。
**连带动作**：额度、间隔与并发都住在一个**纯函数**里（一次只挑一件、挑**最近**那一件 —— 他最可能还在等的那件）；额度数的是"**发起过几次**"（认不出"上游失败 / OOM"就先都算 —— 那是更严的方向，而且"我试过几次"这句话是真的）；崩溃环里**一件都不重来**（那由降级启动挡）。
**判据**：`src/resume-plan.js` · `test/resume-plan.test.js` · `test/reconcile.test.js` · [`../dev/10-RECONCILE.md`](../dev/10-RECONCILE.md)。

### `D10.1` 只做只读的活

**结论**：只有**整轮只碰过读类工具**的活才自动重来；**碰过会改东西的工具（哪怕只碰了一下）⇒ 只通知、不自动重来**，并在话里带上"**你看一眼，要不要再做一遍**"。
**理由**：判据必须能回答"这件事做过没有"，而今天没有任何东西能回答它 ⇒ 只能按"**这一轮动过东西没有**"来保守地分；而那句"你看一眼"是这一条通知的**全部意义**（丢了它，就只剩一句免责声明）。
**连带动作**："这一轮动过东西没有"这件事**要从工具调用里记下来、而且落盘**（重启之后才查得到）；那条账**不含工具名、不含参数**（它会 replay 给客户端）。
**判据**：`src/tools.js` 的 `isReadOnlyTool` · `src/session-translate.js`（按工具调用记那一笔）· `test/mutation.test.js` · `test/resume-plan.test.js`。

### `D10.2` 只读白名单（保守；`bash` 不在里面）

**结论**：只读白名单是**按名字列的**：读文件与找文件的、上网查的、读自己与别的 agent 状态的那几件 —— **`bash` 不在名单里**（一个 shell 能干任何事）。**不在名单里的一律算"会改东西"**（默认拒绝，不是默认允许）。
**理由**："帮我查个东西"这类活只有在走"读/查"那几件工具时才会自动续做，**走了 `bash`（哪怕只是列个目录）就只通知** —— 这是**刻意的保守**：宁可少续做，也不能重复下单、重复发信。
**连带动作**：名单是**冻结的数组**（不是可变的集合 —— 冻一个集合会给人"改不了"的错觉）；SDK 升级加了新工具时，它会**自动落到"会改东西"那一类**（这是安全的默认），不必改这张表。
**判据**：`src/tools.js` 的 `READ_ONLY_TOOLS` · `test/mutation.test.js`（含"默认拒绝"与"`bash` 不在里面"两条）。

### `D10.3` 失败五类

**结论**：失败**五类**：**① 上游不通**（不计额度）· **② OOM / 被硬杀**（不计额度）· **③ 我们自己的错**（落盘失败 / 代码 bug）· **④ 它做不完**（超时 / 上下文不够）· **⑤ 等主人确认而没等到**。
**理由**：前两类不计额度，是因为那两类失败**不是它的错**（"上游失败 / OOM 也计入额度"会让用户收到的是假话：明明不是它做不成，却被算成它做不成）。
**连带动作**：🔴 **分类器的现状要说清**：**① 与 ② 已经有判据**（① 只认明确的网络错码与"对面现在没法干活"的状态码；② 拿**内核的 cgroup 计数**当证据 —— `SIGKILL` 不算证据，那是猜）；**③④⑤ 仍然没有分类器**（拿不到能把它们分开的信号 ⇒ **认不出就说**，不编）；每一类各有一句人话。
**判据**：`src/notice.js` 的 `FAILED_LINES` / `failedLine` · `src/session-translate.js` 的 `isUpstreamFailure` · `src/oom.js` · `test/auth-failure.test.js` · `test/oom.test.js`。

### `D10.4` 「挪走」＝ 先收口，后面的话另起一条

**结论**：「挪走」＝**先收口旧的那条，后面的话另起一条**；它与**转交**（**不收口**、往同一个气泡里续写）**语义相反**，所以**必须是两个不同的状态值**。
**理由**：它是**唯一**与"同一时刻每间最多一条未收口"自洽的那个；共用一个状态值的话，那条不变量**没法校验**（无从判断"这一轮到底收没收回"）。
**连带动作**：转交那四条硬规矩照旧 —— **只有工具调用能发起**（正文里写"我转给某一间"不算，那叫"把自然语言当控制面"）· **一轮最多一次 ＋ 禁回环**（`A→B→A` 被拒）· **目标必须已存在**（不建）· 发起那条消息**不收口**且续写挂**同一个气泡**；续写事件的可见标签打**发起那一间**，"谁在干活"另加一个字段、只用于审计与用量。
**判据**：`src/handoff.js` 的 `decideHandoff` · `test/handoff.test.js` `D-1`…`D-8` · [`02-ARCHITECTURE.md`](02-ARCHITECTURE.md) §4.5。

### `D10.5` 续做并发 ＝ 全局 1

**结论**：续做**全局同时只跑一件**（一次只挑一件，挑**最近**那一件）。
**理由**：两件一起自动重来，等于把"同一条路走两遍"的风险乘二，而"重复下单 / 重复发信"正是这一族最贵的错；而"每会话几件"那种口径会让并发数随房间数长上去，谁都不知道上限在哪。
**连带动作**：这一条落在那个**纯函数**的最后一步（候选按时间排序、只取第一条）；它与"同一件两次之间要隔一段"是两条不同的闸（一条管并发、一条管频率）。
**判据**：`src/resume-plan.js`（排序后只取第一条那一段）· `test/resume-plan.test.js`。
