## 第 1 族 · 安全与权限（`P1` / `P2`）

### `P1` 助手不能改自己：它只能提申请，签字的是主人

**结论**：凡是"让改动变成**下次开机自动读**"的路径，都只有主人能按下那一下。
**理由**：威胁的真实形态不是"它干一次坏事"（那能收拾），而是"**坏事能不能留下来**"——它读到一段看不见的网页内容 → 被诱导写进自己的配置 → **从今往后每轮开机都读那一段** → 而表面上一切正常。只要它还握着改自己的手，一人一台盒子、记忆隔离、外部内容不可信**全都白装**：它能从那一边把墙拆了。
**连带动作**：改动写成补丁放 `proposals/`（已在 `.gitignore` 里），主人跑 `scripts/apply-change.sh <补丁>` 把它变成**一个 commit**；apply **不替主人重启**（重启会打断正在说的那一轮，重启是主人自己决定的一步）。
**判据**：`v2/services/core/test/apply-change.test.js` · [`../dev/19-P1-P2.md`](../dev/19-P1-P2.md) · [`06-OPERATIONS.md`](06-OPERATIONS.md)。

### `P1.1` 只有主人亲口说"改"才能执行

**结论**：助手可以提方案、可以写补丁，**永远不能自己按那个按钮**。
**理由**：这道闸挡的不是"多一步"（主人自己说过：从第 3 次起他会开始闭眼 apply —— 那样 P1 就没了），而是"**改主意的窗口**"：正因为它要经过主人，他才有机会在按下之前说"等等，不是这个意思"。
**连带动作**：助手产出的命令必须**短到主人愿意看**（一条命令 ＋ 一个补丁）；申请里不许夹"顺手也改一下"。
**判据**：`scripts/apply-change.sh`（只从 `proposals/` 取、要求树干净、只落一个 commit）· `test/apply-change.test.js`。

### `P1.2` "摘够"的判据：没有任何一条路能让助手的写入变成"下次开机自动读"

**结论**：**部署期**只要还剩一条这样的路径，就没摘够；**开发期**的形态是**审计**（每次重建开机清单都留一行痕）。
**理由**：这是 P1 唯一可操作的验收口径 —— 不说"它应该老实"，只说"**还剩几条路**"；路数得清，才谈得上收口。
**连带动作**：开机清单里凡是"开机就喂给 agent 的"（人格 / 能力层 / 小程序限定档 / 模型补丁 / profile / `AGENTS.md` / 手册）都必须是 `strict`；`src/` 与 `scripts/` **今天刻意是 `report`（只报不拦）**——开发期代码天天改，否则每改一行主人就得补一条 `sudo`；**这个让步有一条测试钉住，免得下一个人以为它已经是 `strict`**。
**判据**：`v2/services/core/src/integrity.js` 的 `protectedPaths()` · `test/integrity.test.js` · 留痕在 [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) §九。

### `P1.3` 说明书与能力收回必须同批改

**结论**：`AGENTS.md` 与 `hupo-persona.yml` 里"**直接动手**"那类话，必须与"收回哪几样能力"**同一批**改，不许只改代码。
**理由**：只改代码不改说明书，等于把同一个坑留给"下一次开机的它"：它照旧以为可以自己动手 —— 而且**它读到的说明书在开机清单里是 `strict`**，改它是一种要被验证的动作。
**连带动作**：两处都在 `protectedPaths()` 里、都是 `strict` ⇒ 改完**要请主人重建开机清单**，否则下次重启拒绝启动。
**判据**：`v2/services/core/hupo-persona.yml` · `AGENTS.md` · `test/integrity.test.js`。

### `P1.4` 判断"哪些文件不能写"的那份清单，助手碰不到

**结论**：清单本身（`/etc/hupo/integrity.json`，`root:root 0444`）与"怎么判"（`src/integrity.js`）都在助手够不着的一侧；每次开机核对，对不上就**拒绝启动 ＋ 报警**。
**理由**：清单要是助手能改的，它就能先把自己的那一条划掉、再改自己 —— 那这道锁只是"仪式"。审的不是"有没有改"，是"**改没改对得上开机时那一份**"。
**连带动作**：清单的 `mode` 字段住在 **root 所有的那份文件**里（助手改不了自己那一档）；想排除某个具体路径，就别把它放进 `protectedPaths()`，**不要按名字连坐**。
**判据**：`src/integrity.js` · `scripts/verify-integrity.mjs --build` · `test/integrity.test.js`。

### `P1.5` 回退不需要助手

**结论**：每次执行前存回退点；**回退由主人一句话完成**（`scripts/rollback.sh`），而且它**一个助手产出的文件都不读**。
**理由**：出问题时**助手本身可能就是出问题的那个** —— 它写的补丁、它记的账、它写的文档都不能当依据。所以回退只信 git 自己的历史。
**连带动作**：回退用 `git revert`（把这一次**反做一遍**，历史留着，回退本身也能被回退）；🔴 **不许用"退回到上一个提交"那种做法** —— 它会连同后面每一个改动一起丢掉。
**判据**：`scripts/rollback.sh` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §三。

### `P1.6` 申请的形式：一个文件，落在助手自己的工作区；host 侧按它执行

**结论**：申请 = 一份**主人看得完**的文件（一条命令 ＋ 一个补丁）；host 侧按它执行；**每次改动记一笔账**。
**理由**：P2 的安全性等于"**主人真的看一眼**"。养成了闭眼跑的习惯，"助手提申请"就退化成"助手有 root，只是慢一点"。所以形态必须短、必须只有一处看的地方、必须留下"谁什么时候改的"。
**连带动作**：补丁只能从 `proposals/` 里来（允许从任意路径 apply，等于主人看的那份和生效的那份可以不是同一份）；`proposals/` 同时被 `.gitignore` 排除（不然申请文件本身就让仓库永远有未提交改动，那道干净闸永远过不去）。
**判据**：`scripts/apply-change.sh`（头部注释把这两条理由写死了）· `test/apply-change.test.js`。

### `P2` 执行特权 = 手动：助手把改动与命令准备好，主人自己上机器跑

**结论**：部署期**不预装任何常驻特权组件**，也不把口令交给助手；助手只准备"到最后一键"。
**理由**：一个公开的网页登录口，要触发一个特权动作而不等于把 root 交出去 —— 难点就这一件。选"人工执行"是因为它的边界**小到能用眼睛看完全部输入**（一条命令 ＋ 一个补丁），而常驻守护/免密那两条的边界大到没人能一眼看完。
**连带动作**：要做的事写成"主人跑什么、跑完会发生什么、怎么撤"；跑完**不替主人重启**（重启留给主人决定）。
**判据**：[`06-OPERATIONS.md`](06-OPERATIONS.md) §五 · [`../dev/19-P1-P2.md`](../dev/19-P1-P2.md)。

### `P2.1` 不预装任何 root 组件

**结论**：不需要 root 服务、不需要定时任务、不需要为"多用户隔离"预装 uid 那一套 —— 今天就能用。
**理由**：每多一个常驻特权件，就多一个"它自己能不能改自己"的问题；而这一批要验的恰恰是"**不靠特权件也能把事情办成**"。
**连带动作**：真要动 root 的那几件（重建清单、装容器）走**主人一句话**；白名单也只给**具体那几条命令**，不是把口令交给助手。
**判据**：`scripts/apply-change.sh` · `scripts/rollback.sh` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §五。

### `P2.2` docker 组永久不碰

**结论**：`deploy` 不进 `docker` 组；宿主上的 docker 访问权 = **宿主的 root**，**永远不给**。
**理由**：那等于给一个**跑着 AI 的账号**免密 root，比"要口令的 sudo"更松 —— 而它看起来只是一次 `usermod`。这是**永久否决**，不是"这一轮不做"。
**连带动作**：需要容器就装 podman（根下的那套不需要 docker 组）；凡是要"用 docker 顺便解决一下"的提议，回到这一条。
**判据**：本机实测 `groups`（`deploy` 只在 `sudo`/`users`）· [`../dev/23-DEV-VS-DEPLOY.md`](../dev/23-DEV-VS-DEPLOY.md)。

### `P2.3` 本轮不装 podman；两种 root 不是一回事

**结论**：容器是"开第二个用户"的开门条件，不是第一步；而**宿主上的 docker 访问权**（＝宿主的 root）永远不给，**容器内部的 root**（＝那个盒子里的 root）应该给 —— 不给它就是个残废。
**理由**：这正是容器方案的卖点：今天不敢给 root，因为给了就是给整台机器；有了容器，可以**在盒子里给它完整 root，而外面一点碰不到**。
**连带动作**：容器那一套的装/撤/核对在 [`06-OPERATIONS.md`](06-OPERATIONS.md) §七与 [`09-APPS.md`](09-APPS.md)；盒内 agent 固定 uid 1000，盒子里的 root 是它自己的世界。
**判据**：`v2/services/core/src/tenants.js` · `scripts/check-container.sh`。

### `P1`／`P2` 的读法：开发期与部署期是两套

**结论**：**部署期**（服务用户的那一套）P1/P2 原样有效；**开发期**（本机、主人就在跟前）主人已授权助手做开发上的特权事（装工具、跑维护脚本、重建开机清单），本机的护栏降级为**审计**（每次重建留痕）。
**理由**：判据**不是"哪台机器"**，是**这一段工作在服务谁** —— 本机同时是开发机又是线上机（`127.0.0.1:8020` ＋ 隧道），所以"换台机器就安全"那种读法是错的。降级不等于拆掉：**留痕就是那根撑着的柱子**（没有它，降级就等于拆）。
**连带动作**：授权**只到开发期**；口令不进任何文件、不进日志；要放开就放开**具体那几条命令**（白名单），⚠️ 但白名单里放一个"助手能改的脚本"实际上仍然是 root（它的价值是留痕，不是圈住）。
**判据**：[`../dev/23-DEV-VS-DEPLOY.md`](../dev/23-DEV-VS-DEPLOY.md) §四／§五 · [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) §九。

### `P-a` 完整性清单由主人手动重建/签名

**结论**：`/etc/hupo/integrity.json` 由主人跑 `scripts/verify-integrity.mjs --build` 生成 —— **`root:root 0444`**，每次改清单都要主人动手一次。
**理由**：这是"清单护住清单自己"这件事绕不开的递归坑的唯一出路：签名动作本身必须在一个助手够不着的地方发生。接受"每次改清单要主人跑一次"，就是接受这条边界。
**连带动作**：**命令不许手打** —— 照 `verify-integrity.mjs` 打印出来的那一条粘（里面是绝对路径：本机没有系统 `node`）；改了 `strict` 的那几个文件（人格 / 能力层 / `AGENTS.md` / 手册 / profile）**不重建，下次重启就拒绝启动**。攒成一次做，少让主人跑几条。
**判据**：`scripts/verify-integrity.mjs` · `src/integrity.js` · [`06-OPERATIONS.md`](06-OPERATIONS.md) §三。

### `C1` "摘够"的判据 ＝ "清单里没有可写路径"

**结论**：P1.2 不是"全仓 grep 等于零"（对运行时数据不成立）——判据是"**那份清单里没有一条是可写路径**"，外加"清单之外的高风险路径要有别的说法"。
**理由**：`~/.dsh/storages/**`（会话缓存 / KV）与账本（用户数据）**每一轮都在被写**：把它们放进清单只有两种结果 —— `strict`（每轮之后开机都对不上 ⇒ 天天拒绝启动）或 `report`（每次开机都报一句 ⇒ 每次都响的报警等于没有报警）。所以它们**故意不在清单里**。
**连带动作**：代价如实认下 —— "有人往 KV / 账本里塞东西"这条路**没有被清单覆盖**；覆盖它得看**内容**而不是**摘要**，那是另一件事。别处的补偿是"写盘只有服务端那一处"（MCP 那支只能经域套接字提请求）。
**判据**：`src/integrity.js`（那两条 `storages` / 账本的注释就是这一条的正文）· `test/integrity.test.js`。

### `C5` 宿主上的 `sudo` 要口令 —— 这是部署期那道锁的地基

**结论**：本机的 `sudo` **没有免密、也没有装白名单**（`sudo -n true` 会失败）；这件事**不是不便，是安全地基**。
**理由**：P2 甲的全部安全性建立在"**多一步、而且那一步只有主人过得去**"上。要是 `sudo` 免密，P2 就退化成"助手有 root，只是慢一点"——而说明书里任何一句"你免密"都会把这道地基说没。
**连带动作**：开发期主人已授权助手做开发上的特权事，但**机制上仍要口令**（要放开就放开具体几条命令，且那条白名单的价值是留痕）；`AGENTS.md` 与 `hupo-persona.yml` 里凡是讲"直接动手"的地方都要与事实一致（`AGENTS.md` 本身是 `strict`）。
**判据**：本机实测（`sudo -n true` 失败）· `AGENTS.md` §八 · [`../dev/23-DEV-VS-DEPLOY.md`](../dev/23-DEV-VS-DEPLOY.md)。

## 第 2 族 · 承重墙（`X1` / `X3`）

### `X1` 口径：编号的"全局"＝ 这个用户那条可见时间线

**结论**：`X1.1` 说的"全局"是"**这个用户那条可见时间线**"——**不是**全机器一个计数器，**也不是**"每条 DSH 会话各数各的"。
**理由**：两个都不是会错意的问题：全机器一个计数器会把两个用户串起来；每条会话各数各的会让"同一间里的编号"在换会话之后对不上。一条可见时间线 = 一条日志，多作用域**只是事件上的 `scopeId` 标签**，不是并列的计数器。
**连带动作**：落地形态由 `P-l` 定死（每个用户一条 `Timeline`；`ScopeView` 是同一把 `Timeline` 上带标签的视图）；"一条 WS 连接 ＋ 焦点路由"是另一层的事，别混进来。
**判据**：`v2/services/core/src/timeline.js` 文件头 · `test/scope-single-log.test.js` · [`../dev/84-DISPATCHER-FOCUS.md`](../dev/84-DISPATCHER-FOCUS.md) §六。

### `X1.1` 编号由调度器统一发

**结论**：编号由**服务端那一个取号函数**发（`Timeline` 的 `#nextSeq`），不是各会话自己数自己的，也不是客户端给的。
**理由**：客户端给的号可以被伪造、可以在重连后重复；各会话自己数的话，"同一条时间线上两件同时发生"就会撞号 —— 而号是客户端续传游标唯一的排序依据，撞号＝**它手里的位置错位**。
**连带动作**：全模块**只许有这一处 `seq++`**；别处要号只能向时间线要。
**判据**：`v2/services/core/src/timeline.js`（"只有一个取号函数"）· `test/seq-monotonic.test.js`。

### `X1.2` 编号 = 已落盘事件的最大编号 + 1，只增不减

**结论**：持久事件的号 = **那条日志已落盘的最大号 + 1**；重启从磁盘取 max ⇒ 编号**单调**；某个房间被回收、盘上最大号变小过，就用**号的"地板"**（留痕里的最大号）挡住回头。
**理由**："只增不减"是客户端那个游标的全部信任来源：号一旦回头，客户端会把**已经拿过的号**当成新事件，或者把丢掉的号当成"还没有"。
**连带动作**：取号的下限（`seqFloor`）由回收那一路传进来；缺省 0 ⇒ 既有调用方逐字不变。
**判据**：`src/timeline.js` 的 `#resumeSeq` / `seqFloor` · `test/seq-monotonic.test.js`。

### `X1.3` 先落盘、再推给客户端；写盘失败必须报出来

**结论**：`store.append` 失败**必须上抛**；顺序永远是"**先落盘成功、再推订阅者**"；写盘失败不许吞。
**理由**：反过来（先推、后落盘）会让"屏幕上已经有的字"在重启后消失 —— 用户看到的是一条他**再也找不回来**的消息。而吞掉失败 = 让服务在盘满之后继续假装正常：崩 → 重启 → 再崩。
**连带动作**：上抛之后**必须有人接**（统一包一层 ＋ 进程级 `uncaughtException` ＋ 用**不落盘的通知通道**发一条人话 ＋ 有界退出 ＋ 退避重启）；接的人写在哪，见 [`03-DEVELOPMENT.md`](03-DEVELOPMENT.md) §5.2。
**判据**：`src/store.js` / `src/timeline.js` · `test/store-append.test.js`。

### `X1.4` 可见时间线上，同一时刻最多一条"还没说完"的消息

**结论**：一条对话里同时只许有一条**未收口**的消息（消息不许交叉）；**但执行照常并行** —— 排队的是**上屏**，不是干活。
**理由**：两条回答交叉着长字，用户分不清哪一句在回答哪一句；可要因此把执行也串起来，就把"同时办几件事"这个能力白扔了。
**连带动作**：未收口那条**按作用域各记一份**（不是全局一份）——否则"甲房间正说着、用户切到乙房间说一句"会当场被这条不变量拒掉；那是把一条正确的规矩用错了地方。
**判据**：`src/timeline.js` 的 `#opens` · `test/message-writer.test.js`。

### `X1.5` 显示用发生时刻

**结论**：时间线上显示的是事件**发生**的时刻，不是客户端**收到**的时刻。
**理由**：补发/重连时"收到时刻"会把三小时前的几十条全画成"刚刚"——那比不显示时间更坏：用户照着"刚刚"去理解一件事的先后顺序，得到的是假的。
**连带动作**：事件落盘时就带 `at`（允许调用方显式给，缺省才是取号那一刻的钟）；客户端只显示这个字段。
**判据**：`src/timeline.js`（`at: event.at ?? clock()`）· `v2/apps/mobile/lib/models/chat_time.dart`。

### `X1.6` 补发段必须带"你不在的时候"

**结论**：断线重连补发过来的那一段，**必须**带一个"**你不在的时候**"的标记；而首次打开那一段**不许**被标成补发。
**理由**：不标，用户会把三小时前的话读成"它刚说的"——那既是骚扰，也是假话（"每次登录都弹一条『刚才出了点事』"就是这个形状）；标反了，他每天开一次 App 就看见一次"你不在的时候"。
**连带动作**：标记字段**现在就留在协议里**（`P-h` 那条线上标记，不落盘）；只在**续传游标 > 0** 时标；首次打开只给**最近的一段**，更早的由客户端往上翻按页取。
**判据**：`src/resume.js` · `test/resume.test.js` · [`../dev/141-HISTORY-FIRST-OPEN.md`](../dev/141-HISTORY-FIRST-OPEN.md)。

### `X1.7` 计数器按可见时间线各数各的

**结论**：张三的号不影响李四的 —— 每个用户**一条日志、一套号**；而同一个用户内部，**多作用域共用这一套号**（`scopeId` 只是标签）。
**理由**：多人共用一台服务时，全局号会把"谁的话在第几位"变成可推断的元数据；而同一用户内部再按房间各数一套，会让"一条可见时间线"这个前提消失（也就没有"一条日志"了）。
**连带动作**：补发与订阅都走**他自己那一份**时间线（身份只从验过签的令牌来）；否则甲连上来的流会补发出乙的话。
**判据**：`src/timeline.js` 的 `eventInScope` · `test/scope-single-log.test.js` · `test/multitenant.test.js`。

### `X2` 协议里现在就带着三样身份标签

**结论**：事件上**现在**就带着 `scopeId`（哪一间产的）· `agent`（谁在说）· `origin`（为什么开口）；界面显示不显示是另一回事，**字段在协议里**。
**理由**：字段是**上线即冻结**的东西（老客户端还在跑）：等界面要用的时候再加，就得同时维护两代协议；而"这条是谁说的、为什么冒出来"这两个问题，界面迟早都要回答。
**连带动作**：`v1` 界面可以不显示，但**不许**因为"现在没人读"就把它拿掉；新加身份信息一律走这两条轴（`agent` ＋ `origin`），不许再新造一个语义重叠的字段。
**判据**：`src/message-writer.js`（`agent` / `origin` 落到事件上）· `test/message-writer.test.js`。

### `X3` 收起 ≠ 删掉：删掉进回收站、到期真删、注销立刻清空

**结论**：删一轮 = 落一条**墓碑**（`turn/deleted`，取号落盘，内容还在盘上）；进回收站后默认留一段期限，**到期前先告一声**；到期或手动"真删" = **压实**（逐条换成最小占位、**保留各自的 `seq`**，盘上 grep 不到内容）；注销账号 = **立刻清空**。
**理由**：真删要真的不在盘上，而 append-only 是删不掉字节的 ⇒ 只能重写；重写又不能让号跳（客户端 `sinceSeq` 全靠号）⇒ "压实但保留号"是唯一自洽的形态。回收站留一段期限是"**可防错 > 可恢复**"里"可恢复"那一半的兜底。
**连带动作**：删前**必须列清单**，而清单是**从状态清单推出来的、不是手写的几句话**（手写的一定漏，漏一项就是屏幕上说"删掉了"、其实还在）；"单条删"不许另造一个"说删就删"的口子。⚠️ 今天界面上的"回收站入口"已经砍掉 ⇒ **用户自己拿不回来**，所以"删之前把要删的摆出来问一次"是底线。
**判据**：`src/trash.js` · `test/trash.test.js` · [`../dev/28-DELETE.md`](../dev/28-DELETE.md)。

### `X3` 的注销那一段：只能注销自己，而且要身份再确认

**结论**：用户能在网页上注销（`POST /api/cancel`，入口在"填钥匙"那一屏下面、不抢眼）：点下去**先列清单**再确认；**只能注销自己**（身份只从验签令牌来）；**再确认一次身份**（要最近真的登录过）；收掉之后**令牌全撤 ＋ 账号那一行也删**；**每个动作写审计**。
**理由**：注销**不可逆**（那一台连同里面的东西一起收掉），而"只认令牌"就意味着**一个被盗的令牌能删掉一个人所有的东西**。
**连带动作**：身份再确认看令牌签发时间，**续期不刷新这个时间** ⇒ 旧令牌刷不过去（挡的就是"被盗的旧令牌"），过不去就 409 且**什么都没发生**；审计写成**两份文件两个写入者**（服务 / 特权侧各写各的 ⇒ 谁也伪造不了对方的行）＋ 形状逐字一致 ＋ 一个脚本并起来给人看。⚠️ 短信通道接上之前，这道门和"登录"一样强。
**判据**：`src/reauth.js` · `src/audit.js` · `test/cancel-route.test.js` · `test/reauth.test.js` · `test/audit.test.js`。

## 第 3 族 · 能力与边界（`P4` / `P5`）

### `P4` 做能力契约层：第一批只做登记表本身 ＋ 一个真数据源，不生成界面

**结论**：有一条**能力登记表**，每条能力登记四样：**形状**（字段 ＋ 只追加）· **版本化**（写进账本就不再改语义，改＝新增字段）· **失败语义**（校验不过就不写，并说清哪一项没听准）· **额度字段**（数值只住代码）。第一批只做**这张表 ＋ 一个真数据源（工时账）**，**不生成界面**。
**理由**：AI 不能在生成界面的同时**现编数据源** —— 否则今天生成的界面字段叫 `amount`、明天叫 `money`，昨天记的账今天读不出来：那不是质量问题，是**不可复现**。这条也是整套产品假设里唯一能两天验证的：用户那句话到底能不能映射到一组**稳定**的能力上。能 ⇒ 生成界面只是渲染问题；不能 ⇒ "AI 手机"退化成"每次现编一个玩具"。
**连带动作**：AI 只做**组合 ＋ 渲染**，绝不发明接口；能力层挂在**仓库自己的一份 patch**（`v2/services/core/hupo-capabilities.yml`）上，**不碰 `strict` 的 profile**；写盘只有宿主一处（模型不许直接写盘，它只能"提一条要写的"）；出口同批（列表 ＋ 导出 ＋ 单条删，形态是**一段能粘进微信的话**，不画表）。
**判据**：`v2/services/core/test/capabilities.test.js` · `test/ledger*.test.js` · [`../dev/31-LEDGER.md`](../dev/31-LEDGER.md) §四。

### `P5` 不做代执行，只做"准备到最后一键"

**结论**：**不做代执行**（不模拟点击、不假装能登进别人的网站替他点）；事做到"**准备到最后一键**"就停下，并说清"接下来该你点"。
**理由**：银行、政务、挂号、快递那些**永远不会给接口**；模拟点击做不到，也不该假装能做 —— 出事要有人负责，而"它替我点了提交"把责任人抹掉了。⚠️ **"声明式代操作"这个叫法不许用**：名字会自己长回"自动化"，而这条路是明确不走的。
**连带动作**：做不到就说做不到 ＋ 他还能怎么办（不假装能做）；它的价值体现在"链接在这，点开就是填好的表"，而不是"我帮你点了"。
**判据**：`v2/services/core/test/persona.test.js`（源码级人格硬规则）· [`01-PROJECT.md`](01-PROJECT.md) §十一。

## 第 4 族 · 命名与登录（`D1` / `D2`）

### `D1` 隐喻 = 一件事一本本子；第一入口 = 图标墙

**结论**：一个物件 ＝ **一件事的一本本子**（**不是**文件夹、**不是**应用、**不是**频道、**不是**房间）；重名之下**加第二行小字**（"最近：…"）；**内置图标保留**；第一入口 ＝ **图标墙**。
**理由**：三个候选只有"本子"一个不撒谎 —— 叫**文件夹**，用户十分钟内就会往里拖文件、传附件（真试过，放不进去，他自己花一整天解开这个误会）；叫**应用**，点开还是聊天，用户判定"点开跟没点一样"；而**本子**承诺的（能翻、能问、能添页）**正好就是聊天已有的能力**，一句空话都不多。撤掉内置图标也不行：它们是"**这不是我的东西**"的锚，撤了第一天桌面就是空的，而空桌面是全篇最一致的发慌点。
**连带动作**：界面上的物件**要用他自己的词**命名；重名靠"最近做过什么"区分，不许拿系统编号顶。
**判据**：`v2/apps/mobile/lib/models/desktop_words.dart` · [`01-PROJECT.md`](01-PROJECT.md) §九 · [`../dev/59-USER-APPS.md`](../dev/59-USER-APPS.md)。

### `D1.1` 「工作区」三个字界面永久禁用

**结论**：**「工作区」永久禁用** —— 图标名 / 标题 / 提示 / 空屏 / 报错，一处都不许；它进禁用词扫描。
**理由**：十个人里**零个**发现"工作区"是什么，而且它出现时会吓到人：05 读成"上班干活的地方"、06 读成"以前学校里写黑板报的角落"、03 的第一反应是"**是不是流氓软件**"。原话比任何道理都硬。
**连带动作**：禁用词一条一条挂在 `models/forbidden_words.dart` 上，由 `test/unit/forbidden_words_test.dart` 扫**整棵树里的字符串字面量**；⚠️ **"必须干净"的那份名单今天还有洞**（设置页顶层那行"模型设置"含禁用词「模型」却不在名单里）—— 洞记在 [`../dev/224-V3-PROJECT.md`](../dev/224-V3-PROJECT.md) §六·2。
**判据**：`v2/apps/mobile/lib/models/forbidden_words.dart` · `test/unit/forbidden_words_test.dart`。

### `D1.1·补` 聊天窗口那一格放开，其余界面照旧

**结论**：**聊天窗口里**，工具名、入参、输出摘要、系统提示词、每轮 token **都可以上屏**；**产品其余界面**（首页 / 登录 / 桌面 / 设置 / 空态 / 报错）照旧**一个内部词都不许有**。
**理由**：放开的是"**把这条会话摊开给人看**"（它的读者是主人自己，要的是可核对），**不是**"文案可以内部化"。把两者读成一件事，那道禁用词闸就废了 —— 而它守的是"用户不用学新东西"。
**连带动作**：默认那一行**仍然说人话**（"做一个小程序 / 跑命令 / 改文件"），**原始名字住在展开的那一块里**；每轮那一串 token 收进「过程」折叠（默认收起）。
**判据**：`test/unit/forbidden_words_test.dart` · [`../dev/115-DSH-WINDOW-PARITY.md`](../dev/115-DSH-WINDOW-PARITY.md) · [`../dev/154-CHAT-RECORD-LOOK.md`](../dev/154-CHAT-RECORD-LOOK.md)。

### `D1.2` 名字由系统提议，只用用户自己说过的词

**结论**：名字**由系统提议**，而且**只用用户自己说过的词**；**永远不问**"你想叫它什么"。
**理由**：一上来问名字，第一反应是"那算了"（用户原话）；而用户自己说过的词（"这篇文章的地方"）才是他认得出的名字 —— 系统编号他记不住，系统造的美名他更记不住。
**连带动作**：新建那一步**不摆命名输入框**（那一步是"多一样要学的东西"）；提议的名字要能从他那句话里指出来源。
**判据**：`v2/apps/mobile/lib/models/desktop_words.dart`（改名入口在长按/详情里）· `test/widget/desktop_test.dart`。

### `D1.3` 能改名，随时能改

**结论**：**随时能改**；入口在**长按 / 详情**里，**不在首建流程里**。
**理由**：名字是会变的（"云澜"被听成"云兰"），改名的成本必须低到随手；而把它放进首建流程，就等于"用一次刚上手的机会考他一道题"。
**连带动作**：改名是本地就拦得住的一件事（空名字不许发一个注定被拒的请求）；改完如实说一声。
**判据**：`models/desktop_words.dart` · `test/widget/desktop_remove_test.dart`。

### `D1.4` 区分同名必须用他自己的话，不许系统编号

**结论**：两个一样的名字，靠**他自己的话**区分（"最近：品牌升级 3h"），**不许**用"第 1 个 / 第 2 个 / 序号"。
**理由**：系统编号对用户是一个**要学的新东西**，而且它不告诉他"这两个哪里不一样" —— 那正是他需要的答案。
**连带动作**：「第 1 个」「第 2 个」「序号」都在禁用词表里；重名那第二行小字读的是"最近做过什么"。
**判据**：`models/forbidden_words.dart` · `models/desktop_words.dart`。

### `D1.5` 产品名 = 「琥珀聊天」

**结论**：**三处逐字用它**：**浏览器标签页** · **"添加到主屏幕"之后的图标名** · **聊天窗口抬头**。**一处出处** ＝ `v2/apps/mobile/lib/models/landing_words.dart` 的 `appName`。
**理由**：名字漂一个字，用户就会以为是两个东西（"我装的那个叫琥珀，这个叫琥珀聊天，是不是山寨"）；而同一份名字写在四处，就一定有一处会旧。
**连带动作**：`web/index.html` 与 `web/manifest.json` 是**脚手架的字符串**（import 不了 Dart）⇒ 靠 `test/unit/web_shell_test.dart` **拿同一个常量逐字钉住**（四处一起漂不了）。⚠️ **品牌名「琥珀」（`landingBrand`）与它不是同一个词**：登录页 / 首页那一格仍是品牌名。
**判据**：`models/landing_words.dart` · `test/unit/web_shell_test.dart` · [`../dev/170-PRODUCT-NAME.md`](../dev/170-PRODUCT-NAME.md)。

### `D1.6` 安卓 2.0 是**另一个 app**，与 1.0 并存

**结论**：装上去的**身份**不同：1.0 是 `chat.hupo.hupo_app`（桌面上叫「琥珀」），2.0 是 `chat.hupo.hupo_chat`（桌面上叫「琥珀聊天」）⇒ **同一台手机上并排装着，新包不会顶掉老包**。
**理由**：主人点名要"另一个 app，不要覆盖 1.0"。安卓按 `applicationId` 认"是不是同一个 app"，所以只要身份不同，两个就谁也覆盖不了谁。
**连带动作**：🔴 **两个下载地址都留着**（新那份 ／ 1.0 那一份原样不动）；⚠️ 网页部署会把静态根清空 ⇒ 1.0 那一份的存档在服务端数据目录，每次部署放回去（**老链接不许 404**）；🔴 **`namespace` 与 Kotlin 那几份不许跟着 `applicationId` 改**（`.MainActivity` 是相对 `namespace` 解析的 —— 那是代码的包名，不是装上去的身份）。
**判据**：`v2/apps/mobile/android/app/build.gradle` · `scripts/deploy-web-v2.sh` · [`../dev/187-APK-TWO-APPS.md`](../dev/187-APK-TWO-APPS.md)。

### `D2` 登录页：门是**手机号 ＋ 验证码**

**结论**：进来那道门是**手机号 ＋ 验证码**（**没有密码**）；"口令""暗号"都不用；按钮说「**打开**」；**四种失败四句话**（码不对 / 手机号不像 / 还没接短信 / 连不上）；临时验证码**必须如实说**；配三件机制：**连不上不清令牌** · **令牌到期自动续** · **忘密码的恢复**（今天没有密码可忘 ⇒ 由验证码这条路接管）。
**理由**：06 那位 68 岁的退休教师**在登录页第一天就放弃**，而 03 的期望原话是"微信抖音都是验证码" —— 验证码是用户**已经学过**的那一套，多一个要打的字段就多一次放弃的机会。含糊的失败提示等于没说：混成一句"登录失败"，他只会反复重输。
**连带动作**：这一屏的**全部文案**只许住 `models/login_words.dart`（那样才进得了禁用词硬闸）；服务端那条密码路照旧认（老客户端/兜底），但**界面上不再有密码框**。
**判据**：`v2/apps/mobile/lib/screens/login_screen.dart` · `models/login_words.dart` · `test/widget/login_test.dart` · [`../dev/37-MULTITENANT.md`](../dev/37-MULTITENANT.md)。

### `D2.1` "能执行命令、能改自己的代码"从登录页拿掉

**结论**：这句承诺**不上登录页**。
**理由**：读完之后是**害怕**（全场只有一个人读得懂）——而登录页是"这道门只有你能开"的地方，不是讲能力的地方；把它留在首屏，等于用一句真话劝退一个本来能用的人。
**连带动作**：它是**产品资产**，不是营销文案：能力怎么讲，去 [`01-PROJECT.md`](01-PROJECT.md) §七 那一节（一块一行），首屏只说"它真会去做"。
**判据**：`models/landing_words.dart` · `models/login_words.dart`（两处都进禁用词闸）。

### `D2.2` 「口令」永久不用

**结论**：**「口令」是永久禁用词**；今天这道门**根本不问口令**（手机号 ＋ 验证码）。
**理由**：用户上一次听到"口令"是"看电视里当兵的站岗"——他得先把它翻译成"密码"，再想"这里为什么要这个"。一个词要过两道，就有一道会卡住人。
**连带动作**：它挂在 `forbidden_words.dart` 上（连"暗号"一起禁：新造的说法同样要学）；文案改动一律走词表闸。
**判据**：`models/forbidden_words.dart` · `test/unit/forbidden_words_test.dart`。

### `D2.3` 按钮说「打开」

**结论**：那颗按钮的字是「**打开**」。
**理由**：「进去」没人读出"进门"，读出来的是"**提交**"——而"提交"是一次有风险的动作（像交表格），"打开"才是他能理解的那件事（打开门、打开一个东西）。
**连带动作**：`model_key_screen` / 设置页里凡是"进入某一屏"的动作，也照"打开 / 关上"这一套说，不许内部词与动词混着叫。
**判据**：`models/login_words.dart`（`loginSubmit`）· `test/widget/login_test.dart`。

### `D2.4` 记忆那句不在这屏说

**结论**：**登录页不说"它会记住你"**。
**理由**：上线之前写它 = **空承诺**；而一个"说了没做到"的记忆承诺，比不提记忆更伤（用户会照着它去信任一个还不存在的能力）。
**连带动作**：记忆要有**可见、可验证、标出处、可一条条删**的出口之后，才谈得上在别的屏讲它（[`01-PROJECT.md`](01-PROJECT.md) §五 原则②）。
**判据**：`models/landing_words.dart` · `models/login_words.dart`（这两份是首屏全部文案）。

### `D2.5` 它自己怎么说话：短、白话、只说他要在意的

**结论**：**能一句说完的不要两句**，先给结果，他问什么答什么。🔴 **不要说的**：过程（"我先…""我推之前…"——做了就说结果）· 实现细节（接口 / 站名 / 字段名 / 状态码 / 版本号 / 文件名 / 端口 / 时间戳 / 工具名）· 复述他的话 · 把所有情况铺开（兜底 / 失败 / 开关在哪 / 以后怎么关）· 设计说明。🔴 **必须说的**（短也要说，一个字都不许省）：① 没做成 / 只做成一半 / 中途改了主意；② **要他按一下**（同意权限 / 填东西 / 改设置）——一句话说清要他做什么；③ 会**丢东西 / 花钱 / 动他已有的东西**——先说；④ 他明确问的细节。
**理由**：主人点名的反例是一段"天气小程序加联网权限"的真实回复 —— 里面**很多不是普适的**。技术味的回答把"我要办的事"埋进了一堆他不需要的判断里。
**连带动作**：⚠️ **这一条不是"少说实话"**：短的是**怎么说**，不是**说不说** —— **报坏消息不挨骂，瞒才挨骂**。
**判据**：`v2/services/core/test/persona.test.js`（源码级，含负向对照）· [`../dev/190-SPEAK-PLAIN.md`](../dev/190-SPEAK-PLAIN.md)。

### `C6` 登录用词以 `D2` 为准：用他已经学过的词

**结论**：两套说法冲突时，**以 `D2`（用户已经学过的那一套）为准**，术语层的建议让路。
**理由**："密码"是微信时代已经学过的词，"暗号"是新造的、**要学**；一个要让用户先学一个词的设计，在登录页这一步就已经输了一半。今天更进一步：这道门连"密码"都不问了（手机号 ＋ 验证码）。
**连带动作**：新造词一律先过"他学过没有"这一问；过不了就进禁用词表 —— 不是文风问题，是缺陷。
**判据**：`models/forbidden_words.dart` · `models/login_words.dart`。

## 第 5 族 · 可访问性（`D3`）

### `D3` 做可访问性，但不做"老人档"这个模式

**结论**：可访问性**做**，但**不做"老人档"这个模式** —— 那几样是"**把默认值改安全**"，**全体受益**。
**理由**：**多一个模式就是多一样要学的**，而且它把"看不清 / 点不准"标成"一类人的毛病"，于是只有那一类人会去开它，其余人继续在不安全的默认值上。
**连带动作**：三样（跟字算 / 不封顶 / 命中区）＋ 甩 ＋ 收起态展开入口，**必须同批**；不可以"只做字号"。
**判据**：`v2/apps/mobile/test/widget/accessibility_test.dart`（那条硬闸一次量完）· [`01-PROJECT.md`](01-PROJECT.md) §十二。

### `D3.1` 不做模式

**结论**：**没有"老人档""简洁档"这种开关**；要改的就改默认值。
**理由**：同 `D3`：多一个模式就是多一样要学的；而且模式一旦存在，"默认那一档可以差一点"就变成默认的借口。
**连带动作**：真需要用户选的，只有**字号**那一条轴（它本来就是个人的偏好）；其余按"最不容易出事"的那个值定死。
**判据**：`v2/apps/mobile/lib/models/appearance.dart` · `test/widget/appearance_test.dart`。

### `D3.2` 三样必须同批，不许拆

**结论**：**容器跟字算** ＋ **不封顶（硬闸）** ＋ **触控目标达标**，**同一批**做；只做字号会更糟。
**理由**：只把字号做大，用户得到的是一屏**更大的、但是点不准也装不下**的字 —— 那比不做还坏：他会以为"这个功能做过了"。
**连带动作**：同批的还有**甩改多条件**与**收起态有看得见的展开入口**（它们是"误触能自救"那一半）；验收一次量完（五档无溢出 ＋ 命中区）。
**判据**：`test/widget/accessibility_test.dart` · [`01-PROJECT.md`](01-PROJECT.md) §十二。

### `D3.3` 关于页按**当前这台设备**如实说

**结论**：不会拼音的人在这台设备上能不能用，**按设备如实说**；检测不到就说得**保守**（"如果你的输入法能语音输入，就能用"），**不许一刀切**。
**理由**：设备**输入法自带语音**时写"用不了"是**假话**，而且会**劝退一个其实能用的人**（走的是输入法，不是我们的话筒）。从"某能力缺失"推出的文案，**能力一到位就要回来改它**。
**连带动作**：⚠️ **今天落地文案要跟着能力走**：`about_facts.dart` 里"原生那个包里还没做录音"那句与事实不符（安卓原生录音/开麦/TTS 已在跑，见 [`../dev/224-V3-PROJECT.md`](../dev/224-V3-PROJECT.md) §三／§六·7）——**改的是落地，不是这条规则**。
**判据**：`v2/apps/mobile/lib/models/about_facts.dart`（这一屏的文案只有这一处）。

### `D3.4` "正在听…"只在**真的在录**时能出现

**结论**：「正在听」是一个**有条件的**词：只有真的在录音时才许出现，唯一合法落点是那颗会转的标记（`hearing_words.dart` 的 `hearListening`）；不录音时**禁用「听」字**，它进禁用词扫描。
**理由**：加了话筒之后"听"就**一个词两个意思**：可能是"它真的在收声音"，也可能是"它收到了、在处理"。把假的画成真的，用户会对着一个不在工作的麦克风说话 —— 那正是"页面在说假话"那一族。
**连带动作**：权限要用人话交代，申请时机 ＝ **第一次按话筒**（不是开 App）；真录不出来、没权限、环境太吵，都要如实说，并给他一条打字的退路。
**判据**：`models/forbidden_words.dart` · `test/unit/forbidden_words_test.dart` · `models/hearing_words.dart`。

### `D3.5` 尺寸随字算、不封顶

**结论**：**容器跟字算**（不是字跟容器）；**不封顶**；并且**做成硬闸**：五档字号 pump **无溢出**，且收起态**有看得见的入口**。
**理由**：真故障是"**字大了、笼子没大**"（Flutter 会缩放显式字号，所以修法不是"字号走主题"——那本来就跟着 —— 而是**容器要跟着字算**）。封顶则意味着"你把系统字体调到最大，我们只给到某一档"——**那又是一种假装支持**。
**连带动作**：判断落在"五档不溢出"这一条上（数值住 [`08-SPEC.md`](08-SPEC.md) §十 与测试）；新加的界面也必须过这道闸，否则它会随时间失效。
**判据**：`test/widget/accessibility_test.dart`。

### `D3.6` 触控目标分两档

**结论**：① **点状控件**（按钮 / 图标）：命中区 **≥44×44**（视觉可以更小，用透明 padding 撑命中区）；② **行级入口**（整行都能点的那种行）：按**面积**算 —— 整行宽 × 行高 ≥ 44×44 且宽 ≥44，而**行高跟着那行文字走**（不为了凑高度把行撑高）。
**理由**：把所有东西一律撑到 44 高，会让"一行小字"漂在一片空白里（真实读数：11 号字那一行被右边一颗 44 的箭头撑到 50）；整行可点之后**命中面积反而更大**（通常从不到两千 px² 变成六千 px²），右边那颗箭头降级成**指示**。
**连带动作**：⚠️ 代价明写：它**不再是"处处 44 高"**；行级那一档的判据量的是**布局盒子**（透明 padding 撑起来的也算），不是"看得见的那一块"。
**判据**：`test/widget/accessibility_test.dart` · `test/widget/chat_spacing_test.dart` · `test/widget/tool_rows_test.dart` · [`../dev/155-ROW-ENTRY.md`](../dev/155-ROW-ENTRY.md)。

### `D3.7` "甩"保留但改造 ＋ 可关

**结论**：「甩」这条手势**保留**，但判据是**速度 ＋ 位移 ＋ 时长三个都要满足**（单看速度会把快速滚动误判成甩），并且**能被动效总开关关掉**。
**理由**：06 那位老人被误触"甩"收起浮窗之后说的原话是"**我找不回来**"——甩本身是他唯一会的那种手势，所以不能删；但只按速度判会把他正常翻看的动作当成收起，所以三个条件缺一不可。
**连带动作**：⚠️ **今天它没有落点**：`widgets/chat_floater.dart` 里只剩三个常量（速度 / 位移 / 时长），**没有任何手势读它们**（改高度的拖动与那两层监听已撤）。⇒ 要么把接线补回来，要么**明说砍掉**；不许让"代码里有常量"冒充"功能在"。
**判据**：`v2/apps/mobile/lib/widgets/chat_floater.dart` 的三个常量 · `models/motion_switch.dart`（动效总开关）。

### `D3.8` 收起态必须有看得见的展开入口

**结论**：**收起态必须有看得见的、点得到的展开入口**（不许是"按了没反应的一块"）：今天那颗就是**录音圆圈右侧那一列的上格** —— 收起档是「展开」（平箭头），展开档**同一颗翻个方向**变「收起」（点一下收回去）；命中区达标，**字挂在 tooltip 与无障碍名上**（图形可以很小）。
**理由**：误触收起来之后必须能自救 —— 06 的原话"我找不回来"说的不是找不到那一小条，是**不知道那一小条就是它**；所以入口必须**一直在同一个位置**、而且看得见"这里能点"。
**连带动作**：展开档里「收起」另有**标题行右端那颗带字的「收起聊天」**（主人点名要的第二条路）；两颗在收起/展开两档里**位置不动**（打开聊天窗口那一下，那颗圆圈一个像素都不许跳）。
**判据**：`test/widget/voice_buttons_test.dart`（量两颗的位置与上下沿对齐）· `test/widget/accessibility_test.dart`。

### `P-d` 收起档**没有**"点外面就展开"这条路

**结论**：**点桌面空白 ＝ 把聊天收回去**；收起档上点它是个空动作（**不展开**）。要展开就走那颗「展开聊天」。
**理由**：桌面上的手势只有一个方向、只学一次（点空白=收起，这是 04 那位用户点名"被破坏就重罚"的那一个）；再叠一条"收起档点外面=展开"就是**多一样要学的**，而且它和"点空白=收起"长得一模一样、后果相反。
**连带动作**：⚠️ v1 基线手册 `08-SPEC.md` §6.3 那两行（"点收起态底部条 / 点收起态那个输入框 ⇒ 展开到上次档位"）与今天的代码不符：代码里 `expand()` 只在那一颗按钮的 `onPressed` 里被调。
**判据**：`v2/apps/mobile/lib/screens/chat_screen.dart` 的 `onTapBlank` / `onCoveredTap`（都是 `collapse()`）· `widgets/chat_floater.dart` 的 `_handle`。

### `D3.9` 「配置」是页面上一个常驻入口

**结论**：**「配置」常驻**（它是桌上那一格「设置」）；要补的缺口是"**填过就再也回不去**"——换一把钥匙，或者看看自己到底填过没有。
**理由**：钥匙填过之后没有任何入口能改、能核对，用户只能重装；而"我以为它还用着旧那把"这种事，属于"界面在说假话"那一族。
**连带动作**：⚠️ **现状必须分得开**：有 / 没填过 / **填过但被判无效** —— 第三种**不许**说成"还没有填"（服务端为此给了专门字段）；「关于」**搬进配置**（顶栏再加一个图标就是七个，手机上那一条会挤成一团）。
**判据**：`v2/apps/mobile/lib/screens/settings_screen.dart` · `models/space_words.dart` · `test/widget/settings_test.dart`。

### `D3.9·补` 配置页是四个 tab

**结论**：四屏 ＝ **聊天 / 语音 / 图片 / 视频**（界面上**不写「模型」**——它是禁用词，用"它管什么"来说）。**语音** ＝ 一把 `API Key`（新控制台那一种；**旧版那两样服务端照旧认**，老账号照旧能用）。**图片与视频是同一把钥匙** ⇒ 只填一栏、两样都能用，界面上**明写"同一把钥匙"**，视频那一屏还要说清**慢、贵、一次只做一段**。视频那一栏有一颗「**验一下**」：**不花钱、不生成**，只回答"这把钥匙那边认不认"，并且"没连上"与"钥匙不行"必须分得开。
**理由**：钥匙的"有没有生效"只能由"这条路现在能不能用"来回答，不能由"那一栏填没填"来回答 —— 只填一栏时两格都该是"能用"，否则页面会说"还没填"而其实能用（说假话）。视频那条又慢又贵，不该让他为了"看看钥匙对不对"**先花一笔**。
**连带动作**：**设置过的那一屏只说「已设置」＋「修改」**，输入框只在没设置过、或点了「修改」之后才画（永远摆一个空框会被读成"没生效"，而密钥**从不回填**）；这条自检**不许**顺手做成"试一条"。
**判据**：`src/creds.mjs`（"同一把钥匙"只有一处规则）· `src/ark-check.js` · `v2/services/core/test/ark-check.test.js` · `models/space_words.dart` · [`../dev/79-CREDS-TABS.md`](../dev/79-CREDS-TABS.md) · [`../dev/223-ARK-CHECK.md`](../dev/223-ARK-CHECK.md)。

### `D3.10` 一套外观只有一处出处

**结论**：**以首页为基准**（暖纸底 / 陶土红 / 正文色 / 次要色 / 卡片 / 描边）；**数值只住 `lib/models/design.dart`**（纯数据），`ThemeData` 在界面层拼；**全站只有一处硬编码颜色**，其余全走 `colorScheme`。
**理由**：四屏各写一套颜色，改一处就要找四处 —— 而"找漏了一处"的表现是屏幕上某两屏的同一个东西颜色不一样，没人会当成 bug 报上来，只会觉得"这个 App 有点糙"。
**连带动作**：改那一处，四屏一起变；⚠️ **不许因此写死字号**（`D3.5` 仍然有效：容器跟字算）。
**判据**：`v2/apps/mobile/lib/models/design.dart` · `lib/screens/app_theme.dart` · `test/widget/appearance_test.dart`。

### `D3.11` 从桌面上删掉一个图标 = 真回收 ＋ 二次确认

**结论**：桌面上删掉一个图标 = **真回收**，而且**必须二次确认**。一起拿走的四样：① 制品那一格 ② 那一间的工作区目录 ③ 那一间的对话记录 ④ 那一间里的数据。**留下来的两样**：审计（记一行"谁在什么时候删了它"）与用量/记账（随制品进回收区，**不是消失**）。
**理由**：他说的"删"就是不要了；留一半（比如只删图标、数据还在）会让"删了"变成假话。而四样里任何一样都够让他后悔，所以确认必须**把要拿走的东西摆出来**再问一次。
**连带动作**：⚠️ **拿不回来** —— 界面上**不许**承诺可恢复（今天没有任何入口能把它列出来）；盘上照旧留一份我们自己能捞的软删，但**界面不承诺**。⚠️ 这是"**同一时刻最多一条未收口**"那条不变量**唯一允许留号洞**的地方（被回收的那些号）——必须留痕。⚠️ 和"回收站"不是一回事：回收站管**单条对话**，这条管**一整个图标那一间**。
**判据**：`v2/services/core/test/app-remove.test.js` · `test/widget/desktop_remove_test.dart` · [`../dev/103-APP-DELETE.md`](../dev/103-APP-DELETE.md) §七。

### `D3.12` 聊天窗口的字分两档，非主要那一档"小很多、紧很多"

**结论**：**主要** ＝ 他的话 / 它的话 / 输入框里的字（一档大字号 ＋ 大行高）；**非主要** ＝ 工具行 / 过程行 / 通知 / 出处与状态小字 / 排队条 / 计划条 / 首页那句提示（**明显更小、行高更紧**）；**他自己发的话也跟着同一档**（主要那一档）。两档**都还在用户字号那条轴上**（相对它平移）⇒ 两档之间的差距不会漂；非主要那一档有**地板**（往小调到某一档时不许更小）。
**理由**：一屏里工具行和正文一样大，读起来没有主次、也更慢；而两档若各写死一对数字，用户一调字号就会互相错位。
**连带动作**：字缩小时，**围在它周围的空当按同一比例收一遍**（气泡内外 / 时间线上下 / 非主要行右边那颗展开箭头）；⚠️ **按钮不缩**（"读一遍"、菜单、撤销那些是**动作**不是"非主要的内容"——缩了会点不着），命中区照旧达标；数值只住 `models/dsh_design.dart` 那几个 token。
**判据**：`test/widget/chat_spacing_test.dart` · `test/widget/tool_rows_test.dart` · [`../dev/119-APPEARANCE-AND-FONT.md`](../dev/119-APPEARANCE-AND-FONT.md) §十。

### `D3.13` 壁纸跟着账号走，不按设备存

**结论**：他在**任一台设备**上挑的那张底图 ⇒ **别的设备登录也该看到它**。权威那一份进**账号**；本机那一份**降级成本机缓存 ＋ 离线兜底**；**亮暗与字号不动**（它们仍然是这台设备的偏好）。
**理由**：壁纸是"我的桌面"，不是"这台机器的桌面"；只存本机的话，换台设备就像换了一个别人的桌面 —— 而主人正是**看着文稿截图问出这件事**的（"这个用户设了壁纸，图上怎么没有？"）。
**连带动作**：三条合成规矩**多一条都不许加**：① **没问上**（网络不通 / 非 200 / 读不懂）⇒ 本机照旧、**一个字节都不写账号**（网不通 ≠ 他改了）；② 账号里"**从没记过**"⇒ 本机有就**顶上去**（老用户升级上来的第一下，不许把他挑过的那张抹成默认）；③ 账号里**有记录**（含"明确不设"那个值）⇒ **听账号的**。⚠️ `null`（没记过）与"空"（明确不设）**必须分得开**；写账号没成 ⇒ 本机照旧生效 ＋ 留一个待补标记，下次开机补一次（**不许假装同步上了**）。
**判据**：`src/prefs-store.js` · `models/wallpaper.dart` 的 `resolveWallpaper` · `test/unit/wallpaper_prefs_test.dart` · `test/widget/wallpaper_sync_test.dart` · [`../dev/183-WALLPAPER-ACCOUNT.md`](../dev/183-WALLPAPER-ACCOUNT.md)。

### `D3.14` 聊天底下那一格：一个真输入框 ＋ 那颗圆圈（`D3.14·补（十三）`）

**结论**：**就三步**：① 按一下那颗圆圈（开始听）；② **识别回来的字直接长在底下那个真输入框里** —— 半句/定稿边听边长，**他点进去随时能改**（他一动手，语音就不再往框里写，发的是他手上那份）；③ **按停** ⇒ 等 `asr/end` 那份**整段**回来 ⇒ **发一次**。
**理由**：中间那两层（"听懂 / 语义校正" / "反问"）去掉了 —— 它花掉一次真实往返，而用户要的只是"我说的话变成字、然后发出去"。**那个框跟打字是同一个**：开不了麦的机器上那颗「打字」摊开的就是它，一条「发送」发出去。
**连带动作**：🔴 **按停要"当场有反应"**（按下去这一刻这一格就变：圆圈不再闪"我在录"、字说"收下了"），但**最后那一份字一个都不许丢**；🔴 **在录时那颗圆圈一明一暗地闪** —— **动的只有颜色**，尺寸 / 位置 / 命中区一个像素都不动；🔴 听的那一段有**上限**（省钱），到点只是**接着开下一轮**、**字一个都不清、一次都不发**；说话时那一份字显示的是一张**不会滚的卡片**（从头显示、末尾省略），点一下才变成真输入框（4 行高、跟着光标会把开头卷出框外）。同一行里另有：**最左那颗「清单」**（点开＝"正在干的活"那张浮窗，两个档同一个位置）与**圆圈右侧那一列两颗**（上＝展开/收起，下＝播放语音）—— 那一列**两块 ＋ 中间那条缝 = 那颗圆圈的直径**（三颗上下沿对齐，判据钉着这条等式）。
**判据**：`widgets/voice_bar.dart` · `widgets/chat_floater.dart` · `test/unit/voice_compose_test.dart` · `test/widget/voice_send_test.dart` · `test/widget/voice_buttons_test.dart` · `test/widget/work_list_test.dart` · [`../dev/214-VOICE-REBUILD.md`](../dev/214-VOICE-REBUILD.md) · [`../dev/210-VOICE-CONTINUOUS.md`](../dev/210-VOICE-CONTINUOUS.md)。

### `D3.15` 每个小程序右上角一颗「退出」；底下那颗 home 取消

**结论**：进任何一个 app（他自己的小程序 / 内置那几格）那一屏，**右上角**都有一颗「**退出**」（＝离开这一屏、回桌面）；底下那条里那颗 **home 取消**（同一件事只有一条路）。字要说人话，不许"返回 / 关闭"混着叫。
**理由**：主人原话是"所有的 app 右上角都有一个退出按钮。所以我不再需要 home 按钮" —— 两颗做同一件事，屏幕上就多一个要分辨的东西。
**连带动作**：🔴 **同一时刻只许有一颗**：网页上"真小程序"是 DOM 元素、压在画布上面 ⇒ 那一颗**由页面那一层画一遍**，Flutter 那颗**不画**（内置那几屏由 Flutter 画）；命中区达标、字与图形一起给。
**判据**：`widgets/mini_app_host.dart` · `models/space_words.dart` 的 `miniAppExitLabel` · `test/widget/mini_app_exit_test.dart` · [`../dev/183-VOICE-FIRST-CHAT.md`](../dev/183-VOICE-FIRST-CHAT.md)。

### `D3.16` 小程序那一屏的层次：网页让一格、安卓铺满、内置那几屏两种平台都让

**结论**：🔴 **网页 ＝ 内容不铺满**：平台视图那个矩形**底部让出一格**（那颗录音圆圈 ＋ 它那行住在这里、**由 Flutter 画** ⇒ **两端同一份实现**）；🔴 **安卓 ＝ 铺满**（内容顶到四边，聊天与圆圈天然在最上层）；🔴 **内置那几屏**（设置 / 发现）**两种平台上都让** —— 它们是"内容"，被收起条压住就点不到。三条收成**一个纯函数**。
**理由**：网页上真小程序是**真的 DOM 元素（iframe）**，永远画在 Flutter 画布**之上**；手机（安卓）上没有这条限制（平台视图在画布**之下**）。这是浏览器/平台定的事实，不是取舍 ⇒ 想"一份实现"就去加壳（丙）的代价是那一帧的 CSP 与嵌套（`frame-ancestors` 只认主那个源 ⇒ 制品那个源被拒 ⇒ 壳里一片空白），得不偿失。
**连带动作**：⚠️ 那条内缩**只许用稳定值**（绝不许喂"浮窗每帧的高度"——每帧 resize 一个真 iframe 会把动效卡没）；⚠️ 出口那颗「退出」也按这条"同一时刻只许一颗"来分（`D3.15`）。
**判据**：`models/mini_frame.dart` 的 `miniAppBleedsBottom` · `test/unit/mini_native_test.dart` · `screens/chat_screen.dart` 的 `bottomInset`。

### `D3.17` 顶上那一条（系统状态栏）：桌面跟壁纸走，别的屏归壳

**结论**：🔴 **面上那一条归壳**：**桌面**那一屏露的是**壁纸**（图标跟着**那张壁纸的顶部**走，不设壁纸时就是那张暖纸 ⇒ 深色图标）；**小程序 / 内置那几屏**顶上那一条是**壳自己的纸色**（那个会长到全屏的面盖到 `y=0`）⇒ 图标**固定深色**；其余屏（登录 / 首页 / 等待）默认也是壳那张纸。
**理由**：小程序是**第三方 HTML**，我们**读不到它的颜色**（也不许注入脚本去读）⇒ 图标没法"跟着页面走"；把页面铺到状态栏下面就只能固定盖一层渐变，而页面第一行又会压回时钟底下（真机报过"第一行压在时钟底下"）。
**连带动作**：交出方式**只有一处**（一个 `AnnotatedRegion` 包住真正盖住那一条的那一层：Flutter 在状态栏正中取样，**谁盖在顶上谁说了算**）；桌面那 28 张壁纸的顶部深浅是**离线量过的**，不许现算。
**判据**：`widgets/system_bar.dart` 的 `SystemBarTint` · `models/wallpaper.dart` 的 `wallpaperDarkTop` · `test/unit/wallpaper_top_test.dart` · `test/widget/system_bar_test.dart`。
