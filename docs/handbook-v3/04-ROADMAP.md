## 二、"版本"在这个项目里的口径

**没有版本号、没有发布列车。** 这里只有一件事：**一批 ＝ 一个可交付的状态**。
（"批"指的是**一次交付**，不是施工流水号 —— 施工考古不进这一份。）

**三条交付判据** —— 缺一条就不算做完：

| # | 判据 | 它到底在要求什么 | 代价 / 边界 |
|---|---|---|---|
| **1** | **能装到平板上** | 交付物是**用户碰得到的形态**：真机上装得上、看得见。主开发设备是平板（[`01-PROJECT.md`](01-PROJECT.md) §十），所以"能装"的读数优先在平板这一侧取 | 不是"代码写完了"。⚠️ **APK 只在主人说了才打**（发布脚本**没有那个词直接拒**）⇒ 平时收尾只重发网页，**手机那一半的读数天然滞后**；滞后的是形状，不是"这条能力不存在" |
| **2** | **有可自动化的验收** | 判据要能**真跑**（命令或测试名），进服务端 `test/` 或客户端 `test/unit` —— **不是"我看着没问题"**。纯函数进 `test/unit`；`test/widget` 一般是提示档，**其中可访问性那一份是硬闸** | 🔴 **负向对照不能省**：证明"闸绿了但不是空转"只有一条路 —— **把它改回错的样子 ⇒ 当场红**。🔴 **闸要打在被测的那一侧**：客户端自己算出来的东西，闸必须在客户端这一侧。这条纪律是拿两次真实失败换来的：探针把地址**写死**、绕过了被测的那行代码；纯函数全绿而**接线恒 404**（见 [`08-SPEC.md`](08-SPEC.md) 的 V13 与 [`../dev/223-ARK-CHECK.md`](../dev/223-ARK-CHECK.md) §五） |
| **3** | **能说清修掉了哪个真实放弃点** | 对着 [`01-PROJECT.md`](01-PROJECT.md) §三 那份"他们放弃在哪"的清单**指得出来** | 防的是"改了一堆东西、但没人能判断好坏" |

🔴 **写不出验收的条目不许进这一份。** 理由不是洁癖：这个产品**一个人在做、几个人在用**，
所以"排后"在实际上**就是"砍掉"**。写不出验收的条目留在表里，只会变成"看起来在做"。
⇒ 要砍就**明说砍了**（§六）；要留就得能回答判据 2。

**顺序不是按"哪个最重要"排的**，是按"**哪个不做，后面的会以什么形式失败**"排的。

**今天这份排序的口径**（主人定的；原文与分界在 [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) §六 顶上）：

| 组 | 怎么对待 |
|---|---|
| **功能** | **先做**。用户看得见、用得上的能力，**一件一件做、每件都收尾** |
| **性能与资源**（磁盘配额 / 闲置回收 / 采样 / CPU 上限 / 容量算式） | **放宽，不是砍了** —— 仍然记在账上（§四.9），只是不占现在的时间 |
| **安全、可用性、正确性** | **照旧要拍板**（临时验证码 · 口令卫生 · 出网 · 语音那条硬闸）—— 一条一条报详情与建议，主人决策 |

⚠️ **别把"放宽"读成"不用管"**：那只是**排序**。§五 那份"做一半更坏"的清单与手册里那些不变量
**一条都没松**。

**一个版本怎么算"钉住"**：

- **tag 只钉仓库那一份**；用户实际在用的是**产物**（网页入口 / 产品层 / 安卓包 / 开机清单）。
- ⇒ "定稿"必须**同时**钉 tag 与产物，**缺一个就不算钉住**；产物锚点只住
  [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md)。
- ⚠️ **定义不是那串号，而是"能重现它的命令"**：`git checkout <tag>` ＋ 两条闸 ＋ 部署脚本 ⇒
  能跑出同一份东西。号只是"当时是哪一份"，**会过期；命令不会**。
- ⚠️ **tag 钉不住"跑着的那一份"**：线上跑的是产物，盒子里那一层还可能落后于仓库（§四.2）。
  想知道"用户正在用哪一份"**要现读**（怎么读在 [`06-OPERATIONS.md`](06-OPERATIONS.md)）。

**一次交付怎么收尾**（四件，缺一件都不算）：
两边的硬闸都跑绿（服务端 `npm test`、客户端 `scripts/check-client.sh`）· 能部署的部署掉 ·
**文档与账对上**（`docs/dev/` 那一篇 ＋ [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) 的账）·
**推上去 ＋ 给主人一份总结**（做了什么 / 验在哪 / 还欠什么）。全部规矩在
[`06-OPERATIONS.md`](06-OPERATIONS.md) 与 [`../../AGENTS.md`](../../AGENTS.md)。

### 4.1 🔴 图像 / 视频：**一次真上游读数都没有**（缺方舟钥匙）—— 3.0 唯一的硬卡点

- **卡在哪**：链路、判据、探针、设置里那块自检**都就位**；缺的是**火山方舟那把 API Key**。
  今天代码里那两个**模型名**与端点是从**第三方速查**抄的（出处在 `image.js` / `video.js` 的文件头，
  官方那两页是前端渲染的、抓不到正文）—— ⚠️ **模型名是会过期的东西**：只住那两个文件**各一处**、
  而且**能被环境变量覆盖**，**绝不散落在调用逻辑里**。
- **要谁做什么**（方舟控制台三件，逐条在 [`../dev/219-V3-IMAGE-VIDEO.md`](../dev/219-V3-IMAGE-VIDEO.md) §六）：
  ① **开通**要用的两个模型：图像（Seedream）与视频（Seedance）—— 没开通的话钥匙再对也会回"不可用"；
  ② **建一把 API Key** —— ⚠️ **别贴进聊天、别写进任何文件**：填进设置里「图片」那一屏就够，
  **视频那栏不用填**（图像＋视频共用同一把）；
  ③ **把控制台上的模型 ID 抄过来** —— 有它我能少花一次冤枉钱。
- **不做会怎样**：界面上图像／视频那两栏**确实还不能用**（`/api/space` 的 `creds.image` / `creds.video`
  仍是假）；"能在聊天里出图／出片"这句话在真读数到手之前**不成立**。
- ⚠️ **那块自检能做什么、不能做什么**：设置里视频那一屏的「**验一下**」拿一个**编出来的模型名**
  把两条路各问一趟 ⇒ **只回答"那边认不认这把钥匙"**，**不画、不做、不计费**
  （名字是编的 ⇒ 到不了业务；而**鉴权在路由之前**：连一条不存在的路径也回同一个 401）。
  它**证不了"模型名与参数对不对"** —— 那只有真跑一次才知道。所以界面上那句话**只说"这把钥匙它认了"**，
  绝不说"能出片"。
  ⚠️ **它自己也没在真上游跑过**：那套判据全是在**假 `fetch`** 上过的
  （[`../dev/223-ARK-CHECK.md`](../dev/223-ARK-CHECK.md) §五）。
- **凭据怎么配才叫"最少"**：**两把**（方舟一把管图像＋视频、语音一把）。
  "图像＋视频共用一把"是一条**明着借**的规则：自己那栏空着就借对方那把，自己填了就用自己的；
  页面上那两格的口径是"**这条路现在能不能用**"（而不是"你有没有填这一栏"）。
  ⇒ **"真·只填一个 key"是砍掉的**（见 §六）。

### 4.2 🔴 产品层（盒子里那一份）**落后于仓库**

- **卡在哪**：线上盒子里跑的那一份与仓库这一份**不是同一版**。差的是**静态下载那条路**
  （`Range` / `206` 断点续传）：宿主这一侧有、盒子里那份没有。一条命令能核这件事
  （`scripts/check-tenant-code-drift.sh`）。
- **要谁做什么**：**主人一句话**（补 / 先不补）。补是**部署期**的事，那三步脚本自己会打印：
  造一版 → **先证明它起得来**（真跑一个一次性容器自报同一个号）→ 翻转；盒子会**自己在空闲时重开**成新版。
- **不做会怎样**：盒子里的人下载大文件**断一下从头下**；而且"**租户跑的就是仓库现在这一份**"
  这句话**不成立**。⚠️ 这一类缺陷**闸天生抓不住**（两边的代码都是"对的"，错的是**跑的那一份**）
  ⇒ 只能靠"发布之后核同版"这条**流程**。

- ⚠️ **要重打包得主人说**（打包很慢，这条是主人定的）；APK 落后于仓库时，落后的是**形状**。

### 4.5 ⚠️ 语音语料那条硬闸**只差读数**

  ⇒ **合成音不算**。
- **要谁做什么**：① 主人念一遍（条数、装置与口径在 [`../dev/77-BLOCKERS.md`](../dev/77-BLOCKERS.md) 的 B13
  与 [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) §六 的 #52）；② 顺带定一个口径：
  命中率是**总的**达标，还是**每一类都要**达标（现在按"总"算、分类照报）。
- **不做会怎样**：语音这条路永远只是"**能听见**"、谈不上"**听得准**"；

### 4.6 ⚠️ 临时验证码还开着

### 4.9 几个还开着的产品决定（不是技术账）

| 要什么 | 为什么 | 不做会怎样 |
|---|---|---|
| **小程序安全模型还剩三件窄问题**：白名单是不是"**它起草 · 我核对 · 你勾选**"？· 自动化任务**跑他自己盒子里、串行**？· 先做哪一样？ | 存储那一样已经落地、今天就能用；剩下三样**只差一句口径** | 小程序只能做"**没状态的小工具**" |
| **「什么算明说」**（管"写小程序"与"画图／做视频"两处）—— 维持 / 放宽 / 收紧 | 机制是**硬的**（服务端自己看当轮那句话，请求里写什么都不作数），但"什么算明说"取的是**保守默认**（宁可误拒） | 认不出会**误拒正常说法**（它会说人话，但不是他想要的那句）；反过来放宽，代价是**花了他没让花的钱** |
| **每用户磁盘配额 / 闲置回收策略** | 一人一台**共用宿主盘**：谁写满拖垮全机（本项目"最贵事故"那一类）；容器级"闲置停 / 销毁"也还没定 | 一个人写满 ⇒ **全机一起坏**；没人用的盒子**照样占着内存** |
| **容量与准入那条判据今天算不出来** | 本机**每一层内存上限都是 `max`** ⇒ 拿不到能算判据的数 | 准入那道闸只能**如实说"算不出判据"**（这是诚实的，不是坏）—— 但它也就**挡不住**"第二个人进来拖垮第一个" |

### 4.10 助手自己能还的技术账（**不用等主人**）

以下都在账上、**都不需要签字**（逐条与证据在
[`../dev/224-V3-PROJECT.md`](../dev/224-V3-PROJECT.md) §七.2）：

- **"pack 身份从哪来"没有产品路**（口径已拍、**待落地**）：页面够得着的存储里没有 pack 身份。
- **替小程序跑的那一轮 agent，它的文件路没被那道界盖住**（它的工作目录就是工作区）。
- **派活的"做完了"没有物证**（子进程自述、宿主不核对）⇒ 🔴 **在补上物证之前，那条总结不许当验收**
  —— 它正是"页面可能在说假话"那一类。
- 派活登记与桌面**可能对不上**；派活总结**不会自动进**主进程的记忆（今天"查得到"、但"不会主动记得"）。

### 4.11 ⚠️ 已知"页面 / 注释在说假话"的那一批（**还没修**）

以下是本次**如实清点**查出来的（逐条证据在
[`../dev/224-V3-PROJECT.md`](../dev/224-V3-PROJECT.md) §六）。它们**都属于"只修致命缺陷"那四类里的
第四类（页面在说假话）**：

- 设置顶层那一行的字**含禁用词**，而词表闸的"必须干净"清单里**没有它** ——
  更糟的是，那个文件的注释却写着"词表硬闸会拦"。
- 落地页 FAQ 还在说"语音还在做、现在打字就能用"，而**网页开麦与安卓原生开麦／录音／念出来都已经在跑**。
- 发现页把"**拉不到**"画成"**现在还没有**"（失败那个字段是死的）。
- 一批**注释与代码相反**（会骗下一个接手的人）；还有几份**写完没人调**的模块（零引用，也**没明说砍**）——
  这违反"以后再说等于永远不做"。
- **同一份数字三处不一致**（决策条数）—— 正是"同一份数字两处就会漂"那条纪律的反例。

⇒ 这一批**不在 3.0 的四件里**，但**不会被"新功能一律进下一版"挡住**：它们本来就该按
"修致命缺陷"那一条走。⚠️ 一条已经修好并**补了闸**的先例：有一条口曾经**恒 404**（键名对不上），
而当时**所有闸都绿** ⇒ 现在多了一道**接线闸**：`serve.js` 交给 `createServer` 的**每一个键**，
它都得**真的认**。

## 五、"做一半比不做更坏"清单（硬约束）

> **为什么有这一节**：这个产品**一个人在做、几个人在用** ⇒ "**以后再说**"等于**永远不做**。
> 而"做一半"比"不做"更坏：用户会撞上一个**看起来有、其实没有**的东西 ——
> 那正是 [`01-PROJECT.md`](01-PROJECT.md) §三 那份清单上最致命的一类
> （"**失败与成功长得一模一样**"）。
> ⇒ 下面每一条**不许拆着交付**；真要拆，先回答"**用户会撞上哪一半**"。

| # | 做一半的形态 | 为什么更坏 |
|---|---|---|
| **1** | **可访问性那几样拆批**（只做字号、不做别的，而且**不说明**） | 用户撞上"**字放大了，但还是打不了字**"。⇒ 要么做齐 ＋ **按设备如实说明**（网页 / 安卓各有各的实话），要么整批推后 |
| **2** | **单独交付登录页文案** | 对不会用的人**纯负价值** —— 门更醒目，他仍然进不去 |
| **3** | **砍掉服务端历史那条口，却留着"上面还有 N 条"** | 给用户一句提示而**永远翻不到**（"说了做不到"，正是十人走查里那条放弃点） |
| **4** | **过程可见性没有乱序保护 / 超时收敛** | 卡住时**永久停在"在查资料"**，比空白更坏 |
| **5** | **编号那条路只做一半**（"谁发号"与"谁不发号"分开交付） | 磁盘会留**号洞** ⇒ "**磁盘无空洞**"这句话就成了假话 |
| **6** | **只做落盘失败上抛、不做"谁接"** | 盘满 → 崩 → 重启 → **再崩**（唯一会**永久丢数据**的那条根） |
| **7** | **只拆纯函数、不补楼层闸** | 拆完了，但那条禁令**仍然没人守** ⇒ 下一个人再违反一次 |
| **8** | **服务端软删，客户端却承诺"能拿回来"** | 今天客户端**没有**"拿回来"的入口（§六）⇒ 界面上出现"可恢复"就是**假话**。"删之前先把要删的摆出来问一次"才是那条底线 |
