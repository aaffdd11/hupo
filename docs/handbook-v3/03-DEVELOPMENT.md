## 一、仓库地图

### 1.1 顶层有什么

```
v2/services/core/     Node.js 调度器（L2）——**常驻进程，线上服务就是它**，听 127.0.0.1:8020
v2/apps/mobile/       Flutter 客户端（L1）——**线上的界面就是它**（Web ＋ 原生安卓，同一套源码）
scripts/              闸 / 构建 / 部署 / 推送 / 查落点（**人跑的，不是服务加载的**）
deploy/               nginx 与 systemd 单元（**部署形态**，不是运行时代码）
docs/                 文档（下面 1.2 讲它怎么分层）
data/                 运行时数据（**`.gitignore` 掉了，绝不进仓库**）
proposals/            助手提、主人签字的补丁（**`.gitignore` 掉了**）
AGENTS.md             开机自动读的作业纪律（**受完整性清单保护**，见 §一.3）
README.md             仓库入口（只做"把人领到门口"这一件事）
```

**每个目录谁读它、它答什么**：

| 路径 | 是什么 | 谁读它 |
|---|---|---|
| `v2/services/core/src/` | 调度器全部实现（入口 `serve.js`） | 改服务端的人；判据在 `v2/services/core/test/` |
| `v2/services/core/hupo-*.yml` | 那几份 `--patch`：SDK server / 人格 / 能力层 / 模型，外加小程序那一轮的限定档 | 改"它是什么性格、手里有哪些工具"的人 |

| `scripts/` | 闸（`check-client.sh` · `gate-server.sh` · `gate-quick.sh` · `gate-stamp.sh` · `check-docs.mjs`）＋ 部署（`deploy-web-v2.sh` · `restart-core.sh` · `build-apk.sh` · `publish-apk.sh`）＋ 提交（`push-changes.sh`）＋ 查落点（`where.sh`） | 每个要跑闸 / 上线 / 提交的人 |

### 1.2 `docs/` 的四层分工

**事实有四个家，每个家只答一类问题**：

| 层 | 住在哪 | 只答什么 | 不许出现什么 |
|---|---|---|---|
| **路由**（L0） | [`../INDEX.md`](../INDEX.md) | "要问什么，读哪一份、哪一节" | **结论、数值、状态** —— 它**只放指针**，所以它几乎不过期 |
| **速查卡** | [`../CHANGE-MAP.md`](../CHANGE-MAP.md) | "我要改个小东西 ⇒ 打开哪几个文件、跑哪几条命令" | 状态与读数（它只许写**路径 · 命令 · 边界**） |
| **手册**（要什么 / 为什么 / 判据） | `docs/handbook-v3/`（这份就是） | 产品定义、结构边界、代码形状、路线、决策、运维、判据 | 历史沉积（"原来／后来／已作废"） |
| **证据**（怎么实现、怎么验、读数多少） | [`../dev/`](../dev/)（按编号一篇一篇长） | 某一批的来由、当时的读数、踩过的坑 | —— |

还有**第五个家**，它其实是**第一个家**：**代码本身**。
`v2/` 的源码与测试是**事实的最终出处** —— 手册与代码不一致时，**先按代码确认事实，
再回来改手册**（不要反过来）。所以本文里每一条都能落到一个文件或一个测试名上；
落不到的，文中标**未核实**。

**"一条事实只有一个家"** 的判据很硬：**同一份数字 / 同一张表 / 同一句话，不许有两处正文**。
- 协议那张事件表**只在这里**（§三）；`02-ARCHITECTURE.md` 只讲结构与不变量，不重抄字段。
- 阈值只在代码与 [`08-SPEC.md`](08-SPEC.md) §十；本文一个数都不写。
- "要改什么 ⇒ 碰哪几个文件、跑哪条闸"只在 [`../CHANGE-MAP.md`](../CHANGE-MAP.md)；
  本文 §八 只讲**怎么用它**，**不抄一份**（抄了就会漂）。
- 卡片点到的文档改名 / 挪家 ⇒ `node scripts/check-docs.mjs` 变红（它守的正是**指针**）。

**为什么这条纪律值得写进手册**：这个项目在"同一份东西写两处"上栽过不止一次，
两次都表现为"一处改了、另一处还在说旧话" —— 而**看旧话的那个人不知道自己在看旧话**。

### 1.3 开机时读的是哪几条路径

改下面这几样，**不是"改完就好"**：它们属于**开机完整性清单**里的 `strict` 条目
（`v2/services/core/src/integrity.js` 的 `protectedPaths()`）—— 对不上，
`serve.js` **拒绝启动**并点名那个文件。

| 什么 | 为什么在清单里 | 改完之后 |
|---|---|---|
| `v2/services/core/hupo-persona.yml` | 每开一个新 agent 就喂一遍，改一句就改掉它的性格与纪律 | **要请主人补一条重建命令**（照 `scripts/verify-integrity.mjs` 打出来的那条粘） |
| `hupo-capabilities.yml` · `hupo-app-agent.yml` · `hupo-model-proxy.yml` | 分别决定"手里有哪些工具""替小程序跑的那一轮有没有手""请求发到哪儿去" | 同上 |
| `AGENTS.md` | 给自己下一次读的说明书 | 同上 |
| `~/.dsh/profiles/*/cordis.yml` · `cordis.patch.yml` | agent 的 profile 与补丁 —— **每轮开机自动加载的东西** | 同上 |
| `docs/handbook/`（**旧那一套**） | 手册就是判据：能随手改判据，任何闸都白设 | 同上 |

`report` 那一档（**只报不拦**，改了不用补命令，但开机横幅上看得见）：

| 什么 | 为什么不拦 |
|---|---|
| `v2/services/core/src/**` · `scripts/**` | 开发期代码天天改；拿它们当 `strict` ⇒ 每改一行主人就得补一条命令 |

> ⚠️ **两条要读准**：
> 1. **哪一条是 `strict` 住在清单文件里**（`/etc/hupo/integrity.json`，`root:root`、只读）

> 机制与判据在 [`06-OPERATIONS.md`](06-OPERATIONS.md)。

## 二、模块依赖与楼层闸

### 2.1 楼层：`models` ← `services` ← `widgets` ← `screens`

客户端 `lib/` 下就是这四层，**加一个入口 `main.dart`**。
依赖**只能向上**，箭头**反过来就是缺陷**：

```
models/      纯逻辑：值与解析、状态转移、几何、词表。**不许碰 UI、不许碰 I/O**
   ↑
services/    传输与状态：HTTP、WebSocket、控制器、本机存储。**不许碰屏幕**
   ↑
widgets/     傻组件：只看 models（面板 / 页面归 screens）。**不许碰 services、不许碰 screens**
   ↑
screens/     装配层：上面三层都能指
   ↑
main.dart    入口：装依赖、选第一屏 —— 谁都能指（就这一个文件）
```

**每一层真正被允许指向哪一层**（`test/unit/import_rules_test.dart` 里那张表就是出处）：

| 从这一层 | 只许指向 |
|---|---|
| `models/` | `models` ＋ `flutter` |
| `services/` | `models` · `services` ＋ 第三方包 ＋ `flutter` |
| `widgets/` | `models` · `widgets` ＋ 第三方包 ＋ `flutter` |
| `screens/` | 全部四层 ＋ 第三方包 ＋ `flutter` |
| `main.dart` | 全部（含自己那一层） |

> `dart:` 的库**不参与楼层判定**（`dart:convert` / `dart:collection` / `dart:math` /
> `dart:typed_data` 这些纯计算库当然让用）；`package:hupo_app/<层>/…` 这种**自家包路径**
> 按第一段算层，和相对路径同等对待。

### 2.2 三条禁令

"楼层图"讲的是**方向**；下面三条是**方向之外点名禁掉的具体东西**。
三条都住 `import_rules_test.dart` 的 `forbiddenPrefixesIn` 与 `allowedTargets`。

| # | 禁令 | 为什么（不这样会怎样） |
|---|---|---|
| **1** | **`models/` 不许 UI、不许 I/O。** 点名的前缀：`package:flutter/material.dart` · `package:flutter/widgets.dart` · `package:flutter/cupertino.dart` · `package:http/` · `package:web_socket_channel/` · `package:shared_preferences/` · `dart:io` | 这一层要能被**不搭界面、不 pump** 的测试直接验（`test/unit` 就是这么跑的）。碰了 material 就要搭 widget 树，碰了 I/O 就要起端口。**判据进不了硬闸的那一刻，这一层就没人守了。** |
| **2** | **`services/` 不许指向 `widgets/` 或 `screens/`** | 服务是"传输与状态"，方向一旦反了，**"服务"就开始依赖某一屏的形状** ⇒ 换一屏就得改传输层；而这一层是协议与状态机的家，改它要动两边 |
| **3** | **`widgets/` 不许指向 `services/` 或 `screens/`** | 组件只能**只读状态、只发意图**：状态经 `models/` 的值进来、意图经构造参数里的回调出去。直接抓 controller 的后果是"**同一个状态有了第二个写入点**"，而第二个写入点不会通知第一个 —— 屏幕上于是出现"按了没反应"或"两处各说各话" |

**配套的一条约定的豁免**：`models` 里**只许**从 `dart:ui` 引 `Color` 这一个纯值类型
（`design.dart` / `dsh_design.dart` / `app_tint.dart`）。
⚠️ **这一条是约定，不是闸**（闸只禁 material / widgets / cupertino，`dart:ui` 是放行的）
—— 所以它靠评审守，不靠红绿。**未核实**：没有任何判据在量"是不是只引了 `Color`"。

> ⚠️ **上一代那一层 `apps/`（内置应用）今天不存在了**。桌面上的小程序走的是
> `widgets/mini_app_*` 与 `services/mini_runtime*`，不再有"内置 app 直接 import 某一屏"
> 那条路。所以旧材料里"禁令 3 = `apps/` 不许 import screens"那句话，
> **指向的是一个今天没有的目录**。

### 2.3 为什么靠 `test/unit/import_rules_test.dart` 强制

`v2/apps/mobile/analysis_options.yaml` 是 `flutter_lints` 的模板 ——
它可以开 / 关 lint 规则，但**加不了"某一层的文件不许 import 另一层"这种 import 禁令**。
⇒ **写在文档里的禁令就是一句口号**：下一个人图省事写一行 `import '../services/stream.dart'`，
没有任何东西会响。

**唯一的区别是把它变成一条判据**。那条判据是一份**扫源码的纯 Dart 测试**（`dart:io` 列目录、
正则读 `import` 行、按目录断言方向），**不需要 `pump`、不开浏览器** ⇒ 它进得了硬闸
（`flutter test test/unit`，收尾由 `scripts/check-client.sh` 跑）。
它自己也带**负向对照**：喂它几段"下一个人真的会那么写"的违规源码，**必须抓得住**；
再喂一份干净的样子，**不许误报** —— 否则"闸绿了"可能只是**闸坏了**。

**两个结构性的设计，别改掉**：

1. **新加一个顶层目录 = 新楼层 ⇒ 默认什么都不能指向**（fail-closed）。
   谁新开 `lib/panels/`，闸当场红，直到他回 `import_rules_test.dart` 的
   `allowedTargets` 里把那一行补上。**不这样做的话，新楼层会悄悄继承最宽松的规矩** ——
   那正是禁令烂掉的方式。
2. **注释里的 `import` 不算**。判据只认**行首的 `import`**，否则一段讲解文字就能把闸撞红。

### 2.4 今天这棵树

按 `import_rules_test.dart` 的同一套口径核过**今天这棵树**：
`models` / `services` / `widgets` / `screens` 四层都有文件，
**三条禁令与依赖方向零违反**（每层的文件数与总数由闸自己报，本文不写死）。

**这不等于"这张图只是描述现状"** —— 它是"**钉住方向**"。今天对，
而"今天对"正是最容易被某次图省事破坏的东西；
所以这条闸的存在理由与现状无关，与**下一个人**有关。

**闸的结构性盲区**（如实列出来，这些都是它**抓不住**的）：

| 盲区 | 后果 |
|---|---|
| 只扫**行首的 `import` 行** | `export '…'`、`part`、以及"字符串里拼出来的 import"它看不见 |
| `main.dart` 是**自由层** | 入口里堆多少逻辑它都不管（那要靠评审，不靠闸） |
| `dart:` 一律放行 | `models` 里引 `dart:io` 会被抓（点名禁），引 `dart:ui` 的别的东西不会被抓 |
| 只按**目录第一段**算层 | 同一层内部怎么互相指，它是允许的（那本来就是允许的） |

## 三、协议

> **这一节有一条硬时点**：**协议字段一旦上线就冻结**（§3.6 讲为什么）。
> 下面每一行的"字段"，都是照着**今天代码里的生产者**写的；
> 谁要加字段，**只加不改语义**，并且**两半一起改**（服务端发 ＋ 客户端认）。
>
> **落点查法**：想知道某条事件今天散在哪些文件里，用 `bash scripts/where.sh '<事件名>'`
> （它按服务端 / 客户端 / 文档 / 测试分组列出来）。**它不是判据**，是一个考古工具 ——
> 为什么不把它做成判据，见 [`../CHANGE-MAP.md`](../CHANGE-MAP.md) §二 那一格。

### 3.1 先分三种帧：**有没有 `seq`** 就是分界线

同一条 `/api/stream` 上跑的是三种东西，**用有没有 `seq` 一刀切开**：

| | 有 `seq`？ | 落盘？ | 重连 / 切焦点补发？ | 例子 |
|---|---|---|---|---|
| **持久事件** | ✅ | ✅ | ✅ | `message/*` · `user/echo` · `tool/*` · `notice` · 墓碑 |
| **瞬态事件** | ❌ | ❌ | ❌ | `message/status` · `step/*` · `reasoning/delta` · `queue/changed` |
| **控制帧** | ❌ | ❌ | ❌ | `client/hello` · `client/ping` · `client/reset` · `client/focus` |

**客户端那一侧的落点**就是这一刀：`models/timeline.dart` 的 `apply()` 先看
`event['seq'] is int` —— **是** ⇒ 走"上时间线"那条路（去重、排序、必要时新建条目）；
**不是** ⇒ 走 `_applyTransient()`，**只改已有条目的状态，绝不新增条目**。
控制帧在更前面就被消费掉了（`services/stream.dart` 的 `_onFrame`）。

> ⚠️ **为什么"不占号"要单独讲成一条原则（§3.4）**：
> 客户端里"上屏一条"和"改一条的状态"是**两个不同的容器**。
> 一个瞬态事件要是被当成持久事件处理，屏幕上会多出一条**谁也说不清它从哪来的**东西；
> 反过来，一条持久事件走了瞬态那条路，它**永远不会出现在时间线上**（会被静默吞掉）。

### 3.2 九类事件（逐条）

> **归类的口径**：按"**这件事是谁对谁说的、它给用户看的是什么**"分九类。
> 每类下面的事件都是**今天有生产者的**（生产者没有的，那一行会明写"没有生产者"）。

#### 3.2.1 第一类 · 用户说的话 —— `user/echo`

- **谁发**：`src/say.js` 的 `SayService.say()`，由 `POST /api/say` 触发。
- **字段**：`messageId`（客户端生成，`u_` 前缀）· `text` · `clientAt`（客户端钟，**只记录**）·
  `scopeId`（**只有非主线的房间才带**；主线不带这个字段，为了让盘上老事件逐字不变）。
  `seq` / `at` 由 `Timeline.emit()` 统一盖。
- **语义**：**这一句已经收下了、落盘了**。它是客户端那条乐观发言的**认领凭据**
  （`timeline.dart` 的 `_applyEcho`：同一个 `messageId` 找回本地那条把它推成 `confirmed`，
  而不是再插一条 —— 否则你会看到自己说的话出现两遍）。
- **幂等**：同一个 `messageId` 再来一次 ⇒ `{duplicate:true}`，**不再落盘、不再投递**。
  "见过的 id"是**从日志重建**的，所以重启不会让去重失效；重发绝不能被"忙"拒掉
  （拒了屏幕上显示"没发出去"，而服务端早收下了）。

#### 3.2.2 第二类 · 助手说的话 —— `message/start` · `message/text` · `message/end` · `message/handoff`

- **谁发**：全部由 `src/message-writer.js` 的 `MessageWriter` 发（`start()` / `chunk()` /
  `end()` / `handoff()`）。调用它的地方是 `src/session-translate.js`（把 DSH 的
  `assistant/message` / `turn/end` 翻成产品事件）。
- **顺序是死的**：`start → text* → end`。没有 `start` 就 `chunk`，它会**自动补一个 `start`**。
- **字段**：

  | 事件 | 字段 | 语义 |
  |---|---|---|
  | `message/start` | `messageId` · `agent` · `origin` · `re` · `scopeId`（**主线是 `null`，字段照样在**）· 可选 `byScope` | 这一条气泡开了 |
  | `message/text` | `messageId` · `block`（`quick`｜`deep`）· `seqInBlock` · `text` | 往气泡里加一段 |
  | `message/end` | `messageId` · `reason` · `sources` | 这一条收口了；**`sources` 是权威版本** |
  | `message/handoff` | `messageId` · `reason` · `to` | 转交了，**但没完**（见下） |

- **`block`**：快答与深答是**同一个气泡**（不配对、不拆条）；`quick` 在前、`deep` 在后。
- **`seqInBlock`**：同一段正文的编号。客户端按 `(block, seqInBlock)` **去重** ——
  因为"从回收站拿回来"会把内容按原样重新追加一遍（**新 `seq`**），
  只按 `seq` 去重挡不住它，屏幕上那句话说两遍。
- **`reason`**：为什么收的口。`completed` 之外的都算**没说完**（`session-translate.js`
  会把被截断 / 被打断的收尾补一句人话，并标成失败收尾）。
- **`sources`**：`[{title, url}]`，**空数组 = 没有出处**。
  `title` 由服务端算好（有标题用标题、没有用域名，`src/sources.js`），客户端只负责画 ——
  **同一件事不许两处口径**。只有真的查过的东西才进这里；读文件、跑命令**不算出处**；
  `url` **只认 `http(s)`**。判据与边界在 [`../dev/67-SOURCES.md`](../dev/67-SOURCES.md)。
- **`message/handoff` 是"转交"，不是"挪走"**：转交 = **不收口，B 用同一个 `messageId` 接着写**
  （用户看到一个气泡）；挪走 = **先收口，后面的话另起一条**。两条路语义相反，**绝不共用状态值**。
  `to` 是内部 id，**只给审计看，客户端不许显示**。契约 [`../dev/100-DISPATCHER-D.md`](../dev/100-DISPATCHER-D.md)。
- **两个今天不消费的字段**：
  - `agent`（`'agent'` / `'hupo'`）与 `origin`（`reactive`｜`proactive`）**是冻结的、有生产者**，
    但**客户端今天不读**（分别回答"谁在说""为什么开口"）。
  - `re`（回跳指针）**在协议里冻结、今天服务端总是给空数组** —— 回跳功能没有生产者。
    **未核实**：没有任何判据在阻止它被填上，也没有判据在验它。

#### 3.2.3 第三类 · 过程（它正在做什么）—— 四样，全是瞬态

| 事件 | 谁发 | 字段 | 语义 |
|---|---|---|---|
| `message/status` | `src/dispatcher.js` 的 `#announceTurn()` | `turn` · `state`（内部名） | "这一轮开始了"；**按轮寻址**，不按气泡 |
| `step/start` | `src/session-translate.js` 的 `#emitStep()` / `#emitStepCategory()` | `turn` · `step` · `state` | 老「步骤流水」档那一路 |
| `step/end` | 同上 | `turn` · `step` · `reason` | 这一步完了 |
| `reasoning/delta` | `src/session-translate.js` 的 `#emitReasoning()` | `turn` · `text` | 它的思考原文；**只有 `level=reasoning` 的连接收得到**（⚠️ 今天新客户端没有这个入口，见 §4.4） |

- **`state` 是内部名，不是给人看的字**。翻人话在客户端
  （`models/process_words.dart`），**认不出来的就不说**（N10：沉默优于编造）。
- **`turn` / `step` 必须带**，两个用处：**乱序保护**（迟到的旧轮不许把"它正在做"点回来）
  与 **超时收敛**（轮一收口就把这一轮的步骤清掉，不许留成"永远在查资料"）。
- 🔴 **`reasoning/delta` 与 `step/*` 绝不许走落盘那条路**。
  它们是**瞬态**（`emitTransient`），因为新连接会按 `sinceSeq = 0` 重放**整条历史** ——
  一条走了落盘通道的推理原文，**以后每一个连上来的人都能拿到**，而它可能含系统提示词片段。
  `test/process-level.test.js` 有两条红灯判据钉着它（一条读盘、一条读重放帧）。
- **档位过滤不在这两层做**：翻译层把过程事件原样推上时间线，"发给哪条连接"由
  `src/server.js` 的 `levelAllows()` 按**连接级 `level`** 决定。
  反过来（在翻译层看档位）会让"用户选的档"影响"盘上有没有" —— 而盘是共享的。
- **工具名不进 `step/*`**：DSH 的 `step/start` 里没有工具名，`tool/call` 到了之后
  才**给同一个 `(turn, step)` 补一条带类别的瞬态状态**。硬编一个类别 = 编造。

#### 3.2.4 第四类 · 工具行 · 系统提示词 · 每轮用量 —— 全部持久

这三样是"**它到底调了什么、成没成、这一轮大概多贵**"的全部凭据，
所以它们走**落盘**那条路（翻页、重连、切回这一间都拿得到）。形状与边界**只住**
`src/tool-rows.js`（纯函数）与契约 [`../dev/116-CHAT-OPEN-AND-REDESIGN.md`](../dev/116-CHAT-OPEN-AND-REDESIGN.md)。

| 事件 | 谁发 | 关键字段 |
|---|---|---|
| `tool/call` | `session-translate.js` 的 `#onToolCall()` | `turn` · `step` · `callId` · `name` · `title` · `args` · `bytes` · `truncated` |
| `tool/result` | 同上的 `#onToolResult()` | `turn` · `step` · `callId` · `ok` · `error` · `excerpt` · `bytes` · `truncated` |
| `system/prompt` | `#onSystemMessage()` | `turn` · `step` · `text` · `bytes` · `truncated` |
| `turn/usage` | `#onTurnEnd()` | `turn` · `usage` · `complete` |

- **`tool/result` 上（DSH 那边）没有工具名** ⇒ 客户端用 `callId` 把结果**就地补到**
  那一行调用上（**位置不动**）：这是"认领身份"，不是"消息配对"。
- **顺序可能倒过来**（翻页 / 本机缓存裁剪会把调用那条挤掉）：结果先到时**先把结果那一行画出来**，
  等调用那条晚一步到了再换成整行 —— 直接丢的后果是那一行**永远停在"在跑"**。
- **有界、而且如实报**：`args` / `excerpt` / 系统提示词都按上限截，截了必须写
  `bytes` / `truncated`。**截断不说 = 页面在说假话。**
- **`turn/usage` 的 `complete`**：DSH 的规矩是"任何一次尝试没报准 ⇒ 整块不画"。
  `usage:null, complete:false` 是**合法的一条**（它照样进日志、取号、落盘，只是界面一行都不画）——
  宁可整块不画，也不给半个总数。
- **系统提示词逐字存**：截断 / 改写的提示词行比没有更坏。

#### 3.2.5 第五类 · 计划 —— `plan/updated`

- **谁发**：`src/session-translate.js` 的 `#onPlanEvent()`，形状在 `src/plan.js`。
- **字段**：`goal`（`{text, phase}` 或 `null`）· `todos`（`[{text, now, done}]`）·
  `doneCount` · `total` · `more`。
- **只在"变了"的时候发**；**清空也要发**（客户端靠它把那条收起来）。
  **工具名、`goalId`、`callId` 一个字节都不发** —— 计划条上不许出现内部词。
- `more` 是"**还有几条没塞进来**"的**如实报数**，不是静默截断。
- 客户端认不出 / 是空计划 ⇒ **一个像素都不画**；全部做完 ⇒ 收起来。

#### 3.2.6 第六类 · 时间线分隔 —— `timeline/marker`

- **字段（客户端认的）**：`kind`（`away`｜`enter`｜`leave`）· `label`。
- **语义**：它是**持久事件**（取号、落盘、有位置）—— "不占号 = 不上时间线"，
  而它**要上时间线**。
- 🔴 **今天服务端没有生产者**：全 `src/` 里搜不到一处发它（只在 `export.js` 的排除表与
  `timeline.js` 的注释里出现）。客户端有这一支（`TimelineMarker`），
  **它是一条"协议槽位在、生产者还没建"的路**。照它去改服务端之前，先确认这一点。

#### 3.2.7 第七类 · 系统通知 —— `notice` · `notice/urgent`

- **谁发**：`src/notice.js` 的 `Notice.notice()`（持久）与 `Notice.noticeUrgent()`（瞬态）。
- **两种通知，触发条件构造上不重叠**：

  | | `notice`（持久） | `notice/urgent`（瞬态） |
  |---|---|---|
  | 什么时候 | **默认**：替你做的决定 / 出事了 / 你不在时发生的事 | **只有一种情形：写盘本身失败** |
  | 时间线里有没有 | **有**（就是那一条） | **没有**（盘满时物理上做不到） |
  | `kind` | `resumed` · `not-resumed` · `expiring` · `crash` · `failed`，外加后台那一族 `work-*` | 只有 `disk-full` |
  | 字段 | `kind` · `text` · 可选 `undo` | `kind` · `text` |

- **`text` 由服务端给、客户端照抄**（一个字节都不重写）。文案表就是 `NOTICE_TEXTS`，
  有一条闸逐条扫它有没有内部词。
- **`undo`**：`{label, action, messageIds}`；今天只有 `trash/restore` 一个动作。
  ⚠️ **客户端今天不画任何撤销按钮**（回收站那条路砍了，见 §4.3）——
  但 `undo` **照旧解析**（协议冻结），只是不画。
- **`noticeUrgent` 要一个"写盘失败的 `cause`"**，给别的东西就抛 ——
  它存在的唯一理由是"盘满了"这句话用普通通道发不出去（那条消息自己就写不进去）。
  `Notice.noticeOrUrgent()` 是那条"落盘优先、写盘失败才退回瞬态"的路。
- **同一条出口不许说两遍**：`(turn, kind)` 这本账把过程通道与通知通道对起来 ——
  同一件事两条通道都说了 ⇒ **通知那一侧抛**。理由不是洁癖：
  一次失败两条通道各报一次，用户收到的就是**通知疲劳**。

#### 3.2.8 第八类 · 删掉 / 恢复 / 真删 —— 三条墓碑

- **谁发**：`src/trash.js`（`TOMB_DELETED` / `TOMB_RESTORED` / `TOMB_PURGED`）。
- **字段**：`messageIds[]`（**不是轮号**）。为什么：真日志里**没有轮号**
  （`message/status` / `step/*` 上的 `turn` 是瞬态的，盘上留不下），而删除的单位是"一轮" ⇒
  "哪几个 id 算一轮"**由客户端给**（它本来就看得见时间线、知道怎么配的对）。
- **语义**：三条都**取号、落盘** ⇒ 重启之后客户端才知道谁被删过。
  - `turn/deleted` ⇒ 客户端把那几个 id **藏起来**（不销毁）；
  - `turn/restored` ⇒ **取消隐藏**（内容还在服务端，补发会带回来）；
  - `turn/purged` ⇒ 服务端已经压实 ⇒ **从内存里丢掉**（永远不会再补发）。
- **`messageIds` 读不出来就"什么都不做"**：宁可不动，也不许凭猜删东西。
- 🔴 **已知缺口（有意的）**：工具行**没有 `messageId`**，`message/*` 也不带 `turn` ⇒
  删掉一轮之后，那一轮的工具行**仍留在屏幕上**。要收口得让墓碑事件带上 `turn`
  （或让 `message/*` 带 `turn`）—— 那时这一段才有依据去藏。写在
  `models/timeline.dart` 的 `hideMessages()` 那段注释里。

#### 3.2.9 第九类 · 控制帧 —— 不占号、不上时间线

**服务端 → 客户端**（在 `services/stream.dart` 的 `_onFrame()` 里**就地消费**）：

| 帧 | 含义 | 客户端动作 |
|---|---|---|
| `client/ping` | 心跳 | 只重置看门狗（太久没收到任何帧 ⇒ 当作断了） |
| `client/hello` | **补发到此为止**（`maxSeq`，可选 `focus`） | 内部合成 `__caught_up__` |
| `client/focus` | 对切焦点的回执（`ok` / `scope`；不成功时带 `error` 与一句人话） | 一律内部合成 `__focus_ready__` —— 它标记的是"**这一间的补发到此为止**"（服务端保证"补发在前、这一帧在后"），**不是**"切成功了" |
| `client/reset` | **你的号跑到我前面了**（日志被换过 / 连错了线） | 内部合成 `__reset__` ⇒ 丢掉本地时间线**重来**（不能当"没有新东西"） |

> **`client/hello` 那一条的顺序是契约**：服务端的顺序是"先把补发那段发完、再发这条 hello、
> 然后才订阅实时" ⇒ 客户端据此把"这条之前收到的都算历史"。收不收得准，
> 决定首屏会不会把整段历史渲染成"断线补发"。

**客户端 → 服务端**（同一条流，JSON 文本帧）：

| 帧 | 形状 | 语义 |
|---|---|---|
| `focus` | `{"t":"focus","scope":"<id>","sinceSeq":<n>}` | **切焦点、不重连**。`sinceSeq` 省了 = 只切、不补发 |
| `job-answer` | `{"t":"job-answer","id":"…","yes":true\|false}` | 他答了那句"另开一处做 / 就在这儿做" |
| `unsay` | `{"t":"unsay","messageId":"…"}` | 撤掉排队里那一句 |

- **`focus` 认不出来 ⇒ 服务端不悄悄退回主线**：如实回 `client/focus{ok:false}` ，
  而且**焦点不动**。悄悄退回的后果是"A 房间的话出现在 B 房间的流里"。
- **`unsay` 没有错误面**：那一句已经被认领 / 根本不认识 ⇒ 服务端**什么都不做**，
  只回一份**当前队列的快照**（`queue/changed`）让客户端收敛。
- 三条都**走同一条流**，不新开 HTTP 路由：一个动作一个家，路由表不用动。
- **认不出的帧一律安静忽略**（协议只加不改，以后还会有别的客户端帧；
  服务端不许因为看不懂就把连接踹了）。

### 3.3 同一条流上的旁族（应用、长活、系统级）

这些**不属于上面九类**，但它们确实在同一条 `/api/stream` 上。
**列出来是因为"客户端认得不认得"差别很大** —— 认不得的会被静默忽略，这是**有意**的。

| 事件 | 持久？ | 谁发 | 客户端 |
|---|---|---|---|
| `app/update-available` | ✅ | `src/app-events.js`（`worlds.js` 盖上那个 app 的 `scopeId`） | 认（去 `/api/apps` 现取新的那一版）；帧里**不带签名 URL** |
| `app/installed` | ❌ | `src/worlds.js` | 认（重拉一次小程序清单） |
| `app/workspace-changed` | ❌ | `src/app-live.js` | 认（那一格的内容变了） |
| `scope/open` | ❌ | `src/job.js`（`dispatcher.js` 发） | 认（界面跟着切过去）。**它不带 `scopeId`** |
| `app/open` | ❌ | 同上 | 认（那一间的助手开了个东西） |
| `job/ask` · `job/ask-expired` · `job/answer-ack` | ❌ | `src/job.js` | 认（那张问话的单子） |
| `queue/changed` | ❌ | `src/queue.js`（`worlds.js` / `server.js` 发） | 认（输入条上面那条"还排着"的横条；**整份快照**，不是增量） |
| `error` | ❌ | `src/process-guard.js` · `dispatcher.js` | **只用来撤"它正在做"并标"它死了"**；`text` **不上屏** |
| `job/start` · `job/report` · `job/abandoned` | ✅ | `dispatcher.js` 的 `noteProduct()` | **客户端没有这一支 ⇒ 静默忽略**（那句总结的家只在主进程那条日志上） |
| `task/mutated` · `task/resumed` | ✅ | `dispatcher.js` · `serve.js` | **没有这一支 ⇒ 静默忽略**（它们给对账用） |
| `ledger/entry` · `ledger/deleted` · `ledger/restored` · `ledger/purged` | ✅ | `src/ledger.js` | **到不了聊天窗口**：它们是**另一条日志**（`LEDGER_TIMELINE_ID`） |

> **"客户端没有这一支"不是缺陷，是分层**：事件是**事实**（落了盘就该发），
> 客户端画不画是**产品决定**。反过来说，加一条**会被用户看见**的事件，
> 就必须同时想清楚"它长什么样、跟谁挤位置"。

### 3.4 三条语义规则

#### 3.4.1 取号

- **唯一取号点**：`src/timeline.js` 里 `Timeline` 的私有 `#nextSeq()`。
  全模块**再没有第二处** `++seq`（`emit()` 是它唯一调用者）。
- **持久事件的号 = 那条日志已落盘的最大号 + 1**；**落盘成功之后才推订阅者**。
- 重启时**从盘上取最大**（`#resumeSeq()`）；盘上没有日志 ⇒ 从零开始 ⇒ 编号**单调**。
- **落盘失败要退号**：`emit()` 里 append 抛了就 `#seq -= 1` 再把错**原样抛出** ——
  盘上没留下东西，号就不该前进（否则下一个事件在盘上就是跳号的）。
- **`seqFloor`**：给"某一间被主动回收"那条唯一例外用的**号的地板**（见
  `02-ARCHITECTURE.md` §5.3）。回收会让盘上最大号变小，重启只读最后一条就会**重发已经发过的号** ——
  而"重编号 / 复用号 = 客户端手里的游标错位"。
- **`store.append` 是同步的**（不用 `await`）：这样"取号与落盘之间插不进别的写入"
  在**语言层面**成立，不需要额外加锁。代价是写盘期间阻塞事件循环 ——
  要改成异步单写者队列，**必须同时改取号方式**，不能只把 `append` 改成 `async`。

#### 3.4.2 补发

- **纯函数在 `src/resume.js`**：`planResume()`（连上 / 重连要点哪些）与
  `planBackfill()`（往上翻一页要点哪些）。它们不碰 IO，所以能拿真事件离线验。
- **`catchUp` 只在"续传游标 > 0"时才标**：首次打开（游标 0）给的是**历史本身**，
  不是"你不在的时候"；标错了，界面会把整段历史渲染成"断线补发"，**每次新装都这样**。
- **首次打开只给最近一段**（上限住 `resume.js` 的 `FIRST_OPEN_MAX`）——
  更早的等他**往上翻**时按页取。**重连那条补发不截**：它带着"你不在时发生了什么"的语义，
  截了会让中间那一段**看起来是连着的**（那是说假话，比慢更坏）。来由 [`../dev/141-HISTORY-FIRST-OPEN.md`](../dev/141-HISTORY-FIRST-OPEN.md)。
- **客户端的号跑到前面 ⇒ 明确要求它重置**（`client/reset`），
  不能当"没有新东西" —— 那会让界面**永远停在一个已经不存在的世界上**。
- **打补发标记必须浅拷贝**（`markCatchUp()`）：事件对象是从日志里读出来的，
  直接改它会把"补发"这个**线上标记**写进磁盘。
- **补发那一路不过档位闸**，而且安全：补发帧全部来自 `readAll()`（盘上的事件），
  而过程事件是瞬态的、**永远不在盘上** ⇒ 任何档位都收得到全量补发，
  而补发里**不可能**有推理原文。（反过来说：谁把 `emitTransient` 换成 `emit`，
  这条就变成泄露通道 —— `test/process-level.test.js` 那条红灯就是为此。）

#### 3.4.3 不占号

**"不占号" = "不上时间线"** —— 三样东西在进入 `Timeline` **之前**就被消费掉：

| 什么 | 谁消费 | 后果 |
|---|---|---|
| **控制帧**（`client/*`、`focus` / `job-answer` / `unsay`） | 服务端连接层 / 客户端 `_onFrame` | 不落盘、不补发、不算"历史" |
| **UI 状态**（本地应声） | 客户端本地 | 只有一个乐观态，没有服务端号可借 |
| **过程事件**（`message/status` / `step/*` / `reasoning/delta`） | 客户端 `_applyTransient` | 断线重连**不会**被补发（代价如实认下） |

**收益**：`seq` 这个字段**永远只在持久事件上出现**，客户端可以直接拿"有没有 `seq`"
当分类器 —— 不需要另一份"哪些类型是瞬态"的名单（名单会漂）。

### 3.5 兼容规则：不认识就忽略

| 情况 | 怎么办 |
|---|---|
| 收到**不认识的 `type`** | **安静忽略**，不抛、不新增条目（客户端 `apply()` 的 `default:`） |
| 收到**不认识的字段** | 忽略（同一个事件多带一个字段，老客户端照旧） |
| **不认识的档位 token**（`?level=`） | 服务端**按默认档服务**，不报错、更不许拒连接 |
| **不认识的 `state`**（过程内部名） | 客户端**不说**（N10：沉默优于编造） |
| **不认识的 `notice.kind`** | **降级分类，但那句话照旧显示**（有 `unknown` 兜底） |
| **不认识的 `undo.action`** | **不画那个按钮**（fail-closed） |
| **认不出的 `tool/call` / `tool/result`** | 那一行**不画**（坏数据的后果只许是"这一行不画"，**绝不能是"打不开聊天"**） |
| **认不出的 `queue/changed`** | 丢掉那一帧，**留着手上那份旧快照**（宁可旧一点，也不编一份空的） |
| `dev=1` 那条附加通道 | **永远是附加，不是替代**（有回归测试守着） |

**共同的形状**：**fail-closed 用在"猜一个值"上，fail-open 用在"要不要弄坏连接"上** ——
认不出的东西一律**少说**，但**不许因此把连接、把界面、把这一轮带走**。

### 3.6 为什么协议字段一旦上线就冻结

**因为客户端不是我们能一起升级的**：网页那一份可以随时重发，
**安卓包装在别人手机上**、旧版还在跑，你收不回来。
⇒ 字段名 / 语义改一次的代价不是"改一行"，是**从此要多背一个兼容分支**，
而且那个分支**没有下线日期**。

**所以这一节的规矩是**：

1. **只加不改语义**。加一个**可选**字段，老客户端不认识它、照旧能用 —— 这是允许的。
2. **改了就要两半一起动**（服务端发 ＋ 客户端认），并且**旧的那一半不许当场失效**。
3. **能不新增就不新增**：已经冻结的两个字段（`agent` / `origin`）就是"同一件事的两条轴"，
   在协议上再加一个 `source` 只是把同一件事说第三遍 —— 那种字段**不加**。
4. **数值 / 名单不进协议**：档位 token（`quiet` / `doing` / `steps` / `reasoning`）
   **四个都冻结**，哪怕菜单上只剩两个 —— 老客户端还在发另外两个。

**已经发出去、今天仍然冻结的"死字段"照样不能删**：
`message/start.re`（今天恒为空数组）、`message/start.agent`（客户端不读）、
`timeline/marker`（今天没有生产者）—— 删一个就是让某一台老设备**静默**少收一条。

## 四、状态机与数据模型

> 这一节讲**客户端手里那份数据**长什么样、能怎么转。
> 服务端那侧"事件怎么落盘、怎么取号"在 §五；结构与作用域的边界在
> [`02-ARCHITECTURE.md`](02-ARCHITECTURE.md) §四。

### 4.1 一条消息：四态与允许的转移

**出处**：`lib/models/message_state.dart`（纯逻辑 ⇒ 进 `test/unit`）。

```
queued ──→ sent ──→ confirmed
   │         │
   └─────────┴────→ failed ──→ queued（只允许"重发"推回来）
   └────────────────→ confirmed（回执比 HTTP 响应先到）
```

| 态 | 界面表现 | 谁能让它转 |
|---|---|---|
| `queued` | **一个确定的"已交出去"标记**（不是转圈 —— 转圈的意思是"不知道"） | 本地按下发送 |
| `sent` | 同上 | 请求成功（服务端收下了） |
| `confirmed` | 标记消失 | 服务端回执到了（`user/echo` 认领同一条） |
| `failed` | **必须有自己的长相 ＋ 重发入口**，**收起态也要显示** | 网络错 / 超时 / 服务端拒绝 |

**四条硬规则**（都写在那个文件的转移表里）：

1. **不在表里的转移一律忽略，不抛**（这类事件可能乱序到达）。
2. **`confirmed` 是终态，不许退回 `failed`**：回执到了就是到了；再把一条已经确认的话改回失败，
   用户会重发一遍，而服务端那边**已经收过了**。
3. **`queued → confirmed` 必须允许**：WS 的回声和 HTTP 的返回是两条路，谁先到都有可能。
   只留 `queued → sent → confirmed` 的话，回执先到会被当成"不允许的转移"丢掉，
   界面永远停在"已交出去"。
4. **`failed → queued` 只有一条路**：重发。**重发必须带服务端去重** ——
   `/api/say` 按 `messageId` 幂等（§3.2.1），否则"重发 = agent 干两遍"。

**分得清"排队"与"失败"**：还有一条不相交的状态在外面 —— `queued` / `sent` 是**还没好**，
`failed` 是**没成**，`confirmed` 是**成了**。界面上的三副长相必须**一眼分得开**；
"失败与成功长得一模一样"是这个产品最贵的缺陷之一（09 号用户的原话：
*"界面把'发不出去'显示成'发出去了'"*）。

### 4.2 作用域与"上屏排队"

**一条可见时间线，一套号，多间房间**：
一个用户只有**一条**日志（`main.jsonl`）、**一个** `Timeline`、**一套号**；
"是哪一间"住在事件上的 `scopeId` 标签里。`ScopeView` 是同一把 `Timeline` 上的
**一层带标签的视图**：写的时候盖标签（**主线不盖**）、读的时候只挑自己那一间。
⇒ **多作用域不是并列的计数器。** 判据：`scope-single-log.test.js` 的 F1。

**"执行可以并行，上屏排队"**：

| | 什么样 | 落点 |
|---|---|---|
| **执行** | 随便并行 —— 非焦点作用域该干活干活 | 进程池按 `<userId>/<scope>` 分键（`worlds.js`） |
| **上屏** | **同一间对话里，同一时刻最多一条未收口** | `Timeline.beginMessage()` 已有未收口就**抛**（不变量 N22） |

⚠️ **`#opens` 是"按 scope 各记一份"**，不是全局一份：一条日志现在装着所有房间，
而 N22 的本意是"**一条对话里**同一时刻最多一条未收口"。收成全局一份的话，
甲房间正说着、用户切到乙房间说一句 ⇒ 乙那条 `beginMessage` 会**当场抛** ——
那是把一条正确的不变量用错了地方。

**"作用域栈"今天没有落点**：客户端那边焦点是**一个值**，服务端那边是
一张**设备 → 焦点**的平表。**没有 push / pop / 父级**。详见
[`02-ARCHITECTURE.md`](02-ARCHITECTURE.md) §4.2。

### 4.3 收起 / 删掉 / 真删（三段）

**今天的三段是这样**（"收起"是**本地的藏起来**，不是一条协议事件）：

```
可见（屏幕上那一条）
  │ ① 藏起来        ← 客户端本地：hideMessages()，**不销毁、不发请求**
  ▼
已藏起来（墓碑之后）
  │ ② 删掉          ← 服务端软删：落一条墓碑 turn/deleted（**有期限**）
  ▼
真删（③ 压实）      ← Store.rewrite()：内容真的不在盘上，**号一个不跳**
```

| 段 | 谁做 | 数据动了没有 | 判据 / 落点 |
|---|---|---|---|
| **① 藏起来** | 客户端（`timeline.dart` 的 `_hiddenIds`） | **一个字节没动**：条目还在，只是"该画哪几条"不再包含它 | `Timeline.items` 是**唯一的**可见视图，所以"藏起来"只有一处，不可能某条路漏了它 |
| **② 删掉** | 服务端（`trash.js`） | 落一条 `turn/deleted`（取号、落盘）；**盘上的正文照旧在**（只追加是删不掉字节的） | 删前必须先把**要删什么 / 删不掉什么**摆出来问一次；键是 `messageIds` |
| **③ 真删** | 服务端（`trash.js` → `store.js` 的 `rewrite()`） | **重写整条日志**：把那一轮的事件换成最小占位、**保留各自的 `seq`** | 原子（写 `.tmp` → fsync → rename）；抽行会让 `verifyMonotonic` 变红 |

**几条必须知道的口径**：

- **删掉的三种终局**：`turn/deleted`（藏起来）· `turn/restored`（取消隐藏）·
  `turn/purged`（从内存丢掉）。三条都**取号落盘** ⇒ 重启之后客户端才知道谁被删过。
- **"删前那份清单"是从状态清单推出来的**（§4.6），**不是手写的几句话** ——
  手写的一定漏，漏一项就是"屏幕上说删了、其实还在"。
- 🔴 **今天客户端上没有任何入口能把删掉的东西列出来，也没有"拿回来"的地方**
  （"回收站"那一整条砍了）：`trash.js` 的软删与恢复接口**照旧在、协议冻结**，
  砍的只是**界面上的入口**。所以"删之前先问一次"是**底线**，不是可选项。
- **桌面那一格**是另一条路（`POST /api/app-remove`）：它也是**软删**（挪进 `.removed/`
  ＋ 审计一行），文案逐字就是"从桌面上删掉"。**没有"收起来"这个中间档** ——
  界面上不许说"还能拿回来"（服务端确实留着，但今天没有任何地方能把它列出来）。
- **为什么真删要"重写"而不是"挖洞"**：只追加是删不掉字节的；
  而**抽行**会让"编号 = 已落盘最大 ＋ 1"（N22）失效，也会让客户端的游标错位。
  ⇒ 压实是**把内容换成占位**，不是把行抽掉。

### 4.4 过程两档

**出处**：`lib/models/process_levels.dart`（纯逻辑）＋ `src/server.js` 的档位闸。

| 档 | 用户看到 | 谁能开 |
|---|---|---|
| **在做什么** ✅ 默认 | 一句人话（"在查资料"→"在算"），**逐个替换** | 今天所有人都是它 |
| **它心里想的**（推理原文） | 它的原话推理 | 🔴 **产品定义上是"只有主人、默认关"；而今天客户端上没有任何换档入口** |

🔴 **今天必须读准的一条**：档位在客户端**钉死在默认那一个** ——
`chat_controller` 把 `_level` 恒置成 `defaultProcessLevel`，它自己那段写着
"**档位选择那一件砍了**；协议一个字没动"。
⇒ 今天**没有任何界面能让用户换成推理原文**：那个 token 只有老客户端（或手改地址里的
`level`）还会发，服务端照旧按连接级放行。**产品定义那一栏与"今天能操作到哪一步"是两件事**，
写文档时别把前者写成后者。

- **四个 wire token 全部冻结**：`quiet` / `doing` / `steps` / `reasoning`。
  菜单上只剩两个入口，另外两个老客户端还在发 —— **一个都不许改、不许删、不许复用**。
  改一个字节就是"某一台老设备静默降成默认档"，而屏幕上不会有任何异常。
- **老设备盘上存着 `quiet` / `steps` / `reasoning` ⇒ 读出来一律归一到默认档**：
  那些档的产品入口已经没了，留着它就是"**卡在那一档、又没法切回来**"的陷阱；
  而菜单上**没有任何一项是选中的**同样是页面在说假话。
- **`level` 是连接级的**：服务端按**每条连接**决定发多少过程 ⇒ 换档只能靠**重连**。
  和"切焦点不重连"**不是一类**，两件事别混。
- 🔴 **"发不发推理原文"绝不能靠客户端判**：客户端那一行只是"收不收着、显不显示"，
  **服务端才是"发不发"**（只有 `reasoning` 那一阶放行 `reasoning/delta`）。
  这是隐私闸的地基 —— 客户端藏起来的东西，网络那一层照样拿得到。
- **两条硬约束**：**不承诺时间**（"大概两分钟"是假话的来源）；
  **必须有乱序保护 ＋ 超时收敛**（否则卡住时永久停在"在查资料"，比空白更坏）。
- **`step/*` 今天的处境**：服务端**照旧为老客户端的 `steps` 档发**，
  新客户端收得到但**不再消费/不再画**（界面那一档已经砍了）。契约
  [`../dev/122-TWO-PROCESS-LEVELS.md`](../dev/122-TWO-PROCESS-LEVELS.md)。

### 4.5 工时账（字段冻结、只追加）

**出处**：`src/ledger.js`（账本本体）＋ `src/ledger-text.js`（出口）。

- **六个字段冻结**（顺序就是回显的顺序）：`kind` · `qty` · `unit` · `unitPrice` · `tax` · `date`。
  **语义一旦写进账本就不再改**；要改就是**新增字段**。
- **只追加，不原地改**：改一条 = **新增一条**，旧的那条永久留在盘上。
  本模块**没有任何"改"的入口** —— 这是结构上的，不是纪律上的。
- **校验在宿主**：模型只能"提一条要写的"，写不写、写成什么由 `ledger.js` 说了算；
  不过 ⇒ **不写**，并**说清哪一项**。⚠️ **能验的只有形状** ——
  宿主验不了"原话里到底说没说这个数"（那是理解，不是校验），所以出处那一层
  靠**回显确认**兜着，本模块不假装能替它。
- **口径不明要显式表达**：含税说不清的（`unknown`）**不进合计**，并在末尾**明说有几条没算进来**。
  只排除不报数就是"悄悄少算"。
- **出口是"一段能粘进微信的话"，不是表**：`renderLedger()`（`ledger-text.js`）——
  不带 markdown、不带表格线。**合计口径只有一处**（`foldTotals()`），渲染那一份**不许自己再算一遍**。
- **账本住在另一条日志上**（`LEDGER_TIMELINE_ID`），和可见时间线**不是同一条**；
  删除走与可见时间线同一套语义（同期限、可恢复、真删压实 —— 见 §4.3），
  但**`restore` 不重发内容**（账本没有"客户端游标"这一层，重发会让同一个 `entryId`
  在盘上出现两份 ⇒ 合计算重）。
- **硬闸**：同一句话**两次** ⇒ 逐字段 diff = 0（时钟与 id 都是注入的，所以判据不用真等）。

### 4.6 状态清单（备份 / 迁移 / 删除都照它走）

**这是一张"哪些是用户的状态"的表。** 删除（§4.3）逐条对的就是它。
**两半必须逐行对得上**：下面这张表的机器可读那一份在 `src/trash.js` 的 `STATE_SURFACES`，
`test/trash.test.js` 有一条闸把两边对起来（**少一行 / 多一行都红**）。

| 那一格 | 是什么 | 删除时 |
|---|---|---|
| `/data/main/` | 主目录的文件 | **会删**（你选的那一轮：你说的话 ＋ 它的回答，立刻从屏幕上消失） |
| `/data/workspaces/*/` | 各作用域（房间）的文件 | **不在这条对话里 ⇒ 不会被这一下碰到** |
| `/data/hupo/memory/` | 记忆索引那一处 | 按 `STATE_SURFACES` 今天判成"**这一处还没建**"（不进用户看得见的那份清单） |
| `/data/hupo/audit/` | 审计那一处 | 同上（**这一格记的是容器布局里的那个位置**） |
| `$DSH_HOME/sessions/` | 会话历史（**记忆本体**） | **删不掉，必须如实说**：记忆是按整段对话存的，抽不掉单独一轮 |
| `$DSH_HOME/storages/` | 投影 / 检查点 | **同上**：它跟着整段对话走 |
| `$DSH_HOME/.credentials.yaml` | 钥匙 | **不是你说的话**（不进这份清单的处置） |

> ⚠️ **一处要读准**：服务今天那本给主人看的审计落在**数据目录下的一个文件**
> （`src/audit.js` 的 `AUDIT_FILE`；容器里 `HUPO_DATA=/data`），**它不是用户内容**，
> 所以**不在上面这张清单里** —— 清单管的是"删掉那一轮要碰到哪些用户状态"，
> 账不归它管。

**为什么它非得是一张表、而不是几句手写的话**：
**手写的一定漏**，而漏一项 = 屏幕上说"删掉了"、其实还在（**说假话**）。
摆成表之后，"少一行"这件事**结构上会红**；手册将来加了新的一格，那条闸会提醒回来补。

> **备份 / 迁移怎么用它**：这三样是"搬走就能复原这个人"的全部 ——
> 他的文件、他的会话记忆、他的钥匙；其余（缓存、投影、临时文件）可以抛弃，
> 但**抛弃谁、保留谁**要照这张表说，不许"看着办"。

## 五、服务端内部契约

> 这一节是**服务端内部的几条契约**：它们不是"建议的实现方式"，是**别的地方依赖它们的形状**。
> 每条都写清"**不这样会怎样**" —— 这五条里有三条是**会永久丢数据 / 永久挂起**那一类。

### 5.1 唯一取号函数

**契约**：`src/timeline.js` 的 `Timeline.#nextSeq()` 是**全模块唯一**的取号点。
`emit()` 是它唯一的调用者；`emitTransient()` **不取号**。

```
emit(event)
  ├─ full = { ...event, seq: #nextSeq(), at: event.at ?? clock() }
  ├─ store.append(id, full)          ← 先落盘
  │    └─ 抛错 ⇒ #seq -= 1（退号）＋ 原样抛
  └─ #publish(full)                  ← 落盘成功之后才推订阅者
```

**不这样会怎样**：

- **取号散在多处** ⇒ 两处各自加一，"磁盘上不得出现空洞"当场变成假话
  （§3.4.1 那条规则的来由：上一代有两处取号，其中一处还给瞬态发号）。
- **先推后落盘** ⇒ 用户看到了、盘上没有。重启之后那一条消失 —— 这比"没收到"更坏，
  因为它**已经被当真过一次**。
- **失败不退号** ⇒ 盘上是连续的，但号跳了一格 ⇒ 下一个事件在盘上留一个洞，
  而客户端按 `sinceSeq` 补发时会把那一段当成"从来没发生过"。
- **`append` 不是同步的** ⇒ "取号与落盘之间插不进别的写入"这条前提没了；
  要么加锁，要么把取号方式一起改掉（**不能只把 `append` 改成异步**）。

### 5.2 `MessageWriter`：一条消息的生命周期

**契约**：`start → text* → end`，由 `MessageWriter` 保证。四条不许破：

| # | 规则 | 不这样会怎样 |
|---|---|---|
| 1 | **没有 `start` 就 `chunk` ⇒ 自动补一个 `start`** | 界面收到一段没头没尾的正文，只能丢掉它（那一段用户就永远看不到） |
| 2 | **`chunk()` 先查 `ended`，已收口就抛**（硬拦，不是提醒） | 谁还攥着旧 writer，谁就能把内容写回**一条已经收口的消息**里 ⇒ 用户看到"**时间倒流**" |
| 3 | **`end()` 幂等**：重复调用返回 `false`，不产生第二条收尾 | 一条消息收两次尾，客户端那一条气泡的状态机会被推成"两次结束" |
| 4 | **`end.sources` 是权威版本**（工具往往在收尾前才返回出处） | 出处停在半路，或者同一个出处两处口径 |

**`start()` 失败要撤登记**：`Timeline.beginMessage()` 可能因为"已有未收口"而抛，
而 `start()` 里 `emit` 落盘失败也要**把刚登记的"未收口"撤掉**。
不撤的话，时间线上会永久留着一个**未收口的幽灵**，之后**每一条消息都开不了口** ——
而现场看起来只是"它不理我了"。这是"不拿不真实的状态污染记录"（N7）的形状：
状态先写下去，失败时忘了收回来。

**`handoff()` 与"挪走"不是一回事**（决策 D10.4）：

| | 收口？ | 后面的话进哪 | 用户看到 |
|---|---|---|---|
| **转交**（`handoff()`） | **不收口** | **同一个 `messageId`**（B 接着写） | **一个气泡** |
| **挪走** | **先收口** | 另起一条 | 两个气泡 |

⇒ `handoff()` **绝不调 `end()`**。而且要记住两条：**可见标签永远是发起那一间**
（`scopeId` 不变，视图不裂）；**"谁在干活"另有一个字段 `byScope`**，
**只用于审计与用量，不许当可见标签**。

### 5.3 ★ 落盘失败上抛之后，谁接

**这是唯一会永久丢数据的根。** `store.append` 写失败必须**上抛**，绝不吞
（`src/store.js`：`append()` 把窗口里的错原样包成 `StoreError` 抛出，
`close` 的错**不许掩盖**上面那个真正的失败 —— 掩盖了调用方就会以为"只是关文件失败"，
从而错过"盘满了"这个事实）。

**三层，缺一不可**：

| 层 | 谁 | 做什么 | 为什么是这一层 |
|---|---|---|---|
| **1** | **调用点** | **不逐处 try** | 发出事件的调用点有很多，逐处 try **必漏**；漏一处就等于那条路又回到"静默吞" |
| **2** | **`emit`** | 落盘失败 ⇒ **抛出**，**订阅者一条都不推**；同时**退号** | 把"要不要兜"收敛到**唯一入口**；"订阅者零收到"是判据的另一半（推了一半再抛，客户端会收到一条盘上不存在的事件） |
| **3** | **进程级** | `src/process-guard.js` 的 `installProcessGuard()`（在 `serve.js` 里装上）：接 `uncaughtException` / `unhandledRejection` ⇒ **用不落盘的通知通道**说一句人话，然后**有序退出**（交给 systemd 拉起） | 没有它，`emit` 抛出的错在 Node 里就是**未捕获异常** ⇒ 进程直接死 ⇒ 拉起 ⇒ **又死**。而盘还是满的 ⇒ **重启风暴**，而每一步都没有人知道发生了什么 |

**第 3 层为什么说得出话**：它走的是**瞬态通道**（`emitTransient`）——**它不写盘**，
所以**盘满时它仍然能发出去**。如果用普通通道报"盘满了"，那条消息自己就写不进去。

**两条配套，别漏**：

- **写盘失败那一条用户看得见的话**走 `noticeUrgent()`（`notice/urgent`，`kind: 'disk-full'`），
  而且它**自己说清"我没能记下来"**（例外不许伪装成正常）。
  只有写盘失败才准走它 —— 给别的 `cause` 它会**抛**。
- **`Notice.noticeOrUrgent()` 是那条"落盘优先、写盘失败才退回瞬态"的路**：
  它是**唯一**允许把"写盘失败"当常规分支处理的地方（别的错照抛）。

**判据**：除了"抛错 ＋ 订阅者零收到"，还要有"**调用点不需要自己 try**" ——
前两条单独成立、第三条不成立的话，下一个人还是会在某个新调用点上加一个 try，
于是那条路重新变成静默丢数据。

### 5.4 ★ 轮的稳定键

**契约**：任何"按轮记账"的结构，键**只能是轮号**（`turn`，DSH 在 `turn/start` 里给的），
不是"当前那个写手对象"，也不是 `writer.messageId`。跨代（agent 重启 / 换会话后轮号会重来）
还要带上**代**：`pairKey(generation, turn)`（`src/worklog.js`）。

**今天落在哪**（三个都要用同一把键）：

| 结构 | 在哪 | 键 |
|---|---|---|
| `#turns`（这一轮的账） | `src/session-translate.js` | `turn` |
| `#deadlines`（这一轮的硬收口计时器） | `src/dispatcher.js` | `turn`（⚠️ 今天这个时间上限**是关着的**，见下面那条） |
| `#turnOwner`（这一轮是主人哪句话引起来的） | `src/dispatcher.js` | `pairKey(generation, turn)` |

**如果拿 writer（或 `writer.messageId`）当键，会怎样**（这条的根因不明显，动手前先读完）：

```
handoff() 会**原地换掉 writer**（session-translate 里 rec.writer = …），
而 dispatcher 手里的 rec 与 translator 的当前轮账**是同一个对象** ⇒
  · "开轮时记下的那个 id" 在 dispatcher 不知情的情况下**变了**；
  · 硬收口的守卫读到的是**新的 id** ⇒ 永远匹配不上 ⇒ **这一轮永不收口**；
  · 清理时删的也是**新 id** ⇒ 旧键**永久残留在表里**。
```

⇒ 后果是"**升格过的轮次，硬收口彻底失效**" ——
"挂起必有收尾"（N19）与过程那一档的"超时收敛"**同时变成假话**，
而屏幕上表现为一个**永远停在"它正在做"的气泡**。

**为什么它藏得住**：`dispatcher.js` 全文**没有任何一处给 writer 赋值**——
它只读（`rec?.writer ?? rec?.adopted`）。单看那个文件，会以为那个对象是稳定的；
改它的人得先知道"**另一个文件隔着一层把这个对象改了**"。

> ⚠️ **今天仍有一个已知的、被接受的缺口**：单轮**时间上限**是关着的
> （主人拍过：不设时长限制）⇒ N19 的"必有超时"只剩"**进程死了**"那一条路
> （进程退出 ⇒ 服务端补一句实话收口）。"活着但卡在一个不动的循环里"**今天没有**
> 由时间触发的收尾。这是那条决定的**已知代价**，不是遗漏。

### 5.5 `AgentRuntime`：env、进程上限、淘汰

**一个房间一条会话，一个会话一个真 `dsh` 子进程**（stdio JSON-RPC）。
进程池在 `src/agent-runtime.js`。

#### 5.5.1 env：先做减法，再把 `PATH` 补对

`childEnv({home, extra})` 的规则（**这是"一套配置"的一部分，两处入口共用**）：

1. **先传全部 `process.env`**，然后**只删密钥类**（名字以 `_API_KEY` / `_TOKEN` / `_SECRET`
   结尾的，大小写不敏感）。
2. **`DSH_HOME` 由参数给**（多租户下每人一份 ⇒ 键是绝对路径，换个 home 就是换个账号）。
3. **`PATH` 里必须能看见"跑我们那个 `node`"的那一格**（`withNodeDirOnPath`）。
4. **`extra` 里的东西最后合并**：一串**不是秘密**的 `HUPO_*`
   （node 绝对路径、那几支 MCP 脚本的路径、那几条域套接字的路径、这一间叫什么）。

**为什么不是严格白名单**：`dsh` 是 **node CLI**，**丢 `PATH` 就回到 ENOENT**；
而那个 ENOENT 与"**`cwd` 不存在**"报的是**同一句话**（实测骗过人一次）。
严格白名单要先把生产机上的变量盘一遍再做 —— 在盘完之前，**减法**已经达成了原本的目标
（去掉密钥），而**零 ENOENT 风险**。

**为什么 `PATH` 还要单独补**：服务自己的 `PATH` 可能**短得看不见 `node`**
（systemd 用户单元就是这样）⇒ 孩子按 shebang 找不到 `node`，退出码与"找不到 `dsh`"**一模一样**。
只修一层会在真机上看起来"没修好"。

**不这样会怎样**：
- 把 `undefined` 塞进 env 会变成字符串 `"undefined"` —— 比"没设"更难查；
- 少了 `HUPO_LEDGER_SERVER` 那几样 ⇒ 能力层那几条 `- insert:` 的 `args` 变成 `[null]`
  ⇒ **整个 plugin tree 加载失败、`dsh` 当场退**。

#### 5.5.2 进程上限与 LRU 淘汰

| 机制 | 在哪 | 形状 |
|---|---|---|
| **上限** | `cfg.agentMaxProcesses` | 池子只可能从 `agent()` 被突破 ⇒ **取用这一刻就是该淘汰的时机** |
| **真正的 LRU 访问序** | `#access` 数组 ＋ `#touch()` | 每次取用把它挪到队尾（`Map` 的插入序**不等于** LRU：从不更新的插入序会把"最早建"当成"最久没用"） |
| **淘汰** | `evictIfNeeded()` | 从**最久没用**的那头开始，直到回到上限 |
| **硬收口** | `stop(sessionId, {reason})` | "为什么要它走"是超时；其余与淘汰同流程 |

**三条安全边界（淘汰里写死的）**：

1. **只淘汰空闲的**：`running === true` ⇒ **跳过**。
   ⚠️ **跳过不等于放弃** —— 下一轮还会看它（`return` 掉不重新计时就会变成"跳过一次 = 永久不淘汰"）。
2. **先收口，再卸载**：回调 `onEvict`（由 dispatcher 把话说圆），然后才 `dispose`。
3. **先从表里摘掉，再去收口**：反过来的话，`await` 收口这段时间里表里还留着那个**正在死的**实例，
   而这期间来一条新消息，`agent()` 会把它又发回给调用方（实测踩到：投递直接失败）。
   摘表管的是"**别再把它派出去**"，收口管的是"**把话说圆**"，两件事不冲突。

**为什么 runtime 自己收不了口**：它**没有翻译层**，不知道哪条消息还没收口 ⇒
只能回调出去。回调链是：
`worlds.onEvict` → `dispatcher.onEvict` → `forceClose('failed')` ＋ `closeUndelivered` ＋ `clearAllDeadlines`。
**不这样会怎样**：用户永远等不到收尾；而且卡住的进程**一直占着一个位置**
（`running` 永远是真的，而淘汰又"跑着的不许卸"）⇒ **永远不会被淘汰**；
用户之后说的话会被 DSH 排进**一个永远不会来的下一轮**（实测），跟着一起没。

### 5.6 准入

**出处**：`src/admission.js`（判据是纯函数）＋ `src/server.js` 的 `/api/say`。
**判据**：内存占用比（分子分母必须**同层** —— 拿我们的 `current` 去除以祖先的 `max`
会算出一个偏小的比，然后在最该拒的时候放行）。

**四条口径**：

1. **判在落盘之前**。落盘之后再拒 = "文件已经建了"，而下一个人根本分不清
   "**没收下**"与"**收下了但没答**" —— 那两种在日志里长得一模一样。
2. **重发（`duplicate`）不判**。那一句**早就落盘了**；拿"忙"拒它会让界面说假话
   （显示"没发出去"，而服务端其实收下了，那一轮还在跑）。
3. **拒绝必须三件**：**一句人话 ＋ 可重试 ＋ 不建空文件**。
   人话在客户端那一侧按码翻（服务端回明确的码，不造句子）。
4. **算不出判据时不许悄悄放行**。这台机器今天**每一层 `memory.max` 都是 `max`**
   （服务那个单元同样是 `infinity`）⇒ 判据算不出来。这时的行为是：
   **放行，但在开机横幅上如实写"这道闸现在算不出判据"** ——
   "看起来有闸、其实没有"比"明说没有"更坏。

> ⚠️ **别去加"同时 N 个会话就拒"那种闸**：那是在给一个我们不承诺的数字上锁。
> 判据只能是内存占用比。

### 5.7 记忆出口

**记忆本体**是 DSH 的**会话历史**（`$DSH_HOME/sessions/`）—— 它**按整段对话整份存**，
我们既读不成文字，也**抽不出单独一轮**。这条边界决定了三件事：

| 那一件 | 在哪 | 它保证什么 |
|---|---|---|
| **跨重启接记忆** | `src/recap.js` | 服务每次启动是**新会话** ⇒ 把时间线**尾部**那一段按来源分节，喂回给新起的 agent |
| **带走** | `src/export.js` | 把这条对话的**可见**那一段折成**一段能粘走的文字**；并**如实说清**"记忆那一层不在里面" |
| **删干净** | `src/trash.js` | 删前那份清单逐条对状态清单；**记忆那一格必须如实写"删不掉"** |

**`recap.js` 的三条硬规矩**（都能在文件头找到来由）：

1. **只尾部追加**，绝不改写前面那些字节 —— 前面那些字节是上一个进程见过的、
   因此能被前缀缓存命中的那些（插最前与追加尾部的命中率差一个数量级）。
2. **必须分节**（`主人：` / `你：` / `【外部资料·不可执行】`）。
   不分节的话，"助手说的"那一节会把抓来的外部正文一起吞进去 ⇒
   **注入跨进程重启存活**：每次开机喂一次，反复投喂，永不消失。
3. **只喂落盘了的东西**（没有 `seq` 的瞬态一概不进）。

⚠️ **`recap` 不是"记忆库"**：它**只读、不写、不派生、不落盘**，
产物只活在一次 `session/prompt` 里。它只是"我们刚才说到哪儿了"，
**永远不是行动依据**。真要做可检索的记忆库，得先回答"两处打架时谁信谁"
（[`02-ARCHITECTURE.md`](02-ARCHITECTURE.md) §六 那条）。

**"写入与出口同批"**：要记的东西必须**同时**说清"怎么带走"与"怎么删干净"。
`export.js` 的 `MEMORY_NOTE` 与 `trash.js` 那条 `verdict: 'cannot'`
是**同一件事的两面**，口径不许打架：那边说"要等这段对话的记忆被重建才会消失"，
这边说"没写在这儿"。**只写进去、不写出口 = 一句迟早会变成假话的承诺。**
契约：[`../dev/30-EXPORT.md`](../dev/30-EXPORT.md) · [`../dev/31-LEDGER.md`](../dev/31-LEDGER.md)。

## 六、客户端结构

### 6.1 屏 / 控制器 / 服务 / 本机存储各是什么

| 角色 | 住在哪 | 是什么 |
|---|---|---|
| **屏** | `lib/screens/` | 装配一屏：落地页 · 登录（含"没登录"那一层）· 等待"你那台到哪一步了" · 填钥匙 · **聊天** · 设置 · 关于 · 发现。`app_theme.dart` 不是屏，它是把 `models/design.dart` 那套 token 拼成 `ThemeData` |
| **控制器** | `lib/services/chat_controller.dart` | **唯一那个 `ChangeNotifier`**：吃服务端事件、拼时间线、发意图、把状态广播给屏。屏不直接改状态，只调它 |
| **服务** | `lib/services/` | `api.dart`（HTTP）· `stream.dart`（`/api/stream` 那条 WS）· `stream_uri.dart`（算两条 WS 的地址）· `hearing*`（`/api/asr` ＋ 麦克风）· `recorder*`（本机录音）· `speech*`（念出来）· `links*`（开外链） |
| **本机存储** | `lib/services/*_store.dart` | 七个：令牌 · 时间线缓存 · 草稿 · 组合中的输入 · 外观 · 壁纸 · 朗读偏好。**全部走同一个包**（见 6.4） |
| **纯逻辑** | `lib/models/` | 值、解析、状态机、词表、几何、地址计算。**判据进硬闸的那一层**（§二） |

**平台分叉是条件导入，不是分支**：`*_web.dart` / `*_native.dart` / `*_stub.dart`
（`hearing` · `recorder` · `speech` · `links` · `mini_runtime`）。
安装那些钩子的地方**只有 `main.dart`**，而且**只在安卓上装**（网页那一份是空操作）。
⚠️ **原生那几份不许进 Web 那条编译链**（`webview_flutter` 同一条纪律）：所以
"哪一半没有"在设计阶段就要想清，而不是等编不过才发现。

### 6.2 "进哪一屏"只有一处

**没登录时**：`models/entry_screen.dart` 的 `landingFirstFor(isWeb:)` ——
网页先落地页（一句"这是什么" ＋ 两个入口），**安卓直接登录页**、而且**不画**回首页的箭头
（没有首页可回，留着它就是个按不动的按钮）。

**登录之后**：`models/space.dart` 的 `spaceScreenFor(space, keySent:)`：`chat` / `waiting` / `key`。

**`main.dart` 是唯一装配处**：它按上面两个纯函数的结果选 `home`。
平台那一刀（`landingFirst`）**只有那一处** —— 别在屏里再判一次 `kIsWeb`。

**为什么放在 `models/` 当纯函数**：判据能在 VM 上直接量，而"选哪一屏"不必为了可测性去动
`kIsWeb`。**一条纪律跟着它**：`space` 那个回执**缺字段 / 认不出来 ⇒ 按"就绪"处理**
（直接进聊天）—— 老服务端没有这个字段，而**不许把老用户挡在门外**。

### 6.3 两条 WebSocket 与它们的地址

**两条**：`/api/stream`（时间线）与 `/api/asr`（语音）。
**地址都是纯函数算出来的，而且共用同一个"原点"函数**（`services/stream_uri.dart` 的 `_wsOrigin`）：

| 函数 | 算出什么 |
|---|---|
| `streamUri({base, page, sinceSeq, level, scope})` | `wss://<host>/api/stream?sinceSeq=…&level=…&scope=…` |
| `asrUri({base, page})` | `wss://<host>/api/asr` |

**同源时看页面自己的协议，跨源时看 `base` 的协议。** 令牌走**子协议**
`['bearer', token]`，**不进 URL**（服务端也忽略 URL 里的令牌，两边守同一条规矩）。

**出过事的那一行**长这样（**别照抄**）：

```
final scheme = base.startsWith('https') ? 'wss' : 'ws';
而 web 上 base **恒为空串**（同源）⇒ ''.startsWith('https') 是 false
⇒ 在 https 页面上拼出了 ws:// ⇒ 浏览器按混合内容**直接拦掉**
```

**而当时每一道闸都是绿的**：验收用的是 node 探针，探针**把 `wss://` 写死了**，
**绕过了被测的那行代码** —— 它测的从来不是客户端真正会发的东西。
⇒ 所以有了那条判据（V13）：**凡是"客户端自己算出来的东西"，闸必须打在客户端这一侧**。
`test/unit/stream_uri_test.dart` 钉住它，含一条"https 页面**不许降级**"的金丝雀。

**原生那一侧还有第二个坑**：原生包**没有地址栏** ⇒ `Uri.base` 是 `file://`、
`Uri.parse('/api/version')` **没有 host** ⇒ "装上去一直连不上"，而闸全在网页那一侧。
⇒ 原生包**必须带地址**（`--dart-define=HUPO_API=…`），
打法**只有一个入口**（`scripts/build-apk.sh`），而这一条判据钉着那个脚本里必须有那一行
（`test/unit/server_address_test.dart`）。地址那一层也是纯函数：`models/server_address.dart`
的 `apiUriFor()` 与 `apkDownloadUri()`。

**地址上的两个参数，语义不同、别混**：
- **`level`**（过程档位）是**连接级**的 ⇒ 换档只能靠**重连**；
- **`scope`** 今天是"**初始焦点**"：连上之后切房间**发一帧、不重连**（§3.2.9 的 `focus`）。
  ⚠️ 它**仍然带在地址上**（老服务端只认它、老客户端也只带它）—— 这一条不许破。

**地址构造只有这一个入口**：谁都不许在别处再拼一遍 `ws://` / `wss://`
（那次事故的第二、第三个入口就是这么来的）。

### 6.4 本机持久化：只有 `shared_preferences`

`pubspec.yaml` 里的 `shared_preferences` 是**唯一**的本机持久化包；
七个 `*_store.dart` 全走它。**没有任何第二个存储后端**（没有 sqlite、没有文件缓存目录）。
小程序那一格自己的数据库**不住在客户端**（它在服务端／盒子里）。

**五条纪律**：

1. **缓存只缓存，不判断**：`timeline_store.dart` 存的是"服务端说过的事实"，原样喂回
   `Timeline` —— 下次开机那一屏和断线前是**同一条渲染路径**画的
   （不可能出现"缓存版和实时版长得不一样"）。
2. **只存带 `seq` 的**。这条规则不需要另立名单：**"号 = 这是落盘的事实"**（§3.4.3）。
3. **有界**，而且**整条整条地丢**（从最前面丢）：截半条 = 解不开 = 那一屏可能只画出半句话，
   那是编造。
4. **命名空间**：`models/scope.dart` 的 `scopedCacheNamespace(namespace, scope)` ——
   主对话**沿用老键**（多租户之后全站用的就是它，改键会让在跑的设备升级那一下白屏），
   别的房间才加 `@<scope>`。多租户之后那一半按令牌里的主体换
   （**换个人登录要能换一份**，退出登录要清）。
5. **坏掉的后果必须小到"就是空屏"**：读写抛了就**当没缓存**，
   **绝不能因此让聊天不能用**。写/清**排队做**（`clear()` 一定排在相邻的写后面，
   否则会把刚判死的缓存又写回去，下次开机画出那个不存在的世界）。

### 6.5 客户端的三条边界（写代码时最容易越的）

| # | 边界 | 越了会怎样 |
|---|---|---|
| 1 | **只上报事实，不做判断** | 判"这句话来自谁""该不该刷新"是服务端的活；客户端再判一次，遇到边界输入两边会给出**不同的答案**，而屏幕上分不出哪个是真的 |
| 2 | **切焦点是"告知"，不是"自己拍板去哪儿"** | 用户点一个图标 ⇒ 客户端算出那一间、记下来、**发一帧 `focus`**（带上那一间自己的游标）；**界面因为"派活 / 问话"要跳到另一间时，只认服务端那一帧 `scope/open`**，客户端不自己猜（`chat_controller` 收到才 `setScope`）。两边各切一次 = **两个裁判** |
| 3 | **内部词一个都不许上屏** | 词表闸（`test/unit/forbidden_words_test.dart` ＋ `models/forbidden_words.dart`）扫的是**放在 `models/` 里的那份文案表** —— 所以用户会看到的字**必须住在 `models/`**，摆在 `screens/` / `widgets/` 里的字符串**闸够不着** |

## 七、测试地图

### 7.1 三道硬闸 ＋ `test/widget` 里那一条

| 闸 | 命令 | 守什么 |
|---|---|---|
| **客户端 · 编译** | `~/sdk/flutter/bin/flutter analyze` | 编译都不过的东西不能上线 |
| **客户端 · 纯逻辑** | `flutter test test/unit` | 协议 / 状态机 / 词表 / 几何 / 地址；**新验收一律写这里** |
| **服务端** | `cd v2/services/core && node --test "test/*.test.js"`（即 `npm test`） | 取号 / 收口 / 对账 / 翻译 / 沙箱 / 供给 |
| **可访问性** | `flutter test test/widget/accessibility_test.dart` | **`test/widget` 里唯一那条硬闸**（决策 D3.5 点名） |

- **一条命令跑完客户端三道**：`bash scripts/check-client.sh`
  （它**按目录**扫 `test/widget/*_test.dart`，所以新加一份会自动进提示档，不必手改脚本；
  这一份已经当过硬闸的会被排掉，免得跑两遍）。
- **服务端收尾**：`bash scripts/gate-server.sh`。
- **`test/widget` 的其余那些是提示档 —— 但别删**：它们是"这件事到底有没有画到屏幕上"的
  **唯一自动化证据**。提示档挂了不拦收尾，**但不等于可以当没看见**。
- **可访问性那条为什么破例是硬闸**：通用规矩"`test/widget` 只是提示"被一条**具体决策**
  覆盖了（D3.5）。它量三样：**字号放到最大那几档 pump 无溢出**（"字大了、笼子没大"
  是走查里最实在的故障）、**命中区下限**、**不封顶**。
  ⚠️ **命中区要量渲染盒子（`RenderBox.size`），不要量语义矩形** ——
  语义矩形的读数随滚动位置变，那种读数**不能当闸**。

**"跑绿了"不等于"闸没空转"**：每条新判据都要有**负向对照** ——
把被测的那行代码**改坏**，闸必须当场红。**会撒谎的闸比没有闸更坏。**

### 7.2 什么必须写成纯函数才能进硬闸

`flutter test test/unit` **不搭界面、不 pump、不开浏览器、不碰平台通道** ——
它能在 Dart 层直接跑完（大多数文件连 `testWidgets` 都不需要）。
⇒ 能进这道闸的只有**"给值、返回值"**的东西。所以下面这些**必须**是纯函数，否则等于没人守：

| 那一类 | 例子（已经这么做的） |
|---|---|
| 状态转移 | `models/message_state.dart` 的 `canTransition` / `nextState` |
| 解析（协议字段 → 值） | `models/timeline.dart`、`models/chat_queue.dart`、`models/tool_row.dart`、`models/trash.dart` |
| 算出来的地址 | `models/server_address.dart`、`services/stream_uri.dart` |
| 界面上的字 | `models/*_words.dart`（**用户会看到的字符串住这一层**，词表闸才扫得到） |
| 几何 / 分页 / 派生视图 | `models/desktop_grid.dart`、`models/scroll_follow.dart` |
| **判"该进哪一屏"** | `models/space.dart`、`models/entry_screen.dart` |
| 服务端的判据本体 | `resume.js` 的 `planResume`、`admission.js` 的 `decide`、`ledger-text.js` 的 `renderLedger`、`plan.js`、`tool-rows.js` |

**判据一句话**：**把"客户端自己算出来的东西"抽成纯函数，闸才打得到它**（V13 那条）。
逻辑埋在 `build()` 里 ⇒ 只能靠 widget 测试，而 widget 多半是提示档 ⇒ **等于没人守**。

### 7.3 不许写的测试

| 不写 | 为什么 |
|---|---|
| **断言像素坐标 / "哪块贴顶"** | 界面一重构**必过期**；而过期的断言比没有更坏 —— 它逼下一个人去**哄断言**，而不是去看产品 |
| **断言控件 key / 内部类名** | 那是实现细节，不是产品要求；改个名字就红的闸，测的不是产品 |
| **断言行为快照**（"默认就最大化"这类"当时是这样"） | 它锁的是**当时的实现**，不是要求；重构之后它只会挡路 |
| **"内部名出现在界面上"那种反向断言** | 反过来写：用**禁用词闸**禁止它出现（`test/unit/forbidden_words_test.dart` 扫词表），而不是断言它"出现在这里" |
| **量语义矩形当命中区判据** | 那个读数随滚动位置变（见 7.1），不能当闸 |

**一句话**：测试只该断言**产品要求**与**纯函数的行为**；凡是"这一屏今天长什么样"的东西，
一旦写进硬闸就变成了**重构的阻力**。

### 7.4 窄闸与戳：同一棵树不重复跑

**迭代期只跑窄闸**（全闸一次很贵，见 [`../dev/212-DEV-SLOW-WHERE.md`](../dev/212-DEV-SLOW-WHERE.md)）：

```bash
bash scripts/gate-quick.sh <改动的路径…>      # 按"改哪块 ⇒ 跑哪条"挑出来跑
bash scripts/gate-quick.sh --list <路径…>     # 只说要跑什么，不跑
```

- **映射只有这一处**（`gate-quick.sh` 里那张 `case`）：服务端 `src/<名>.js` ⇒ 同名
  `test/<名>.test.js`；客户端 `lib/**.dart` ⇒ `flutter analyze` ＋ 同名 unit / widget 判据；
  `.md` ⇒ 文档闸；`scripts/*.sh` ⇒ `bash -n`。
- **认不出就如实说"认不出"**，退回让你判断，**绝不悄悄放过**（找不到同名判据也会退回全闸）。
- 它**不当全闸用**：结尾一定会写一句"**收尾还要跑全闸**"。

**收尾跑全闸，而且同一棵树不重复跑** —— 全闸会**留一枚戳**：

| 动作 | 命令 |
|---|---|
| 服务端全闸（带戳） | `bash scripts/gate-server.sh` |
| 客户端全闸（带戳） | `bash scripts/check-client.sh` |
| 真要重跑（不管戳） | 上面两条加 `--again` |

**戳的四条口径**（实现 `scripts/gate-stamp.sh`）：

1. **指纹只认内容**：源码 ＋ 判据 ＋ 依赖清单 ＋ **工具链版本**；任何一样变了 ⇒ 戳作废、照跑。
2. **读不出来 / 文件不在 / 解析失败 ⇒ 一律当"该跑"**（fail-closed，绝不因为"读不出"而跳过）。
3. **有窗口**：过了窗口就是新的一次收尾，照跑（窗口长度住脚本，本文不写数值）。
4. **戳只落本机，它不是判据**，只是一句"刚跑过"。

**另外两条不许破**（纪律，不是脚本能拦的）：**同一条全闸不许并行跑第二遍**；
`check-client.sh` 之后**不许**再单独跑 `flutter test`（它已经包含 analyze ＋ unit ＋
全部 widget ＋ 可访问性）。契约：`docs/dev/213-GATES-CHEAPER.md`。

**文档闸**：`node scripts/check-docs.mjs`（链接可达 ＋ `#锚点`可解析 ＋ 路由层不许有数值 ＋
同一份里不许有重名标题）。它**只保证指针没断**，不保证内容还对 ——
内容对不对只有硬闸知道。所以任何"现状"都不许写死：**写命令，不写数字。**

## 八、文件级索引怎么用

**这一节不抄索引** —— "我要改个小东西 ⇒ 打开哪几个文件、跑哪几条命令"那张表
**只有一个家**：[`../CHANGE-MAP.md`](../CHANGE-MAP.md)。抄一份到这里，
两份就会各自漂，而**看旧那一份的人不知道自己在看旧那一份**。
本节只讲**怎么用它**、以及**什么时候不该用它**。

### 8.1 先问那一句判据

> **这次改动会不会改变"别人依赖的形状"？**

| 答案 | 怎么走 |
|---|---|
| **不会**（改个颜色 / 间距 / 字号 / 文案，加一个纯逻辑函数，修一个界面小 bug） | **走卡**：按"我要改什么"查到落点与闸，**不必**读手册全篇 |
| **会** | **停下来读手册**：协议字段 · 人格 · `strict` 文件（手册 / `AGENTS.md` / 那几份受保护的 `hupo-*.yml`）· 线上 · 小程序沙箱边界 |

"会改变形状"的那几样，卡里也各自点了一格指向对应手册章节 —— **那不是让你跳过手册**，
是让你知道**要读哪一节**。

### 8.2 卡上只有三样东西

**路径 · 命令 · 边界**。它**不许有状态、条数、读数** —— 一旦写"现在有多少"，
它当天就开始漂（`scripts/check-docs.mjs` 会把这份也一起扫）。
这张卡的维护纪律（改完顺手补一格、超了就拆、改名就靠文档闸变红）写在它自己那一份里。

**卡不是判据**：判据只住 [`08-SPEC.md`](08-SPEC.md) 与 `test/`。
卡只负责**把人领到门口**。

### 8.3 两个"找不到"怎么办

- **卡上没有对应的一格** ⇒ **加一格**，而不是回去通读手册。
  "每次都要通读"正是这张卡当初存在的理由。
- **不确定一条协议事件落在哪** ⇒ 先跑
  `bash scripts/where.sh '<事件名>'`（服务端 / 客户端 / 文档 / 测试分组列出来）。
  ⚠️ **它是考古工具，不是判据**：为什么不把它做成"两边一致"的自动闸，
  见 [`../CHANGE-MAP.md`](../CHANGE-MAP.md) §二 那一格（**会撒谎的闸比没有闸更坏**）。
