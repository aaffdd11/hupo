**谁该读**：碰线上之前。

---

## 计划中的节

| 节 | 回答什么 |
|---|---|
| **一、本机是什么** | **这台机器就是跑线上服务的那一台**（开发、测试、服务用户三件同机）；另一台是什么 |
| **二、改一样东西要做什么动作** | 服务端 / 客户端 / `strict` 文件（手册 · `AGENTS.md` · 人格）**各是什么动作**；⚠️ **改客户端不许重启服务** |
| **三、服务端** | 入口 · 数据在哪 · **开机完整性清单**（对不上就拒绝启动）· 那条很短的 `PATH` 与绝对路径纪律 · 重启脚本 |
| **四、客户端** | 一条命令跑完三道闸 · 产物指纹 · **"浏览器那条路"的检查**（客户端自己算出来的东西，闸要打在这一侧） |
| **五、权限模型（P1/P2）与回退** | 助手只能提申请、签字的是主人；回退一句话就够、且不读助手产出的文件；开发期与部署期的分界 |
| **六、供给上限与准入** | 一个人能开多少、满了怎么拒（**给人话**）、为什么必须有进程上限与淘汰 |
| **七、容器** | 验收清单（缺一条就全白做）· 装/撤/核对 · 怎么删一台（五条不许破） |
| **八、钥匙三个入口** | 网页填 / 盒内放 / 本机投递；三个入口写**同一个文件** ⇒ 没有第二份真相 |
| **九、产品层怎么更新** | 造一版 → **先证明它起得来** → 翻转 → 容器自己重开；旧版本不许顺手删 |
| **十、备份 / 恢复 / 回退** | 照状态清单走；含密钥的那份备份必须加密；**没演练过的备份不算备份** |
| **十一、监控与告警** | 盯哪几个读数；告警必须说人话（内部名不许出现） |
| **十二、探针纪律** | 不许拿真实 id 打破坏性口 · 改文件每一步都要断言"旧的那段真的在" · 闸别带管道跑 |
