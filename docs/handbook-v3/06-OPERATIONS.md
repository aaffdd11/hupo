# 06 · 怎么跑起来、怎么不出事

**这一份回答什么**：怎么起、怎么改、怎么部署、怎么回退、出事怎么办。
**谁该读**：碰线上之前。

> **一条事实只有一个家**：这一份讲**人怎么做**（动作、顺序、代价、边界条件）。
> **判据、阈值、不变量全文在 [`08-SPEC.md`](08-SPEC.md)** —— 这里只带指针，不抄一份
> （抄一份，那天就开始漂）。
> **要问什么该读哪一份**：先看 [`../INDEX.md`](../INDEX.md)（它只放指针、不放结论）。

> ⚠️ **本机没有系统 `node`**：只有 nvm 里那一个（`/usr/bin/node` 不存在）。
> 所以下面凡是要跑 `.mjs` 的地方都写 `"$(command -v node)"` —— 粘进 shell 就当场展开成

> `sudo node …` 会撞「找不到命令」，而那条命令恰恰在最需要它的时刻出现
> （服务起不来的时候）。`scripts/` 下的脚本**自己会算 node**，走脚本就不用管这一条。

## 一、本机是什么

**这台机器就是跑线上服务的那一台。** `127.0.0.1:8020` 上跑的就是用户访问的那个服务，
对外域名是 **`https://w.stalkerai.cn`**（本机 → VPS 的 frp 隧道，配置在
`~/.local/frp/frpc-w.toml`，由 `hupo-frpc-*` 那几个用户单元看着）。

⇒ 三个身份叠在同一台机器上：**改代码 + 跑测试 + 服务用户**（三件同机）。

| | **本机（你在这里）** | **另一台** |
|---|---|---|
| 项目路径 | `/home/deploy/proj/hupo` | **不在这台**（本机没有那个 checkout） |
| 服务 | `scripts/restart-core.sh` / 用户单元 `hupo-core.service` 起的 `src/serve.js`，听 `127.0.0.1:8020` | 上一代那个部署（单元 `concierge-core`，另一个端口） |
| 域名 | `https://w.stalkerai.cn` | `https://hupo.stalkerai.cn` |
| 用途 | **改代码 + 跑测试 + 服务用户** | **上一代**，还活着，跟本机这一套不是一回事 |

**为什么这条必须先说**：把它当"一台可弃的开发机"会导出两个都致命的行为 ——
① 在本机到处找服务而找不到；② 更坏：**以为线上在别处，于是改完不管部署**。
两套部署**都在跑**，改哪一套都不会顺手改到另一套。

**怎么核**（两条都只读）：

```bash
systemctl --user is-active hupo-core            # 线上服务在不在（active / enabled）
cat /proc/$(pgrep -f src/serve.js | head -1)/cgroup   # 它的 cgroup 指向 …/hupo-core.service
```

⚠️ **本机同时是主人的桌面机**：上面还跑着**他自己的别的会话**。⇒ 两条禁令：

- **不许 `pkill -f` / `pgrep -f`**：`-f` 匹配整条命令行，而**运行这条命令的 shell 自己
  命令行里就带着那个模式** ⇒ 会把自己杀掉。（`restart-core.sh` 因此按 **PID 文件**走，
  不按模式。）
- **不许"看到 dsh 就杀"**：我们的 agent 是**本服务的子进程**；优雅地 `SIGTERM` 服务本身，
  `serve.js` 会 `dispatcher.shutdown()` → `runtime.shutdown()` 把子进程带走。杀错了是**毁别人的活**。

**`sudo` 要密码**（`sudo -n true` 会失败）。这一条决定了流程的形状：

- **需要 root 的动作都得主人自己跑**：重建开机清单 · 装/撤特权侧 · 建租户池 · 删租户 ·
  改宿主上那份 nginx。
- **给主人的命令必须能直接粘**（见本文开头那条 `node` 的规矩）。
- 🔴 **口令不进任何文件、不进任何日志**。要放开就放开**具体那几条命令**（白名单），
  **不是把口令交出去**。⚠️ 而白名单里放一个"助手能改的脚本"，**实际上仍然是 root** ——
  它的价值是**留痕**，不是圈住它（详见 [`../dev/23-DEV-VS-DEPLOY.md`](../dev/23-DEV-VS-DEPLOY.md) §五）。

**开发期 / 部署期的分界不是"哪台机器"，是"这段工作在服务谁"**（见 §五）。
本机**同时是开发机又是线上机**，所以"换台机器就安全"那种读法是错的。

**这台机器算不出"容量"那类判据**：服务所在 cgroup 从它自己一路到 `/user.slice`，
**每一层 `memory.max` 都是 `max`**。而"内存占用比"是**有上限时**才算得出来的相对量。
⇒ 服务不去猜，它在**开机横幅里如实写"算不出判据"**（§六、§十一）。

## 二、改一样东西要做什么动作

三类，**生效方式完全不同**：

| 改了什么 | 怎么生效 | 要不要重启服务 |
|---|---|---|
| **服务端**（`v2/services/core/`） | `scripts/restart-core.sh` | **要** |
| **客户端 / 界面**（`v2/apps/mobile/`） | 重新构建 + 上传：`bash scripts/deploy-web-v2.sh` | 🚨 **千万不要重启服务** |
| **`strict` 文件**（手册那一层 · `AGENTS.md` · 人格 · `~/.dsh/profiles`） | **重建开机清单**（一条 `sudo`）；重建**之后**再重启 | 要（重建之后） |

### 2.1 🚨 改客户端为什么**不许**重启服务

两条理由，都踩过：

1. **重启对客户端改动毫无作用**。界面跑在浏览器 / 手机里，只有**重新构建上传**才会变。
2. **重启会把正在回答的助手杀掉**。助手是那个服务的**子进程**。在"改了界面、还没部署、
   还没验证"的时候重启它，**等于在任务中间自杀**：文件改了，用户屏幕上什么都没变，
   而他**再也等不到回话**。

⇒ 客户端那一条的完整动作是：跑闸（§四）→ `deploy-web-v2.sh` → 公网核一眼 → **浏览器那条路的检查**。
**全程不碰服务**。

### 2.2 `strict` 那一条为什么是这个动作

那些文件是**开机自动读**的东西：人格、能力层、`AGENTS.md`、手册那一层、
以及 agent 的 profile 与补丁。清单是它们的**摘要**；对不上，服务就**拒绝启动**。
⇒ 改完**必须重建清单**，否则下次重启起不来。（清单本身、放哪、权限、怎么重建，见 §三。）

🔴 **顺序是固定的**：**先把所有 `strict` 文件改完 → 重建清单 → 再重启。**
反过来的形状是：重建完了又去动了一份 strict 文件 ⇒ 重启时服务拒绝启动，
而屏幕上只说"起不来"。

⚠️ **重建命令别手打**：照 `verify-integrity.mjs` 打出来的那一条粘 ——
它里面是**这台机器的实际路径**（含 node 的绝对路径）。

**改了哪些 `strict` 路径，以清单为准**（清单是唯一权威；`--list` 会一条条列出来）：

```bash
"$(command -v node)" scripts/verify-integrity.mjs --list   # 不用 root：先看要钉住哪些东西
```

## 三、服务端

### 3.1 入口 · 数据 · 日志

| 项 | 值 |
|---|---|
| **入口** | `v2/services/core/src/serve.js` |
| **起它的两条路** | 用户单元 `hupo-core.service`（模板 `deploy/systemd/hupo-core.service`，**enabled + active**，开机自启）· `scripts/restart-core.sh`（它**认单元**：单元在跑就走 systemd 那条路） |
| **端口 / 对外** | `127.0.0.1:8020`（只监听本机）→ `https://w.stalkerai.cn`（frp 隧道） |
| **数据** | `v2/services/core/data/` —— **永不入库**（`.gitignore` 已排除，别改） |
| **日志** | `v2/services/core/serve.log` —— **跨重启接记忆靠它** |
| **租户通道** | 一个运行期目录，每个租户一个套接字 |
| **开机完整性清单** | `/etc/hupo/integrity.json` |

**数据为什么"永不入库"**：那里面是**发生过什么**，不是"开机照做什么"。
它是用户的状态、是运行期流水，可能含凭据。⇒ 它进 git 就等于把"状态"和"代码"混成一份，
而且一旦提交就再也收不回来。

### 3.2 开机完整性清单（P1 的落地）

**是什么**（`src/integrity.js`）：一份"**开机自动读的东西**"的摘要清单。三类：

1. **会被执行的**（调度器代码、主人会手动跑的脚本）；
2. **开机自动喂给 agent 的**（人格、能力层、模型那条补丁、`AGENTS.md`、profile 与补丁）；
3. **判据本身**（手册那一层 —— 能随手改判据，任何闸都白设）。

**文件在哪 / 权限**：`/etc/hupo/integrity.json`，**`root:root 0444`**。

**对不上会怎样**：`strict` 条目对不上 ⇒ `serve.js` **拒绝启动**，并**点名那个文件**。
（`report` 条目对不上只**大声报**，服务照起 —— 用在"本来就该变"的东西上：
口令、撤销表、运行时会自己续期的令牌。拿那些当 strict ⇒ 某天开机**无故拒绝启动**，
而主人不在跟前。）

🔴 **为什么路径写死、不走环境变量**：服务是**助手自己重启**的。清单路径或"要不要强制"
只要能从环境变量来，助手敲一句就能把这道闸整个关掉 —— **那等于给它一个关闸开关**。
⇒ 路径写死；"哪些条目只报不拦"这件事**住在清单文件里**（root 所有 ⇒ 助手改不了自己那一档）。
⇒ 唯一能停用它的动作是主人 `sudo` 把它挪走 —— 那是主人的动作，看得见。

**怎么重建**（**只有主人能跑**；没 root 会被当场拒）：

```bash
"$(command -v node)" scripts/verify-integrity.mjs --list          # 先看一眼要钉住什么
sudo "$(command -v node)" scripts/verify-integrity.mjs --build    # 重建
```

**日常核对**（谁都能跑）：

```bash
"$(command -v node)" scripts/verify-integrity.mjs
```

它的退出码**分得很清楚，别读混**：

| 码 | 意思 |
|---|---|
| `0` | 对上了（或刚建好） |
| `1` | 只有"**只报不拦**"的条目动过 ⇒ **服务照常起**，但要知道这件事 |
| `2` | **`strict` 对不上 ⇒ 会拒绝启动** |
| `3` | 清单**还没建** ⇒ **P1 那条保护现在是没有的** |

⚠️ **"清单还没建"必须大声说出来**：悄悄过去就等于"看起来有这道闸、其实没有"，
**那比不设更坏**。服务在开机横幅里也如实写（对上了 / 只有只报的动过 / **还没启用**）。

**建完它会反着查一遍**：`coverageGaps()` 问的是"**声明要保护、盘上真有东西、清单里却一条都没有**"
的那几条。那种条目等于**没有闸**（"写着有、其实没在核对"），所以它们是**问题**（拒绝启动那一档），
不是提示。这条反查是必需的 —— 正着核对的函数**永远看不见清单里没有的东西**。

⚠️ **两个真实形状，值得记着**（这条规矩为什么存在）：

- **清单是按"仓库属主的 home"算的，不是按"现在跑这条命令的人"算的**。
  `sudo` 之下 `os.homedir()` 是 `/root` ⇒ `~/.dsh/**` 那几条被算成 `/root/.dsh/**`，
  那里一个文件都没有 ⇒ 被静静跳过 ⇒ **P1 最核心的那几条保护从来没进过清单**，
  而横幅照样写"对上了"。这正是本仓库最忌的形状。⇒ 现在清单里**记着它是按谁的 home 建的**，
  换一个 home 会被查出来（条目里存的是绝对路径，所以逐条 hash **照样全绿**）。
- **往受保护目录里新加一个文件**也算"漏了"：正着核对只遍历**清单里已有**的条目。

**每次重建都要留痕**：时间 / 为什么 / 动了哪几个文件，记在
[`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) §九（它是"攒着要重建清单的改动"那一节）。

### 3.3 那条很短的 `PATH`，与"spawn 出去的东西要么绝对路径要么自己补"

服务归 **systemd 用户单元**之后，它那份 `PATH` **很短**（用户单元那份，**没有 nvm 那个 `bin`**），
而本机 `node` 与 `dsh` **只住在那里**。

⇒ 🔴 **规则：不靠 `PATH`。服务 `spawn` 出去的任何东西，要么给绝对路径，要么自己把 `PATH` 补齐。**

落地在三处（改这一块之前先读 [`../dev/140-AGENT-BIN.md`](../dev/140-AGENT-BIN.md)）：

- **`dshBin` 的取值顺序**（`src/config.js` 的 `resolveDshBin()`）：
  显式给的 `HUPO_DSH_BIN` → **`node` 同目录那个**（`dsh` 与跑我们的 `node` 是同一套装的）
  → 裸名 `dsh`（那时 `PATH` 里得有它 —— 容器里就是这样）。
- **开机的 `preflight`** 会问一次"这份环境里找得到它吗"（`dshBinProblem()`），
  找不到就**拒绝启动**。三态分清楚：带路径的看那个文件在不在；裸名逐个 `PATH` 目录找；
  **不许把"没找到"说成"没装"**。
- **孩子的 `PATH`** 由 `agent-runtime.js` 补上 `node` 与 `dsh` 那两格。

**为什么这条是硬的**（它是拿事故换来的）：裸名 `dsh` ⇒ `spawn` 当场 `ENOENT`；
改用绝对路径之后**还是**起不来 —— 因为 `dsh` 的 shebang 是 `#!/usr/bin/env node`，
而**孩子的 `PATH` 里没有 `node`**。**两层的症状一模一样**：用户只看到"接不上活"，
盘上像什么都没发生过。而 `spawn` 的 `ENOENT` 是**二义的**（"命令找不到"与"工作目录不存在"
报同一句）⇒ 现场极难认。

⚠️ **从 shell 手动起服务是测不出这条的**（你的 shell 有 nvm 的 `PATH`）——
判据必须**拿服务那一份环境**跑（`/proc/<pid>/environ`）。

⚠️ **同一条纪律适用于别处**：`preflight` 会一起查的还有几条 —— 工作目录、
人格 patch、能力层 patch、账本那支 MCP server、我们自己的 SDK server 那一层 patch。
**缺了要当场说**：它们缺了**都不会报错**（agent 起得来、答得出，只是"说话不像它"
或者"少一个能力"），没人会去查配置。

### 3.4 `restart-core.sh`：它做的事、它的只读预检、它不能做的事

```bash
scripts/restart-core.sh            # 重启，**日志留着**（跨重启接记忆靠它）
scripts/restart-core.sh --fresh    # 重启并清空 data/main.jsonl（**说过的话会没** ⇒ 必须显式要）
scripts/restart-core.sh --now      # 不等它说完，立刻重启（**会切掉正在说的那一轮**）
```

**① 默认先等它把手上的话说完。** 直接重启会把正在说的那一轮连同回答一起杀掉，
用户看到话说一半没了。服务每秒把"手上还有没有没说完的话"写进 `data/status.json`，
脚本就等那个文件变成"不忙"再动手。
⚠️ **等一个已经死掉的服务 = 脚本永远卡住**，那比切一轮话更坏 ⇒ 它有**上限**，
而且还要看那行状态**是不是陈的**（服务死了就没人再更新它）；到点就**照样重启**，
并把这件事实说出来。

**② 动手之前先"只读"地问一句：新服务起得来吗。**
它跑一遍 `verify-integrity.mjs`，**只看退出码 `2`**：

- `2` ⇒ **不停旧的**，打印那一条补救命令，然后退出。留下的还是**活着的**旧服务 ——
  **"停在那里"比"整站下线"好得多**。
- `0` / `1` ⇒ 照常重启（`1` 是"只有只报不拦的动过"，服务照常起）。

⚠️ **不许"非零就拦"**：那会把**每一次改 `src/` 之后的重启都拦住**（而改 `src/` 是天天在做的事）
—— **一道会误报的闸很快就会被绕开**。
强行跳过预检：`HUPO_SKIP_PREFLIGHT=1 bash scripts/restart-core.sh`。

**③ 指纹不许默认成 `dev`。** 没显式给就从 `web/index.html` **真正引用的那份产物**里读
（部署时入口文件叫 `main.<指纹>.dart.js`，`index.html` 引的是同一个指纹的 bootstrap）；
读不到再退回 `web/main.*`；都读不到才算 `dev`。默认成 `dev` 的话，`/api/version`
报的就是**一句假话**（"我是哪个版本"和磁盘上真正在服务的产物对不上）。

**④ 报到状态为止，不喊口号。** 起没起来看**进程/单元与退出码**；
最后把**整段开机横幅照原样**打出来 —— ⚠️ **不许挑词过滤**：过滤词表会漏掉新加的行
（漏的恰好是"完整性"与"准入"那两道闸那一行），而"新加一行横幅就悄悄看不见"会复发。
⇒ 按形状取（从**最后一个横幅头**到它后面那条全破折线），加多少行都不会漏。

### 3.5 归属哪个单元 · 为什么不许拿 `systemctl --user stop` 清 scope

- 线上服务活在那个单元的 cgroup 里：`…/app.slice/hupo-core.service`。
- 🔴 **那条禁令照旧**：**`systemctl --user stop`（不带单元）会顺手清掉 DSH 的 scope**，
  把**别的会话一起杀掉** —— 线上真出过事（502 了几分钟）。
  清那些 scope 之前，先 `pgrep -af src/serve.js` 看它在不在里面。
  ⇒ 脚本里所有 `systemctl` 调用**只点这一个单元**。
- 🔴 **单元掉进"崩溃环"时**，`restart-core.sh` 会按 `systemctl --user is-active` 选路 ⇒
  可能走**手动那条路**，把服务起在**会话 scope 里**（会话一收，线上就跟着死），
  而且它**停不掉** systemd 那个（手动路只认 `serve.pid`，systemd 不写它）⇒ **两个进程抢端口**。
  ⇒ 正确顺序：**先把"起不来的原因"修掉 → `systemctl --user start hupo-core` 把它弄活
  → 再用 `restart-core.sh` 走 systemd 那条路**。
- **判断"服务到底归谁管"看 cgroup**：`cat /proc/<pid>/cgroup` 里应当是 `…/hupo-core.service`；
  写着别的 scope ⇒ **它不在单元里**（这就是要收拾的形状）。
- systemd **不做命令替换**：`Environment=` 只能来自文件 ⇒ 真指纹是写一个 drop-in 再
  `daemon-reload` 递进去的。⚠️ 不用"设 manager 的环境变量"那种办法：manager 的环境
  **不落盘**，机器一重启就没了 —— 而"开机自启"正是这个单元存在的理由，
  重启之后 `/api/version` 又会掉回 `dev`。

## 四、客户端

### 4.1 一条命令跑完三道闸

```bash
bash scripts/check-client.sh
```

它**一条命令一条命令地跑，不用 `&&` 串** —— 串起来的话第一条挂了后面就都不跑，
而"**哪几条**挂了"比"第一条挂了"有用得多：

| 档 | 是什么 | 拦不拦 |
|---|---|---|
| **硬闸** | 静态分析（编译都不过的东西不能上线） | 拦 |
| **硬闸** | 单元测试（协议 / 状态机 / 纯逻辑） | 拦 |
| **硬闸** | 可访问性（五档不溢出 + 命中区 + 不封顶） | 拦 |
| 提示 | 其余 `test/widget/*_test.dart`（断言的是"**有没有画到屏幕上**"） | **不拦**，但**别删** |

- 🔴 **可访问性那一份是硬闸，不是提示档**：手册的通用规矩（"widget 测试只是提示"）
  在这里被一条**具体决策**覆盖。
- ⚠️ **提示档按目录动态取，不写死文件名**：写死的话，**以后新加的 widget 测试会永远不跑**——
  而"新加的那一份"恰恰是最该跑的那一份。（实测漏过两次。）
- ⚠️ **别的提示档挂了不必为了它停手**，但它是"这件事到底有没有画到屏幕上"的**唯一自动化证据**。

**留戳**：同一棵树、同一个工具链刚跑过 ⇒ 当场跳过并告诉你上一版刚跑过；
树一变（内容变了）戳就作废（指纹＝源码 ＋ 判据 ＋ 依赖清单 ＋ 工具链版本）。
要真再跑一遍加 `--again`。⚠️ **判据一个字没变**（还是那几条命令），
变的只是"什么时候真的再跑一遍"—— 收尾时同一道全闸被跑两遍（还并行）会吃掉大量工具时间。

### 4.2 产物必须走部署脚本

```bash
bash scripts/deploy-web-v2.sh            # 构建 + 部署 + 重启 + 公网验证
bash scripts/deploy-web-v2.sh --no-build # 不重新构建，直接部署现有的 build/web
```

🚨 **别手打 `flutter build web`。** 理由（**入口指纹在它里面**）：

- Flutter web 的产物**文件名里没有指纹**（`main.dart.js` / `flutter_bootstrap.js`），
  而服务端对**带指纹的名字**才长缓存。⇒ 如果不管，浏览器会把旧的那份当成"很久不用再问"，
  **于是每次部署对已经来过的人等于没部署**。
- ⇒ 部署时脚本给**入口文件**起一个**带指纹的名字**并改写引用：名字变了浏览器就一定会取新的；
  名字没变就直接命中缓存（不用往返）。
- 指纹按**入口文件的字节**算（内容不变 ⇒ 名字不变 ⇒ 缓存照样命中）。

**这一步为什么不是"一次性解药"**：老访客浏览器里存着旧的 `immutable` 响应，换响应头改不了它
已经存下的东西 —— 但**入口那个 HTML 一直是 `no-cache`**，所以老访客会取到新的 HTML，
而新的 HTML 指向一个**新名字** ⇒ 自动绕开旧缓存。

**脚本里还有这几步，每一步都有一个"不这样就会白屏/卡死"的理由**：

- **部署前替跑两道硬闸**（客户端 + 服务端）：红 ⇒ **一步都不往下走**（线上仍是上一版）。
  ⚠️ 以前它一道闸都不跑 ⇒ "闸是绿的"和"线上跑的东西"之间**没有任何强制关系**。
  逃生口要**明写**（`HUPO_SKIP_GATES=1`，用了会打在输出里），不许偷偷用。
- **字体回退自托管**：补丁**必须打在算指纹之前**（否则等于"改了补丁正文而名字不变"，
  浏览器会一直吃缓存里的**旧补丁**）。**必须是绝对 URL**（相对地址会让引擎"取到了字节却对不上号"）。
- **自托管 CanvasKit**：默认构建会把它指向公网 CDN，国内经常取不到 ⇒ 页面卡着等。
  判据**不是**"产物里有没有那个字符串"（那个字符串是加载器里的分支，**永远在**），
  而是那面旗真的为真。
- **预压缩**（br + gz）：⚠️ 必须在**改名之后**压；⚠️ **压不动不许挡住上线**（只是首屏慢一点）。
- **别把旧入口删掉**：老访客的浏览器里可能还存着**上一版的 `index.html`**，
  它引用旧名字；删了那个文件，而服务端对未知路径**回 index.html**（SPA 兜底）⇒
  浏览器把**一段 HTML 当 JS 解析** ⇒ **直接白屏**。⇒ 保留最近几次的入口文件。
  两条护栏缺一条就会把**刚发布的那一版**删掉：当前这一版**按指纹点名排除**；
  旧的那几份用 `cp -p` 放回来（**保留各自的 mtime**）。
- **把不在 git 里的东西拷回静态根**：`web/` 每次部署都被清空，而首页那颗下载、
  图标原图、源码包、参赛文稿都住在那儿 ⇒ 脚本逐个拷回去，并如实报一句"没有它 ⇒ 这次那个下载会 404"。
- 🔴 **引用图检查（重启之前）**：改名是 `sed` 出来的，**漏一处线上白屏**，
  而构建和单测都还是绿的（它们守的是 Dart 源码，碰不到产物里的路径）。
  ⇒ 从 `index.html` 出发顺着引用把每个被引用的文件都找到，**一个 404 都不许有** ——
  这是"**页面能不能开**"的唯一本地判据。
- **公网验证**：`/api/version` 的指纹 · 带指纹产物的缓存头 · 预压缩真的生效（要**带上
  `Accept-Encoding` 问一句**才看得出来）· 字体镜像白名单挡得住且穿越路径没被当字体发出去 ·
  **入口那个 HTML 必须 `no-cache`**。
- ⚠️ **重启那一段必须读退出码**：`restart-core.sh` 有只读预检，清单对不上时它**故意不停旧服务**、
  打印补救命令、退出非零。把它的输出 `grep` 成几行会**把原因那几行滤掉**，
  症状只剩最后一句"线上指纹不是 X"（**症状对了、原因看不见**）。

### 4.3 "浏览器那条路"的检查（为什么它非有不可）

```bash
HUPO_TOKEN=<令牌> "$(command -v node)" scripts/check-web-browser.mjs --shot /tmp/shot.png
```

**V13：凡是客户端自己算出来的东西，闸要打在客户端这一侧。**
用把关键参数**写死**的旁路工具（node 探针 / 手打 curl）验收 ⇒ **不算数**——
**绿的是那个工具，不是产品。**

**这条规矩的由来**：客户端把流的地址**算**成了 `ws://`，在 https 页面上被浏览器按
**混合内容**拦掉 ⇒ **那条路从来没通过一次**。而同一时刻**所有闸都是绿的**：
验收用的是 node 探针，探针把 `wss://` **写死了**，正好**绕过了被测的那一行代码**。
（全过程见 [`../dev/16-STREAM.md`](../dev/16-STREAM.md)。）

**它验两件事，一件都不能省**：

1. **页面自己**建的那条 WebSocket 通没通、有没有收到帧 —— 这是那类 bug 的**唯一可观察信号**；
2. `--shot` 截一张图 —— **Flutter web 把字画在 canvas 上，查 DOM 查不到文本**，
   所以"屏幕上到底长什么样"**只能看一眼**。
   （打开无障碍语义树之后 DOM 里就有字了，那是读"写了什么"；**"长什么样"仍然只能看截图**。）

**纪律**：

- 令牌用服务端 `Auth.issue()` **现发**，而且**不许写进任何文件、不许进日志**。
- 本机浏览器在 `~/.cache/hupo-chrome`，不用给参数。
- ⚠️ **拿一个还没开好空间的号的令牌来跑会得到"假红"**：页面会停在等待屏、
  **根本不该连那条流**，而脚本仍然会报"没通 + 0 帧"。⇒ 看结论之前先确认令牌**能聊天**，
  或者只看截图。
- `deploy-web-v2.sh` 在部署后会自己跑一遍这一眼；⚠️ **它不挡上线**（没浏览器 / 没拿到令牌
  ⇒ **如实说一句**，部署照常算成功）。真坏了会在上面那几条**阻塞**检查里先红。

### 4.4 安卓包

🔴 **只在主人说了才打。**

```bash
scripts/publish-apk.sh --owner-asked   # 主人明说要 APK：打包 + 拷进静态根 + 在线核一遍
scripts/publish-apk.sh --no-build      # 只把**现成的**那个包拷回去（不重打）
```

**为什么这条要写进脚本而不是靠记性**：打包一次好几分钟（构建 + 签名 + 上传核对），
而**大多数改动根本不需要新包**（网页那一半刷新就有）。⇒ `publish-apk.sh`
**没有 `--owner-asked` 直接拒绝**（非零退出）—— 要跳过这一道，得**故意**把那个词打出来。
平时收尾**只跑 `deploy-web-v2.sh`**。

**名字带版本号**：

- 号是**脚本算的**（`scripts/build-apk.sh`）：取「git 提交数」与「本机那份高水位」里
  **大的那个 ＋ 1** ⇒ **单调增**（安卓不许降级安装），而且"同一个提交打两次"也各是各的号。
- **版本名也带它** ⇒ 装的人能在 设置→应用 里**看见**手上是哪一个包。
- 🔴 **那一版叫什么不住在别处**：写进 `data/apk-build.json` 的 `file`，
  `publish-apk.sh` 与 `deploy-web-v2.sh` 都**从账里读**（两处换算就一定会漂）。

🔴 **要从包里核**：

- 打完用 `aapt2 dump badging` 读出来的号必须等于算出来的那个 ——
  "**源文件对 ≠ 包对**"是这一份里反复出现的那条纪律（ManifestMerger 会合并、库 manifest 会注入）。
- 权限也从包里核（`scripts/check-apk.sh`）：网络权限必须在；后台录音**一票否决**。

**签名**：

- 正式签名那份住在**仓库外**（0600），脚本 source 它再交给构建；
  **缺了那四个变量就当场抛**（不许悄悄退回 debug 签名 —— debug 签名是公开的，不能往外发）。
- `publish-apk.sh` 把签名指纹记在 `data/apk-signing.json`，**变了就当场喊**：
  ⚠️ **换过签名的包叠不上去**（旧版会看到 `package is null` 那一类提示）⇒
  **已经装了旧版的人必须先卸载再装**。
- ⚠️ **同一把签名才叠得上去**；它一丢，已装的人只能卸载重装 ⇒ **请离线备份**。

**发出去两个名字，两个各在线核一遍**：

- 带版本那个是**留档**（那一条链接永远指向那一版，谁都能回头下）；
- 稳定名是**已经装在他手机上的那些老客户端的链接**（**冻结契约，不许 404**）。
- 核的是：HTTP 200 · 安卓那个 MIME · `content-disposition: attachment` ·
  与本地那个**逐字节一样**。⚠️ 为什么非要在线核：本地文件放对了**不等于**访客拿得到 ——
  静态服务会不会把 `.apk` 当页面回退、中间那层会不会改类型、隧道会不会截断，
  **只有真请求一次才知道**。

⚠️ **`deploy-web-v2.sh` 会清空 `web/`** ⇒ 部署网页之后要**确认一眼**那个下载还在
（脚本里有一句再拷回来；保险起见也可以补一次 `publish-apk.sh --no-build`）。

## 五、权限模型（P1/P2）与回退

### 5.1 方向：助手只能提申请，签字的是主人

助手可以提、可以写方案，**永远不能自己按那个按钮**。

**为什么**（威胁的真实形态）：**不是"它干一次坏事"**（那能收拾），
而是"**坏事能不能留下来**"：

> 它读到一段看不见的网页内容 → 被诱导写进自己的配置 →
> **从今往后每轮开机都读那一段** → 而表面上一切正常。

⇒ **P1**：**没有任何路径**能让助手的写入变成"**下次开机自动读**"的东西。
落地就是 §三那份清单（`strict` 对不上 ⇒ 拒绝启动；**清单本身 root 所有 ⇒ 助手碰不到**）。
⇒ **P2**：助手把改动与命令准备好，**主人自己上机器跑**。

### 5.2 P2 落在哪两条命令上

```bash
# 助手：把补丁放进 proposals/（这个目录已在 .gitignore 里）
# 主人：自己跑
bash scripts/apply-change.sh proposals/xxx.patch
```

- **补丁只能从 `proposals/` 里来**（用 `realpath` 判，软链 / `..` / 相对路径都绕过不了）：
  P2 甲的安全性全靠"**主人真的看一眼**"，而"一眼"只能落在一个文件上。
  允许从任意路径 apply，等于**主人看的那份和真正生效的那份可以不是同一份** ——
  这条护栏就退化成"助手有 root，只是慢一点"。
- **要求仓库里没有未提交的改动**：apply 之后那个 commit 必须**只包含这一个补丁**，
  否则"**回退一次**"就不等于"**退回这一步**"。真要带着别的改动跑，
  主人得自己显式 `--allow-dirty`（**那是他的签字**，不是脚本替他做的）。
- **先 `git apply --check` 再真 apply**：没通过就**什么都没改地退出** ——
  主人看到失败时，仓库应当和他敲命令前一样。
- **补丁本身与改动落进同一个 commit**（归档进 `docs/dev/applied/`），
  commit 正文带上补丁开头那句说明 —— 三个月后翻 log 的人先看到的是"**为什么**"，不是一串 diff 路径。
- **它不重启**：直接重启会把正在说的那一轮连同回答一起杀掉，而**重启是主人自己决定的一步**。
  它只把"接下来做什么"打印成**一小块**。

⚠️ **甲的安全性 = "主人真的看一眼"。** 养成闭眼跑的习惯，甲就退化成"助手有 root，只是慢一点"。
⇒ 形态必须"**短到主人愿意看**"。

### 5.3 回退

```bash
bash scripts/rollback.sh            # 回退最近一次改动
bash scripts/rollback.sh <commit>   # 回退指定的那一次
HUPO_SKIP_RESTART=1 bash scripts/rollback.sh   # 只回退，不重启
```

- 🔴 **必须用 `git revert`**：它把这一次**反做一遍**，历史留着 ⇒ **回退本身也能被回退**。
  **不许用"退回到上一个提交"那种做法** —— 它会连同后面的**每一个**改动一起丢掉。
- 🔴 **它不读任何助手产出的文件**（不读 `proposals/`、不读账、不读 `docs/`）：
  **出问题时助手本身可能就是出问题的那个**。回退要"**主人一句话完成、不需要助手参与**"。
- **冲突时它 `git revert --abort`**，把仓库**回到主人敲命令之前的样子**，
  再把手动收拾的步骤打出来 —— 不把仓库停在"回退进行到一半"那种半吊子上。
- ⚠️ **为什么它可以替主人重启，而 apply 不行**：回退几乎总是"**服务已经坏了要救回来**"，
  坏掉的服务没有"正在说的话"可保，再让主人手打一条命令只是把没法用的时间拉长。
  服务不在本机时它**只提示、不假装重启成功**。

### 5.4 开发期与部署期的分界

🔴 **分界不是"哪台机器"，是"这段工作在服务谁"。**
本机**同时是开发机又是线上机**（服务 + 隧道都在这台上），所以"换台机器就安全"那种读法是错的。

| 期 | 助手能做什么 |
|---|---|
| **开发期**（本机、主人就在跟前） | **可以用 `sudo`** 做开发上的事：装工具、跑维护脚本、**重建开机清单** |
| **部署期**（给用户用的那一套） | **P1/P2 原样有效**：只能提申请，**签字的是主人** |

- ⚠️ **本机的护栏是审计，不是锁**：助手能自己重建清单 ⇒ **锁不住它**。
  ⇒ 每次重建都要**留痕**（见 §十一 与 [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) §九）。
- ⚠️ **那不等于"随便改"**：口令**不进任何文件、不进日志**；要放开就放开**具体那几条命令**
  （白名单），**不是把口令交给助手**。
- ⚠️ **别把"开发期可以 sudo"读成"部署期也能自己动手"** —— **那不成立**。
- ⚠️ **在本机改仓库代码不属于这一条**（那是正常的开发工作）；这一条针对的是
  **让改动变成"下次开机自动读"**的路径。
- 逐字依据：[`../dev/23-DEV-VS-DEPLOY.md`](../dev/23-DEV-VS-DEPLOY.md)。

### 5.5 审计留痕

- **每次重建开机清单**：在 [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) §九 记一笔
  （时间 / 为什么 / 动了哪几个文件）。那一节还记着"**现在攒着什么、还没重建**"。
- **租户那一侧的账**（两份文件，按时间并起来看）：

```bash
bash scripts/show-audit.sh [--tail N] [--since 日期]
```

  服务写 `<数据目录>/audit.log`、特权侧写 `/var/log/hupo/tenant-audit.log` ——
  **谁也写不了对方的文件 ⇒ 谁也伪造不了对方的行**。两边的行**逐字同一个形状**
  （出处只有一处），**拒了也记**。
  ⚠️ **同一次注销会有两行**（服务"收到请求" ＋ 特权侧"真收掉了"）——**对得上才算真收了**。
- **纪律**：只记**事实**，**不记完整参数**（参数里可能有主人的隐私）；
  **钥匙一个字符都不许有**；手机号**只写掩码**。

## 六、供给上限与准入

### 6.1 准入闸：满了就明确拒绝

判据是**内存占用比**（`memory.current / memory.max`）：到线就**拒新会话**
（`src/admission.js`；阈值住代码与 [`08-SPEC.md`](08-SPEC.md)，**这里不写数**）。

三件硬要求：

1. 🔴 **不许"先落盘再拒"**：判的位置必须在**落盘之前**。落盘之后再拒，文件已经建了，
   而下一个人**根本分不清"没收下"和"收下了但没答"** —— 那两种在日志里长得一模一样。
2. **拒绝必须三件**：一句**人话** + **可重试** + **不建空 jsonl 文件**。**不许静默拒绝。**
3. ⚠️ **别加"同时 N 个会话就拒"那种闸**：那是在给一个**我们不承诺的数字**上锁。
   （"一个进程同时留几个 agent"那个配置项**只用于淘汰与告警，不是准入判据**。）

### 6.2 进程上限与淘汰

（`src/agent-runtime.js`。）

- 一个进程**同时留几个 agent** 是有上限的；**取用那一刻就是该淘汰的时机**。
- 淘汰**只淘汰空闲的**（**跑着的绝不卸**），而且**先收口再卸**（先把话说圆，再放 agent 走）。
- 访问序**真的是 LRU**：每次取用把它挪到队尾。

**为什么这三条缺一不可**（这是取舍，不是洁癖）：

- **没有上限** ⇒ 每一条连接都会热一个 agent，而那个 id 来自 URL 且**无上限** ⇒
  `?conv=N` 就是 N 份内存。
- **没有淘汰** ⇒ 进程只增不减，最终靠 OOM 收场（而 OOM 是**不可控**的收场）。
- **只淘汰"空闲"、且"先收口再卸"** ⇒ 单纯"到点就卸"会在**正说话**的时候把人家的回答掐断；
  而单纯"跑着的不许卸"会留一堆**永远不会被淘汰**的 —— 两条合起来才是对的：
  **卸之前先看它手上有没有话，有话就等它说完**。
  ⚠️ 而"跳过之后要**重新计时**"（否则跳过一次 = 永久不淘汰）也是这一条的一部分。

### 6.3 租户容量：能开几台是"算出来的"

**不是人写的常数。** 算式**只有一处**（`scripts/lib/tenant-capacity.sh`）：

- **物理上限** = 可用字节 ÷ 每台镜像字节（整除，半台不算一台）；
- **策略上限** = 物理上限**扣掉余量** —— 写进模板的那个值。

**为什么留余量**：每台不只是一份镜像，还有**一个卷 + 日志 + 容器可写层**，它们**都会长**。
把盘填满之后坏掉的**不是"新租户开不出来"**，而是**已经在跑的那些** ——
这个项目里"最贵的事故"都是这一类。

```bash
bash scripts/set-tenant-limit.sh                 # 只看：镜像多大、盘多大、算出多少、模板现在是多少
sudo bash scripts/set-tenant-limit.sh --write    # 写回模板（**只改 max_tenants 那一行**）
bash scripts/check-tenant-limit.sh               # 这条算式与"只改那一行"的判据
```

**三条纪律**：

1. 🔴 **算不出来就不写**（读不到镜像大小 / 可用空间 ⇒ **只说不做，不许猜一个数**）；
2. 🔴 **不许悄悄缩小到比现有租户还少**（那等于"这台机器不该有这些人"，而它只是算错 /
   盘被占满 ⇒ 要显式 `--force`，并且把后果写出来）；
3. **只改那一行**（其余字节逐字不动 —— 那个模板是**两套语言的共同输入**）。

### 6.4 今天这条路上的缺口（**如实说**）

- 🔴 **本机的准入闸现在算不出判据**：服务所在 cgroup 从它自己一路到 `/user.slice`，
  **每一层 `memory.max` 都是 `max`** ⇒ 那个比值算不出来。⇒ **不许悄悄放行**
  （"看起来有闸、其实没有"），服务在**开机横幅里如实写"算不出判据"**。
- **"一个进程留几个 agent"只是淘汰与告警用的**，不是准入判据 ⇒ 它顶不上那道闸。
- **磁盘那几档今天只分级、只告警，不改运行时**（不自动清、不拒活、不拒新会话）——
  详见 §十一。
- 判据与阈值全文住 [`08-SPEC.md`](08-SPEC.md)；这一份只讲**人怎么做**。

## 七、容器

### 7.1 为什么是一人一台 · 两种 root 不是一回事

| | 是什么 | 给不给 |
|---|---|---|
| **宿主上的容器守护进程访问权** | = **宿主的 root** | ❌ **永远不给**（加进那个用户组 ≡ 交出 root） |
| **容器内部的 root** | = **那个盒子里的 root** | ✅ **应该给** —— 不给它就是个残废，装不了包、改不了配置 |

⇒ 这正是容器方案的卖点：**在盒子里给它完整 root，而外面一点碰不到**。

### 7.2 验收清单（缺一条就全白做）

判据全文在 [`08-SPEC.md`](08-SPEC.md) §十三（V1 / V1b / V3 / V4 那一族）；
**逐条能跑**的是：

```bash
bash scripts/check-container.sh
```

- 在容器里读**宿主凭据**（`/proc/1/root/...` 那条路）**必须失败**；
- 🔴 **负向对照不能省**：在容器里**写 `/tmp` 必须成功** ——
  否则那个"失败"可能只是因为**容器根本没跑起来**，什么都证明不了；
- 访问**云元数据地址**（就是那一个众所周知的地址，脚本里钉着它）**必须失败**（带正对照）；
- **密钥不许出现在容器里**：判的是**"谁去读、失败成什么样"**，**不是"文件在不在"** ——
  用户自己的凭据**就是**要进他自己的容器（否则它没法调模型）；
  真正要的是"盒内除了那个持有凭据的服务身份之外，**谁（尤其 agent）都够不着它**"；
- 🚫 **一票否决**：**不许用"这是本机 / 测试环境"当理由降级通过**。

本机走**无根 `podman`**（镜像是现造的，不碰任何 registry）：
`deploy` **不在**那个容器守护进程的用户组里，而且**永久不加**（加进去 ≡ 交出 root）。
⚠️ 脚本自己声明：它验的是"**agent 与宿主**"这几条；
**"用户之间互相看不见"不在它里面**（记在 [`../dev/34-CONTAINER.md`](../dev/34-CONTAINER.md)）。

### 7.3 三条约束（都是踩出来的）

| 约束 | 说明 |
|---|---|
| **`podman` 不许以 root 跑** | 镜像住在**造它那个用户**的 rootless 存储里。以 root 跑 `podman image exists` 会得到"没有这个镜像"，然后**你会以为镜像丢了** |
| **`sudo -u` 保留当前目录** | 换身份之前先 `cd /tmp`，否则报 `cannot chdir …` —— 看起来像权限不对，其实只是**站在一个他进不去的地方** |
| **系统盘只读 + `/tmp` 要 `1777`** | 盒里 `/tmp` 不给那个可写模式 ⇒ 盒子里的 agent（**非 root 身份**）**写不进去**，而现象只是"**它不理我**" |

### 7.4 装 / 撤 / 核对三个脚本

> ⚠️ **装它属于"部署期"（P2）：命令由主人跑。助手只写代码与方案。**

```bash
bash scripts/install-provision-helper.sh                    # 只看：要装什么、现在什么样（不动任何东西）
sudo bash scripts/install-provision-helper.sh --yes         # 装
sudo bash scripts/install-provision-helper.sh --uninstall   # 撤（一条命令回到装之前）
bash scripts/install-provision-helper.sh --check            # 核对：仓库那份 vs root 装着那份，逐字节比
```

🔴 **它存在的唯一理由（A9）：root 要跑的每一份文件，必须 root 拥有。**
直接让单元去跑仓库里那个脚本是**不行的** —— 仓库属主就是服务自己，
一个被攻陷的服务改一行，**下次申请触发时那段代码就是以 root 跑的**。
⇒ 这里是**拷贝**：仓库里那份是**源码**，装着那份才是**运行的那份**。

⚠️ **`--check` 不是可选的**：改完仓库里那几份脚本**不会**自动生效（root 跑的是拷贝）。
这与"**改完了 ≠ 生效了**"是同一件事 —— **核对命令的意义就是让这件事看得见**，
而不是靠人记得。

**装的时候它只做三件，且一台容器都不建**（第一台要等真有申请）：
① 把要 root 跑的那几份**拷成 root 拥有**；② 建那个申请投放口；③ 写并启用单元。

**验的时候那条纪律照旧**：**不需要签字就能验的，装之前先验掉**。
安装器的 `--root <临时目录>` 让这件事成立 —— **同一段代码换一个目的地**（跳过 systemd），
于是那几条最要紧的判据在**签字之前**就有答案：

| 验什么 | 怎么验（**都不用签字、都不碰真机**） |
|---|---|
| **拒的那一半** | `sudo bash scripts/check-provision-refusals.sh` —— 逐条带负向对照，且**它自己一台都不建** |
| 🔴 **A9 那几条**（四份 root 拥有 · 单元指向**拷贝**而不是仓库 · 服务身份**读得到但改不动** · **改了仓库那份 `--check` 认得出**） | `sudo bash scripts/check-provision-install.sh` —— 靠安装器的 `--root <临时目录>`；跑完**自证**真机上那几处一处都没动 |
| **模板两边推出来的一样**（同一份模板，JS 与 shell 各推一遍） | 上一条里那一步（**真把 shell 脚本跑一遍**，与 JS 那边算的比） |
| 🔴 **装完之后那两条**（真建一台 · 装完之后服务身份与装之前的基线**逐字相同**） | `sudo bash scripts/check-provision-after-install.sh --phone <测试号>` —— ⚠️ 它会**真的建一个号**；**跳过的那几条会明写"跳过"** |

⚠️ **只有"真建一台"与"装完之后服务身份不变"那两条**必须等装完 ——
**没装之前不许把它们算成绿的**。

**建池**（把机器准备好给租户容器；`/srv` 是 root 的，要 root 建一次）：

```bash
bash scripts/create-tenant-pool.sh              # 只看：把要做的每一件事打印出来
sudo bash scripts/create-tenant-pool.sh --yes   # 真做
```

它动的是**机器状态**，不是代码：① 卷（0700、属主是他自己）；② `linger`；
③ 镜像进**他自己那份** rootless 存储（每人一份，互不可见）。
⚠️ **`linger` 不是小事**：它让租户的进程**留在机器上**。这里开它是因为"容器必须一直在跑、
等着领配置"这个形状**非要它不可**；但它确实**扩大了一点面** —— **如实写在脚本顶上，不藏**。
⚠️ 产品层那条只读挂载在"**还没发布过产品层时**"不写进单元：`podman` 会把**不存在的挂载源
建成一个空目录** ⇒ 之后那条软链就别想再翻了。

### 7.5 怎么删一台（**五条不许破**）

> **契约**：[`../dev/43-AUTO-PROVISION.md`](../dev/43-AUTO-PROVISION.md)。⚠️ **不可逆。**

```bash
bash scripts/remove-tenant.sh --n <编号>              # 只看：把要做的每一件事打印出来
sudo bash scripts/remove-tenant.sh --n <编号> --yes   # 真删
```

1. **静态表那两台永远不许删** —— 它们是**老用户正在用的**，删了就是"把人家的世界删了"。
   这条是**硬拒，没有开关**。⚠️ **两边一致**：服务侧判"受保护"、脚本这边也硬拒。
2. **只认模板推得出来的名字**：别的一律拒（**防手滑删错东西**）。
3. **先停服务、再删人**：不停就删，那个用户的管理器会把容器**又拉起来**，
   而 home 已经被删了 —— 现象是一串看不懂的错。
4. **幂等**：删过的再跑 ⇒ 说"已经没有了"，然后**照样清残留**
   （subuid 条目 / 通道目录 / 待办申请 —— 半路失败会留下这些）。
5. ⚠️ **它不碰"别人"**：只按名字删，**不扫目录、不猜**。**没有"删全部"这种参数。**

⚠️ **删完要 `scripts/restart-core.sh`** —— 不然宿主会一直替一个**不存在的租户**听着。

**判据**：

```bash
sudo bash scripts/check-tenant-removal.sh                        # 只验"拒"的一半
sudo bash scripts/check-tenant-removal.sh --throwaway <名字>     # 再真删一台来验
```

**用户自己那一条**：填钥匙那一屏的**下面**有一个**不抢眼**的「取消注册」⇒
点下去**先列清单**（会没掉什么、**没法撤销**）再确认 ⇒ `POST /api/cancel`。

- 🔴 **只能注销自己**（身份**只从验签令牌里的 `sub` 来**）；
- 走**同一个投放口**（`<n>.cancel`，**不新增任何特权面**）；
- 助手**先回收再建**（他反悔了就不给他建）；收掉之后**令牌全撤 + 账号删**；
- **身份再确认**：注销要"**最近真的登录过**"（看令牌里的签发时间）。⚠️ **续期不会刷新它** ⇒
  **旧令牌刷不过去**；不满足 ⇒ 服务端回 `needs-relogin`，界面说「…**现在什么都没动**」
  并送他回登录那一屏。
- ⚠️ **如实说**：短信通道接上之前，这道门和"登录"本身一样强
  （挡的是"**被盗的旧令牌**"，不是"知道你验证码的人"）。

## 八、钥匙三个入口

### 8.1 钥匙住哪

钥匙住在**他自己的卷里**（`<数据目录>/creds.yaml`，**`root 0600`**）——
所以**重建容器、换运行层都不会再丢**（住 tmpfs 的话重建一次就没了）。
路径**只有一处出处**（`src/key-path.mjs`）。

- 盒里那个小代理**每次请求现读**它 ⇒ 放进去**立刻生效，不用重启**。
- 🔴 **边界**：agent 跑在**非 root 的那个身份**上，而文件是 `root 0600` ⇒
  **agent 读它必须 `EACCES`**（真机验过，验的是**临时**一把、验完删掉）。
  ⚠️ 判据要**挑一个存在的路径**，不许拿 `ENOENT` 糊过去（"不存在"与"没权限"是两件事）；
  **正对照**是 **root 读得到**。

### 8.2 三个入口，写的是同一个文件

| # | 入口 | 谁用 | 要 root | 怎么用 |
|---|---|---|---|---|
| 1 | **网页上填** | 用户自己 | 不要 | 设置里那个「配置」（契约见 `../dev/48` 那一族的文档）。走中心当管道推给他那台容器；**中心那份不落盘** |
| 2 | **盒内放** | 主人（救急 / 开发） | 要 | `podman exec -i hupo-tenant-<租户> /bin/node /app/code/src/put-key.mjs`，粘钥匙、回车、Ctrl-D |
| 3 | **本机投递** | 主人 | **不要** | 往 `~deploy/.hupo-keys/<租户名｜编号｜手机号>.key` 里写一把，宿主替他送进去 |

**三条必须一起成立的规矩**：

- 🔴 **三个入口写的是同一个文件** ⇒ **谁是最后写的谁生效**，**没有第二份真相**。
- 🔴 **投递"送到才算送到"**：文件要留到那一台**自己说"我有钥匙了"**才删 ——
  （中心内存里那份不落盘 ⇒ 读到就删会在宿主重启时**把没送到的弄丢**）；
  那台没在跑 ⇒ 文件**留着**，并且**每隔一会儿再送一次**。
- ⚠️ **认不出的名字**（写错 / 带路径 / 没有后缀）⇒ 挪进 `.rejected/` 并**说清为什么**，
  **不许静默删掉**（那里面可能是一把**真钥匙**）。

**入口 1 会如实说话**：它说现在是"有 / 没填过 / 填过但被判无效"这三种里的哪一种。

**⚠️ 代价如实记**：钥匙**落盘**了（在他自己那台的卷上）。**能读到那块盘的人就能拿到它。**
导出**不会**把它带出去（导出的是一段文字，不扫文件系统）。

**判据**：

```bash
bash scripts/check-key-delivery.sh              # ①~④ 要一个真容器 ⇒ **不要以 root 跑**
sudo bash scripts/check-key-delivery.sh --live  # 再看一眼真机器那两台
```

它每条都带**负向对照**，包括"**那台还没确认 ⇒ 文件必须还在**"与
"**日志与账本里不出现钥匙**"。

> 🔴 **改这一块之前先读 [`../dev/46-KEY-DELIVERY.md`](../dev/46-KEY-DELIVERY.md) §七**：
> 这条规则**只能住在一处**（`src/key-path.mjs`），而且**镜像里的入口不许碰它** ——
> 镜像里那个旧入口会把旧路径**显式传进来**，那正是要挡的形状。

## 九、产品层怎么更新

### 9.1 为什么要分"层"

容器里跑的那套东西**原来整个住在镜像里** ⇒ "改进产品" = **重造几百 MB 镜像 + root 分发到
每一台 + 每台重建容器**。而**真正变得快的那部分只有很小一块**（调度器 + 人格 + 能力），
agent 本体一个人就占大头。⇒ 按"**多久变一次**"劈开：

| 层 | 装什么 | 住在哪 | 多久变 | 谁动它 |
|---|---|---|---|---|
| **运行层** | node + 它的库 + **agent 本体** + 入口 | **镜像**（只读） | 很少 | 主人（建池那一条命令） |
| **产品层** | `src/` + 人格 + 能力 + 代理 patch | 宿主上一个目录，**只读**挂进盒里的 `/app/code` | 每次改进产品 | `deploy`（**每次翻转记账**） |
| **用户层** | 数据（卷） | 租户自己家里 | 用户自己 | 不动 |

⚠️ **加东西要同时想清楚"它是不是按人不同的"** —— 按人不同的东西**不许**放进产品层
（那会把"改一次"变成"改 N 次"，而且没有一处能看全）。

### 9.2 三步：造一版 → **先证明它起得来** → 翻转

```bash
bash scripts/build-tenant-code.sh                     # 造一版（**不碰任何在跑的东西**）
bash scripts/build-tenant-code.sh --verify <指纹>     # 🔴 **先证明它起得来**
bash scripts/build-tenant-code.sh --publish <指纹>    # 翻转（记账一行）
bash scripts/build-tenant-code.sh --list              # 有哪些版本 / 现在是哪个
bash scripts/build-tenant-code.sh --rollback <指纹>   # 回滚（也记账）
bash scripts/build-tenant-code.sh --current           # 只打印当前指纹（给别处读）
bash scripts/build-tenant-code.sh --prune [--yes]     # 收拾旧版本（**默认只看**）
```

🔴 **`--verify` 非有不可**：翻转之前**先真跑一个容器**、要它**自己报出这个指纹**。
**没有它，一次手滑就是所有租户的助手一起起不来。**
⚠️ 只有"**容器自报的那个指纹**"才证明**是这个挂载带进去的** ——
不真的起一遍，任何静态比较都不算。

**指纹只由内容决定**：同一份内容两次算出来必须**一模一样**；改一个字节必须变；
**算它的地方只有这一处**。
⚠️ 唯一例外是预审规则里那个**自指**字段（它记的就是这一版的指纹）——
算指纹时把它当**空串**看，构建那一刻才盖上 ⇒ **改规则一个字节 = 换一版**
（"母体升级"与"旧评级失效"都靠它）。

**翻转是原子换**：先建临时的再 `mv` —— 直接换软链会先 unlink 再建，
**中间那一瞬间 `current` 不存在**，而那一刻正好有容器重开的话，它挂一个不存在的路径 ⇒ 起不来。

**每次翻转记账**（一行：from / to / 为什么 / 谁）—— 这是主人拍板"归 `deploy`、
可以自己翻转"时点名的那一条。

⚠️ **旧版本不许顺手删**（**删了回滚那条路就断了**）：`--prune` 是**显式的**，
而且**默认只看**。它里面还有一条：`current` 是那条**软链**，**不是一版** ——
它**永远不许被当成一版删掉**（删了之后容器重开会挂到一个不存在的路径上，
而容器运行时会把那里**建成一个空目录**）。

### 9.3 容器**自己**重开（那帧不带内容）

- 宿主经**已有的那条通道**发一帧 `reload` —— **里面一个字段都没有**。
  它是**通知，不是远程执行口**（宿主本来就已经决定容器跑什么代码）。
- 容器**先把手上那一轮说完**再退（读它自己写的状态），退完由单元把它拉回来。
  ⇒ **不需要 root、不需要重建容器、不会切断正在说的话**。
- ⚠️ **不许用 root 去动别人的容器**；翻完也不用重启任何东西 ——
  宿主发现指纹不同就会叫它重开。

### 9.4 "这一台跑的是哪一版"必须看得见

- `--list` 打出**所有版本**与**当前那个**（当前用箭头标出来）。
- 宿主**如实报每台盒子自报的指纹**。
- **一条命令核同版**（收尾时跑一次，几秒钟）：

```bash
bash scripts/check-tenant-code-drift.sh
```

  退出码：`0` 同版 · `1` **落后**（要 build / verify / publish）· `2` 环境不具备。

🔴 **为什么非要这么较真**：发布出去的那一版比某一刀还早 ⇒ 盒子那份代码里
**少一条内部口** ⇒ 宿主把"建 app"转给盒子、盒子回 404 ⇒ **盒子里的用户建 app 全失败**
（看到的是"**你那台刚才没应，等会儿再试。**"），**而宿主那一份是好的**（一验就分得清）。
⚠️ 那个比较**本来就有**，但它跟一大堆容器检查绑在一起 ⇒ **不常跑** ⇒ 才被漏过去。
⇒ 单独拎出来一条几秒钟的命令，**收尾时跑一次**。

### 9.5 两条踩过的坑（动手改这一块之前先看）

两条都是"**两端各自都对、合起来不收敛**"：

1. **单元里挂的是那条软链本身**，**不是**解引用之后的某个指纹。容器是**创建那一刻**
   解析它的，而每次重启都会重建容器 ⇒ **翻那条链才对新容器生效**。
   ⚠️ 写死指纹 ⇒ 宿主看见的永远是旧版 ⇒ 一直叫它重开 ⇒ **来回退**。
2. **"当前是哪一版"永远现读**（一次读链 + 一个小文件），
   **不许在开机时读一次存起来** —— 缓存会在翻转之后**变成假话**，
   而它正好用在"要不要叫那台重开"的判断上 ⇒ 同样**来回退**。

⚠️ 还有一条：单元模板**只能在 root 身份下才写得到别人家里**，所以
"以 root 跑一次、再去别人家里看结果"那种验法**等于没验** ⇒ 渲染抽成了**纯函数**
（`create-tenant-pool.sh --render` 写 stdout），判据对着它跑 `systemd-analyze verify`。

## 十、备份 / 恢复 / 回退

### 10.1 照状态清单走

**哪些是"用户的状态"、哪些可抛弃，只有一处说法**：
[`../dev/78-OUT-OF-REPO.md`](../dev/78-OUT-OF-REPO.md) §一。
**备份 / 迁移 / 删除都照那份清单走；容器里其他一切可抛弃。**

那份清单分两类：

- **在仓库里的**：代码与文档 —— **git 就是它们的备份**。
- 🔴 **不在仓库里的机器状态**（这才是备份真正要管的）：
  数据目录（事件流 / 记忆 / 会话历史 / 审计 / 租户表 / 钥匙 / 凭据文件）·
  `~/.dsh/**`（agent 自己的 profile 与凭据）· frp 隧道配置（**里面有密钥**）·
  发布签名那份（`~/.hupo/release-signing.env` ＋ keystore）· 开机完整性清单 ·
  宿主上那份 nginx 配置（仓库里有一份**逐字节照抄**的抄本，漂了要能被查出来）。

⚠️ **`data/` 与 `*.jsonl` 不进 git**（`.gitignore` 已排除，**别改**）：
那里面是**发生过什么**，而且可能含凭据。它进 git 就等于把"状态"和"代码"混成一份，
而且一旦提交**再也收不回来**。

### 10.2 三条纪律

1. 🔴 **含密钥的那几样，备份必须加密**（`~/.dsh/.credentials.yaml` · `<数据目录>/creds.yaml` ·
   语音那三样 · frp 的密钥 · 发布签名）：
   **不许进任何会显示给别人的地方，也不许写进日志**。
   口令文件与备份仓库**不在同一块盘**（两个都丢才算真丢）。
2. 🔴 **没演练过的备份不算备份。** 演练要**真做**：还原到一个**临时目录**、
   **逐文件解析**、并**比对事件条数与最大编号**。
   ⚠️ **"逐字节一致"这个闸门不能松** —— 它同时验了**备份、迁移、和"密钥没被换掉"**三件事。
3. 🔴 **恢复路径不能依赖助手。** 最坏情况是"必须有人登机器手工回退"，
   而**这台机器只有主人一个人类** ⇒ 必须有一份**不用助手**的恢复步骤，
   而且**主人得被告诉过这条路径**。
   （原话：**"修理工住在要修的房子里"** —— 能修它的助手正是这个服务的一部分，
   它连不上、也起不来。）

**删除**：走"**收起 / 回收站 / 真删**"三段，**删前必须列清单**
（用户自己那条见 §七；那一屏会先把"会没掉什么、没法撤销"列出来再确认）。

**备份连续失败要主动开口**（不能只在日志里躺着）。

### 10.3 ⚠️ 今天的缺口（如实说）

**仓库里没有备份脚本，也没有演练记录。** 这条路上现在只有规范（[`08-SPEC.md`](08-SPEC.md) 的运行机制那一节）
与上面这份状态清单，**没有可跑的自动化**。在它有之前，"我们有备份"这句话是**未核实**的。

### 10.4 故障处理三条

| 情况 | 怎么办 |
|---|---|
| **服务端起不来** | 先看**为什么**：`systemctl --user status hupo-core --no-pager` 与 `serve.log` 末尾。多半是**开机清单对不上**（`strict` 文件刚改过还没重建）⇒ 照 `verify-integrity.mjs` 那条 `sudo` 命令重建，再 `scripts/restart-core.sh`。**不是清单的问题** ⇒ `bash scripts/rollback.sh`（`git revert` 那一次）→ 确认存活 —— 见 §五。⚠️ **别拿 `systemctl --user stop` 去清 scope**（§三）。 |
| **客户端改坏了** | 重新构建**上一个版本**并上传（**不要碰服务**）：`git revert` 客户端那一次改动 ⇒ `bash scripts/deploy-web-v2.sh`。⚠️ 部署脚本**自己会先跑两道硬闸**，所以"闸是红的"这种情况**根本到不了线上**（线上仍是上一版）。 |
| **盘满** | 它是**唯一会永久丢数据**的路径：落盘失败**必须上抛**，而且**要写清谁接**（只写上抛不写谁接 = 盘满 → 崩 → 重启 → 再崩）。今天磁盘那几档**只告警、不自动清、不拒活** ⇒ **人要自己上去清**。先看巡检报的是**哪一档**、**哪一块盘**、是**空间**还是 **inode**。清完确认服务还在。 |

**回退**：见 §五（`scripts/rollback.sh` = `git revert`，**不读助手产出的文件**）。
**产品层那一侧的回退**是 `build-tenant-code.sh --rollback <指纹>`（§九）——
它同样只翻那条链、记一行账，**不重启任何东西**。

## 十一、监控与告警

### 11.1 盯哪几个读数

每一个都来自一个**真在跑**的模块：

| # | 盯什么 | 谁在看 / 为什么 |
|---|---|---|
| 1 | **磁盘用量 / inode / 文件描述符** | `src/disk-watch.js` 周期采样，按 `src/disk-grade.js` 那张表分级。今天**只分级、只告警，不改运行时**。⚠️ **算不出来就说"算不出来"**：拿不到用量回 `unknown`，**绝不许当成"没事"**（那就是"看起来有闸"）。每一项**各自独立**：一项读不到，不许把整趟丢掉 |
| 2 | **内存占用比（准入）** | `src/admission.js`：每次要接新句子之前判一次；开机横幅里报"**现在算不算得出判据**"。⚠️ **本机算不出来**（每层 `memory.max` 都是 `max`）—— 横幅**如实写**，不许静默放行 |
| 3 | **"手上还有没有没说完的话"** | `data/status.json`（每秒写）。它既是重启脚本"等它说完"的依据，也是"它卡住没有"的读数（**状态陈了**就说明服务可能已经不在了） |
| 4 | **手上还有哪些活** | `src/worklog.js` 逐件落盘：**一件活只有三种结局**（做完 / 被明确取消 / 挂着等），**没有"消失"** —— 被硬杀、超时、进程退了，都要**落一条收口**。重启后**逐件**答得出"还在 / 已停 / 做完了" |
| 5 | **进程死了 / 崩溃环** | 单元会把它拉回来；崩溃环里"**先修原因 → `start` 弄活 → 最后才用 `restart-core.sh`**"那条顺序见 §三 |
| 6 | **完整性清单的状态** | 开机横幅那一行：**对上了** / 有"**只报不拦**"的动过 / **还没启用**（清单不在）。⚠️ 报成"OK"而其实没启用，就是"看起来有闸、其实没有"—— **比不设更坏** |

**收工也要看得见**（`src/shutdown-budget.js`）：收工的每一步都有上限，**整条也有**。
两条纪律：

- 🔴 **不许为了快就把正在跑的活砍了**（说出去的话要有终态）⇒ 上限到了**不是"把它掐掉"**，
  而是**如实记一句"这一步没等完"**，然后继续往下收；也**不**去"强拆连接"
  （那会让在飞的请求**静默消失** —— 而"静默丢弃"正是这一条要防的）。
- 🔴 **每一步都要点名**（人话，不是对象）：卡在哪一步要写进**日志一行**，
  下一次谁看日志都能一眼说出来。
- 只要前面有一步没等完 / 抛了 ⇒ **不许说"这次是好好走的"**（下次开机的横幅会如实写"没善终"）。

### 11.2 告警必须说人话

- 监控的产物**不是日志，是给主人看的一句话**。
- **内部名不许出现**（工作区 / 口令 / 连接 / 客户端 / 云端 / 工具名 / 模型……）——
  **这是缺陷，不是文风问题**。
- **数值只住代码与 [`08-SPEC.md`](08-SPEC.md) 的阈值总表**；面向人的那句话**只有话，没有数**。
  例：盘满那一档对用户说的是一句"**这台现在存不下了，先不接新的话 —— 等一会儿再试，
  你现在这些都在**"（规则那一层给**每一档**都配了一句人话）。
- ⚠️ **"每次都响的报警等于没有报警"**：把一个**正常运行就会变**的东西放进 strict / 告警里，
  只会把人的注意力训练成"**忽略这一栏**"。⇒ 那种条目要么**只报**、要么**干脆不进清单**
  （这个取舍写在 `src/integrity.js` 里，连同它**放弃掉了什么**）。
- 判据与阈值全文在 [`08-SPEC.md`](08-SPEC.md)；这一份只讲"**盯什么、怎么说**"。

## 十二、探针纪律

**一、不许拿真实的 id / 名字去打"会造成破坏"的那几条口**（删、清空、改名、复制、卸载……）。

要对比路由在不在，**用不存在的 id**：活着的话它会回一句**人话**，死了才是 404 ——
**两种都答得出"这条口在不在"，但只有前者不会动到他的东西**。

⚠️ 这条是**拿主人的数据换来的**：核"新加的那条口到底上没上"时，拿主人桌面上**真实的**
那个小程序打了一次删除口 —— **把它删了**（软删：整包挪进回收区）。所幸登记里没有对话、
制品与工作区整套还在，**原样搬了回来**。⇒ 破坏性口的探针**只用假 id**。

**二、"重启之后要核进程起得比文件新"。**

改完东西重启一次，**读它的输出与退出码**，再核对外那个版本读数或开机横幅 ——
**别把输出丢进 `/dev/null`**，否则"**改了却没生效**"和"**根本没重启成**"看起来一模一样。
（那一次重启被开机完整性挡住了，而输出被丢掉，差一点读成前者。）

**三、改文件每一步都要断言"旧的那段真的在"。**

用"把这一段替换成那一段"而**不断言旧的那段真的在**，会在**锚点变了**的时候
**静默什么都不做**。这条也是拿事故换的：一次替换少了一行 import，重启当场报错，
线上停了一会儿（单元在自动重启里反复失败 —— 反复失败比干净地停更难看）。
⇒ 纪律：**改完立刻做语法检查 ＋ 起一遍**；**重启脚本必须读退出码**
（这条规矩当天就救了一次）。

**四、闸别带着管道跑。**

有的闸会**真起一个 agent 进程**去抓系统提示；外面套 `| tail` / `| grep -q` 时，
**读端提前收工**会让它内部那一路撞 **broken pipe**，于是某几条检查**假红**
（屏幕上写着"系统提示里找不到"，其实那份提示好好的）。
⇒ 跑闸就**原样跑**（红绿都看全）；要留证据就 `> 文件` 再读文件。
⚠️ 判据内部也一样：`printf … | grep -q` 这种写法自带同一个竞争
（一找到就退出 ⇒ 写端撞 broken pipe）—— 能用 bash 自己的模式匹配就别开管道。

**五、把关键参数写死的旁路工具不算验收。**

见 §四的 **V13**：node 探针 / 手打 curl **绿了，只说明那个工具绿了**。
**凡是客户端自己算出来的东西，闸要打在客户端这一侧。**

**六、判据自己也会有"只在某个状态下成立"的假设。**

一条判据如果默认"还没装"（或"盘是空的"、"这是第一次"），**那种假设一过期，
好系统就开始报红**，然后下一个人会去**把闸关掉**。
⇒ 判据要么写成对状态无关的，要么把"跳过"**明写出来** ——
**跳过的那几条会明写"跳过"，不许静默算绿**。

**七、验不了，常常是"没给它一个能验的形状"。**

几条最要紧的判据一开始被写成"要等签字装完才验得了"，其实只是**工具少一个测试入口**。
多花的那一点，换来的是"**整套模型会不会作废**"那一条能在**签字之前**就有答案。
⇒ 碰到"这条验不了"，先问一句：**是它真验不了，还是我没给它一个能验的形状？**
