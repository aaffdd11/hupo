# 01 · 这是什么、给谁、能做什么、为什么

> 这一份回答"它是什么、给谁、今天能做什么、为什么长这样"。
> 判据与契约不在这一份（去 [`08-SPEC.md`](08-SPEC.md)）；证据在 [`../dev/`](../dev/)。

---

## 一、一句话与唯一承诺

**一句话**：**一台哑终端 ＋ 一台只属于他的主机 ＋ 一个调度器** ——
用户只看见**一个聊天窗口**和**一张桌面**。

**唯一承诺**：***你说的事它真会去做，不只是陪聊。***

**形态**：聊天浮窗 ＋ 桌面图标墙（一格 ＝ 一间 ＝ 一条对话）。**不是**应用商店、**不是**自动化工具、
**不是**搜索引擎。

**独特之处**：能**记住**、能**自己办**、办完**回来说** —— 而且这三件事
**用户都要能验证**（看不见的记忆等于没记住）。

---

## 二、给谁（十个第一人称用户走查）

设计不是拍脑袋来的：先做了**十个第一人称的用户走查**，每个人的原话与"一周后他还用不用"都在
`git show f93f296:docs/ux/0*.md`。

| 谁 | 他自己的话（一句话） | 一周后的结论 |
|---|---|---|
| 主人（项目出资者） | 「主动点桌面生成物的次数：**0**」 | 生成物没人点 ⇒ 做完要**主动说** |
| 后端工程师 | 「我会因为它**说了做不到**而放弃」 | 不假装能做 |
| 小饭馆老板 | 「话发出去了，**没有任何一样东西是活着的**」 | 等待期必须有"活着"的信号 |
| 通勤的人 | 「**6 秒**没第一个字，上划杀掉」 | 首句要快 |
| 家长 | 「我不会原谅它**把我说过的话说错**」 | 准确性优先于流畅 |
| 六十八岁退休教师 | 「**就在登录页放弃**」 | 登录页是放弃点 |
| 设计师 | 「我做出来是要给人看的，它给我的东西**我发不出去**」 | 产出要能带走 |
| 写作者 | 「**找不到**半小时前写的那一段」 | 历史要翻得到 |
| 工地的人 | 「界面**把发不出去显示成发出去了**」 | 失败与成功必须长得不一样 |
| 用平板的人 | 「一遍一遍地，**桌面被抹掉**」 | 状态要留住 |

## 三、他们放弃在哪（五条致命问题）

十个人里，**八个**的放弃点指向同一件事：**"它活着没有 / 记着没有 / 说的是不是真的"用户无法验证，
而系统自己也不说。**

| # | 致命问题 |
|---|---|
| **★1** | **发出去之后没有"活着"的信号** —— 十个人里**十个**都提到等待期的空白 |
| **★2** | **记忆不可验证** —— 黑盒记忆 ＝ 默认"没记住" |
| **★3** | **失败与成功长得一模一样** |
| **★4** | **"工作区"十个人里零个发现**（内部词直接暴露） |
| **★5** | **看不见的边界** ⇒ 用户不敢说真话 |

---

## 四、五个根因（**四个都是"系统没说话"**）

| 根因 | 是什么 |
|---|---|
| **R1** | 按下发送到第一个字之间**是空的** |
| **R2** | 不知道"**我在哪一层 / 谁在说**" |
| **R3** | 一切都是**静默**的 |
| **R4** | **内部词汇直接暴露**给用户 |
| **R5** | 把**手机比例当普适前提** |

⇒ 结论：**把省下来的每个字，花在"让用户知道发生了什么"上。**

## 五、五条产品原则

| # | 原则 | 它挡住了什么 |
|---|---|---|
| **①** | **系统做的每件事都要说出来** | ★1 ★3（沉默＝用户以为死了） |
| **②** | **看不见的东西等于不存在**（记忆必须有可见出口） | ★2 |
| **③** | **不假装能做**（沉默优于编造） | ★5 · 后端工程师那条 |
| **④** | **不许要用户学新东西**（内部词一个都不许上屏） | ★4 · R4 |
| **⑤** | **可防错 > 可恢复**（删之前先把要删的摆出来问一次） | 误删 |

## 六、它今天能做什么（**能力全景**）

> **"包含现有功能"就是这一节。** 一块一行；指针指向那一块的契约/证据。
> ⚠️ 每一条都**以代码为据**；**还没通的**在 [`04-ROADMAP.md`](04-ROADMAP.md) §四，不在这里充数。

| 那一块 | 今天真能做 |
|---|---|
| **进来** | 手机号 ＋ 验证码（⚠️ 本部署的验证码通道状态见 `04` §四）· 密码登录 · 令牌续期与撤销 · **注销**（不可逆，先身份再确认） |
| **说话** | 按一下那颗圆圈说话 ⇒ 识别回来的字**直接长在底下那个真输入框里**（他也能点进去改）· **按停就发** · 说到上限**接着开下一轮**、字一个都不清 · 第一次按失败**自动再试一次** · 在听的涟漪 |
| **打字** | 同一个输入框打字（语音与打字是**同一格**）· 草稿本机留着 |
| **它答话** | 一条**有序时间线**（取号/收口/补发/去重）· **看得见它在做** · 会答话、说话像它自己（人格硬规则）· 重启还记得 |
| **长活** | 默认放后台 · **先说一声** · 做完/失败都**主动提醒** · 随时能问"那件怎么样了" · 一张"正在干的活"清单 · **不设时长限制** |
| **桌面** | 一格 ＝ 一间 ＝ 一条对话 · 切房间**不重连** · 在建/在做两种状态 · 做完自己变回来 · 壁纸与偏好**跟着账号走** |
| **小程序** | 从桌面加号建 · 助手在对话里**当场做** · 能装（fork）· 能上架 · 发现有 · **打开时一次把权限问完** · 每一格自己的 **SQLite** · 能连**声明的**网站 · 能**问它的助手** · 能**定时任务** · 能**拍照** · 有外观基线（细节在 [`09-APPS.md`](09-APPS.md)） |
| **出图 / 出片** | 聊天里说一句 ⇒ 助手自己调（**入口不加按钮**）：**图片**（Seedream）与**视频**（Seedance）各一条路；视频是**异步**的，成品回他问的那一间。⚠️ **真上游读数还没拿到**，见 `04` §四 |
| **念出来** | 网页走设备合成器 · 安卓走系统 TTS |
| **记账** | 工时账：字段冻结 · 只追加不原地改 · 出口是**一段能粘进微信的话**（不是表） |
| **多租户** | 一人一台盒子；盒里的助手**真能自己跑命令**；产品层只读挂载、空闲自己重开 |
| **口袋里的那一个** | 安卓包（原生录音/开麦/TTS 是手写平台通道，不是 pub 插件）· 网页同一套界面 |
| **带走** | 对话导出（一段能粘走的话）· 回收站（软删）· 源码包与参赛材料的下载 |

## 七、产品声音（它怎么说话）

**登录页文案**（定稿）：

> **琥珀**
> 你说的事它真会去做，不只是陪聊。
> 所以这道门只有你能开。
> 〔密码〕 装机器时给你的那一串
> 〔打开〕

配三件机制：**连不上不清令牌** · **令牌到期自动续** · **忘密码的恢复写在登录页上**。
真正的缺陷不是"缺一个找回密码的页面"，而是"**每 30 天要人帮一次**"。

**说话纪律**（人格那一层，判据在 `08` §十二）：**短、白话、只说他要在意的**；
第一句先应一声、不给结论；不许留客式追问；不许说要做然后不做；不许提内部词。

## 八、命名与用词纪律

| 规矩 | 内容 |
|---|---|
| **隐喻** | 一件事 = **一本本子**（不是文件夹 / 应用 / 频道 / 房间） |
| **永久禁用词** | **「工作区」**（界面上出现即**缺陷**） |
| **必须换的词** | 「口令」→ 密码 · 「进去/登录」→ 打开 |
| **不许泄入界面** | 工具名 · 搜索 · 上下文 · 系统提示词 · 阶段内部名（过程要翻成人话） |
| **名字从哪来** | 系统提议、**只用用户自己说过的词**、可随时改；重名用他自己的话区分 |
| **产品名** | 界面上的名字是**「琥珀聊天」**；「琥珀」是品牌名 |

完整清单与判据在 [`07-APPENDIX.md`](07-APPENDIX.md) §二（词表在那道 `test/unit` 闸里）。

## 九、过程可见性（看得见它在做）

**两档**（`D7`）：

| 档 | 给谁 | 是什么 |
|---|---|---|
| **在做什么**（默认） | 所有人 | 一句人话（"正在查资料"） |
| **推理原文** | **只有主人**，默认关 | 它的原话推理；**只有服务端能决定发不发**（不是客户端藏） |

两条硬约束：**不承诺时间**（"大概两分钟"是假话的来源）· 必须有**乱序保护与超时收敛**。

## 十、设备优先级

**主目标设备是手机**（浮窗贴底、可拖可收）；**主开发设备是平板**（宽屏是首要验收场景）。
两样都要能装、都能看。**内容列限宽、居中**（值住代码）。

---

## 十一、明说做不到的（边界）

| 不做 | 为什么 |
|---|---|
| **不代执行** —— 登录、提交、付款的最后两下由他来 | 出事要有人负责；只做"准备到最后一键" |
| **不假装记得** —— 翻不到就说"我去翻翻" | ★2 |
| **语音没网 / 没麦** ⇒ 明说，给打字退路 | 手机上没有第二条命 |
| **不会拼音的人**按设备如实写（网页 / 安卓各有各的实话） | 不许一句"支持语音"糊过去 |
| **横屏没做好的地方**写"已知"，不装作没有 | ★5 |

## 十二、可验收的体验判据

> 这些是"像不像话"的判据，不是功能清单。**判据的全文与实现约束在 [`08-SPEC.md`](08-SPEC.md) §六。**

1. 四种状态（排队 / 发出 / 确认 / 失败）**视觉上分得开**
2. **失败有自己的长相**，并且**有重发入口**；收起态也看得见失败
3. 200ms 内没有服务端回应 ⇒ **本地先应一声**
4. 触控目标 **≥ 44**
5. 内容列**限宽、居中**
6. 界面上出现**内部词 = 缺陷**（词表闸）
7. 写死的字号必须走主题（**写死尺寸 = 缺陷**）
8. 浮窗高度用**绝对档位**；转屏要重置
9. **新增助手消息触发的高度变化 = 0**
10. 甩能关；收起态有带字的展开入口
11. ⭐ **"第一次成功"必须他一个人走完**（不靠别人站旁边）
12. 语音的**句子级命中率不达标不上线**（语料与装置在代码里）
13. 装饰层要**看得见**（判据打在像素上，不是"代码里有"）

## 十三、方法论（这几条换来的教训）

| # | 教训 |
|---|---|
| **1** | **先跑用户体验走查，再做工程规划** |
| **2** | **每轮独立评审，而且评审必须去代码里核**（不许拿文档当事实） |
| **3** | **前提性事实必须复核**（第一轮评审推翻的三条"承重"论断，全是在代码里证伪的） |
| **4** | **拍板必须落文件**（没落文件的"定了"等于没定） |
| **5** | **不写"以后再说"** —— 要砍就明说砍了 |
