## 二、界面用词纪律

### 2.1 🔴 这是缺陷，不是文风问题

界面上出现内部词，**不是"读起来不专业"，是"用户读不懂这句话"** ——
而走查里最一致的失败恰恰是这个（`01-PROJECT.md` §三 的 ★4 与 R4：
「工作区」这个词**十个人里零个发现**，有人读完以为"这是不是流氓软件"）。

理由不是审美：**用户读不懂一个词，就等于系统没说过那句话**；
而"系统没说过"在这个产品里会直接变成"它活着没有 / 记着没有"的怀疑
（`01-PROJECT.md` §四：五个根因里四个都是"系统没说话"）。

⇒ 所以这条纪律**由闸强制，不由人提醒强制**。

### 2.2 它由哪道闸强制

| 闸 | 在哪 | 它扫什么 |
|---|---|---|
| **禁用词扫描（硬闸）** | `v2/apps/mobile/test/unit/forbidden_words_test.dart` | ① 手写的那份**"必须干净"文案清单**（含直接展开数据源的那些）逐句 `scanForbidden`；② 一份**源码级**判据：`lib/services/chat_controller.dart` 里 `_lastError` 那几行不许含「服务器」；③ **整棵树**扫描：字符串字面量 `'正在听'` **只许**出现在 `lib/models/hearing_words.dart` |
| **词表本身** | `v2/apps/mobile/lib/models/forbidden_words.dart` | `forbiddenWords` 表 ＋ `scanForbidden()` / `hasForbidden()`。**表里每一条都必须写"为什么"**，有判据钉着（不然下一个人会把它加回来） |
| **跑它** | `bash scripts/check-client.sh` | `test/unit` 是硬闸；`accessibility_test.dart` 是另一道硬闸 |

⚠️ **"扫的是字符串字面量"很重要**：注释里出现"工作区 / 连接 / 模型"**不算违规**
（那是对着下一个人说话的），违规的是**会画到屏幕上的那一份**。

### 2.3 五档处理（**永久禁用** / **必须换** / **不许泄入界面** / **条件禁用** / **不许用**）

| 类别 | 词 | 处理 |
|---|---|---|
| **永久禁用** | **工作区**（图标名 / 标题 / 提示 / 空屏 / 报错，一处都不许） | 换"本子"或直接说他在做的事（`D1.1`） |
| **必须换** | **口令 → 密码** · **进去 / 登录 → 打开** | "口令"让人想到"当兵的站岗"；"进去"读出来是"提交"（`D2.2` / `D2.3`） |
| **不许泄入界面** | 工具 / 搜索 / 上下文 / 系统提示 / 具体工具名（`web_search`、`bash`、`subagent`…）· 客户端 / 云端 / 服务器 / 调度器 / 时间线 / 作用域 / 会话 / 模型 | 过程展示**必须翻成人话**（工具行映射表在 `lib/models/tool_row_words.dart`；回答里提内部词违反人格硬规则第 6 条） |
| **条件禁用** | **「正在听」** | **只在真的在录音时才可以**（`D5.13`）。唯一合法落点是 `lib/models/hearing_words.dart` 的 `hearListening`（只在 `Hearing.listening` 为真时画），**由上面那条整树扫描钉死** |
| **不许用** | 系统编号（"第 1 个" / "序号"） | 区分同名**必须用用户自己的话**（`D1.4`） |

### 2.4 🔴 词表今天有两个洞（如实记，别当它已经严丝合缝）

| # | 洞 | 证据 | 后果 |
|---|---|---|---|
| **1** | **设置页顶层那一行「模型设置」没进"必须干净"清单** | 字在 `lib/models/space_words.dart`（`settingsRowModel`），而 `test/unit/forbidden_words_test.dart` 的 `copies` 清单**没有它**（它列了 `settingsAppearance*` / `settingsClearDb*` / `settingsGrants*`，唯独没列这一条） | 而 `lib/screens/settings_screen.dart` 抬头那句注释写着"界面上**没有** `模型`…（词表硬闸会拦）" —— **那句话今天是假的**：`模型` 明明在词表里，那一行却不在被扫的清单里 ⇒ **页面在说假话**。⚠️ 这与 [`01-PROJECT.md`](01-PROJECT.md) §九 末尾那条"两个洞"是**同一件事**，改法与验收都在那一条上 |
| **2** | **词表里没有「连接」** | `forbiddenWords` 全表（`lib/models/forbidden_words.dart`）没有这个词；而 `lib/models/conn_state.dart` 的 `statusLine()` 画的正是 `'正在连上…'` / `'还没连上'` | 这两句**今天没被任何闸扫**（`copies` 那份清单里也列的是 `'网断了，我在等它回来'` 等几句，不是这两句）。注意：它**目前**只是没被覆盖，不是"已经泄进了界面" —— `连接` 这个词**没有**作为字符串出现在 `lib/` 的任何用户文案里（源码里的"连接"都在注释里） |

**为什么把洞写进手册**：这两个洞的形状是同一个 ——
**闸只扫"被登记过的字"**，所以**新写的一句文案，天然落在闸外**。
⇒ 这正是 `test/unit/forbidden_words_test.dart` 里那句注释的意思（"新加的句子必须列在这里，
没进这份清单的句子 = 没验过"）。**修法不是加两个词，是让"新文案出生就进闸"变成结构上必然。**

## 三、今天已知的坑

> 每条三样：**现象 · 根因 · 现在怎么处理／为什么先不动。**
> 素材来自一次四路只读清点（[`../dev/224-V3-PROJECT.md`](../dev/224-V3-PROJECT.md) §六）**并逐条回代码复核**；
> 复核后**推翻或收窄的**在条末标出来。

### 1. 开发期的门是开着的

- **现象**：任何手机号 ＋ 一个环境变量里的固定验证码都能进。这不是上线形态。
- **根因**：`HUPO_DEV_CODE` 是**开发期**的入口，真短信通道还没接；而它是**可选设置**，
  设置与不设置在开机横幅上是两句不同的话（`src/config.js` 的 `devCode`、`src/serve.js` 的横幅）。
- **现在怎么处理**：**先不动**，因为关掉它之前必须先接真短信（否则没人进得来）。
  ⚠️ **接手的人不要顺手把它当成"漏洞"去关** —— 关掉等于把门焊死。真实的现状要用**现跑**确认，不许照抄文档。

### 2. 页面在说假话（禁用词那道闸的两个洞）

- **现象**：设置页顶层写着「**模型设置**」；而 `settings_screen.dart` 的注释自称"界面上没有 `模型`"。
  另有 `conn_state.dart` 那两句连接态文案**不在任何闸的覆盖里**。
- **根因**：禁用词闸**只扫"登记过的字符串"** ＋ 两处源码级判据，**不扫整棵树**（见 §二·2）。
  新写的一句文案，天然落在闸外 —— 闸看起来是绿的，洞是真的。
- **现在怎么处理**：**没修**（属"页面在说假话"那一类，`test/unit` 词表闸今天罩不到它）。
  修法见 §二·4：**不是补两个词，是让新文案出生就进闸**。判据必须落在 `test/unit`（纪律 3）。

### 3. 落地页在说假话

- **现象**：安卓那条还写着"语音那几样（说话输入、录音、朗读）**还没进包**"，
  FAQ 还写着"有语音吗？**还在做。现在打字就能用**"。
- **根因**：落地页那几句话住在 `lib/models/landing_words.dart`，它**与功能落地不同步**：
  网页开麦、安卓原生开麦 / 录音 / TTS 都已经在跑（原生那几件是**手写平台通道**，不是 pub 插件）。
- **现在怎么处理**：**没修**。⚠️ 它与"关于"那一份是**两处各自写了一份事实**，
  所以一处更新、另一处不动 ⇒ 必然漂。修的时候要让它们指向**同一处**（而不是各改一句）。

### 4. 「我拉不到」被画成「现在还没有」

- **现象**：发现页（Discover）在拉取失败时显示的是**空态那句话** —— 也就是"现在还没有"。
- **根因**：客户端这三层各自把失败咽掉，最后变成"空数组 = 没有东西"：
  `lib/services/api.dart` 的 `discover()` 在**非 200** 与**异常**两种情况下都 `return const []`；
  `lib/screens/chat_screen.dart` 的 `_loadDiscover()` 在没令牌时也 `return const []`；
  `lib/screens/discover_screen.dart` 的 `_failed` 其实是**死字段** ——
  它唯一的赋值是 `_failed = got.isEmpty && _failed`，右值永远是它自己的假值，
  **永远为假**，所以那个"拉不到"的分支从不画。
- **现在怎么处理**：**没修**。⚠️ 这一类是**最贵的一种界面缺陷**（`01-PROJECT.md` 五条原则第 ③ 条：
  不许假装；"失败与成功长得一样"在走查里排 ★3）。修法是让"拉不到"**有自己的那句话**，
  而 `_failed` 那类字段要么接上、要么删掉（留一个永远为假的字段就是下一个人的地雷）。

### 5. `tool-fs` 关不掉写入的一半

- **现象**：替小程序跑的那一轮（"限定档"）**仍然写得了那个工作区里的文件**。
- **根因**：`tool-fs` 在 DSH 里是**一整块**（读与写在一起），这一层只能做减法（`disabled: true`），
  **关不掉它一半**。
- **现在怎么处理**：**已文档化的缺口，不是待修 bug**。三条防线照旧：
  那一轮 `cwd` 只能是**那个小程序自己的那一间**；跑完要核工作区有没有被动过；
  要彻底只读**得另起一个 DSH profile**（而 `~/.dsh/profiles/**` 是开机清单里的 `strict`，要主人点头）。
  依据：`v2/services/core/hupo-app-agent.yml` 头顶第 ③ 条。

### 6. 别的会话 / 别的入口没接的几处

- **现象**：主人的那一份（没有盒子那台）问话那条路**没接**，会如实回"这台设备上还没接上问话那条路"；
  小程序定时任务与"问它的助手"**租户侧一律不接**。
- **根因**：这几条路要花**那个环境的钥匙**（花在他自己的盒子里），而主人那台既没有盒子、本机也没有那个代理；
  租户那半的房间名取不到。
- **现在怎么处理**：**已文档化的缺口** —— 关键是**它如实说**（不是静默失败）。
  见 `v2/services/core/src/app-ask.js` · `v2/services/core/src/server.js`（`askAgentFor`）。

### 7. 「问不上」那句话永远不会出现

- **现象**：`waitingRetryFail`（"刚才没问上。等会儿再按一次。"）在真机上**一句都不会出现**，
  而 `waiting_screen.dart` 抬头自称"问不上就说问不上"。
- **根因**：那句由 `WaitingScreen.retryFailed` 决定，而 `lib/main.dart` 里构造 `WaitingScreen`
  的那一处**从来没传这个参数**（它有默认值 `false`）⇒ 那个分支是死的。
- **现在怎么处理**：**没修**。它在"这个字段有默认值 ⇒ 忘了传也不报错"这一类里长大 ——
  ⚠️ 同类的字段在客户端还有几个（见本条 15）；修法是**给不传的情况一个能红的东西**，
  不是把默认值改成 `true`。

### 8. 单轮硬收口今天是关着的

- **现象**：agent 卡在一个不动的循环里 ⇒ **不会有任何收尾**，用户永远等不到那句"结束"。
- **根因**：主人 2026-10-04 明确要求"**不设时长限制，不设时长限制**"⇒ 默认被关掉
  （`src/dispatcher.js` 的 `TURN_DEADLINE_MS = 0`；`src/config.js` 里 `turnDeadlineMs=0` 会打一条说明）。
- **现在怎么处理**：**已知并接受**，但**代价要记住**：不变量 `N19`（"挂起必有超时，且必有合法收尾"）
  今天只剩"**进程死了**"那一条（agent 进程退出 ⇒ 服务端补一句实话收口）；
  **"进程活着、卡在不动的循环里"这一种没有收口**。
  ⚠️ 要收这一种，就得把那一枪再打开（`HUPO_TURN_DEADLINE_MS=<毫秒>`）；**别偷偷打开** ——
  那是主人的决定。开机横幅会自己把这一条打出来（`src/serve.js`）。

### 9. 写完没人调的模块：登记了，但没接线也没说砍

- **现象**：`v2/services/core/src/data-namespace.js`（数据命名空间边界）与
  `src/method-edge.js`（三条登记边）**在 `src/` 里零引用** —— 只有各自的测试文件引它们
  （`test/data-namespace.test.js` / `test/edges-three-kinds.test.js`）；
  `src/delivery.js` 抬头自认"**只建登记面，不建真传输**"。
- **根因**：这些是按契约先建的"那一层"，**还没有生产调用点**（92 §③ 阶段 5 的三条登记边在飞）。
  ⚠️ 而纪律 4 写着"**以后再说等于永远不做**" —— 现在的状态**正好是那句话的反面**：
  既没接线，也没明说砍。
- **现在怎么处理**：**保持原状，但它是账**：要么接线、要么在 [`04-ROADMAP.md`](04-ROADMAP.md) §七 明说砍。
  ⚠️ **不许把它读成"已经有了"** —— 判据绿 ≠ 它在承重位上。

### 10. 台账与事实漂了（数字不许有两处）

- **现象**：决策条数在几处写着不同的数（`AGENTS.md` 一个数、决策那一份自己另一个数、
  正文里实测又是第三个量级 —— 含全部 ID 又是第四个）。
- **根因**：**同一个数字写在两处** ⇒ 一定漂（这正是维护纪律 1 想防的形状）。
- **现在怎么处理**：**以实测为准，谁都不许再抄一份**。要判"多少条"，自己数（例如对旧那份决策表
  `grep` 出唯一 ID 再数）；**新手册只允许有一处提到条数**。
  ⚠️ 别照抄 [`../dev/224-V3-PROJECT.md`](../dev/224-V3-PROJECT.md) §六·11 里那三个数 ——
  它们是**当时**的三个读数，本条要的是"**别再有两处**"这条纪律。

### 11. 送人的那几张"账本表"落后于事实

- **现象**：`docs/dev/77-BLOCKERS.md`、`docs/dev/63-OWNER-DECISIONS.md`、`docs/dev/00-PROGRESS.md` §六
  这三张表都停在更早的日期，§六 那张甚至**还留着已经关闭的行**（它自己的规矩是"还一笔就搬走"）。
- **根因**：那几张表是**给人看的账本**，靠"每次收尾顺手改"维护；收尾一漏就停。
- **现在怎么处理**：**别照抄那两张旧表**；以重新核过的那一节为准
  （[`../dev/224-V3-PROJECT.md`](../dev/224-V3-PROJECT.md) §七），
  数字与进度以 [`../dev/00-PROGRESS.md`](../dev/00-PROGRESS.md) 为准。

### 12. 产品层与线上跑的代码可能不是同一版

- **现象**：线上那台盒子里跑的"产品层"（调度器 / 人格 / 能力那一份）可能落后于仓库这一版，
  而**两边都能正常跑** ⇒ 谁都不响。
- **根因**：产品层是**一处只读挂进容器**的目录，改它 = 写文件 ＋ 让容器重开；它**不会自己同步**。
- **现在怎么处理**：这正是不变量 **N29**（"这一台跑的是哪一版必须是看得见的事实"）要防的形状。
  判据脚本：`bash scripts/check-tenant-code-drift.sh`（**它红就是真红**，别当噪音）。
  ⚠️ 补不补是**部署期的决定**（P1/P2：助手只能提申请）。

### 13. 客户端还留着一批"暂时"与死代码

- **现象**：暗色那两档（暗 / 跟随系统）**暂时收起来**，token 一个字节都没删；
  桌面图标那枚**未读小点没人给它赋值**；`homeButtonIcon` 这个常量零引用；
  `SystemNotice` 只有定义、没有调用点。
- **根因**：多数是**有意留着**（各自有注释说明为什么），但**没有集中成一张单子** ⇒
  下一个接手的人分不清"这是故意的"还是"这是烂尾的"。
- **现在怎么处理**：**先不动**，但**每一个都要有注释指路**（已有的照旧；新加的死代码必须带一句"为什么留着"）。
  现状出处：`lib/models/appearance.dart`（暗色那一套的边界）·
  `lib/models/space_words.dart`（`settingsAppearanceDarkNotReady`）·
  `lib/widgets/app_desktop.dart`（那枚小点的注释自己写着"现在还没有人给它赋值"）·
  `lib/screens/chat_screen.dart`（`homeButtonIcon`）· `lib/widgets/bubbles.dart`（`SystemNotice`）。

### 14. 注释与代码相反 —— 专门骗下一个接手的人

- **现象**：`v2/services/core/src/app-ask.js` 里一句"主人那一份**还没接上**"；
  `lib/models/about_facts.dart` 说"原生包里**还没做录音**"（已经做了）；
  客户端还有按更早的形状叙述的注释（例如把内置应用说成"三个"）。
- **根因**：注释跟着**当时**的代码写，而代码往前走了；**没有任何闸扫注释**（也不该扫）。
- **现在怎么处理**：**见到就顺手改**（这是唯一一种"顺手改注释"被鼓励的地方）。
  ⚠️ 反面：`about_facts.dart` 那句不是普通注释 —— 它是**关于页文案的数据源**
  （原文就是画到屏幕上的那句），所以它属于 §三·3 那一条。

### 15. "有没有接上线"这件事，闸过去看不见（今天仍要人盯）

- **现象**：一个功能可以做到"**路径在、纯函数对、客户端喂假回执绿、手册也写了**"，
  而**接线本身是断的**（历史上真发生过一次：键名传错 ⇒ 那个口恒 404，四道闸全绿）。
- **根因**：那一组闸**各看一层**：路径表看路径、纯函数测试看函数、客户端测试看下游、
  手册看文档 —— **没有一道看"这两半的名字对不对得上"**。
- **现在怎么处理**：**已经补了一道**：`v2/services/core/test/server-wiring.test.js` ——
  它判"`serve.js` 传给 `createServer` 的**每一个键**，`createServer` 都得真的认"。
  ⚠️ **它只盯名字**：名字对、**值接错了**（把 A 的函数传给 B）它看不出来 ——
  那一半得靠各功能自己的判据（例如那个口自己的真回执用例）。
  ⇒ 新增"一条口"的时候，**同时**要问：它的名字有闸吗？它的值有闸吗？

## 四、会过期的实测事实

> 🔴 **这一节里一个数字都不许当结论用。** 每条写三样：**它是什么 · 怎么现跑出来 · 上次读到的量级（会变）**。
> 量级只用来"估"，**动手前必须现跑**。

| 它是什么 | 怎么现跑出来 | 上次读到的量级（**会变**） |
|---|---|---|
| **调度器常驻内存** | `ps -o pid,rss,etime -p $(pgrep -f "src/serve.js" \| head -1)` | 本机那次 **≈ 90MB 量级**（一个几千行 node 进程的常态） |
| **一个 agent 进程的内存** | 宿主上：`ps -o pid,rss,etime -p $(pgrep -f "hupo-sdk-server.yml" \| head -1)`；**盒子里**：`docker exec <盒子名> ps -o rss,args -C node` | 宿主上那次读到的是**几百 MB 量级**（根因是它要装一份完整运行时 ＋ 模型连接）；⚠️ **盒子里那一路本机没有 docker 权限，那次没量到** —— 要量就在有权限的地方跑 |
| **带界面的 DSH 宿主（`dsh web`）** | `ps -o pid,rss,etime -p $(pgrep -f "dsh web" \| head -1)` | 本机那次 **GB 量级、而且跑越久越大**（十几天的进程）⇒ 结论不是数字，是**"复用 DSH 要分清复用哪一层"**：带界面的宿主**别想塞进容器**，我们复用的是 `--profile sdk` 那一层 |
| **当前线上是哪一个构建** | `curl -s http://127.0.0.1:8020/api/version`（本机就是线上那台）· 盒子对不对得上用 `bash scripts/check-tenant-code-drift.sh` | 本机那次是一个 12 位十六进制指纹；**别抄它**，它每次部署都变 |
| **会话存储的布局** | `ls ~/.dsh/sessions/` · 再看一层 `ls ~/.dsh/sessions/<那一组>/ \| head` | **两层**：`--<项目>-<slug>--/` 是**组**，组里每一条会话一个目录，里面是 `session.lock` ＋ `session.v3.jsonl.zstd`。⚠️ **组目录本身永远不是清理候选**（那是别人的目录） |
| **"键是绝对路径编码"⇒ 换路径等于换账号** | 生成规则只有一处：`v2/services/core/src/prune.js` 的 `groupSlugFor()`（把绝对路径逐段用 `-` 连起来、前后各加 `--`）。要核对就 `node -e` 调它、或拿一个真目录名反推 | 例：`/home/deploy/hupo-workspace` ↔ `--home-deploy-hupo-workspace--`。**这就是不变量 `N21` 的来由**（同一用户必须一份 `DSH_HOME`；换路径 = 看起来像换了个人 ⇒ 记忆全断） |
| **会话记录占了多少盘 · 能清多少** | `node scripts/prune-sessions.mjs`（**默认只看不删**；真删要显式 `--apply`） | 本机那次：**上百份旧记录、几 MB 量级**。⚠️ 大小随用量涨；**默认不删是对的**（删掉就没了） |
| **工作区注册表** | `ls ~/.dsh/storages/` · `head -c 400 ~/.dsh/storages/workspace.json` | 一份 `workspace.json`（有序、持久；**对模型不可见**）＋ 一份 projcache |
| **证书什么时候到期** | **TLS 不在本机收** —— 真正那一跳在 VPS 上（仓库里 `deploy/nginx-w-stalkerai.conf` 是**抄本**，漂没漂用 `bash scripts/check-nginx-drift.sh` 看）。到期时间直接问线上那一跳：`openssl s_client -connect <公网那一跳>:443 -servername w.stalkerai.cn </dev/null 2>/dev/null \| openssl x509 -noout -enddate`；在 VPS 上还可以 `certbot certificates` | 上次读到的是**一个具体的年月日**（**会变**：certbot 会续）。⚠️ **本机读不到 VPS 的文件**（`/etc/letsencrypt` 不在本机）⇒ 要么问那一跳、要么上 VPS；**别照抄手册里任何日期** |
| **DSH 是 rc 这一档** | `grep -m1 '"version"' <dsh 安装路径>/package.json`（本机是 nvm 下那份 `@deepseek-ai/dsh`）· 或 `dsh --version` | 上次读到的是 **`0.1.5-rc.x`** 这种形状 —— **rc = 接口可能变**。⇒ 升级时**逐条复核**那些"已验证可用"的能力（§六），别默认它们还在 |
| **上游模型名的来源** | 图片：`v2/services/core/src/image.js` 的 `DEFAULT_IMAGE_MODEL`（可用 `HUPO_IMAGE_MODEL` 覆盖）· 视频：`src/video.js` 的 `DEFAULT_VIDEO_MODEL`（`HUPO_VIDEO_MODEL`）· 端点基址在各自文件里（同样可覆盖） | 代码里写的是**两个带日期后缀的名字**。🔴 **它们一定会过期**（上游按 `-日期` 发版）⇒ 这就是为什么它们**只住一处、而且能被覆盖**；换名字**只改那儿**，不许散进调用逻辑。⚠️ 今天这两个名字是**从第三方速查抄的**，**还没有一次真上游读数为它们背书** —— 真模型 ID 以控制台 / 第一次真打上游的回话为准 |

> ⚠️ **还有一类"会过期"要单独记**：**开机完整性清单**（`/etc/hupo/integrity.json`）里的 `strict` 条目。
> 改了那些受保护文件（人格 / `AGENTS.md` / `docs/handbook/**` / profiles）之后，
> **不重建清单，下次重启会拒绝启动**。怎么重建、命令长什么样：跑
> `node scripts/verify-integrity.mjs` 它自己会把那一条打出来（**里面是绝对路径** ——
> 本机没有系统 `node`，`sudo node …` 会撞"找不到命令"）。**别手打那条命令，照它打出来的粘。**

## 五、评审教训

> 两轮**独立**评审（各三席）各推翻了什么（结论级），以及从中挑出的两条最贵的教训。
> ⚠️ 评审**不是终审**：它给的每个引用也是断言，也要复核。

### 5.1 两轮各推翻了什么（结论级）

| 轮 | 评审对象 | 推翻的结论 |
|---|---|---|
| **第一轮** | **实施计划** | 计划说"五个基础设施项都是**承重的**"，其中**三条在代码里证伪**：客户端并不会丢掉第二个会话 · 淘汰计时器其实**会**重新计时 · 本地发言并不会被丢掉。⇒ 那一版的"承重"排序不成立 |
| **第二轮** | **工程文档** | 结论是"**方向对、细节错了一批**"：把一条**当天就已经被违反**的禁令当成"要维持的现状" · 若干处写着"必须写死"而**没有写死成什么** · 新测试文件在索引里**一处都没登记** · 有一处**批次顺序倒置**（下游的验收早于它依赖的那一块） · 有一处**自相矛盾**（同一件东西既列"本轮建"又列"本轮不建"）。协议也从 8 个字段**砍到 6 个**（其中一个字段的概念本身就错、两个没有数据源） |

### 5.2 最贵的教训之一：**前提性事实必须复核**（不许拿文档当事实）

**形状**：一段论证如果建在一个**没核过的前提**上，后面每一句都可以很严密 —— 而结论照样是错的。
文档里写着的"事实"**不是事实**，它是**某个人当时的一句话**。

**具体例子**：第一轮讨论里，有人拿"**本机 `sudo` 免密**"当论据，据此把一条安全结论改了方向；
而**本机实测 `sudo` 要密码** ⇒ 那条结论要翻。**代价不是多写一句话，是整套取舍建在沙子上。**

**它换来的做法**：手册里每一条断言都要能**指到代码或测试**；指不出来的**标"未核实"**。
⚠️ **包括手册自己**：见 [`../handbook/07-APPENDIX.md`](../handbook/07-APPENDIX.md) §3.3 ——
评审给的引用**也被复核推翻过**（行号对不上、"总数"数错）。
⇒ 引用别人的行号之前，**先打开那一行看一眼**。

### 5.3 最贵的教训之二：**结论对不等于归因对**

**形状**：结论（"这个东西没生效"）是对的，**归因**（"因为没人读它"）是错的。
照错归因动手 = **做无用功**：你会去新写一个本来已经存在的组件，
而真正的断链**还在原地**，症状一点不变。

**具体例子**："状态挂不上"那一次。当时的说法是
"`message/status` 推了，但 working / thinking / handoff **全库没有 UI 读**"。
**实测**：那个状态组件**是存在的，四态全都渲染**。
真正的断链在**取号**那一环：服务端推状态时带的是**空的消息号**，
客户端拿空号去查那条消息**永远查不到** ⇒ 状态永远挂不上 ⇒ 那个组件永远不显示。

⇒ **修法是修取号，不是写组件。**
**它换来的做法**：报一个"没生效"之前，先把**链条**一节一节量出来
（谁发出、带了什么、谁收到、拿什么去查、查到没有），**别停在第一处看起来可疑的地方**。

## 六、两份能力清单

### 6.1 DSH 已验证可用的能力（一条一行：能力 · 我们怎么用它 · 坑在哪）

| 能力 | 我们怎么用它 | 坑在哪 |
|---|---|---|
| **workspace 列表** | 一格格子背后那些有序、持久的工作目录＋会话 | **对模型不可见**；它**不是安全边界**（见下一条） |
| **session 日志** | 记忆本体：append-only、可 fork / replay / 压缩 | 它**按 root 分区**；键是绝对路径编码 ⇒ **换路径＝换账号**（§四 · `N21`） |
| **session 查询** | 跨会话与会话内全文检索（"我说过的那件事在哪"） | 检索到的是**原文碎片**，不是结论；别当成"它记住了"的证明 |
| **session 标题** | 桌面那一格的名字 | **永不进入模型输入** ⇒ 别指望它能左右它的行为 |
| **storage domain** | 有 schema 校验的键值存储（工作区注册表等） | 校验的是**形状**，不是**值对不对** |
| **jobs** | 长活：默认放后台、先说一声、做完/失败都提醒 | **待处理通知不跨宿主销毁存活** ⇒ 交付前先问一句"宿主还在吗" |
| **subagent** | 派活 / 一次性或可续的子 agent | 它的"做完了"**今天没有物证** ⇒ 在补上之前**不许当验收**（见 [`../dev/224-V3-PROJECT.md`](../dev/224-V3-PROJECT.md) §7.2） |
| **session 引用** | 跨会话带一份**有界、不可变**的快照 ＋ 固定警示 | 它是**不可信**输入：来自网页的正文可能带指令 ⇒ 记忆写入五道闸门里有专门一条挡它 |
| **system prompt** | 人格与角色那一层（`hupo-persona.yml` 等 patch） | 更新必须**追加在缓存历史之后**（`in-history`）⇒ 前缀才保持可复用；**插最前会把命中率打下去**（`08-SPEC.md` §十二 那条前缀不变量） |
| **指令链** | `AGENTS.md` 逐级下发（开机读的就是它） | 它是**受保护文件**之一 ⇒ 改了要重建开机清单，否则重启拒绝启动（§四 末尾） |
| **文件沙箱** | 约束 agent 能写哪儿 | 🔴 **只约束写，保留读** ⇒ **"关在某个目录里"不等于隔离**（`02-ARCHITECTURE.md` 那条最要紧的话） |
| **bash 沙箱** | 约束文件访问 | **网络与进程可见性不保证**；失败时**关闭**（fail-closed）⇒ 别把"它跑过了"当成"它跑成了" |
| **stdio JSON-RPC（`--profile sdk`）** | 调度器 ⇄ 一个真 agent 子进程那一跳，我们**只复用这一层** | `--patch` 是**全局选项**，必须写在 `--profile` **之后**；patch 里 `- id: <已存在>` 才是"改一个"，写成 `- insert:` 会**又加一个**（`hupo-capabilities.yml` / `hupo-app-agent.yml` 顶上各写了一遍） |

> ⚠️ **这一整表都挂在"DSH 是 rc"这个前提上**（§四）：**升级时逐条复核**。

### 6.2 已经踩过的坑（一条一行：坑 · 现象 · 对策）

| 坑 | 现象 | 对策 |
|---|---|---|
| **XML 注释里含 `--`** | ManifestMerger 解析失败，构建起不来 | 改措辞 ＋ **用 XML 解析器验一遍**（别靠眼睛） |
| **Release 包缺 `INTERNET` 权限** | release APK 没有网络，而 debug 一切正常 | 显式声明（**模板只在 debug / profile 声明**）⇒ 出包后**核权限**，别信"模板里有" |
| **`flutter doctor` 卡住** | 超过一分钟不动 | **放后台跑**，别占着这一轮 |
| **界面测试挂了会挂住** | 一轮跑很久不结束，用户看到的是"卡死并且不会改变" | **照常交付**，用真机确认；**不要为了哄旧断言拖延**（旧断言锁的是实现，不是产品要求） |
| **日志正常但屏幕空白** | 最难查的一种 | **不许只看日志下结论** —— 真机看一眼（Flutter web 把字画在 canvas 上，查 DOM 查不到文本） |
| **拿没复核的前提当论据** | 结论要翻 | **前提性事实必须复核**（§5.2） |
| **归因错就动手** | 白做一轮，症状不变 | **结论对不等于归因对**（§5.3）；先把链条量出来 |
| **名字对不上，四道闸全绿** | 一个功能"做完了"却一次都没通 | **接线闸**：`test/server-wiring.test.js`（它只盯名字，值接错还得靠功能自己的真回执判据） |
| **"以后再说"** | 半年后它还在原地，而所有人以为它在排队 | 要砍就**明说砍了**（纪律 4）；写不出验收的条目不许进路线图 |
| **同一份数字写两处** | 过一阵两处不一样，谁都不知道哪个对 | **一条事实只有一个家**（§三·10 就是这个形状） |
