## 一、三层 ＋ 一条旁路

```
L1 终端层   Flutter（Web / Android）＝ 一条有序时间线 ＋ 桌面图标墙 ＋ 小程序运行时
            「只上报事实，不做判断」
                 ⇅  HTTPS ＋ WebSocket（Bearer 令牌；两条 WS：/api/stream · /api/asr）
L2 调度层   v2/services/core（常驻进程，听 127.0.0.1:8020）
            取号 / 收口 / 补发 / 排队 / 撤回 / 未读 / 导出 / 长活提醒 / 准入 / 制品分发
            「不能有表达欲」（唯一例外：产品固定话术）
                 ⇅  stdio JSON-RPC（`dsh --profile sdk --patch <role>`）
L3 工作层   一个会话 ＝ 一个真 dsh 子进程（人格 / 工具 / 上下文装配 / 跨重启接记忆）
            「永不直接对用户说话」（话由这一间那条可见时间线出口）
旁路 监控层  一个**真 dsh 进程**、只看档、产出**不许进指令位**
            「它是第二个执行体，输入是主 agent 的输出（可被网页污染）」
```

### 1.1 三层各是什么

| | L1 终端 | L2 调度器 | L3 工作层 |
|---|---|---|---|
| **是什么** | 壳：**一条有序时间线**（按编号排，绝不配对）＋ 桌面图标墙 ＋ 小程序运行时 | 永续进程；一个用户**一个** `Worlds`，里面挂着 N 条会话（每条 = 一个房间） | **一个房间一条 dsh 子进程**，stdio 上说 JSON-RPC |
| **跑在哪** | 用户的设备 / 浏览器 | 服务端（本机即线上那一台） | 服务端 spawn；租户那一份在**他自己的盒子里** |
| **和谁说话** | **只和 L2**（HTTP ＋ 两条 WS） | 对 L1 = HTTPS ＋ WS；对 L3 = stdio JSON-RPC | **只和 L2**（不碰网络，不认令牌） |
| **唯一的键** | 客户端只认**编号**与**房间标签**，不判断 | 进程池的键是 `<userId>/<scope>` | 会话 id 由 `dsh-sessions.json` 的映射钉死，**一个房间永远同一条** |
| **代码落点** | `v2/apps/mobile/lib/services/stream.dart` · `models/scope.dart` | `v2/services/core/src/serve.js` · `server.js` · `dispatcher.js` · `worlds.js` | `agent-runtime.js` · `sdk-server-hupo.mjs` · `dsh-sessions.mjs` |

**中间走什么协议**：L1⇄L2 是 HTTPS ＋ WebSocket，令牌走**子协议**（`['bearer', token]`），
**不进地址**；两条 WS 是 `/api/stream`（时间线）与 `/api/asr`（语音）。
L2⇄L3 是 **stdio JSON-RPC**：`initialize` / `session/prompt` / `shutdown`（`agent-runtime.js`），
外加我们自己的 `session/resume`（`sdk-server-hupo.mjs`）。
⇒ **中间没有第四个东西**：这三段就是全部。接口逐字段的表在 [`08-SPEC.md`](08-SPEC.md) §二。

### 1.2 每一层"不许做什么"

| # | 边界 | 它具体禁掉什么 | 为什么 |
|---|---|---|---|
| **1** | **终端只上报事实，不做判断** | 不判"这句话来自谁"、不判"该不该刷新"、不判"这条该不该显示" | 判断权在服务端 ⇒ **同一份事实只被解释一次**。客户端再判一次，两边的判法一定会漂，而漂的那一侧用户看不见 |
| **2** | **调度器不能有表达欲** | 它**自己造句子**给用户是缺陷。**唯一例外**：产品固定话术（"我单独拿去做"、"我没能给出结论"这类，住在代码里的常量，不是模型生成的） | 用户看到的话必须能追溯到**一个人在一次回答里说的**。调度器一旦"顺便说一句"，那句话就没有出处，也没人能为它负责 |
| **3** | **子 agent 永不直接对用户说话** | 工作层只往它那一间的**那条可见时间线**写；上屏由调度器按焦点决定 | 一条时间线是**唯一**的可见面。让子 agent 各自开一条出口，"谁在说"就没了 |

**第 1 条容易读反**：客户端**要**做的是**呈现**（排序、滚动、草稿、缓存），
**不许**做的是**取代服务端的判断**。判"哪一间"这件事在服务端（`focus.js` 的 `routeTarget`），
客户端只**告知**"我现在看着哪一间"（`stream.dart` 的 `focus()`）——
它甚至**不许自己切房间**：切过去只认服务端回来的那一帧（`client/focus`）。

### 1.3 旁路（监控层）为什么存在

它存在的理由只有一条：**"它答得好不好"这件事，正在干活的那个 agent 自己判不了**。
所以另起一个**真 dsh 进程**，把源码与申报当作正文喂给它，让它给总结 / 风险点 / 评级
（`review-agent.js` 的 `buildReviewPrompt`）。

它的形状由**三条不许破**决定（`review-agent.js` 顶上那段，每一条都有判据）：

| # | 规矩 | 为什么 |
|---|---|---|
| **1** | **只挂模型那条 patch，不挂人格、不挂能力层** | 要的是"一个中立的读者"，不是琥珀；更不能给它那几条能写盘的工具 |
| **2** | **它是看，不是写** —— cwd 是一次性临时目录（`mkdtemp`），源码**当正文喂进去**，跑完把工作区**逐文件 sha 核一遍**，变了一个字节就 `unavailable` | "审着审着把东西改了"还当审过了，是这套机制里最坏的一种假话 |
| **3** | **算力记到这个 app 头上**（接 `UsageLedger`）；运营方那一侧复评**不记到用户头上** | 预审吃的是用户自己的算力 |

🔴 **它的产出永远不进指令位**。理由不是洁癖：**它的输入是主 agent 的输出，而主 agent 的输出
可能已经被看不见的网页内容污染过**（提示注入）。所以这一层的产出只有一个去处：
**给人看的裁决面**（`review.js` 的裁决与 `review.jsonl` 那本账）。
⇒ **认不出一律 `escalate`，绝不"因为审不了就当审过了"**（fail-closed）。

### 1.4 🔴 为什么"去掉调度器还能照旧"不成立

这句听起来像"少一层更干净"，实际是把**服务端那个进程本身**读成了"你和聊天之间多出来的一层"。
它去掉的正是**服务端**。它承担的职责一条条列在这儿，**每一条都不是"转发"**：

| # | 职责 | 它具体做什么 | 代码落点 |
|---|---|---|---|
| 1 | **取号** | 全模块**唯一**的取号函数；号 = **那条日志已落盘最大 + 1**；落盘失败要**退号** | `timeline.js` `#nextSeq` · `emit` |
| 2 | **收口** | 同一时刻**每间最多一条未收口**；超时/失败/被卸下都必须收尾 | `timeline.js` `beginMessage`/`endMessage` · `dispatcher.js` 硬收口那一档 |
| 3 | **落盘顺序** | **先落盘成功，再推订阅者**；写盘失败**上抛**，不许吞 | `store.js` `append` · `timeline.js` `emit` |
| 4 | **补发** | 断线重连按 `sinceSeq` 把缺的那一段补回来；补发只是**视图过滤**，不是第二条日志 | `resume-plan.js` · `server.js` 的 WS 订阅 |
| 5 | **排队** | 一句话在飞时后面的话排队；那一帧的形状**只从一处来** | `queue.js` `queueChangedEvent` |
| 6 | **撤回 / 回收站** | 删掉 = 落一条墓碑，不是从日志里挖洞；可少的不动产一样都不动 | `trash.js` |
| 7 | **未读** | 他不在这一间时发生的事要有可见痕迹；打开过就清 | `unread.js` · `focus-book.js` |
| 8 | **导出** | 他那一间的对话要能带走 | `export.js` |
| 9 | **长活与提醒** | 逐件落盘的活账 ＋ 承诺账；主动提醒"去哪看" | `worklog.js` · `time-words.js` · `notice.js` |
| 10 | **准入与容量** | 满了**明确拒绝**，而且在**落盘之前**判 | `admission.js` · `server.js` 的 `/api/say` |
| 11 | **多租户供给** | 一人一份世界、一人一份 `DSH_HOME`、进程池按人按间分键 | `tenants.js` · `worlds.js` `pathsFor`/`agentKeyFor` |
| 12 | **制品分发** | 签名 URL、第二个原点、租户那份从盒里取 | `app-serve.js` · `apps-box.js` |
| 13 | **每间一个 agent 进程** | 进程池、LRU 淘汰、换手到 agent 的 uid | `agent-runtime.js` |

⇒ **客户端只说我们这套协议**（HTTP ＋ 两条 WS），**工作层那台在盒子里、经隧道** ——
**中间没有别的翻译层可以去掉**：去掉的就是这两头的中间那一段本身。
"切房间不重连"这件事正是调度器存在的直接后果（一个 WS 连接是物理约束）。

⚠️ **唯一一处"它会过问'这件事在哪一间做'"是长活的派活**，而且它是**问用户**：
推一帧问话（`job.js` 的 `jobAskText` / `JOB_ASK`），**没答之前什么都不建**，
超时或不答 ⇒ 那一笔**作废**（`JOB_ASK_EXPIRED`），**不是默认答应**。

## 二、三条边界 ＋ 一条安全事实

### 2.1 三条边界（是对 §1.2 那三条的展开，也是最容易搞错的地方）

| # | 边界 | 照直觉理解会怎么错 |
|---|---|---|
| **1** | **终端只上报事实** | 直觉："客户端当然要自己判一下该不该显示。" ⇒ 错在**同一个判断有了两处实现**。判"这一句该送哪一间"是服务端的（`focus.js`）；客户端只**告知焦点**。客户端再判一次，遇到边界输入（焦点没告知过 / 服务端答不准）两边就会给出**不同的答案**，而屏幕上分不出哪个是真的 |
| **2** | **调度器不能有表达欲** | 直觉："它都说'我单独拿去做'了，那让它顺便报个进度呗。" ⇒ 错在**那句话没有出处**。要主动说话就走**已有的产品话术**（`notice.js` 的 `notice()`，它落盘、取号、用户看得见），而不是让调度器现场造句 |
| **3** | **子 agent 永不直接对用户说话** | 直觉："子 agent 干完了，直接回一句最省事。" ⇒ 错在**一条时间线之外多出一条出口**，"谁在说"就没了。子 agent 只能往**它那一间**那条可见时间线写（`ScopeView.emit`），上屏由调度器的焦点路由定 |

### 2.2 🔴 一条安全事实：**工作区根目录不是安全边界**

**事实本身**（DSH 那一层的原文口径，逐字在 `@deepseek-ai/dsh-fs-sandbox/README.md`）：
文件沙箱 **`confines model file writes and edits`**，
**`while preserving the local filesystem's read behavior`** ——
它**只约束写**，它**明确保留读**。三个模式分别是：`read-only` 拒掉所有变更、
`workspace-write` 只允许写到**会话工作区**或平台的临时根、
`danger-full-access` 完全不限制变更；被拒的操作回 `FS_SANDBOX_DENIED`。

⇒ **在这台部署上跑的是 `danger-full-access`**（见本手册 [`07-APPENDIX.md`](07-APPENDIX.md)），
也就是说**连"只约束写"这一半今天都没有**。而这不是"忘了收紧"：工作层需要它。

#### 照直觉理解会怎么错

| 直觉 | 错在哪 |
|---|---|
| "`main/` 和 `workspaces/` 是兄弟目录 ⇒ 主目录的 agent 翻不到子工作区" | **沙箱不管读**。`read` 那一类工具不受 `workspace-write` 约束，而 `danger-full-access` 下连写也不受约束。**父子/兄弟的摆法保护不了任何东西** |
| "每个房间有自己的 `cwd`，所以房间之间是隔离的" | `cwd` 只决定"**相对路径**从哪儿算"和"模型默认往哪儿写"。它**不是一道闸**：一条绝对路径就跨过去了 |
| "工作区名是 1:1 映射到一个目录 ⇒ 目录就是那间房的边界" | 反过来才对：**目录只是那间房的"落点"**。防越界靠的是**名字进路径之前必须校验**（`workspace.js` 的 `checkScope` / `safeScope`，`tenants.js` 的 `safeUserId`）——那防的是**路径穿越**，不是"模型能不能读别人" |

#### 那么记忆隔离靠什么

**靠"会话历史按 root 分区"** —— 而这**一半是自动成立的**：
DSH 把会话记录落在 `$DSH_HOME/sessions/` 下、**以 root 的绝对路径为键**编码
（`dsh-sessions.mjs` 顶上那段写的就是这件事：会话存储的键是绝对路径编码）。
⇒ 换一个 root = 换一条会话 = 换一份记忆，**不需要额外机制**。

⇒ 所以设计上是**靠"指针对 + 检索"让它没有理由去翻目录**，**不是靠堵**。
真正的跨人边界**不在目录**，在 **uid**（见 §三）。

⚠️ **同一条纪律在代码里被写了三遍，就是为了让人别再读反**：
`worlds.js` 顶上（"这一层是同进程的过渡层，**不是安全边界**"）、
`timeline.js` 的 `ScopeView`（"过滤是为了视图不串"）、
`scope.dart` 的 `eventInScope`（"它是**视图过滤**，不是安全边界"）。

## 三、多租户：一人一台盒子

**形状**：一个用户 ＝ **一台属于他自己的盒子**（rootless `podman`，跑在他自己的 uid 下）
＝ **这个人的整个世界**。用户之间**不共享进程、不共享目录、不共享 DSH**。

```
用户的那台盒子（rootfs 只读；/data 是唯一可写的卷）
  /data/                     ← 这个人的世界（卷；宿主的 /home/<租户>/tenant，0700、属主是他）
    main/                    ← 主目录（顶层对话的 workspace root）
                                 ⚠️ 不是 /data，更不是 home
    workspaces/
      <scope>/               ← 子工作区（＝桌面上的一个图标）
    dsh/                     ← 这份专属 DSH 的 DSH_HOME（会话历史按 root 分区）
    hupo/apps/<id>/          ← 制品库（指针 ＋ 不可变版本 ＋ 只追加的审计）
  /app/code                  ← **产品层**：宿主上那一个目录，**只读**挂进来
  /run/hupo                  ← tmpfs（本地通道那条套接字）
```

**为什么是"盒子"而不是"一人一个目录"**：目录分得再干净，**跑的还是同一个内核、
同一个服务账号**。一个用户手里的 agent 能自己跑命令 ⇒ 它要越界只需要一条绝对路径。
⇒ **只有内核能拦它**，而内核拦人的东西叫 uid。这也正是"容器方案的卖点"：
可以**在盒子里给它完整 root，而外面一点碰不到**。

### 3.1 隔离边界落在 **uid**

| 层 | 靠什么分开 | 落点 |
|---|---|---|
| **人 ↔ 人** | **OS 用户（uid）**＋各自的 **rootless** 容器存储 | `scripts/create-tenant-users.sh` · `create-tenant-pool.sh`（脚本里每一处 `podman` 都**以它自己的属主身份跑、不以 root**；镜像 `load` 进**每人自己那一份**存储） |
| **同一个盒子里：服务 ↔ agent** | **换手**：服务是 root，**agent 降到镜像里指定的 uid**（`HUPO_AGENT_UID`/`HUPO_AGENT_GID`） | `config.js` 的 `agentUid` · `agent-runtime.js` spawn 时的 `uid`/`gid` |
| **同一个盒子里：宿主 ↔ 容器** | 容器只经**可信 UDS** 与宿主的内部口说话（那些口**不验签、不认令牌**，身份就是"你从哪条 UDS 进来的"） | `tenant-channel.mjs` · `apps-box.js` 的 `INTERNAL_PREFIX` |

🔴 **换手不许静默失败**。`config.js` 与 `agent-runtime.js` 都把这条写死了：
换不过去 ⇒ `spawn` 回 **EPERM**（异步 error）⇒ 走失败那条路**大声报出来**，
**绝不退回 root**。理由：**静默退回 = 边界不在，而一切看起来正常** ——
这正是这个项目最忌的那种失败。
⇒ 宿主上 `agentUid` 是 `null`（服务跑在 `deploy` 下，没有特权、也不该有）；
**盒子里必须换**：盒内服务是 root，而 root 带着 `CAP_DAC_OVERRIDE`，
**agent 是 root 时任何权限位都拦不住它读钥匙**。

### 3.2 容器内目录布局的三条硬规则

| # | 规则 | 为什么（不这样会怎样） | 判据 |
|---|---|---|---|
| **1** | **主目录 root 不许是 home**（也**不许把 `DSH_HOME` 放在工作目录里面**） | home 底下躺着 `~/.dsh/.credentials.yaml`（模型钥匙）、`~/.ssh/id_rsa`、`~/.bashrc`。前两个会被**读**到，第三个会被**写**到 —— 写 `.bashrc` 就是**持久化代码执行**：下一轮开机自动跑，而表面上一切正常 | `app-workspace.test.js` 的 **A7**：`agentCwd !== dshHome`，且 `dshHome` 不许在 `agentCwd` 里面 |
| **2** | **主目录 root 不许包含 `workspaces/`**（两者必须**平行**） | 一旦 `workspaces/` 在 `main/` 里面，主目录那个 agent **写进子工作区**只需要算错一个相对路径。平行之后，写被 root 挡住（哪怕读不受限） | 同上 **A7**：`dirname(mainCwd) === dirname(workspacesRoot)`，且互不包含。落点 `workspace.js` 的 `workspacesRoot` |
| **3** | **每人一份 `DSH_HOME`** | DSH 会话存储的键是**绝对路径**。两个用户的工作区若同名，共享一份 `DSH_HOME` 就会**撞进同一份记忆** —— 而且是"两边日志都正常"的静默串号 | `multitenant.test.js`（"每个人的 `DSH_HOME` 与工作目录都不同"）· `tenants.test.js` · `worlds.js` 的 `#mainPathsFor` |

**第 2 条还有一个未来理由**：万一以后要**收紧读**，平行布局不用搬家 ——
它现在就长在"收紧之后也成立"的形状上。

**第 3 条的边界要读准**：是"**每人一份** `DSH_HOME`"，**不是"每间一份"**。
同一个人的两个房间共用他那份 `DSH_HOME`，会话靠 `cwd` 分组（A7 里那条
"房间共用**这个人**那份 `DSH_HOME`"）。⇒ 少这一条，同一个人的两个 app 会挤进**同一个**
agent 窗口（`agentKeyFor` 那条注释点名的形状：两个房间的话糊在一起）。

### 3.3 容器里的 root：**给，但只在盒子里**

| | 是什么 | 给不给 | 依据 |
|---|---|---|---|
| **宿主上的 docker / 容器运行时访问权** | ＝ **宿主上的 root**（能挂载任何目录、能起特权容器、能读别人的卷） | ❌ **永远不给** | `create-tenant-pool.sh` 第 4 条不许破："**不碰 docker 组**（P2.2 永久否决）" |
| **容器内部的 root** | ＝ **那个盒子里的 root** | ✅ **给** | 不给它就是个残废：装不了包、改不了配置、跑不了用户自己的东西 |

**但容器不是"能跑就行"，它自己那一圈约束一条都不能省**（`create-tenant-pool.sh` 渲染出来的单元）：

| 约束 | 为什么 |
|---|---|
| **rootfs 只读**（`--read-only`）＋ `/tmp`、`/run/hupo` 走 tmpfs | 盒子里那份东西**不许被自己改掉**；可写的只有 `/data` 那个卷 |
| **`--cap-drop=ALL`，只加回建用户/交文件真正要的那几个** | 能力面越小越好；加回来的那几个都是"把刚建的那一格交给他自己的 agent"必需 |
| **`--security-opt=no-new-privileges`** | 不许通过 setuid 那一类路径重新提权 |
| **产品层 `/app/code` 只读挂载** | 见 §3.5：改进产品是写文件，而**写文件的人不该是盒子里的人** |
| **不挂 docker 套接字、不挂宿主任何可写目录** | 挂了就等于把上面那张表的第一行偷偷还回去 |

⚠️ **"给盒子里的 root"这件事的性质要说清**：它不是"我们信任盒子里的 root"，
而是"**盒子里那个 root 能碰到的全部，只有他自己那一格**"。
⇒ 这一条成立的前提是**容器那一圈约束真的在**
（见 [`06-OPERATIONS.md`](06-OPERATIONS.md)），缺一条，"给 root"就变成"给半个宿主"。

### 3.4 容器不是"第一步"，它是"开第二个席位的开门条件"

**容器本身不产出任何用户能看见的东西**：今天用户看得见的能力
（说话、桌面、小程序、长活、记账…，见 [`01-PROJECT.md`](01-PROJECT.md) §六）
**没有一件是"因为有了容器"才有的**。它买的只有一样东西：
**第二个席位的开门条件** —— 没有它，第二个用户与主人共享同一个内核、同一个服务账号，
"一人一台"这件事就不成立（见 §3.1）。

🔴 **所以它不能单独上**：容器必须与**供给上限**（进程上限 ＋ 淘汰 ＋ 准入）**同批**落地，
否则**容器只是把天花板复制一遍** —— 每一台盒子各自能跑满，而"总共有多少台、
每台同时几个活"这两件事没有人管 ⇒ 从"一个用户把机器吃满"变成"N 个用户一起把机器吃满"，
**症状更晚出现、更难归因**。
⇒ 这两半的判据是分开的（容器那一半见 [`06-OPERATIONS.md`](06-OPERATIONS.md)；
准入与容量的接口语义在 [`08-SPEC.md`](08-SPEC.md)），**验收时不许只验一半**。

### 3.5 改进产品 ≠ 重建盒子（这条决定了很多事）

**产品**（调度器 ＋ 人格 ＋ 能力层 ＋ patch）**不住在镜像里**：它是宿主上一个目录
（`/srv/hupo/tenant-code/<指纹>/`），建容器时**只读**挂进 `/app/code`（`product-layer.js` 顶上那段）。
⇒ **改进产品 = 写文件 ＋ 让那一台重开一次**：不必重造镜像、不必重建容器、**不需要 root**。

配套的是"**这一台跑的是哪一版**必须是看得见的事实"：
容器**如实自报**版本指纹，宿主拿它与当前那一版比，**不一致就说话、并叫它重开**
（`product-layer.js` 的 `readProductLayer` / `compareTenantBuild`；
`serve.js` 里 `onBuild` 那一处把结论接上）。
**叫它重开的那一帧不带任何内容** —— 它是一个通知，**不是一个远程执行口**。
🔴 **读不到"当前那一版"时，谁都不叫**：叫了就是让每一台去挂一个不存在的东西。

**为什么"跑起来"那一步的接线不能住在镜像里**：镜像里只留一个**薄加载器**
（找到产品层 / 报出版本 / 把它跑起来），**其余全在产品层**。
理由是结构性的：**"改一次接线就要重造镜像"本身就是缺陷** ——
镜像里那份规则、显式传参绕过默认值、看门拿错基线，**每一层单独看都"实现对了"**，
合起来就是"**放钥匙的说放好了、用钥匙的还在看别的地方**"。
⇒ 这条规矩买的是"接线只有一处、改它不需要碰镜像"。

## 四、作用域

### 4.1 1:1:1:1

> **一个作用域 ＝ 一个工作区 ＝ 一条 DSH 会话 ＝ 一个目录 ＝ 桌面上一个图标。**

| 层 | 实体 | 是什么 | 拥有记忆？ |
|---|---|---|---|
| 归置 | **workspace** | `<dir>/workspaces/<scope>/` 那一格 ＋ 它自己的清单（`.hupo.json`：id / 名字 / 入口） | ❌ **不拥有**（对模型完全不可见，零上下文成本） |
| 干活 | **session** | 一次连续对话；**自带 workspace root** | ✅ **记忆在这里** |
| 落盘 | 那条日志（`main.jsonl`）＋ 事件上的 `scopeId` 标签 | 可见历史 | —— |

**四个"一"各自的落点**：

| 那个"一" | 落在哪 | 代码 |
|---|---|---|
| 一个**作用域** | scope 名（小写字母数字短横；`main` 是保留名） | `workspace.js` `safeScope` / `checkScope` / `RESERVED_SCOPES` |
| 一个**工作区** | `<dir>/workspaces/<scope>/` | `workspace.js` `scopeDirFor` |
| 一条**会话** | 进程池键 `<userId>/<scope>`；DSH 会话 id 由映射钉死 | `worlds.js` `agentKeyFor` · `dsh-sessions.mjs` `sessionIdFor` |
| 桌面**一格** | 客户端把"开着的那个东西"翻成 scope | `scope.dart` `scopeOfOpenApp` |

⚠️ **两点别读错**：

1. **"一条会话"不等于"一条日志"**。多作用域**不是并列的计数器** ——
   一个用户只有**一条**可见日志（`main.jsonl`）、**一套号**，"是哪一间"住在事件上的
   `scopeId` 标签里（`scopeTimelineId` 恒返回 `main`；`ScopeView` 负责盖标签与挑标签）。
   判据：`scope-single-log.test.js` 的 **F1**（两个 scope 的事件落在同一个文件、同一套号），
   以及它的反例（每 scope 各自从 1 起 ⇒ 当场红）。
2. **"归置"与"记忆"是两件事**。"一个文件夹一套记忆"是**结果**，不是 workspace 这个实体在管。
   这条区别决定：改名字 / 归档 / 删图标，动的是**归置**还是**记忆**。

### 4.2 "作用域栈"今天没有落点

有"焦点"，**没有"栈"**。

| | 今天是什么 | 代码 |
|---|---|---|
| **客户端** | 焦点是**一个值**（`String _focus`），不是一叠：打开某个东西 ⇒ 算出那一个 scope；回桌面 ⇒ 回 `main`。**没有层级、没有"上一层"** | `stream.dart` 的 `_focus` / `focus()` · `scope.dart` 的 `scopeOfOpenApp`（吃一个 `String? openApp`，返回**一个** scope） |
| **服务端** | 落盘的是一张 **`设备 → 焦点`** 的平表（外加一份"没带设备标识时用的"兜底），**不是栈**：`set(device, scope)` 就是**覆盖**那一台那一格，没有 push / pop / 父级 | `focus-book.js` 的 `FocusBook`（`devices` 是对象表、`set` 直接赋值）· `dispatcher.js` 的 `setFocus` / `focusFor` |
| **已知的那些** | `devices()` 回的是"哪些设备告知过"，用来判定**这一份焦点答不答得准**，与层级无关 | `focus-book.js` 的 `devices()` · `focus.js` 的 `knownFocus` |

⇒ 所以"退回上一层"这件事今天**不存在**：从某一间回桌面，走的是"焦点改成 `main`"，
而不是"弹出一层"。判据也只钉到这一层：`handoff.test.js` **D-9**（焦点按**设备**各记一份；
没带 / 没告知 / 多台矛盾 ⇒ `unknown`，**不许拿最新那台顶替**）。
⚠️ **"多设备"与"栈"是两件不同的事**：前者是"谁在看"，后者是"看过哪些"。
今天系统只回答前者。

### 4.3 一致性铁律

> 🔴 **界面显示的作用域，与这条会话的 root，必须始终一致；不一致就报错，不许继续。**

**为什么单列一条**：只切界面没切 root，会出现"**界面上我在 A 里，说话却写进了顶层**"。
这种 bug 最难查，而且它**让隔离静默失效**。

**它落在哪一层**（`focus.js` 的 `routeTarget`，接线在 `server.js` 的 `/api/say`）：

| 情形 | 行为 |
|---|---|
| 客户端**没告知过**焦点（老客户端 / 还没连流） | **不比较**，照旧送出（老行为不动） |
| 归处提示 **==** 焦点 | 送出 |
| 归处提示 **!=** 焦点 | **既不按提示送、也不按焦点送**：回 `focus-mismatch` ＋ **反问一句** —— **不投递、不落盘**（`say.say()` 根本没被调用，盘上不留"没被回答的话"） |
| 焦点**答不准**（多台设备互相矛盾 / 那台从没告知过） | 按"**不知道**"处理（`FOCUS_UNKNOWN`）—— **绝不拿最新那台的顶替** |

🔴 **两边静默赢都是缺陷**：按焦点送 = 把 B 那间的话吞掉；按提示送 = 把活送错地方而且看不出来。
⇒ 判据：`focus.test.js`（第 16 条那条，含三档与反例）。

### 4.4 切换 ＝ 换会话（不是改一个字段）

**root 在会话创建时定下，运行中改不了**（会话头里记着 cwd；`agent-runtime.js` 起进程时
`cwd: cfg.agentCwd`，`initialize` 也带 `cwd`）。
⇒ 所以"进入一个作用域" ＝ **结束当前这条 ＋ 开一条新的（带新 root）**。
**是"换一条会话"，不是"改一个字段"。**

**但"换会话"不等于"重连"**，这两件事在今天的形状里是分开的：

| | 怎么发生的 |
|---|---|
| **切焦点** | 客户端发**一帧** `{"t":"focus","scope":…,"sinceSeq":…}`（`stream.dart` 的 `focus()`）—— **连接不动**，服务端按新焦点补发那一间的历史、之后的实时帧也按新焦点路由 |
| **换会话** | 服务端在需要时把这一间的会话换掉（`agent-runtime.js` 的 `rotateSession` ＋ `dsh-sessions.mjs` 的映射），**下一次取用**才按新映射建进程 |

⇒ 地址上那个 `scope` 今天的语义是"**初始焦点**"（老服务端只认它，老客户端也只带它）——
它**不再是**"这条连接只听这一间"。
**一个 WS 连接是物理约束**：不能每个房间一条连接。

**"翻页"是这条纪律的一个特例**（不是另一套机制）：一轮的上下文大到一定程度 ⇒
把这一间的会话换成**下一条新的**，旧的那条文件**原样留着**；
"接得上"靠本来就有的那套（新实例第一次投递时把那段时间线喂回去）。
判据的落点在 `session-budget.js`（`shouldRotateSession`）与 `worlds.js` 的
`SESSION_ROTATE_WHAT` 审计。

### 4.5 跨作用域：转交与"挪走"

**转交（handoff）** —— 一条消息、一个气泡，换一间接着写：

```
A 正在回答（同一条消息，同一个气泡）
  ├─ ① A 调 handoff_to(scope, reason)        ← ⚠️ 工具调用，不是自然语言
  ├─ ② A 那条消息**不收口**，打一个 message/handoff 状态 → 客户端显示"马上说完"
  ├─ ③ 调度器组装交接包 → 交给 B
  └─ ④ B 接着往**同一个 messageId** 里写
```

**四条硬规矩**（`handoff.js` 的 `decideHandoff`，判据 `handoff.test.js` D-1…D-4）：

| # | 规矩 | 为什么 | 判据 |
|---|---|---|---|
| **1** | **只有工具调用能发起** | 正文里写"我转给某一间"**不算** —— 检测关键词就是"把自然语言当控制面" | **D-1**（结构性成立：`record()` 只可能从 MCP 那条口进来） |
| **2** | **一轮最多一次 ＋ 禁回环**（`A→B→A` 被拒） | 回环不是"多绕一圈"，是**同一件事永远做不完** | **D-2**（含"同一条消息再转一次 ⇒ 拒"） |
| **3** | **目标必须已存在**（**不建**） | "顺手建一个"会让一次手滑在盘上留下一条日志 | **D-3** |
| **4** | **发起那条消息不收口**，续写挂**同一个 `messageId`** | 收了口就等于"挪走"（另起一条），用户的屏上会裂成两个气泡 | **D-4** |

**"挪走"的语义**：**先收口，后面的话另起一条**。
它与转交**语义相反**，所以**必须是两个不同的状态值**（判据 **D-8**）——
共用一个值的话，"同一时刻最多一条未收口"这条不变量没法校验。

**标签的规矩**：转交续写的事件 `scopeId` 打**发起那一间**（用户看得见的那一间）
⇒ 前后半段同一个标签、视图不裂、客户端一个气泡；
"谁在干活"**另加一个字段**（`byScope`），**只**用于审计与用量 ——
**不许**拿干活者当可见标签。

### 4.6 "用户切走了，A 还在干活"怎么办

> **A 照常做完，结果照常进 A 的会话历史。不做任何跨作用域投递。**

理由：**用户切走 ≠ 话题结束，而意图不可知。**

| 如果猜 | 结果 |
|---|---|
| "切走 = 结束" | 误判 |
| "切走 = 还相关" | 也误判（而且更坏：把话送错地方） |
| **不猜，两端各自做完、互不投递** | **零误判** |

这是"**沉默优于编造**"从"答什么"搬到"**投给谁**"。

**精确表述**（三句都要读，不然会实现错）：

- **"搁置"不是一种新状态**。它就是"A 的消息正常写完了"。
- **"隐藏"不是"不投递"，而是"不实时提醒"**。事件照常进那条日志、照常取号。
- ⇒ 判据 **D-5**：他在乙间时甲间做完了 ⇒ **不实时推给乙**，甲的历史里查得到。

**三件配套**：

| # | 做什么 | 代码 |
|---|---|---|
| **1** | **A 要知道"用户当前不在我这一层"**（动态运行时事实） | `focus-book.js`（按**设备**记焦点；答不准 ⇒ `unknown`） |
| **2** | **未读标记**（桌面上那一格带小点）——"动作可静默，事实不能静默"最轻的落实 | `unread.js`（判据 **D-6**：有新东西答得出"有未读"；他打开过就没了 ＋ 落盘） |
| **3** | **A 被回收前结果必须落盘** | 判据 **D-7**：agent 被卸下之后，那件事/那条消息**仍查得到**（换一个进程读盘） |

⚠️ **别把这三件读成"给她发通知"**：这里的动作全是**账**（落盘的、可查的），
不是"往屏幕上推一条"。屏幕那一侧只在他在那一间时才动。

### 5.3 两条必须知道的例外

**例外一：主动回收会留下号洞（N22 的**唯一**例外）**。
从桌面上删掉一格 ＝ **真回收**：那一间的对话记录要从日志里拿走。
口径是：**只增不减照旧**（不许重编号、不许回退、不动任何别的号）；
**允许的洞只有这一种**；**必须留痕**（`reclaim.js` 的 `RECLAIMED_FILE`：记着哪一间、哪些号、什么时候、谁删的）；
校验器**按留痕解释洞** —— **能解释的洞通过，解释不了的洞当场红**，
而且**反向也要咬得动**（把留痕删掉一条 ⇒ 当场红）。
⇒ 落点：`reclaim.js` · `store.js` `verifyMonotonic({reclaimed})` · `timeline.js` 的 `seqFloor`（号的"地板"：
被拿走的号**不许复用**）。判据：`app-reclaim.test.js` **S8**/**X2**/**X5** · `room-reclaim.test.js` **R1–R4**。

**为什么不重编号**：重编号 ⇒ 客户端手里的游标（`sinceSeq`）全部错位，要么漏、要么重放一屏。
**号是给游标用的，不是给人看的。**
**为什么不"清空正文留空壳"**：那是"留着一份看不见的副本"，而用户要的是**真回收**。

**例外二：N19 那一半"必有超时"今天只剩一种**。
**收尾仍然必有**（进程退出 ⇒ 服务端补一句实话收口；OOM 有专门那句），
但**单轮的时间上限不存在** ⇒ "进程活着、卡在一个不动的循环里"这一种，
今天**没有**由时间触发的收尾。
⇒ 这是那条决定的**已知代价**，不是遗漏；读数与来由在
[`../dev/173-DSH-STUCK-ANALYSIS.md`](../dev/173-DSH-STUCK-ANALYSIS.md) 与
[`../dev/174-NO-TURN-DEADLINE.md`](../dev/174-NO-TURN-DEADLINE.md)。

## 六、明说没建的

> 这一节存在的理由：那几个模块**在规划里讲过**，读旧材料的人会以为"已经有了"或"快有了"。
> **它们不是排在后面，是不建。**（判据：这一节里每一条都有一句"为什么不建"，
> 而不是"什么时候做"。）
>
> ⚠️ **这一节那几句"为什么不建"是本手册自己的陈述**（是本篇作者的技术判断），
> **不是某条决策记录的原话**。**权威的"已取代与不建"清单住在
> [`08-SPEC.md`](08-SPEC.md) §七** —— 两边若不一致，**以 `08` 为准**。

| 模块 | 它本来要做什么 | **为什么不建** |
|---|---|---|
| **`budget`（成本三级）** | 按轮/会话/全局三级记预算并降档 | **没有价格表**：上游不给我们一份"这个模型多少钱"的权威来源。而"自己抄一份价目表"的那条路必然过期，过期之后**它算出来的每个数都是假话** —— 比"没有这个数"坏 |
| **`tracer`（每轮 trace）** | 每一轮留一份可回放的执行轨迹 | 它要的是**全局唯一的执行上下文**，而这条链路跨**三个进程、两条协议、还有一层隧道**。拼出来的"一份 trace"是**看起来完整、实际有洞**的东西 —— 而排障的人会信它 |
| **`policy`（来源分级 → 能力档）** | 把来源分级做成一张可配的策略表 | 今天只有**两档**（见 N3 的落点）。做成表 = 允许"悄悄加一档"，而每加一档都要重新证明"这一档给不出越权"。**两档能证的，表证不了** |
| **`audit`（系统级动作审计）** | 一份统一的系统动作审计流 | 各处的账**已经各自落盘**（`audit.js` 的按人审计、`egress-log.js` 的出网留痕、制品的只追加审计、`reclaim.json` 的回收留痕）。再包一层"统一审计"只会多一份**可能与真实那几本对不上**的副本 —— 而审计这份东西**对不上就等于没有** |
| **KV（记忆）** | 一个可检索的记忆 KV 库 | 今天的记忆就是**那条会话历史 ＋ 指针对检索**（见 §二 那条安全事实）。上 KV = 多一份**与事件流并行的真相**，而 N6 说事件流才是权威。⇒ 要建它，得先回答"两处打架时谁赢"，而那个答案今天不存在 |

⚠️ **读这一节的正确姿势**：不要问"什么时候做"，要问"**要建它，得先解决上面那句为什么**"。
