# 产品面板 · 第二轮 · 议程（AI 手机：多租户 + 工作区 + 统一窗口）

> **第一轮**（`docs/pm-panel/SYNTHESIS.md` → `DECISIONS.md` 11 条拍板）解决的是**单用户**那一代。
> 这一轮是新的一代：**一人一台容器、一条会话一个工作区、客户端只看到一条时间线**。
>
> **本轮的输入**：
> - `docs/design/ai-phone-architecture.md`（新架构，659 行，凡【实测】都给了出处）
> - 本议程（已知的待决策清单）
> - `ARCHITECTURE-v7.md` §14/§15（继续有效的部分 + 悬空项）
> - `docs/pm-panel/01|02|03-*.md`（三位第一轮的讨论稿，用于对照立场是否变过）
>
> **本轮与前一轮最大的不同**：这一轮的绝大部分技术前提**已经实测过了**
> （DSH 的原语、会话按 workspace 分区、沙箱只约束写不约束读、token 用量存在）。
> 所以本轮**不许再用"我猜 DSH 可能做不到"当论据**——要么引用文档里的【实测】出处，要么标【推定】。

## 一、规矩（沿用第一轮，一字不改）

| 判定 | 条件 |
|---|---|
| **收敛项** | 三人结论一致，且**判据不冲突**（不是"都没意见"，而是"理由不同但指向同一动作"） |
| **真争议** | 两个及以上不可调和的选项，且**各有可测判据**——不强行折中，列出来给主人拍板 |
| **伪争议** | 只是措辞不同、或一方在替另一方设稻草人 ⇒ 直接消掉并写明为什么 |
| **优先级** | 有实测数据的立场 > 无数据的直觉；但"用户会不会回来"这类判断，允许场景推演压过数据 |

**每人每条都要给：结论（选哪个字母）+ 判据（凭什么）+ 我会砍什么（代价）。**

## 二、议程

### A · 地基（🔴 不决定就没法开工）

| # | 议题 | 选项 | 背景 |
|---|---|---|---|
| A1 | **状态清单现在写死吗**（容器里"哪些路径是用户的状态"，是备份/迁移/删除的唯一依据） | a) 现在写进文档 b) 实现时再说 | 清单就是几行路径，零成本；推迟就变成在已跑起来的系统上考古 |
| A2 | **备份的加密与恢复演练** | a) 和备份一起做（可推迟） b) 现在就定成硬要求 | 压缩≠加密；`$DSH_HOME/.credentials.yaml` 与全部对话在同一个包里 |
| A3 | **每用户一份 `DSH_HOME`** 升为硬规则？ | a) 是 b) 只是推荐 | 【实测】会话存储的键是**绝对路径**（`--home-deploy-proj-hupo--`）。共享 `DSH_HOME` ⇒ 不同用户的同名工作区撞进同一份记忆 |
| A4 | **容器怎么拿到**（本机三道锁：不在 docker 组 / sudo 要密码 / AppArmor 挡无根 userns） | a) `usermod -aG docker deploy` b) 装 rootless podman c) 先不动 | **a 等于给 deploy 免密 root**；b 是本机 AppArmor 已放行的唯一无根路径 |

### B · 作用域与转交（🟡 定了能少返工）

| # | 议题 | 选项 | 背景 |
|---|---|---|---|
| B1 | **转交怎么触发** | a) A 调用工具 `handoff_to` b) 调度器解析 A 的自然语言 | b 脆弱且会被注入利用（A 被污染后随便说一句就触发） |
| B2 | **一轮内能转几次** | a) 1 次 + 禁回环 b) 允许多次 | 多次 ⇒ 用户被踢来踢去，与"不留人、不拖时间"冲突 |
| B3 | **转交的前提** | a) 目标工作区必须已存在 b) 允许临时造一个 | b ⇒ 每遇到话题就临时造 agent = 无限增殖，违反"单次不生成、多次才生成" |
| B4 | **工作区最大深度** | a) 2 b) 不限 | 与 v6 `maxDepth=2` 一致 |
| B5 | **转交时 A 与 B 的人格差异** | a) voice 共用、role 分开 b) 各自独立人格 | b ⇒ 用户觉得"换了个人"（`seamless` §4.3 的原话是 a） |
| B6 | **用户主动点桌面图标进工作区时，交接怎么做** ⚠️ 从未定过 | a) 和系统转交一样带材料 b) 干净进入什么都不带 c) 只带"你在顶层聊到哪一句" | 这是**第三条入口**（不是系统转交、也不是用户切走） |
| B7 | **进工作区时前文搬不搬** | a) 搬原文 b) 从零 c) 只带摘要 + 指针 | a ⇒ 顶层历史"少几句"，属于页面说假话 |
| B8 | **未读标记的形态** | a) 桌面图标带点 b) 时间线加折叠段 c) 不做 | "动作可静默，事实不能静默" |
| B9 | **A 被问细节但手里只有摘要时** | a) 直说不知道 b) 拿指针去检索（`dsh-session-query-sqlite`） | a 最保守；b 体验好但多一次检索 |

### C · 记忆索引 KV（🟡）

| # | 议题 | 选项 | 背景 |
|---|---|---|---|
| C1 | **KV 要不要做语义抽取**（"报名截止 3/20"这类事实） | a) 只做机械索引（标题/时间/参与会话） b) 机械 + 语义抽取 | 不做 b 就没有"主目录记得小升初的截止日" |
| C2 | **KV 谁来写** | a) agent 直接写 storage domain b) 只能通过 hupo 的工具、过 provenance 校验 | a ⇒ 被注入的 agent 能持久化假记忆，且绕过审计 |
| C3 | **KV 里"不知道"要不要显式表达** | a) 空着 b) 显式 `trust: unknown` | b 让"我不知道"成为可表达的状态，而不是等着被填的空缺 |

### D · 还没正面回应的两块大设计（🔴 我认为最值钱）

| # | 议题 | 背景 |
|---|---|---|
| D1 | **能力契约层**（云端数据服务 + 带 schema 的登记表）：做不做、什么时候做 | 最早的诉求是"背后是数据服务、前台 AI 生成"。这一层是"生成 APP"的承重墙：**AI 只做组合和渲染，绝不发明接口**。没有它，生成物攒不起来 ⇒ "多次需求固化成 APP"这条主线不成立 |
| D2 | **没有 API 的世界怎么办**（银行/政务/挂号/快递）：做不做"声明式代操作" | 已经否掉了"模拟点击操控 APP"（理由：UI 一改就碎、无法审计、延迟高）。代价是这些事没有数据服务可接。**不做就等于承认"AI 手机"只覆盖愿意开放接口的那一小块** |

### E · 资源与容量（🟡）

| # | 议题 | 选项 | 背景 |
|---|---|---|---|
| E1 | **一进程多 session vs 每工作区一进程** | a) 一进程多 session（省内存，隔离靠分区） b) 每工作区一进程（隔离强，内存 ×N） | 【实测】workspace root 是 **session 级**的 ⇒ a 技术上可行 |
| E2 | **容量：一台机器装几个用户** | a) 换机器 b) 做 scale-to-zero | 生产机 4vCPU/7.2G；agent 172MB ⇒ **3 个并发就撞 1G 上限** |
| E3 | **模型调用走不走总机代理** | a) 走 b) 不走 | 原为成本计量；【实测】`dsh-token-meter` 存在 ⇒ 该理由消失。只剩**密钥不扩散 + 限流** |
| E4 | **每容器 cgroup / 磁盘配额的数** | —— | 待实测 |

### F · 安全（🔴）

| # | 议题 | 背景 |
|---|---|---|
| F1 | **agent 自己的手有多大**（v7 §15 第 1 条） | 容器解决了**用户之间**，**没解决 agent 与宿主**。生产上 agent 仍挂 `danger-full-access` + 免密 sudo。而"agent 能改自己"正是让一次注入变成灾难的原因 |
| F2 | **provisioner 的特权路径** | 不能长在公网 API 上；参数必须全部来自模板（**绝不能让请求字段进容器创建参数**） |
| F3 | **用户容器之间网络隔离** | 默认 bridge 里容器**互相可达**；另需封 `169.254.169.254` |
| F4 | **API 密钥怎么进容器** | a) 白名单 env b) 总机代理。v7 §3.4 的"白名单 env"**一直没实现**（现在代码是 `env: process.env` 全文透传） |
