## 〇、我这一轮最想说的一句话

**这一轮最大的风险不是"做不出来"，是"做出来了，而且它说它做好了"。**

新架构里每一个最值钱的设计——一条时间线下面是 N 条会话、转交时不换气泡、B→A 汇报、
KV 索引、"搁置不是状态"——都是**把接缝藏起来**的设计。藏接缝的产品收益是真的（用户以为在跟一个人说话），
但它把"机器换了人""B 说的话不可信""这条记忆没有出处"这三件事**从界面上移走了**。
所以这一轮我必须给每一条藏起来的接缝配一个**看得见的痕迹**，否则我们就是花钱买了一个更会撒谎的产品。

一句话：**接缝可以藏，事实不许藏。这一轮凡是"藏了接缝又没留痕迹"的条目，我一律要求砍或加痕迹。**

## 二、D1 / D2 单独说（能力契约层 / 没有 API 的世界）

这两块我单独写，因为它们**不是功能，是护栏的形状**。第一轮我打的正是"没地基就加面"，
而这两块恰恰是最容易被当成"面"推迟掉的两块。

### D1 · 能力契约层：做，但第一批只做"登记表 + 版本化 + 失败语义"

**它引入的不可恢复失败模式（三条，按严重度排）**

1. **契约一变，全部已生成的应用同时坏** —— 这是**全局性、不可恢复**的故障形态。
   功能坏了能加回来，契约坏了不行：如果能力目录没有版本号，上游某天改了一个字段语义，
   我们**没有一个可以回滚的点**，因为"老版本应用"和"新版本能力"是同一份东西。
   ⇒ 硬要求：**能力必须有版本；已发布的应用钉住它生成时的版本；上游变更只能新增版本，不能改旧版本语义。**
2. **把攻击面从"工具层"搬到"业务层"** —— agent 若能自己注册能力，就能凭空发明一个"接口"，
   于是"AI 绝不发明接口"这条纪律**只在提示词里成立**，不在执行边界里成立。
   ⇒ 硬要求：**能力目录只由人/受审流程写，agent 只能读、只能组合**（与 C2 同一条逻辑）。
   我会砍掉：任何"agent 自动发现并登记新能力"的便利。
3. **"没有 API 的能力"被静默降级成"不存在"** —— 失败原因必须能区分：
   *没有这项服务 / 超时 / 限流 / 鉴权失败 / 上游返回了错误*。全塌成一句"查不到"，
   用户就会得到错误的结论（"这家医院不能网上挂号"），而真相是"我们超时了"。
   ⇒ 我会砍掉：任何把失败原因合并成一种的接口设计。

**还需要在契约层出现、但议程没提的字段（这是我最想说的一段）**

- **额度 / 频率 / 费用 / 是否涉及支付** —— 没有这几个字段，系统就可能在主人不知情时花钱。**涉及支付的调用第一版一律不自动执行。**
- **副作用级别的声明** —— 纯查询 vs 会改状态，必须由能力自己声明，不能由调用方猜。
- **撤销/补偿路径** —— 写操作必须写清"怎么退"。写不出退路的操作，第一版按"不可逆"处理。
- 并且我要一个**本地不变量**：**"改本机状态"（写日历、关闹钟、改通讯录）也算外部副作用**，要和调云端接口同等待遇；否则我们会用"本机"这个词给自己开后门。

**什么时候"它会不 work"（我说得清，而且必须写进文档）**

- 上游没有稳定接口、只有页面 → 这条能力**不存在**（不是"降级"）。
- 需要支付确认 → **必回人**。
- 需要短信验证码 / 人脸核验 → **必回人**。
- 有多个写入者同时改同一个源（用户自己也在网页上改）→ **我们不保证一致**，只能回查。
- 能力处于 `experimental` → **不许出现在用户应用的生成路径上**（可以给开发者卡片）。

**顺序与代价**：第一批只做"登记表 + 版本化 + 失败语义 + 额度字段"，**不做**"生成 APP"。
砍掉的：这一轮任何自动生成的用户应用。这笔账我认——但**契约现在不写，以后每一块都得重做**，
因为版本化不是能事后补的补丁：补的那天，所有已经存在的东西都已经没有版本了。

### D2 · 没有 API 的世界：不做代操作，只做"准备到最后一键"

**先说结论的形状**：**第一版不代做任何账户动作。** 议程已经否掉"模拟点击操控 APP"，
我加上一条更硬的：**这条否掉的决定不许以后以任何名义复活**（包括"换个名字叫声明式"）。

**"声明式代操作"会引入的三条不可恢复失败模式**

1. **终态不可逆 + 我们的失败不可见**。挂号真的挂上了、重复提交真的产生了两笔订单——
   这类错误没有"撤回"，只有一笔真实损失。而它的诱因往往是我们的重试逻辑：
   **超时重试 = 二次提交**，这是自动化事务里最经典的一类事故。
2. **它要求我们保管主人的账号口令**。一旦保管，**一次注入就等于以主人身份操作银行/政务**。
   我们连"该不该存这个口令"的法律依据都没有，更不用说怎么保证它不进备份包（见 A2）。
3. **审计断链**。真出了事，我们拿不出"谁在什么时候点了什么"的凭据，而这类外部服务的对账只认它们自己的日志。

**替代方案：把"准备到最后一键"做满**（这也是我给陆明的正面提案，不是只否不做）

- 把表单**填好**（字段、参数、注意事项），生成一条**深链**，用户点一下到他自己的 App/浏览器里确认提交。
- **列官方入口**：我们只做"哪一个才是官方入口"的核对（这条价值很高：假入口是真实风险）。
- **待办清单 + 时限提醒**（报名截止、缴费期限）——**提醒是产品，代操作不是**。
- **可以做的自动动作**：查（只读）、算、整理、生成、提醒。

**什么时候"它会不 work"**：① 主人不在场；② 一次要对多笔；③ 需要轮询等放号；
④ 需要"办成了才算数"的闭环确认。这四种情况下，主人得到的是"该我了"的提醒，**不是**"已经办好了"。

**我会砍什么**：砍掉模拟点击与代操作；砍掉口令托管；砍掉轮询等待；
砍掉"用代办清单冒充代操作"（文案上不许暗示"我替你办了"）。

## 三、议程上没有的问题　← 这一节最关键

> 每条：`问题 / 为什么现在不处理会更贵 / 建议塞进哪一组`

**N1 · 未读标记的清除规则从来没有定过**
- **问题**：B8 只定"形态"（图标带点 / 折叠段 / 不做），没定"什么时候消"。是打开就算已读？滚到底才算？用户手点掉？
- **为什么现在不处理会更贵**：三份不同的实现在三处各写一个，最后的标准答案会变成"点开就没了"——**用户于是错过东西，而界面显示"没有新东西"**。这是"事实被静默"的最典型形态。
- **塞进**：B 组（与 B8 同条，判据：打开工作区即已读，服务端持久化）。

**N2 · 全局 seq 在调度器重启后的恢复策略（现在是靠巧合成立的）**
- **问题**：【实测】`conversation.js:3-4` 写着"seq 由**会话自己**管理（不是全局）"，且 `seq` 是内存里的 `++`，重连靠 `sinceSeq` 补发；重启后靠**从已落盘事件里取最大值**恢复（`store.js:150`）。新架构 §八 要把 seq 改成"由调度器分配的全局 seq"——**那么调度器重启后，这个全局 seq 从哪里恢复？** 架构里没有写。如果从 1 重新开始，客户端的 `sinceSeq` 续传逻辑会**丢消息或重复补发**。
- **为什么现在不处理会更贵**：这是唯一一处"底层改来源、上层协议不改"的改动（新架构 §八 明说客户端一个字都不用改）——**正因为客户端不改，seq 出错就没有任何一层能兜住**。等到多工作区跑起来再发现，已有的对话历史已经是一堆无法解释的游标。
- **塞进**：A 组（我建议直接写成不变量：**调度器重启后全局 seq = 所有会话已落盘事件 seq 的最大值 + 1，只增不减**）。

**N3 · "搬到另一台机器/另一个容器"这条恢复路径不存在，而 A2 的备份清单只覆盖备份**
- **问题**：状态清单被定义成"备份/迁移/删除的唯一依据"，但整份文档里**没有任何迁移动作**：容器重建（内核升级、镜像换代、机器更换、用户想换一台机器）时，用户怎么把状态搬过去？
- **为什么现在不处理会更贵**：容器一旦成为"用户的整个世界"，**容器重建就是最贵的一天**。而它的成本几乎全在"清单漏项"上——漏一个 `$DSH_HOME/storages/`，用户的"当前状态"就退回某个旧检查点。清单今天写，救的是那天。
- **塞进**：A 组（A1 的附件：清单里的每一条都要有"怎么搬"的一句话）。

**N4 · B9 与 N13 直接冲突（这是架构自己内部的不一致）**
- **问题**：B9 的选项 b"拿指针去 `dsh-session-query-sqlite` 检索"是**读 B 的原文**，而同一份架构的 N13 说"跨作用域只走摘要与指针，不走原文"。
- **为什么现在不处理会更贵**：这不是措辞问题，是**两条不变量兑现成两套代码**。哪套先落地，后落地的那套就要拆前面的。
- **塞进**：B 组（我的裁决：B9 取 a + "请 B 再答一次"，并**改 N13 的措辞**，把"不许读原文"写成机械判据，而不是写在愿景里）。

**N5 · 设备丢失 / 令牌被盗这一轮没人管，而它是"主人不敢把事交给它"的最短路径**
- **问题**：令牌 TTL 30 天、无吊销（第一轮实测），本轮又新增了"多工作区 = 更多能做的事"。丢一台平板 = 别人拿到主人的整个工作区。
- **为什么现在不处理会更贵**：等到"一个用户一台容器"落地，撤销令牌就不再是"改一个字段"，而是要**把一条已建立的会话身份从多台设备上踢掉**。
- **塞进**：G 组（最小版：设备列表 + "退出全部设备"，TTL 从 30 天改短，阈值：**7 天不活跃即需重新认证**）。

**N6 · 有副作用的调用怎么保证"只做一次"**
- **问题**：D1 的能力调用会重试（超时、限流都会触发）。**没有幂等键，就一定有重复下单/重复提交。**
- **为什么现在不处理会更贵**：幂等键必须在**契约层**定义（每个能力的请求要能带一个调用方生成的唯一键）。等接口长出来再补，等于要求每个能力各自实现一遍。
- **塞进**：D 组（D1 的必填字段之一；判据：同一个幂等键重放两次，外部只发生一次）。

**N7 · 容器的版本与回滚（"谁能改容器基础镜像"）**
- **问题**：容器解决了用户之间的隔离，但**镜像成了所有用户共享的单点**——一个坏镜像同时影响所有人，而且用户看不见、也修不了。
- **为什么现在不处理会更贵**：这是"我把命交给了别人维护的东西"这一类风险。它必须有一个**冻结版本 + 回滚一条命令 + 变更前公告**的流程，否则出事那天我们连"回到昨天"都做不到。
- **塞进**：F 组 / 新增运维条（判据：镜像 tag 不可变，回滚演练过）。

**N8 · 容器内存触顶时，容器里的人看到什么**
- **问题**：C 组只写了"什么会把内存打满"。**触顶那一刻用户看到什么**没有定：是"变慢"、是"一句话"、还是"白屏"？（第一轮我们花整节讨论的正是"页面在说假话"。）
- **为什么现在不处理会更贵**：容器化之后"触顶"从"我们服务的故障"变成"用户世界的故障"，**用户没有任何办法自救**。文案与行为必须现在定：明确说、可重试、不许静默变慢。
- **塞进**：E 组（判据：容器内跑一个吃满内存的进程，用户必须收到一句话，且服务随后仍可用）。

**N9 · 用户的"垃圾桶"：agent 删掉的东西能不能找回**
- **问题**：A1 的清单是给"备份"用的，但**用户自己的文件被 agent 删了**不在讨论范围内。而"agent 能改自己"之外，"agent 能删主人的东西"才是日常最可能伤到人的那条。
- **为什么现在不处理会更贵**：它便宜得离谱（保留期 + 软删除目录），而一旦发生，**恢复成本全部压在 A2 的那份还没演练过的备份上**。

2. **A1 清单机器可读**，且清单里每条都有"怎么搬"的一句话（N3）。
3. **A2 加密 + 恢复演练**，并记下 **恢复分钟数**（W6）；**没演练过就停在这里**。
4. **A3 路径带 `userId`**：`DSH_HOME=/var/hupo/<userId>/dsh`。验收用例：两个用户都建"小升初"，各问截止日，**各答各的**；路径里没有 `userId` ⇒ 不许开第二个用户。
5. **E5/W5 每用户计量键**：trace 每行带 `userId`，键为 `{userId, uncachedInputTokens, outputTokens}`；一个用户触顶**不影响**另一个。
6. **W3 先回答"第二个用户是谁"**（家人 / 付费用户）——它决定 A3/A4/F2/F3/F4 的形状；没答案不开工。
7. **T3 迁移命令存在且演练通过**（用户 X 从容器 A 搬到 B，数据不丢、逐字节一致）。**这是我第一轮给的可测让步，现在正式写成分界。**
8. **A4 的 V1–V5 全绿**，且在**干净机器上重跑一遍**照样全绿。
9. 到此才允许开第二个席位。

### F1 · 收敛范围（"摘到哪一步算够"）——三层 + 一条定义

- **L1 提权**（现在验，零成本）：agent 会话内 `sudo -n true` **必须失败**。⚠ 本机现在**偶然**已满足 ⇒ 判据必须写成断言以防回潮。
- **L2 文件**（行为判据现在写，全量切在 E1 有答案后）：`workspace-write` —— **两个工作区并发写各自 root 成功率 100%、交叉写失败率 100%**；写 `/etc`、`/usr`、`~/.ssh`、`~/.dsh/settings.yaml`、其他项目目录**全部失败**。
- **L3 系统单元**（现在验）：agent 不许 `systemctl restart|stop|enable` 任何 unit；"重启自己"只能是调度器/宿主。
- **"够"的定义（三方收敛的关键）**：**只要还有一条路径能让 agent 的写入变成"下一个会话自动读到的东西"，就不算够**（KV / `AGENTS.md` / persona / settings preset / 工作区级配置）。判据 = §二-1 的 `grep` **= 0**。
- **对陆明的让步**：他的"禁 sudo / 禁写 unit / 禁碰他容器"我全收，作为 **L1 + L3 +（有容器后的 L2）**；但他必须接受 **L2 的行为判据**——否则"不碰他容器"在没有容器时无从验、有容器时又拦不住容器内写宿主挂载。

### E3 · 收敛：**走代理（a）是 v1 唯一形态；"算钱"这条理由删掉**

- **理由只剩两条**：① 容器里不该有真实模型密钥（`$DSH_HOME/.credentials.yaml` 就在容器里，见 A2/F4）；② **限流与审计需要集中一个点**。
- **"算钱"不能留，而且比第一轮更不能留**：① meter 全包**没有价格字段**（`grep -iE 'usd|currency|perMTok'` 在 `dsh-token-meter/lib/index.js` 命中 **0**；代码里的 "price" 一律指 token 数）；② 就算硬算，量被 cache read 主导（实测 **98.57%–99.75%**）⇒ **是一条会反向指引决策的假数**。
- **给陆明的 b 留一道门（不是否决，是条件）**：每容器独立密钥可以，前提两条同时成立——(i) 容器内**不存在任何 agent 可读的密钥文件**（F4 白名单 env + 密钥不进 `$DSH_HOME`）；(ii) **吊销一把密钥演练过一次**（记录时间与影响面）。缺一 ⇒ 默认 **a**。
- **限流口径**：按 `{userId, uncachedInputTokens + outputTokens}` 计；`cacheReadTokens` 单列、**不进阈值**。

### E2 · 收敛：**c（席位=1）+ b（退场机制=现在做）**，"换机器"三人一致砍掉

- **席位**：本轮只服务一个人，`userId` 只立接口不开席位；**闸门 = 上面 A4 的 1–9 步序列**。
- **现在必做（我改判的部分）**：全局 LRU + 主目录/调度器永远热 + 工作区 scale-to-zero。理由：只有 per-session 30 分钟 idle TTL、无全局 LRU（实测），195MB/agent vs `MemoryMax=1G` ⇒ **不做就是 OOM，不是慢**。
- **数值口径重算**：⌊1024/195⌋ = 5，含进程开销取 **3–4 并发**。
- **判据**：8:40 电梯问天气 **≤3s**；点 5 分钟未动的图标 **≤8s 且屏幕有字**；4 个工作区全开不撞顶；撞顶**必须有人话**（N8）。
- **对陆明的反驳**：他砍 E4 的"配额数字"我同意一半——**阈值可以校准，拒绝的动作不许晚**；而且他"内存闸 ≥0.75 拒"其实与我同条，我要求把它写成**行为**：拒绝时用户看到一句人话 + 服务随后仍可用。

## 四、B8 / B9 / C1 三条小分歧的收敛

### B8 · 未读标记（我 a / 沈简 b / 陆明 a）⇒ **a 为主 + 沈简那半降级为"一条静默分隔"**

- 形态：① 桌面图标小点（**服务端持久**，App 重启后还在）；② 用户**当前就在 App 内**时，时间线末尾插**一条**分隔（"你不在时，这里有过 N 条"），默认折叠、**不弹不响、不许打断正在输出的气泡**；③ **打开工作区即视为已读**（清除规则，N1）。
- 阈值与闸门：先做 ①②；**当"用户一周内至少 1 次因为没看见而未读到该看的内容"这个证据出现时**，才升级成完整的折叠段（沈简的形态）。
- 砍：未读数字、逐条动画、红点常驻。

### B9 · A 只有摘要时（我 a / 沈简 a / 陆明 b）⇒ **默认直说不知道；满足 R1–R5 才允许检索一次**

- **R1 归属唯一**：问题里能唯一映射到**一个已存在**工作区（工作区名/话题名/制品名，命中数 = 1）。命中 0 或 **≥2 ⇒ 不检索**；≥2 时正确的话是"你指哪一条？"。
- **R2 只用于定位**：检索产物只能是**指针 + 摘要**；检索结果**不许**作为新事实写回主目录、不许进 KV（C2）。
- **R3 原文不进 A 的上下文**：要原文就"**请 B 再答一次**"。这条让 N13 与 B9 不再冲突：**检索可以存在，但它的输出不是原文。**
- **R4 一次一条、超时 3s**：失败即直说不知道，**不许换关键词重试**（陆明的 ≤3s 我接，加"只一次"）。
- **R5 必须带出处**：答复带"这条来自 <工作区>"；**只有检索有结果时才允许给结论**。
- **必须直说不知道（无条件）**：① 归属不唯一；② 问的是"结论/偏好"而 KV 是 `unknown`（C3）；③ 检索超时/失败；④ 问的是"不可逆动作该不该做"（这类只有人拍板）。
- 判据：22:10 问"那个表里 2023 年那几篇"（归属唯一）⇒ **≤3s** 答出 + "在哪条工作区"；换成"上次那个号是几号"（归属不唯一）⇒ 必须问回去，**不许猜**。

### C1 · KV 语义抽取（我 b / 陆明 b / 沈简 a）⇒ **做，四前提 + 三段失败行为；沈简的 ≤3 次/周 作关闸（方向反过来：先做、按数据关）**

- 四前提（缺一 ⇒ 退到只机械）：① **异步**（"用户说话 → 看见第一句"这条路上不许出现抽取）；② 快模型 + 关思考；③ 每条带出处 `source:{chatId,scopeId,seq}`；④ 无出处只能进"待确认"。
- 抽取范围（接陆明）：只抽含**日期/数字/专名**的句子；`facts` 入库前 **无出处 = 0**。
- **语义抽取失败/出错时用户看到什么（议程直问，三段，必须不同）**：
  1. **超时/模型失败（没抽出来）** ⇒ **界面零变化**（它不是用户发起的动作），trace 记一行；若用户这一轮正好问到那条，答"**这件事我没记下来**"。⚠ 用词必须区分：不是"不知道"（= 世上没有），是"没记下"（= 我没存）。
  2. **抽出来了但无出处/置信度低** ⇒ 进"待确认"，**最多在下一次相关对话里以一句话出现**（"我记了这条，你看对吗？"），**必须带可点开的出处**；用户不确认 ⇒ **永不进受信层**。
  3. **抽错了（与原文不符）** ⇒ 唯一必须可撤销的一条：点开出处能看到原话 → **一次动作可删**（软删 7 天）；并且必须有"**今天它记住了什么**"的界面（沈简要的透明性我认，这也是这一条敢做的唯一理由）。
- 关闸：一周内"主人需要它记住上次结论"的轮次 **≤3 次/周 ⇒ 关掉语义抽取、只留机械索引**；**>3 次/周 且"无出处 = 0"成立 ⇒ 继续**。
- 砍：`experience`/`taxonomy`、每轮都抽、同步抽取、无出处入索引层。

## 五、我认为"现在不定就会返工"的前 3 条（其余排后）

> 判据只有一条：**不定的话，要不要改协议 / 迁移已有数据 / 做不可逆操作？** 要 ⇒ 前 3。

   - 为什么：这是**协议字段**。v1 显示上只写"它"可以，但**协议里必须带 `scopeId`**，否则以后补 = 改客户端 + 迁移数据。

3. **"收起来 vs 删掉"分档（陆明 #2）+ 我的 N9 / N11，必须与 A1 清单同批。**
   - 为什么：删除**不可恢复**；且 A2 的恢复演练一旦按 A1 清单跑，"制品留不留"就被固化——以后再改要重做演练。

   - 若不定：第一次误删就落在"那份还没演练过的备份"上。

## 六、token 用量口径的正确写法（一句可直接入档的话）

**替换 `docs/design/ai-phone-architecture.md:621` 的"✅ v7 §11'算不出美元'的前提是错的，接上即可"：**

> **token 用量：`dsh-token-meter` 已随 bundle 挂着，实测 21/21 会话的 `tokenUsage` 有非零计数（`uncachedInputTokens` / `outputTokens` / `cacheReadTokens`），但**没有价格表、没有 `userId` 维度、且总量被 cache read 主导（实测 98.57%–99.75%）** ⇒ **"计数可用、金额算不出"**：v7 §11"不显示估算美元"的结论保留，理由改写为"**没有价格表且总量口径失真**"，成本与配额一律用 `{userId, uncachedInputTokens + outputTokens}` 计数，cache read 单列、不进阈值。**

**回答议程提问（E3 的"算钱"还能不能留）：不能留。** 两条理由都不成立：① meter 全包无价格字段（currency 类词命中 0）；② 即便拿 token 数当代理，**98.57%–99.75% 是 cache read**（缓存命中价远低于未命中），这个数会**反向指引**决策（"谁读缓存多谁更贵"）。走代理（a）只留两条理由：**密钥不扩散** + **集中限流/审计**。
