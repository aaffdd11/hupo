# R2 · 02 · 陆明 —— 场景派 / 交付派（AI 手机这一轮）

> **我是谁**：我只问一句"主人今天会不会用它拿到东西"。
> **我怎么判断**：把用户放回具体那一分钟——几点、在哪、手上拿着什么、屏幕多大、网络好不好。
> **我信三件事**：没有交付物的助手只是聊天机器人；用户只记得最后一次成功；场景决定优先级，不是风险表。
> **我愿意牺牲**：完美的安全模型、极简主义洁癖。

## 〇、我这一轮最想说的一句话

**"一人一台容器"我要，不是因为要卖给别人，是因为它把我第一轮最想要的那件事白送给我——
agent 自己起的重活再也杀不掉他的对话（第一轮那 4 次 OOM 的根因就在这里）；
但"一个工作区几个人共用"我照砍。**

### 我这一轮立场变了一条（必须写明）

| 第一轮我说 | 这一轮我说 | 为什么变 |
|---|---|---|
| **砍掉"多用户 / 家人共用"这一整条路线** | **"一人一台容器"做；"一个工作区多人共用"砍** | 词没变，指的东西变了。第一轮的"多用户"= 两个人共用**同一个助手、同一份记忆**（必然稀释交付，我继续砍）。这一轮的"多用户"= 每人有**自己的**容器、记忆、工作区——那不是稀释，那是**隔离**。而我要的隔离不是安全，是**交付**：构建被杀 = 用户的活没做成，这是第一轮那四次事故的原话 |

除这一条外，A–G 上我的结论和第一轮的信仰完全一致，没有第二条立场变化。

## 二、D1 / D2 单独说

这两块是我第一轮那句"从'主人说完'到'他在屏幕上点开'的时间，今天是无穷大"的正面。**这一轮如果只保住一件事，就是它们。**

### D1 · 能力契约层（有接口的世界）

**结论：做。这一轮只做"登记表的形状 + 1 个真实数据源"。不做"云端数据服务"这个词带出来的全套。**

#### 场景推演

**▸ 第一次：周三 21:30 · 沙发 · 笔记本 1440 全屏 · 浏览器全屏**

他说「把上周那几篇论文按结论整理成一个能筛选的表」。

- 今天（已经能做到的）：agent 写一份 H5，说"放在工作区了"，然后**他拿不到**——交付形态只有编译进包里的 Flutter 原生页。**这就是无穷大。**
- 有小程序之后：那条消息里出现一个图标，他点开、筛选、拿到结果。第一版到这里就够了。

**▸ 第二次：下周三 21:40 · 同一个位置** ← **这一条才是契约层的存在理由**

他说「再加一个按年份排序的按钮，数据用上个月新下的那批」。

- **没有契约层会发生什么**：agent 从零再写一份。数据形状自己现编——上次"结论"这个字段叫 `conclusion`，这次叫 `finding`；筛选逻辑重写；上次修好的一个小 bug 回来了。于是他**同一件事有两个版本**，一个在消息记录里、一个在屏幕上。
- 而我信的是：**用户只记得最后一次成功。** 而"最后一次"是坏的那一次。
- **有契约层**：数据源和字段在登记表里，`paper.conclusion` 是写死的；这次只改渲染。他看到的还是那个表，只是多了一个按钮。

**▸ 第三次：周五 07:50 · 地铁 2 号线 · 手机 390 宽 · 单手 · 4G 两格**

他不改东西，只想瞄一眼筛选结果。手机不发运行时（G5），所以他看的是**制品**。

- 制品引用登记表里的 source id ⇒ 在任何屏幕上渲染出的字段都一样。
- 制品是 agent 一次性现编的 HTML ⇒ 同一个"工具"在两块屏幕上可能长得不一样，因为底下根本没有"同一个数据"。

**▸ 他会不会回来**

他连续两周每周改一次。第三次之后，这个表会变成"他每周五早上会打开看一眼"的东西。
如果第二次就数据不一致，**第三次他不会来**。这个窗口大概两周，过期不候。

#### 判据（可测）

- 同一意图做两次，产物字段与类型**逐字节一致**（把两份制品的字段清单 `diff` 出来）；
- 制品里裸 `URL` / `fetch(` 命中数 = **0**，只允许引用登记表里的 source id；
- "AI 只做组合和渲染，绝不发明接口"落成一句可查的话：登记表中不存在的字段，制品里出现即失败。

#### 我会砍什么

- 砍"云端数据服务"的全套（网关、鉴权、配额、DevPortal）——**这轮只做"登记表的形状"和 1 个真数据源**；
- 砍"用户自定义数据源 / 自己贴 API key"；
- 砍能力授权 UI（沿用 DECISIONS 第 6 条：再说一句话就是授权）。
- **代价**：这一轮看过去像 demo，只能演示一个数据源。我认——**先让它能重复，再让它能多**。

### D2 · 没有 API 的世界（银行 / 政务 / 挂号 / 快递）

**结论：做"声明式"这一半，不做"代执行"那一半。**
说人话：**agent 做全部可复述的部分，把不可逆的那一下留成一张"你只差这 30 秒"的清单。**

#### 场景推演

**▸ 场景一：周二 07:55 · 地铁 2 号线 · 手机 390 宽 · 单手 · 4G 两格**

他要给妈妈抢一个专家号。号源没有可用 API。

- **不做**：他说"帮我挂个号"，agent 说"这个我做不到"。→ 一台叫"AI 手机"的东西，在**最需要它的那一刻**说"我做不到"。这一条会直接决定他会不会把这台设备拿给别人看。
- **做全套代执行**：agent 拿他的账号密码，进去点、填、提交。失败不是理论：挂错科室、重复提交、买错号——**都是不可恢复的**。而 07:55 的地铁上，他**没有能力核对**。
- **做"声明式 + 人工最后一下"**：agent 查清哪天放号、要带什么材料、把要填的内容先备好、算出哪个时间段最容易点到；然后把**提交 / 输验证码 / 支付**留成清单。
  他看到的是一行行能照做的东西，而不是一个"正在为你操作"的转圈。

**▸ 场景二：同一天 12:10 · 公司食堂门口 · 手机 · 单手**

他打开 app，一眼看到那张清单，照着点了两下，挂上了。
**交付物是一张清单，不是一个自动执行器。**

**▸ 场景三：他会不会回来**

- 做成"全自动"：第一次出错（钱、号、提交出去的东西），他再也不用。
- 做成"清单 + 最后一下"：它每天都能用一点，而且**每次成功他都在场**——他记得最后一次成功，因为**那次是他自己按下去的**。

#### 判据（可测）

- 一份代办清单里，**至少有一个动作是主人做的**（不合格 = 全自动，不接受）；
- "往外发钱 / 提交申请 / 输验证码 / 人脸"这几类，agent 一律不代做，且在清单里标出来；
- 整份清单主人能在 **30 秒内**走完（超过 30 秒就说明它没把该做的做完）；
- 失败时给的是"卡在第几步 + 怎么接着做"，不是"失败了"。

#### 我会砍什么（以及和 D1 的关系）

- 砍模拟点击操控 APP（沿用已否：UI 一改就碎、无法审计、延迟高）；
- 砍存银行 / 政务凭据（**存了就等于把"不可逆"交出去了**）；
- 砍通用 RPA、"自动重试直到成功"、"后台帮我盯着抢"。
- **代价**：它永远不是全自动，"AI 手机"的卖点少一半。我认。
- **关系**：D2 **不新开一套**。D1 的登记表里，"代办清单模板"就是其中一类条目——有接口的走 source，没接口的走 checklist。两条腿一张表。

## 三、议程上没有的问题　← 这一节最关键

格式：问题 / 为什么现在不处理会更贵 / 建议塞进哪一组。

### 1. 桌面图标墙没有上限、排序和归档规则

- **问题**：工作区 = 桌面一个图标（1:1:1:1），但没人定：多少个算多、按什么排、多久没用自动收起来。
- **为什么现在处理更贵**：图标墙是**交付物的唯一入口**。等他攒到 20 个再定规则，就是在他已经记住空间位置之后**重排他的桌子**——他会迷路，而且会觉得"我东西乱了"。现在决定只是几行规则。
- **建议塞进**：**B 组（B10）**。具体：默认按"最近用过"排；超过 12 个时**提议**归档；归档用 `dsh-workspace` 原生能力（"removes projects **without deleting**"），且归档入口一眼能找到。

### 2. "收起来"和"删掉"没分档，而删除会碰到记忆和制品

- **问题**：他点图标上的"删除"，删的是图标、目录、`$DSH_HOME/sessions/`、还是 `/data/hupo/apps/` 里的制品？§4.2 说 workspace 不拥有记忆——**产品上没写清**。
- **为什么现在处理更贵**：误删记忆**不可恢复**，事后他只会说"它把我东西弄丢了"。而且这一条的 UI 出口（两档）必须在第一版就有：补的时候要改协议，还要改他已经养成的空间习惯。另外 A2 的恢复演练一旦按 A1 的清单跑，"制品留不留"就被固化了。
- **建议塞进**：**B 组（B11）**。具体：默认动作是"收起来"（**不删数据**）；"删掉"必须写清删哪些路径（直接用 A1 清单里的原话），且**不提供**"一并删除原始会话"这个选项。

### 3. 一条消息有两个时间，补发时显示哪个没定

- **问题**：全局 `seq` 由调度器分配（§8），所以"发生时刻"和"入库/补发时刻"不是同一个。他 22:00 打开 app，会看到 16:00 的事按 seq 补进来。
- **为什么现在处理更贵**：v6 附八那次"从 15:31 挂到 16:39"就是这个形态的灾难版。时间线一旦说假话，他就没法判断"这活是刚干完还是拖了三小时"——而"我单独拿去做，完了跟你说"是长任务**唯一**的交付形态，它的信任全靠这个。客户端已经在渲染时间，改规则要动客户端。
- **建议塞进**：**B 组（B12）**。具体：显示用**发生时刻**；补发那一段必须带一句静默分隔（"你不在时"）；**不许**把补发时间显示成现在。

### 4. B 的汇报在时间线上"发言人是谁"没定义，也没有可点开的指针

- **问题**：来源标记扩到 `user / dispatcher / agent:<scopeId>`（§9），但客户端气泡的发言人只有"我 / 它"两档；B 说了什么，A 又是**根据它**去做的动作，主人看不到那句原话。
- **为什么现在处理更贵**：这是**协议层字段**。等有 5 个工作区再补 = 改客户端 + 迁移已有数据。而"同一件事前后两个人在说"正是"换了个人"最容易暴露的地方（N20 说事实不能静默，但只提了未读标记）。
- **建议塞进**：**B 组（B13）**。具体：v1 显示上可以只写"它"，但**协议里必须带 scopeId**；B 的汇报要能点开看原话（配合我的 B9：拿指针去检索）。

### 5. 三级预算按谁算（每人还是全局）

- **问题**：DECISIONS 第 5 条的 75/90/100 是在"一个用户"的世界里定的。一人一台容器之后，分子是每个 `userId`，还是整台机器？
- **为什么现在处理更贵**："**必须在开口之前停**"意味着调度器在投递前就要知道配额——这是记账位置 + 协议的事。先按全局做，第二个用户上线那天，一个人的活会停掉另一个人的，而且**理由说不清**。
- **建议塞进**：**E 组（E5）**。具体：按 `userId` 算，一个用户触顶只影响他自己；容器外留一份每用户用量账（`dsh-token-meter` 在容器内，靠桥接上报）。

### 6. 多设备焦点（v1 必须先写死一句）

- **问题**：手机 + 平板/网页会同时在线。而"焦点"是"这句话投给谁"和"未读怎么算"的**唯一依据**（§7.1）。
- **为什么现在处理更贵**：协议一旦把焦点当单值，第二个设备一登录就会出现"我说的话它没听见"或者"答案跑到另一个屏幕上"。这种 bug 最难查，而且直接打掉信任。
- **建议塞进**：**G 组（G7）**。具体：v1 **写死"一个用户一个活跃设备，第二个登录踢掉第一个"**（简单、可解释、能写进文档）；多设备焦点等真有需求。

### 7. 新用户的第一分钟（空桌面）

- **问题**：他装完 app 打开，看到的是一张空桌面 + 一个聊天框。"AI 手机"这个词承诺了一个桌面，但第一天桌面上什么都没有，他不知道自己能干什么。
- **为什么现在处理更贵**：第一分钟决定他会不会回来（信仰②③）。而且空状态和图标墙的规则（第 1 条）**是同一套东西**——等图标墙定型再补空状态，等于重做一遍。
- **建议塞进**：**G 组（G8）**。具体：空桌面上给 **3 个可以直接点的动作**（不是教程、不是"欢迎使用"），点一下就走完一件事——例如"把这张截图里的信息整理成表"。
