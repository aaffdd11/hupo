> **上游**：`SYNTHESIS.md`（十份走查的汇总）。
> **本文的任务**：把那些问题变成**要做什么**，并且分清"一个改动解决一批"和"逐条要单独处理"。

根因级的一次改动，能一次带走一批——**这就是为什么先看根因、再看逐条**。

## R1 · "按下发送"到"第一个字"之间是空的

### 现象（10/10 都撞到）

- 03：话在屏幕上，然后**没有任何一样东西是活着的** → 判它坏了
- 04：**6 秒**没第一个字就上划杀掉
- 06：等待期只有 **11px 灰点无字**，数到三就以为坏了
- 04：冷启动 **2.7–5.1s 正好吃在最贵的三秒里**，屏幕只有白屏+转圈
- 09：失败时**连小转圈都消失** ⇒ 界面把"发不出去"显示成"发出去了"

### 根因

现在整条链路上，唯一承担"我在干活"的是服务端的 `StreamStatus`（"正在查…"），
而它**要等第一个气泡出现才有**。在它之前：

```
按下发送 ──────── 本地把话画上屏 ──────── 【空白】 ──────── 服务端第一个气泡
                                          ↑ 这里什么都没有，可能 1 秒，可能 5 秒
```

而且"失败"这个结果**没有自己的长相**——`pending` 从 `true` 变 `false`，
不管成功失败都一样，所以失败看起来就是成功。

### 解决方案（四件事，按时间顺序）

**① 按下发送的同一帧：那条话旁边给一个"已经交出去了"的确定信号**
不是转圈（转圈=不知道），是一个**确定的**标记：比如一个对勾从灰变实。
04 要的就是"知道自己没坏"，不是"更快"。

**② 200ms 内还没有服务端回应 → 本地先出一句应声**

> **这是 03 说的"微信会先给我一个字"**，也是这一条里最关键的改动。

- 由**本地**先出，不依赖网络、不依赖模型
- 话术固定且极短（"收到""在看""我翻一下"）
- 必须**进 `message/status` 那条通道**（不是消息、不进历史）——
  **这条通道你们已经有了**，只是要把它从"服务端下发"提前到"本地兜底先出"
- 服务端的 `StreamStatus` 一到就**替换**掉本地那句（不要两条并存）

> ⭐ **升级选项（已拍板，见 `R2-DECISIONS.md` 的 D7）**：做了 D7（展示"在做什么"）之后，
> 这句应声可以**从固定话术升级成真实动作**——不是"收到"，是"**我去查一下上海现在的天气**"。
> **同样一件事，效果差很多。** 所以 R1 和 D7 应该同批做。

**③ 给消息一个真状态机，而不是一个 `pending` bool**

```
排队中 → 已送出 → 已确认（服务端回了） →┐
   └──────────────→ 失败 ────────────┘（可重发）
```

- **四种状态必须视觉可区分**（09：现在四种里有两种长得一样）
- **失败必须有自己的长相** + **一个重发按钮**
- **收起态也要显示失败**（09：现在失败红字只在展开时显示）
- 修 B2：`chat_controller.dart:420` 注释承诺的"界面提供重试"**不存在**，要么兑现要么删掉注释

**④ 启动时先画本地最后一屏，再去补**

修 B6：`timeline` 只在内存 ⇒ 刷新/杀进程后**一片"说点什么"的空屏**。
冷启动先渲染本地缓存的一屏，再走网络补齐（`sinceSeq` 那套本来就能补）。

### 归属
工程席位：**前端与体验**（③④）+ **协议与时序**（②的 status 通道）
需要主人拍板：**无**（这条没有取舍，只有做不做）

## R2 · 时间线上没有"我在哪一层"和"谁在说"

### 现象

- **工作区 10 个人里 0 个发现**
- 04 / 07 / 10 都说"**不知道我在哪一层**"、"感觉不到切换 = 不知道这里换过东西"
- 08：快答+深答拼一条且明确"不加标签" ⇒ **分不出哪段是自己写的**
- 07：两个图标同名又不能改名 ⇒ **会记错工时**（对他是生死线）

### 根因

时间线是**唯一**的表达界面，但它只表达了"话"，没表达"**谁说的、在哪一层说的**"。
`scopeId` 和来源字段（X2 已拍板"现在就留"）**只留在了协议里，界面上一个字都没有**——
那 X2 就没有验收对象。

### 解决方案

**① 一条常驻的"我在哪"锚**

不是切换时闪一下，是**一直在**。放在浮窗顶栏那一行（现在那里放的是最新一句话）：

```
小升初 ·  26 条                        ← 这一行常驻
─────────────────────────────────
```

- 名字**由用户给**（见 ③）
- 10 说得具体：他在平板上多窗口来回切，**最需要这个锚**
- 这一行同时解决 04 的"我不知道自己在哪儿"

**② 每条消息带一个轻的来源**

不是标签墙，是**一眼能分**：自己的话靠右（现在就是），
它的话靠左（现在就是），**但"来自别的层的话"要有第三种长相**（比如左侧加一个很轻的竖线 + 一行小字"小升初那边"）。

- 08 要的就是这个（他分不清哪段是自己写的）
- 04 说"需要看三四次才懂"——**所以它得一直在，不是第一次就指望看懂**

**③ 名字由用户给，系统只用他话里的词**

三个人分别提了三种叫法：

| 谁 | 他说的词 |
|---|---|
| 05 | 小升初（**他自己说的词**） |
| 07 | 项目 |
| 06 | 你的药 / 你儿子家 |
| 08 | 这篇文章的地方 |

⇒ **规则**：系统提议名字时，**只能用用户自己说过的话里的词**（他说"小升初"，就用"小升初"），
**不许用我们造的"工作区"**。而且**允许改名**（07 的生死线），**允许重名时自动区分**。

**④ 进去/出来时，时间线上要有一个可见的分隔**

X1.6 已经定了"补发段带『你不在的时候』"。这里再加：

```
───────── 进入「小升初」 ─────────
```

这样"换了地方"这件事在**时间线上是看得见的**，而不是靠用户猜。

### 归属
工程席位：**前端与体验**（①②④）+ **协议与时序**（`scopeId` 落到事件里）
需要主人拍板：**无**（但"名字由用户给"这条要用在 P4 的能力命名上）

## R3 · 一切都是静默的

### 现象

| 谁 | 什么被静默了 |
|---|---|
| 03 | 桌面冒出方块，**没人告诉我**，还删不掉 → "流氓软件" |
| 05 | 桌面凭空多出图标 → "**中病毒了**"，会去问妹夫 |
| 04 | 后台做完**只留桌面一个小点，而桌面在浮窗后面** |
| 09 | 发送失败**静默**（收起态连红字都没有） |
| 02 | **失忆不报错**——它没有"我缺了一块"这个可表达状态 |
| 07 | "删除账号"有入口、"导出"没有 ⇒ 这个不对称**直接触发信任问题** |
| 02 | 记忆说"记下来了"，但**没有任何地方能回看** |

### 根因

**系统替用户做的每一个决定，它都不说。** 而"说了"这件事的成本极低。

这正好命中已拍板的 **N20（动作可静默，事实不能静默）**——
但走查证明 **N20 的范围划小了**：05 明确请求

> **N20 请把"桌面多了一个图标"算作事实——存在不能无感，动作可以无感。**

### 解决方案

**① 建一条"系统说话"的通道**（这是根因级的做法）

它**不是聊天气泡**，是一个独立的状态/通知层。所有"系统替用户做了决定"都走它：

| 什么时候 | 说什么 |
|---|---|
| 桌面新增了一个物件 | "小升初聊得挺多了，我给它单独开了个地方，在桌面上" + **一键撤销** |
| 后台的事做完了 | 推一条（不是只在桌面上点个小点） |
| 某条消息发失败 | 明确说"这条没发出去" + 重发 |
| 它翻不到某段记忆 | "这段我手上没有，我去翻一下"（**别装作记得**） |
| 一个物件被收起/删掉 | 说清去哪了、怎么找回来 |

**② 桌面是"有生命的"，不是静态的**

- 02 的洞察最关键：**"桌面是静态的，所以不会想它是动态的"** ⇒
  桌面必须**自己有动静**（新物件出现时有可见的动作 + 一句话）
- 04 的实测：**未读红点是唯一有效的入口** ⇒ 红点不是锦上添花，是入口
- 长按可删（03：微信长按可删是既有心智）

**③ L 失忆必须可表达**（这条最深）

02 说得很准：**它语气前后一致、会往前接，但没有"我缺了一块"这个状态。**

解法接上已经拍板的 **B9（有条件检索）**：
把"被问到细节时去检索"**扩展成"自己发现可能缺了一块时主动去翻"**。
翻不到就直说"这段我没有"——这比装作记得便宜，也比装作记得可信。

**④ "删除"与"导出"必须对称**

07 的这条是**信任问题**，不是功能问题。
现在设置里"删除账号与全部数据"有正经入口，"导出一份"没有 ⇒ 用户会想到"它能删，我不能拿"。
⇒ 这两个动作要么都有，要么都没有。**建议都有。**

**⑤ 记忆必须有一个可见的出口**

- 一份"**它记住了什么**"的清单（能一眼看到、**能一条条删**）
- 关键结论旁边要有出处：**"（你 9 月 16 日说的）"**
- 05 的原话是这一条的价值所在：**"没有它我不敢跟它说真话"**

### 归属
工程席位：**前端与体验**（①②④）+ **安全与运维**（⑤的删除/导出）+ **协议与时序**（③的检索触发）
需要主人拍板：**记忆出口的形态**（清单放哪、长什么样）

## R4 · 内部词汇直接暴露

### 现象

| 内部词 | 谁被卡住 |
|---|---|
| **口令** | 03（不知道那是什么，微信抖音都是验证码）· 06（**因此直接放弃**） |
| **连接** | 03 · 06（"正在恢复连接…"被读成坏了） |
| **工作区** | 05（"会读成上班干活的地方"）· 06 · 07 · 08 |
| **客户端 / 云端 / 版本号 / 序号** | 03（「关于」页全读不懂） |
| 登录页那句"能执行命令、能改自己的代码" | 03：**读完是害怕，不是放心** |

而 02 同时指出：**那句是全 App 唯一诚实交代能力边界的地方**，建议保留这种诚实。

⇒ **一个真张力：诚实 vs 恐吓。** 不是二选一，是**换个说法**。

### 解决方案

**① 一份术语替换表（发布前逐条检查）**

| 内部说法 | 界面上说 |
|---|---|
| 口令 / 密码 | **"进门的暗号"** 或直接"密码"（微信用户更熟"密码"） |
| 连接 / 正在恢复连接 | **"网断了，我在等它回来"** |
| 工作区 | **用户自己给的词**（见 R2③） |
| 客户端 / 版本 | 不出现（放进"关于"里，非技术用户不看就不该看到） |
| 云端 / 服务器 | 不出现 |
| 会话 | "聊天" |

**② 检查做成一道闸**

> **界面上出现内部词 = 缺陷**（不是文风问题）。

这条可以机械化：维护一份"禁用词表"，在测试里扫界面文案
（`smoke_test.dart` 里已经有一条"产品界面无内部分类词"，**把它扩成正式的禁用词扫描**）。

**③ 登录页那句重写：诚实，但不用黑话**

保留"它会自己动手、不只是聊天"这个**诚实的内核**，换成用户能懂且不害怕的说法：

| 现在 | 改成（示意） |
|---|---|
| "这台机器上的助手能执行命令、能改自己的代码" | "它不是只陪你聊天的——你说的事它真的会去做。所以这道门只有你能进。" |

**并且**：02 建议**对记忆也照此说一次**（"它会记住你说的重要的事，你可以随时看看它记住了什么"）。

### 归属
工程席位：**前端与体验**
需要主人拍板：**登录页那句话的最终措辞**（这是产品声音，得你定）

## R5 · 布局把"手机的比例"当成了普适前提

### 现象（都有实测数字）

- **10 平板**：浮窗宽 **1260px**，内容被卡在 532px，**右边 675px 全空**；
  图标 52×52 落在 **314px** 格子里（占 **16.6%**）；`_columns = 4` **写死**；
  浮窗高按屏高比例（横屏拉满 **97.3%**）；**每说一句每收一句都自动拉满 ⇒ 桌面反复被抹掉**
- **06 老人**：图标名 **11**、收起行 **12**、桌上名 **14** 全是常量，**系统字体调最大它们不变**；
  收起 124px 里**只剩 9px 给消息**；唯一按钮约 **40px 且无字**；拖拽按速度判甩，**手抖就甩没**
- **08 写作**：`_pageSize = 10` 按"**条**"分页，而他一条 600 字 ⇒ **翻页形同失效**

### 根因

三个不同的尺寸都用了同一个错误假设：**"屏宽就是手机宽度、条数就是阅读单元、字号是固定的"**。

主人早先说过要靠 **responsive + 定制化的 padding/margin** —— **这批走查正好给出了"定制化"的具体清单**。

### 解决方案

**① 内容列加上限，横屏改两栏**

| 情形 | 怎么做 |
|---|---|
| 宽 > 900 | 内容列限宽（你们文档里已有 **760**），**两侧留白居中** |
| 横屏平板 | **左列 = 物件列表，右列 = 对话**（10 说这是"大屏最省解释的形态"：左列天然显示"我在哪"） |

**② 尺寸/列数随屏宽变，不写死**

- 图标尺寸和 `_columns` 按可用宽度算（不是固定 4 列 + 固定 52px）
- **触控目标 ≥44**（你们文档里已有这条，但老人实测那个箭头只有约 40px 且无字）

**③ 浮窗高度改"绝对档位"，不用屏高比例**

现在是 `124 + (屏高 - 146) × hFactor` ⇒ 屏越高占得越多（横屏拉满 97.3%）。
改成固定档：**收起 / 半屏 / 大半屏 / 满屏**（绝对像素），并且**转屏时重置到最近档位**
（现在转屏 `_hFactor` 不重置，10 实测"每次转屏都重新决定占我多少桌面"）。

**④ 自动拉满要收敛**

10 的放弃点是"**每说一句、每收一句都 `_maximize()`**" ⇒ 一边做别的事时桌面被反复抹掉。
⇒ **只在"用户主动说话"时拉满；助手回话时不动高度**（或者做成可关）。

**⑤ 分页按"内容高度"，不是按"条数"**

08 的整条链路都卡在这里。改成：

- 按**渲染后的高度**分页（不是按条数）
- **显示还有多少**（"上面还有 34 条"）
- **可搜索**、**可按时间跳**
- 长消息**不和短消息用同一套分页**（他一条 600 字，10 条分页等于一次放出 6000 字）

**⑥ 字号必须可调，且跟随系统**

- 11 / 12 / 14 这些常量**必须走主题的字号**
- 老人档：**字体放大后，浮窗收起高度要跟着长**（不然 124px 里还是只剩 9px）

**⑦ 误触必须能自救**

- 收起后**有一个看得懂的展开入口**（不是 40px 无字箭头）
- **"甩"要能关**（手抖就甩没 = 06 的第二次放弃点）
- 收起态点外面不该"什么都不做"（06 试过，没反应）

### 归属
工程席位：**前端与体验**（主）+ **协议与时序**（分页/搜索要能查服务端历史）
需要主人拍板：**平板是不是主目标设备**（见下）

## 需要你拍板的六件事

| # | 要拍什么 | 我的建议 | 为什么必须你定 |
|---|---|---|---|
| **D1** | **界面上的"物件"叫什么** | **用用户自己说过的词**（他说"小升初"就叫"小升初"），系统提议时不许用"工作区" | 这是产品声音 |
| **D2** | **登录页那句话的措辞** | 保留诚实内核、去掉黑话（见 R4③） | 这是产品声音 |
| **D3** | **老人档做不做** | **做**。理由：你的设备里已经有平板（大屏），而"字号可调 + 语音输入"是同一批改动 | 一个人的产品里，"以后做" = "永远不做"。要么排进去，要么明确写下"不做、且已知某类人用不了" |
| **D4** | **平板是不是主目标设备** | 如果主力是手机，平板档可以排后；**但你自己就是平板用户**，所以建议至少把"内容列限宽 + 自动拉满收敛"这两条放进第一批 | 决定 R5 的排期 |
| **D5** | **语音输入做不做** | 做。06 的门口就是它（不会拼音 = 门没开） | 涉及权限申请（录音），是产品决定 |
| **D6** | **P4 第一个数据源换成什么** | 换成一个**目标用户真的会反复问**的能力（07：他需要的是"工时/报价"，天气不是） | 见下 |

### 关于 D6（这条是我自己选错，得改）

我在 P4 上建议用"天气"当第一个真数据源，理由是"现成的、客户端里已经有 584 行"。
**07 证明了这是错的**：

> 天气不是我的需求。我最需要的"工时/报价"恰好是**未登记能力**，
> 于是要么当场编字段（不可复现）、要么说不会（**第一周就走**）。

⇒ **用一个"用户不需要的能力"去验证"能力契约能不能成立"，样本本身就有偏。**
建议换成目标用户会**反复问**的那一类（记一笔账 / 记一条名单 / 记一个日期）。

## 解决顺序（建议）

| 批 | 做什么 | 为什么先做 |
|---|---|---|
| **第 1 批** | **R1 全部**（首字前的应声 + 消息状态机 + 本地缓存）+ **7 条 bug**（B1–B7） | 它们对应 **8/10 的放弃点**，而且都是**低成本、高确定性**——不需要任何新设计，只需要把现有承诺兑现 |
| **第 2 批** | **R2 全部**（"我在哪"的锚 + 说话人 + 名字由用户给） | 它决定"工作区"这个概念能不能被发现；**不做，后面所有跟工作区有关的功能都没人看得见** |
| **第 3 批** | **R3 全部**（系统说话通道 + 记忆出口 + 删除导出对称） | 它是"敢不敢把事交给它"的地基 |

| **随时** | **R4**（术语表 + 禁用词扫描 + 登录页文案） | 成本极低，且**越早做越好**（文案一旦铺开就难改） |

## 一句话

> **十份走查真正的产出不是那 200 条问题，是那五个根因。**
> 而五个根因里，**四个都是"系统没说话"**——没说它收到了、没说它记住了、没说它在哪一层、没说它替你做了什么决定。
> 所以这一轮最大的收获可以压成一句话：
> **把省下来的每一个字，花在让用户知道发生了什么上。**
