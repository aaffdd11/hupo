# 用户体验走查 · 合成（10 个不同用户）

> **输入**：`docs/ux/01-owner.md` … `10-tablet.md`（十份第一人称走查，共约 2400 行）
> **方法**：见 `README.md`。**走查对象是计划中的产品**，对照现状（已出的 APK）。
> **纪律**：每条结论都点名到"哪一屏、哪句话、哪一步"；含糊的抱怨不进这份稿。

## 〇、最重要的一条：十个人的放弃点，指向同一件事

十个人，身份横跨"只会用微信"到"会抓包"，居然**收敛到同一件事上**：

| 谁 | 他会放弃的那一步 |
|---|---|
| 01 主人 | 拿到命令但人在手机上 → **改主意的窗口被关掉了** |
| 02 技术 | 它说"我记下来了"，而**我无法验证** |
| 03 不技术 | 话发出去了，**没有任何一样东西是活着的** → 判它坏了 |
| 04 通勤 | 按发送后 **6 秒**没第一个字，上划杀掉 |
| 05 家长 | 第 5 次问，它给了旧日期，**没标出处、语气还很肯定** |
| 06 老人 | **登录页第 30 秒**——不会拼音，门就没开 |
| 07 自由职业 | 要出报价单发客户时，它**给了一段发不出去的字** |
| 08 写作 | **找不到半小时前写的那一段** → 退出、开备忘录 |
| 09 断网 | **丢一次字就走**——忍不了"看着像发出去了，其实没说出去" |
| 10 平板 | 每说一句、每收一句，**桌面就被抹掉一次** |

**抽象成一句话**：

> **"它到底活着没有、记着没有、说的是不是真的"——这件事用户无法验证，而系统自己也不说。**

十个人里有 **八个** 的放弃点落在这件事上。这不是十条独立的体验问题，**是同一个洞的八种表现**。

## 一、致命问题（多数人会在此放弃）

### ★ 致命 1 · 发出去之后，没有任何"活着"的信号

**十个人全部提到等待期。** 而且他们脑子里唯一的对照物是**微信**。

| 谁 | 原话 / 实测 |
|---|---|
| 03 | 屏幕上出现我说的话了，然后**没有任何一样东西是活着的**——没转圈、没"正在想"、连个"嗯"都没有。我又按了一次箭头，那一刻判它"坏了" |
| 04 | 7:55:12 按下发送，7:55:19 除了转圈还没第一个字 → **上划杀掉**。对手不是别的 AI，是"我自己翻微信，七秒能翻到" |
| 06 | "它在想"只有 **11px 灰点、无字**，我数到三就以为坏了 |
| 04 | 冷启动 **2.7–5.1s 正好吃在我最贵的三秒里**，屏幕上只有白屏和转圈 |
| 04 | 容忍线：**打开到能打字 3s / 首字 6s / 首字到可用 8s** |

> **注意**：这不是"要更快"。04 明确说"慢我会以为坏了，会重发"——他要的是**知道自己没坏**。
> 现有设计里唯一承担这件事的是 `StreamStatus`（"正在查…"），
> 但它**只在有气泡之后才出现**；从"按下发送"到"第一个气泡出现"这一段**是空的**。

### ★ 致命 2 · 记忆不可验证 ⇒ 黑盒记忆 = 默认没记住

| 谁 | 原话 / 实测 |
|---|---|
| 02 | 它说"记一下"会确认，但**没有任何界面能回看/删除**。设置页里唯一能回答"它记住了什么"的两条入口都写着"（待接入）"，点下去是 SnackBar「尚未接入」⇒ 我**永远无法区分"真记住了"和"顺着我的话说"** |
| 05 | 关键结论没有"（你 9 月 16 日说的）"这种小字。**看不见的记忆我一律不信**——我一周截 24 张图就是证据 |
| 05 | 第 5 次问报名时间，它给的是我周一那个旧日期，**没标出处没标时间、语气还很肯定** ⇒ 放弃。不是答错（当场承认我能接受），是"**记不住还说得跟真的一样**" |
| 02 | **失忆不报错**：跨重启只回灌最近 8 条用户发言（`timelineContext` 的 `maxTurns = 8`），更早的真没有，但**它语气前后一致、还会往前接** ⇒ 它没有"我缺了一块"这个可表达状态 |
| 07 | 上月按它给的表报给客户 **5000**（12.5h×400），这月同样问法给 **11.5 小时**，**我只在客户问起后才知道** |
| 08 | 我唯一的验伪办法是"你把我写的第一段复述一遍"——而这个**被系统明令禁止**（`dispatcher.js` 的 `recapPrompt` 写着"不要复述它"） |

⇒ **这条直接命中架构里的 N14**（"主作用域可以不知道细节，但不许替它编细节"）。
但走查发现的问题比 N14 更前一步：**用户连"它到底知不知道"都看不出来**，所以 N14 没有验收对象。

### ★ 致命 3 · 失败与成功长得一模一样

**09 是唯一一个读了代码去核实的**，他挖出四条（**都是真 bug，见 §四**）：

- 失败时**连小转圈都一起消失** ⇒ 看着就是"发出去了"
- **没有重发按钮**——而 `chat_controller.dart:420` 的注释写着"保留在时间线上，由界面提供重试"，**界面里一个字都没有**
- 失败红字**只在展开状态显示**，收起时静默失败；文案是 `ClientException with SocketException: …`
- 刷新/杀进程后**屏幕全空**（`timeline` 只在内存）

原话：**"发失败我能忍，忍不了看着像发出去了、其实没说出去。第二次直接卸。"**

### ★ 致命 4 · "工作区"这个概念，十个人里 **0 个** 发现了

十位全部明确说"没有发现"。而且更糟的是**它出现的时候会吓到人**：

| 谁 | 原话 |
|---|---|
| 03 | 方块冒出来时没人告诉我、长按也删不掉 ⇒ 我第一反应是"**流氓软件**" |
| 05 | 桌面凭空多出"小升初"图标没人告诉我 ⇒ 我第一反应是"**中病毒了**"，会去问我妹夫 |
| 02 | 桌面是静态的，所以**不会想它是动态的**；"会话"在用户心里就是聊天历史，绝不会被理解成记忆分区 |
| 01 | 桌面图标点开是整页小程序，计划却说"点进去还是在聊天"——**两种心智模型在同一个桌面撞车** |
| 07 | 我第一反应是"它给我装了个应用"，点进去还是聊天就判定"**点开跟没点一样**" |
| 10 | 模型层面发现了（图标变多），但**"我现在在哪个工作区"一次都没确认成功** |

**而 04 给出了唯一有效的入口**：

> **一周里唯一一次主动点桌面，是因为图标上出现了小红点。**
> **没有未读标记，桌面图标对我来说就是死的。**

⇒ 这**验证并加强了 N20**（"动作可静默，事实不能静默"），而且**范围要扩大**。
05 明确请求：

> **N20 请把"桌面多了一个图标"算作事实——存在不能无感，动作可以无感。**

**还有一个用词问题（05、06、07 三个人各自提的）**：

| 谁 | 他说那东西该叫什么 |
|---|---|
| 05 | "工作区"这个词我看不懂（会读成上班干活的地方），界面上别出现 |
| 06 | 对我它是"出黑板报的角落"，建议图标就叫"你的药""你儿子家" |
| 07 | 请叫"**项目**"：能改名、进去要一直显示我在哪个项目里 |
| 08 | 我不要"工作区"这个词，我要的是"**这篇文章的地方**" |

⇒ **名字必须由用户给，或者用他生活里的词。**"工作区"是我们内部的说法。

### ★ 致命 5 · 看不见的边界 ⇒ 不敢说真话

| 谁 | 原话 |
|---|---|
| 05 | 没有"它到底记了我什么"的清单（要能一眼看到、**能一条条删**）——**没有它我不敢跟它说真话** |
| 07 | 架构 §3.3 的状态清单**在界面上一个字都没有**；而"删除账号与全部数据"有正经入口、"导出"没有 ⇒ 这个不对称**直接触发信任问题** |
| 02 | 记忆没有出口 ⇒ 不可验证 ⇒ 黑盒记忆 = 默认没记住 |

## 三、分人群问题

### 06 退休老人 —— **门就没开**

| 问题 | 实测数字 / 出处 |
|---|---|
| 登录页只有"口令"打字框，**我不会拼音** | 30 秒放弃 |
| **没有话筒、没有按住说话** | `AndroidManifest` 只申请了 `INTERNET`，无录音权限 |
| **小字写死调不大** | 图标名 **11**、收起时那行 **12**、桌上名 **14**，全是常量 —— 把系统字体调最大它们不变 |
| 收起 124px **实际只剩 9px 给消息** | 抓手 14 + 那行字 32 + 输入框约 45 + 手势条约 24 ≈ **115** |
| 唯一能看的那行还被砍断 | `maxLines: 1` + 省略号 |
| **误触收回后无法自救** | 唯一按钮是约 **40px、无字**的箭头；展开靠双击抓手（无提示）；收起态点外面不做事 |
| 拖拽按速度判甩（`>650`），**手抖就甩没** | — |
| 发送是 **20px** 的 ↑，与"停圈"只隔 **4px** | — |
| 屏幕出现"正在听…"，但那是"它不出声"，不是听我说话 | 我会对着手机说话，然后以为是我笨 |

### 10 平板 —— **宽屏是坏的（而且算得出数字）**

| 问题 | 算出来的 |
|---|---|
| 浮窗左右各留 10px ⇒ 宽 **1260px**；内容被 `maxWidth: 560` 卡成 **532px** | **右边约 675px 完全用不上**（不是"一行太长"，是一半宽度浪费） |
| 竖屏 780px 反而**刚好用满** | 同一份代码**横屏怪、竖屏对**，而横屏是主要用法 |
| 图标 52×52 落在 **314px** 的格子里（占 **16.6%**） | 图标间空 **262px**；`_columns = 4` **写死**，屏再宽也只放 4 个 |
| 浮窗高按屏高比例 ⇒ 横屏拉满 **97.3%** | 桌面只剩 **12px** 顶缝 |
| 转屏 `_hFactor` **不重置** | AndroidManifest 的 `configChanges` 含 `orientation｜screenSize` 且无 `screenOrientation` ⇒ 每次转屏都重新决定占我多少桌面 |
| 拉满时"离底 160px 自动滚底" | **转屏把正在读的那段滚走** |
| 键盘占 330px ⇒ 横屏 app 只剩约 **470px** | 半开档 **286px** ＝ 一次一条消息，打字时读不到上下文 |
| **无左右分栏**（"左边列表右边对话"一次都没出现）；分屏 640 宽只是"被挤窄的手机版" | 外接键鼠基本没考虑 |
| **每说一句、每收一句都 `_maximize()`** | ⇒ **一边看视频一边用它时，桌面被反复抹掉** |

**放弃点**：**"一边做别的事、一边跟它说话"**这一步。**放弃的不是产品，是在平板上用它。**

### 08 写作 —— **分页直接废掉**

| 问题 | 实测 |
|---|---|
| `_pageSize = 10` 按"**条**"分页，而他的"一条"是 **600 字** | 一屏放不下两条，翻页形同失效；**无总数、无搜索、无按时间跳、无书签** |
| 快答+深答拼成一条，且 `answer_bubble.dart` 注明"**不加标签**" | 他**分不出哪段是自己写的**，也找不到接缝 |
| 长文渲染成"聊天记录" | 段落感丢失、挤成一坨 ⇒ **自己的稿子在自己手机上都变得不想读** |
| 输入框 `maxLines: 5` + 发送即清空 | 六百字写不完；**写一半切出去就丢** |
| 没有"我写的时候它别出声"的开关 | 它插话**把输入条顶掉** |
| 唯一的验伪动作被系统禁止 | 见 §一·致命 2 |

### 07 自由职业 —— **东西出不去 + 数据没着落**

| 问题 | 实测 |
|---|---|
| **生成物出不去** | 气泡是 `SelectableText` 纯文字；全仓库 grep 确认**无导出、无文件上传入口、无表格** ⇒ 粘到微信排版就散，而它记的账**是要给客户看的** |
| **数据无着落** | 关于页只有版本号+连接状态；设置里"删除账号与全部数据"**有入口**、"导出一份"**没有** |
| 工作区**像文件夹却放不进东西** | 他试着建"合同与发票"往里放扫描件，**放不进去** |
| "关闭 / 收起 / 删掉 / 回收站 / 彻底删"**界面上分不清** | ⇒ **他一周一个图标都不敢删**（X3 写清了，但界面没说） |
| **两个图标同名** | 按客户名起名 ⇒ 同一个客户两个项目是两个同名图标；`icon label` 只 1 行 11px、4 列、省略号；**不能改名** ⇒ **会记错工时，对他是生死线** |
| 后台做完只留桌面一个小点，而**桌面在浮窗后面** | 没有系统通知，等结果只能盯 |

### 04 通勤 —— 速度与误触

- 容忍线：**打开到能打字 3s / 首字 6s / 首字到可用 8s**
- **"反问即流失"**：他发的是"昨天的数据""帮我看下"这类残缺短句，**一次澄清问句 = 当天流失**
- "进工作区"的预算：**一次点击、零等待，且在我本来就想看那个东西的时刻**；40 秒场景一次都不会点

### 05 家长 —— **明确要，但有三个否决条件**

他要一个"小升初"，理由三条：

1. **我的记忆本来就是分文件夹的**
2. **我需要一个看得见的边界来验证它记住了**——"**工作区 = 它记性的体检报告，不是整理工具**"
3. 我需要一个只谈这件事的干净地方

**三个否决条件**：

1. **不要让我起名字/排序/归档**
2. **记忆不能在两个地方各记一半**（进了工作区它要是问"你家在哪个区"，我立马不用）
3. **同一条消息不能在两处显示或答两遍**

### 01 主人 —— **P1/P2 有一个自欺，而且是我写的方案里的**

> **最狠的一条自欺**：甲的安全性全押在"主人真的看一眼"，而**我是唯一读得懂 diff 的人**
> ⇒ 我会永远自认为看懂了，**第 3 次起就只 apply + 按上箭头重启，P1 从那时起就没了**。

另外两条：

- **待确认的改动申请在界面上无处可见**（没有列表 / 详情 / diff 视图）
- **命令顺序有 bug**：允许"apply 了没 commit 就重启"；回退用的 `HEAD~1` **对连续提交是错的一跳** ← **这是我写的，确实错了**

## 四、读到代码才发现的 bug（不是体验问题，是真 bug）

| # | Bug | 出处 | 影响 |
|---|---|---|---|
| **B1** | **断网会把用户登出** | `websocket_transport.dart:112-115`：`authStatus()` 的 `catch` 把**任何网络失败**当成 `required:true, authenticated:false`，接着走 `_noteUnauthorized()` 清掉内存令牌；`main.dart:90` 再把 `null` 落盘 | **地下车库开一次 App 就要重新输口令**（试多了还会 429）。R13 承诺的"变灰自动恢复"在**冷启动路径上根本走不到** |
| **B2** | **"界面提供重试"是一个不存在的承诺** | `chat_controller.dart:420` 的注释 vs 全库 grep：界面里没有重发 | 用户没有出路 |
| **B3** | **失败与成功的视觉完全一致** | 失败时 `pending=false` ⇒ 连小转圈都消失（`chat_screen.dart:778`） | **最坏形态就是现在这样**：界面把"发不出去"显示成"发出去了" |
| **B4** | **`offline` getter 全库零引用** | `chat_controller.dart:234` | 灰化实际读的是 `c.connected`；这个 getter 是死代码，容易误导 |
| **B5** | **重连退避恒为 2 秒** | `websocket_transport.dart:165` 的 `_attempt = 0` 在每次重连前归零 | 参数里的 `maxReconnectDelay: 8s` 与文档写的"退避封顶 8s"**永不生效** |
| **B6** | **刷新/杀进程后屏幕全空** | `timeline` 只在内存（`chat_controller.dart:39`）；全库无消息持久化 | 冷启动断网时打开就是一片"说点什么"的空屏 |
| **B7** | **P2 的命令顺序**（01 指出，我确认是我写错了） | 见 §三·01 | 允许"没 commit 就重启"；`HEAD~1` 回退对连续提交跳错 |

## 五、对设计的修改建议

### 必须现在改（否则做出来就是上面那十个人的放弃点）

| # | 改什么 | 谁提的 |
|---|---|---|

## 七、给工程师那一轮的输入

1. **§四那 7 条 bug 先修**（B1 断网登出、B3 失败=成功、B2 空承诺、B5 退避、B6 无持久化、B7 命令顺序、B4 死代码）——它们都是**低成本、高确定性**的。

4. **P4 的第一个数据源要重选**（见 §六）——建议选一个**目标用户真的会反复问**的能力。
