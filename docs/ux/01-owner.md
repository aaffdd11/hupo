# 01 · 主人自己

> 走查对象：`docs/design/ai-phone-architecture.md`（计划中的产品）＋ `docs/pm-panel/R2-DECISIONS.md`（已拍板）。
> 对照：现在真装在我手机上的那个版本（`apps/mobile/`，`flutter build apk` 装过）。
> 纪律：**我是这个产品的主人，也是它的作者。** 我每天都在改它，我装了 APK 天天用。
> 我最没耐心：3 秒没反应我就认定"它卡了"。我的特殊用法是**拿它去改它自己**。
> ⚠️ 而 P1 刚拍板之后，这件事变了：它不能自己改了，只能写申请，**我自己上机器跑一条命令**。
> 这一篇就是走查这件事。我刻意假装我不知道时间线、工作区、回收站是怎么实现的——
> 看界面上到底告没告诉我。

---

## 一、我是谁

- **技术熟练度**：满级。这仓库的代码是我写的/我看着写的。我会 `git apply`，我有终端，
  我早上打开电脑第一件事是 `git status`。
- **用手机的习惯**：主力机，一天解锁 80 次以上。**大多数想法出现在手机上**——
  地铁上、床上、洗碗时。在电脑前坐着的时间一天大概两小时，而且那两小时我在写代码，不在用产品。
- **我要它干什么**：三件事。
  1. 查（今天天气、这个报价值不值得买）
  2. **记**（老婆说的那个截止日期、"这周要交的东西"）
  3. **改它自己**（"把浮窗改高一点"、"抓手不好拖"、"重启一下"）——第三件是我的高频用法，
     也是这个产品对我最独特的地方：它是我唯一一个"我说一句它就把自己改掉"的工具。
- **我的耐心预算**：**3 秒**。超了我就认为它坏了，会去按"停下"或者干脆切走。
  我不用它的时候不会去"设置"里找原因，我会去用微信。

## 二、第一天：前 5 分钟逐步发生什么

**第 0–25 秒 · 锁屏 → 进去。** 打开，一个居中的"助手"两个字 + 一个"口令"输入框 + 一个"进去"。
桌面上是 4 个图标：天气、会话、关于（开发者模式关着）。**我的第一反应是"就这？"**——
一个聊天 App 我装了 6 个了。我装它是因为**它是我自己写的**，别的用户没有这个理由，
所以我在这里是**对我自己最有利的走查对象**，我提醒自己后面要打折。

**第 25–50 秒 · 我盯着屏幕，屏幕盯着我。** 屏幕上面 2/3 是图标墙，
底下那条贴着屏幕底边的东西我一开始没认出是聊天窗——它太矮了。
后来我知道它收起时是 **124 逻辑像素**：14px 的抓手 + 32px 的标题行 + 一条输入框。
**我第一眼看到的是一条缝，不是一个助手。** 我犹豫了一下：那条灰灰的小横杠（40×4）是什么？
我不敢按，因为我不知道按下去会发生什么。

**第 50 秒–2 分 · 第一句话。** 我点输入框，键盘弹出来，**浮窗自己弹到满屏**（`_maximize()`）。
这个动作我要夸一句：**好用**。我什么都没学，我想说话，它就变大——这是全篇唯一一个
"不需要教就对了"的地方。我输入"今天天气怎么样"，点发送。
**第 1.5 秒**：一条用户气泡（蓝，靠右）+ 一条助手气泡里出现转圈 + "正在查…"。
**第 3 秒**我还没看到字，我拇指已经移到"停下"那个小圆圈上了。**我忍住了，因为这是我自己的产品。**
真用户不会忍。

**第 2–3 分 · 出答案。** 一段话，可以。我心里"嗯"了一声。
但**我注意到桌面上那 4 个图标一个都没变**——我说完天气，桌面上也没有多出什么。
如果我真不知道内部，我会得出"这跟 ChatGPT 网页版有什么差别"。
事实上我在这个产品上花了几个月，**第一天我没看见任何"它会为我攒东西"的迹象**。

**第 3–5 分 · 我开始试点。** 依次点桌面上 4 个图标：
- 天气：整页盖上来，一个我硬编码的 7 天预报（Open-Meteo）。
- 会话：一个列表。
- 关于：版本号 + 连接状态。
- 返回：容器左上角一个 `‹`，右上角一个胶囊里的 `×`。

**第 5 分 · 我得出第一个结论（而且是错的）**：这是一个**聊天 App，加一个工具箱式的桌面**。
我没有发现任何别的东西。（这条后面第六项还要说，它是本篇最要命的一条。）

## 三、我第一次卡在哪

不是卡在连接，也不是卡在延迟。**是卡在"我想让它改点东西"这一句话上。**

第 4 分钟我跟它说：**"把浮窗改高一点，抓手太细了不好拖。"**

- 以前：它回"改好了，我重启一下自己，几秒后就好"。**这是我的爽点，是我最舍不得的功能。**
- P1/P2 之后：它回一段话，说它会把改动写成一个文件放在它自己的工作区，
  然后我要 **`cd <repo> && git apply <patch> && git commit && sudo systemctl restart concierge-core`**。

**我卡在哪一屏**：不在任何一屏。**卡在手机的屏幕上，和一台不在我身边的电脑之间。**
我盯着"助手"发来的那段命令。它写得再短，对手机上的我也是**一段不能执行的东西**。
那一刻我的拇指刚刚才学会"点输入框就弹满屏"，现在它没地方可去。

顺带报三个我在这一步真的会撞上的东西：

1. **命令的顺序本身就是错的**：文案是 `git apply` → `git commit` → 重启。
   如果我 `apply` 成功、`commit` 忘了、然后重启——我现在跑的是**没进 git 的代码**，
   我的回退点（`git checkout HEAD~1`）**指不到它**。这条命令在教我一个错的动作顺序。
2. **回退那条命令不对**：`git checkout HEAD~1` 对"我今天已经提交过 3 次"的仓库是错的一跳。
   我真正的回退点是"apply 之前那个 commit 的 hash"。**我拿到回退命令的时候，得自己去想这个 hash。**
3. **"马上说完"这四个字会骗我。** 计划里 A 转交给 B 时，那条气泡不收口，
   状态显示"马上说完"（`answer_bubble.dart:179` 现成的文案）。
   我是最没耐心的人：**这四个字从第 1 秒就是在骗我——它明明什么都没说完。**
   挂 90 秒我就去按那个 20px 的"停下"小圆圈。而"停下"按下去之后，那条气泡变成什么，**界面上没有告诉我**。

## 四、我在哪一步会放弃（最关键的一条，对我自己狠一点）

**我会在"我拿到命令、我人不在电脑前"这一步放弃。** 但这句话太体面了，我要往下挖三层。

### 第一层（假答案，作者最容易骗自己）："多跑一条命令而已，反正我本来就开着终端"

**假的。** 反例就在上面：我的想法出现在手机上，终端在 3 公里外。
更要命的是"反正我本来就开着终端"这句话，是我为了给自己减少痛苦编出来的——
**它把 P2 的代价算成了 10 秒，实际代价是 8 小时。**
P2 的决策文本自己写了"**必须做到十秒能看完，否则会被绕过**"。
我现在读这句话才知道它真正的意思是：**这 10 秒不在电脑前发生。**

### 第二层（真答案）：被关掉的不是"一步"，是"我改主意的窗口"

这才是杀手。我想改浮窗的时候，脑子里不是一个需求，是**一串连续调整**：
"高一点" → 看到结果 → "再高一点" → "这个抓手的颜色不对" → "算了，还是矮一点"。
这是一次**对话**，五六轮，全程 3 分钟。

现在每一轮 = 一次"上机器跑一条命令"。这不是"每轮慢 10 秒"，**这是每轮都断线**——
因为中间隔着"我从手机走到电脑前"这段物理时间。
**结果是我不会连续调整。我会攒。** 我会对自己说"等晚上回去一起弄"，
然后在晚上把白天那 5 个想法里剩下的 1 个（通常是最后一个、也是最不重要的那个）跑掉。

> **P1 + P2 的实际效果，是把我的迭代节奏从"对话节奏"降到"提交节奏"。**
> 从我每天改它 5 次，变成我一周改它 1 次、一次改 5 件。
> **这就是我放弃的形态：不是卸载，是"少用它来改它自己"。** 而"用它改它自己"正是这个产品
> 对我唯一不可替代的地方。它丢的是护城河，不是效率。

### 第三层（最狠的一条，也是我作为作者唯一骗过自己的地方）

甲的安全模型只有一句话撑着：**"主人真的看一眼。"**
（`R2-DECISIONS.md` P2：「甲 的安全性 = "主人真的看一眼"」）

**而我是唯一能读懂那个 diff 的人。** 所以我会**永远认为我看懂了**。
这份 diff 是我自己让它做的，我扫一眼"改了 chat_screen.dart 的高度常量"，
脑子里已经有了它改完的样子——**于是我按回车**。
我不是"闭眼跑"，我是**睁着眼、但没在审**。这比闭眼跑更危险，因为日志上看起来我做对了。

**系统里没有任何东西能在那条命令上拦住一个"自认为看懂了"的作者。**
没有第二个人读 diff，没有双签，没有"这条命令正在重启一个跑着 agent 的服务，你确定吗"。
我审我自己写的、我让助手改的、影响我自己的补丁。**这是一条自己签自己的链。**

⇒ **所以我会放弃的不是耐心，是审慎。** 具体在第几次？**我猜第 3 次。**
第 1 次我认真读 diff，第 2 次我读改动的那几行，
第 3 次我只 `git apply` 然后按上箭头重启。**从第 3 次起，P1 就没了。**

**再补一刀（对比出来的）**：我现在最舍不得的，恰恰是那个刚被摘掉的"直接动手"。
P1.3 说必须同批改 `AGENTS.md` 和 persona 里"直接动手、不要问"那两处，
**否则助手会一直试、一直被拒，体验比现在更差**。
这条我认。但我要指出：手册改了，**我脑子里的期待没改**。
我至少还会试三五次"你直接改啊"，每次被拒一次，我就对这个产品多想一次"怎么变麻烦了"。
**手册是当天改的，习惯是慢慢磨掉的——这段时间里，产品在我这里是在掉分的。**

## 五、第一周

**还在用。** 但用法分成两半，一半活着，一半死了。

- **活着的那一半（日常三件事：查 / 记 / 陪）**：跟第一天没差别。天气、记个日期、随便聊两句。
  这部分我留下来了。
- **半死的那一半（改它自己）**：从一天 5 次掉到一周 1 次。
  我攒了一周，周五晚上坐在电脑前，一次性 apply 一批。
  **我这一周里没有一次"顺手就把它改了"。**
- **我主动去点桌面上生成的东西的次数：0。**
  第一周结束的时候，桌面上还是那 3 个图标的形状——**没有任何一个是我的**。
  我不是不想点，是**没有可点的东西**。这条我本来不打算算作问题，
  因为"工作区图标"是计划里的、还没做。但走查的规矩是"我第一天看到的界面"，
  那我看到的就是：**桌面上没有我。**

## 六、我有没有发现"工作区"这个概念

**没有。** 而且我是**刻意假装忘了内部细节之后，认真找过一遍**的。

我逐屏找过的位置和结果：

| 我找的地方 | 我看到的 | 我推断出什么 |
|---|---|---|
| 桌面顶栏 | 一个圆点 + "Hupo" | 这是 App 名字，不是范围/位置 |
| 聊天浮窗标题行 | "助手" ／ 或最新一句话的一行预览 | 一个正在说话的东西，没有"在哪一层" |
| 输入框提示 | "说点什么" | 没有"在这个话题里说"的暗示 |
| 空列表占位 | "说点什么" | 同上（**和输入框提示一字不差**，我会以为它是输入框的一部分） |
| 收发过渡 | "正在查…" / "还在处理，这个要多花点时间…" / "马上说完" | 三个进度文案，**都不含"谁"** |
| 有没有分隔线 | 没有。时间线是一条连续列表 | 我看不出哪句在顶层、哪句在小升初 |
| 有没有来源/出处 | 没有。长按没有菜单，气泡上没有可点的地方 | 我没有任何入口回查"这句从哪来" |
| 点一个桌面图标 | 整页盖上来一个独立小程序（天气/会话/关于） | **图标 = 工具**，不是"一段记忆" |

**结论**：如果我不知道架构文档，我会把它理解成**"一个带工具箱桌面的聊天 App"**。
计划里那句"点进那个图标，**还是在聊天**，只是记忆换到了那个工作区里"——
按我现在真机上看到的形状，点图标得到的是**一个完全不像聊天的整页**。
所以用户会学到"图标 = 小应用"，**然后用这个错误的模型去看后面长出来的东西**。
等他哪天发现"这个新图标点开居然是聊天"，他不会觉得"哦这是工作区"，
他会觉得"这两个图标怎么不是一类东西"。

**大白话：工作区在界面上不存在。** 唯一让我意识到"有分层"的线索是"马上说完"和
"还有件事在处理：xxx"这类状态行——而它们**说的是"有件事"，不是"在哪个地方"**。
事实没有静默（N20 要求的未读标记会补上这个洞），
但**"我在哪一层"这件事，从第一天到第一周，界面一次都没说过。**

## 七、我发现的 UX 问题

一行一条，不排序，不带解决方案：

1. 桌面图标点开是**整页小程序**，而计划说"点进去还是在聊天"——**两种心智模型会在同一个桌面上撞车**。
2. 桌面上**没有未读标记**，所以"某个工作区有东西可看"这件事，我不主动点就永远不会知道。
3. 收起状态的浮窗只有一条缝（124px），**我看不出它是个聊天窗**；抓手那根 40×4 的灰条没有任何文字或提示告诉我"可以拖"。
4. 双击抓手 / 点浮窗外面也能收起——**这两条手势在界面上零提示**，只存在于代码注释里。
5. 收起时标题行显示"助手"（没消息）或最新一句话的前 30 来个字符，**和输入框的"说点什么"长得像同一块区域**，第一眼会看错。
6. 空状态的占位文字"说点什么"和输入框 hint 一字不差，**我会以为是同一句话渲染了两遍**。
7. "马上说完"（handoff）是**一句会挂很久的话**，而且它承诺的是"说完"，不是"在等谁"；挂久了唯一的出路是那个 20px 的"停下"图标。
8. 状态行只有"什么状态"，没有"谁/在哪"；**同一条气泡可能中途换人写**，而接缝不显示——我会读成"它口气变了"。
9. 时间线**没有分隔线、没有范围标记**，所以我永远无法知道某句话属于哪个工作区（X2 说字段要现在留，但界面上 v1 也不显示）。
10. 一次对话的调参节奏（改高一点→再高一点）需要**连续 5–6 轮往返**，而 P2 之后每轮都要上机器跑命令 ⇒ **迭代节奏从"对话"掉到"提交"**。
11. 申请落地在"助手自己的工作区"——**我在界面上没有任何地方能看见我的待办申请**（没有列表、没有详情页、没有 diff 视图）。
12. P2 给的命令顺序（`git apply` → `git commit` → 重启）**允许出现"apply 了但没 commit 就重启"的半成品状态**。
13. P2 给的回退命令 `git checkout HEAD~1` **对连续多次提交的仓库是错的一跳**，回退点应该是一个具体 hash。
14. **回收站不可见**：X3 说删掉进回收站留 30 天，但桌面上没有任何"回收站"入口，我也看不到"30 天后真删"的倒计时。
15. **没有"我在哪"的全局状态**：开了 3 个工作区之后，除了桌面图标，我没法一眼看出"现在有几件事在跑、各自在哪"。
16. 输入框旁边那个"停下"是**一个没有文字的图标**，而且**只在它正在说话时才冒出来**、紧挨着"发送"——它出现的时机正好是我最没耐心、最想乱点的时候。
17. 口令登录页**冷启动要手输**（token 过期时），而这是我唯一一个"想随手用一下"的工具——多一道门就多一次放弃的机会。

## 八、只让我改一件事

**给"改它自己"这件事在手机上留一个能看见、能累积的地方。**
不是把执行搬回手机（P1/P2 不动），是**让申请在界面上存在**：
桌面上出现一张"待你确认的改动"的卡（或者一个专门的图标），
点进去能看到：改了哪几个文件、原来长什么样、改完长什么样、一条能复制的命令、回退点。
申请积累在那里，我什么时候坐到电脑前什么时候处理——**但它是可见的，不是靠我说完就忘的一句话。**
理由：我在第四节挖出来的真问题不是"要跑命令"，是"**我改主意的窗口被关掉了**"。
一个可见的待办列表不会把窗口开回来，但它至少让**第 3 次到第 5 次的想法不会掉在地上**。
现在这个形态下，它们掉在地上，而且我不知道它们掉过。
