# 用户体验走查 · 10 个不同用户（第二轮）

> **为什么这一轮要在工程师之前**：
> 如果走查发现"用户根本不会去点桌面上那个图标"，工程做得再漂亮也白做。
> **UX 的产出是工程规划的输入，不是它的后续。**
>
> **方法**：10 个不同的人，**第一人称**走查一遍。不是"用户可能会……"，
> 是"我打开它，我盯着输入框，我退出了"。
>
> **走查对象**：`docs/design/ai-phone-architecture.md` 里**计划中的产品**；
> 同时知道"现在真实能装的版本长什么样"作为对照（`apps/mobile/`，已出 APK）。

---

## 一、这个产品是什么（走查者共用的底）

**一句话**：一个私人 AI 助手，想做成人生的第一个"AI 手机"入口。

**用户看到的**：

- 打开就是**一个纯粹的聊天窗口**——贴着屏幕底部的浮窗，能拖、能甩、能收起来
- 浮窗后面是一层**桌面**（图标墙）
- 桌面上每个图标**不是别人做好的应用**，而是"**你的需求被固化下来的形状**"：
  你反复聊同一类事，助手就给它单独开一个"**工作区**"，变成桌面上的一个图标
- 点进那个图标，**还是在聊天**，只是记忆换到了那个工作区里

**现在的真实版本（已经能装到手机上，我们做过 APK）**：

- 一条时间线：用户发言和助手发言各自成条，**不做一问一答配对**
- 贴底浮窗：**三档**（收起 / 半开 / 全屏），抓手能拖、能甩、双击能收
- 桌面图标墙：**4 个内置应用**——天气、会话、关于、开发者模式
- 要**输口令登录**
- 连的是 `https://hupo.stalkerai.cn`
- 断网时：浮窗**变灰**（真抽掉颜色）+ **点不动** + 转圈"正在恢复连接…"

**计划中的版本（走查的就是它）**：

- 桌面上那些图标，会变成**用户自己攒出来的**（不再只有内置那 4 个）
- 用户看到的**时间线仍然只有一条**（顶层 + 各个工作区的内容都在这一条上，用分隔线隔开）
- 进工作区时**感觉不到切换**，但记忆换到了那个工作区
- 助手可以在后台继续干活，做完把结果汇报给"**大管家**"（也就是顶层）
- 删掉一个图标 = **进回收站**（30 天能找回），不是真删

## 二、十个人（覆盖三个维度）

**技术熟练度**：只会用微信 → 会自己装 APK
**需求类型**：查 / 记 / 办 / 写 / 陪
**设备与网络**：旗舰 / 千元 / 平板 / 网络差

| # | 文件 | 是谁 | 为什么要他 |
|---|---|---|---|
| 01 | `01-owner.md` | 主人自己 | 基准线：最熟产品，也最没耐心 |
| 02 | `02-techie.md` | 会折腾的技术朋友 | 会自己装 APK，会试边界、试奇怪的话 |
| 03 | `03-nontechnical.md` | 不技术的同龄朋友 | **不知道"APK"是什么** |
| 04 | `04-commuter.md` | 忙的职场人 | 早上地铁、一只手抓扶手、只发短句 |
| 05 | `05-parent.md` | 学生家长 | 小升初：高频、信息密集、焦虑 |
| 06 | `06-retiree.md` | 退休老人 | 字体、不会打字、只用语音 |
| 07 | `07-freelancer.md` | 自由职业者 | 记账、报价单、清单——要"留下来"的东西 |

| 10 | `10-tablet.md` | 平板用户 | 就是主人那台小米平板 |

## 三、每人要交的七项

1. **我是谁**（技术熟练度 / 用手机的习惯 / 我要它干什么）
2. **第一天**：打开之后**前 5 分钟**逐步发生什么（一屏一屏写）
3. **我第一次卡在哪**（具体到哪一屏、哪一句话）
4. **我在哪一步会放弃**（最关键的一条）
5. **第一周**：还在用吗？为什么？有没有主动去点桌面上生成的东西
6. **我有没有发现"工作区"这个概念**
7. **我发现的 UX 问题**（一行一条，不带解决方案也可以）

---

## 四、纪律

- **第一人称**。"用户可能会"一律不算。
- **必须指名道姓**：哪一屏、哪句话、哪一步。含糊的抱怨不算。
- **允许说"我觉得挺好用"**——但要说出好在哪一步。
- **失败要说清失败在哪一步**，不是"太难用"。

---

## 五、产出

- `01-*.md` … `10-*.md`：十份第一人称走查
- `SYNTHESIS.md`：汇总（普遍问题 / 分人群问题 / 致命问题 / 对设计的修改建议）
- **`SOLUTIONS.md`：解决方案** —— 把问题变成"要做什么"。
  **它把所有问题归到 5 个根因上**（一次改动带走一批），再逐条给方案，最后列出**需要主人拍板的 6 件事**。

> ⚠️ **这批走查发生在写代码之前，所以绝大多数不是"改回来"，是"设计进去"**——
> 这是把 UX 放在工程前面换来的唯一好处，得用掉。
