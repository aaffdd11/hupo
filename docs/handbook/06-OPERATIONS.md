## 二、部署

### 2.1 分两半，**生效方式完全不同**

| 改了什么 | 怎么生效 | 要不要重启服务 |
|---|---|---|
| 服务端（`services/core/`） | 重启服务 | **要** |
| agent 的人格 / 手册 | 重启服务 | **要** |
| **客户端 / 界面（`apps/mobile/`）** | 重新构建 + 上传 | 🚨 **千万不要重启服务** |

🚨 **改客户端时绝对不要重启服务。** 两个原因，都踩过：

1. **重启服务对客户端改动毫无作用**——界面跑在浏览器/手机里，只有重新构建上传才会变。
2. **重启服务会把正在回答的助手杀掉**——助手是那个服务的子进程。
   在改界面、还没部署、还没验证、还没回话的时候重启它，**等于在任务中间自杀**：
   文件改了，但用户屏幕上什么都没变，而且他再也等不到回话。

### 2.2 服务端

```
systemd 单元 = concierge-core
入口        = services/core/src/index.js
端口        = 8091（只监听本机；nginx 反代 /api/）
会话存储    = $DSH_HOME/sessions/（键是**绝对路径的编码**）
```

⚠️ **`DSH_HOME` 当前无处设置**——它只出现在文档与 `scripts/diagrams.mjs:585` 里，
**生产机上到底有没有、值是多少，必须先核**（这件事挡着 §四 的 env 白名单）。

### 2.3 客户端

```
cd apps/mobile
~/sdk/flutter/bin/flutter analyze          # 硬闸：编译
~/sdk/flutter/bin/flutter test test/unit   # 硬闸：协议 / 状态机 / 纯逻辑
~/sdk/flutter/bin/flutter test test/widget # 只警告，不阻断
~/sdk/flutter/bin/flutter build apk --release
```

**产物**：`apps/mobile/build/app/outputs/flutter-apk/app-release.apk`

⚠️ **`test/widget` 挂了就照常继续**。它断言的是布局（像素坐标、控件 key），
**界面一重构它必然过期**（现在 **49 条挂 10**）。
正确做法：界面测试挂了 ⇒ 照常构建 ⇒ **用真机确认** ⇒ 有空再回头更新那些断言。

⚠️ **但 `flutter analyze` 与 `test/unit` 挂了必须修干净**——它们是硬闸，
守的是协议与状态机。想清楚是真的改了协议，还是把状态机改坏了。

**已踩过的坑（写进 checklist）**：

| 坑 | 症状 |
|---|---|
| `AndroidManifest.xml` 的 XML 注释里含 `--` | **ManifestMerger 解析失败**，构建报错 |
| Release 包没声明 `INTERNET` | Flutter 模板**只在 debug/profile 声明** ⇒ release APK **没有网络** |
| `flutter doctor` 卡住 | 它可能耗时超过一分钟 ⇒ **放后台跑** |

## 三、权限模型（P1 / P2 怎么落地）

### 3.1 P2：执行特权走**手动**（今天就能用）

```
助手产出：一个补丁（diff）—— 改了哪几个文件、从什么改成什么
主人看到：一条命令 + 一个补丁
主人跑：  cd <repo> && git apply <patch> && git commit && 重启服务
回退：    git revert（⚠️ 不是 `HEAD~1`）
记账：    git log（白拿）
```

- **助手能控制的只有补丁内容**——而那正是主人要看的那一眼
- **回退点、审计、谁什么时候改的**：git 天生都有，**不用另造**
- **零预装**：不需要放脚本、不需要 root 服务、不需要定时任务

⚠️ **甲的安全性 = "主人真的看一眼"。** 养成闭眼跑的习惯，
甲就退化成"助手有 root，只是慢一点"。
⇒ 所以形态必须"**短到主人愿意看**"。

⚠️ **回退命令必须用 `git revert`，不是 `git checkout HEAD~1`。**
（旧文档写错过这条。）

### 3.2 P1：助手不能改自己

| # | 机制 |
|---|---|
| 1 | 只有**主人亲口说"改"**才能执行。助手可以提方案，**永远不能自己按那个按钮** |
| 2 | "摘够"的判据：**没有任何路径**能让助手的写入变成"**下次开机自动读**"的东西 |
| 3 | **说明书同批改**：`AGENTS.md` 与人格文件里的"直接动手 / 免密 sudo"**必须与能力收回同批改** |
| 4 | **清单本身要护住**：判断"哪些文件不能写"的那份清单，**助手碰不到**（`root:root 0444`）；每次开机核对，对不上**拒绝启动 + 报警** |
| 5 | **回退不需要助手参与**——出问题时助手本身可能就是出问题的那个 |
| 6 | 申请写成**一个文件**放在助手自己的工作区；每次改动**记一笔账** |

⚠️ **C5（不能延）**：`AGENTS.md` 与人格文件里写着 **`sudo` 免密**，而**本机实测要密码**。
**P2 甲的安全性正建立在"要密码"上** ⇒ 必须同批改，
否则**助手的自我认知会把护栏读没**（它会以为"反正我免密"，然后一直去试）。

### 3.3 两个"半成品"必须先修

| # | 问题 | 为什么它挡住 P1 |
|---|---|---|
| 1 | **`store.append` 静默吞异常**（`store.js:22-28`） | 与"写失败必须上抛"相反。**唯一会永久丢数据**的根 |
| 2 | **无进程上限、无淘汰策略** | 见 §四 |

## 四、供给上限与准入

### 4.1 为什么它是"第二个用户的开门条件"

```
2 用户 ×（1 焦点 + 1 监视）× 195MB  +  调度器 80MB
= 860MB  >  640MB（软限）
```

⇒ **第二个用户上线就会把第一个人的 agent 拖下水。**

### 4.2 现在缺什么（**去代码里核过**）

| 缺什么 | 现状 |
|---|---|
| **进程上限** | **全库不存在**（`agentMaxProcesses` 这个名字一次都没出现） |
| **回收机制** | 只有一个 30 分钟的空闲 TTL——**而它不够**（见下） |
| **准入** | 没有。`?conv=N` 就是 N × 195MB |
| **LRU 访问序** | ❌ 不更新顺序（`agent():342-354`），`Map` 的插入序 **≠ LRU** |
| **"先收口再卸"** | `agent-runtime` **全文没有 translator** ⇒ 只能直接卸，**收不了口** |

### 4.3 目标

| # | 做什么 | 关键点 |
|---|---|---|
| 1 | **进程上限** | 一个明确的数字，配套"满了怎么办" |
| 2 | **真 LRU** | **必须先修访问序**，否则"LRU"名不副实 |
| 3 | **`onEvict` 回调** | runtime 收不了口 ⇒ **必须回调 dispatcher** 让它先收口再卸 |
| 4 | **跑着的不许卸** | `running === true` 必须跳过，**且跳过之后要重新计时**（否则跳过一次 = 永久不淘汰） |
| 5 | **准入** | 内存闸；**先卸再拒**；拒绝必须给**一句人话**（不许静默拒绝） |
| 6 | **env** | 先做减法：传全部环境变量，**只删 `*_API_KEY` / `*_TOKEN` / `*_SECRET`** |

⚠️ **env 白名单不能随手砍**：`dsh` 是 node CLI，**丢 `PATH` 就回到 ENOENT**；
还需 `HOME`（读 `~/.dsh`）、`TMPDIR`、`LANG`，以及部署侧注入的变量。
**严格白名单要先盘点生产机 unit 文件**，不许先砍后盘点。

## 五、容器

### 5.1 两种 root 不是一回事

| | 是什么 | 给不给 |
|---|---|---|
| **宿主上的 docker 访问权** | = **宿主的 root** | ❌ **永远不给**（P2.2） |
| **容器内部的 root** | = **那个盒子里的 root** | ✅ **应该给**——不给它就是个残废，装不了包、改不了配置 |

> 这正是容器方案的卖点：现在不敢给 root，因为给了就是给整台机器；
> 有了容器，可以在盒子里给它**完整 root**，而外面一点碰不到。

### 5.2 验收清单（**缺一条就全白做**）

| # | 必须满足 |
|---|---|
| 1 | **绝不能把宿主 docker 的接口挂进容器**（挂了 = 把整串钥匙放进一个你打算锁起来的房间） |
| 2 | **不许 `--privileged`** |
| 3 | **不许挂宿主 `/`、`/etc`、`/home/deploy`、`~/.ssh`、`~/.dsh`** |
| 4 | capabilities **默认全收、按需开**（`cap_drop: [ALL]` 起步） |
| 5 | **封住通往宿主内网端口的每一条路**（如 8091） |
| 6 | **封住云元数据地址**（`169.254.169.254`——容器逃逸的标准第一步） |
| 7 | **系统盘只读**，只有数据盘可写 ⇒ 改坏了扔掉重建 |
| 8 | **容器之间不互通** |

### 5.3 约束（本机实测）

⚠️ **本机做不了容器实验**：`deploy` 不在 docker 组、`sudo` 要密码、
`apparmor_restrict_unprivileged_userns=1` 挡掉无根容器。
⇒ **容器相关的一切只能在生产机上验**。

### 6.1 哪些是"用户的状态"

```
/data/main/                    主目录的文件
/data/workspaces/*/            各作用域的文件
/data/hupo/memory/             记忆索引 KV          ← 本轮不建，路径先留着
```

**备份 / 迁移 / 删除 都照这份清单走。容器里其他一切可抛弃。**

### 6.2 三条纪律

| # | 纪律 |
|---|---|
| 1 | **`.credentials.yaml` 含模型密钥** ⇒ 备份**必须加密**，且**不许进任何会显示给用户的地方**，也不许写进日志 |

| 3 | **删除走"收起 / 回收站 / 真删"三段**（X3）：收起无期限；删掉进回收站 30 天；**删前必须列清单** |

### 6.3 迁移

**一人一容器**之后，迁移 = 搬上面那份清单。
⚠️ **会话存储的键是绝对路径的编码** ⇒ **换路径等于换账号**，
迁移时必须一起处理（不变量 N21：同一用户一份 `DSH_HOME`）。

## 七、监控与告警

### 7.1 现在有什么

| 东西 | 作用 |
|---|---|
| **监控 agent** | 在旁边看每一轮对话：时效（等多久）/ 合理性（答没答对题、编没编、查没查）/ 个性适配 / 记忆一致 ⇒ **把毛病落成任务** |
| 说话画像 | 从对话里**纯统计**出来，存 `data/personality/`（**不进仓库**），新会话开场自动注入 |
| 性能采样 | 定时采样，写 `data/metrics.jsonl` |

### 7.2 值得盯的几件事

| # | 盯什么 | 为什么 |
|---|---|---|
| 1 | **`oom_kill > 0`** | 说明供给上限没做对（§四） |
| 2 | **磁盘剩余** | 盘满是**唯一会永久丢数据**的路径（`store.append`） |
| 3 | **重连次数** | 坏令牌会造成**每 2 秒无限重连**（客户端缺陷，批 1 修） |
| 4 | **首句延迟 / 空窗** | 时效纪律：用户等的是这两个数 |
| 5 | **同一件事被记两遍** | 应声与系统通知**双通道**（批 3 要合并） |

### 7.3 ⚠️ 告警必须"说人话"

监控 agent 的产物**不是日志**，是**给主人看的一句话**。
**内部名不许出现在告警里**（同一条禁用词纪律，见 `07-APPENDIX.md`）。

## 八、故障处理与回退

### 8.1 改坏了怎么办

| 情况 | 怎么办 |
|---|---|
| 服务端起不来 | `git revert` 上一次改动 → 重启服务 → 确认存活 |
| 客户端改坏了 | 重新构建上一个版本并上传（**不要碰服务**） |
| 盘满 | 清数据盘 → **确认 `store.append` 的失败路径已经接住**（否则它会崩给你看） |
| 一次注入留下了东西 | **P1 那条路必须已经被堵上**——否则改完还会被重新注入 |

### 8.2 回退的硬要求

> **回退必须"由主人一句话完成，不需要助手参与"。**
> 理由：**出问题时助手本身可能就是出问题的那个。**

⇒ 所以 `rollback.sh` 只做 `git revert` + 重启，**不读任何助手产出的文件**。

### 8.3 重启自己的正确姿势（**生产机上**）

⚠️ 不要直接重启服务——那会把**正在说话的助手**连同这一轮回答一起杀掉，
用户会看到话说一半没了。要**延迟重启**，先把话说完。

⚠️ **本机没有这个服务**，这一节只在生产机适用。
