# 02 · 架构

> **这份文档回答：系统由什么组成、边界在哪、什么绝对不能做。**
>
> 它**不回答**"怎么改代码"（`03-DEVELOPMENT.md`）、"先做什么"（`04-ROADMAP.md`）。
>
> ⚠️ **本文有两类内容，已分别标注**：
> - **【已实测】** = 拿代码或探针核过，或可从 DSH 行为直接确认
> - **【设计】** = 已拍板的目标态，**还没实现**
> - **【未决】** = 两份以上文档说法不同，**本文不替它们调和**（集中列在 §七）

## 〇、一句话

> **一台哑终端 + 一台云端专属主机 + 一个调度器。**
>
> 用户看到的是**一个聊天窗口**；底下是**多条 DSH 会话**，每条待在自己的工作区里；
> **调度器**决定"谁的话投给谁"，并按自己的时钟把这些话拼成用户看到的那**一条时间线**。

## 一、三层 + 一条旁路

```
L1 终端层    Flutter（Web / iOS / Android）
             = 一条有序时间线 + 小程序运行时 + 图标墙
             「只上报事实，不做判断」
                          ⇅  HTTPS + WebSocket（Bearer 令牌）
L2 调度层    services/core，永续进程
             = 节奏 / 任务账本 / 协议翻译 / 对账续做 / 准入 / 制品分发
             「不能有表达欲」（唯一例外：产品固定话术）
                          ⇅  stdio JSON-RPC（dsh --profile sdk --patch <role>）
L3 工作层    一个会话 = 一个真 agent 子进程
             = 人格 / 工具 / 上下文装配 / 跨重启接记忆 / 说话画像
             「永不直接对用户说话」（话由主 agent 出口）

旁路 监控层   独立进程，只读档
             「它是第二个执行体，输入是主 agent 的输出（可被网页污染）」
```

### 1.1 各层是什么、跑在哪、怎么通信

| | L1 终端 | L2 调度器 | L3 工作层 |
|---|---|---|---|
| **是什么** | 壳 = 一条有序时间线（按编号排，**绝不配对**） | 永续进程 | 一个会话 = 一个真 `dsh` 子进程 |
| **跑在哪** | 用户的设备 / 浏览器 | 服务端（`services/core`） | 服务端，由调度器 spawn |
| **和谁说话** | 只和 L2 | 对 L1 = HTTPS+WS；对 L3 = stdio JSON-RPC | 只和 L2 |
| **职责** | 渲染时间线、装小程序、上报事实 | 路由 / 邮政 / 归一化 / 账号与供给 | 干活、说话 |
| **绝不** | 不做任何判断 | 不能有表达欲 | 不能自己决定自己有什么能力 |

### 1.2 三条最容易搞错的边界

| # | 边界 |
|---|---|
| 1 | **"只上报事实，不做判断"**——终端不判断"这句话来自谁"、不判断"该不该刷新" |
| 2 | **"不能有表达欲"**——调度器只有产品固定话术这一个例外（"我单独拿去做"、"我没能给出结论"）。**写明这个例外，是为了免得后人误读成"调度器可以说任何话"** |
| 3 | **"永不直接对用户说话"**——子 agent 也一样；话只能由主 agent 出口 |

### 1.3 最重要的一条安全事实

> ⚠️ **工作区根目录不是安全边界。**
>
> 文件沙箱**只约束写**，它**明确保留"本地文件系统的读行为"**。
> 把主目录和子工作区放成父子目录，**子工作区的文件对主目录的 agent 依然可读**。
>
> ⇒ **记忆隔离靠的不是目录**，而是"**会话历史按 root 分区**"（这一半是自动成立的）。
> ⇒ 所以设计上是**靠"指针对 + 检索"让它没有理由去翻目录**，**而不是靠堵**。

## 二、多租户：一人一容器

**【设计】** 一个用户 = 一台容器 = **这个用户的整个世界**。

```
用户容器
  ├─ 一份专属 DSH
  ├─ 若干工作区（每个 = 一个目录 + 一条会话 + 桌面一个图标）
  └─ hupo 地盘（记忆索引 / 制品 / 审计）
```

### 2.1 容器内布局

```
/data/                          ← 容器内，这个用户的整个世界
  main/                         ← 主目录（顶层对话的 workspace root）
                                   ⚠️ 不是 /data，不是 home
  workspaces/
    <scope-name>/               ← 子工作区（= 桌面上的一个图标）
  hupo/                         ← hupo 的地盘，不在任何 workspace root 里
    memory/                     ← 记忆索引
    apps/                       ← 生成的小程序制品
    audit/                      ← 审计
$DSH_HOME/                      ← 这份专属 DSH 的（会话历史按 root 分区）
```

### 2.2 三条硬规则

| # | 规则 | 为什么 |
|---|---|---|
| **1** | **主目录 root 不许是 home** | `~/.dsh/.credentials.yaml`（模型密钥）、`~/.ssh/id_rsa` 会被**读**到；**`~/.bashrc` 会被写**到 ⇒ **持久化代码执行**。⚠️ 现有生产实现用的是独立工作目录，**那是对的，别退回去** |
| **2** | **主目录 root 不许包含 `workspaces/`**（必须**平行**） | 否则主目录的 agent 会**写进子工作区**（算错一个相对路径就发生）。平行之后写被 root 挡住 |
| **3** | **每个用户一份 `DSH_HOME`** | 会话存储的键是**绝对路径**。两个用户的工作区若同名，**共享 `DSH_HOME` 就会撞进同一份记忆** |

> 第 2 条还有个未来理由：**万一以后要收紧"读"，平行布局不用搬家。**

### 2.3 容器里的 root：**给，但只在盒子里**

| | 是什么 | 给不给 |
|---|---|---|
| **宿主上的 docker 访问权** | = **宿主的 root**（能挂载任何目录、起特权容器） | ❌ **永远不给** |
| **容器内部的 root** | = **那个盒子里的 root** | ✅ **给**——不给它就是个残废，装不了包、改不了配置 |

⇒ **这正是容器方案的卖点**：现在不敢给 root，因为给了就是给整台机器；
有了容器，可以**在盒子里给它完整 root，而外面一点碰不到**。

**但有前提，缺一条就全白做**（见 `06-OPERATIONS.md` §五）。

### 2.4 容器**不是第一步**

**【未决→已决】** 产品面板裁决：因为**执行特权走手动**（不需要任何预装的 root 组件）、
且当前权限下**装不了容器**，所以容器的定位是
"**开第二个席位的开门条件**"，**不是第一步**。

⇒ **凡是不需要 docker 的块，今天就能动工**（见 `04-ROADMAP.md` 批 1–5）。

## 三、作用域模型

### 3.1 一个作用域是什么

> **一个作用域 = 一个工作区 = 一条 DSH 会话 = 一个目录 = 桌面上一个图标（1:1:1:1）。**

**这条简化让整个模型干净：切换对话框 = 切换工作区 = 切换会话 = 同一件事。**

三层实体，**只有中间那层拥有记忆**：

| 层 | 实体 | 是什么 | 拥有记忆？ |
|---|---|---|---|
| 归置 | **workspace** | 一个目录 + 标题 + 排序 + 该目录下的会话清单 | ❌ **不拥有**（**对模型完全不可见，零上下文成本**） |
| 干活 | **session** | 一次连续对话；**自带 workspace root** | ✅ **记忆在这里** |
| 落盘 | `$DSH_HOME/sessions/<root 编码>/` | 历史文件 | —— |

> ⚠️ **"一个文件夹一套记忆"是结果，不是 workspace 这个实体在管。**
> 这条区别决定：改工作区名、归档、删图标时，动的是"**归置**"还是"**记忆**"。

### 3.2 作用域栈与焦点

```
一条可见时间线（客户端只认它）
  └── 作用域栈：[主目录] → [本子] → …
        · 同时只有一个"焦点"作用域
```

**并行与上屏（别混）**：

| | 什么样 |
|---|---|
| **执行** | 随便并行——非焦点作用域该干活干活 |
| **上屏** | 排队——同一时刻最多一条未收口 |

### 3.3 一致性：最容易埋的雷

> **界面显示的作用域，与 session 的 root，必须始终一致；不一致就报错，不许继续。**

**为什么单列一条**：只切界面没切 root，会出现"**界面上我在 A 里，说话却写进了顶层**"。
这种 bug 最难查，而且它**让隔离静默失效**。

### 3.4 切换的本质（**这一条决定了实现难度**）

**【已实测】** root 是**会话创建时**定下的（会话头里记着 cwd），**运行中改不了**。

⇒ 所以"进入一个作用域" = **结束当前这条 + 开一条新的（带新 root）**。
**是"换一条会话"，不是"改一个字段"。**

### 3.5 跨作用域：转交与"看不见"

**转交的时序【设计】**：

```
A 正在回答（同一条消息，同一个气泡）
  ├─ ① A 调用 handoff_to(scope, reason)     ← ⚠️ 工具调用，不是自然语言
  ├─ ② A 那条消息**不收口**，状态置 handoff  → 客户端显示"马上说完"
  ├─ ③ 调度器组装交接包 → 交给 B
  └─ ④ B 接着往**同一条消息**里写
```

⚠️ **这里有一处与其他文档矛盾**：另一份文档写的"挪走"是
"**先收口，后面的话另起一条**"。**两者共用了同一个状态标记**——
**【未决】见 §七 不一致 3。**

**"用户切走了，A 还在干活"怎么办（最重要的设计决定）**：

> **A 继续做完，结果搁置，不投递、不触发。**

理由：**用户切走 ≠ 话题结束，而意图不可知。**

| 如果猜 | 结果 |
|---|---|
| "切走 = 结束" | 误判 |
| "切走 = 还相关" | 也误判 |
| **不猜，两端各自做完、互不投递** | **零误判** |

这是"**沉默优于编造**"从"答什么"搬到"**投给谁**"。

**精确表述**：

> **A 照常做完，结果照常进 A 的会话历史。不做任何跨作用域投递。**
> **"搁置"不是一种新状态。它就是"A 的消息正常写完了"。**
> **"隐藏"不是"不投递"，而是"不实时提醒"。**

**三件配套的小事**：

| # | 做什么 |
|---|---|
| 1 | **A 要知道"用户当前不在我这一层"**（落点是动态运行时事实） |
| 2 | **未读标记**（桌面上 A 的图标带小点）——"**动作可静默，事实不能静默**"最轻的落实 |
| 3 | **A 被回收前结果必须落盘** |

### 3.6 界面上的名字（**工程词与用户词是两套**）

| 工程侧 | 用户侧 | 备注 |
|---|---|---|
| 作用域 / 工作区 | **本子** | ⚠️ **"工作区"三个字界面永久禁用**（决策 D1.1） |
| 图标墙 | 桌面 | 手机第一入口 |
| 浮窗 | 那个聊天框 | 唯一的窗口 |

**隐喻 = "一件事的一本本子"**，**不是文件夹、不是应用、不是频道、不是房间**。
理由：**本子承诺的（能翻、能问、能添页）正好就是聊天已有的能力，一句空话都不多。**

## 四、调度器的职责

```
调度器（永续，同时持有 A、B、C… 每条会话）
 ① 对用户的路由
      当前焦点在哪条 → 它的输出投给用户
      其它条的输出 → 照常进时间线，但不实时提醒
 ② agent 之间的邮政
      转交包 / 未读 / 焦点告知
 ③ 归一化成一条时间线
      编号、收口、补发
 ④ 账号与供给
      鉴权、配额、进程上限与准入
```

**核心原则**：

| # | 原则 |
|---|---|
| 1 | **编号由调度器统一发**（不是各会话自己数自己的） |
| 2 | **先落盘、再推给客户端**（写盘失败必须报出来，不能吞） |
| 3 | **一个 WS 连接是物理约束**——不能每个会话一条连接 |
| 4 | **掩饰发生在调度器** ⇒ 客户端仍然只认一条时间线 |

⚠️ 第 4 条有个直接后果：**多作用域几乎不需要改客户端协议**。
但**"几乎"不等于"不用改"**——真正要动的是**传输层的生命周期**
（见 `03-DEVELOPMENT.md` §2.5 欠账 3：今天退一个会话会打死全站连接）。

## 五、不变量 N12–N25

> **编号接在 N1–N11 之后**（N1–N11 的正文见 [`08-SPEC.md`](08-SPEC.md) §一）。
> 这 14 条是**跨模块的硬约束**——
> 违反它不是"写得不好"，是**架构错了**。

| # | 不变量 |
|---|---|
| **N12** | **界面作用域 = session 的 root**，不一致就报错，不许继续 |
| **N13** | **跨作用域只走摘要与指针，不走原文**；作用域之间的会话历史**永不互通** |
| **N14** | **主作用域可以不知道细节，但不许替子作用域编细节**（"不知道"必须可表达） |
| **N15** | **切换作用域前必须把上一条气泡收口**；收口完成前不许开新的 |
| **N16** | **转交必须是一轮内最多一次、禁止回环**；且前提是目标作用域已存在 |
| **N17** | **记忆无出处不写**；未采信的只能进"待确认"，**不得作行动依据** |
| **N18** | **agent 不许直接写记忆**；写入必经 hupo 的工具与出处校验 |
| **N19** | **挂起必有超时，且必有合法收尾**（不许留下永远"马上说完"的气泡） |
| **N20** | **动作可静默，事实不能静默**：跨作用域发生的事必须有可见痕迹 |
| **N21** | **同一用户一份 `DSH_HOME`**（会话存储的键是绝对路径，共享即串记忆） |
| **N22** | **编号 = 那条可见时间线已落盘事件的最大编号 + 1，只增不减**；**同一时刻只有一条会话能写可见时间线**；显示用**发生时刻**；补发段必须带"你不在时" |
| **N23** | **协议必须带作用域标识与来源**（客户端 v1 可以只显示"它"，**但字段现在就留**——协议一旦上线就改不动） |
| **N24** | **收起 ≠ 删掉**：默认"收起来"**不动数据**；"删掉"逐条对状态清单；工作区内删除**可找回** |
| **N25** | **任何能让助手写入变成"下次开机自动读"的路径，都必须不存在**；**apply 只认主人原话**；**清单 root 只读**；**回退不需要助手** |

### 5.1 ⚠️ 关于 N22：口径必须分「现状」与「目标」

| | 是什么 |
|---|---|
| **现状**【已实测】 | 编号是**每个对话 id 一份**（会话对象自己的计数器） |
| **目标**（X1.1/X1.2 + **P-l 甲**） | **每个用户那条可见时间线一个计数器**，由调度器统一发、= 那条日志已落盘最大 + 1 |

⚠️ **N22 正文的"全局"= "这个用户那条可见时间线"**，
**不是**全机器一个计数器，**也不是"每条 DSH 会话各数各的"**。
⇒ **P-l 定稿：一条可见时间线 = 一条日志，作用域只是事件上的标签**，
所以"统一发号"与"按时间线各数各的"**其实是同一句话**。

### 5.2 ⚠️ 关于 N24：天数以决策记录为准

N24 原文写"工作区内删除**可找回**"，而 **X3 / D6 那一批拍板的是"回收站默认 30 天"**，
且删除流程是 **收起 → 删掉（回收站）→ 到期真删 → 注销清空**。
⇒ **以 30 天那段为准**；N24 只保留"**收起 ≠ 删掉**"这个要点。

### 5.3 ⚠️ 关于 N25：**它此前不在任何架构文档里**

评审发现：**N25 只出现在决策记录里，自带标注"（待写入架构文档）"**，
而原始四份架构文档的不变量**止于 N24**。

⇒ **本手册是 N25 第一次落进架构正文的地方。**
它的依据是 **P1**（助手不能改自己）与 **P2**（执行特权走手动），
以及那条"**威胁的真实形态不是它干一次坏事，而是坏事能不能留下来**"。

## 六、与上一代架构的关系

**上一代（v7 那一版）里仍然有效的规范已经收敛进 [`08-SPEC.md`](08-SPEC.md)。**
新版覆盖它没有的三件事：

| # | 覆盖了什么 |
|---|---|
| 1 | **多租户**：从"一个用户"变成"一人一台容器" |
| 2 | **作用域**：从"一条会话 = 一个话题"变成"**一条会话 = 一个作用域**" |
| 3 | **统一窗口**：客户端**仍然只认一条时间线**，底下是多条会话 |

### 6.1 两条**明确改了上一代的话**

| # | 原话 | 改成 | 为什么 |
|---|---|---|---|
| 1 | "工作区根目录是隔离边界" | **不是安全边界**——它**只约束写，不约束读** | 文件沙箱的原文就是"confines model file **writes and edits** … while preserving the local filesystem's **read** behavior" |
| 2 | "算不出美元，因为 DSH 没有暴露用量" | **计数是活着的**（21/21 会话非零），但**没有价格表、没有用户维度、且被 cache read 主导（98.6%–99.8%）** | ⇒ 结论仍是"**不显示估算美元**"，但**理由变了**：不是"测不到"，而是"**没有价格表且总量口径失真**" |

> ⚠️ 第 2 条是一个**真实教训**：原来的理由**是错的**，而错理由会推导出错的修法
> （"等 DSH 暴露用量就好了" vs 实际是"永远算不出、因为拿不到价目表"）。

### 6.2 明确**不覆盖**的部分

上一代的其余内容（taint 棘轮、两档能力、制品管线、监控层、审计、备份）
**继续有效**——它们的正文**已搬进 [`08-SPEC.md`](08-SPEC.md)**（§一 不变量、§四 安全模型、
§三 数据与存储、§五 成本与可观测性），**本手册不重复**。

> ⚠️ **这是删旧文档时最容易出事的地方**：这些内容原本挂在
> "v7 仍然有效、本文不覆盖"这句话上。**删 v7 就必须给它们一个新家**——
> 否则那句话会变成一个指向空处的引用。

## 七、悬空与不一致（**不调和，只列**）

## 九、这张架构图最容易骗人的三处

| # | 容易以为是 | 实际是 |
|---|---|---|
| 1 | "把 agent 关在目录里就隔离了" | **只约束写**，读不受限（§1.3） |
| 2 | "客户端要为多作用域大改" | **几乎不用**——掩饰发生在调度器。**但要改传输层生命周期**（那是个真 bug） |
| 3 | "容器是第一步" | **不是**。它是**第二个用户的开门条件**；而供给上限（进程上限 + 淘汰 + 准入）**必须与它同批**，否则容器只是把天花板复制一遍 |
