### 1.4 资源与供给（**第二个用户的拦路虎**）

| # | 坏在哪 | 后果 |
|---|---|---|
| **无上限** | `server.js:99` 每条 WS 连上都 `warm()` 一个 agent；`conversationId` 来自 URL 且**无上限** | **`?conv=N` 就是 N × 195MB** |

## 二、术语与用词

### 2.1 术语表（**工程侧**）

| 词 | 指什么 |
|---|---|
| **琥珀 / hupo** | 这个产品 |
| **DSH** | DeepSeek Harness，跑 agent 的那层底座 |
| **调度器 / dispatcher** | `services/core`，常驻进程。四个职责：对用户的路由 / agent 之间的邮政 / 归一化成一条时间线 / 账号与供给 |
| **作用域 / scope** | 一条 DSH 会话 + 一个目录。**界面上永不出现"作用域"三个字** |
| **工作区** | ⚠️ **界面永久禁用词**（D1.1）。它是"作用域"在工程语境里的旧称 |
| **本子** | 作用域在**用户面前**的说法（D1 定义的隐喻） |
| **可见时间线** | 用户看到的那一条。**P-l：一条可见时间线 = 一条日志** |
| **作用域栈** | 主目录 → 本子 → …… 同时只有一个"焦点" |
| **浮窗** | 手机上那个唯一的聊天窗口 |
| **图标墙** | 桌面。作用域与内置应用都以方块出现在这里 |
| **一轮 / turn** | agent 的一次完整回答。**有构造上稳定的编号**（P-f 用它作键） |
| **收口** | 一条消息走到 `end`。**同一时刻最多一条未收口** |
| **升格 / escalate** | 一轮太久时，调度器把它变成"我单独拿去做"的可见任务 |
| **转交 / handoff** | 一个作用域把活交给另一个（最多一次、禁回环） |

### 2.2 界面用词纪律（**不是文风建议，是缺陷**）

| 类别 | 词 | 处理 |
|---|---|---|
| **永久禁用** | **工作区** | 图标名 / 标题 / 提示 / 空屏 / 报错，**一处都不许**（D1.1） |
| **必须换** | **口令** → **密码** | "口令"让人想到"当兵的站岗"（D2.2） |
| **必须换** | **进去 / 登录** → **打开** | "进去"没人读出"进门"，读出来的是"提交"（D2.3） |
| **不许泄入界面** | 工具 / 搜索 / 上下文 / 系统提示 / 内部工具名 / 阶段内部名 | 回答里提内部词**违反既有规矩**；过程展示**必须翻成人话**（D7.1） |
| **条件禁用** | **"听"字** | **不录音时禁用**（"正在听…"是假承诺）；录音时用"在听你说"（D5.5 / D5.13） |
| **不许用** | **系统编号** | 区分同名**必须用用户自己的话**（D1.4） |

### 2.3 两处"看着冲突、其实不冲突"（**写规范时必须写明**）

| 看着冲突 | 实际 |
|---|---|
| "**不要复述它**"（`dispatcher.js` 的 recapPrompt） vs "**回答首句回显原话**"（D5.7） | 前者禁的是复述**历史**；后者是回显**当轮输入**。**两回事。** |
| "回答里不提内部词"（人格文件） vs "等待期展示在做什么"（D7.5） | 前者反对的是**回答的腔调**（"根据搜索结果…"）；后者是**过程的可见性**。**两件事。** |

### 2.4 五个"不许写"

| 不许写 | 为什么 |
|---|---|
| 界面上的内部词 | 缺陷，不是文风（做成 `test/unit` 的闸） |
| **写死尺寸** | 它没有约束力（那条常量至今还在）⇒ **升成一条规矩：写死尺寸 = 缺陷** |
| 断言像素坐标 / 控件 key / "哪块贴顶" | 界面一重构必过期 |
| 断言"默认就最大化"这类**行为快照** | 它锁的是实现，不是产品要求 |
| **"以后再说"** | 一个人的产品里，**以后就是永远**。要砍就明说砍了 |

## 三、评审史（**两轮，各三席**）

### 3.1 第一轮：评审**实施计划**

**推翻了那一版计划的核心论断**——它说"五个基础设施项都是承重的"，
**其中三条在代码里证伪**：

| 原论断 | 复核结果 |
|---|---|

| 淘汰计时器不会重新计时 | ❌ 它会（`_armEviction` 有重新 arm） |
| 本地发言会被丢掉 | ❌ 不会 |

⇒ **教训**：**前提性事实必须复核**。
一位参与讨论的人曾拿"`sudo` 免密"这个**没复核的事实**当论据改了结论——
**而本机实测 `sudo` 要密码**。那条结论因此要翻（见 C5）。

### 3.2 第二轮：评审**工程文档**

三席（契约可执行性 / 协议可实现性 / 索引一致性）把工程文档**逐条拿代码核**，结论是
"**方向对、细节错了一批**"：

| 类别 | 数 | 最难看的一条 |
|---|---|---|
| **凭空写错** | 5 | 把"三条禁令"当成要维持的现状，**而第三条今天就已经被违反**（`conversations_app.dart:11`） |
| **说必须写死却没写** | 4 | 序号契约（"如何共存必须写死"至今没写死） |
| **漏掉的文件** | 9 类 | **全部新测试文件在索引里 0 处** |
| **批次顺序错** | 1 | 纯函数拆分在批 3，**而批 2 的验收依赖它** ⇒ 出口早于入口 |
| **自相矛盾** | 1 | 记忆 KV 标"批 4"，而它同时列在"本轮不建" |

**协议 v2 从 8 个字段砍到 6 个**（`source` 概念错；`scopeId`/`reRefs` 无数据源；`catchUp` 降级复又定案）。

⇒ **教训**：**文档里每一个"必须写死"，都要能在同一页找到"写死成了什么"。**
找不到，就是没写死。

### 3.3 ⚠️ 评审**自己也引错了几处**（第三轮核实发现的）

> **这一节是故意留的**：评审不是终审。**它给的每个行号也当断言看**，
> 第三轮独立核实推翻了它的 5 处引用。
> ⇒ **教训：引用行号时，先 `sed -n` 看一眼那行是什么。**

| # | 评审/文档怎么写 | 实测是 | 影响 |
|---|---|---|---|
| 1 | `smoke_test` **12 挂 3** | **18 挂 3**（静态 12 条声明，**其中一条在一个 7 项循环里**） | 挂数对（3）；**总数错**。总数 49 挂 10 不受影响 |
| 2 | `chat_controller.dart` 的承诺注释在 **`:424`** | 在 **`:420`**（`:424` 是空行）。**原始计划写的 420 才是对的** | 动手时以 **420** 为准 |
| 3 | 自动拉满那块在 **`:143-147`** | 在 **`:142-146`**（`:142` if、`:145` 拉满、`:146` `}`）。**原始计划写的 142-146 才是对的** | 动手时以 **142-146** 为准 |
| 4 | 事件流是 broadcast（**`:207`**） | broadcast 声明在 **`:48-50`**；`:207` 是 `_events.add(event)` | 链条结论不变，出处要改 |
| 5 | `info.turn`（`session-translate.js` **`:202`** 已随 info 给出） | `turn` 在 **`:210`**（对象字面量 `:209` 起）；`:202` 是 writer 的 `messageId` | 修法不变，行号要改 |

### 3.4 ⚠️ 一处**结论对、归因错**（比行号错更值得记）

评审（以及它的上游）说"`message/status` 推了但 **working/thinking/handoff 全库没有 UI 读**"。

**实测**：`answer_bubble.dart:27/52/176-181` **有一个 `_StatusLine`，四态全都渲染**。

⇒ **真正断链的是取号**：`dispatcher.js:567` 发 `messageId: ''`
⇒ `chat_controller.dart:378 _messageOf('')` 恒 null
⇒ `:284 applyStatus` 不生效 ⇒ `message.status` 永远 null ⇒ `showStatus` 恒 false。

**为什么这条值得单列**：归因错了，**修法就会错**——
"没 UI 读"会让人去**写一个新的状态组件**（白做），
而真因是**取号失败**（S2 已经包含它）。
⇒ **结论对不等于归因对；照错的归因动手会做无用功。**

## 六、两份"能力清单"

### 6.1 已经验证可用的 DSH 能力

| 能力 | 用途 |
|---|---|
| workspace 列表 | 有序、持久的工作目录 + 会话（**对模型不可见**） |
| session 日志 | append-only；fork / replay / compaction |
| session 查询 | 跨会话与会话内全文检索 |
| session 标题 | **永不进入模型输入** |
| storage domain | schema 校验的键值存储 |
| jobs | 忙时→下一步；闲时→有界跟进。**待处理通知不跨宿主销毁存活** |

| session 引用 | 有界、不可变的**不可信**快照 + 固定警示 |

### 6.2 已经踩过并写进 checklist 的坑
