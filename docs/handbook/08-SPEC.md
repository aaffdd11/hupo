#### 四条角色定义与纠偏

| 角色 | 定位 | **纠偏（最容易被搞错的地方）** |
|---|---|---|
| **接收层** | 先应一声、给方向 | **不是"机器人客服"**——它是有判断的 |
| **处理层** | 真正干活 | **它就是一个真 agent**，不是"调一次模型" |
| **反馈层** | 给出深思后的结论 | **不是"第二个接话的角色"**，它是**经过深思熟虑的那部分回答** |
| **监控层（旁路）** | 看这个对话到底好不好 | **它是第二个执行体**，拿**只读档**，产出**不许进指令位** |

#### 两块回答必须是"**一个人在一次回答里说的**"

一轮对话里用户应当收到**两块内容**：① 接收层的**快速回答**（回应、确认、方向）
② 反馈层的**深思回答**（研究之后的结论）。

> **`ARCHITECTURE-seamless.md` 解决的核心问题**：
> **怎么让这两块看起来是一个人在一次回答里说的，而不是两个人各说一段。**
>
> ⇒ 这就是协议里"**quick + deep 同一个气泡**"那条规则的来由。

#### 交付形态：回答不只有"几句话"

> **判断标准不是"内容多少"，而是"这个回答是否需要一次交互"。**
> ⇒ 需要交互的回答，形态可以是 **H5 / 动态页面 / 完整应用**。

⚠️ **【本轮缩小范围】**：本轮**只做最小形态**（不联网 / 无权限生态 / 不许反向发话），
**iOS 商店版不发**。

#### 说话人识别与主被动对话（**本轮不做**）

| 角色 | 系统怎么对待 |
|---|---|
| **主人** | **默认只对主人回应**；以主人为记忆主体 |
| **访客** | **默认不回应**；发言进会话语料，**不进主人的对话记忆** |
| **被点名** | **例外通道**：任何人对助手直接说话（非主人也算）⇒ **必须回应**，否则用户会觉得"它不理我" |

⚠️ **【本轮不做】**：级联 / 说话人识别 / 被动模式。

#### 情绪与前提

**R3：情绪只影响"怎么说"，不影响"说什么"。**
（这是 `R1–R5` 里的第三条，见 §1.1。）

#### ⚠️ 两起**真实的**"页面在说假话"事故（**最重要的一段**）

> 创始人两次来问「页面怎么还在说……」。
> **两次都不是显示 bug，是服务端把不真实的状态写进了对话记录。**

**事故一：「还有件事在处理」永远挂着**

| | |
|---|---|
| **现象** | 页面上那行灰字从 15:31 挂到 16:39，用户半小时后还在看它 |
| **根因** | 那句话是客户端**从事件记录重建**的（`task/created` 建、`task/completed` 消）。而 agent 改客户端改到一半重启了服务，**它自己连同那件活一起被杀**，**没人补 `task/completed`** |
| **修法** | 启动时**对账**：扫记录，`task/created` 没有配对的 `task/completed` ⇒ 一定是被打断的 ⇒ **一定收口**。但**只对最近 6 小时内**的说话；更早的旧账悄悄清掉 |
| **措辞** | 用「**可能没做完**」而不是「没做完」——系统只知道"我被断了"，**不知道**那件活到底做完没有（可能改完了只是没来得及回话） |

**事故二：「我已经升级好了。」堆了 7 句**

| | |
|---|---|
| **现象** | 对话里躺着 **7 句一模一样的**「我已经升级好了。」（每次服务重启一句） |
| **根因** | 判断"要不要说这句"的判据**太松**：只看「它之前在这个会话里」+「本次启动还没说过话」⇒ **每次重启、只要客户端重连就说一句**。**判据里缺了"他确实被打断"这一条** |
| **修法** | 由客户端自报一个它**确实知道**的事实：**「这次连接是断线重连，还是页面刚打开」**（传输层记 `_everConnected`，连成功过一次之后的连接才带 `interrupted=1`） |

**事故三：回答硬截断在半句（用户拿到"看起来说完了"的残篇）**

| | |
|---|---|
| **现象** | 回答断在「一个是"避」「临海老」——用户拿到一个**看起来说完了**、其实没说完的残篇 |
| **根因** | agent 撞上单步输出上限时，收尾原因是 **`max-tokens`**，而**翻译层完全忽略这个原因**，一律写成"正常说完" |
| **两处修** | ① **识别非正常收尾**：原因不是"正常说完"时**补一句说明**（"这条我说太长了，被长度限制截断，剩下的我没说完"）并把收尾标成失败——**绝不许把半句当完整回答**；② **把输出上限调大** |

> ⚠️ **还有两条同族事故**（未被计入上面这三起，但同样真实）：
> - **消息交叉**：挪走时只说了"我拿去做"、**没把 agent 手上那条气泡收口** ⇒
>   后续文本写回**更早**的那条消息 ⇒ **时间倒流**、用户看到"像在补齐对话"。
>   ⇒ 修法：挪走时**先收口、再另起**；不变量"**消息之间不许交叉**"写进测试。
> - **编造具体来源**：回答写了"某大学某年有一篇论文，访谈了 227 名幼儿"，
>   **而那一轮的来源条数是 0**。⇒ 修法：人格勒紧七类 + **机械化兜底检查**。

#### 这些事的共同教训（**写进纪律**）

> **客户端的显示是服务端事件的投影。**
> 服务端一旦写进一条不真实的状态，**页面就会一直替它说那句话——而且说得理直气壮**。
>
> ⇒ **写进对话记录的每一条，都要问一句"这条一直是假的怎么办"**（这就是 **N7**）。

### 1.3 ⚠️ "来源"这个词指**两个不同的东西**（**别再混**）

这是本项目最容易搞混的一处，**因为它俩同名**：

| | 是什么 | 取值 | 活在哪 | 状态 |
|---|---|---|---|---|
| **taint 来源分级** | 进入 agent 上下文的东西**从哪来**，**决定能力档** | `owner` / `product` / `derived` / `foreign` | **host（调度器）** | ✅ **【有效】**（N3） |
| **协议字段 `message/start.source`** | 曾想表达"这条消息是谁触发的" | —— | 协议线上 | ❌ **【已取代】删掉了**（决策 P-i） |

⇒ **协议侧改用已经在线上的两条轴**：
**`agent`**（谁在说：`agent` / `dispatcher`）+ **`origin`**（为什么开口：`reactive` / `proactive`）。

⇒ **taint 那一套没有取消**，它活在 host 侧，与协议字段无关。

## 四、安全模型

### 4.1 来源分级 × 能力档（**两档，不是四档**）**【有效】**

| 来源 | 档位 |
|---|---|
| `owner`（主人原话，经鉴权通道 + 设备/构建指纹） | **受信档**：全权 |
| `product`（固定话术、画像块） | 受信档（**但它本来就不带工具调用**） |
| `derived`（网页 / 子 agent / 监控层 / 未复核记忆） | **吃到即降只读档** |
| `foreign`（小程序输入 / 制品内容 / 别的会话） | **只读档** |

**只读档** = `bash` / 写文件 / 改系统 / 对外发送**全部 deny**；
**但"只读工具"与"写工作区"不受限**——⚠️ 把文件工具整个禁掉会把"读文件"也一起杀掉，**agent 变废人**。

**清 taint 只在 host**（`dispatcher.say()` 收到 `owner` 时清）——**模型碰不到**。
如果模型能清自己的 taint，"读到网页 → 自己清 → 改系统"就是一条直路。

**无审批 UI**：问的方式是**对话里一句带新信息的话**（"查到了 3.2.1，要我直接升上去吗"）。
⛔ **不做**：审批弹窗、`request_capability` 一键授权、自动衰减。

**监控会话套同一套只读档**——它今天是**同权的第二个全权执行体**，这是要改的。

### 4.2 其他防线 **【有效】**

| 防线 | 内容 |
|---|---|
| **鉴权** | 口令 **fail-closed**（没设口令 ⇒ 除三个公开路由外一律 503）；XFF 取**最后一跳**；登录失败计数**落盘** |
| **密钥** | spawn 用**减法 env**（去掉 `*_API_KEY` / `*_TOKEN` / `*_SECRET`）；`~/.ssh` 与 `data/auth.json` 收权 |
| **自我修改** | 见 **P1**（助手只能提申请，签字的是主人）；策略文件 root 只读 + **开机前完整性校验** + 回退不需要助手 |
| **注入持久化** | 所有"会自动进未来上下文"的落点（人格 / 设置 / profile patch / 画像 / 手册）**都进完整性清单** |
| **制品** | ✅ **已落地**（2026-09-22）：独立 origin（`apps.stalkerai.cn`）· 沙箱（不给 `allow-same-origin`）· hash（读回来逐字节核）· **版本不可变**（同版本重发拒）· **不可变审计**（谁/哪一轮/哪句话/rootHash）· ⚠️「发布走特权口」今天的读法是**由 L2 服务端发布，不是 agent 自己写**（制品落在用户自己的世界目录里，不需要 root）—— 见 [`59`](../dev/59-USER-APPS.md) §四 |

### 4.3 一人一台：**"新号自动拿到一台"的安全模型**（A1–A9）**【有效】**

> 判据是不变量 **N26–N28**（`02-ARCHITECTURE.md` §五）。这一节写**怎么算做到了**。

**问题的准确形状只有一件**：*一个公开的网页登录口，要怎样才能触发一个特权动作，
而不等于把 root 交出去。*

| | 做法 | 结论 |
|---|---|---|
| ① | 给服务一条 **sudoers / polkit** 规则 | ❌ 边界变成"那个脚本必须毫无破绽"，而脚本要吃参数与环境 |
| ② | 一个**常驻的 root 守护** | ❌ 一块要长期盯着的面（协议解析、常驻进程本身） |
| ③ | ✅ **申请队列**：服务只能"放一个文件"，特权侧按需（`systemd` 触发）读它 | **选它**：边界小到**能用眼睛看完全部输入** |

| # | 不变量 | 怎么验（**每条都要带负向对照**） |
|---|---|---|
| **A1** | 🔴 **特权侧只读一个整数**：申请 = `<整数>.req` 这个**文件名**；**内容一律不读**，不收参数，不读环境里的任何路径 | 把一个内容是 shell 命令的申请放进去 ⇒ 那个编号正常处理，而**那串命令一个字都没被执行** |
| **A2** | 🔴 **一切从模板推出**（用户名 / 编号 / 目录 / 卷 / 单元名）；推不出来就**拒**，**不许猜** | 拿 `../` / `;` / `$()` / 空 / 超上限逐个塞 ⇒ **全拒**，且目录里**没多出东西** |
| **A3** | 🔴 申请目录 **sticky、root 属主**；每一项必须是**普通文件**（不是符号链接）且属主 = 服务那个 uid | 放一个符号链接冒充申请 ⇒ **拒**（对照：普通文件 ⇒ 认） |
| **A4** | **幂等 + 有上限**：同一个编号重复申请**什么都不做**（绝不重建、绝不清空人家数据） | 同一个编号连投多次 ⇒ 只建一次；超上限 ⇒ **不做**（并且**明说**） |
| **A5** | **拒也要留痕**，并且处理完就**删掉申请**（不管成败） | 一个坏申请 ⇒ 文件**不见了**、日志有那一行、系统**没有**反复触发 |
| **A6** | **服务的身份不变**：不加 sudo 权限、不进 docker 组 | 装完前后 `id` / `sudo -l` / docker 组成员 **逐字相同** |
| **A7** | **每次申请与每次真建都留痕**；那一行**不含手机号、不含凭据**（只有编号） | 扫日志：不该出现的东西一个都没有 |
| **A8** | ⚠️ **装它本身是"部署期"的动作 —— 要主人签字**（P2） | 助手只写代码与方案；装进系统的命令**主人跑** |
| **A9** | 🔴 **root 要跑的每一份文件都必须 root 拥有**（见 N27） | `stat` 四份都必须是 `root`；以服务身份改它们 ⇒ **`EACCES`**；并提供"仓库那份 vs 装着那份"的**逐字节核对** |

🔴 **A9 是最容易漏、而且漏了会把 A1–A8 全部作废的那一条**：
若让单元直接跑**仓库里**那个脚本（仓库属主 = 服务自己），那么一个被攻陷的服务
改一行，下次申请触发时**那段代码就是以 root 跑的**。⚠️ 而它**看起来是对的**
（路径对、脚本真的跑了、日志漂亮）。
⇒ 所以：**运行的那一份必须是 root 拥有的拷贝**，并且要有"**改完了 ≠ 生效了**"的核对命令
（见 `06-OPERATIONS.md` §五）。

⚠️ **诚实边界**：`A1–A5 / A7 / A9` 那几半**不需要真建东西**就能验（拒的那一半）；
"**真建一台**"那一半只在装完单元之后验得了 —— **没签字之前，不许把它算成绿的**。

### 6.1.1 🔴 **动效纪律：永不结束的动画必须有一个能关的总开关**（2026-09-22）

> ⚠️ **现在的客户端里没有"永不结束"的动画**（2026-09-22 加的那个水面背景
> 已经在 **2026-09-23** 按主人要求删掉了）。⇒ **这一节是"将来要加时先读"的前提**，
> 不是对现状的描述。它的价值在于：**踩过一次，而且代价是整套界面闸**。

> 这一条**不是审美**，是**闸的形状**：`pumpAndSettle()` 的出口是"没有下一帧了"
> （`flutter_test/src/widget_tester.dart`：`do { pump() } while (hasScheduledFrame)`），
> 而一个 `..repeat()` **永远出不来** ⇒ 转到 10 分钟超时。
> 实测：一个只有 `..repeat()` 的探针，3 秒内就 `pumpAndSettle timed out`。

| # | 规矩 |
|---|---|
| **M1** | 凡是**永不结束**的动画，必须有一个**库级总开关**（默认 **开**）。⚠️ 默认关的话，线上是静止的、而测试是绿的 —— 两边都不知道自己错了 |
| **M2** | 关它的地方**只许有一处**（现在是 `test/flutter_test_config.dart`）。⚠️ "每个用例写一行" = 要写十几个文件 ⇒ 以后新加的用例**一定会漏** |
| **M3** | **关掉它 ≠ 删掉那一层**："不动"与"没有"是两件事。做装饰的那一层关掉之后**照旧在树上、照旧画**（停在第 0 刻），否则"用户开了减弱动态效果"会**静默少一样东西**（两张截图看起来"差不多"） |
| **M4** | 系统要求**少动**（`MediaQuery.disableAnimations`）⇒ 纯装饰**不画**（同 D3.5：别假装支持） |

### 6.1.2 🔴 **装饰层必须能"看得出来"：结构判据全绿也会整层看不见**（2026-09-23，真栽过）

> ⚠️ **这一段记的是一次已经结束的事故**：那一层（水面背景）**2026-09-23 已按主人要求删除**。
> M5–M7 留下来是因为它们**与那一层无关** —— 换成任何"看得见的东西"都成立。

> **事故**：桌面的水纹上线后，主人回了一句 *"水纹没有生效。"* —— 他是对的。
> 水面画在 `Stack` 最底层，而**上面那层 `Material` 是不透明的纸色**
> ⇒ 涟漪照常在算、ticker 照常在跑、**一个像素都透不上来**。

| # | 规矩 |
|---|---|
| **M5** | **"加了/改了看得见的东西"必须有判据打在像素（或那一层的颜色）上**。⚠️ 出事那版**八条判据全绿** —— 它们验的是"在不在树上 / 会不会吃点击 / 会不会拖死 `pumpAndSettle`"，**没有一条验"画出来的东西看得见"**。判据全在验**结构**，而这件事**只**在像素上成立 |
| **M6** | 一条**正**、一条**反**：① 把画家的输出光栅化成图，**必须有一片点和底色不同**（拦住 alpha=0 / 颜色写成底色 / 尺寸算成 0）；② **源码级**钉住"盖在上面的那一层必须透明"（拦住"把不透明的纸又摆回去"） |
| **M7** | 🔴 **读数与用户说的打架时，先信用户**。我事后做过一整套像样的排查（隔几秒截图 / 把 alpha 提到 100% / 拿普通 canvas 动图当对照），得出的结论是"**页面根本不重画**"—— **那是错的**：它在重画，只是**被盖住了**。⇒ 用户那句"没生效"比我一整页截图分析值钱 |

> ⚠️ 这一批**自己栽过一次**，记在这儿：`build()` 里算"动不动"时漏了那个总开关
> （`_run()` 里算对了 —— **同一个判断写两处**）⇒ `desktop_floater_test` 7 条超时。
> ⚠️ 那条判据（"pumpAndSettle 不挂"）**随那一层一起删掉了** —— 它只对那一层有意义。
> 抓到它的是"pumpAndSettle 不挂"那条判据，因为它**不读那个标志**。
> ⇒ 顺带一条：**给开关写的判据，自己不许去读那个开关。**

> **验收**：小程序打开后，对浮窗中心坐标做 hit test ⇒ 命中**聊天**，不是小程序。

### 6.2 三档与触发规则

**三档**：收起 / 半开 / 最大化。高度用**系数**表达（具体值在代码里）。

> **默认档 = 收起**（主人 2026-09-22 定：一进来看得见桌面，点那条**带字的**「展开」才开聊）。
>
> 🔴 **收起态 = 抓手行 + 输入条**（主人 2026-09-22：*"助手那个聊天窗口，收缩的时候也有一个输入框。"*）
> —— 这本来就是阈值总表里写的形状（`抓手 + 标题行 + 输入条`），中间那版做丢了。
> ⚠️ 上下两态用的是**同一个输入条实例**：两处各建一个的话，"打了一半再展开"会换一个 `State`、**框里的字就丢了**。
> ⚠️ 从收起态发出去**照样"发就拉满"**（那也是这一档最有用的一条路）。
> ⚠️ 默认值这件事**是产品行为，不是实现细节** —— 要改它就得改这一行并升版本，
> 别为了哄某个测试把默认值改回去。
>
> 🔴 **抓手行最前面有一个图标：这句话是在哪儿说的**（主人 2026-09-23）：
> **在桌面上**（没进任何小程序，也就是全局）= 一个**家**；**进了某个小程序** = **那个小程序
> 自己的图标**（与桌面上那个图标**同一个来源** —— 不然"进去了"在两处会长得不一样）。
> ⚠️ 它是**指示，不是按钮**（点了不做任何事 ⇒ 不涉及 D3.6 的命中区）；**收起态也画它**
> （收起那条照样能把话发出去）。详见 [`../dev/52-DESKTOP.md`](../dev/52-DESKTOP.md) §七。

| 事件 | 结果 |
|---|---|
| **用户按下发送** | → **最大化**（发就拉满） |
| **只有状态变化**（thinking / working） | **不动**——状态不是"开口"，否则每次状态跳变都抽动窗口 |
| 点浮窗外面 / 点桌面空白 | → 收起 |
| 双击抓手 | 收起 ⇄ 回到上次档位 |
| **400ms 内的连续触发** | **合并成一次**（防抖：助手连发多段不该让窗口抖） |

> ⚠️ **【已取代】** 旧规格里还有一条"**助手开口说话（有新的一条调度器消息）→ 最大化**"。
> 它被 **D4.8 推翻**：**新增助手消息触发的高度变化必须 = 0px**
> ——"每说一句每收一句桌面就被抹掉一次"是**平板用户的主要放弃点**。
> ⇒ **只有"用户主动说话"才拉满。**

### 6.3 手势优先级（写死，避免打架）

| 手势 | 结果 |
|---|---|
| 竖向拖抓手 / 标题行 | 改高度（**跟手**，松手吸附） |
| 甩 | 下甩收起 / 上甩拉满。⚠️ **判据已改**（D3.7）：**速度 + 位移 + 时长三个都要满足**，且**要能关** |
| 双击抓手 | 收起 ⇄ 上次档位 |
| 点浮窗**内部** | **无反应，不许漏到下面** |
| **用词（2026-09-22）** | 🔴 **浮窗「里面那圈」叫 padding**（内容离边）· **「外面那圈」叫 margin**（浮窗离屏，= Z3/Z4 那个 30）。⚠️ 两个词混着说，改的人**一定会改错那一处** |
| **展开态的「收起」** | 🔴 **必须一直看得见**（2026-09-22）：它原来在那条**横向滚动**的动作里 ⇒ 窄屏 + 大字号下**会被滚出视野**，而"想收起来"的时候找不到出口 = **没有出口**。⇒ **钉在横滚之外** |
| 点收起态底部条 | 展开到上次档位 |
| **点收起态那个输入框**（"说点什么"） | **同一条**：展开到上次档位（2026-09-22 主人点名）。⚠️ 两处必须走**同一个方法**（`expand()`）—— 各写一套迟早分叉 |
| 点桌面空白 | 收起 |

> ⚠️ **"点浮窗自己不该有任何反应"是靠 `HitTestBehavior.opaque` 挡的**——
> **这条必须保留**：`deferToChild` 挡不住，点空白会**漏到桌面**。

| # | 规则 |
|---|---|

| 项 | 要求 |

### 6.7 实现约束（都踩过）

| # | 约束 |
|---|---|
| 1 | 点浮窗自己**必须**用 `HitTestBehavior.opaque` 挡住 |
| 2 | **跟手拖拽期间动画 = 0ms**（手指按下的东西必须跟着手指） |
| 3 | **"还有件事在处理"的小标在收起态必须留着**——不能被浮窗吃掉 |
| 4 | 小程序容器要保持**挂载**（Z2） |
| 5 | 🔴 **凡是要求用户"粘一长串"的输入框，必须自带一个「粘贴」按钮** |
| 6 | 🔴 **拖拽手势只许绑抓手 / 标题行** —— 绑在**整块浮窗**上会把**内容的滚动吃掉**（往上拖时间线被当成"把窗口拉高"）。2026-09-22 实测栽过：当时**没有判据**，是"重发那个入口"那条先红的 |
| 7 | 🔴 **浮窗里那块内容，没地方时**要**能滚**（空屏也一样）—— 高度变小（桌面那一条 + 四边 30）之后，3.1 倍字号下它会被挤扁；**不许靠"把字写小"**（D3.5） |

> ⚠️ **第 5 条是 2026-09-21 主人亲报「我无法黏贴，为啥」之后加的，理由很实**：
> Flutter 把字画在 **canvas** 上，长按弹的是**它自己的**选择菜单 ——
> 而**空输入框里没有可选的文字** ⇒ **菜单不弹 ⇒ 没有"粘贴"**。
> 桌面浏览器按 `Ctrl+V` 没事，**手机没有物理键盘就卡在这儿**。
> 而"钥匙"那一屏要的恰好是"粘一长串" ⇒ **没有按钮就是进不去**。
> ⇒ 一个按钮按下去就是"**用户手势**"，能合法读剪贴板。
> ⚠️ 读不到剪贴板时**不许只说失败** —— 要说清"还能怎么办"（用键盘上的粘贴键 / 手动输入）。
> ⚠️ 这一条**不是"这一屏的问题"，是这一类的**：任何"要粘东西"的新输入框都得带上它。

#### ⚠️ 已知问题：`hupo.chat` 无法签发证书（**域名级拦截**）

**现象**：Let's Encrypt 验证持续 403；同一台机器、同一 nginx、同一插件的另一个域名
却 `dry run successful`。**唯一变量是域名。**

**排查到的证据**：

| 观察 | 结果 |
|---|---|
| LE 的请求是否到达本机 nginx | ✅ 是（访问日志有 `23.178.112.x`） |
| nginx 对 LE 的响应 | `200` 但 **0 字节** |
| 同一 URL 本机访问 | `200`、87 字节（正常） |
| 挑战文件状态（钩子自检） | 644、87 字节 ✅ |
| 换子域 | ❌ 同样 403 |
| 换域名 | ✅ **一次签成** |

**结论**：`hupo.chat` 存在**域名级拦截**。本机在**大陆**节点上，
80/443 对外提供服务的域名需要 **ICP 备案**——`*.stalkerai.cn` 已备案所以正常，
`hupo.chat` 大概率未备案。

**处理**：主域名用 `hupo.stalkerai.cn`。
若要用 `hupo.chat`，需先在云厂商完成备案（或确认没有配 CDN/WAF 拦截）。

## 十一、运行机制（崩溃守护 / 回退锚点 / 预算降档）

> 这三条**不在代码里，也不在别处**——上一代把它们写在细架构里。
> ⚠️ **它们是目标态**（当前多数未实现），但**是"怎么不出事"的答案**。

### 11.1 崩溃守护

```
读 data/.crashloop.json
  + journalctl -u <服务> -n 50 里有没有 oom-kill
        │
        ├─ 5 分钟内 ≥3 次启动 **且** 有 oom-kill
        │     ⇒ 置 CONCIERGE_SKIP_RESUME=1
        │     ⇒ 落 data/.degraded
        │     ⇒ 记一条**待发消息**（要告诉用户）
        ▼
   **降级启动**：不续做、不预热，**只服务对话**
```

**恢复**：**连续 10 分钟无崩溃**才恢复正常。

> ⚠️ **降级期间不续做**——这是刻意的：崩溃环里继续续做只会放大问题。
> ⚠️ **降级必须对用户说一句人话**（N11），**不许静默降级**。原话是：
>
> > 「**刚才我连着重启了几次，先把手上这件事放一放，你现在说什么我都接。**」
>
> 降级期间健康检查要暴露 `degraded: true`，并发一条 **P0 告警**。

### 11.2 回退锚点 `data/.last-good.json`

| 项 | 规定 |
|---|---|
| **什么时候写** | **运行满 60 秒且无崩溃**才写 |
| **里面存什么** | `{commit, startedAt}` |
| **用途** | 它是**自动回滚的锚点**——回退到那个 commit |
| **谁执行回退** | ⚠️ **不需要 agent**（N5）——这一点很重要：**出问题时 agent 本身可能就是出问题的那个** |

### 11.3 预算三级怎么落地

| 级 | 触发 | 行为 |
|---|---|---|
| `warn` | 任一计数 ≥ **75%** 软上限 | **不改变行为**；进开发者卡片与任务簿 |
| `degraded` | ≥ **90%** | **不再放行新的工具调用**（理由是"预算到上限，把手上结论说清楚"）+ **不再接受新的任务**（这一轮就地收尾） |
| `stopped` | ≥ **100%** | **才停**，且**必须留一句人话** |

> ⚠️ **"必须在开口之前停"**：`message/end` 不许是长度上限或失败造的**半句**。
>
> ⚠️ **日界重置**：本地日 **00:00**。**不在进程内挂 `setTimeout`**（跨天时进程可能重启过），
> 而是**每次记账时比较 `dayKey`**，变了就清零 + 记一条步骤。

### 11.4 启动横幅要报告状态（**别静默**）

```
鉴权 fail-closed（未设口令，仅三公开路由） ／  鉴权 ✓
降级启动（跳过续做）  ／  策略校验 ✗
```

> 原来那条"鉴权未生效"的裸奔警告**要删掉**——fail-closed 之后**这种情况不可能进入服务态**。

## 十二、L3 运行契约（工具能力 / 记忆写闸门 / 人格）

> 出处：`docs/design/L3-worker.md`。**这些不在代码里**，删旧文档就会丢。

### 12.1 role 三类 → 三份 patch

**role 不是标签，是启动参数**：它决定挂哪份 patch、注入哪个权限模式。

| role | 谁用 | patch | 权限模式 | 能不能改系统 |
|---|---|---|---|---|
| `owner` | 主人原话触发的会话 | `policy-owner.yml` | `workspace-write` | 能，**但受 taint 约束** |
| `untrusted` | 本会话**已吃到**外部内容（taint 置位） | `policy-untrusted.yml` | `read-only` | **不能** |
| `monitor` | 监控层 | `policy-monitor.yml` | `read-only` | **不能** |

> ⚠️ **role 只能在 spawn 层决定**——hook 的子 agent 接缝**不带 per-kind 标签**
> （matcher 是常量）。所以"按角色区分"**必须在 `AgentRuntime` 里做**。

#### 三份 patch 大致长什么样（**照抄原文的要点**）

**受信档**：权限模式 `workspace-write`（**要改系统时由 host 显式提权，不由模型自己切**）；
主 agent 保留派活能力但**禁孙 agent**。

**只读档 / 监控档**：权限模式 `read-only`，然后**逐个 `disabled: true`**——
`tool-bash`（**最关键的一条**）、`tool-web`（对外发送）、`tool-subagent`、
`tool-workflow`、`tool-ralph`、`tool-skill`（**技能 = 指令注入载体**）；
监控档另加 `tool-fs` 的**写关闭**。

> ⚠️ **两道叠加，不是二选一**：权限模式 **＋** hook 的 `deny`。
> **即使模式被切回来，hook 仍然 deny。**
>
> ⚠️ **已知最严重的冲突**：权限模式可能被宿主的**默认预设（`danger-full-access`）盖掉**
> ⇒ 建议"**改默认预设**"与"**无论如何保留 hook deny**"**一起做**。

### 12.2 逐工具能力矩阵（**两档**）

| 工具 | 干什么 | 受信档 | 只读档 |
|---|---|---|---|
| `tool-fs` | 读/写文件 | ✅ | **读 ✅ / 写 ❌**（靠权限模式） |
| `tool-fs-search` | glob / grep | ✅ | ✅ |
| `tool-bash` | 跑命令 | ✅ | **❌ deny** |
| `tool-pwsh` | PowerShell | ✅ | ❌ deny |
| `tool-web` | 网页抓取 / 搜索 | ✅ | **❌ deny**（对外发送） |
| `tool-subagent*` | 派活 | ✅（受深度约束） | ❌ deny |
| `tool-workflow` / `tool-ralph` / `tool-jobs` | 大规模 fan-out | ✅（受预算约束） | ❌ deny |
| `tool-skill` | 技能（**= 指令注入载体**） | ✅ | ❌ deny |
| `tool-todo` / `tool-goal` | 内部计划 | ✅ | ✅ |

> ⚠️ **绝不许把 `tool-fs` 整个 disabled**——那会把"**读文件**"也一起杀掉，
> **agent 变废人**。只读性靠**权限模式**对"文件副作用"的约束来保证。
>
> ⚠️ **`tool-web` 在只读档也 deny**：只读档是"**已经吃到外部内容之后**"的档位。
>
> ⚠️ **hook 里只写 `deny`，不写 `ask`**——无头会话**没有人应答 `ask`**。
>
> ⚠️ **降档必须"换进程"，不是"运行时改模式"**——进程级隔离，**模型碰不到**。

### 12.3 记忆写入的五道闸门（**五条都要**）

| # | 闸门 | 为什么 |
|---|---|---|
| 1 | **兜底路径不沉淀** | 实测踩过：问"跟客户解释延期"**复用了"失眠"的答案** |
| 2 | **表面相似度闸门**：`score = 0.6×coverage + 0.4×jaccard`，**阈值 0.18** | 实测：单用 Jaccard 会把两句同义的话判为不相似（0.17） |
| 3 | **只写陈述，不写指令** | **知识库里出现祈使句 = 后门** |
| 4 | **无出处不写**；网页来源默认"未采信" | N4 |
| 5 | **`looksLikeInstruction()` 扫描**：祈使句 / 零宽字符（U+200B–200D）/ `\u202e` / 隐形 Unicode ⇒ **quarantine** | quarantine 的条目**永不装配到指令位** |

**采信度与"行动依据位"**：

| 采信度 | 谁能用 |
|---|---|
| `owner` | 可进**行动依据位** |
| `verified` | 可进行动依据位（**需有复核记录**） |
| `unverified` | **只能进"参考"位**，且**必须显示出处给用户可核** |

**读出口（只给主 agent）**：本轮只读相关条目 → **尾部追加**成"装配简报"
→ 用途是**决定派哪个子 agent / 要不要新建**。
⛔ **不给"记忆直接出话"出口**（快答由主 agent 第一段文本承担）。

**条目字段**：`{id, userId, key, value, source, trust, at, expiresAt, tags, hits}`
——其中 `value` **只写陈述，不写祈使**；`source` 取值
`owner | web:<url> | app:<id> | agent:<会话> | derived`；`trust` 见上表。

**衰减与提升**（来自 v1 的实测代码）：

| 项 | 公式 |
|---|---|
| **衰减** | **`confidence × 0.5^(days/30)`**（半衰期 30 天） |
| **被引用提升** | `hits + 1`，且 **`confidence = min(0.98, c + 0.12)`** |

### 12.5 上下文前缀不变量（**实测差 18 倍**）

### 13.1 容器验收（**必须逐条跑，不许"看起来没问题"**）

| # | 判据 | 期望 |
|---|---|---|
| **V1** | 在容器里读宿主凭据（`/proc/1/root/...` 指向宿主的密钥文件与 ssh 私钥） | **必须失败** |
| **V1b** | **负向对照**：在容器里 `touch /tmp/canary` | **必须成功**——否则"失败"可能只是因为容器根本没跑起来 |
| **V3** | 访问云元数据地址 `169.254.169.254` | **必须失败** |
| **V4** | **a** 以 **agent 的身份**（非 root，见下方"agent 的身份"）读凭据那条路<br>**b** `env \| grep -cE '(_API_KEY\|_TOKEN\|_SECRET\|DEEPSEEK)'`（**agent 进程的 env**）<br>**c** `grep -rl "sk-" /data /home` | **a** 必须失败，**且失败方式必须是 `EACCES`（`permission denied`），不许是 `ENOENT`**<br>**b** = 0<br>**c** = 0 |

> **V4 说的到底是什么**（v1.8 改）：**"容器里不许有秘密"** 这句话在**整台容器**上讲是不成立的 ——
> 用户自己的凭据**就是**要进他自己的容器（否则它没法调模型）。
> 它真正要的、也是这里要判的，是：**盒内除了那个持有凭据的服务身份之外，谁（尤其 agent）都够不着它。**
> ⇒ 判据因此钉在**"谁去读、失败成什么样"**上，**不钉在"文件在不在"上**。
>
> ⚠️ **`c` 绿了不算 V4 过**：凭据按契约住在 **tmpfs**（不在 `/data`、也不在 `/home`），
> 所以 `c` **本来就该是 0** —— 拿"我把它放到扫描范围之外"当通过，正是本项目最忌的"**看着像过了**"。
> `c` 留着是有用的，但它管的是**另一件事：别处（用户数据里）漏了副本**（agent 把 key 抄进自己的工作区、或写进日志）。
>
> **V4a 的负向对照（不能省）**：① **root 读同一份必须成功**（服务侧拿得到）；
> ② **同一目录里放一份 `0644` 的对照项，agent 读必须成功** ——
> 否则"读不到"可能只是因为**路径拼错了 / 挂载没进去 / 文件压根不存在**，而那种"失败"什么都证明不了。
>
> **"agent 的身份"**：不是 `root`。理由：容器里的 root（哪怕在 userns 里）带着 `CAP_DAC_OVERRIDE`，
> **任何权限位都拦不住它**；因此"agent 读不到凭据"这件事**只有在 agent 不是 root 时才可能成立**。
> 具体 uid 与凭据路径写在该批的契约里（`docs/dev/`），**不许在镜像里悄悄改**。

> 🚫 **一票否决**：**不许用"这是本机 / 测试环境"当理由降级通过。**
> **负向对照（V1b）不能省**——没有它，V1 的"失败"什么都证明不了。

| # | 事实 |
|---|---|
| 1 | token 计数**没有用户维度** ⇒ 多用户计量**要自己在外层包一层** `{userId, uncachedInputTokens + outputTokens}` |
| 2 | **cache read 占绝对主导（98.57%–99.75%）** ⇒ ⚠️ **它不能进任何阈值判断**——否则阈值会被一个"几乎免费"的量淹没 |

⇒ **结论：不显示估算美元**（宁可显示"—"）。**"算得出计数"不等于"算得出钱"。**

⚠️ 另一条**会静默作废缓存**的：代理只能**原样转发请求信封**——
一旦它加了计费块 / 换了 key / 改了 header，**前缀缓存全废**，
而**命中率下降是看不出来的**（只会变贵）。
⇒ **验收**：代理必须**透明**，且**缓存命中率要有回归测试**。

## 十四、小程序沙箱与制品管线

> 🔴 **2026-09-22 起：这一节不再是"将来的口径"，它就是现在的契约**（主人拍板做"乙"，已上线）。
> 落地结果与逐条判据在 **[`59-USER-APPS.md`](../dev/59-USER-APPS.md)**；下面这些铁律**一条都没放宽**。
> ⚠️ 唯一被推翻的是 §7.3 那句"本轮不建"（原生侧仍然不建）。

### 14.1 沙箱（**三条铁律**）

| # | 规定 |
|---|---|
| 1 | Web 端 iframe 用 **`sandbox="allow-scripts allow-forms"`** ⚠️ **绝不能同时给 `allow-same-origin`**——同时给等于**没有沙箱** |
| 2 | 小程序**文档的 CSP 写 `connect-src 'none'`** ⇒ 它**自己发不出任何请求** |
| 3 | **下载由壳发起**（不是小程序发起）；原生侧用**独立的数据存储**；**禁原生桥** |

⚠️ **验收**：全库 `grep` 原生桥相关 API **命中 = 0**。

**为什么"下载由壳发起"是必需的**：`allow-scripts` 给的 opaque origin 下，
`localStorage` 会**抛 `SecurityError`** ⇒ 小程序**没有持久化能力**是**设计**，不是缺陷。

> ⚠️ **opaque origin 带出的一个坑**：此时 `event.origin === "null"`，
> **不能拿域名做校验** ⇒ 沙箱通信必须改用**一次性 nonce**（打开时下发，关闭即废）。

### 14.2 清单校验（**逐字段**）

| 字段 | 规则 |
|---|---|
| `id` | 正则 **`^[a-z0-9][a-z0-9-]{0,31}$`** |
| `sha256` | **64 位十六进制** |
| `entry` / `icon` | 含 `..` / 绝对路径 / `http(s)://` / `javascript:` ⇒ **拒** |
| `minShellVersion` | 高于当前壳版本 ⇒ **不安装**，提示"**这个小程序要更新客户端**"——**不是白屏** |

### 14.3 生命周期（**每态都有超时与收口**）

```
requested → downloading（超时 30s 推 定）→ installed（hash 通过）
   → running（等 ready 5s 推 定）⇄ background → closed ／ failed
```

- 超时 ⇒ `failed{download-timeout}` **+ 可重试**
- 原生容器崩溃 ⇒ **只重试一次**
- **离线时说清楚**：`installed` 即可用，断网可打开**上次的版本**；
  **有更新也不自动跳版本**
- 打开前校验 hash；失败 ⇒ 切 **`last-known-good` 指针** + 上报

### 14.4 制品管线

| 项 | 规定 |
|---|---|
| **权限** | 发布走**特权口**，**不在公网路径上**；专用属主；原子切换用 `ln -sfn` |
| **不可变** | **版本目录只允许新建，绝不覆盖**；保留最近 **3** 版 |
| **审计** | 每次发布落一条**不可变**审计 ⇒ **"哪个制品是哪句话生成的"可倒查** |
| **部署** | ⚠️ **整包部署不许动制品**（`rsync` 必须带排除项）；**被盖住的小程序不重建** |
| **独立 origin** | 制品走**独立域**，**绝不反代 `/api/`** |

### 14.5 两条容易漏的安全项

| # | 项 |
|---|---|
| 1 | **制品不能跨会话污染**——一个用户生成的制品不能影响别人 |
| 2 | **抓取要防 SSRF**：私网地址黑名单 + **DNS rebinding**（解析后再校验一次） |

## 十五、L2 实现约束

> 出处：`docs/design/L2-dispatcher.md`。**这些是实现层才看得见的约束**，
> 删旧文档就会丢。⚠️ 与手册其他部分冲突时，**以本节更具体的规定为准**。

### 15.1 启动十步（**每一步失败怎么办都要写死**）

| 关键步 | 失败处理 |
|---|---|
| 策略校验（**开机前**） | 不一致 ⇒ **拒绝启动 + 告警**；⚠️ 有逃生开关（**只给主人**，且要留痕） |
| 恢复事件流 | **改读尾部若干字节**取最后时间戳（原来是全量读+解析，与"3 秒自愈"冲突）；单会话读失败 ⇒ **跳过它 + 记一条错误，不阻断启动** |
| 对账续做 | 任何异常**不得阻断启动**（包住，失败只落健康文件里一条） |
| 端口被占 | 退出让 systemd 重启；反复失败 ⇒ 崩溃守护接手降级 |

### 15.2 准入的接口语义

| 情形 | 返回 |
|---|---|
| 拒绝 | **必须给一句人话 + 可重试**，且 ⚠️ **不建空的会话文件** |

> ⚠️ **"不建空文件"这条容易被忽略**：拒绝时如果先把日志文件创建了，
> 用户会看到一条**永远没有内容的会话**。

### 15.3 对账续做规则

| 项 | 规则 |
|---|---|
| 判据 | 有"开始"没有配对的"结束" ⇒ **一定是被打断的** ⇒ **一定收口** |
| 范围 | **只对最近 6 小时内**的说话；更早的旧账悄悄清掉 |
| 额度 | 同一件 **≤3 次**；⚠️ **上游失败 / OOM 不计入**（否则用户收到的是假话） |
| 措辞 | 「**可能没做完**」而不是「没做完」——系统只知道"我被断了" |
| 失败分类 | **五类**，分类决定"算不算额度"与"对用户怎么说" |
| 崩溃环 | 见 §11.1 |

### 15.4 上游熔断

```
closed → open(60s) → half-open → closed
触发：60 秒内 5 次上游失败
```

对用户说「**上游不通**」，**不是**「没做完」。

### 15.5 鉴权（九条改造）**【已部分实现】**

| # | 规定 |
|---|---|
| 1 | 口令 **fail-closed**：没设口令 ⇒ 除三个公开路由外**一律 503** |
| 2 | XFF 取**最后一跳**（不是第一跳） |
| 3 | 登录失败计数**落盘**（重启不清零） |
| 4 | 令牌带主体标识；**撤销表**独立落盘 |
| 5 | ⚠️ **访问别人的资源返回 404，不是 403**（403 会泄露"存在"这个事实） |
| 6 | 令牌**不许放 URL** |
| 7 | 限速 |
| 8 | 登录审计 `{at, result, ip}` |
| 9 | 公开路由**只有三个**，其余全要令牌 |

### 15.6 配置项（**只列容易忘的那几个**）
