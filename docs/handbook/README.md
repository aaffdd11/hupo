## 二、三条最省时间的读法

**十分钟路线**（只想搞清这是什么）：
`01-PROJECT.md` §一 产品是什么 → §三 十个用户告诉我们什么 → §四 五条产品原则。

**开工路线**（要动手改代码）：
`04-ROADMAP.md` §一 批次总表 → 找到你要做的那一批 → `03-DEVELOPMENT.md` 对应的
模块与文件索引 → 有疑问再查 `05-DECISIONS.md`。

**评审路线**（要判断一个改动能不能做）：
`05-DECISIONS.md` §一 决策速查表（一条一行）→ 命中哪条读哪条 →
`02-ARCHITECTURE.md` §五 不变量 → `07-APPENDIX.md` §一 现状缺陷清单。

## 四、维护纪律（**四条，破一条这套手册就废**）

| # | 纪律 |
|---|---|
| **1** | **不写数值。** 阈值、超时、容量**只住在代码与 `05-DECISIONS.md` 的判据里**。手册正文写"跟着字算"，不写"124px"。**写死数值的那一刻它就开始过期。** |
| **2** | **协议字段一旦上线就冻结。** `03-DEVELOPMENT.md` §三那张表**动工前定完**，之后只加不改语义（旧客户端还在跑）。 |
| **3** | **纯函数进 `test/unit`，不写界面断言。** `test/widget` 只是提示不是闸（它现在 49 条挂 10，一重构必过期）。新验收写进 `test/unit` 才算有人守。 |
| **4** | **"以后再说"等于永远不做。** 每一批都必须回答"**能验证什么**"和"**装不装得上平板**"。**写不出验收的条目不许进批次表。** |
| **5** | **要删任何一条结论，先确认它已经在这里有家。** 上一轮删旧文档时，靠的就是"先把 N1–N11、接口表、安全模型搬进 `08-SPEC.md`，再删"。**顺序反了就会丢东西。** |

## 五、几个容易搞混的名字

| 名字 | 指什么 |
|---|---|
| **琥珀 / hupo** | 这个产品（个人 AI 助手） |
| **DSH** | DeepSeek Harness，跑 agent 的那层底座（`@deepseek-ai/dsh`） |
| **调度器 / dispatcher** | `services/core`，常驻进程。对用户的路由、agent 之间的邮政、归一化成一条时间线、账号与供给 |
| **作用域 / scope** | 一条 DSH 会话 + 一个目录。**界面上永不出现"作用域"三个字** |
| **工作区** | ⚠️ **界面永久禁用词**（决策 D1.1）。它是"作用域"在工程语境里的旧称 |
| **本子** | 作用域在**用户面前**的说法（D1：隐喻定稿） |
| **浮窗** | 手机上那个唯一的聊天窗口（可拖、可收、可展开） |
| **图标墙** | 桌面。作用域与内置应用都以方块出现在这里 |

⚠️ **只写"禁止"不够**：`03-DEVELOPMENT.md` 把"界面不许出现内部词"做成了一道
`test/unit` 闸（禁用词扫描），**不是文风建议**。
