## 〇、一句话

> **一台哑终端 + 一台云端专属主机 + 一个调度器。**
>
> 用户看到的是**一个聊天窗口**。他说的每件事，底下有一条自己的"本子"在办；
> 他不需要知道"本子"是什么，只需要知道**它记住了、它在办、它没骗我**。

**产品对用户的承诺（唯一一句）**：

> **你说的事它真会去做，不只是陪聊。**

## 一、这是什么、给谁

### 1.1 它是什么

| | |
|---|---|
| **形态** | 一个聊天窗口（浮窗）+ 一个桌面（图标墙） |
| **不是** | 不是应用商店，不是自动化工具，不是搜索引擎 |
| **独特之处** | **它能记住、能自己去办、办完会回来告诉你**——而这三件事**用户都要能验证** |

### 1.2 它**不是**什么（**这几条和不做什么一样重要**）

| 不是 | 为什么 |
|---|---|
| **不是"能替你点手机"的自动化** | 银行、政务、挂号、快递这些**永远不会给接口**。⇒ 只做"**准备到最后一键**"，**做不到就明说做不到** |
| **不是"老人档"那种模式** | **多一个模式就是多一样要学的**。可访问性是"**把默认值改安全**"，全体受益 |
| **不是每次都现编一个玩具** | **AI 不能在生成界面的同时现编数据源**——否则今天的字段叫 `amount`、明天叫 `money`，**昨天记的账今天读不出来** |
| **不是靠"以后再做"堆出来的** | 一个人的产品里，**"以后"等于"永远"**。要砍就明说砍了 |

## 二、十个用户（**这是本项目的需求来源**）

十个人，**第一人称**走查一遍：读设计 → 写下"我第一天怎么用、第一周怎么用、我卡在哪、我会不会回来"。

| # | 是谁 | 一句关键原话 | 一周之后 |
|---|---|---|---|
| **01** | **产品主人本人**（技术满级） | "**我主动去点桌面上生成的东西的次数：0。**" | ⚠️ **半死**："不是卸载，是**少用它来改它自己**" |
| **02** | 32 岁后端工程师 | "**我不会因为它难用、慢、界面丑而放弃。我会因为它说了做不到而放弃。**" | 降级：**"私人助手"掉到"搜索框"** |
| **03** | 38 岁开小饭馆（不懂 APK） | "**话发出去了，没有任何一样东西是活着的** → 判它坏了" | ❌ **放弃**："每天想起来点一次，点完心里更烦" |
| **04** | 29 岁运营（通勤 40 秒） | "**6 秒**没第一个字，我上划杀掉" | 留下，但**用法和设计者以为的完全不一样** |
| **05** | 41 岁超市排班（小升初家长） | "**我不会原谅它把我说过的话说错。**" | 留下："这一周我**没走**" |
| **06** | **68 岁退休教师（不会拼音）** | "**就在登录页。** 不是用了一阵子以后放弃，是第一次打开就放弃" | ❌ **第一天就放弃** |
| **07** | 34 岁独立设计师 | "**我做出来是要给人看的。** 它给我的东西，**我发不出去**" | 部分留下："**不再把重要的事交给它**" |
| **08** | 45 岁公众号作者 | "**我找不到我半小时前写的那一段**" | 留下但降级：**"一个我偶尔问两句的聊天框"** |
| **09** | 27 岁工地管材料（网络差） | "**界面把'发不出去'显示成'发出去了'**" | ⚠️ **条件性**："**第二次丢，我就卸了**" |
| **10** | **平板用户（主人那台小米平板）** | "**一遍一遍地，桌面被抹掉**" | 留下但降级：**"放弃的不是产品，是在平板上用它"** |

**十条走查的真实产出不是那 200 条问题，而是下面三件事。**

## 三、最重要的发现：**十个人的放弃点，指向同一件事**

```
01 主人      拿到命令但人在手机上 → 改主意的窗口被关掉了
02 技术      它说"我记下来了"，而我无法验证
03 不技术    话发出去了，没有任何一样东西是活着的 → 判它坏了
04 通勤      按发送后 6 秒没第一个字，上划杀掉
05 家长      第 5 次问，它给了旧日期，没标出处、语气还很肯定
06 老人      登录页第 30 秒——不会拼音，门就没开
07 自由职业  要出报价单发客户时，它给了一段发不出去的字
08 写作      找不到半小时前写的那一段 → 退出、开备忘录
09 断网      丢一次字就走——忍不了"看着像发出去了，其实没说出去"
10 平板      每说一句、每收一句，桌面就被抹掉一次
```

> **"它到底活着没有、记着没有、说的是不是真的"——
> 这件事用户无法验证，而系统自己也不说。**
>
> 十个人里有 **八个** 的放弃点落在这件事上。
> 这不是十条独立的体验问题，**是同一个洞的八种表现**。

### 3.1 五条"致命问题"（多数人会在此放弃）

| # | 致命问题 | 用户原话 |
|---|---|---|
| **★1** | **发出去之后，没有任何"活着"的信号** | 十个人**全部**提到等待期 |
| **★2** | **记忆不可验证** ⇒ **黑盒记忆 = 默认没记住** | 02："**我对黑盒零容忍。看不到它记住了什么，我就默认它没记住。**" |
| **★3** | **失败与成功长得一模一样** | 09："发失败：蓝底气泡，右边，**没有小转圈**"——和成功**完全一致** |
| **★4** | **"工作区"这个概念，十个人里 0 个发现了** | 十位全部明确说"没有发现" |
| **★5** | **看不见的边界 ⇒ 不敢说真话** | 07："**界面上一个字都没有**，这是我最后放弃的原因" |

### 3.2 两个最"贵"的放弃点（因为它们丢的是产品的护城河）

| 谁 | 丢的是什么 |
|---|---|
| **01 主人** | "**用它改它自己**"是这产品对他**唯一不可替代**的地方。而他预计"**第 3 次起，P1 就没了**"（第 1 次认真读 diff，第 2 次读改动那几行，第 3 次只 `git apply` 然后按上箭头重启） |
| **09 断网** | "**这个才是留存的真杀手**：不是哪天发不出去，是**我根本不会再点开它**" |

## 四、五个根因（**30 多个问题，只有 5 个根因**）

| 根因 | 一次带走 | 一句话 |
|---|---|---|
| **R1** | 13 条 | **从"按下发送"到"第一个字"之间是空的**，而且失败与成功长得一样 |
| **R2** | 8 条 | 时间线上"**我在哪一层**"和"**谁在说**"完全没有表达 |
| **R3** | 9 条 | **一切都是静默的**——系统替用户做的每件事，它都不说 |
| **R4** | 6 条 | **内部词汇直接暴露**（口令 / 连接 / 客户端 / 云端 / 工作区） |
| **R5** | 7 条 | 布局把"**手机的比例**"当成了普适前提（平板 / 老人 / 长文全崩） |

> **五个根因里，四个都是"系统没说话"**——
> 没说它收到了、没说它记住了、没说它在哪一层、没说它替你做了什么决定。
>
> ⇒ 这一轮最大的收获可以压成一句话：
> **把省下来的每一个字，花在让用户知道发生了什么上。**

### 4.1 每个根因的判据（**用户原话**）

**R1 · 等待期是空的**

- 03："话在屏幕上，然后**没有任何一样东西是活着的** → 判它坏了"
- 04 的容忍线：**打开到能打字 3 秒 / 首字 6 秒 / 首字到能用 8 秒**
- 06：等待期只有 **11px 灰点无字**，数到三就以为坏了
- 09：失败时**连小转圈都消失** ⇒ 界面把"发不出去"显示成"发出去了"

**R2 · 不知道我在哪一层**

- **"工作区"十个人里 0 个发现**
- 07：两个图标同名又不能改名 ⇒ **会记错工时**（对他是生死线）
- 10：多窗口来回切，**最需要"我在哪"这个锚**
- 08：快答+深答拼一条且明确"不加标签" ⇒ **分不出哪段是自己写的**

**R3 · 一切都是静默的**

| 谁 | 现象 |
|---|---|
| 03 | 桌面冒出方块，**没人告诉我**，还删不掉 → **"流氓软件"** |
| 05 | 桌面凭空多出图标 → **"中病毒了"**，会去问妹夫 |
| 02 | **失忆不报错**——它没有"我缺了一块"这个可表达状态 |
| 07 | "删除账号"有入口、**"导出"没有** ⇒ 这个不对称**直接触发信任问题** |
| 09 | 发送失败**静默**（收起态连红字都没有） |

**R4 · 内部词汇**

| 词 | 谁被它挡住 |
|---|---|
| **口令** | 03（微信抖音都是验证码）· **06（因此直接放弃）** |
| **连接** | 03 · 06（"正在恢复连接…"被读成坏了） |
| **工作区** | 05（"会读成上班干活的地方"）· 06 · 07 · 08 |
| **客户端 / 云端 / 版本号 / 序号** | 03（关于页全读不懂） |
| **"能执行命令、能改自己的代码"** | 03：**读完是害怕，不是放心** |

**R5 · 手机比例当普适前提**（**都有实测数字**）

| 谁 | 实测 |
|---|---|
| **10 平板** | 浮窗宽 **1260px**，内容被卡在 **532px**，**右边 675px 全空**；图标 52×52 落在 **314px** 格子里（占 **16.6%**）；列数**写死**；横屏拉满 **97.3%**；**每说一句每收一句都自动拉满** |
| **06 老人** | 桌面图标名 **11**、收起行 **12**、标题 **14** 全是常量，**系统字体调最大它们不变**；收起 **124px** 里**只剩 9px 给消息**；唯一按钮约 **40px 且无字**；甩按速度判，**手抖就甩没** |
| **08 写作** | 按"**条**"分页（一页 10 条），而他一条 **600 字** ⇒ **翻页形同失效** |

> 三个不同的尺寸都用了同一个错误假设：
> **"屏宽就是手机宽度、条数就是阅读单元、字号是固定的"**。

## 五、五条产品原则（**从上面的结论倒推，不是先验的**）

| # | 原则 | 它对应什么 |
|---|---|---|
| **1** | **系统做的每一件事都要说出来** | R1/R2/R3 —— 五个根因里四个是"系统没说话" |
| **2** | **看不见的东西等于不存在**（黑盒记忆 = 没记住） | ★2 —— 记忆必须有**可见出口**：能看到、能删、带出处 |
| **3** | **不假装能做**（沉默优于编造） | ★5、P5 —— 边界要明说，做不到就说做不到 |
| **4** | **不许要用户学新东西** | R4、"一步而不是两步"、"不做老人档" —— 用他已经会的词和手势 |
| **5** | **可恢复 > 可防错** | 误触能自救、删除进回收站、"甩"要能关 |

> ⚠️ **原则 4 是一把尺子**，能挡掉很多看起来不错的方案：
> - 不准造新词（"**开门的话**"要被否，因为"密码"用户**已经学过**）
> - 不准加新模式（**"老人档"要被否**）
> - 不准多一步（语音要"按住说、松手发"——**这是他在微信里学会的手势**）

## 六、已经定下来的产品声音

### 6.1 登录页（**决策 D2 定稿**）

```
        助手
    你说的事它真会去做，不只是陪聊。
    所以这道门只有你能开。
    [ 密码 ]
      装机器时给你的那一串
    [ 打开 ]
```

**四条它不做什么**：

| # | 不做什么 | 为什么 |
|---|---|---|
| 1 | **不说"能执行命令、能改自己的代码"** | 读完是**害怕**；全场只有一个人读得懂 |
| 2 | **不用"口令"** | 用户上一次听到是"**看电视里当兵的站岗**" |
| 3 | **不用"进去 / 登录"** | 没人读出"进门"，读出来的是"**提交**" |
| 4 | **不在这屏说"记住了什么"** | 记忆出口上线前写 = **空承诺** |

⚠️ **这屏配三件机制，缺一条它就会再出现一次**：
① 连不上**不清令牌** ② 令牌到期**续期** ③ **忘密码的恢复写在这一屏**。

> 因为真正的 bug 不是文案，是：**"每 30 天要人帮一次"。**
> "第一次要人帮"可以接受（老人的手机本来就是子女装的）；
> **不可接受的是"每 30 天要人帮一次"。**

### 6.2 界面上的名字（**决策 D1**）

| 定什么 | |
|---|---|
| **"工作区"三个字** | ⚠️ **界面永久禁用**——图标名 / 标题 / 提示 / 空屏 / 报错，一处都不许 |
| **名字从哪来** | **系统提议，只用用户自己说过的词**；**永不问"你想叫它什么"** |
| **能改名吗** | **能，随时能改**；入口在长按/详情里，**不在首建流程里** |
| **重名怎么办** | **用他自己的话区分，不许用系统编号**；图标下加**第二行小字**（"最近：品牌升级 3h"） |
| **隐喻** | **一件事的一本本子** |

**为什么隐喻必须是"本子"**（这一段把两边都堵住了）：

| 如果叫 | 会怎样 |
|---|---|
| **文件夹** | 用户 10 分钟内就会往里拖文件、传附件——**07 真的试过，放不进去，他自己花了一整天解开这个误会** |
| **应用** | 点开还是聊天，用户判定"**点开跟没点一样**" |
| **本子** ✅ | 它承诺的（**能翻、能问、能添页**）**正好就是聊天已有的能力**，一句空话都不多 |

### 6.3 过程要不要给用户看（**决策 D7**）

**给，但分层。** 关键区分是"**在做什么**"和"**在想什么**"：

| 档 | 用户看到 | 谁能开 |
|---|---|---|
| **在做什么** ✅ **默认** | 一句人话，**逐个替换**："在查资料" → "在算" | 任何人 |
| **推理原文** | 模型在想什么 | ⚠️ **只有主人，默认关** |

> 🔴 **2026-09-26 更正**（主人原话：*「**名不副实的要去掉**。」*）：
> 原来还有两档，**砍了** ——
> **安静**只掐掉「它正在做…」那一行、**掐不住工具行**，做不到它名字说的事；
> **步骤流水**被**工具行**（名字 · 人话标题 · 成败 · 展开看入参输出，而且落盘、
> 切回来还在）说得更准更全，它只剩一串粗粒度、瞬态的重复行。
> 契约与判据在 [`dev/122`](../dev/122-TWO-PROCESS-LEVELS.md)；四个 wire token 仍然冻结。

**两条硬约束**：**不承诺时间**（有了预期却没兑现，用户更焦虑）；
**展示过程不能替代速度**（它只是让等待可忍受）。

### 6.4 设备优先级（**决策 D4**）

> ⚠️ **归属澄清**：**"先用平板。"这句话是主人补的**（决策 D4）。
> **十份走查里从没有写过"平板是主开发设备"**——走查把"平板是不是主目标设备"
> 列为**待拍板的问题**，是主人回答了它。

| | 指的是什么 |
|---|---|
| **主目标设备** = **手机** | 产品面向谁、**砍功能时不能坏谁** |
| **主开发设备** = **平板** | **每天用它、验收看它、第一印象来自它** |

**实际含义**：平板的宽屏**不是"第 1 批顺带做"，而是第 1 批的首要验收场景**。
理由（走查里的原话）："**他每天亲眼看的坏东西，会绑住他后面两周的排期**。"

**一条配套承诺**：

> **如果这一批交付后横屏仍然难看，就明说"平板横屏还没做好、已知"。**
> **不许用"排后"把话混过去**——"一个人的产品里，**以后就是永远**"。

## 七、边界：**明说做不到的部分**

| 边界 | 怎么说 |
|---|---|
| **不代执行** | "报销单我填好了，3 笔、合计 842 元。**登录和提交这两下得你来**——链接在这，点开就是填好的表。" |
| **不假装记得** | 翻不到就说"**这段我手上没有，我去翻一下**"，**别装作记得** |
| **语音没网 / 这台手机没有** | **明说**，不摆一个按不动的按钮 |
| **不会拼音的人** | 语音上线前，**关于页必须明写"不会拼音的人这个版本用不了"** |
| **横屏还没做好** | 就写"**已知**" |

> **这一节和功能清单一样重要**：产品的可信度来自"**它说的它真做到**"，
> 而**编造一次就够毁掉它**。

## 八、可验收的体验判据

> ⚠️ **原文没有独立的"验收标准"字段**；下面这些是从用户原话里抽出来、**可直接当判据用**的表述。

| # | 判据 | 来源 |
|---|---|---|
| 1 | **四种状态视觉可区分** | "现在四种里有两种长得一样" |
| 2 | **失败必须有自己的长相 + 一个重发入口** | 09 |
| 3 | **收起态也要显示失败** | 09 |
| 4 | **200ms 内没有服务端回应 ⇒ 本地先出一句应声** | 03"微信会先给我一个字" |
| 5 | **触控目标 ≥44** | 实测那个箭头只有约 40px 且无字 |
| 6 | **内容列限宽（760）+ 居中**（2026-09-24 回填：**没有"宽 >900"那个断点** —— 代码里一律限宽） | 10：1260px 里只用 532px |
| 7 | **界面上出现内部词 = 缺陷**（做成 `test/unit` 的闸） | R4 |

## 十、本项目的方法论（**为什么文档长成这样**）

| # | 做法 | 为什么 |
|---|---|---|
| 1 | **先跑用户体验走查，再做工程规划** | "如果走查发现用户根本不会去点桌面上那个图标，工程做得再好也白做" |
| 2 | **每一轮都有独立评审，且评审必须去代码里核** | 两轮评审各挖出真问题；其中一轮**推翻了实施计划的核心论断**，另一轮挖出**两个今天就在咬人的 bug** |
| 3 | **前提性事实必须复核** | 有人拿"`sudo` 免密"这个**没复核的事实**改了结论——而实测**要密码** |
| 4 | **拍板必须落文件** | "口头说过的、没写进决策记录的，不算数" |
| 5 | **不写"以后再说"** | 一个人的产品里，**以后就是永远** |

> 这五条不是流程洁癖。第 2 与第 3 条各自**救回了一个会被做错的方向**：
> - 第 2 条：计划里三个"承重"的论断在代码里**证伪**
> - 第 3 条：一个基于错误前提的决策被翻掉
