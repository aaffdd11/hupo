## 一、作品一句话

> **琥珀是一个会自己动手把事情办完的私人助理**：
> 你对它说一件事，它**真的去做**（查、写、算、做一个小程序），**做完回来告诉你**；
> 它**记得住**、**不会骗你**、**你随时能查它做了什么**。

它由三件东西组成（都是我们自己写的）：

| 那一件 | 是什么 | 规模（实测） |
|---|---|---|
| **一个聊天窗口 + 一个桌面** | 用户看到的全部界面：一格图标 ＝ 一间小屋 ＝ 一条对话 | 客户端 146 个源文件 · 128 份判据 |
| **一台"专属主机"** | **每个用户一台自己的盒子**（容器），他的数据、他的钥匙、他的助手都在里面 | 3 台在跑 · 每台 4 GiB（2026-10-04 实测 `memory.max=4294967296`） |
| **一个调度器** | 把"他说的话"变成"一轮一轮的活"：记账、收口、崩溃后接着办 | 服务端 121 个模块 · 142 份判据 · **1513 条判据全过** |

## 二、它是给谁用的（为什么做）

> ⚠️ **2026-10-04 主人更正了这一定位**（原话大意）：*「不仅仅是看不清小字的人……我发现我越来越
> 不需要在电脑上，可以移动办公，在手机、pad 上输入；但输入越多，越发现打字的效率根本没有语音高。
> 它其实是**把人类从输入里解放出来**，应用场景更宽：八岁的孩子、九岁的孩子也能用，
> 六十岁、七十岁的老人也能用。」*

⇒ **定位 = 「会说话的人都能用」**（从八九岁的孩子到六七十岁的老人，再到在手机 / 平板上移动办公的人）。
**「不会打字 / 看不清小字的人」是设计基准，不是使用者范围** —— 最难的那一端能做到，别的人一定也能用。
界面那几条硬规矩（**字放到 3 倍不破版** · **命中区 ≥44 像素** · **不许只有图形没有文字、按不动的按钮** ·
**内部词一个都不许上屏**）就是「跨度这么大还得都能用」的直接结果；它们**是缺陷清单里的条目**，有判据盯着。
⚠️ **交上去那一份（`琥珀-作品设计说明.pdf`）的 §2.1–2.4 已经按这个定位重写过**，两边不许说两套话。

## 三、技术原理（AI 用在哪、怎么用）

### 3.1 一轮对话：不是一个"大模型答题"，而是一条**可收口的流水线**

```
他说一句 → 调度器把它变成"一件活"（起任务、落盘）
        → 起一个 agent（我们自己的 DSH 运行时），把这一间的历史喂回去（最近 40 句 / 6000 字）
        → agent 调工具（读文件 / 跑命令 / 查网 / 造小程序），过程**实时**推给他看
        → 收口：做完了 / 他说别做了 / 断了 —— 三种结局**都要落账**
```

* **可收口**是这个系统的地基：每一件活都有"票"，落一条 `work/open`，收口落一条 `work/close`；
  硬杀之后重启，逐件答得出"已停"，不会变成"查无此件"。
* **看得见**：工具行、过程、用量都进时间线（他自己决定看到哪一档）。
* **模型**：租户用的是 `deepseek-flash`（**低推理开销**那一档），钥匙只在他自己盒子里。

### 3.2 小程序：**AI 写的东西，在一个关起来的沙箱里跑**

这是本项目最有意思的一段：**用户说"帮我做一个记账的"，AI 当场把那个小程序写出来**，
桌面上**当场长出那一格**（做的时候是灰的、中间转着圈；做好了它自己变回来）。

技术上分三层：

| 层 | 谁在管 |
|---|---|
| **代码** | AI 写（HTML/JS，或者带 SQLite 的小程序） |
| **平台那一刀** | 服务端建工作区、登记、签名入口 URL、**页面绝不自己拿包名** |
| **沙箱** | 跑在**只读挂载**的层里；每个小程序**自己一格库**（跨格读不到）；**要联网 / 要连哪个站 / 要问 AI，都要他打开时点过头**；出网**留痕**（只记域名与量，不记正文） |

### 3.3 语音：**听得见、听得懂、还会问回去**（正在做的那一层，V2.0）

* **听**：浏览器/手机录音 → 火山（豆包）**大模型流式语音识别** → 文字（今天落在输入框里）。
* **懂**（V2.0 的核心）：先由**一个不吃"思考"的快速模型**读一遍这句话 ——
  它只干一件事：**把这句话理顺 ＋ 告诉我哪里不确定**（是上周还是上个月？给谁看？要不要存数据？）。
  不确定就**问回去**（**语音 ＋ 流式文字**同时给），问明白了**才自动发出去**；
  问不明白就不硬发（屏幕上如实说"这句我没听清"）。
* **说**：把问题用**语音合成**念出来（正在接通火山那一路）。

⚠️ 这一层的规矩写死在代码里：**只许"听他说的"，不许"替他多要"** ——
想要更多（要不要存数据）必须**问出来、他答了**才算他的意思。

### 3.4 一人一台盒子：**隔离靠容器，不靠"约好"**

* 每个用户一台 rootless 容器（`cap-drop=ALL` 后再按需加回），**只读挂载**产品代码，
  **一台 4 GiB**；一台出事不影响别人。
* 宿主只做三件事：转发、签名、记账。**他的数据、他的钥匙、他的助手都在他自己那台里**。
* **钥匙不出盒子**：盒内有一个 root 小代理握着真钥匙，agent 手里只有一个占位符
  （它连"读钥匙"这条路都没有）。

## 四、实现过程（怎么一步步做出来的）

**做法：判据先行、一次一小步、每一步都留账。**

| 阶段 | 干了什么 |
|---|---|
| **规划** | 先写**唯一权威文档**（手册 10 份：要什么 / 为什么 / 不变量 / 接口 / 阈值 / 安全模型 / 容器验收），**两轮独立评审**，决策逐条拍板 |
| **实现** | 一批一个可交付状态；**每一批都要过两道硬闸**（服务端判据、客户端判据），过不了不许往下走 |
| **每一步都有"负向对照"** | 光"通过"不算数：**删掉那条规矩，判据必须变红**（这一条在本项目里叫"变异验证"，是硬要求） |
| **上线** | 本机就是线上：重启服务、重发"产品层"（盒子那一份）、部署网页，然后**从公网取回来核指纹** |
| **留痕** | 每一次重建开机清单、每一批上线读数，都写进账本（`docs/dev/` 182 篇契约 · 一份热账本） |
| **V1.0 定档** | 2026-10-04：**V1.0 冻结**（打了 git 标签，连同线上两个产物指纹一起钉住）；之后只修致命缺陷，新功能进 V2.0 |

⚠️ **过程中真栽过的跟头也写在账上**（这一条对评委很重要：它说明"测试结果"不是摆拍）：
比如客户端把流的地址算成了 `ws://`、在 https 页面上被浏览器拦掉，而当时**所有判据都是绿的** ——
因为判据用的是 node 探针、把 `wss://` 写死了，绕过了被测的那行代码。
⇒ 从那以后立了一条规矩：**凡是客户端自己算出来的东西，判据必须打在客户端这一侧**。

## 六、安全考虑（**这一节是重点**）

| # | 防线 | 具体是什么 |
|---|---|---|
| 1 | **助手只能提申请，签字的是主人** | 要改运行中的系统（装东西、动配置），助手把命令准备好，**由人按键**。理由不是洁癖：威胁的真实形态是"**坏事能不能留下来**"（读到一段看不见的网页 → 被诱导写进自己的配置 → 从此每轮开机都读它） |
| 2 | **一人一台盒子** | 容器隔离 + 只读代码层 + 每台资源上限；跨用户读不到对方任何东西 |
| 3 | **钥匙不出盒子** | 盒内 root 代理握钥匙，agent 只有占位符；**日志与回话里永不出现钥匙** |
| 4 | **小程序：声明 ≠ 已给** | 制品说"我想要联网 / 想用 AI"，**只是它想要**；用户**第一次打开时一张弹窗**一次问完，点头的才生效；**存储天生就有**但**每格独立、跨格读不到、他随时能一键清空** |
| 5 | **出网留痕** | agent 能访问网络，但**去哪、多少量**都落账（**不记正文**），可查 |
| 6 | **开机完整性清单** | 人格 / 手册 / 能力层这些"决定它下次开机读什么"的东西，哈希写进 root 只读清单；**动过就拒绝启动**，每次重建都留痕 |
| 7 | **删除要二次确认** | 删之前先把它要带走的东西（聊天 / 数据 / 经验）**逐条摆出来**，再问一次；服务端是**软删**，还能拿回来 |
| 8 | **页面不许说假话** | 做不到的事**不许画按钮**；拿不到的事实**不许猜**（"不知道"就说不知道）——这条被当成**缺陷**来管，有判据 |

## 八、现场演示脚本（约 4 分钟）

> ⚠️ **演示前先做一件事**：进「设置」→ **演练入口**（一个空白、临时的对话系统）——
> 整条链真跑，但**一个字节都不发出去**、不碰你的真实聊天与桌面。
> ⇒ 这样演示可以**反复做**，不怕说错话、不怕留垃圾。（**这个入口已经在了**：设置 → **说一句试试** ——
> 2026-10-04 做的，见 `docs/dev/182`；判据里钉着「整场一次都不会真发出去」。）

| 时间 | 演什么 | 说一句什么 |
|---|---|---|
| 0:00 | 打开页面 → 登录 → **桌面** | "这是他自己的桌面，每一格就是一个小程序，也是它的一条对话。" |
| 0:30 | 对着它说一句人话（语音） | "我不用打字，说一句就行。"（指屏幕上的字） |
| 1:00 | 让它**做一个小程序**（"帮我做一个记账的"） | "它现在真的在写代码。"（指桌面上**新长出来的那一格是灰的、转着圈**） |
| 1:45 | 等它做完 ⇒ 那一格**自己变回正常颜色** | "做好了它自己变回来，点开就能用。" |
| 2:15 | 点开小程序，用一下（记一笔、看它存住） | "数据存在它自己那一格里，别的小程序看不到。" |
| 2:45 | 让它干一件**长的活**（"帮我把这些整理成一张表"），然后**合上页面** | "长活它自己放后台办，办完会主动告诉我。" |
| 3:15 | 回到桌面 ⇒ **"在做"那个小圈**在转 | "哪一件还在办，桌面上看得见。" |
| 3:30 | 演示 V2.0 那一层（说一句说得含糊的话） | "它听不清会**问一句**，问清楚了才发出去 —— 不会替我乱猜。" |
| 3:50 | 打开「设置」→ 安全那几项 | "他自己的钥匙、他点头才开的权限、还有这份开机清单。" |

**如果评委问"AI 在哪"**：三处最小可讲的 ——
① 大模型驱动的一轮一轮调度（它自己决定用哪几样工具去做）；
② 小程序是**它写的代码**，跑在沙箱里；
③ V2.0 那层"听懂"用的是**同一个快速模型**，但**只让它判断、不让它替用户说话**。
