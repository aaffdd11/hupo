## 二、三条硬约束（**别再照着旧那份文稿交**）

1. 🔴 **字数上限 3000**。旧文稿 5524 字（实测）⇒ 已重写成 [`作品设计说明.pdf`](作品设计说明.pdf)（2558 字）。
2. 🔴 **作品设计说明里不许出现与申报人相关的个人信息**（模板原话：*"以下不能出现与申报人相关的个人信息，如姓名、所在区域、指导教师、就读学校等"*）。
   ⇒ 新稿把封面那一栏（姓名/学校/指导教师）**整块去掉了**，那些信息只出现在**申报表**里。
3. 🔴 **必须以"作品设计说明"的四段结构交**：一、作品简介　二、设计制作过程　三、使用说明　四、创新点。
   新稿就是照这个顺序写的（另外带 2–3 个关键词与参考文献）。

⚠️ 顺带两条活动的硬规矩：**每名队员只能报一个项目**、**以个人为单位**；**每人至少 1 位指导教师**。

## 三、查新报告：查新点与检索词（可直接抄进那张表）

**查新点（需要查证的创新点，4 条）**

1. 语音输入之后**不直接执行**：加一层"只负责听懂、不负责创作"的快速模型，把话理顺但不许添加用户没提过的要求，不确定就**问回去**（语音 ＋ 文字）再发。
2. 让**非开发者**用自然语言生成只属于自己的**个人小程序**，当场出现在桌面上、点开即用、数据持久保存，并可长期迭代。
3. **一人一台隔离主机**跑同一个助手：数据与钥匙都在用户自己的容器里，**钥匙明文不进执行环境**（助手环境只有占位符）；权限逐项由用户点头；上网留痕；删号即删主机。
4. 把每一轮对话做成**有始有终、可查账的"活"**：做过什么、成没成、花了多少可查；被硬杀后重启能逐件如实交代"做完了 / 已停"。

**检索词（中英文各一组）**

- 中文：语音优先 私人助理 · 自然语言 生成 小程序 · 大语言模型 智能体 容器 隔离 · 多租户 人工智能 助手 钥匙 不出容器 · 对话 收口 账本
- 英文：voice-first AI assistant · LLM generated mini-app · per-user container isolation for LLM agents · agent turn lifecycle ledger · sandboxed user-generated app

**检索范围**（表里可勾的，全选）：中国学术期刊网 · 维普 · 万方 · PQDD-B 博硕士论文 · 国家知识产权局 · 国家标准委 · 百度学术。
⚠️ **这些库要账号**（学校/区少科站通常有）⇒ 这一步只能你或老师来；我把"要点 ＋ 名词"备好，能省掉大部分时间。

## 四、电子作品源文件（要交，但**先剥离个人信息**）

仓库就是源文件（`v2/services/core` 服务端 ＋ `v2/apps/mobile` 客户端 ＋ `docs/` 文档 ＋ 判据）。
⚠️ **打包前必须剔掉这几样**（里面有个人信息或密钥类内容）：

- `v2/services/core/data/`（**用户数据、口令、凭据**，一律不交）
- `docs/dev/` 里带手机号/账号的那几篇（如 `173-DSH-STUCK-ANALYSIS.md`）、`docs/dev/77-BLOCKERS.md`

⇒ 我出一份**打包脚本**（白名单式，只装代码 ＋ 判据 ＋ 手册 ＋ 作品设计说明），跑完再逐个人工核一遍。
