# 作品设计说明 · 两块（产品特点 / 技术特点）

> 主人 2026-10-07：*「接下来是设计说明。那么就需要两块，**产品特点，和技术特点**。」*
> 用途：徐汇「雏鹰杯」要交的**作品设计说明**（PDF，**500–3000 字**，须含作品简介 / 设计制作过程 /
> 使用说明 / 创新点）—— 这两块是把那四节收成一条线来讲：**第一块讲用户看得见的，第二块讲怎么做到的**。
> 纪律：**产品特点那一块不讲底层**（容器 / 调度器 / 大模型 / 接口一律不提，只说屏幕上的现象）；
> **技术特点那一块讲技术，但说人话**（评委不是同行）。
> ⚠️ 与现有那份 [`作品设计说明.html`](作品设计说明.html)（约 2570 字）**并用时注意总字数上限**。

---

## 〇、模板（附件 5）要求 → 覆盖点

模板原文硬要求：**不能出现与申报人相关的个人信息**（姓名 / 所在区域 / 指导教师 / 就读学校）·
**作品名称** · **关键词 2–3 个** · 正文**四部分**（**500–3000 字**）· **参考文献**（按实际填）。

| 四部分 | **必须答到的点**（缺哪个评委就会问哪个） |
|---|---|
| **一、作品简介** | ① 一句话说清**这是什么**；② **给谁用**（谁最需要）；③ **解决什么问题**（生活里的真事，不是空话）；④ **为什么这么做**（立意）；⑤ **能做什么**（功能清单，一件一行）；⑥ **不做什么**（边界，一两句，比"什么都能"更可信） |
| **二、设计制作过程** | ① **需求从哪来**（观察 / 走查，不是拍脑袋）；② **先立规矩**（动手前定下要什么、不许怎样）；③ **技术怎么实现**（分几块、每块干什么）；④ **中间碰到什么问题、怎么解决的**（至少一两个真事）；⑤ **怎么证明它真能用**（自动判据 / 真机真上线）；⑥ **版本与迭代**（现在到哪一版） |
| **三、使用说明** | ① **怎么开始**（打开 / 登录）；② **主要操作**（说话、打字）；③ **让它做小程序**（长什么样、什么时候能用）；④ **长活怎么等**（放后台、回来说、可追问）；⑤ **状态怎么看**（在做 / 做完了）；⑥ **设置**（壁纸 / 字号 / 钥匙）；⑦ **手机上怎么用** |
| **四、创新点** | ① **3–5 条**，每条一句"**新在哪**"（不是复述功能）；② 至少一条是**方法上的新**（怎么做工程，不只是做了什么）；③ **不吹**：说清哪里比不了（例如不训练模型） |
| **参考文献** | 按**实际用到的**列（接口文档 / 参考的开源项目 / 本作品自己的文档） |

**交稿前的四条自查（都过了才交）**：

1. **个人信息 0 处**：姓名 / 学校 / 区域 / 指导教师 / 手机号 / 邮箱 —— 全文搜一遍（含页眉页脚、文件名、图片里的字）；
2. **字数在 500–3000**（不含标点空白的实测值，不是感觉）；
3. **四部分标题照模板写**（作品简介 / 设计制作过程 / 使用说明 / 创新点），**作品名称与关键词在正文之前**；
4. **PDF 交上去**（模板要的是 PDF）。

### 现有那份（`作品设计说明.html`，约 2570 字）对着这四条查的结果

| 覆盖点 | 现状 |
|---|---|
| 作品名称 · 关键词 · 四部分标题 · 参考文献 | ✅ 都有（关键词三个：语音优先 · 私人助理 · 小程序生成） |
| 个人信息 | ✅ 全文搜过：**一处都没有** |
| 字数 | ✅ 约 2570 字，在 500–3000 内 |

| 二、设计制作过程 | ✅ 先立规矩 / 判据变异 / 技术四块 / 真上线 / 三条真事都在；⚠️ **"需求从哪来"**只隐含在简介里 ⇒ 开头点一句更好 |

是**另起一份更短更口语的稿子**时用的，不是必须替换现有那份。

## 一、产品特点（用户屏幕上看得见的东西）

**用户通过和它对话，实现聊天、也能创建可复用的应用**（琥珀以 DeepSeek Harness 为技术基座）。

**屏幕上只有两样东西：一个聊天窗口，一个桌面。**

1. **说话就能用** —— 点一下麦克风说一句、**说完按停就发**；认出来的字**当场长出来，点一下就能改**。
   孩子还没学打字、老人打不了拼音，照样能用。
2. **说完它是真去办** —— 不是给你一段答案，而是把事办完：查资料、算数、写东西、画图、记一笔账、上网查。
3. **它会当场给你造一个小程序** —— 说一句「帮我做一个记账的小程序」，桌面上先长出一格
   **灰色的、转着圈的格子**（代表还在做）；做完那一格自己变回正常颜色，**点开就能用、数据存得住**。
4. **桌面就是它的成果架** —— 一格图标 ＝ 一件事（一个小程序 ＝ 一条对话）：做出来的东西**留在那儿**，
   关掉再回来还在，点开接着用。
5. **东西留得住** —— 说过的话、做过的事、答应过的事，关页面、重启、换设备都还在，**能翻出来看**。
6. **过程看得见** —— 它正在做什么、用过哪几样本事、花了多少，都摆在记录里；
   不是黑箱里忽然冒出一个答案。
7. **长活有交代** —— 时间长的事它先说一句"我先去办"，放到后台；**办完或失败都主动来说一声**，
   随时可以问「那件怎么样了」。
8. **成没成说清楚** —— 办不成也说明白，**不会把"没办成"说成"办好了"**。
9. **一个人一份，互不打扰** —— 每个人看到的都是**自己的那一份**；自己做出来的东西还能**分享到广场**，
   别人在「发现」里找到就直接用。
10. **谁都能上手** —— 系统字号放到最大那几档也不破版（判据逐档钉着）、能点的地方手指都点得准、
    屏幕上**没有一个看不懂的词**。

**一句话**：**说得出口，它就办得到，办出来的东西留在你自己的桌面上。**

## 二、技术特点（怎么做到的）

**1. 语音：转成文字直接进输入框，按停就发，中间没有第二个 AI**
「听」用大模型流式语音识别，边说边出字；**字当场长出来**，他点一下就进去改
（一改，后面的话就不再覆盖他改的那份）。**按停** ⇒ 整段回来 ⇒ 发出去（只发一次）。
⇒ 说多少句都行：中间那条时长上限到点只是接着开下一轮，**字一个都不清、一次都不发** —— 只有他按停才算说完。

**2. 一句话会变成"一件有始有终的活"**
登记落盘 → 起一个助手（把这一间的历史喂回去）→ 它自己决定用哪几样本事 → **收口**。
收口有三种结局：**做完了 / 用户说别做了 / 断了**，三种都落账。
所以**硬杀重启之后，它还能逐件如实回答"做完了 / 已停"，不会变成"查无此事"**。

**3. 每个用户一台自己的"盒子"，钥匙不出盒子**
一人一台独立空间（去掉多余权限、代码只读、每台限制内存），他的数据、他的助手都在里面；
助手的环境里**只有一个占位符**，真正使用钥匙的是盒内一个受控小程序 —— **助手连"读钥匙"这条路都没有**。
账号不要了，那台盒子一起删掉（**删号即删盒**）。

**4. AI 写出来的小程序，跑在关起来的沙箱里**
用户说要什么，AI 写代码；**平台这一侧负责建目录、登记、签名入口，页面自己说了不算**。
每个小程序：代码只读、有**自己独立的一格数据库**（别的程序读不到）、
**想联网或想用 AI，要用户第一次打开时点过头才生效**；上网**留痕但只记域名与次数，不记内容**。

**5. 助手只能"提申请"，按按钮的永远是人**
它有能力改自己的代码 —— 但流程是**它提申请、人签字**：改动与命令先摆出来，由人执行。
理由很实际：最危险的不是"它干一次坏事"，而是"坏事能不能留下来"。

**6. 判据先行 ＋ 变异验证（每条规矩都得证明自己抓得住错）**
每做一件功能，先写"怎么算做完了"的自动判据；写完还要**故意把那条规矩删掉或改坏，看判据会不会当场变红**，
不红就说明这条判据是空转的。这套做法真抓到过问题，例如：
小程序外壳曾经一片空白、而当时所有判据都是绿的 —— 因为判据绕开了出错的那一行；
于是多了一条规矩：**凡是客户端自己算出来的东西，检查必须打在客户端这一侧**。

**7. 一直在真机上真上线，不是演示原型**
本作品跑在真实的服务器和真机上（手机、平板、电脑都验过），版本用**一次版本标签 ＋ 线上产物的指纹**钉住。
每一项改动都留下账：做了什么、读数是多少、还欠什么。

**8. 面向最难的那一端做设计**
拿"不会打字、看不清小字的人"当**设计基准**（不是"使用者上限"）：
三条硬规矩（系统字号五档逐档不破版 · 能点的都点得准：点状 ≥44×44、整行按面积算 · 页面不出现内部行话）都是**有判据盯着**的缺陷条目。
最难的一端能用，别的人一定也能用。

**如实说**：本作品**不训练模型**，用的是通用大模型的接口（语音识别也是）；
论模型本身的聪明程度与生态规模，比不过市面上成熟的助手。它比的是**形状**：
**AI 放在用户自己那台机器上、替用户办事，还给用户造软件。**
