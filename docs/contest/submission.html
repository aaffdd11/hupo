摘要

我做的作品叫「琥珀」，是一个会自己动手把事情办完的私人助理。用户对着它说话，它不只是聊天： 它会真的去查资料、写代码、做计算，做完主动回来告诉用户结果；它记得住以前说过的事；出了错会如实说， 半途被打断也能接着说。它最特别的地方是它能给用户"造软件"：用户说一句 「帮我做一个记账的小程序」，它当场写出程序，桌面上当场长出一个图标，点开就能用、数据还存得住。 为了让不会打字、也看不清小字的人也能用，整个界面守着三条硬规矩：字放到 3 倍不破版、 每个按钮的可点范围不小于 44 像素、不允许出现只有图形没有文字、按不动的按钮。 系统用「一人一台专属小主机」的方式保证隐私：每个人的数据、钥匙、助手都跑在自己那台隔离的小主机里。 目前的版本（V1.0）已经在真实的服务器和真机上运行（三台用户的小主机在跑），1513 条自动判据全部通过。

一、作品是做什么的

打开琥珀，看到的是两样东西：一个聊天窗口，和一个桌面。 桌面上一格图标 = 一个小程序 = 它和用户之间的一条对话。用户可以打字，也可以按住麦克风说话。

它给用户的一句承诺：你说的事它真会去做，不只是陪聊。

这句话拆成三条能验证的行为：

  • 记得住：关掉页面、甚至整台机器重启，它还记得之前说过的事（聊天记录、做过的事、答应过的事都落了账）。
  • 真去做：它能读文件、跑命令、查网、算数、画图、记账，还能写一个新的小程序出来。
  • 做完回来说：长一点的活它先放到后台，一句"我先去办"；办完或者失败，它主动说一声；用户随时可以问「那件怎么样了」。
图 1　真实运行中的桌面（截图取自线上）。每一格是一个小程序，也就是一条对话；左下角「＋」是"造一个新的"。

二、为什么要做它

2.1 它是给谁的

它是给不太会用智能手机的人做的：不会拼音、看不清小字的长辈。这类用户有三个真实困难： 打字慢或者根本不会打；界面字太小、按钮太小，点不准；听不懂"工作区、云端、客户端、模型"这些词， 而这些词恰恰是大多数 AI 软件界面上到处都是的。所以本项目把这三件事当成缺陷来管， 而不是当成"风格问题"：

  • 文字放大到 3 倍时界面不许破版、不许溢出（有专门的自动检查，五档字号全跑一遍）；
  • 每一个可以点的东西，可点范围不小于 44 像素（有检查逐屏扫描）；
  • 界面上不许出现内部词（有一份禁用词表，代码里的每一句给用户看的话都要过这道检查）。

2.2 现在的 AI 助手差在哪

常见问题琥珀怎么处理
只会说，不会做；说得头头是道，事情没办助手手里有真的工具（读文件、跑命令、查网、造小程序），并且每一轮活都落账：做了什么、成没成、花了多少，都查得到
做完不说，用户不知道到底办没办收口时主动说结果；失败也主动说清是哪一步没成，而不是悄悄卡住
中途被打断就"失忆"，或者干脆假装没发生过它把"还开着的活"逐件记在盘上；重启后会逐件如实回答"做完了 / 已停"，不会变成"查无此事"
用户不敢把隐私交给它一人一台隔离的小主机，钥匙只在自己那台里，连助手自己都读不到明文钥匙

三、技术原理

3.1 总体结构

系统由三部分组成：用户手上的界面、一台负责转发与记账的中心服务， 以及每个人自己的那台小主机（用容器做的隔离环境，我们叫它"盒子"）。 真正干活的东西（助手、聊天记录、小程序、钥匙）全都在用户自己的盒子里。

3.2 一轮对话：一条有始有终的流水线

用户说一句话，在系统里不是"丢给大模型答一句"，而是变成一件有票、有账、有结局的活：

① 开票把这句话登记成一件活
落盘：谁、哪一间、什么时候
→
② 起助手把这一间的历史喂回去
最近 40 句 / 6000 字
→
③ 干活它自己决定用哪几样工具
读文件 / 跑命令 / 查网 / 造小程序
→
④ 收口三种结局都要落账
做完了 / 用户说别做了 / 断了
全过程实时推给用户看（它正在做什么、用到哪几样工具、花了多少），用户可以选择看详细还是只看结论。
图 3　一轮对话的流水线。"有始有终"是整个系统的地基：没有收口的活，重启后要能逐件如实交代。

3.3 人工智能用在哪三处

（1）当"大脑和手"：由大模型驱动的工具调用

助手背后是一个大语言模型（低推理开销那一档，响应快）。它做的不是"续写文字"，而是 决定下一步用哪样工具、看结果、再决定下一步，直到这件事办完。 这些工具的调用与结果都进聊天窗口的记录里 —— 也就是说，用户能看见 AI 是怎么一步步做事的， 不是黑箱里冒出一个答案。

（2）当"程序员"：由 AI 写出来的小程序，跑在沙箱里

这是本作品最有意思的一段。用户说「帮我做一个记账的小程序」，系统做了四件事：

① 听懂要什么AI 判断这是要"造一个东西"
→
② 写代码AI 当场写出小程序的代码
→
③ 平台那一刀服务端建目录、登记、签名入口
页面自己说了不算，身份由平台给
→
④ 桌面上长出一格做的过程中是灰的、转着圈；做完自己变回来
图 4　一个小程序从"一句话"变成"桌面上的一格"。

每个小程序都跑在一个关起来的沙箱里：代码是只读挂载进去的；每个小程序有自己的一格数据库， 别的程序读不到；它想联网、想连哪个网站、想用 AI，都要用户第一次打开时点过头才生效 （默认什么都没有）。它上网还会留痕：去过哪些域名、多少次，都记在账上（不记录内容）。

（3）当"耳朵和嘴"：听得见，还要听得懂（在研）

现在已经做到的：按住麦克风说话，语音流式识别成文字（用的是豆包大模型语音识别），说完文字就在输入框里。 正在做的下一版（V2.0 第一件）解决的是一件更细的事： 听清楚了，不等于理解对了。所以我们加一层"只听懂、不创作"的快速模型：

  • 它把用户说的话理顺（补标点、改同音错字），但不许添加用户没提过的要求；
  • 它只回答"我哪里不确定"（是上周还是上个月？给谁看？要不要存数据？）；
  • 不确定就问回去（同时用语音念出来 + 文字流式显示），问明白了才自动发出去；
  • 问了两轮还不清楚，就不硬发 —— 屏幕上如实说"这句我没听清，你再说一遍"。

这一层的关键设计是"宁可问一句，也不替用户猜"：因为猜错以后，助手会真的照错的去做。

3.4 怎么做到"你的东西只有你有"

  • 一人一台盒子：每个用户一个独立容器（无特权容器 + 去掉全部特权能力后再按需加回）， 代码层只读挂载，每台限制内存（现在每台 4 GiB）；一台出问题不影响别人。
  • 钥匙不出盒子：模型钥匙放在盒子里的一个特权小程序手里， 干活的助手环境里只有一个占位符 —— 它连"读钥匙"这条路都没有。
  • 删号即删盒：账号不要了，那台盒子一起删掉。

四、实现过程

我用了一套"先立规矩、再写代码，而且每一步都要能被推翻"的做法：

  1. 先写"要什么、为什么"：把设计决定一条条写下来（为什么这么做、代价是什么、以后不许怎么做）， 前后做了两轮独立评审。这些文档是"规矩"，不是"事后说明"。
  2. 判据先行：每一件功能都配"怎么算做完了"的自动判据；代码写完，判据必须通过。
  3. 负向对照 + 变异验证：光"通过"不算。每条判据都要证明它抓得住错 —— 我会故意把那条规矩删掉或改坏，看判据是不是当场变红；不红就说明这条判据是空转的。
  4. 每一步留账：做了一批就记一行账（做了什么、读数是多少、还欠什么）。 现在仓库里有 182 篇实现契约，全部可追溯。
  5. 边做边真上线：目前版本 V1.0（2026-10-04 定档）， 已经部署在真实的服务器上、真机上在用（现在有三台用户的小主机在跑）；之后只修严重问题，新功能进 V2.0。
这一段最想说明的是：这个作品不是"演示原型"。 它有真用户、真服务器、真容器，也有真出过的故障和修法（例如有一次浏览器端因为地址算法写错导致数据流被浏览器拦掉， 而当时所有自动判据都是绿的 —— 因为判据绕开了出错的那一行。我们把这条教训写成了新规矩： 凡是客户端自己算出来的东西，检查就必须打在客户端这一侧）。

六、安全考虑

#防线具体做法
1助手只能提申请，签字的是人要改动运行中的系统（装东西、改配置），助手把命令准备好，由人按键执行。理由是：真正的危险不是"它干一次坏事"，而是"坏事能不能留下来"——比如它读到一段看不见的网页内容，被诱导写进自己的配置，从此每次开机都读它，而表面上一切正常
2一人一台盒子容器隔离 + 只读代码层 + 资源上限；跨用户看不到对方任何东西
3钥匙不出盒子盒内特权小程序握钥匙，助手只有占位符；日志和回复里永不出现钥匙
4小程序：声明 ≠ 已给小程序说"我想要联网 / 想用 AI"只是它想要；用户第一次打开时一张弹窗一次问完，点过头的才生效；数据天生就有存储，但每格独立、跨格读不到、随时能一键清空
5上网留痕助手能访问网络，但去过哪、多少次都落账（不记录内容），可查
6开机完整性清单决定"它下次开机读什么"的文件（人格、规范、能力清单），哈希写在 root 只读清单里，动过就拒绝启动；每次重建都留痕
7删除要二次确认删之前先把它要带走的东西（聊天 / 数据 / 经验）逐条摆出来再问一次；服务端是软删除，还能拿回来
8页面不许说假话做不到的事不许画按钮；拿不到的事实不许猜（"不知道"就说不知道）。这条被当成缺陷来管，有判据盯着

八、不足与改进方向

  • 语音输出还没接通手机：网页上已经能用设备自带的声音念出来，手机（安卓包）还不能；正在接通云端语音合成。
  • 登录还靠临时验证码：正式短信通道还没接，这是"已知并接受"的临时状态，不是最终形态。
  • 性能还没优化：目前策略是"先功能、后性能"，所以内存占用、并发上限都还比较宽松。
  • "助手卡住"还有一类情况不能自动收尾：进程死掉能自动收场，但"进程活着却卡在不动的循环里"目前没有自动收尾（这是为了让长活不被时间上限砍掉而做的取舍，写在设计记录里）。
  • 平台只有网页和安卓：iOS 还没做。
