## 三、这一轮改了什么（客户端那一处"等"）

**改之前**（`197` 之后的样子）：`ch = 连上; await ch.ready;` → 开麦 → 音频直接 `send`。
**那个 `await` 就是剩下的洞**：连接冷的时候要 **4.4 秒**，这 4.4 秒里麦克风还没开
（网页与安卓**两份都是这个顺序**）。

**改之后**：**采集与连接并行**。

```
按下那颗圆圈
  ├─ ① 把连接**开出去**（不 await）
  ├─ ② 立刻开麦（getUserMedia / AudioRecord）
  │     每采到一包 ⇒ outbox.add()：连上了就当场发；没连上就**攒在本机**
  └─ ③ 那条连接一握上手 ⇒ 先发 asr/start，再把攒着的**按原来的顺序**补发
```

* 新 `models/asr_outbox.dart`（纯逻辑）：一包都不丢、顺序不许变、`clear()` 报得出丢了多少；
* 两道门的长短关系：`_verdictLimit`（**10 秒**，连接＋握手那一拍）—— 因为现在攒着的音频
  **不会丢**，多等一会儿是白赚（原来 5 秒，而冷启单是连接就量到 4.4 秒 ⇒ 会误报"这条走不通"）；
* 服务端那一侧**本来就有**一份同样的攒法（`src/asr-doubao.js` 的队列）；这一改让
  "他按下来说的头几个字"**从最前面那一毫秒起就进了本机**。
