> ## 🔴 **2026-09-23 追加：展开那一刻也是"打开"**（主人实测报的）
>
> **主人原话**：*"聊天展开的时候默认显示了最早的聊天。这是不对的。应该默认展示最新的聊天。"*
>
> **根因**（和本文上面那条**不是同一个**）：**收起档根本不建时间线** ——
> `chat_floater.dart` 里是 `if (collapsed) … else Expanded(child: widget.child)`，
> 所以**点"展开"那一刻时间线才被建出来**，新视口的偏移从 **0** 开始 = 停在**最早**那条；
> 而"跟到底部"那次调用只在 `initState` 的 post-frame 跑过一遍（那时还是收起档、没有列表可滚）。
> ⇒ **修法**：`chat_screen.dart` 的 `onTier` 里，**一旦变成非收起档**就
> `_userScrolledAway = false` + post-frame `_jumpToLatest()`（`jumpTo`，**强制**）。
> ⚠️ **而且它要连补几帧**（4 帧 ≈ 66ms）：第一次真机截图只落到了"**差一条**"——
> 最后那句用户的话被输入条切掉、它的回答还在下面。两个原因叠在一起：
> ① 展开是**动画**（视口还在长）；② 列表**懒加载**（跳到底之后新露出来的条目才被 build，
> `maxScrollExtent` **又长一截**）。⇒ 每帧再钉一次当前的最大值，直到稳定。
>
> ⚠️ 而且这 4 帧补跳**必须一发现"用户动过手"就立刻收手**（`_userScrolledAway` 为真 ⇒ 直接 return）：
> 不然它会把用户**刚做的上滑**又拽回底部 —— 那正是本文件上头那条"**用户正在翻就不打断他**"要挡的。
> 🔴 **这一条是被已有的硬闸抓出来的**：D3.6「主界面（含"重发"那个入口）」那条判据先上滑到顶去找"重发"，
> 补跳把它拽回底部 ⇒ 1.75x/2.0x/3.1x 三档全红（"Found 0 widgets with text 重发"）。
>
> ⚠️ **如实说一句**：**"懒加载那半"没有判据钉住** —— 把连补拿掉（只跳一次）时，
> `test/widget/scroll_follow_test.dart` 那几条**照样全过**（测试环境里一次就够）。

## 一、证据链（怎么发现的）

收尾那次浏览器端到端检查（`scripts/check-web-browser.mjs --shot`）报的是**全绿**：
1 条 WebSocket / 79 帧 / 认出 5 类事件 / 续期换新。**路是通的。**

但截图里停在**第一次对话**（"今天是星期几"那几句），而当时盘上已经有 78 条：

```
截图里最后那条   →  seq 19 （2026-09-20 19:55）
盘上最后一条     →  seq 78 （2026-09-21 01:29）
```

⇒ **那条闸只证明了"路通了"，没证明"屏幕上对不对"** ——
而 Flutter web 把字画在 canvas 上，**查 DOM 查不到文本**，
所以"看一眼截图"是这一侧**唯一**的手段。这一条本身就是那条闸的价值。

## 二、根因

`chat_screen.dart` 原先只有一条跟随判据：

```dart
final nearBottom = pos.maxScrollExtent - pos.pixels < 160;
if (nearBottom) { _scroll.animateTo(pos.maxScrollExtent, …); }
```

而**首屏**是 `pixels == 0` 对上一屏历史 ⇒ `maxScrollExtent - 0` 远大于 160
⇒ `nearBottom` **恒 false** ⇒ **一次都不滚**。

⚠️ 它错起来是**静默**的：没有异常、没有任何闸会红，只是"打开看到的是最老那段"。
这和这个仓库反复栽的"静默降级"是同一个形状。

## 三、判据（写下来，别只写代码）

> **打开时、以及新内容进来时，只要用户自己没往上翻过，就必须跟到底部。**

反过来那条同样不许破：**用户自己往上翻过之后，不许把他拽下去**（旧行为，保留）。

## 四、修法

| # | 做了什么 | 为什么 |
|---|---|---|
| 1 | 判据搬成**纯函数** `lib/models/scroll_follow.dart` | 它是一条**能算错的规则**；纯函数才进得了 `test/unit` 的硬闸（手册：纯函数进 unit，界面断言只是提示） |
| 2 | 新增一个布尔 **`_userScrolledAway`** | "离底部近"不足以判断"该不该跟"；缺的正是"用户有没有自己翻过" |
| 3 | 那个布尔**只由手指拖出来的滚动**置位（`ScrollStartNotification` / `ScrollUpdateNotification` 的 `dragDetails != null`） | 我们自己 `animateTo` 产生的那次不算 —— 否则第一次跟随就把自己关掉（那正是这个 bug 的另一种写法） |
| 4 | `initState` 里也**跟一次**（postFrame） | 本机缓存那一屏（`17-LOCAL-FIRST.md`）可能在**挂载之前**就已经在控制器里了，那时 `_onChanged` 一次都不会触发 |
| 5 | 首屏用 **`jump`**，后续用 `animate` | 历史一长，`animate` 会当着主人的面从最老那条**一路滑下来**（页面自己在动，很吓人） |

## 七、连带修的一处**闸**（同一个改动带出来的）

时间线**会滚**之后，可访问性硬闸（`accessibility_test.dart` 的 D3.6 扫描）红了 ——
量到「重发」的命中区是 `Size(65.2, 20.5)`。查下来**不是按钮变小了**：
那个矩形是**被视口裁过**的（按钮有 44 高，滚到一半 ⇒ 语义矩形只剩 20.5）。

⇒ 这是**闸自己的缺陷**：读数**随滚动位置变** ⇒ 同一份代码，滚到哪儿决定闸红不红。
而"读数会变的闸"下一步就是被绕过。

修法两条（都在 `accessibility_test.dart`）：

1. `sweep` 改成**先 `ensureVisible` 再量**（改成异步）：量之前把按钮**完整露出来**；
2. 主界面那条用例**先滚到最上面**，并且**断言「重发」真的在这棵树里** ——
   因为默认位置现在是"最新那一条"，不显式滚上去的话它可能根本没被 build，
   而 `checked > 0` 照样是绿的（顶栏那几个图标永远在）⇒ 闸会**悄悄漏掉那只按钮**。

⚠️ **反向对照**（证明这道闸被改完之后**没变松**）：把「重发」的
`minimumSize` 改成 `10×10` **并且** `tapTargetSize` 改成 `shrinkWrap`（真的把命中区做小）
⇒ **当场红**。

⚠️ 顺带记一个**容易误判**的点：只改上面两项里的**一个**，闸**不会红** ——
因为另一项仍然撑着 44（`minimumSize` 给 44×44，`padded` 再撑到 48）。
那两次"没红"是**对的**，不是漏报。

## 八、⚠️ 顺带发现：提示档那一段**写死了一个文件名**

写这一条的时候发现：我新加的 `test/widget/scroll_follow_test.dart` **根本不在任何一道闸里**。
`scripts/check-client.sh` 的提示档原话是"剩下的界面测试"，而它跑的是**硬编码的一个文件**：

```bash
run "其余界面测试（提示）" "提示" -- "$FLUTTER" test test/widget/busy_line_test.dart
```

⇒ 后果：**以后每加一个 widget 测试，它都不会跑** —— 而"新加的那一份"恰恰是最该跑的。
实测已经漏过**两次**：批 3 加的 `process_levels_test.dart`（11 条）与本条加的 `scroll_follow_test.dart`（3 条）
**从没进过任何闸**。它们绿不绿，谁都不知道。

修法（不靠纪律，靠结构）：**扫目录**，只排掉已经当过硬闸的 `accessibility_test.dart`：

```bash
for f in test/widget/*_test.dart; do … done
run "其余界面测试（提示）" "提示" -- "$FLUTTER" test "${HINT_FILES[@]}"
```

并且：一个文件都没有时**直接非 0 退出**（"这一档成了空转"本身是个错误，不是"没东西可跑"）。
⇒ 从此漏一个在**结构上不可能**。实测：提示档从 **5 条**变成 **19 条**（5 + 11 + 3）。
