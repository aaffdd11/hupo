# 189 · 那一格三颗按钮：录音 · 展开聊天 · 播放语音

> **主人 2026-10-05 原话**：*「语音按钮的右侧，需要两个按钮。一个是展开聊天，一个是播放语音。
>   所谓播放语音，就是开启和关停的状态，如果开启，会将对 agent 的回复进行语音转换和实时播报。
>   如果关闭，则不播报。播报只播报核心内容，也就是字体较大的那个内容。」*
> ⇒ 手册 `D3.14` 再补 · 升 `v2.57`。

  圆圈与那两颗照样点得动）。

## 二、播放语音那一颗说什么、不说什么

| | |
|---|---|
| **开** | 它**新说的话**（`message/end` 且 `reason == 'completed'`）会被念出来；那颗图标是实心喇叭 + 琥珀色 |
| **关** | 一个字节都不念，而且**关掉的那一刻立刻停下正在念的那一段**（不许"按钮说关、它还在念"） |
| **念哪一份字** | 🔴 **只念核心内容** ＝ 气泡里那两段**大字**（`quick` ＋ `deep`，`AssistantMessage.displayText`）。工具那一行 / 过程 / 出处 / 每轮 token 那些**小字一个都不念** |
| **什么时候念** | 那一条**说完**了才念（半句 / "没说完" / "卡住了"不念 —— 念出来会让人以为事情做完了）；**首屏那段历史不念**（一登录就把它以前说过的话全念一遍是骚扰） |
| **谁念** | 网页：浏览器自带的合成器（`window.speechSynthesis`，一个字都不往外发）。**安卓那一侧今天还念不出来**（`speech.dart` 那一条桩）⇒ **那颗按钮不画**，等火山那把语音合成接上再说（见 `181` §六 第一问的乙） |

⚠️ **念不出来的设备一个按钮都不许画**（`speech.dart` 纪律 ②）——
调用处那一句 `canSpeak ? … : null` 就是那道门，判据钉着它。

🔴 **网页上的一个真坑（顺手修了）**：浏览器给音色是**异步**的，而 `canSpeak` 是**同步**读的
⇒ 第一帧上还没有音色 ⇒ 那颗按钮**先不画**；没有别的原因重建的话，它要等很久才出现。
⇒ 新加 `watchSpeakReady()`（`speech_web.dart` 听 `voiceschanged`，别的平台空操作）：
音色一到位就举手一次，界面重建 ⇒ **按钮自己出现**。

## 六、2026-10-05 下半场：两档 ＋ 安卓也能念（主人的两条回话）

> **主人原话**：*「播放语音按钮没看到。展开聊天我希望不要有移动聊天窗口高度的选项，
>   就是完全展开或者完全收起。」*

### 6.1 只有两档

* `FloaterTier` 由三档收成**两档**（`collapsed` / `full`）—— **"半开"那一档删了**；
* **"拖着改高度"整条砍掉**（那两层 `Listener`、跟手高度、甩动吸附、`halfRatio`、
  `dragFloor` 的那套算法全删）⇒ 展开那颗箭头**点一下就是拉满**，拖它什么都不发生；
* 判据跟着改（`desktop_floater_test`）：**拖它不改高度**（负向对照）＋ 点它**一次到全开**
  （量的是"上边距＝那一个常量"，不是"可用高度的百分之多少"）。

### 6.2 安卓上那颗「播放语音」

**为什么"没看到"**：那一侧原来走的是 `speech_stub.dart`（`canSpeak` 恒假）⇒
按"念不出来就不画"那条规矩，那颗按钮**根本不画**。

**改法**：安卓那一份改用**系统自带**的合成器（`android.speech.tts`）——

| 在哪 | 干什么 |
|---|---|
| `android/.../NativeTts.kt`（新） | `TextToSpeech` ＋ 中文音色判定 ＋ 念完回调；channel `hupo/tts`（`canSpeak` / `speak` / `stop` ＋ 主动回一条 `ready`） |
| `MainActivity.kt` | 挂第三条 channel（与录音/开麦同一个地方） |
| `AndroidManifest.xml` | 🔴 **必须**有 `<queries><intent><action android:name="android.intent.action.TTS_SERVICE"/></intent></queries>` —— Android 11 起 app **看不见**没声明的包，不写这一条引擎起不来（按钮就永远不出现） |
| `lib/services/speech_native.dart`（新） | 钩子那一份（`installNativeTts()`，只在 Android 装）；`ready` / `speakEnded` 两条回调 |
| `lib/services/speech_stub.dart` | `canSpeak` 由 `const bool` 改成**取值**（钩子说了算）＋ `watchSpeakReady` / `notifySpeechReady` |
| `lib/main.dart` | `installNativeTts()`（与 `installNativeHearing()` 并排） |

⚠️ **它不联网**：念的是系统那一层（与网页用 `window.speechSynthesis` 是同一件事）。
⚠️ **引擎起不来 / 没有中文音色** ⇒ 照旧**一颗都不画**（不假装）。

### 6.4 又一笔：那颗按钮在两档里**不许挪窝**（主人当场看出来的）

> **主人原话**：*「打开聊天历史窗口后，我发现按键变了。语音按键位置改变了。是新做了一个还是原来的？」*
> ⇒ **是原来那一颗**（同一个 widget、同一个 key、同一份实现）。位置变了是**这次改动的副作用**：
> 那两颗原来**只画在收起档**，打开窗口那一下外面少了 ~96 像素 ⇒ 圆圈与它左边那句字整块往右跳。

**改法**：两个档走**同一个** `_bottomRow` —— 播放那颗**一直在**；展开那颗只在收起档画、
**位置留着**（展开档是一个等宽的空格）⇒ **一个像素都不动**；而收起来的出口**仍然只有**
标题行右端那颗「收起」（不新造第二条路）。

🔴 **顺手量出来的 4 像素**：`Material` 默认 `padded` 会把点击区从 44 撑到 48 ⇒
收起档那一格 48、展开档那个空位 44 ⇒ 录音那一格差 4 像素（判据量到 506 vs 510）。
⇒ 给那颗箭头加 `tapTargetSize: MaterialTapTargetSize.shrinkWrap`（**仍是 44×44**，D3.6 硬闸照过）。

**判据**：`test/widget/voice_buttons_test.dart` ④ —— 两档里录音那一格的右边缘、
播放那颗的位置**逐像素相同**；负向对照：展开档**不画**展开箭头、但标题行那颗「收起」在。

### 6.5 那两颗改成一列 ＋ 长方形轮廓（主人 2026-10-05 原话）

> *「语音按钮右侧，展开聊天窗口和开启关闭语音，是一列的。就是上下关系。展开在上，
>   开启关闭在下。然后他们都要有一个长方形的按钮轮廓。」*

* 收起档那一行右边从"横排两颗"改成**一列**：`Column([展开, 播放])`；
* 两颗都是**长方形 ＋ 一圈轮廓**（`TextButton` 带 `side` + `RoundedRectangleBorder`，
  圆角 12）；**开着**的「播放语音」轮廓与图形都用琥珀色（状态一眼看得出）；
* 尺寸住 `design.dart`：`voiceAuxW = 64`（**＝那颗圆圈的宽**，一列对齐它）·
  `voiceAuxH = 44`（≥44 硬闸）· `voiceAuxGap = 4` · `voiceAuxRadius = 12`；
* 🔴 **两个档仍然是同一个形状**：展开档画一个**等大的空格** ⇒ 语音那颗不挪窝（6.4 那条照旧成立）。

**判据**（`test/widget/voice_buttons_test.dart` ①）：两颗**同一条竖线**（`dx` 相等）、
**展开在上**（`bottom <= speak.top`）、两颗都有**圆角矩形轮廓**且 `width > 0`
（负向对照：没有轮廓 / 轮廓宽度为 0 都会被点出来）。

### 6.6 缩小一些 ＋ 要有底色（主人 2026-10-05 原话）

> *「那两个按钮可以缩小一些，然后需要底色的。」*

* **看得见的那一块缩小**：`Container` 40×28（`voiceAuxFaceW/H`，圆角 9），里面图形 18；
* **要有底色**：平时 `d.card`（与录音那颗圆圈同一个底）＋ 一圈弱描边（`p.borderL3`）；
  **开着**的「播放语音」整块 `d.accent` ＋ 白图形（状态一眼看得出）；
* 🔴 **手势那一格不动**：外面仍是 44×44（`voiceAuxW/H`，`tapTargetSize: shrinkWrap`）——
  这正是 D3.6 那句"**视觉仍小，用透明 padding 撑命中区**"；
  判据量的是**布局盒子**（`accessibility_test` 的 `sweep()`），所以两边都成立。
* 这一列的高度随之从 92 落到 90（44+2+44），浮窗那条 bar 也跟着矮一点。

**判据**（`test/widget/voice_buttons_test.dart` ①）：那次量的是**里面那一块**
（`Container` 的 `BoxDecoration`）——**有底色**（`color != null`）、**有轮廓**（`border`）、
**是圆角矩形**（`borderRadius != null`），而且**它比手势那一格小**（缩小的负向对照）。

### 6.7 上面那颗"翻个方向" ＋ 录音那颗白底加一圈琥珀（主人 2026-10-05 原话）

> *「那个展开窗口，你要帮我把它变成展开以后是变成缩小窗口的按钮啊，所以它位置就不变，
>   然后呢关于聊天的那一个按钮呢？就是那个语音按钮呢上外面要加一个边框啊，这个边框就是有
>   那个琥珀色，就是按下去录音时候的那个颜色，然后呃录音按钮和展开按钮他们也都有一个白色的底色」*

* **上面那一颗**：`_handle(p, collapsed: ...)` —— **同一个 key、同一个位置、同一个样子**，
  收起档朝上（点它 = 拉满）、展开档朝下（点它 = 收起）。
  🔴 **于是展开档里「收起」有两条路**：标题行那颗（`D3.15`／2026-09-29 主人自己定的）
  ＋ 这一颗。这不是打架：主人这次点名要"位置不变的那颗翻成缩小窗口的按钮"。
  判据跟着改：那几处 `findsOneWidget` 的「收起」断言改成 `findsWidgets`。
* **录音那颗圆圈**：`CircleBorder(side: BorderSide(color: d.accent, width: voiceCircleRing))`
  —— 平时也带着那一圈琥珀（按下去录音时那个颜色），底色仍是那张纸的白；
  在录时整颗变琥珀（`RecBlink` 一明一暗地闪），那一圈还在（与底同色，不碍事）。
* **白底**：圆圈与那一列两颗**平时都是那张纸的白**（`d.card`）。

**判据**：`test/widget/voice_blink_test.dart` 新增一条 —— 那一圈是 `d.accent`、宽度 > 0、
底色是 `d.card`；`voice_buttons_test` ④ 改成量"展开档那颗**还在原处**、点它真收起来"。

### 6.8 三颗是一体的（上下沿对齐、风格统一）＋ 网页那颗按钮（主人 2026-10-05 原话）

> *「聊天按钮，展开聊天，播放语音，他们是一体的，因为我看到横屏以后他们不在一个位置了。
>   我看首先网页端无法显示播放语音按钮，其次他们高度不同。就是展开关闭，播放语音两个合起来，
>   高度应该和录音按钮是一样的。他们风格也应该统一。」*

**① 一体的（几何）**：`2 * voiceAuxFaceH + voiceAuxGap == voiceCircleBox`
（30 + 4 + 30 = 64）—— 判据直接钉这条等式，并量"两块之间的缝就是 4"。
⚠️ 外面那两格仍是 **44 高**（D3.6 的手伸得进去），但**面贴着内沿**
（上面那颗贴下沿、下面那颗贴上沿）⇒ 看得见的是一列 64 高、与圆圈**上下沿对齐**。
🔴 **一个坑（记着）**：那一列的高度是**无界**的 —— 单摆一个 `Align` 会被框架自己那层
`Align(center)` 居中（实测面与面之间变成 18 而不是 4）⇒ 必须给一个 `SizedBox(height: 44)`。

**② 高度恒定**：念不出来的设备**下面那一格留着**（画一个等大的空格）——
不留的话这一列矮一半，上面那颗与圆圈就对不齐（"一体"就散了）。

**③ 风格统一**：三颗都是 `d.card` 白底 ＋ **同一圈琥珀**（`d.accent`、粗细 `voiceCircleRing`）。

**④ 网页那颗按钮不许因竞态消失**：`speech_web.dart` 原来只听 `voiceschanged` 一条事件，
而各版本浏览器**会漏**（主人报"网页端无法显示播放语音按钮"）⇒ 再补一条**轮询**
（`speakPollEvery` 500ms / `speakPollFor` 20s），看到音色就举手；到期还没有就安静收手
（那颗按钮不画 —— 按 D5.16 那条规矩）。

**判据**：`test/widget/voice_buttons_test.dart` ⑤（三选一：等式、缝隙、命中区、那一圈的颜色与粗细）。

### 6.9 网页端为什么没有那颗按钮（主人 2026-10-05 问的）

> *「网页端为什么没有语音应答功能按钮？」*

**查出来（不是"没做"，是"做了但静默消失"）**：那一句门原来是
**"浏览器的音色表非空"**才画那颗按钮（P1-2，2026-09-24 定的）——
而各浏览器给音色是**异步、而且不一定给** ⇒ 那颗按钮**根本不出现**。
我的无头浏览器就是这样（实测：`speechSynthesis` 在、`getVoices()` 空）。

**改法**（拆成两个问题，各管各的）：

| 问题 | 判据 | 用在哪 |
|---|---|---|
| **画不画那颗按钮** | `canSpeak` ＝ **这个平台有没有那个能力**（`speechSynthesis` 在不在） | 界面上那一句 `canSpeak ? … : null` |
| **真念得出来吗** | `speechHasVoices` ＝ 音色表空不空 | **按下去**那一下：空的 ⇒ `speakAloud` 回 `false` ⇒ 界面上**如实说一句**（`speakCannotWords`） |

⚠️ **"屏幕上不许出现按不动的东西"一个字没松**：那颗按钮现在**按下去一定有反应**
（要么念出来，要么说清"这台设备上没法念出来"）。

**判据**（`test/unit/speak_test.dart`）：那一条 P1-2 **改了口径** —— 现在钉三件：
① `canSpeak` 看的是**能力**（而且**不许**再拿 `getVoices` 判它）；② 写死 `true` 照旧不许；
③ `speechHasVoices` 那一条在、而且"没音色 ⇒ `return false`"（不许假装交出去了）
＋ 那句实话真的接上了（控制器里有 `speakCannotWords`）。

### 6.10 直白那份带下划线 ＋ 按停要等两步都完（主人 2026-10-05 原话）
