## 一、这一层的四个模块

| 模块 | 管什么 | 最容易做错的一条 |
|---|---|---|
| `auth.js` | 口令 / 令牌 / 限速 / 审计 | **fail-closed**：没设口令 ⇒ 一律 503（不是放行） |
| `resume.js` | 续传与补发（纯函数） | **`catchUp` 只在续传游标 > 0 时才标** |
| `say.js` | 用户说话 + **幂等** | 去重必须**跨重启有效** |
| `server.js` | 路由 / 静态 / WS | **WS 没令牌在握手阶段就拒**，不是先连上再关 |

## 二、六条硬要求，以及为什么

### 2.1 fail-closed（`auth.js`）

**没设口令 ⇒ 除三个公开路由外一律 503。**

为什么这是一条硬要求而不是"最佳实践"：默认放行的话，
**一次"忘了设口令"的部署就等于把整台机器公开发布出去**——
而部署者**不会察觉**，因为一切看起来都在正常工作。

⇒ 所以服务启动横幅**把状态喊出来**（手册 §11.4）：

```
鉴权  ⚠️ 还没设密码 ⇒ 除三个公开路由外一律 503（fail-closed）
      设密码：npm run set-pass -- "你的密码"
```

**公开路由只有三个**：`/api/version`、`/api/auth`、`/api/login`。
`PUBLIC_ROUTES` 是个冻结常量，加任何一个都要在评审里回答"它真的必须公开吗"。

### 2.2 令牌只走头，不走 URL

- HTTP：`Authorization: Bearer <token>`
- WS：**子协议** `['bearer', <token>]`

**URL 里的令牌一律忽略**——URL 会进访问日志、进 `Referer`、进浏览器历史。
有一条测试专门钉这个（`?token=...` 必须 401）。

### 2.3 WS 在**握手阶段**拒

没令牌 ⇒ 直接回 `401` 并断开，**不建立连接**。
"先连上再关"会给爬虫/扫描器留下一个可以站着的连接。

### 2.4 `catchUp` 只在续传时标（决策 P-h）

```
sinceSeq = 0    → 全量历史，**不标** catchUp   ← 首次打开
sinceSeq > 0    → 只补后面的，**标** catchUp   ← 断线重连
```

**标错的后果**：每次新装客户端，整段历史都会被渲染成"你不在的时候"。

另外一条同样重要的：**客户端游标跑到我们前面时**（日志被换过、或它连的是另一条线），
**必须明确回一个 `client/reset`**，不能"什么都不发"——
那会让界面**永远停在一个已经不存在的世界上**。

> ⚠️ `markCatchUp` **必须浅拷贝**。事件对象是从日志读出来的，
> 直接改它等于**把"补发"这个线上标记写进磁盘**。有测试钉这条。

### 2.5 幂等必须跨重启

客户端会在"它以为没发出去"的时候重发——而那种时刻，
**服务端很可能刚重启过**（这正是它没收到回执的原因）。

⇒ "见过的 messageId" 是**从日志重建**的，不是内存里的一个 `Set`。

### 2.6 令牌长度按**码点**数

`'🔒🔒🔒🔒🔒'.length === 10`（UTF-16 单元），但用户看到的是 **5 个字符**。
口令长度是策略，但**数错就是数错**。⇒ 用 `[...s].length`。

## 三、验收（对到手册的判据）

| 判据 | 测试 |
|---|---|
| fail-closed：没口令 ⇒ 503 | `server.test.js`、`auth.test.js` |
| 公开路由只有三个 | `auth.test.js` |
| 无令牌 / 错密码 / URL 里带令牌 ⇒ 401 | `server.test.js` |
| 锁定并**给剩余时间**（D2） | `auth.test.js`、`server.test.js` |
| 撤销表、失败计数**落盘**，重启仍生效 | `auth.test.js` |
| 审计只记 `{at, result, ip}`，不含口令/令牌 | `auth.test.js` |
| XFF 取**最后一跳** | `auth.test.js` |
| 幂等（含跨重启） | `say.test.js`、`server.test.js` |
| `catchUp` 只在 `sinceSeq > 0` | `resume.test.js`、`server.test.js` |
| 游标超前 ⇒ `client/reset` | `resume.test.js`、`server.test.js` |
| WS 握手阶段拒无令牌 | `server.test.js` |
| 落盘失败 ⇒ WS 上收不到那条 | `server.test.js` |
| 静态：入口不缓存、产物可长缓存、防目录穿越 | `server.test.js` |

**怎么跑**：

```bash
cd v2/services/core
npm test        # 108 条
npm start       # 起服务（默认 127.0.0.1:8020，fail-closed）
```

## 四、⚠️ 这一批**没做**什么

| # | 没做 | 什么时候 |
|---|---|---|
| 1 | **agent 运行时**（spawn / role patch / 进程上限 / LRU） | 下一批——现在说了话没人接 |
| 2 | **`message/*` 的产出**（谁来回话） | 随 agent 运行时 |
| 3 | **`scopeId` 真正参与路由** | 作用域那一批 |
| 4 | **`/api/conversations` 系列**（列表/导出/删除） | 出口那一批 |
| 5 | **`step/*` 的产出**（现在只是"若出现则不推给非 dev 连接"） | 过程可见性那一批 |
| 6 | **真正的 `dev=1` 附加通道**（现在是"过滤已知的 step 前缀"） | 同上 |
| 7 | **前端**（Flutter web） | 下一批，见 `03-DEPLOY-WEB.md` |

⚠️ **现在这个服务"能收话但不会回话"**——这不是缺陷，是顺序：
先把"进来的路"做对（幂等、认证、续传），再接上"干活的那一头"。
