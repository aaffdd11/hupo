# 21 · 打了还没发出去的那句话（**欠账 18**）

> **这一批做的事**：用户自己打了、**还没被服务端认领**的那句话，刷新一下**不丢了**。
> 它回来的时候还是「没发出去」那个样子，还有「重发」——**不是凭空变成"已收到"**。
>
> **手册依据**：`17-LOCAL-FIRST.md` §七第 1 条（这条欠账就是那一批**明说没做**的）·
> `03-DEVELOPMENT.md`（`timeline_store.dart`：**只缓存，不判断**；有界；命名空间）·
> `08-SPEC.md` §4.1（四态）· 不变量 **N11**（拒绝 = 人话 + **可重试**）
> **代码**：`lib/services/draft_store.dart`（新）· `lib/services/chat_controller.dart`
> **测试**：`test/unit/draft_store_test.dart` **+21**（unit 96 → **117**）

---

## 一、这个缺陷长什么样

`Timeline` 里**只有带 `seq` 的服务端事实**会被 `timeline_store.dart` 存下来。
用户自己打的那句（`queued` / `sent` / `failed`）**没有号** ⇒ 只住在内存里：

```
打一句 → 按下发送 → 网卡住了（屏幕上：「没发出去」+「重发」）
   │
   └─ 刷新一下 ⇒ **那句话没了**，而且用户不知道自己丢了什么
```

⚠️ 它比"少显示一条"更坏：屏幕上刚刚还写着「没发出去」——**用户以为它还在**，
一刷新却像从来没打过。这正是 `17-LOCAL-FIRST.md` §一 记的那类失败
（"我把它弄坏了"），只是这次丢的是**用户自己的字**。

## 二、边界：两本账，**不许重叠**

| | 存什么 | 判据 | 谁的地盘 |
|---|---|---|---|
| `timeline_store.dart` | **服务端说过的事实** | 带 `seq` | 助手说过什么、服务端认领过什么 |
| `draft_store.dart`（新） | **我这边还没被认领的话** | `UserUtterance` 且 `state != confirmed` | 我打了一半的那几句 |

两句关键的话：

* **被认领（`confirmed`）⇒ 从存档里消失**。它已经变成服务端事实，归旁边那本账了。
  ⇒ 刷新**不会出现两遍**（这是最刺眼的那种缺陷，有一条测试专钉）。
* **存档从时间线现算**（`draftsFrom(timeline.items)`），不另立一份"影子列表"。
  ⇒ 不可能出现"存档里有一条屏幕上没有的"。

```
按下发送 ──► addLocalUtterance ──► `_saveDrafts()`（**不等**，先存档再发）
                                        │
服务端回声 ──► timeline.apply（认领）──► `_saveDrafts()` ──► 那条从存档里去掉
```

⚠️ `_saveDrafts()` 一律**不 await**：存档是"最好有"，
**绝不能拖慢用户按下发送之后那一屏**（那正是 8/10 的放弃点）。

## 三、只有三个字段（最少必要）

`messageId` + 正文 + 当时的态。**服务端事实那两个特征（`seq` / `type`）一个都不写**——
有一条测试直接断言字段集合就是那三个。

`messageId` 是重发的命根子：**必须用同一个**，否则服务端会当成新的一句，
于是 agent 干两遍（评审 E2）。

## 四、⚠️ 唯一一处"不是原样存"：`sent` 读回来是 `failed`

这是这一批里**唯一一个判断**，值得单独说清楚（它不是洁癖）：

走到 `sent` 只说明 **HTTP 200 到过**，**回执还没来**。而刷新之后，
那条回执**永远不会来了**——`user/echo` 补发的是"这句已经被认领"这件事，
**没被认领的那次请求不会有人重放**。

⇒ 留着 `sent` = 屏幕上写着「已送到」、**却没有「重发」这个入口**：
  用户既不知道它到底到没到，也没有任何办法再试一次。**那就是说假话。**

⇒ `storableState()`：`sent → failed`，只此一条。其余原样。

| 存进去时 | 读回来时 | 屏幕上 | 能做什么 |
|---|---|---|---|
| `queued` | `queued` | 已交出去 | 等（回执来了就认领） |
| `sent` | **`failed`** | **没发出去** | **重发** |
| `failed` | `failed` | 没发出去 | 重发 |

⚠️ 降成 `failed` **不会让 agent 干两遍**：服务端按 `messageId` 幂等
（重复那次返回 `duplicate`，不落盘、不重放）。

## 五、有界、坏了当没有、命名空间（照 `timeline_store.dart`）

| 事 | 值 / 做法 | 为什么 |
|---|---|---|
| 条数 | `capDrafts = 20` | 屏幕上同时"没发出去"的话一般就一两条，20 是个宽裕的余量 |
| 字符 | `capChars = 64 * 1024` | 够一整段长粘贴，又只是 localStorage（一般 5MB）的一个零头 |
| 丢法 | 从**最前面**整条整条丢 | 截半条 = 解不开 = 可能画出半句话，**那是编造** |
| 坏行 | 跳过它，好的照用 | 一行坏不许拖垮整份存档 |
| 读不到 / 存不上 | 当没存档，**绝不抛** | 存档坏掉的后果必须小到"就是少几句话" |
| key | `hupo_drafts_v1.<namespace>` | 形状与 `hupo_timeline_v1.<namespace>` 一致 |

⚠️ 命名空间（`scopeId + userId`）**这次仍然只填了一半**，理由与
`17-LOCAL-FIRST.md` §五 完全相同：客户端里没有 `scopeId`，也不解析令牌里的用户名。
⇒ 现在真正兜住"换个人就串"的是：**退出登录时清掉**（`logout()` → `_invalidateLocal()`）。
⚠️ **多人那一批两本账要一起补 `userId`。**

## 六、接线（`chat_controller.dart`）

| 时机 | 做什么 |
|---|---|
| `start()` | **先读本机**（先时间线缓存、后我自己的话），**再连流** |
| `send()` | 乐观上屏之后**先存档、再发请求**（切出去也不丢） |
| `resend()` | 态变了 ⇒ 存档跟着变（重发中仍是"可再试"） |
| `_deliver()` 每个分支 | 态落了 ⇒ 存档跟着走（`sent` 存成 `failed`） |
| `ingest()` 每帧 | 派生存档一遍 ⇒ **被认领的那条自动消失** |
| `ingest('__reset__')` | 清了存档之后**立刻按幸存的时间线重存**（见下） |
| `logout()` | **一起清**（换个人登录不许看见上一个人打了一半的话） |

⚠️ `__reset__` 那一条不显眼：`_invalidateLocal()` 会把存档一起清掉，
而 `timeline.reset()` **刻意保住**用户自己未确认的那几句（`timeline.dart`）
⇒ 复位之后必须**立刻重存一次**。不重存的话，刷新之后那几句就真没了——
那正是这一批要修的东西。手边这个坑是写测试时才发现的。

## 七、两处为了"能测"而加的口子

| 口子 | 为什么 |
|---|---|
| `start({bool openStream = true})` | 纯逻辑的闸**不该去开真 socket**（那会让"这件事对不对"变成"这台机器上网络快不快"）。⚠️ **生产路径永远是 `true`**，而且顺序永远是"先读本机、再连流" |
| `DraftStore.flush()` | 控制器里那几处 `_saveDrafts()` 是**不等**的；`await Future.delayed(0)` 只是**赌**它写完了。`flush()` = 等队列追平，生产路径不调 |

顺带记一条测试上的教训：本地 `messageId` 是"钟 + 计数"生成的
（`u_<ms>_<n>`），**测试里不许瞎猜那个 id**——要认领它就得先从时间线上把它读出来。
第一次写那两条测试就是猜了 `'u1'`，于是"认领"根本没认上，红得很隐蔽。

## 八、验收

```
$ flutter analyze                 → No issues found!
$ flutter test test/unit          → 117 passed（96 → 117，+21）
$ bash scripts/check-client.sh    → 四道闸全过
```

🔴 的几条：

1. **存档里只有本机未确认的话**——服务端事实一条都不许混进去（两边各存各的）
2. 读回来是 `failed` / `queued` 那个态（**不是凭空变成"已收到"**），而且**还能重发**
3. **被认领（`confirmed`）之后那条必须从存档里消失**（不然刷新会重复出现）
4. 有界：条数封顶、字符封顶，**整条整条地丢**
5. 一行坏了不拖垮整份存档；读不到 / 存不上都不抛
6. 命名空间：换一个就看不见对方的
7. **`logout()` 之后读不到了**（换个人登录不许看见上一个人打了一半的话）
8. 屏幕上那几句（四个态的人话 +「重发」）仍然过**禁用词扫描**
