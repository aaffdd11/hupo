# 228 · 左下角那颗「键盘」（主人 2026-10-09）

> 主人原话：*"左下角有个在办的事务的按钮，这个按钮下面放一个键盘按钮。
>   点击会打开输入框和键盘。再次点击会收起。"*
> 这一页记：**为什么原来他没有地方打字** · 那颗按钮做成什么样 · 两处不明显的坑 ·
> 在哪一端验的（判据 ＋ 真浏览器读数）。

---

## 一、为什么原来打不了字

那一格（`widgets/voice_bar.dart`）**只在三种情况下才画**（`_showField`）：

1. **正录着**（字要长出来给他看）；
2. 他按了那颗「打字」——⚠️ 而那颗**只在开不了麦的机器上才画**
   （`if (widget.canHear) _circle(t) else if (!_typing) _typeChip(t)`）；
3. 框里已经有字（语音识别回来的 / 草稿）。

⇒ **能开麦的那一台（他的手机、他的浏览器）根本没有进打字那条路的口**：
框只在录着的时候出现，而他一旦松手按停，那一句就自己发出去了。
⇒ 主人要的这颗按钮，补的正是**那个不存在的入口**。

## 二、做成什么样

| 项 | 落点 |
|---|---|
| 位置 | `chat_floater.dart` 的 `_bottomRow`：**最左那一列**，上面「清单」、下面「键盘」（中间 `voiceAuxGap` 的缝） |
| 面子 | 与「清单」「展开」「播放语音」**同一套**（`_auxFace`：白底 ＋ 一圈琥珀 ＋ 墨色图形）；**开着时整块变琥珀** |
| 图形 | 收起档 `keyboard_alt_outlined`、展开档 `keyboard_hide_outlined`（**位置不动**，同「展开」那颗的规矩） |
| 命中区 | 44×44（D3.6 硬闸量的就是这一格） |
| 无障碍 | `Semantics(button: true, toggled:)` ＋ 读屏名**跟着这一档换**（`打开键盘` / `收起键盘`）；悬停那句是 `打字` |
| 高度影响 | 两颗 44 ＋ 4 = **92**，与右边那一列（展开/播放）**一模一样高** ⇒ 底下那一行的高度不变 |

**状态只有一处**（`screens/chat_screen.dart` 的 `_keyboardOpen`）：

```
浮窗那颗按钮  ← keyboardOpen / onToggleKeyboard（它只画、只报告"被按了"）
输入条那一格  ← typingOpen   / onKeyboardWanted(bool)（它只照着画、并请求开或收）
```

⚠️ 为什么不让输入条自己存一份：两份状态一定会出现"**框还摊着、按钮却写着「打开键盘」**"。
输入条那边三个入口（那颗「打字」、说话时那张卡片"我要改"、**那一句发出去之后**）都走同一个回调
——最后那个是"要**收**"：原来这一格自己收，现在开关住上层 ⇒ 不请它收，
屏幕上就留下"框没了、按钮还亮着"（`compose_draft_test.dart` 那条判据当场就会红）。

## 三、两处不明显的坑

1. 🔴 **有草稿时"收起"收不掉。** 框画不画原来由"录着 / 摊着 / 有字"决定
   ⇒ 只要有草稿，那颗按钮就压不住它。⇒ 新增 `_collapsed`（**只由那颗按钮置位**，
   下一次摊开 / 开录 / 来了新字就清掉）；**录着那一档不受它影响**（正说着不许被藏起来）。
2. 🔴 **不能在 `didUpdateWidget` 里当场喊"收"。** 那几句跑在 build 中间
   ⇒ 请上层改状态要**排到下一帧**（`_wantedSoon`），否则就是"build 期间 setState"。

## 四、顺带改对的一句假话

这个框空着时的提示原来是 `voiceTypeInstead`（**"这台开不了麦，先打字试试。"**）——
那是在"只有开不了麦才会摆这个框"的年代写的。现在**能开麦的机器**也会摆它
⇒ 照旧用那一句就是**屏幕在说假话**。⇒ 拆成两句：能开麦 ⇒
`voiceTypeHereLead`（"打一句吧，打完按发送。"）、开不了麦 ⇒ 原来那句。
（两句都在 `test/unit/forbidden_words_test.dart` 的硬闸名单里。）

## 五、判据

- `test/widget/keyboard_button_test.dart`（**新**，5 条）：① 两个档都在「清单」**下面**、左边对齐、命中区 ≥44；
  ② 点一下 ⇒ 框出来**并且真的拿到焦点**（＝键盘弹出来）、再点 ⇒ 框没了**且焦点交回**；
  ③ **有草稿时也收得掉**、再打开草稿还在；④ 单一出处（源码级盯 `chat_screen` 那四句）；
  ⑤ 那句提示**能开麦时不许说"这台开不了麦"**（带反例）。
- `test/widget/compose_draft_test.dart`（**原有**）：发出去之后那一格**整个收起来**
  ⇒ 它守的正是第 2 节最后那条"按钮也得熄"。
- 硬闸：`bash scripts/check-client.sh` ⇒ analyze ＋ unit ＋ 全部 widget ＋ **可访问性（五档不溢出 / 命中区 ≥44）** 全过。

## 六、在哪一端验的（**别只看闸**）

1. **widget 层**：上面那两份判据（VM 上是桩：`canHear` 恒假 ⇒ 那条"能开麦"的分支只能单独喂）。
2. 🔴 **真浏览器**（V13 那条路，`scripts/check-web-browser.mjs`，令牌现发现用、不落文件）：
   - 无障碍语义树里**真的有一颗** `打开键盘`（与 `清单`／`展开`／`读出来` 并列）；
   - 在**真页面上按坐标点它**（`--click-at`，CDP 真事件，不是页面里派的合成事件）
     ⇒ 截图：**输入框长出来了（光标在里面、提示是"打一句吧，打完按发送。"）**，那颗按钮**变琥珀**；
   - 同一趟点「清单」⇒ 那张浮窗也照旧长出来（说明坐标点这一套是真有效的对照）。
3. ⚠️ **没验的（如实说）**：**手机上键盘真的弹起来**那一下 ——
   网页端没有软键盘可言（`focus()` 之后只有光标）；真机那一步要主人的手机。
