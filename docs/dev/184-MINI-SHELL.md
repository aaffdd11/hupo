> ⇒ 这一篇**留着当"当时为什么想这么做、又为什么不行"的记录**，**不是**要照着做的契约。
> 定下来的层次写在手册 **`D3.16`**：**安卓＝聊天在最上（一份实现）**；**网页＝在 iframe 上再画一遍浮层（DOM）**。
> **代码已经退回**：`src/mini-shell.js` 与 `test/mini-shell.test.js` 删了，`app-serve.js` 那三条路由删了，

> **为什么不行**（实测，不是猜）：壳在**制品那个源**（`apps.` / `127.0.0.1:8021`）上，
> 而小程序那一页的 CSP `frame-ancestors` 只认**主那个源** ⇒ 浏览器按 CSP 拒掉那一帧 ⇒ **壳里一片空白**；
> 把制品源加进名单也只是把"嵌套"这件事的代价越堆越高，换不来什么（主人已经否）。

> **主人 2026-10-05 原话**：*「你不能用 flutter 画一个画布出来承载 iframe 吗？这样他就可以在第二层了」*
> ⇒ 先回答那句：**网页上做不到**（浏览器不许把 iframe 画进 canvas，跨源内容读不出像素）；
> **手机上可以**（安卓那侧本来就有"平台视图渲成纹理"的模式）。
> ⇒ 于是给了三条路，他选 **丙：在 iframe 里再包一层我们自己的壳，按钮由那一层画**。

## 一、要变成什么样（一句话）

```
今天：  Flutter 画布 ← iframe(小程序) 在上面 ⇒ 想压在上面只能"再用网页画一遍"（两份实现）
丙：    Flutter 画布 ← iframe(我们自己的壳) ← iframe(小程序)
                         └ 那颗麦克风圆圈 / ✕ / 那行字**由壳画**（天然在小程序之上，一份实现）
```

* **好处**：① 按钮**一份实现**（不再"桌面一套、小程序里一套"）；② 永远在小程序内容之上；
  ③ 网页与手机**同一套**（手机也加载 HTML）；④ **白边一并解决** —— 壳是我们自己的页面，
  它的 CSS 由我们写（`position:fixed; inset:0` ＋ 内层 iframe 精确贴满 ⇒ 那条缝**结构上不存在**）。
* **代价**：多一层嵌套；"页面问一句"（`ask`）那条消息通道要**挪一层**（原先是 iframe↔Flutter 的
  postMessage，现在变成 壳↔Flutter，而 壳↔小程序 再一层）。

## 二、落点（动手前先读这一节）

| 在哪 | 干什么 |
|---|---|
| `apps-serve` 那一侧（第二个原点） | 新增一个**壳页面**：`/one/shell?u=<签名过的活地址>`（＋ 它的 CSS/JS 两个静态文件）。壳自己的 CSP：`default-src 'none'; frame-src <那一个原点>; style-src 'self'; script-src 'self'` —— **不给 `unsafe-inline`**（与现有纪律一致） |
| `mini_runtime_web.dart` | `iframe.src` 从"活地址"换成"壳地址"；**删掉我上一批加的那一套 DOM 叠加**（words/mic/exit 那三样），改成"往壳里 postMessage" |
| `mini_app_frame.dart` / `chat_screen.dart` | 那三个回调（`onMic` / `onExit` / 那一行字）**形状不变**，只是从"DOM 叠加"改成"壳里画" |
| 消息通道 | ① 壳→Flutter：`{kind:'hupo-chrome', what:'mic'\|'exit'}`（点击）；② Flutter→壳：`{kind:'hupo-words', text}`、`{kind:'hupo-mic-state', listening}`；③ 已有的 `ask` 通道**原样保留**（壳只做转发，**不解析**） |
| 安全 | 🔴 壳**不许**拿到任何钥匙／令牌：它收到的是**已经签好名的活地址**（短时效、绑人）；小程序那一层**照旧 `sandbox="allow-scripts"`**（**不给** allow-same-origin） |
