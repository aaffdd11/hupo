# 174 · 单轮时间上限关掉（"不设时长限制"）

> **主人 2026-10-04 原话（说了两遍）**：*「不设时长限制，不设时长限制」*
>
> **它是对着哪个读数说的**：查那个用户的流水查出 —— 375 轮里 **11 轮**被那条 180 秒的上限砍掉，
> 耗时全在 **160–179 秒**，最近的轮次几乎每轮都撞上；用户看到的是
> *「这条我卡住了，后面没说完。你可以让我接着说。」*。读数全在 [`173`](173-DSH-STUCK-ANALYSIS.md)。

## 一、改了什么

| 落在哪 | 改前 | 改后 |
|---|---|---|
| `src/dispatcher.js` 的 `TURN_DEADLINE_MS` | `180_000` | **`0`**（`0` = **不设**那一枪） |
| `src/config.js` 的默认 | `HUPO_TURN_DEADLINE_MS ?? '180000'` | `?? '0'` |
| `src/config.js` 的那条告警 | `0` ⇒ 报警说"**生产上不该这样**" | `0` ⇒ 只**如实说明**它是关着的、以及代价（不再当异常） |

`dispatcher` 里那两条 `turn-deadline` 处理 —— **全都留着**。
⇒ 判据继续按"**显式传 `turnDeadlineMs`**"的用例跑（`npm test` **1505/0**，一条没动），
要再打开就是一行 env：`HUPO_TURN_DEADLINE_MS=180000`。

## 二、关掉之后，什么还兜着 / 什么不兜了（**写在明处**）

| 情形 | 现在会怎样 |
|---|---|
| ✅ **agent 进程死了**（崩了 / 被内核 OOM 杀 / 容器重开） | `agent.on('exit')` → `forceClose('failed', …)` ⇒ **照样收口**，而且**如实说**（内核真 OOM 过时用专门那句）；排队里那几句也逐条收口 |
| ✅ **服务端自己重启** | 老规矩：重启后按盘上的账把开着的活收成"已停" |
| 🔴 **进程活着、只是卡在一个不动的循环里**（真"卡死"） | **今天没有收尾了** —— 那一轮会一直开着。这正是手册 **N19**（"挂起必有超时，且必有合法收尾"）原来靠这一枪的地方，已在手册里写明 |

> ⚠️ **这不是漏设**：是主人看过上面那份读数之后**明确要求**的。
> 代价也**不是猜的**：手册事故一那行"还有件事在处理"挂了 **68 分钟**，就是这一枪挡下来的那种事故。

## 四、还没做的（**明说，别以为顺手做了**）

1. **"轮内长等"那条没动**：那个 agent 还是会在轮内用 `job_output(wait:true, timeout_ms: 90000)`
   把时间耗在等待上 —— 现在**不会再被砍**了，但一轮要等多久仍是它自己决定的。
2. **容器 768 MB 那条没动**：9-25/9-26 那 **110 次 OOM** 是另一个根因
   （`173` §一根因 B）。今天只改了"时间"，**内存一个字没加**。
3. **被 OOM 杀掉时那句话**：代码里本来就有专门那句（`info.oom === true`），
   **没验证过它真在线上出现过** —— 只在日志里确认过 OOM 事件本身。
