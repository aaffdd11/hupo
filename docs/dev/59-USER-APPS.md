## 一、三件必须先接受的**产品后果**（不是拦你，是后果）

1. 🔴 **"用看的人自己的钥匙"＝别人写的程序能花你的钱。** ⇒ 三件一起做：**如实告知** · **配额与速率** · **随时能撤**。**不做成"悄悄花"。**
2. 🔴 **别人写的代码跑在你的机器上** ⇒ N1（独立原点）与沙箱**一条不省**；制品**永远拿不到任何密钥**。
3. ⚠️ **发现里是别人写的内容 ⇒ §4.1 的 `foreign`（只读档）**：制品发来的文本**不许进一个有工具的执行体**。

## 三、制品与存储（形状冻结）

```
每人的世界：<world>/hupo/apps/<id>/
  current.json              ← 指针 {"version":3}（**回滚＝改指针**）
  versions/<n>/manifest.json + 制品文件（**0444 · 发布后只读**）
  audit.jsonl               ← **只能追加**
共享库（乙-3）：data/published-apps/<authorHash>/<id>/versions/<n>/… + index.json
```

`manifest.json` 字段：`schema` · `id` · `version` · `title` · `icon`（白名单名）· `entry` ·
`files[{path,sha256,bytes}]` · `rootHash` · `permissions` · `minShellVersion` · `createdBy` ·
`createdTurn` · `createdAt` · `bytes`。

**限额只有一处**（`src/apps.js` 的常量）：id 32 字 · 标题 40 字 · 文件 ≤40 个 · 单文件 ≤256KB ·
整版 ≤2MB · 版本 ≤20 个 · 相对路径 ≤120 字。
⚠️ **手册纪律 1**：这些数字**不抄进文档**，只住代码。

**四条硬规矩**：版本**不可变**（同版本重发 ⇒ 拒）· 校验不过**盘上一个字节都不动** ·
读回来**每个字节都要对得上 hash** · 路径**不许越界**（`..` / 绝对 / 反斜杠 / 空段 / 控制字符全拒）。

## 三·补、乙-3 的两条形状决定（先说清，后面全靠它们）

1. 🔴 **发布 = 复制一份进共享库**（作者自己那份不动）；
   **装上 = 复制一份进他自己那一格**。
   ⇒ 两个好处：① **制品口那条路一行都不用改**（它只从"你自己那一格"读，签名/校验全是乙-1 那套）；
   ② **作者下架或删掉，装过的人那份还在**（助手会在对话里如实说这一点）。
   代价：**磁盘上有副本**（一个制品 ≤2MB，这个价换"别人撤不走你装好的东西"，值）。
2. 🔴 **id 全局唯一**（谁先发布谁占住）：重名直接拒，并说清"这个名字被别人用了"。
   理由：客户端桌面上那个图标**按 id 认人**，两个不同的人各发一个 `dice`
   会让"装上哪一个"变成一件说不清的事。
3. ⚠️ **共享库里不存作者身份**，只存 `sha256(sub)` 的前 12 位（下架时比对哈希就够）；
   对外显示的昵称也是**按哈希生成**的（`用户 4c10` 这种）—— **手机号那种东西绝不上这儿**。

## 四、第二个原点（N1 的落点）

- **本机**：壳听 `127.0.0.1:8020`，制品口听 `127.0.0.1:8021`。
  浏览器的同源判定是 `scheme+host+port` ⇒ **这已经是两个原点**（N1、沙箱、CSP、拿不到令牌**都能在本地真验**）。
- **生产**：要一个新域名（如 `apps.stalkerai.cn`）＝ DNS + 证书 + nginx + frp visitor + systemd，
  **全在 VPS 上，而那台跑着 13 个别站** ⇒ 按 P1/P2 **要主人签字**（配方：`docs/dev/03-DEPLOY-WEB.md` §三）。
  ⚠️ **这一步没做完之前，乙-1~乙-4 只能在本地验收** —— 明说，不假装。
- **入口 URL 是现签的**：`/a/<id>/<version>/<path>?u=<sub>&e=<到期>&s=<HMAC>`，
  签的是 `sub|id|version|exp`（**绑人 + 绑版本 + 短时效**）。
  ⚠️ **制品原点上没有 cookie、iframe 也带不上 Bearer** ⇒ "只有他可见"靠**签名**，不靠登录态。
- **响应头**：`Content-Security-Policy`（`default-src 'none'` · `connect-src 'none'` ·
  `frame-ancestors <壳>`）· `Cache-Control: no-store` · `nosniff` · `no-referrer` ·
  🔴 **绝不发 `X-Frame-Options`**（发了壳里就嵌不进去）。

### ⚠️ 一处与计划的偏离（记下来，别当没发生）

计划里写的是"制品服务是**独立进程**"。**这一批做成了同进程的第二个口**，理由是运维现实：
这台机器上已经有一笔账叫"服务不在 systemd 下"（#48），再加一条常驻进程就是**再加一条没人管的进程**。
对浏览器而言它**仍然是另一个原点**（N1 要的是这个），而它的路由面**小到看得完**（验签 / 读 / 带 CSP 回）。
⇒ 真要进程级隔离，等容器那一批（批 6）一起做。

## 五、沙箱（N2 的落点）

- Web：`<iframe sandbox="allow-scripts">` —— **故意不给 `allow-same-origin`**
  ⇒ 制品活在**不透明原点**里：`parent.document` / `localStorage` / cookie **全碰不到**。
- `allow=""`（摄像头/麦克风/定位一个都不给）。
- **乙-1 不给它任何回话通道**（壳不监听 message）⇒ "制品拿不到任何能力"是**结构上成立**的，
  而不是"我们记得没给它"。将来要放开（乙-4 的「问一句」）＝**新的一批 + 新判据**。
- 非 Web（原生 / 测试环境）：**说一句人话**（`appRuntimeNotHere`），**不许白屏**。

## 七·补、⚠️ 两条**实测**出来的事实（乙-1 当场踩的，下一步要靠它们）

1. 🔴 **`frame-ancestors` 必须写"真正嵌它的那个地址"**。
   第一版默认取本机壳的地址 ⇒ iframe **起来了、origin 也对、sandbox 也对**，
   可里面是浏览器那个「打不开」的图标。**修法**：把它写进这台机器的部署状态
   （`data/tenants.env` 的 `HUPO_APPS_FRAME_ANCESTORS`，**多个地址用空格列**：
   公网壳 + 本机壳）。
   ⚠️ 教训与 `53-MOTION.md` §六 同类：**"起来了"不等于"跑起来了"** —— 必须看一眼里面。

2. 🔴 **浏览器不肯在 `https` 页面里嵌一个 `http://127.0.0.1` 的 iframe**（实测：
   公网 `https://w.stalkerai.cn` 那趟，iframe 一切正常而内容是那个"打不开"图标；
   换成**本机 http 壳** `http://127.0.0.1:8020` 那趟，**骰子直接画出来了**）。
   ⇒ **本机验收走 http 壳**（`--url http://127.0.0.1:8020/`）；
   **公网验收必须等制品口也上 https** —— 那就是乙-5（VPS 上那个域名，**要主人签字**）。
   ⚠️ 这一条把"为什么乙-5 不能省"从"计划里的一句话"变成了**实测结论**。

## 七·补二、乙-2 当场踩到的两条（都是"两份东西打架"的形状）

1. 🔴 **同一份人格里两句话打架**。早先我写过一条边界："有人说『帮我做一个小程序』⇒
   **那是你做不到的事**"。乙-2 把这件事做出来之后，那句话**变成了假话** ——
   而它**还留在人格里**，于是线上真的出现了："上一轮它说做不到，下一轮它做出来了"。
   ⇒ **修法：把那条边界收窄到"改界面"**（桌面长什么样、按钮在哪儿），
   并**明写一句"早先这一节写的是一律做不到 —— 那句现在只对『改界面』成立"**。
   ⚠️ 教训：**加一条能力，要回头查一遍"有没有旧话在否认它"**。
2. 🔴 **慢闸抓到 `invalid config`**：`hupo-capabilities.yml` 里两个 `!!js process.env.…`
   在**没设那个环境变量**时求值成 `undefined` ⇒ dsh 判 `invalid config`，
   **整棵插件树加载失败**。慢闸那个脚本第③段是账本那批写的，只设了账本的变量。
   ⇒ 修了脚本（两个都设），并且在能力层判据里加了"两条 MCP 都要在、变量都要有"。
   ⚠️ 这条形状值得记：**加第二条同类插件时，所有"给第一条设环境"的地方都要跟着改**。

## 七·补三、乙-4 的岔路（**这一节是给主人拍板用的**）

主人点名要的那条是：*"使用的时候，涉及到的 apikey 是自己的，不是开发者的。"*
查过代码之后，事实是这样的 —— **"用他自己的钥匙"没有现成的路**：

| 路 | 今天的实情 |
|---|---|
| **走 agent**（它天然拿着他自己的钥匙） | ✅ 钥匙天然是对的（owner 那份在 `~/.dsh/.credentials.yaml`；租户那份在各自盒子的卷里，**agent 在盒子里读得到**）。🔴 **但今天没有"只读档"**：手册 §4.1 的"来源分级 × 能力档"那一层，在 `02-ARCHITECTURE.md` §八 里明写**本轮不建**（`policy` 模块）。⇒ 把小程序的（**别人写的**）话丢给一个**全权执行体**，正是这个项目最怕的形状。 |
| **走直连模型**（没有工具，天生安全） | 🔴 **L2 拿不到钥匙**：owner 那份是 DSH 自己的凭据格式；租户那份 0600 在盒子里。要开这条路得**新做一条"用他的钥匙"的口**（租户那条要**改容器镜像**，在盒子里加一个"只做一次补全"的入口）。 |
| **给 dsh 一个"这一轮不给工具"的模式** | ACP 有 `session/set_mode`，但 `sdk` 那份 profile **没有配任何 mode** ⇒ 要改 profile（**strict** 文件）并新定一条决策。 |

⇒ **三条都要动"本轮不建"的东西或要改容器**，所以**要主人点名走哪条**（见 `00-PROGRESS.md` §六 #55）。

### ✅ 主人 2026-09-22 定向（他的原话）

> *"a 做了小程序，并分享到发现，b 收录该小程序，实际上就是将这个小程序代码 fork 出来。
> 因为 a 和 b 都是用户，所以他们存 apikey 的方式是一样的。所以 b 在小程序里如果用到 apikey，
> 则用的就是 b 自己的。"*

**这句话说的正是本设计的地基**：
* **制品里永远没有钥匙**（乙-1 就钉着：发布时扫密钥、原点上不认令牌、iframe 不给 `allow-same-origin`）；
* **装上 = 复制一份代码**（乙-3）⇒ b 手上那份就是**他自己的**；
* 所以 b 用到的钥匙**必然是 b 的** —— **只要"花"这个动作发生在 b 自己的环境里**。

⇒ **方向定了：在 b 自己的环境里花**（这就是 β 的实质）。而**缺口只有一处**：
那个页面在沙箱里**连网都不许**（`connect-src 'none'`）⇒ 它够不着模型，
**必须由平台在 b 的环境里替他花**。

**技术上怎么落**（查证过的两条事实，让这件事比原先估的便宜）：
1. **b 的环境里已经有一个握着钥匙的东西**：租户盒子里的 `src/model-proxy.mjs`（它读卷里的 `creds.yaml`、替调用方换成真 key）；
2. 🔴 **盒子那一端是产品层代码**：`src/entry.mjs` 顶上写着"它跑在容器里"，
   而产品层是**从宿主机挂载进容器**的（`-v /srv/hupo/tenant-code/current:/app/code:ro`）
   ⇒ **加一条通道 op 不用重建镜像**（`build-tenant-code.sh` + 重载就够）。
   主人那一份在同一条思路上：他的 key 在**他自己的** `~/.dsh/.credentials.yaml`。

⚠️ 所以乙-4 的后半（记作 **乙-4b**）是：**一条通道 op（盒子里的代理替他做一次补全）+ 主人那条对应路径 +
客户端的 ask 窄通道 + 把已经做好的授予/配额接上**；判据是"切两个用户，验花的是**看的人**那一把"。
⚠️ 在那之前，这一批**只做不依赖它的那一半**（下面 §七·补四），而且
**人格里如实写着"它现在还不能问话"** —— 不许嘴上先答应。

3. **"他明说才许写"现在是软的**（工具描述 + 审计；服务端看不到"这一轮他说了什么"）⇒ 机制闸排乙-4。
