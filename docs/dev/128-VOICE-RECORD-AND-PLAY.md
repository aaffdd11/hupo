## 一、屏幕上多出来什么

设置页 →「语音」那一屏，在**钥匙那张表单下面、「试一下」上面**多一块：

```
──────────
录一段
按一下开始录，再按一下停；录完在下面听一遍。这段只留在你这台设备上，不发给任何人。
[        开始录        ]      ← 一颗通栏大按钮（正在录时它自己就是「停下」）
[        听一遍        ]      ← 只有"手里真有一段"时才画（正在放时是「别放了」）
        刚才那段：3.4 秒      ← 同上，只有真有东西时才说
       （失败/空录时，这儿是一句实话）
```

🔴 **排在「试一下」前面**（`screens/settings_screen.dart` 的 `_credBlocks`）：
"**先能成功把录音录下来**"（主人 2026-09-27 前半句就是这个）比"把音频送到识别路上"
更基础 —— 上面那块**不依赖任何钥匙、任何上游、任何网络**。

⚠️ 只在**接了线**（`voiceRecord != null`）时才画 —— **不给假按钮**（同 `123` 那条）。

## 二、🔴 它和旁边那块「试一下」的分工

| | 「录一段」（这一块） | 「试一下」（`123-VOICE-TEST-BUTTON.md`） |
|---|---|---|
| 验的是 | **这台设备的麦克风本身** | **整条识别路**（钥匙 ＋ 上游 ＋ 那台机器接上） |
| 要钥匙吗 | **不要** | 要（服务端按身份现取） |
| 音频去哪 | 🔴 **哪儿都不去**：本机临时地址，本机放 | 送到 `/api/asr` |
| 没有麦克风权限时 | 说一句白话（`hearDenied`） | 同左（**同一句**） |

⇒ 两块的按钮**长得像但不是一件事**，所以他一眼能分清的那句话必须写在屏幕上：
**`voiceRecHint` 里那句"这段只留在你这台设备上，不发给任何人"**。
（`AGENTS.md` §六 第 4 条：屏幕上不许出现内部词 —— 这里用的是"这台设备 / 不发给任何人"。）

## 三、那一段去哪了（一个字节都不往外发）

```
按「开始录」 → getUserMedia({audio}) → MediaRecorder.start()
按「停下」   → 关麦（track.stop()）→ MediaRecorder.stop()
             → 那几块拼成一个 Blob → URL.createObjectURL(blob)  ← 🔴 本机地址（blob:）
按下「听一遍」→ new Audio(url).play()                          ← 🔴 本机放，不经过网络
```

| 事 | 落在哪 |
|---|---|
| 采集 ＋ 拼装 ＋ 放音 | `v2/apps/mobile/lib/services/recorder_web.dart`（网页那一份） |
| 别的平台 | `recorder_stub.dart`：**`canRecord` 恒假**，如实说"这里录不了" |
| 对外那几个名字 | `services/recorder.dart`（条件导出，**零新依赖**，同 `hearing` / `speech` / `links`） |
| 状态与那几行字（纯的） | `models/voice_record.dart` ＋ `models/hearing_words.dart` |
| 画出来 | `widgets/voice_record.dart` |

⚠️ **本机地址是会漏的**：新录一段之前先 `revokeObjectURL` 放掉上一段；
**离开这一屏**时界面只停声音、收麦（`dispose`），**不释放那一条地址** ——
一次设置页访问最多漏一条（几十 KB）。**明说没做**，没藏（见 §六）。

⚠️ **`MediaRecorder` 与 `AudioContext` 一样，这个 SDK 的 `dart:html` 里没有** ⇒
采那条走 `getUserMedia`（`dart:html` 有）、`MediaRecorder` 走 `dart:js_util`
（同一个理由见 `hearing_web.dart` 抬头）。

## 四、失败各说什么话（**一个原因一句话，且与话筒那几句共用**）

| 机器原因 | 谁给 | 屏幕上那句话 |
|---|---|---|
| 没权限 | `getUserMedia` 抛（`NotAllowed`/`Permission`/`Denied`） | `hearDenied` |
| 这里没那套东西 | `mediaDevices` 没有 / 没有 `MediaRecorder` | `hearCantHere` |
| 开不起来（别的错） | `MediaRecorder` 建不出来 / `start()` 抛 | `hearFailed` |
| **录下来是空的**（零字节 / 零毫秒） | `recordStop()` 回 `null` | `voiceRecEmpty`：*这一段里什么都没有 —— 再录一次试试。* |

🔴 三条不许破：

1. **绝不静默**：开不起来 ⇒ **当场收场 ＋ 说一句**（绝不假装还在录）。
2. **绝不给不存在的按钮**：手里没东西 ⇒ **不画**「听一遍」。
3. **同一个原因不许两种说法**：没权限/开不了麦那几句**直接复用话筒那套词**
   （`forbidden_words_test.dart` 钉着它们都在词表里）。

⚠️ **`canRecord == false` 时照样画那颗按钮**，点下去说一句白话 ——
**藏起来等于让他自己猜**（同话筒那条，主人 2026-09-23 当场问过）。

⚠️ **正在放的时候按「开始录」** ⇒ 先把放音停掉再开录（不叠在一起、也没有按不动的键）。

## 五·补一、🔴 顺手改掉的一处**闸自己的错**（同一次撞上的）

`accessibility_test.dart` 那道命中区硬闸原来是量**语义矩形**（`getSemantics(w).rect`）。
加这一块时它红了，报 `Size(552.0, 42.0)` —— 而那颗按钮的**盒子是 62 高**。

当场量了三遍，**同一棵树、同一颗按钮**读出三种值：`62` / `42` / **`-459`**
（负的高度连矩形都不是）；换个顺序量，红的又是**另一颗**按钮。
⇒ 那不是被测代码的毛病，是**判据自己的读数会随滚动位置变**
（语义矩形的几何要按祖先视口的语义裁剪在变换后的坐标里再切一次 ——
切错了框架也不报错）。文件里原来就写着"读数会变的闸下一步就是被绕过"。

**改成量 `RenderBox.size`**（`tester.getSize`）—— 那正是 `hitTest` 用的命中区，
`_RenderInputPadding` 已经把 `Material` 之外那一圈算进去了（那本来就是 Flutter 给的命中区）。
⚠️ **不放宽**：语义矩形只可能比盒子**小**（裁过）⇒ 读数从"裁过的"换成"真的"，
只可能把**假的红**量绿，不会反过来。改完 369 条一次全绿（原来基线也是 369 条）。

## 五·补二、线上读数（2026-09-27 部署后当场做的 · **假麦克风**）

```
入口指纹 671fc0f1fff0 ｜ 客户端源码指纹 dea1819bb43e ｜ 核心横幅「完整性 对上了」
Chrome：--use-fake-device-for-media-stream --use-fake-ui-for-media-stream（假设备 ＋ 自动给权限）
真页面上**点语义节点**（不是坐标）按顺序读出来的：
  ⑥ 点「开始录」 ⇒ ⑦ 那一行当场变成「停下」          ← 麦克风真的开起来了（不是装的样子）
  ⑧ 点「停下」   ⇒ ⑨ 出现「听一遍」**而且**出现「刚才那段：3.4 秒」 ← 真拿到了一段（不是空的）
  ⑪ 点「听一遍」 ⇒ 【修之前】整整 7 秒一直写着「别放了」（见下面那张"修之前"）
                 ⇒ 【修之后】回到「听一遍」，而且**页面一条错都不报**
```

真图：[`128-raw/voice-record-live.png`](128-raw/voice-record-live.png)
—— 那一屏上「录一段」／那句"不发给任何人"／「开始录」／「听一遍」／「刚才那段：3.4 秒」都在。
修之前那一眼：[`128-raw/voice-record-live-before-fix.png`](128-raw/voice-record-live-before-fix.png)
—— 同一个位置写着「别放了」（其实是**没有声音**的）。

🔴 **就是这一趟当场看出一个真毛病（已修）**：`Audio.play()` 返回的是一个 **Promise**，
而"自动播放被拦"是**它 reject** —— 那条路上 `onError` **根本不响** ⇒ 按钮会**一直停在
「别放了」**上（没有声音、屏幕上却说正在放：页面在说假话）。**修**：把那个 Promise 接住
（`recorder_web.dart` 的 `play()` 那段），接住就按"放完了"收场。

⚠️ **只有这一条路看得见它**：单元与界面判据注的是**假的**开麦/放音，**碰不到真的 `play()`** ——
这就是"客户端自己算/自己调的东西，闸要打在这一侧"那一族的又一个实例。

⚠️ **还是没验到的**：**真麦克风**（对着麦说话、耳机里听见自己的声音）——
假设备只有一个蜂鸣音；真机上的**自动播放策略**也只有在真实手势下才有意义
（上面走的是合成点击）。

## 六、如实说（没验到的）

| # | 事 |
|---|---|
| 1 | **真麦克风没验到**（**网页这一侧**）：判据里注进去的是假的开麦/收手；线上那趟用的也是 **Chrome 的假设备**（§五·补二）⇒ "插上耳机/对着麦说话能录到声音"这件事**只有在主人的手机上按一下才算数**。⚠️ 但**网页那条路本身（开麦 → 录 → 拼 → 本机放）已经在真页面上走通了**。★ **原生那一份 2026-09-28 做出来并由主人在真机上验到了**（*「很好，安卓可以录音了。」*）—— 见 [`129`](129-NATIVE-ANDROID-BUILD.md) §十二 |
| 2 | **非网页那一份（`recorder_stub.dart`）只有单元级的形状**：`canRecord` 恒假、`recordStart` 回 `unsupported`；**真机上"点了会说那句话"没验**（手机壳那一条本来就没做，P1-23） |
| 3 | **本机地址会漏一条**（见 §二 那条 ⚠️）：离开设置页时**不** `revokeObjectURL`。要修就得让界面把"走开"这件事也交给服务层（多一个注入的动作），**这一次没做** |
| 4 | **录下来的东西不落盘、不能带走**：刷新页面就没了（它是 `blob:`）。主人说的是"录音和播放"，**没有说"存起来/发出去"** —— 要那个是另一件（也是另一条安全线），**没做** |
| 5 | **时长是"从按下到按下"**（墙上时间），不是音频流的真实长度 —— 麦克风被占着那种"零字节"的情况由"空录"那一档兜住，但**中间有停顿的那段会更长**，这一版不校正 |

**明确没做**：把录音发出去（任何形式）· 存到盒子里 · 波形/进度条 · 录音时锁住别的按钮 ·
`releaseAll`（服务层留了这个名字，**界面没接**）· 手机壳上的原生录音（P1-23）。
