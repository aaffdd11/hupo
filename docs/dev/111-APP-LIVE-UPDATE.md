# 111 · 制品换了一版 ⇒ 正开着它的那个界面自己换上

> **主人 2026-09-26 原话**：
> *"小程序那边，我希望是一种前后端完全同步的模式，也就是说后端增加内容前端显示是一一匹配的。不需要刷新。"*
>
> **这一篇只做"制品版本"这一半**（"后端数据实时取"那一半是**另一批**：
> 手册 §2.2 里那一帧 `app/workspace-changed` —— "他自己改的那一份内容变了"，
> 走**瞬态**、只推给正开着那一间的那条连接）。

---

## 一、这是什么（一句话）

**一小程序（制品）真的换了一版之后，正开着它的那一屏自己换成新的一版 —— 不用他刷新、不用他关掉重开。**

改之前：打开一个小程序用的是**当时那一条签名 URL** ⇒ 助手改了它（发新版 / 装上一版），
屏幕上还是旧的，**只有刷新或重开才看得见**。

---

## 二、形状：`app/update-available`

服务端落在**那条可见日志**上的一条**持久**事件（`src/app-events.js` · **只加不改**）：

```
{ "type": "app/update-available", "id": "<app id>", "version": <新版本号>, "at": <毫秒> }
```

加上日志本来就会盖的那几样（`seq`、以及 `scopeId`）：

| 字段 | 谁盖的 | 为什么 |
|---|---|---|
| `type` · `id` · `version` · `at` | `appUpdateAvailableEvent()` | **只有这一处**出这个形状（两半共用同一份读法：`appUpdateOf()`）|
| `seq` | `Timeline.emit` | **持久事件**（落盘、有号）⇒ 重连/切回那一间**补得上** |
| `scopeId` = **那个 app 的 id** | `ScopeView.emit`（`worlds.js`）| 实时那一路按**焦点**筛（`server.js` 的 `eventInScope(event, focus)`）⇒ **只有正开着这一间的那条连接**实时收得到（打开一个小程序 = 房间切到它的 id）|

### 2.1 为什么是持久事件（而不是瞬态）

`app/installed`（装上了一个）是**瞬态**：它是"现在这一刻发生的事"，不占号、不落盘、重连不重放。
而"**有一版新的**"是**盘上的事实** —— 他离线那会儿发的那一版，回来（重连/切回这一间）**还得知道**。
⇒ 这一条走 `emit`（取号 + 落盘 + 推），补发那条路自然会把它带回来。

⚠️ **号一个都不许重编**：取号只走那把 `Timeline` 的 `#nextSeq`（`timeline.js` 顶上那条规矩），
这一条没有另开计数器。

### 2.2 为什么**不在**那两处放签名 URL

`entryUrl` 是**短时效**的（绑人 + 绑版本 + 现签），而这条帧要**落盘**、而且那条日志
**同一个人的每条连接都读得到**（多作用域只是同一份日志上的标签）。

⇒ 把签名写进去就是**写一句迟早变假的话**（十分钟后那条 URL 就过期了），
而且把"短时效的东西"塞进了一份长期留档里。

⇒ 这一帧只给 `id` + `version`，客户端**自己去 `/api/apps` 现取**（那里会给**新那一版**新签的 `entryUrl`）。
判据 **U1d** 逐字扫这一帧的原文（`entryUrl` / `sig` / `s=` / `/a/<id>/` 一个都不许出现）。

### 2.3 为什么**不走**通知那条路

`Notice`（`notice.js`）那条通道是"**替你做的决定 / 出事了 / 你不在时发生的事**"——
它落地是**一句要人看的话**（浮窗里弹一下、时间线上留一条）。

而这一帧**一句话都没有要说**：它只是"界面，你手里那一版旧了"这个同步信号。
走通知 = 每次发新版都在他眼前弹一条"有个小程序更新了"（那是**通知疲劳**，而且信息量为零）。

⚠️ 反过来，"**没做成**"那一件事**必须**走通知 —— 见 §六。

## 三、客户端：只换那一帧

### 3.1 `AppUpdate.of(event)`（`models/mini_update.dart`）

认帧只认这一处：`type` 对上 + `id` 非空 + `version` 是 ≥1 的整数；
**认不出来安静忽略**（协议只加不改：旧客户端收到认不出的类型本来就不理）。

### 3.2 `ChatController.ingest`：**举手，但不 `return`**

```dart
final update = AppUpdate.of(event);
if (update != null && appUpdates[update.id] != update.version) {
  appUpdates[update.id] = update.version;
  lastAppUpdate = update;
  appUpdateRevision += 1;   // 界面靠它认"是不是新的一条"
}
```

🔴 **不许在这里 `return`**（`app/installed` 那条是 `return` 的，这一条**不一样**）：
它是**持久**事件 ⇒ 必须继续走到 `timeline.apply`，否则客户端的游标停在这一号上，
**每次重连都从这一号重放一遍**。（它本身画不出任何东西：`models/timeline.dart` 对认不出的类型安静忽略。）

⚠️ 去重按 **`(id, 版本)`**：补发那条路必然重复送（协议 R5）。

### 3.3 `ChatScreen._onAppUpdate`：三种情形

| 收到的是谁 | 做什么 |
|---|---|
| **正开着的就是它** | **现取一次清单**（`Api.appsOrNull()` → 新那一版的 `entryUrl`）⇒ `MiniAppFrame` 换一帧 ⇒ **iframe 换掉** |
| **别的 app** | **一个像素都不动**（连接口都不多打一次）—— 只记一笔"它有新版" |
| **没开着**（在桌面上/在别的小程序里） | 只记一笔（`_staleMine`）；**下次点开它之前先重拉一次清单**，免得点开还是旧那一版 |

⚠️ **版本号是唯一的判据**（不是 URL）：服务端**每次调用都现签**一条新 URL ⇒
"同一版"重签出来的 URL 也不一样 ⇒ 只看 URL 的话，收到任何一条更新提醒都会白换一帧。
⇒ 已经在这一版上（`update.version <= mine.version`）就**什么都不做**（判据 **U3** 的对照那一半）。

**旧那一帧要收干净**（判据 **U5** · `widgets/mini_app_frame.dart`）：

* `miniViewLedger.unhost(旧的)` —— 挂载那本账里销号（不销的话，**老那条全局监听还会替新页面
  把"问一句"再送一次** ⇒ 多花一次他的额度）；
* `releaseMiniAppView(旧的)` —— Web 那一侧真去**退订**那条 `onMessage` 监听；
* ⚠️ **`registered` 那本账不许销**：`ui_web.platformViewRegistry.registerViewFactory`
  **同一个 viewType 只许注册一次**，销了号再注册会**当场抛**。

### 3.4 `MiniAppFrame`：一帧 = 一条 `entryUrl`

`viewId = miniViewIdOf(entryUrl)`（**只有这一处算法**，`models/mini_frame.dart`）。
URL 变了 ⇒ `viewId` 变了 ⇒ `HtmlElementView(viewType:)` 换了 ⇒ **iframe 是新的一个**。
`MiniAppHost`（外壳、顶栏、扩开/收回动画）**一个字都没动** —— 换的只是它里面那个孩子，
所以**聊天浮窗和桌面不受影响**（判据 U2 里那一屏照旧）。

## 四、服务端：那一刀挂在哪儿

**挂在 `Apps.create()` 这个唯一漏斗上**（`src/apps.js` 的 `onVersion` 回调），
而不是挂在某一个工具调用点上。

理由：`create()` 是**所有写路**都经过的那一个地方 —— 工具那条新路（`snapshotWorkspace`）、
老路、**从共享库"装上"**（`published.installInto`）、复制（`apps.copy` 各版本）、
`/api/app-copy` 的那条路，**条条都落到它**。
挂在漏斗上 ⇒ "**以后又加了一条写路却没喊**"在结构上不可能；挂在某一个调用点上 ⇒ 下一条写路必漏。

三处顺序是刻意的：

| 顺序 | 为什么 |
|---|---|
| **真的写完之后**（文件、`manifest.json`、`current.json` 指针都成了） | 早一步喊，客户端去 `/api/apps` 可能拿到**上一版** ⇒ 屏幕上什么都不会换（那就成了一句假话） |
| **第一版不喊**（`version === 1`） | 那不是"更新"，而且那一刻**还没有任何界面开着它**（新造出来的东西走 `app/installed` 那条） |
| **喊不出去不许让"写成了"这件事失败**（`try/catch`） | 盘上已经有这一版了 ⇒ 这时候回报一个失败，就是让工具说假话 |

`worlds.js` 那一段只做两件事：**盖上房间标签**（`#viewFor(userId, appId).emit`）、
**把帧放进那条日志**。它不是安全边界（跨人的隔离靠容器，同 `worlds.js` 顶上那段）。

## 五、真机读数（不刷新就换上）

**做法**：本机另起一个核心实例（临时数据目录 / 另两个端口 / **不碰线上那个单元、不碰 u2**），
用**真令牌**（`Auth.issue()` 现发，**不写进任何文件**）开真浏览器（`scripts/check-web-browser.mjs`），
**走既有 MCP 工具**（`mcp-apps-server.mjs` 的 `app_install`）发新版。

⚠️ 如实说清两件事：① **最初那一版是夹具**（用服务端自己的 `Apps` / `Published` 两个类写下去的，
判据里也是这么摆的）—— 被验的那一刀是**"更新"**，它走的是真 MCP 工具；
② 这一趟起的是**宿主那一侧**的实例（主人那份），**租户（盒里）那一侧没跑**：
租户的 `/api/stream` 与制品库都在他盒子里（`server.js` 把升级原样转进去），
盒里跑的是**同一份代码**、同一套接线 —— 但"盒里那一趟"确实没有读数。

### 5.1 那一帧（盘上原话）

```
{"type": "app/update-available", "id": "dice", "version": 2, "at": 1790399496473, "scopeId": "dice", "seq": 1}
```

* 那一帧**不属于主线**（主线视图里读到的是 **0** 条）⇒ 它只属于 `dice` 那一间；
* 帧里**没有** `entryUrl` / `s=` 那类签名（逐字扫过）。

### 5.2 界面：**没刷新，自己换上了**

同一个浏览器会话里，两次读到的 iframe 地址（`timeOrigin` 两次**完全相同** ⇒ 页面**没有重新加载**）：

| 时刻 | 那个 iframe 的 `src` |
|---|---|
| 打开之后（改之前） | `http://127.0.0.1:8124/a/dice/**1**/index.html?u=owner&e=…&s=9853…` |
| 发新版之后（等 **38.8 秒**） | `http://127.0.0.1:8124/a/dice/**2**/index.html?u=owner&e=…&s=fa02…` |

浏览器那条路的自动断言里，客户端**认出的事件类型**逐字包括
`client/hello / client/focus / client/ping / **app/update-available**`；
WebSocket **1 条、断过 0 次**。

截图：改之前是**第一版**（绿底），发新版之后同一屏变成**第二版**（红底）——
容器顶栏还是「掷骰子」、底下的聊天浮窗照旧（没有被搞乱）。

### 5.3 "没做成"那一句（真机原话，见 §六）

MCP 工具那侧回的是（给模型看的）：

```
没装成：单个文件太大：index.html
```

而**他屏幕上**出现的是（从那一次真机读数的截图与语义树里读到的原话）：

```
「掷骰子」这一版没能存下：里头有一份东西太大了。拆小一点，我再来一次。   [知道了]
```

落盘那一行：

```
{"type":"notice","kind":"failed","text":"「掷骰子」这一版没能存下：里头有一份东西太大了。拆小一点，我再来一次。","seq":2}
```

⚠️ 同一句话连发两次只落了**一条** —— 通知那本限频账（同一句话几小时内只说一次）照旧生效。

## 六、顺带修的一件真事：**没做成必须有一条人话**

**主人 2026-09-26 报的现场**：奥数小站"扩充题库，小程序里没显示新题"。
查下去**不是刷新问题**：

* `/api/apps` 里 `aoshu-bank` **只有 v1** ⇒ **根本没有新版发出来**；
* 那一间里助手最后一句原话是
  **「压到 200KB、再转成文本就 266KB，超了单页 256KB 的上限。我试几种压法。」**
  ⇒ 它撞的是我们的**单文件上限**，而且它是**自找的**（压完再转 base64 文本会涨 33%，不压反而放得下）；
* 而那之后**没有然后了** —— 主人那边**一点提示都没有**。

⇒ 这一批顺手补上：**小程序那几条工具没做成 / 被拒（任何原因）⇒ 他那边要有一条看得见的话**。

| 件 | 怎么落 |
|---|---|
| 挂在哪儿 | `handleAppsOp()` **那个唯一入口**上（`apps-socket.js`：动作本体挪进 `runAppsOp()`，外面留一层壳）⇒ 任何调用方都漏不掉 |
| 说什么 | `src/app-fail-words.js`：**分类 → 一句固定的话 + 那个小程序的名字** |
| 走哪条路 | 现成那条通知通道（`Notice` · `kind` 用既有的 `failed`）—— 与"文件落错地方"那一句（`#tellMainLeak`）**同一条路** |
| 🔴 不许端原文 | 工具那句 `error` 是**写给模型看的**（里头有内部短名、还有"工作区"这种**禁用词**）⇒ **一个字都不许原样上屏**（`AGENTS.md` §六.4） |
| 🔴 两档**不喊** | `needs-ask`（他本人没说要做 ⇒ 助手该回头问一句）· `needs-choice`（刷新还是分叉 ⇒ 等他拿主意）：**这两件不是失败，是"要问他一句"**，喊一条"没做成"就是假话 |

判据把这两向都钉住了：**没做成 ⇒ 有那条人话**（点名 ＋ 不含内部词）、
**那两档 ⇒ 一个字都不喊**、**成了 ⇒ 也不喊**（不许"狼来了"）。

## 八、明确不做的

* **不做"数据实时取"那一半**（"后端数据增加、前端一一匹配"的另一半）：这一篇只管**制品版本**。
* **不让服务端把新 `entryUrl` 推给他**：签名**不落盘、不进日志**（§2.2）。
* **不新开 HTTP 路由、不新开日志、不新开号**：只在那条可见日志上**加一个可选事件**。
* **不通知**（不弹浮窗、不留一句要人看的话）：这一帧没有话要说（§2.3）。
* **不动 `MiniAppHost` 的外壳**（顶栏 / 扩开收回 / 被聊天盖住那几条规矩一个字没动）。
* **不改已经冻结的那几条**（`app/installed` 的瞬态语义、`/api/apps` 的形状、`entryUrl` 的签法）。
