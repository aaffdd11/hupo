## 一、这个缺陷长什么样

旧的那一屏只住在内存里（`Timeline._items`）。于是**刷新一次 = 全白**：

```
打开 → 空屏（什么都不显示）→ 连上 → 服务端把全部历史补发一遍 → 有字了
        ↑ 8/10 的放弃点就在这一段空白里（而且它骗人：看着像"什么都没发生过"）
```

⚠️ 它不只是"慢"：一个不会拼音的用户刷新之后看到**一片空白**，
第一反应是"我把它弄坏了"——而这正是手册 H1 最在意的那类失败。

## 二、做法：**只缓存，不判断**

`TimelineStore` 把**服务端说过的事实**原样存下来，下次开机原样喂回 `Timeline`：

```
收进来 ──► `_facts`（只有带号的）──► 攒 1.2 秒 ──► 本机
                                                    │
开机 ──► 读回来 ──► `Timeline.seedFromCache()` ─────┘
```

```dart
Uri … // 不在这里 —— 这里只做一件事：存和取
static bool isPersistable(Map<String, dynamic> e) => e['seq'] is int;
```

三处刻意的克制：

| 克制 | 为什么 |
|---|---|
| **只存带 `seq` 的** | 决策 P-g 里"瞬态不占号"本来就意味着**号 = 这是落盘的事实**。⇒ 不需要另立名单 |
| **不解释、不合并、不挑** | 存的是事件，不是"缓存版的状态"。画的时候走**同一条渲染路径** ⇒ 不可能出现"缓存版和实时版长得不一样"（有一条测试专钉这个） |
| **整条整条地丢** | 满了从**最前面**丢。截半条 JSON = 解不开 = 可能画出半句话，**那是编造** |

## 三、⚠️ 差点写出来的一句假话

缓存里最后一个事件很可能是一条 `message/start`（那一轮还没收口）。
照 `Timeline` 里那条**给断线重连用的**兜底（`_hasOpenAssistant`），
屏幕会立刻出现：

```
它正在做…
```

**可那一轮很可能是上次关机时断的**——我们根本不知道它还活着没有。

⇒ 加了 `_stale`：**从缓存画出来的那一屏，在服务端开口之前一个字都不许说。**

| 什么时候 | 屏幕上 |
|---|---|
| 刚用缓存画完、还没连上 | 只有字，**没有**"它正在做" |
| 服务端来了**任意一条**真帧（`markFresh()`） | 该说"它正在做"才说 |
| 那一轮真被服务端收口了 | 收口事件会**接着补发上来**，自己就撤了 |

这一条和既有的 `_agentDead` 是同一类东西（都是"知道了就别装不知道"），
所以放在同一个地方、同一组成员里钉住。

## 四、四个必须做对、但不显眼的地方

| # | 事 | 不做会怎样 |
|---|---|---|
| 1 | **先读缓存、再连流** | `sinceSeq` 要从缓存里那个号接着要，否则每次开机都把全部历史重放一遍 |
| 2 | **服务端说"你这号不对了"（`client/reset`）⇒ 缓存一起清** | 不清的话下次开机又把那个**已经不存在的世界**先画出来，然后再被打脸 |
| 3 | **在飞的那次 `save()` 也要作废**（`_saveGen`） | 光 `cancel` 定时器不够：已经发出去的那次写会晚一步落地，把刚判死的缓存写回去 |
| 4 | **坏了就当没有** | 一行解不开 ⇒ 跳过它；整个读不出来 ⇒ 空屏。**缓存坏掉的后果必须小到"就是空屏"**，绝不能让聊天不能用 |

## 五、命名空间（**手册点名要求的**）

手册 `03-DEVELOPMENT.md` 写着：必须带 **`scopeId + userId`** 命名空间。

⚠️ **今天只能填一半**：客户端里既没有 `scopeId`（单作用域），
也**不解析令牌里的用户名**（那就等于把令牌当数据源，没必要）。
⇒ 现在：

* key = `hupo_timeline_v1.<namespace>`，`namespace` 是**参数**（形状对了）；
* 真正兜住"换个人就串"的是：**退出登录时清缓存** + `client/reset` 时清缓存；
* **多人那一批必须把 `userId` 那一半补上**（记在 §六）。

> 为什么不用令牌的哈希当命名空间：Dart 的 `String.hashCode`
> **跨版本不保证稳定**，而拿它当 key 会静默失效；真要做就得引一个 sha256 依赖。
> 现在用"清"来保证不串，**比用一个不稳的 key 更可靠**。

🔴 的几条：

1. **没号的东西一条都不许进缓存**（瞬态不是事实）
2. **字符封顶：整条整条地丢**（每一行都还得是完整的一条 JSON）
3. **条数封顶：留最后那些，不是最前面那些**
4. **命名空间：换一个就看不见对方的**
5. **缓存先画出一屏：字在，但不许说"它正在做"**
6. **服务端一开口，"它正在做"才是真的**

## 七、这一批**没做**的（明说）

| # | 没做什么 | 为什么 |
|---|---|---|
| 1 | **用户自己打了、但还没发出去的那句话不进缓存** | 它没有号（不是服务端事实）。而"重发"要有 `messageId` 和一句话的正文——那是另一件事（要给它一个本机命名空间）：**这一批没做，记在这里**。⇒ 刷新会把"没发出去"那条弄丢 |
