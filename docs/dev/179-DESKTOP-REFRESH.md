# 179 · 桌面自己会刷新（"app 做好了没有刷新"那件事）

> **主人 2026-10-04 原话**：
> *「桌面并没有自动刷新。就是app做好了没有刷新。我们要有刷新机制。」*
>
> ⇒ 定案写进手册 `05-DECISIONS.md` 的 **`D4.29`**（升 **v2.44**）。

---

## 一、查出来的到底是什么（两条，都在**服务端**）

### ① 助手"直接把文件写完"这条路，桌面**从来收不到信号**（这是主因）

助手部署一个小程序最常见的做法是**在那一间的目录里直接写文件**
（`docs/dev/112`：cwd 就是那一间，"写进去就是部署"）。这条路：

| 会响 | 不会响 |
|---|---|
| `app/workspace-changed`（工作区 watcher 看见文件变了） | 🔴 `app/installed`（**桌面**那一格要的那一声） |

而 `app/workspace-changed` 是**按焦点路由**的 —— 只有"**正开着这一间**"的那条连接收得到
（`docs/dev/112` §四，判据 V5 钉的正是这条）。⇒ 站在**桌面**前的人（他没开着那一间）
**一个字节都收不到**：那一格还是灰的（"在建"），只能手动刷新页面。

⚠️ 对照着看就清楚了：`app/installed` 只有**两条**来路 ——
`AppWorkspaces.write()`（服务端那一刀替模型写文件的场景）与 `app_create` 那一下。
**直接写盘这条路一条都不占** ⇒ 那条信号对"助手自己动手写"这种最常见的形状是**哑的**。

### ② 活收口那一条**说不出是哪一间**（上一批 `#275` 带出来的毛病）

`work/open` 一直带 `scopeId`，而 `work/close` **没带** ⇒ "某一间的活收口了"这句话
在服务端那一层**丢掉了归属**，接信号的那一端（`worlds.js` 的 `onChange`）要求必须有 `scopeId`
⇒ 直接跳过。症状：桌面上那个"在做"的角标**亮起来就再也灭不掉**。
（是这一批的判据 W4 抓到的：开票收得到、收口收不到。）

## 二、刷新机制 = 三半（缺一半那种"机制"就还是漏的）

| # | 在哪 | 什么时候 | 干什么 |
|---|---|---|---|
| ① | **服务端** | 那间工作区的内容**直接变了**、而且它**不再是"在建"** | 往他的流里推一条 `app/installed`（＝"桌面可能变了"） |
| ② | **客户端** | 他从某一间小程序**退回桌面**（点 home） | 重拉一次 `/api/apps` |
| ③ | **客户端** | 这一屏**从后台切回来**（手机 / 浏览器标签） | 重拉一次 `/api/apps` |

🔴 **为什么服务端那一条不够**：瞬态事件**不补发**（`emitTransient`：不占号、不落盘）
—— 他**没在看**的那段时间发生的事，他回来时一条都收不到。⇒ ②③ 就是**为他补那一课**。
🔴 **为什么光有 ②③ 也不够**：他**正看着桌面**的时候（浮窗是收起的、桌面就在眼前），
没有任何"回来"这个动作 ⇒ 只能靠 ① 那条实时信号。

### ① 的落点（**唯一一处**）

`src/worlds.js` 的 `emitLiveChange(userId, scope)` —— 它正是 watcher 那一声的唯一出口
（`serve.js` 的 `startLiveWatchers` 与 `onWorkspaceChanged` 都打它）。在原来那一帧之后加：

```js
if (w.apps?.has?.(id) && w.workspaces?.isBuilding?.(id) === false) {
  w.timeline.emitTransient({ type: 'app/installed', appId: id, title: … });
}
```

* **为什么加"不是在建"这一条**：一次文件写入**能改变的桌面事实只有一个** ——
  `building`（入口那一份从占位变成真内容）。还在建 ⇒ 桌面上那一格没变 ⇒ **一个字都不喊**
  （对租户来说，一次多余的清单重拉就是**多开一趟隧道**）。
* **为什么不会成灾**：文件事件在 watcher 那一层已经**按间合成**（`debounceMs`）——
  一次"写一堆文件"最多喊一声。
* ⚠️ **如实说**：`AppWorkspaces.write()` 那条路会**响两声**（它自己那一声 ＋ watcher 那一声）。
  两声之间隔着一个 debounce，客户端就是多拉一次清单（很小）；**不为此再加一层去重**
  （去重自身要记状态，而这里没有任何正确性问题）。
* ⚠️ 已经做完的小程序**再被改一次**也会喊一声（条件只问"不是在建"）—— 这是**故意的**：
  那一句的语义就是"**桌面可能变了**"，而它确实可能变了（名字 / 入口 / 权限都在清单里）。

### ②③ 的落点

`v2/apps/mobile/lib/screens/chat_screen.dart`：

* `_closeApp()`（home 那颗按钮）末尾：`unawaited(_loadMyApps())`；
* 那个 State 现在 `with WidgetsBindingObserver`，`didChangeAppLifecycleState` 里
  **`resumed` ⇒ `_loadMyApps()`**（`initState` 注册、`dispose` 摘掉）。

## 四、如实说

* ⚠️ **租户那一边靠盒子**：watcher 是在**盒子**里跑的（工作区在他盒子里），
  所以 ① 那条信号由**盒子**直接推给（经宿主转进去的）他那条连接。
  ⇒ **产品层必须重发**，否则他那一台仍然是老样子。
* ⚠️ **上一批那两条事实一个字没改**：`building` / `working` 仍然是**算出来的**、**不落盘**；
  这一批只是把"它们什么时候可能变"这件事**补全**（多了一条来路 ＋ 两个"回来看"的时机）。
* ⚠️ **仍然可能有"没收到信号"的时刻**（网络瞬断、进程重启、补发不覆盖瞬态）——
  但那三个时机（信号 / 退回桌面 / 切回来）已经覆盖了所有"**他眼睛看着桌面**"的情形；
  真要说剩下的：他**一直盯着桌面、而信号恰好丢了**（断线那一下），那种情况**他能看见断线**
  （顶上那条"网没通"），也就知道该刷新。
* ⚠️ **这一批没做**：桌面**定时轮询**。不做，是因为它买不到上面那三种情形之外的正确性，
  却对租户是**持续的隧道流量**（每次都要过一趟盒子）。要真需要，那时再谈（现在没有证据）。
