## 一、为什么要做（这一条不做的代价）

做小程序的 agent **看不见浏览器**（`app-lint.js` 顶上第一段就写着）。它写得出来、跑得通、
功能也对 —— 然后用户看到的是一个**一眼就是模板**、或者**手机上字小到看不清**的页面。

而看这一页的人里，正是**"看不清小字、点不准"的那一端**（`01-PROJECT.md` 写的就是他们）。
⇒ 这不是审美问题：**"能不能看清、能不能点着"是缺陷那一类。**

## 二、落到三个地方（**都在它真正会读到的地方**）

| # | 落在哪 | 为什么是这儿 |

| ① | **`app_create` 的工具描述**（`src/mcp-apps-server.mjs`）：**外观基线八条** | 这一句是 agent **动手造之前**必读的那一段。写在人格里是"每一轮都读"，容易被当成背景音；**写在它正要调的那个工具上，最贴脸** |

| ③ | **写歪了当场报给它自己看**：`src/app-lint.js` 新增第 ⑧ 档（4 条机械自查，**只报不拦**） | 前面两条是"告诉它怎么做"，这一条是**查它做没做**。跟既有的"引了外部资源 / 碰 localStorage / 用了没声明的能力"同一档、同一个回执 |

### 那八条（`app_create` 描述里那一份）

1. **手机优先**：`viewport` 必须有，按窄屏排（一列、不横滚）。
2. **字号**：正文 16px 上下、小字不低于 12px；分层靠**字重和颜色**，不靠缩小。
3. **一屏一个重心**：一页只解决一件事。
4. **留白成节奏**：同组靠紧、异组拉开；标题上面的空当 > 下面。
5. **对比度**：正文 ≥4.5:1；彩色底上的次要文字用**同色的深一档**，**绝不用灰**压。
6. **点击区 ≥44px**。
7. **不碰那几样一眼认得出的模板**：渐变字 · 玻璃拟态 · 卡片套卡片 · **左边一条彩色竖条的提示框** · emoji 当图标。
8. **状态要齐**：空 / 正在算 / 出错，各有一句话告诉他怎么办。

⚠️ **字体只能用系统自带的**（小程序引不到外部字体）：
`system-ui, -apple-system, "PingFang SC", "Noto Sans CJK SC", sans-serif`。

### 第 ⑧ 档那四条（机械可判、判出来就是真毛病）

| 自查项 | 判什么 | 为什么它是**缺陷** |
|---|---|---|
| `no-viewport` | 没有 `<meta name="viewport">` | 他那边按手机那点宽度打开 ⇒ 整页按桌面宽渲染，**字小到看不清** |
| `focus-removed` | `outline: none/0` 却**没有**替代的焦点样式 | 用键盘或用读屏的人**不知道焦点在哪** |
| `tiny-text` | 有 `font-size` < 12px | 跟"字号放到最大那几档也不破版"那条服务的人是同一批人 |
| `gradient-text` | `background-clip: text`（两种写法都认） | 对比度跟着底色变 ⇒ 常常读不清，而且是一眼认得出的模板感 |

⚠️ **只报不拦**（同这一档既有的纪律）：拦住会把"它明明能做对"变成"它做不出来"；
但要**说得足够大声**（回执里直接摊在它眼前，并写清怎么改）。
