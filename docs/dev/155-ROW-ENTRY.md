## 一、问题：一行 11 号字，被一颗 44 的按钮撑成 50

| 东西 | 数值 |
|---|---|
| 那一行的字 | **11 / 行高 14**（`DshTypes.chatQuiet`）|
| 右边那颗展开箭头 | **44×44**（为了过 D3.6 的"命中区 ≥44"，`tapTargetSize: shrinkWrap` + `min=max=44`）|
| 那一行的上下留白 | `DshChatSpace.rowPadV = 3` ×2 |
| ⇒ **整行高度** | **44 + 3 + 3 = 50** |

屏幕上的样子就是**一行小字漂在一片空白里** —— 而这一行在时间线里**一次能出现好几条**
（工具行 / 系统提示词行 / 轮次过程 / 排队抬头）。

## 二、改法：整行可点，箭头降级成"指示"

**新控件 `DshRowEntry`**（`lib/widgets/row_entry.dart`）：

- **整行都是命中区**：`InkWell`（Material 的水波；**不用 `GestureDetector`** —— 那是源码级禁令）
  ＋ `Semantics(button: true)` ＋ `Tooltip`（悬停/读屏那句"展开 / 收起"）；
- **那两颗箭头不再是按钮**：18 的 `Icon`，只做指示 ⇒ **不再参与 D3.6 的点状那一档**；
- 行高**跟着那一行文字走**（上下各 `rowPadV`）。

**D3.6 同日分两档**（这是这次真正的"判据改动"，写在手册里）：

| 档 | 判据 | 为什么 |
|---|---|---|
| **点状控件**（按钮 / 图标） | 命中区 **≥44×44** | 没变（原来就这一条）|
| **行级入口**（整行可点） | 整行宽 × 行高 **≥44×44（1936）** 且**宽 ≥44**；**行高不设下限** | 面积**更大**、手指要够的地方从"一颗小图标"变成**整行** |

⚠️ **不是放宽，是换了个更好按的形状**：原来那颗箭头 44×44 = **1936 px²**；
一行通常 300×20 = **6000 px²**（三倍多）。代价也明写：**它不再是"处处 44 高"**。

## 四、判据（谁把它撑回去就该红）

1. **硬闸 `test/widget/accessibility_test.dart`**：
   - `sweep()` 里新增**行级入口那一档**：每一颗 `DshRowEntry` 都要"宽 ≥44 且 面积 ≥1936"
     （扫到 0 行**不算红** —— 那一屏可能本来就没有这种行）；
   - D3.6 那一组新增一条专用用例（夹具用 `_filePanelFeed()`，它里面**有三条工具行**）：
     **扫到 ≥1 行**（负向对照：不许空转）· 宽 ≥44 · 面积 ≥1936 ·
     **1.0x 下行高 <44**（那正是这次的目的）· **点行的最左边也要能展开**（证明整行都是入口）。
     ⚠️ "行高 <44"只在 1.0x 上钉：3.1x 下**文字自己**的行高就超过 44 了（那是 D3.5 要的）。
2. **`test/widget/chat_spacing_test.dart`**：原来那条"可点区域仍 ≥44"改成按**行级**口径量
   （并加一条"点行左边也能展开"）。
3. **`test/widget/tool_rows_test.dart` / `queue_strip_test.dart`**：它们本来就是
   **按 key / 按图标**点的（不是按"那颗按钮"）⇒ 自动跟着新形状走（**一条没改**）。

**读数**：`flutter analyze` 干净 · 客户端硬闸**全过**（`check-client.sh` 退出码 0，五档不溢出 + 命中区全绿）·
受影响的四份 widget 判据 **420 条全过**。

## 五、⚠️ 这一批**没做**的（明说）

- **右栏（文件面板）里那种行**没动：它不在聊天时间线里，而且它的行高不是这颗箭头撑的
  （`file_panel.dart` 那处是另一套形状）；
- **展开态标题行右边那颗「收起」**没动：它和标题同一行，标题字号是 20/28，
  行高本来就不由它决定（2026-10-01 已经把它的图形 24→18、外框收到 44）；
- **手势（竖向拖 = 改窗口高度）**没动：它还绑在收起态那一条上（见 `chat_floater.dart`）。
