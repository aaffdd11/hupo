## 三、身份与路由（**手册没写、这里定死**）

### 3.1 手机号 = 账号；`sub` = userId

* 令牌**已经带 `sub`**（`auth.js:313`），今天只有一处硬写死：**`server.js:356` `auth.issue({ sub: 'owner' })`**
  ⇒ 那处改成"登录时算出的 userId"。
* 🔴 **调度器不许有"当前用户"全局**：身份**只能靠参数传**。
  （服务席的原话：*"一个 `currentUser` 全局加一次 `await`，就是 A 的请求写进 B 的账本。"*）
* 会话 → 用户：`Map<sessionId, userId>`，**与 `#agents` 同生共死**；
  且 `sessionId` 由 userId 派生（`${userId}/${随机}`），**不许**出现"两个用户的会话撞同一个键"。

### 3.2 容器里那个 agent **不许知道 userId**

它只拿两样东西：`DSH_HOME` + `HUPO_LEDGER_SOCKET`（`agent-runtime.js:311,320`）。
**身份藏在路径里，不藏在参数里** —— 把 userId 当参数递进去，等于给它一个**伪造的把手**。

### 3.3 浏览器怎么走到"他那台容器"

```
浏览器 ──► 调度器（8020，只听 127.0.0.1）──► 那台容器里的 dsh
                    ▲
                    └─ 身份 = 令牌里的 sub ⇒ 查 userId ⇒ 查容器
```
⚠️ 调度器**只做路由，不做内容**：它转发的字节**不落盘、不进日志**（那是用户的对话）。

## 四、容器的形状（**实测过的那些约束**）

| 项 | 定下来的 |
|---|---|
| OS 用户 | `hupo-a` / `hupo-b`（uid 2001/2002），各自一段 subuid/subgid |
| 起法 | `sudo -u hupo-a podman run …` ⇒ **容器 root → 2001**（**绝不许映射到 1001**） |
| 卷 | `/home/hupo-a/tenant`（属主 `2001:2001`，**0700**）→ 容器内 `/data`；`/home/hupo-a/.dsh` 同 |
| 容器内布局 | 按 §2.1：`/data/main` · `/data/workspaces/<名>` · `/data/hupo/{memory,apps,audit}` |
| ⚠️ **workspace root** | **绝不许是 home、也绝不许包含 `workspaces/`**（§2.2 规则 1、2）—— 否则那个 agent 读得到**用户自己的 key**，还能写 `.bashrc` |
| `DSH_HOME` | 每用户一份，而且**容器内路径每用户不同**（N21：键是绝对路径） |
| 镜像 | ⚠️ 无根镜像在各自 `~/.local/share/containers` ⇒ **共享不了**，只能各自 load 同一个只读 tar |
| 网络 | 实测：容器**够不着**宿主 `127.0.0.1`（8020 安全）；但**够得着**宿主 `0.0.0.0` 的服务（这台机器上有 `:22` `:80` `:6001` `:8000`）⇒ **要给容器定网络策略**，不能默认全通 |

## 五、网页终端（**②那条路的落法**）

* 形态：用户在自己那台容器里得到一个 **tty**，自己跑 dsh 的配置命令把 key 写进
  容器内的 `~/.dsh/.credentials.yaml`。
* 🔴 **key 不经过调度器**：终端是**字节流转发**，我们的进程**不解析、不落盘、不进日志**。
* 🔴 **终端绝不许以调度器的身份开**（那等于把 `deploy` 的 shell 递给用户）⇒
  必须 `sudo -u hupo-a podman exec`，而**能不能 `sudo -u` 到某个用户，本身就是那道边界**。
* ⚠️ 终端 = "能执行任意命令"的入口 —— 但那是**他自己的容器**，所以是**允许**的（§2.3：盒子里的 root 给）。
  代价要认：**他能在自己那台里做任何事，包括把 key 泄给他自己** —— 那是他的选择。

## 八、判据（**可执行 + 带负向对照**）

| # | 判据 | 对照 |
|---|---|---|
| 1 | **容器能起**（§13.4 第一道） | `V1b`：容器里写 `/tmp` 必须成功（否则"失败"什么都没证明） |
| 2 | 🔴 **甲的会话，乙读不到**（§13.4 第二道） | 乙读**自己**那份**必须成功**；失败必须是 `EACCES`，**`No such file` 不算** |
| 3 | 🔴 **甲容器读不到乙的 API key**（**你这条新需求最要紧的**） | 甲读自己的 key **必须成功** —— 不然只是"文件没挂进来" |
| 4 | **搬家前后逐字节一致**（§13.4 第三道） | 负向对照：故意把 workspace 挂到别处 ⇒ 同一会话 resume **必须接不上** |
| 5 | **临时码关着时登不进** | 开着时、任意手机号 + `123456` 能进（证明开关真的管用，不是永远拒绝） |
| 6 | **key 不落进调度器** | 在用户的终端里配完 key 之后，**调度器进程的内存/日志/磁盘里搜不到它** |
