## 二、三席各自的要点

**甲席（制品与分发）**：一个包（`@hupo/agent-layer`，声明 `dsh.bundle.patch`），版本＝内容 sha256 前 12，`.tgz` 离线装到 `~/.dsh/profiles/sdk/node_modules/` ＋ 改 `dependencies` 与 `dsh.profile.bundles` **两行**（⚠️ **这两行不要 `sudo`** —— 清单只钉 `cordis*` 两文件）。装法自己写：解到 `.staging-<fp>` → `mv -T` 原子换 → **最后**写 json；`--rollback` ＝装回上一版；核同版一条命令 ＋ **负向对照**（改包内一个字节必须报落后）。**第一步：只固化 `hupo-app-agent.yml` 那一份**。代价：`sudo` **0 条**、秒级、~1MB/版（⇒ 只留上一版）。🔴 **软肋**：**bundle 是配置层机制，不是文件分发机制** —— 人格仍由 `config.js:198` 的路径默认值读，包只换目录 ⇒ **"哪一版"仍写在代码里，两处真相没消灭**。

**乙席（信任与边界）**：固化把"哪些字节算被批准"从 N 个文件**塌缩成 1–3 行声明**，**攻击面从"每个文件的 hash"移到"解析链"**。签名（离线 tarball ＋ 预置公钥）只把"版本号是**自证**"升级成"**可验证**的声明"，**它不会把弱变强**；最大的风险是**制造"已经守住"的错觉** —— 威胁链里被诱导的是**写声明**那一步，签名完备照样中招。**分层而不是替代**：`strict` 管"路径上今天的字节"· 包＋版本管"这整块制品是哪个发布"· **P1/P2 管"谁有权让它生效"**（install/update 必须与 `--build` 同级：主人手动）。留痕四行（包@版本＋摘要 / 用哪把公钥 / 动了哪几个声明 / `sudo` 原文＋时间），而且**必须落在助手碰不到的地方**（`00-PROGRESS.md` §九 是助手自己写的，它改得动）。

**丙席（可维护性与漂移）**：进包的判据是"**可在别处装载的判据**"，**绝不装"关于本仓库当下状态的结论"**（手册正文 / `docs/dev/**` / `AGENTS.md` / `00-PROGRESS.md`）—— 后者一进版本号就是**第二份真话**。粒度主张**按"谁一起改"切（4 个包）**，不按文件切；内容哈希＝源文件哈希**现算**，仓内不留第二份副本。**它另外查出四处真洞**（见 §三.6）。

## 四、收口

### 4.1 分界（三席独立收敛到同一条线）

| 层 | 里面是什么 | 今天的形态 | 进不进包 |
|---|---|---|---|
| **运行时输入**（每开一个 agent 读一遍） | 人格 · 能力层 · 小程序限定档 · 模型代理（＋ `hupo-sdk-server.yml`） | 仓里 5 份 yml（4 份 `strict`） | ✅ **进包** —— 这是唯一真正的"内容" |
| **判据/规范** | `08-SPEC.md` §十 阈值表 · app-lint 那套 | 手册里的表（`strict`） | ⚠️ 可进"判据包"，**但必须能现算**，不许变成第二份真话（丙席那条判据） |
| **说明书 / 关于当下的结论** | 手册正文 01–07/09 · `AGENTS.md` · `docs/dev/**` · `00-PROGRESS.md` | `strict`（手册）/ 普通 | ❌ **不进包** —— 一进版本号就是第二份真话 |
| **现场覆盖层** | `cordis*.yml`（`web` 那份有真补丁） | 4 份 `strict` | ❌ 不进包（它是"最后一道本机覆盖"，进包＝用包盖包，回退粒度变粗） |
| **运行时数据 / 凭据** | `storages/**` · 账本 · `auth.json` · `.credentials.yaml` | 不在清单（有记录的接受风险） | ❌ **永不进包** |

### 4.2 形态（我建议的最小可行）

- **先一个包**（`@hupo/agent-layer`）：⚠️ **我不采纳丙席"第一步就 4 个包"** —— 今天最大的痛是"改一句人格 ⇒ 重建一次 19 条清单"，**不是耦合**；一上来拆 4 个包会把"一次重建"变成 4 套版本动作，反而不省。**保留他那条判据**（"按谁一起改切"）：等真出现"只改人格、不碰能力"的节奏，再拆。
- **版本＝内容摘要现算**（源文件哈希组合，不手写）—— 两席同此。
- **装法**：`npm pack` 出 `.tgz`（可进 git 或随产品层进盒）＋ `npm install --offline`（**实测 265ms**）；装完那份是**拷贝** ⇒ 它的字节可以独立核对。
- 🔴 **一条硬要求（甲席软肋的解药）**：包一旦引入，`config.js` 的默认路径必须指到**装进来的那份**，而"**现在是哪一版**"只许由**一条命令**回答（`check-agent-layer-drift.sh`），**不许写在代码里** —— 否则就是把"两处真相"从手册搬到代码。

### 4.3 护栏怎么办（**这一条要主人拍**）

| | 清单记什么 | 换版本要 `sudo` 吗 | 护栏 |
|---|---|---|---|
| **甲（保守）** | 装进去那份**目录的哈希**（把那个包路径从 `ALWAYS_SKIP` 里开**一个显式例外**） | **要**（但"改一句"变成"换一版"＝一次动作，不再是 N 个文件） | 字节级**不降** |
| **乙（激进）** | "**允许的签名者公钥 ＋ 允许的版本集合**" | **不要** | ⚠️ **降级**：从"内容不可悄悄改"变成"内容必须是被签名的那一版" |

- 走**乙**还必须同时处理两件：① **声明文件**（`package.json`／`bundles`）也得被护住 —— 而那两行**会被正常安装改写**（`integrity.js:99–102` 的教训：收了它＝"无故拒绝启动"）⇒ 只能"只报不拦"或"装完立刻重建"；② 签名密钥的轮换与旧钥验老包。
- **我的建议：先走甲。** 今天**只有一台机、一个主人**，签名买到的是"来源与可携带"，现在几乎用不上；它要付的（密钥管理 ＋ 声明文件那道新口子）立刻要付。等真有第二台机/第二个用户要跨机搬运时再上乙。

## 六、要主人拍的（**一条**）
