## 二、⚠️ 但本机有一件必须先说清的事：**这台机器既是开发机，又是线上机**

`AGENTS.md` §一 那张表把"生产机"写成**另一台机器**（另一个 checkout、systemd `concierge-core`、8091）。
**可今天真正在给主人用的那一份，就是这台机器上的 8020 + frp 隧道**（`w.stalkerai.cn`）。

⇒ 所以在**这台机器上**"开发期给我 sudo"，会**同时**解锁"正在服务的那一份"的护栏。
这不是文字游戏，它的直接后果是：

> **一旦助手在本机有 sudo，`/etc/hupo/integrity.json` 那道锁在本机就只剩"记录"作用。**

因为：我改完人格/手册/`AGENTS.md` 之后，**可以自己重建清单** ⇒ 核对永远能通过。
⇒ **锁的价值没了，剩下的是"审计"**：每次重建都是一次**看得见、可回溯**的动作。

### 2.1 这不是"降级通过"，是换了一种保护

| 保护形态 | 挡得住什么 | 什么时候够用 |
|---|---|---|
| **锁**（现在的 `strict`） | 助手**偷偷**把改动变成"下次开机自动读" | **部署**：没人在旁边看着每一次改动 |
| **审计**（开发期应有的形态） | 挡不住助手，但**每次都留痕** | **开发**：主人就在跟前，图的是快 |

⇒ 建议：**本机保持"锁"的机制不变**（对不上就拒绝启动 —— 那是防"没注意到"的安全网），
**但把"重建是预期动作"写进文档**，并让每次重建都留下一条记录（谁、什么时候、改了哪几个文件）。

## 五、比把口令给我更好的做法（**推荐**，主人二选一）

口令一旦贴出来就**留在对话记录里**了，而且**它能开这台机器上的所有门**。更合适的是
**只给几个具体命令免密** —— 一个 `sudoers.d` 文件，随时能删，删了就没了：

```bash
# /etc/sudoers.d/hupo-dev   （用 visudo -f 建；权限 0440）
# 只放开开发真正要用的那几条，别给"任何命令"
deploy ALL=(root) NOPASSWD: /home/deploy/.nvm/versions/node/v24.15.0/bin/node /home/deploy/proj/hupo/scripts/verify-integrity.mjs --build
deploy ALL=(root) NOPASSWD: /usr/bin/apt-get install -y chromium-browser
deploy ALL=(root) NOPASSWD: /usr/bin/apt-get install -y *
```

* ⚠️ 最后一条**很宽**（装包等于能装任何东西）—— 只在你接受"开发期就这样"时才加。
* 完全不想放开 `apt` 的话，那就留着：**需要装东西时主人自己跑一次**。

**两条路都行**，但我要把差别说明白：
**白名单** = 我能做的**恰好是那几件事**，其余一律照旧要你；**给口令** = 这台机器上我说了算。
开发期你觉得哪个合适就哪个 —— 但我不该替你选这个。
