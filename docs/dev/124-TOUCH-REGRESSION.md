## 〇、一句话

**三条症状是同一个根因，而且只在"手按住一会儿"的时候出现**：

> 手按住气泡 **≥500ms**（`kLongPressTimeout` 的默认值）⇒
> 弹出一层 `showModalBottomSheet`（气泡菜单）⇒ 它那层 **barrier 铺满全屏**
> ⇒ **时间线拖不动、抓手行每一颗按钮都没反应、输入条被那张单子整个盖住**。
> 收起的窗口里**没有气泡可长按** ⇒ 只有它正常 ——
> 那正是主人那句 *"聊天依然收起才能发送"*。

⚠️ **为什么 #168 一定漏掉它**：那一趟用的是**合成的瞬点**
（`tester.tap` / 探针同拍 `down+up`）—— **瞬点永远到不了 500ms**，
所以"长按"这条路上发生的事，桌面那一整套判据**一次都没走过**。

| # | 症状 | 复现 | 根因 |
|---|---|---|---|
| ① | 时间线滑不动 | ✅ **在长按菜单弹着的时候复现**（拖 0 像素）· ❌ 平时的拖/甩**滑得动** | 菜单那层 barrier |
| ② | 按钮点不开 | ✅ 复现（菜单弹着时一颗都不响应；另有 **390 宽下那一排动作**的账，见 §三·五） | 同上 ＋ 一个 `Spacer` ＋ 一条**没结**的 a11y 账 |
| ③ | 收起才能发送 | ✅ **在长按菜单弹着的时候复现**（两次都没发出去）· ❌ 平时（含键盘弹着）**发得出去** | 菜单盖住输入条 |

## 一、怎么复现的（装置与口径）

**装置**：`scripts/check-web-browser.mjs` 那一条路（CDP 接无头 Chrome），
外加四件这一趟必须有的东西：

| 件 | 为什么必须有 |
|---|---|
| `--width 390 --height 844` ＋ `Emulation.setDeviceMetricsOverride{mobile:true}` | 手机那一档几何 |
| `Emulation.setUserAgentOverride`（Android Chrome UA） | 引擎的 `isMobile = !isDesktop` 是按 **UA/`navigator.platform`** 判的（`ui_web` 的 `detectOperatingSystem`）—— 不换 UA，无头 Chrome 在 Linux 上**永远走桌面那一支**，`viewInsets` 那条路整条不执行 |
| JS 里合成 `PointerEvent{pointerType:'touch'}` 派到 `flt-glass-pane` | ⚠️ **CDP 的 `Input.*` 送不到 Flutter**（工具头实测）；页内合成 pointer 进得去 |
| 把 `window.visualViewport` 换成一个**高度能改**的假对象 ＋ 派 `resize` | 装出"键盘弹起来"：引擎源码里 `EngineFlutterView._didResize`（`window.dart`）在**手机 ＋ 正在编辑**时**不改 `physicalSize`**，而是 `computeKeyboardInsets` 报 `viewInsets = 满高 − visualViewport.height`（`full_page_dimensions_provider.dart`）。⚠️ 抄**真实** `visualViewport` 的值会踩坑：文档刚建出来时引擎还没打自己的 viewport meta（那之前是 980 宽的默认视口 ⇒ `height ≈ 2120`），抄了当场把浮窗顶到屏幕外 |

**令牌**：`src/auth.js` 的 `Auth.issue({sub:'u2'})` **现发**，只在内存里，**没写进任何文件**。
线上那一版是 `0ec2b1af0068`（`data/deploy-stamp.json` 对到 commit `3d6059b`，
**已经含 #168 那四条修**——我核过产物里的中文字句，确认打的是那一版之后的代码）。

## 二、三条症状逐条：复现了什么、没复现什么

### ① 时间线（平时的拖 / 甩）：**没复现**（它是好的）

展开态、390×844、触屏 pointer：

```
慢拖（手指往下 340→620，14 步 ×16ms） ⇒ 画面与语义 rect 指纹**都变了**
甩  （手指往上 620→260，6 步 ×8ms）   ⇒ 也变了
「回到最新」那颗按钮出现                ⇒ `_userScrolledAway` 真的置上了
```

⇒ **手指拖这条路是通的**（#168 修的那两条也在起作用：`_isUserScroll` 三种都认、
补帧自己排帧）。⚠️ 也试了"键盘弹着时拖"——一样滑得动。

### ② 按钮：判据是"**弹出来的那一层**才让它们不响应"

上一趟的按钮普查（展开态，逐颗派触屏点）：
`收起（抓手）· 打开右侧边栏 · 收起（箭头）· 聊天 · 轨迹 · 回收站 · 导出 · 过程 ·
回到最新 · 按一下说话` —— **平时每一颗都有反应**（打开面板 / 换 tab / 开语音…）。

🔴 但只要长按菜单弹着，**一颗都不响应**（读在 §二·③）。
另外**390 宽**下还有一条独立账（那一排动作排到了视口外），见 §三·五 —— **那条没结**。

### ③ 发送：平时**发得出去**；长按菜单弹着时**发不出去**（复现）

先说"平时"（含键盘那一档）：

```
【键盘没弹】发送钮 {"l":304,"t":746,"r":352,"b":794}
【键盘弹起 300】发送钮 {"l":304,"t":446,"r":352,"b":494}   ← 输入条整块上移 300
                  textarea 748..796 → 448..496
点 (328,470) ⇒ POST /api/say ✅ ＋ user/echo 回来了
对照组点键盘底下那个老位置 (328,784) ⇒ 什么都没发生（它确实在键盘底下）
```

⇒ **"展开时发不出去"本身没复现**（与 #168 一致）。**复现的是下面这一条：**

**按住 450ms / 600ms（同一颗气泡、同一套装置，只改按住多久）：**

```
450ms ⇒ 长按菜单**不弹**（阈值下 —— `kLongPressTimeout` = 500ms）
600ms ⇒ 菜单**弹了**（"要拿这一条怎么办 / 复制 / 多选 / 删掉 / 算了"，整张单子在屏幕下半）

菜单弹着的时候：
  · 拖时间线（340→600）⇒ 前后两张截图 **sha 一模一样** = 一个像素都没动
  · 点发送 第一下 ⇒ 没有 /api/say；**这一下把菜单关掉了**（barrier 吃掉）
  · 点发送 第二下 ⇒ **还是没有 /api/say**（输入框那条 DOM 连接被那层拿走过，得先点回输入框）
  · 菜单的语义容器 = **(0,0)-(390,844)** —— 整个窗口都是它的
```

再单独量一遍"菜单弹着"的现场（这是"按钮不对"最直的一刀）：

```
[① 塞完字]            textarea="p7-…" · 发送 disabled=null · 焦点=TEXTAREA
[② 长按之后]          textarea=(没有这个元素) · 焦点=FLUTTER-VIEW · 菜单=true
[③ 关掉菜单之后]      textarea=""（Flutter 那边那份字还在）
[④ 重新点输入框 + 发送] textarea="p7-…" · ⇒ **POST /api/say ✅**
[⑤ 收起 → 塞字 → 发送]  ⇒ **POST /api/say ✅**
```

⇒ **它是可恢复的**（点回输入框就行），但一个不会去点"输入框"的人，
看到的就是"**这个窗口点不动了、只有收起来才能发**"。

## 三、根因

### 三·一 长按那一层是**模态**的（三条症状的同一个根）

`screens/chat_screen.dart` 的 `_onBubbleLongPress` 原来：

```dart
final action = await showModalBottomSheet<BubbleAction>(context: context, builder: (_) => const BubbleMenu());
```

`showModalBottomSheet` 会推一条**路由**，它自带一层铺满全屏的 `ModalBarrier`。
于是"手按住气泡"这一个动作的代价是**整个窗口失去输入能力**：

* 时间线：触摸被 barrier 吃掉 ⇒ 屏幕上是"**无法滚动聊天窗口**"；
* 抓手行那几颗按钮：同上 ⇒ "**按钮也不对，点不开**"；
* 输入条：那张单子**从底部盖上来**（单子 9/16 屏高）＋ barrier ⇒ "**发不出去**"。

而它**为什么这么容易撞上**：门槛是 Flutter 的 `kLongPressTimeout` = **500ms**。
真手指"按下去、准备滑"的那一下、老人家的慢按，都在这个量级上 ——
这不是"长按"，这是**手停了一下**。

⚠️ **这一条与"桌面/触屏"无关，与"有没有 500ms"有关**：
所以桌面上一整批判据（瞬点）看不见它，而主人那台手机天天撞。

### 三·二 一个什么都不画的 `Spacer` 吃掉了那一排动作的一半宽

`widgets/chat_floater.dart` 的标题行原来是：

```
[8] [标题 Flexible] [8] [两个 tab] [Spacer] [动作 Flexible] [收起 48]
```

`Spacer` 与动作那一条**都是 flex 1** ⇒ 剩余宽**对半**分给"什么都不画的空白"和"那一排动作"。
390 宽下量到（widget，同一台假服务端、同一个宽度）：

```
有 Spacer：横滚条 35.4 宽（连「过程」都被切掉半个）
没 Spacer：横滚条 53.0 宽（「过程」整颗在里面）
```

⇒ 它是纯粹的浪费（`Flexible` 里的横滚条是**贪婪**的，会自己把分到的宽占满，
所以拿掉它那一排**仍然贴右**）。

### 三·三 键盘那一段（#168 修过的）**复核：是好的**

这一趟按**引擎真实的那条路**装了一遍（Android UA ＋ 正在编辑 ＋ `visualViewport` 缩小）：
输入条整块跟着键盘上移，时间线还剩一大块，发送点得到。
⇒ #168 的根因 C（`SizedBox(viewInsets.bottom)` 多算一遍）**确实修住了**（不是这一批的账）。

### 三·四 （没结）`_sendButton` 的 `canSend` 是"上一次"的读数

`widgets/composer.dart` 的发送钮外面是 `ValueListenableBuilder<TextEditingValue>(valueListenable: _controller)`：
`canSend = value.text.trim().isNotEmpty && !widget.hearing.busy` **在输入框变的时候才算**。
`hearing.busy` 变了而框里的字没变时，这一个小块**不会重算**（`ValueListenableBuilder.didUpdateWidget`
只在 `valueListenable` 换了的时候重建）。
本轮**没有证据**说它在真机上咬过人（探针里 `aria-disabled` 与文字始终对得上），
所以**没有动它** —— 记在这儿，别当它不存在。

### 三·五 🔴 **没结的账**：390 宽下那一排动作"看不见还挂在别人的坐标上"

读数（widget，390 宽；真浏览器上同一个形状）：

```
横滚条（视口）   = (230.3, 82.0) - (283.3, 130.0)    ← 53 宽
「回收站」那一颗 = 排在 (82.6 …) ── 在视口**左边外面**
「导出」         = 排在 (170.9 …) ── 也在视口外面
「过程」         = (245.1 … 273.3)                    ← 只有它在里面
聊天 tab         = (96.2, 94.8)-(124.4, 116.8)        ← 与「回收站」**压在一起**
```

真浏览器上的**活证据**：按 a11y 树里「回收站」那颗节点的坐标点下去，
**命中的是【聊天】tab**（视图从"轨迹"切回了"聊天"）—— 那就是主人说的
"**按钮也不对**"最直的一刀：**树里说的位置不是它**。

**为什么这一轮没修**：390 宽下这一行**物理上摆不下**（两个 tab 140 ＋ 四颗动作 250 ＋ 收起 48
＞ 一行 314）。真修法要么给一颗「更多」的出口、要么把它们搬出这一行 ——
**那是产品决定**（手册 §二 纪律 2：界面上加东西要主人点头）。
⇒ 这一轮只做了两件**有读数**的事（§三·二 的 `Spacer`、把口径改成实话），
其余**如实挂账**。⚠️ 顺带把 `chat_floater.dart` 里那句
"一行 + 横滚：高度不变、**一个都不藏**"改成了实话（它原来在说假话）。

## 七、🔴 如实说（真机还欠什么）

1. **没上真机**：这一趟全部读数来自**无头 Chrome ＋ 合成触屏**（真机在主人手上）。
   合成事件缺的三样，恰好是可能会改变结论的三样：
   **①真手指的动量**（甩）、**②浏览器的合成器**（真触摸先过 `touch-action`/命中测试，
   合成事件直接派进 `flt-glass-pane`）、**③真键盘**（`viewInsets` 是假 `visualViewport` 装出来的；
   引擎那两条路径按**源码**装，但真机报多少没验）。
2. **"长按 500ms"这个门槛我没动**：动它要自己写 `LongPressGestureRecognizer`
   （`InkWell` 不给这个口），而 `lib` 里有**源码级禁令**不许出现裸 `GestureDetector`
   ⇒ 这一轮改的是"**弹出来的东西不许挡窗口**"（结构上把三条症状一起拿掉），
   不是"把门槛调慢"。⚠️ 门槛仍然是 500ms：**手停 500ms 还是会长按出那一条** ——
   只是现在它**不挡任何东西**了。
3. **§三·五 那条账没结**：390 宽下「回收站/导出/打开右侧边栏」仍在视口外，
   a11y 树里那几颗仍挂在 tab 的坐标上（**真浏览器上点错过**）。
   真修法要**主人点头**（加一颗「更多」出口 / 把它们搬出这一行）。
4. **§三·四 那条没动**：`_sendButton` 的 `canSend` 只跟着输入框重算（`hearing.busy`
   变了不一定重算）—— 本轮没有它咬人的证据，所以**没改**，只是记下来。
5. **暗色那一档**：主人这台是**暗色系统主题**。这一批没有动外观那条轴
   （#169 之后默认已经回亮，跟随系统**暂时一律亮**）⇒ 这一条的读数与暗色无关，
   但真机上"暗色 ＋ 长按"这个组合**没量过**。
6. **没部署、没重启、没推**（按派活单）。客户端改了 ⇒ 要
   `scripts/deploy-web-v2.sh`；上线之后**建议用真手机把这一条走一遍**：
   按住一条气泡 0.6 秒 → 看它是不是**只在输入条上面**多一条 → 然后再滑时间线、再点发送。
