# 54 · 打字框 + 上面那条草稿（第三本账）

> 主人 2026-09-22：*"聊天浮窗要改版，改成微信那样。就是要有一个空的输入框，
> 但如果用户输入过，没发送，则显示在上面作为草稿。草稿也是要记住的。"*

---

## 一、⚠️ 先说清：这**不是**原来那本"草稿账"

这个项目里原来就有个东西叫 draft（`draft_store.dart`，欠账 #18 修的）。
**它不是这一件。** 两本账的边界写死在这儿：

| | 存什么 | 什么时候进的账 | 长什么样 |
|---|---|---|---|
| `draft_store.dart` | **按过发送**、但还没被服务端认领的那句话 | 按下发送之后 | **时间线里的一条**（带四态、有"重发"） |
| **`compose_store.dart`（新）** | **压根没按发送**、只住在打字框里的字 | 一边打一边存 | **输入框上面那条**（一个字都没发出去） |

⇒ **混成一本的代价**：刷新之后同一句话既在时间线上、又在草稿条里 —— **画两遍**。
（这正是这个项目最刺眼的那类形状。）

---

## 二、形状（"微信那样"）

```
┌────────────────────────────────────────┐
│  你打了一半                              │  ← 草稿条：只在「框是空的 + 本机存着草稿」时出现
│  帮我把这周的工时记一下                   │     原话照抄，最多三行（超了省略号）
│  [ 接着写 ]  [ 不用了 ]                   │     两条出路，命中区都 ≥44
├────────────────────────────────────────┤
│ [粘贴] [   说点什么           ] [ ↑发送 ] │  ← **空的输入框**（草稿不在框里）
└────────────────────────────────────────┘
```

三条规矩：

1. **框是空的**：草稿**不**驻在输入框里 —— 主人在上面单独看得到它。
2. **点「接着写」⇒ 字回到框里、上面那条收起来**（同一句话不许画两遍）。
   一旦他自己开始打字（框里有字），那条也收起来。
3. **点「不用了」⇒ 清掉**（本机那份也清）。

**存哪**：`ComposeStore`（`hupo_compose_v1.<按人分的命名空间>`，`shared_preferences`）。
上限 `capChars`（8K）：超了**截断**，不写爆 —— 它是"最好有"，不是"必须有"。
⚠️ **退出登录必须清**（换个人登录不许看见上一个人打了一半的话）。

## 四、同一批里另外两件（主人在同一句话里要的）

| 要什么 | 怎么落的 |
|---|---|
| **展开后要有收回的按钮** | 🔴 原来那个「收起」在抓手行那条**横向滚动**里 ⇒ 窄屏 + 大字号下会被滚出视野，**"想收起来"时找不到出口**。⇒ 现在**钉在横滚之外**，永远看得见 |
| **小程序点开要有效果：从哪里打开，就从哪里扩开** | 图标点的时候**把自己在屏幕上的矩形报上来**（`DesktopApp.onOpen(Rect)`，图标自己量 —— 上层不用猜它在哪儿）；`MiniAppHost` 用 `AnimationController` + `Rect.lerp` 从那个矩形长到全屏（`motionPage`，`easeOutCubic`）。⚠️ 内容是**按全屏排版**、被那块矩形"露出来"的 —— 不是一个小窗被放大（后者看得出是假的） |

**判据**（`test/widget/mini_app_test.dart` 加到 **8 条**）：
点开**第 0 帧**时还不是全屏、而且**起点在那个图标附近**（硬切的话这一帧就铺满了）；
中途在长大；收尾 == 屏幕矩形。

## 五、⚠️ 这一批踩到的（留给下一个人）

1. **量错对象**：`MiniAppHost` 自己是铺满的 `Stack`（它不动）——
   动的是里面那块被露出来的矩形。判据一开始量的是 host，于是"刚点开就全屏"的假读数，
   差点把好好的动画判成硬切。⇒ **判据要量"那个在动的东西"**。
2. **参照物拿错**：起点该拿**图标那个格子**比，不是它下面那行**文字**
   （文字只有 25px 宽，格子 92px）—— 拿文字比会把正确的动画判红。
