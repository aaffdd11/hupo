## 一、手册要什么（三件，一件都不能少）

| 要求 | 出处 |
|---|---|
| 判据是**内存占用比**：`memory.current / memory.max ≥ 0.75` ⇒ 拒新会话 | §9.1 / §10.3（"留 25% 给握手峰值与监控 agent"） |
| **没有计数闸** —— "不给数字，所以判据只能是内存" | §9.1 |
| 拒绝必须：**一句人话 + 可重试 + 不建空 jsonl 文件** | §9.1 + **N11** |

⇒ 所以**不许**顺手加"同时 N 个会话就拒"：那是在给一个**我们不承诺的数字**上锁。

## 二、⚠️ 这台机器上，这个判据**算不出来**（实测，不是推测）

```
$ cat /proc/<服务 pid>/cgroup
0::/user.slice/user-1001.slice/user@1001.service/app.slice/dsh-subprocess-*.scope
```
> ⚠️ 这个路径长这样，是因为**这台服务是从一个 DSH 会话里 `setsid nohup` 启的**
> ⇒ 它**继承了那个会话的 scope**。生产机上它会有**自己的单元**（`MemoryMax=1G`，
> §10.3 那一行的由来）—— 那时判据才算得出来。

逐层往上（内核实际生效的是路径上**最小**的那个）：
  …/dsh-subprocess-*.scope   memory.max = max
  …/app.slice                memory.max = max
  …/user@1001.service        memory.max = max
  …/user.slice               memory.max = max
  /user.slice                memory.max = max
```

**每一层都是 `max`** ⇒ 手册那个 0.75 是**有上限时**才算得出来的相对量。

⇒ 处理方式与完整性清单**同一个套路**：**不许悄悄放行**（"看起来有闸、其实没有"比没有闸更坏），
要**如实说"这道闸现在算不出判据"**。横幅里就写着：

```
准入     ⚠️ **算不出判据**（这一层没有内存上限 ⇒ 这道闸现在不生效）
```

等**容器 / systemd 单元**那次 `sudo` 落地（`MemoryMax=1G`），它自然就活了 —— 两半是同一批。

## 三、判在哪一刻（这一条最容易做错）

**必须在落盘之前判**（`server.js` 的 `handleSay` 里、`say.say()` 之前）：

```
收到一句 → ① 是不是重发？ → ② 忙不忙？ → ③ 落盘 → ④ 交给 agent
                 │                │
                 │                └── 忙 ⇒ 429，**什么都没写**
                 └── 是重发 ⇒ **不判忙不忙**（见下）
```

**为什么"落盘之后再拒"不行**：那在日志里和"没收下"长得**一模一样**，
而下一个人根本分不清 **"没收下"** 和 **"收下了但没答"**。
⇒ 所以 §9.1 那句"不建空 jsonl 文件"的落点就是这里，验收也是直接看**那个文件在不在**。

### 3.1 ⚠️ 重发**永远不许被拒**

重发的意思是"我没收到你的回执，再说一遍"——**那一句早就落盘了**。
拿"忙"把它拒掉，界面上会显示「没发出去 · 重发」，**而服务端其实收下了**，
而且那一轮**已经在跑** ⇒ 用户会再发一遍 ⇒ **界面在说假话**。
⇒ 所以 `say.js` 多了一个 `isDuplicate(messageId)`，准入先问它。

## 四、契约（服务端 ↔ 客户端）

| | |
|---|---|
| **回答** | `POST /api/say` ⇒ **HTTP 429**，body `{"error":"busy"}` |
| **含义** | 它现在忙不过来，**这一句没收下**（没落盘、没投给 agent） |
| **客户端该做** | 那条发言进 **failed**（屏幕上就是「没发出去」+「重发」= **N11 要的可重试**）+ 状态条说清"忙"，**不许**说成"网断了" |
| ⚠️ **注意** | **429 在 `/api/login` 上是另一个意思**（登录失败太多次、锁住了，要带 `retryAfterSec`）。两处各管各的，**别顺手把登录那条改坏** —— 有一条测试钉住这件事 |

> 为什么复用 429 而不新造一个状态码：它本来就是"请求太多，稍后再来"的语义，
> 而且**协议字段一旦上线就冻结**（`03-DEVELOPMENT.md` §三）——复用比新造更容易被下一个人理解。
> ⚠️ 但它是**同一个码两种语义**，所以两边都必须有测试钉住（`busy.test.js` 最后一条）。

| `busy.test.js`（5 条） | 🔴 **拒了之后那个 jsonl 一个字都没写** + **正对照**（不忙时会写 ⇒ 证明前一条不是空跑）· 🔴 **重发不许被拒** · 忙时拒新的、不动旧的 · 429 两处语义各管各的 |

⚠️ **那个正对照是必须的**：只验"拒了没文件"，如果文件路径本来就写错，
这条会**永远绿**——看起来验过了，其实什么都没验。
