# 为什么做琥珀 · 它跟豆包 / 腾讯 Buddy 那一类比，好处在哪

> 主人 2026-10-07：*「帮我跟豆包跟我 budy 之类的都对比一下，然后为什么我要做这个软件，它有什么好处。」*
>
> 这一篇是**答话的底稿**：可以直接拿去讲、拿去写材料；对表的每一格都能在仓库里找到出处。
> 「budy」按**腾讯那一串 Buddy** 算 —— `WorkBuddy` / `CodeBuddy` / `DataBuddy` / `MusicBuddy`，
> 腾讯自己把它们统称 **Buddy AI**（[36氪：腾讯开始批量生产"Buddy"了](https://eu.36kr.com/zh/p/3993969499765767)），
> 再加上手机厂商自带的那些助手（小艺 / 小爱 / Bixby 那一类）—— 它们都是**"一个场景配一个 AI 搭子"**的思路。
> 如果指的是别的某个 app，说一声我照着改。

---

## 一、先说清楚**不比什么**（不吹）

| 不比 | 为什么 |
|---|---|
| **模型聪不聪明** | 琥珀**不训模型**，用的是通用大模型的接口 —— 论回答质量、知识面、生态规模，比不了豆包、元宝、Buddy 那一串 |
| **语音成不成熟** | 琥珀的语音**识别本身就是豆包那一套**（豆包大模型的语音识别）；豆包的语音／视频通话、耳机唤醒，我们做不出来也不打算做 |
| **能不能替你点手机** | 银行、政务、挂号、快递这些**永远不会给接口** ⇒ 琥珀只做"**准备到最后一键**"，做不到就明说做不到（[`handbook/01-PROJECT.md`](../handbook/01-PROJECT.md) §1.2） |
| **谁的用户多** | 它们几亿用户，琥珀现在是**家里那几台**在跑 |

⇒ 下面比的**不是"谁更聪明"，而是"形状不一样"**：AI 放在**谁的机器**上、**交出来的是什么**、
**记忆归谁**、**边界能不能查**。

---

## 一·补、主人自己是怎么说的（2026-10-07 口述）

> 这段是他**口述的原意**（我只理顺了句子，没改意思）—— **这是这一篇的立论**：

1. **人的记忆是有限的** ⇒ 记忆本来就该放到外面去；而**豆包、元宝这些的记忆并不持久**。
2. **Buddy 那一类虽然灵活，却不适合小孩子和老人开箱即用**（它按场景分工，是给职场人、开发者用的）。
3. **DeepSeek Harness 那种太专业**，用起来有门槛。
4. **免费的工具配套差，而且内容归平台所有。**
5. ⇒ 所以要做**自己的桌面平台**：**开箱即用**、**自己付算力**换来**更强的工具**
   —— 这等于**走在人们前面**。
6. 类比：**四十年前，电力就是生产力；敢于拥抱未来生产力的人，率先拿到未来的优势。**

**这段话成立的前提（也就是我们自己要盯住的判据）**：

| 他说的 | 落到判据上是什么 |
|---|---|
| 记忆不持久 | 「持久」不只是"存在服务器上"，而是**能查**：翻得出来、删得掉、**删号即删盒**；看不到记住了什么，就等于没记住 |
| 开箱即用 | 判据是**不会打字的人第一次打开就能用**（走查里那位六十八岁的退休教师，当年就死在登录页） |
| 自己付算力 | 另一面是**要花钱、要维护**；换来的是**模型能换、账自己看得见** |
| 走在人们前面 | 这句是**愿景不是现状**：现状是家里那几台在跑，不是几亿用户 |

## 二、四方对表

| 比什么 | **琥珀** | **豆包 / 元宝**（通用 AI 助手 App） | **腾讯 Buddy 那一串**（WorkBuddy · CodeBuddy · DataBuddy） | **Codex / Claude Code**（开发者智能体） |
|---|---|---|---|---|
| **AI 住在哪** | **你自己那台小主机**（他的文件、数据、钥匙都在那儿） | 厂商的**云**上；要动你的手机/文件得靠系统级授权与插件 | 厂商的云 ＋ 桌面客户端（WorkBuddy 是"职场智能体工作台"） | 你的**代码仓库**里（云沙箱或本机终端） |
| **干完交出来什么** | **桌面上多出一格能用的小程序**（当场写、点开就用、数据存得住）＋ **事情真的办完** | 回答 / 总结 / 写文稿 / 搜资料；手机助手那一支能在 App 之间替用户点 | **一份活儿的成品**：文档、代码、数据报告、歌 | 可以合并的**代码改动**（补丁 / PR）＋ 测试结果 |
| **怎么输入** | **语音优先**：点一下说、按停就发；识别的字当场长出来、**点一下就能改** | 打字为主；语音很成熟 | 打字为主（职场 / 开发 / 数据场景） | 打字为主（命令行 / IDE） |
| **记忆在哪 · 删号会怎样** | 记在**他自己的盒子里**：关掉、重启、换设备都还在；**删号即删盒** | 记在**厂商账号**里 | 记在**厂商账号与工作区**里 | 记在项目／仓库上下文里 |
| **记忆能留多久 · 能不能查** | **持久且在册**：重启、换设备都在；**每一步做过的都能翻出来**（做过什么、成没成、花了多少） | **不持久**：会话与账号级记忆，**也看不到它到底记住了什么**（走查原话："看不到它记住了什么，我就默认它没记住"） | 按产品线各记一段，跟着账号走 | 跟着项目／仓库走，换个项目就没了 |
| **开箱即用吗（谁得先学）** | **就是给不会打字的人做的**：点一下说话、说完按停就发；字号放到最大那几档也不破版、能点的地方手指都点得准 | 对普通用户友好；但对**不会打字、看不清的老人**仍以打字为主 | **灵活但专业向**：职场／开发／数据各有各的用法，**小孩和老人不适合** | **门槛最高**：命令行／IDE，只有开发者用 |
| **算力谁付 · 内容归谁** | **自己付算力**（用哪个模型自己挑、账在自己机器上）；**内容与数据归自己** | 免费／会员由平台承担 ⇒ **按它的条款，你写的东西在它的平台上** | 平台承担 ⇒ 内容归账号／工作区 | 按席位／用量付费，产出归仓库 |
| **面向谁** | **会说话的人都能用**：八九岁的孩子 → 六七十岁的老人 → 手机/pad 上移动办公的人 | 所有普通用户（这一层它们做得比我们大得多、快得多） | 职场人 / 开发者 / 数据岗（按场景分工） | 开发者 |
| **边界能不能查** | 助手**只能提申请、人按按钮** · **钥匙不出盒子** · 小程序权限弹窗 · **开机完整性清单** —— 每一条都在仓库里可查、有判据盯着 | **厂商自证**（用户看不到边界怎么实现的） | 厂商自证 | 权限交给开发者自己管（沙箱 / 审批） |
| **能不能改** | **整个实现是我们自己写的**（实现契约与判据的条数见 [`dev/00-PROGRESS.md`](00-PROGRESS.md)），每一处都能动 | 封闭的 App | 封闭的 App | 改的是代码，不是"助手本身" |
| **谁的东西** | 用户的东西**归用户**：数据、钥匙、账都在他那台机器上 | 归账号 | 归账号 / 工作区 | 归仓库 |

**一句话的区别**：
> **它们把 AI 放在自己的云上，替用户说话；琥珀把 AI 放到用户自己那台机器上，替用户办事，还给用户造软件。**

由此长出三件它们**今天不是这个形状**的事：

1. **给不会写代码的人"造一个只属于他的小程序"** —— 做完就留在他的桌面上，明天还在；
2. **每一件活的来龙去脉在用户自己机器上逐条留账**（做过什么、成没成、花了多少），删号一起走；
3. **钥匙和数据不出他那一台** —— 助手连"读钥匙"这条路都没有。

## 三、为什么做这个软件（三个由来，都是真事）

### 3.1 十个人走查下来，放弃点指向**同一个洞**

立项前拿十个人**第一人称**走查（技术满级的主人本人 · 后端工程师 · 开小饭馆的 · 通勤族 · 家长 ·
**六十八岁不会拼音的退休教师** · 设计师 · 公众号作者 · 工地断网 · 平板用户）。
十个人的放弃点里，**八个落在同一件事上**：

> **"它到底活着没有、记着没有、说的是不是真的"—— 用户无法验证，而系统自己也不说。**
> （[`handbook/01-PROJECT.md`](../handbook/01-PROJECT.md) §三）

⇒ 所以琥珀从第一天起把这三件事**做成看得见的**：
话发出去了**有活着的信号**；记忆**能翻出来看**；失败与成功**长得不一样**；它做过的每一步**留账**。

### 3.2 主人自己的用法变了：**打字不如说话**

> *「我越来越不需要在电脑上，可以移动办公，在手机、pad 上输入；但输入越多，越发现打字的效率根本没有语音高。
> 它其实是**把人类从输入里解放出来**，应用场景更宽：八岁的孩子、九岁的孩子也能用，六十岁、七十岁的老人也能用。」*

⇒ **定位 = 「会说话的人都能用」**。不会打字、看不清小字的人是**设计基准**，不是"使用者上限"。
界面那几条硬规矩（系统字号放到最大那几档也不破版 · 能点的地方手指都点得准 · 不许只有图形没有文字 · **内部词一个都不许上屏**）
就是"跨度这么大还得都能用"的直接结果。

### 3.3 现有产品的"形状"不解决这件事

| 现有产品解决的是 | 琥珀想解决的是 |
|---|---|
| 问一句答一句（**内容**） | **事情**：说完它去办，办完回来说一声 |
| 记忆在账号里（**看得见结果，看不见过程**） | 记忆与账在**自己机器**上，**随时能查** |
| 通用 App（**谁的用法都一样**） | **一人一台、长出自己的东西**（桌面上的小程序就是他自己的） |
| 封闭（**边界靠相信**） | 边界**写在仓库里、有判据盯着**，助手**只能提申请** |

## 四、有什么好处（按人群说，不说空话）

| 谁 | 好处 | 现在真的做到了吗 |
|---|---|---|
| **不会拼音的老人**（六十八岁那位就是设计基准） | **说一句就行**：点一下就说、说完按停就发；说错的字**点一下就能改** | ✅ 语音输入是主路径（安卓原生录音 + 流式识别） |
| **孩子**（八九岁） | 说话就能**造东西**：一个小程序、一张图、一本账、一个下棋的小游戏 —— 做完**留在桌面上**，明天点开还在 | ✅ 桌面 ＋ 小程序 ＋ 画图 ＋ 记账；图像/视频生成在做（v3.0） |
| **手机 / 平板上移动办公的人** | 说话比打字快；长活**放后台**，做完**主动来告诉**；随时能问"那件怎么样了" | ✅ 长活 ＋ 提醒 ＋ 手机/平板都适配 |
| **在乎数据归谁的人** | **一人一台盒子**：数据、钥匙、账都在自己机器上；**删号即删盒**；助手**读不到钥匙** | ✅ 多租户 ＋ 容器隔离 ＋ 完整性清单 |
| **技术主人自己** | **能改自己**：整个实现是自己写的，助手可以提申请、签字的是人 | ✅ 这套仓库就是它的源码（P1/P2） |

**最实在的三条（也是我们敢说的三条）**：

1. **"说话就能用"** —— 不用学拼音、不用学打字、不用学界面；这是"把人类从输入里解放出来"的字面意思。
2. **"它真去办，办完回来说一声"** —— 不是陪聊：桌面上的小程序、账本、图，都是**办完的成品**。
3. **"你的东西在你手里"** —— 数据、钥匙、账、甚至这套软件本身，都在你能拿到的地方。

## 五、如实说（这些地方我们比不了 / 还没做到）

| # | 事 |
|---|---|
| 1 | **模型与语音都是别人的**：琥珀不训模型，回答质量和语音成熟度取决于所用接口；豆包、元宝、Buddy 那一串在这两点上比我们强 |
| 2 | **生态与规模比不了**：它们有账号体系、多端同步、几亿用户与插件生态；琥珀现在是**家里那几台**在跑 |
| 3 | **不能替你点手机**：银行、政务、挂号那类"没有接口"的事，只能准备到最后一键 |
| 4 | **iOS 商店版没有**（本机没有 Mac）；安卓主题图标（单色）也没做 |
| 5 | **它会慢、会花钱**：一轮要等模型；上下文长了要翻页；长活放后台是默认 |
| 6 | **对比依据**是各家公开发布的介绍与报道（资料截至 2026-10，其中豆包"手机助手"那一支还是技术预览版）—— 它们更新很快，这一篇会过期 |
| 7 | **我们自己也在用**：语音网络延迟、会话翻页这些还在打磨（[`dev/208`](208-TURN-LATENCY.md) · [`dev/210`](210-VOICE-CONTINUOUS.md)） |
| 8 | **"免费的内容归平台"要按各家协议看**：各家条款不一样，这一篇说的是**形状**（东西存在它的平台上、按它的规则用），不是指某一条具体条款 |
| 9 | **"自己付算力"的代价是真的**：机器、电、模型调用费、运维都自己出；现在这台机器**既是开发机又是线上机**，坏了自己修 —— 换来的是**模型能换、账自己看得见** |

## 六、一句话（可以直接讲给人听）

> **豆包那类是把最强的 AI 放在云上、替你说话；腾讯 Buddy 那一串是给每个场景配一个搭子。**
> **琥珀只想做一件事：把 AI 放到你自己那台机器上，让你说一句话，它真把事办完 ——
> 办完的东西留在你的桌面上，账和钥匙也留在你手里。**
> 它今天没有别人聪明、也没有别人大；但它**是你自己的那一个**。

> **四十年前，电力就是生产力；今天，算力就是生产力。**
> 谁先把算力变成"**自己的、开箱即用的**"那一份 —— **不会打字的人也能用、记忆留在自己手里** ——
> 谁就先拿到未来的优势。这就是做琥珀的理由。
