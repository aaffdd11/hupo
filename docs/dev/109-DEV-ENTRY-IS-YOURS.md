## 七、🔴 铁律（主人 2026-09-25 当场定）：**一个用户容器里只许有一个 DSH**

> 主人原话：*"你在用户容器里面起了两个 deepseek harness，对吧？这是绝对绝对不允许的，
> 它只允许有**一个** deepseek harness，然后你**所有**的对话都是在这一个 deepseek harness 里面完成的。"*

**先核清 DSH 自己的说法**（`node …/dsh/lib/bin.js --help`，别再猜）：
- DSH **没有守护进程**：`dsh [options] [command]` 每次调用都是"boot 一个 profile"（web / tui / headless）
  ⇒ **一次调用一个进程**，这是它本来的形状，不是"起了两台"；
- **家目录与会话只有一份**：`$DSH_HOME/sessions`（盒里 `/data/dsh`），**按 cwd 分项目**、**与 profile 无关**。

⇒ **"一个 harness" = 一个 `$DSH_HOME` ＋ 一个 profile（一套配置）**。
调度器按轮起的那几个进程是**同一套配置的多次调用** ⇒ 那不是第二个 harness。

🔴 **真正违规的是我们这一处**：开发者模式那条起的是 **`--profile web`** ——
**另一套配置**（没有人格、没有工具、cwd 也不对）⇒ **那才是"第二个 harness"**。

**所以**：
1. 那条入口**只许起同一套**（`--profile web` ＋ `hupo-persona.yml` ＋ `hupo-capabilities.yml` ＋ 模型那条 patch），
   而且 **`DSH_HOME` 就是那一个**（`/data/dsh`，**不许另设**、不许有第二个 home）；
2. 房间清单照旧（D6）：`main` ＋ 每一间工作区，点哪间就用**那间的 cwd** ⇒ 看到的必须是**同一份会话**；
3. **D7′（源码级/参数级 · 改过一次，别照旧版读）**：那条入口起出来的**只有一套配置** ——
   判据落在**同源的三样**上：**① 同一套 patch**（`agentPatchArgs()`，与调度器那台**一处出处**）·
   **② 同一个 `DSH_HOME`**（只有一个）· **③ 那一间的 cwd**。
   ⚠️ **`--profile web` 这一行不改**（`DEV_WEB_PROFILE`），而且**不许**把它当成"D7 的反例"。
4. **D7″（为什么这条判据改过 —— 我原来那条是错的，如实记）**：
   我最初把 D7 写成"源码里不许再出现 `--profile web`"，理由是把 `web` 读成了"第二套配置"。
   **真机一查就塌了**：`dsh --profile sdk --host …` ⇒ `error: unknown option '--host'`（exit 1）——
   **浏览器界面只有 `web` 这个 app 提供**（`web` 才是那个 app；`sdk` 是 stdio JSON-RPC）。
   ⇒ 照旧那条判据做，这条入口**当场起不来**，而且是**照着一条错的判据把它改坏**。
   所以 D7 改成 D7′（同源落在 patch / home / cwd 三样上），而"它是不是第二台 harness"按
   主人那句话读：**一个 `$DSH_HOME` ＋ 一套 profile** —— 判据是"参数与那台逐字同源"，
   不是"profile 名字像不像"。⚠️ 冲突时**以事实（真机读数）为准**，并把判据改对（这就是第 11 条）。

### 8.3 同一次**批**下来的那一件：让 DSH 认得出这些房间

`ensureRoomRegistered()` 原来**默认只读**（写 DSH 的 `workspace.json` 属于"改运行中的东西"）。
主人批了 ⇒ `serve.js` 现在传 `workspaceNudge: true`：起那台之前把注册表 `initialized` 置回 `false`，
让 DSH 按对话头**重新发现所有房间**（`main` ＋ 每一间工作区）。

⚠️ **为什么非它不可**：注册表一旦初始化过，DSH **再也不发现新房间**，界面会把那一间的对话
**整个藏掉**（**光把 cwd 指对不够**）⇒ D3/D6 都会红。⚠️ 那是**写盘**，所以它**不是默认值**，
