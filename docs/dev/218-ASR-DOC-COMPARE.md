> 这一篇就是那次逐条对表：**哪几条一样、哪几条不一样、改了哪几条、还剩哪几条要问他**。

| 项 | 文档怎么说 | 我们（改前） | 现在 |
|---|---|---|---|
| **端点** | 双向流式 `…/bigmodel`；**"更推荐使用双向流式模式（优化版本）"`…/bigmodel_async`** —— *"不再是每一包输入对应一包返回，只有当结果有变化时才会返回新的数据包"* | `bigmodel`。🔴 **真读数**（同一段 2 秒合成音、同一把真钥匙）：**22 帧**；他那一场真录音里，说完之后上游把同一份结果**重发 120+ 帧** | ✅ 换 `bigmodel_async`：同一段音频 **2 帧** |
| **单包大小** | 单包 **100~200 ms**；双向流式 **200 ms 最优** | 网页 `_blockFrames = 4096` 采样 = **256 ms**（**超了**）；安卓 `CHUNK_BYTES = 3200` = 100 ms ✓ | ✅ 网页 **2048 = 128 ms**（`createScriptProcessor` 只收 2 的幂 ⇒ 200 ms 表达不出来；没有改成"攒 200 ms 再发"：那要多一个 flush，漏了就**切掉最后 200 ms**）；安卓 100 ms 不动（本来就合规） |
| **`result.text`** | **"整个音频的识别结果文本"**（`result_type` 默认 `"full"` ＝ 全量） | 🔴 按"只管当前这一句"**再累积一遍** ⇒ 同一段一遍遍长（"多的离谱"） | ✅ **整段替换**（段号恒 0、接缝去重、回声丢掉）—— 见 `216` §二·补4 |
| `show_utterances` | 开了才有 `utterances`／`definite` | `true` ✓ | ✓ 不变 |
| `enable_itn` / `enable_punc` | 默认 true / true | 都传 `true` ✓ | ✓ 不变 |
| `definite` | 分句标识 | 用着（真帧里见过"定稿 是"）✓ | ✓ 不变 |
| **`vad_segment_duration`** | 默认 **3000 ms**（静音超过它才切成两句） | 没传 ⇒ 用默认 3000 ms ✓ | ✅ **正好与他要的"别说着就被切断"一致**（我们不传 `end_window_size`，所以不会 800 ms 就判停） |
| **`enable_ddc`（语义顺滑）** | 默认 false；开了会删**停顿词 / 语气词 / 语义重复词** | 没开 | ⏳ **要问他**：开了他的话会干净（"呃/啊/重复"被清掉），但也可能**删掉他真说的话**（产品取舍） |
| `enable_nonstream`（二遍识别） | 只在优化版支持；更准，但**尾字时延更大 / 更贵** | 没开 | ⏳ 先不动 |
| `X-Tt-Logid` | *"强烈建议记录…作为排错线索"* | 没记 | ⏳ 顺手加（只记 logid，不记正文） |
| `end_window_size` | 强制判停（默认 800 ms，最小 200） | 没传 | 保持不传（理由同上：不要按静音硬切） |

## 真读数（同一段 2 秒合成音 · 同一把真钥匙 · `scripts/check-asr-doubao.mjs --spend`）

```
端点 wss://…/sauc/bigmodel        → 上游回帧 22 帧
端点 wss://…/sauc/bigmodel_async  → 上游回帧  2 帧
（两次都 ✅ 握手成功；合成音不是人话 ⇒ 只说"通了"，不说"听得准"）
```

⚠️ 那两次真连**按秒算钱**（各 2 秒）—— 这是文档要求"以真跑一次的回话为准"那一条的代价，如实记在这儿。

## 改了之后要盯什么

* 换端点之后**帧的形状**仍要确认一次（"只在有变化时回帧"⇒ 帧更少、更稀疏）；
  容器日志里现在没有那条第 217 篇里的临时诊断了（用完就撤了）。
* 网页那一侧的单包 256→128 ms 只影响"发包疏密"，**不影响音频内容**（一包不丢）。
