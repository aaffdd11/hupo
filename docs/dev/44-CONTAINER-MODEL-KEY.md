# 44 · 盒子里的钥匙到底能不能用（真机端到端）

> 主人 2026-09-21：*"apikey 是否完成也需要测试才行，要能成功连上容器内部的 deepseek harness 才行。"*
>
> **他是对的。** 在这之前我验的只是**那个标志位**（`hasKey` 活过宿主重启），
> 而且用的是**假钥匙**。**"钥匙送到了"与"钥匙能用"是两件事。**

## 一、结论先说

| 那一跳 | 结果 |
|---|---|
| 用户填的钥匙 → 宿主内存 → 通道 → 盒内 `/run/hupo/creds.yaml`（`600 root` · tmpfs） | ✅ **通**（实测文件出现、模式正确） |
| 盒内小代理拿它去打**真上游** | ✅ **通**（DeepSeek 回 `401 ... your api key: ****0000 is invalid` —— 它真的收到并用了这把钥匙） |
| 🔴 **agent（uid 1000）起得来** | ✅ **修好了**（原来**根本起不来** —— 见下，**三个断点**） |
| 🔴 **dsh 跑完一轮**（`turn/start` → `assistant/attempt` → `turn/end`） | ✅ **通**（用盒子自己那份代码重放的） |
| 🔴 **真钥匙 ⇒ 真回答** | ⏳ **没验 —— 缺一把真钥匙**（见 §五） |

⚠️ **所以答案是：在这一次之前，盒子里的 agent 是"看起来在跑、其实一个字都答不出来"。**
界面上你说什么，它只会回一句 *"你刚才那句我没来得及做，就卡住了。再说一次吧。"* ——
而**盒内日志一行线索都没有**。

## 二、三个断点（每一个都只在 stderr 里，而 stderr 没人看）

### 断点 ①：agent 读不到那几份 `--patch` 文件

```
Error: dsh: failed to read overlay /app/hupo-persona.yml:
       EACCES: permission denied
```

`hupo-persona.yml` 与 `hupo-capabilities.yml` 在仓库里是 `600`，
而 `cp` **把权限一起带进镜像** ⇒ uid 1000 读不到。
dsh 开机第一件事就是读它们 ⇒ **当场退（code 1）**。

⇒ 修：镜像组装完之后 `chmod -R a+rX "$R/app"`。
⚠️ 为什么安全：**镜像里没有任何秘密**（那把 key 是运行时才进
`/run/hupo/creds.yaml`，在 `0700` 的 `/run/hupo` 里，**不在镜像里**）。
决策 ① 要保护的是"agent 读不到**自己的 key**"，不是"agent 读不到代码"。

### 断点 ②：原生模块缺动态库

```
ERR_DLOPEN_FAILED libutil.so.1: cannot open shared object file
```

我们那个 `scratch` 镜像**只 `ldd` 了 node 自己**的依赖 ⇒ node 跑得起来，
但 `node-pty` 的 `pty.node` 有**它自己的**依赖。
⚠️ 它的现象**极难查**：dsh 报的是

```
dsh: plugin tree failed to load: ... failed to import loader entry subprocess
```

—— **一个字都没提"缺库"**。因为 node-pty 的加载器把 dlopen 的失败
**吞成了"找不到模块"**（`Cannot find module './prebuilds/linux-x64/pty.node'`），
于是现象与"文件没拷进去"**一模一样**，而文件明明在那儿（75976 字节）。

⇒ 修：**凡是从别处拷进来的二进制，都要对它自己 `ldd` 一遍**（`.node` 也算）。
库从 8 个变成 13 个。

### 断点 ③：盒里 `/tmp` 对 agent 不可写

```
EACCES: permission denied, mkdtemp '/tmp/dsh-spill-XXXXXX'
```

单元里写的是 `--tmpfs /tmp`（没给 mode）⇒ 盒里 `/tmp` 是 **`775 root`**，
uid 1000 写不进去。而 dsh 需要一个临时目录放"溢出到磁盘"的东西。

⇒ 修：`--tmpfs /tmp:rw,nosuid,nodev,mode=1777`。

## 三、为什么这三条耗了好几轮（真正该记住的那一条）

**三条都只出现在 dsh 的 `stderr` 里，而三处都不把它露出来：**

| 环节 | 原来是什么样 |
|---|---|
| `agent-runtime.js` 的退出回调 | `reason: \`进程退出 code=${code}\`` —— **只有退出码，没有原因**。而 `stderrTail` 明明**收着**（最后 2000 字） |
| `dispatcher.js` 的 `exit` 处理 | 把原因存进 `#lastError` —— 而**没有任何地方打印它** |
| agent 起不来时给用户的话 | 走 `emitTransient`（**瞬态**）⇒ 盒里没有客户端连着 ⇒ **没有任何人看得见** |

⇒ 现象就是：**界面上只多一句含糊的话，日志上什么都没有。**
这和项目里已经记过的那几次"页面在说假话"是**同一个病**，只是这次在**日志**这一侧。

⚠️ **不许再这样**。这次的落点是三条：

1. `agent-runtime.js`：退出原因**带上 stderr 尾巴**（封顶 400 字）；
2. `dispatcher.js`：`#lastError` **必须 `console.error` 出去**；
3. `tenant-shell.mjs`：`watchForKey` 等不到时那句原来写
   *"先把服务起起来"* —— **那是假话**（宿主服务一直活着，真原因是**人还没填钥匙**）。
   改成 *"还没等到 key —— 用户还没在网页上填（填了会自动送到，不用重启这一台）"*。

> 📌 **纪律（这次学到的）**：**"起不来"这件事，必须能从日志里读出原因。**
> 一个"什么都不说"的失败，排查成本是"一句真话"的**几十倍** ——
> 这次是三条叠在一起，每一轮都只能靠猜。

## 五、还差什么（**缺一把真钥匙**）

第 ③ 步拿到的是 `401` —— 它证明**整条路都通了，只差钥匙本身是真的**。
`401` 与 `200` 之间的那一跳，**只有真钥匙能验**。

⇒ 需要：**主人自己那把钥匙**（在网页上填，或者给测试用的一把）。

* 填法：登录 → 那一屏"还你那串钥匙" → 填进去（它只送到**他自己那一台**，不落盘）；
* 填完我要看的：给他发一句话，**盒内时间线里出的是模型真的回答**，
  而不再是 `这条我没说完就断了。` / `你刚才那句我没来得及做…`。

⚠️ **我不会去读宿主上那份 `~/.dsh/.credentials.yaml` 来当测试钥匙** ——
那是一道明写下来的线（"宿主那份凭据绝不进任何租户的盒子"）。
钥匙要由**主人给**。

## 六、🔴 顺手把"失败分类器"最要紧的那一档做掉了

排这一趟的时候发现：**dsh 其实把原因说得很清楚**。

```
turn/end → reason: { kind:'error',
                     error: { message: 'Authentication Fails, Your api key: ****0000 is invalid',
                              code: 'AUTH', status: 401 } }
```

而翻译层**一律**说 *"这条我没说完就断了。"* —— 那是一句**用户没法行动**的话：
听着像"我们这边抽风了，再试一次"，于是他会一遍遍重试，
**而真正该做的是回去把那串钥匙重新填一次**。

⇒ 修：`session-translate.js` 增加 `isAuthFailure()` + `AUTH_LINE`：

> **你填的那串钥匙它说用不了。刷新一下这一页，就能重新填。**

⚠️ **这句话差点变成假话，值得记下来**：第一版我写的是"**回上一屏**重新填一次就好" ——
可这一屏（聊天）里**根本没有回填钥匙那一屏的路**：客户端只有在
`hasKey === false` 时才进得去那一屏。⇒ 那句"回上一屏"**用户做不到**。

⇒ 所以这一档要**两半一起做**（缺一半就是假话）：

| 那一半 | 做什么 |
|---|---|
| 说话 | 翻译层认出 `AUTH` ⇒ 说"刷新一下这一页就能重新填"（**可重试**，N11 要的） |
| 🔴 **把路修出来** | 宿主收到那一声 ⇒ 把**这一把**标成"用不了"（`serve.js` 里的 `badKeys`）⇒ `hasKey` 变回 `false` ⇒ **刷新真的就回到填钥匙那一屏**；他重新填一把 ⇒ **当场把那条账摘掉** |

⚠️ `badKeys` **只在宿主内存里**（不落盘、不进日志）——它是一份"这一把不灵"的账，
**不是钥匙**；钥匙照旧只在内存与盒内 tmpfs 里。

⚠️ **客户端那一半我没做**（它现在还要求用户**手动刷新一次**）。
更该做的是"那一句话一出来，界面自己回填钥匙那一屏" —— 那要客户端认得出这条消息，
**单独立项**（记在 §八）。这次只做到"说的那句话**是真的**"。


⚠️ **认不出来就退回原来那句**（宁可含糊，也**不许**把别的失败说成"钥匙不对"——
那会让人把一把好好的钥匙白改一遍）。判据在 `test/auth-failure.test.js`（7 条，带负向对照）：
`AUTH`/401 认得出；`RATE_LIMIT`/`UPSTREAM`/`socket hang up`/`max-tokens`/`completed`
**都不许**被认成钥匙不对；那句话里也不许出现内部词。

> 📌 这就是 `42` §8.4 那条欠账里**唯一"用户自己能修"的一档**，所以先做它。
> 其余（上游不通 / OOM）仍然欠着。

## 九、⚠️ 末了又抓到的四个（每一个都是"单测全绿、线上没反应"）

这一节是**这一趟最值钱的部分**：前面 §六 那套做完了、单测也全绿，
**可真机上一点反应都没有**。逐段量下去，是四个**接线**上的坑。

### 9.1 🔴 `Worlds` 少了**存下来**那一行

```
constructor({ ..., onAuthFailure = null }) {      ← 参数加了
  this.#wantTrash = trash;
  this.#now = now;
  // ✗ 少了：this.#onAuthFailure = onAuthFailure;
}
...
onAuthFailure: this.#onAuthFailure ? () => ... : null,   ← 往下传的那行也加了
```

⇒ `#onAuthFailure` **永远是 `null`**，整条链子**静默断掉**。
而我那两条单测都是**直接打 `Dispatcher`** 的 ⇒ **全绿**。

⚠️ 教训：**接线的每一段都要有一条闸"从外面"打进来**。
⇒ 补了一条 **Worlds 级**的用例（造一个真的 `Worlds`，走它给的那条路），
并做了**变异验证**：把那行删掉 ⇒ **正好那一条红**。

### 9.2 🔴 那条 `key-bad` 消息**静默丢了**

`notifyHost` 原来直接把隧道那个 `send` 挂出去，而它写的是 `conn?.write(...)` ——
连接**恰好在重连**时**写进了空气**，调用方却以为说成了。
现象：**容器日志说"我告诉宿主了"，而宿主什么都没收到。**

⇒ 两处改：① `notifyHost` **如实返回"说出去了没有"**；
② 没送到就 **`dropTunnel()` 掐一下**：三秒后它自己连回来，
   `tunnel-ready` 里会**自报**"我这儿有没有钥匙" —— 那是一条**一定会送到**的路。

### 9.3 🔴 "宿主说没有"和"容器说没有"，两边要互相对得上

加了 `onKeyBad(userId, why)`，**两种情形分开**：

| `why` | 什么时候 | 做什么 |
|---|---|---|
| `rejected` | 上游回 401（**确认**这把不灵） | 标成"要重填"（`badKeys`） |
| `absent` | 容器自报"我这儿没有钥匙"（重启过 / 被撤了） | **只清宿主那本账**，**不许**标成坏的 |

⚠️ 混成一种的话，**容器每重启一次就会把用户一把好好的钥匙标成坏的**。
⇒ 补了一条带负向对照的用例钉这件事。

### 9.4 🔴 那个"等钥匙"的循环**领到一把就收工了**

```js
if (ok) { log('  ✓ 凭据就位 —— 不再等了'); return; }   // ✗ 于是只有第一把能送到
```

⇒ **换的那把 / 重填的那把，全都没人接**（宿主推了个空）。
更坏的是宿主那本账已经是"有钥匙" ⇒ **用户看着有钥匙、而模型那条路其实不通**。

⇒ 改成**一直守着**：每送到一把就隔一会儿重连一次继续等；
重连时那一下还会发 `need-key`，宿主手上有的**立刻回给它**（空窗也不会丢）。
⇒ 也补了闸 + **变异验证**（退回"领到就收工" ⇒ 正好那条红）。
**实测**：填错 → 撤掉 → **再填一把 ⇒ `hasKey` 变 true 而且盒里真的有那把**
（`creds.yaml` 里读到了那串的尾巴）。

### 9.5 🔴 去重挡住了**第二次**撤销（用户会卡住）

`onAuthFailure` 开头原来是 `if (badKeys.has(userId)) return;` ——
于是**一个容器一辈子只会撤一次钥匙**：用户**第二把又填错**时，
盒里那本账还记着"说过了" ⇒ **不删、不告诉宿主** ⇒ 宿主 `hasKey` 还是 `true`
⇒ **他刷新也回不到填钥匙那一屏**。
⚠️ 宿主清那本账的唯一时机是"他又填了一把"，而**盒里那本没人清**。

⇒ 改成**每次都真做，去重只留给日志**。
**实测**（连着两把错的）：第一次 ⇒ `false`；再填 ⇒ `true`；第二次 ⇒ **`false`** ✅

> 📌 **这一节四条是同一件事**：*"我这段代码是对的"* 与 *"它在真机上真的发生了"*
> 之间隔着一整条**接线**。⇒ 每加一条链子，**闸要从最外面那个入口打进去**，
> 而且**每条都要做变异验证**（不然你只是又写了一遍自己的假设）。

## 九、🔴 主人报「我无法黏贴，为啥」（2026-09-21）

**根因**（不是我们代码写错了）：Flutter 把字画在 **canvas** 上，
长按弹的是**它自己的**选择菜单 —— 而**空输入框里没有可选的文字**
⇒ **菜单不弹 ⇒ 没有"粘贴"**。
桌面浏览器按 `Ctrl+V` 没事；**手机没有物理键盘就卡在这儿**。

⚠️ 而这一屏要的恰好是"**粘一长串钥匙**" ⇒ **没有按钮就是进不去**。
（同一类：`[SO 78506316](https://stackoverflow.com/feeds/question/78506316)`、
`MediaQueryData.supportsShowingSystemContextMenu`。）

**修法**：**给一个「粘贴」按钮** —— 按钮一按就是"用户手势"，能合法读剪贴板。

| 改哪 | 怎么改 |
|---|---|
| 钥匙屏 | 输入框下面一个「粘贴」；读到就填进去；**读不到就说清"还能怎么办"**，而且**不许清空他已经填的** |
| 聊天输入条 | 左边一个粘贴图标；**接在光标处**（他可能已经打了一半），**不是**替换掉 |

**闸**：`test/widget/paste_test.dart` **5 条**（含三条负向对照：读不到 ⇒ 不清空 · 空剪贴板 ⇒ 什么都不插 · 内部词）。

⚠️ 这条规矩**进了手册**（`08-SPEC.md` §6.7 第 5 条）：**它是"这一类的"，不是"这一屏的"** ——
以后任何"要粘东西"的新输入框都得带上它。
