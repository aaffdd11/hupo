## 一、① `ask` 搬到 app 原点（✅ 2026-09-30）

> **原话**：*「这些功能都要有」*。而这一片是**已经在用的能力**在补齐两端 —— 比新做一样更值钱。

### 1.1 它原来为什么"只有网页有"

`ask` 原来只有**一条**路：制品 `postMessage` → 壳（Flutter）→ `/api/app-ask` → 本机小代理 → 模型。
🔴 而**安卓那一侧不许装桥**（手册铁律 3）⇒ 平板上那个小程序**问不了话**（页面收不到"壳在"那句
`hupo-ready`）。这不是漏做，是那条路**天生**只有网页能用。

### 1.2 现在什么样（和存东西**同一个形状**）

| 那一刻 | 形状 |
|---|---|
| 制品发一句 | **`POST /ask`**（**对它自己那个源**），正文 `{id, v, u/e/s 或 ticket, prompt}` |
| 凭据 | 和 `/db` **同一套**：入口签名换一张**会话票**，之后用票（`appTicketOf`，绑人绑 app） |
| 判定 | 🔴 **和 `/api/app-ask` 同一个函数**（`server.js` 的 `askForApp`）：**声明 → 他允许 → 配额 → 花在谁的环境里** |
| 花在哪 | 主人 / 单租户 ⇒ **本机**那个小代理；**租户 ⇒ 过隧道进他盒子**（钥匙在他盒里 —— `app-ask.js` 顶上那条） |
| 回来 | `{ok:true, text, left, max, ticket}`；被拒 ⇒ `{ok:false, status, error, text}`（**人话在 `text` 上**） |

⇒ **网页与安卓吃同一个 CSP 头、走同一条路** ⇒ **两端都通，而且不再依赖壳**。
⚠️ **壳的桥一个字没删**（旧页面照旧能用）；新页面**不必**再等 `hupo-ready`。

### 1.4 给**创建小程序的 agent** 的规则（页面里那段）

```html
<script>
// 用他的钥匙问一句（花他的钱：每问一次算一次，每天有上限）。
// 规矩：① 对它**自己那个地址**发一次请求（两端都通，不用等壳）
//      ② 第一次带入口 URL 里那三样（u/e/s）换一张票，之后用票
//      ③ 被拒就**如实显示**（"没说要问话" / "还没允许" / "今天问得够多了" / "问得太快了"）
const Q = new URLSearchParams(location.search);
const VER = (location.pathname.match(/^\/a\/[^/]+\/([^/]+)\//) || [])[1] || 'live';
let askTicket = null;
async function ask(prompt) {
  const body = askTicket
    ? { id: APP_ID, v: VER, ticket: askTicket, prompt }
    : { id: APP_ID, v: VER, u: Q.get('u'), e: Q.get('e'), s: Q.get('s'), prompt };
  const r = await fetch('/ask', {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify(body),
  });
  const j = await r.json();
  if (!r.ok || j.ok !== true) throw new Error(j.text || '没问成');
  if (j.ticket) askTicket = j.ticket;
  return j.text;
}
</script>
```

⚠️ **页面要能没有它也能用**：`ask` 要**声明了 ＋ 他允许了**才有；拿不到就问不了 ——
那时候**别摆一个按了没反应的按钮**，说一句人话（"这一句得先允许它用你的钥匙"）。
