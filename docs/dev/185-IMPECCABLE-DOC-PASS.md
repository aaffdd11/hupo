# 185 · 用 impeccable 过一遍参赛文稿（能用的用，不能用的说清）

> **主人 2026-10-04 原话**：
> *「找一下 guthub 的 impeccable 项目，是做界面的。帮我看看这个能不能用来帮我把这个设计说明做漂亮？」*

**结论一句话**：**能用，而且我已经用它扫过、改过一版** —— 但它不是"套上去就变漂亮"的模板，
它是一套**给 AI 用的设计规矩 ＋ 一个能扫文件的检查器**；对**文稿（HTML→PDF）**能用的那一半，
我用上了；**给网页 App 的那一半**（悬停 / 状态 / 动效 / 组件）跟印刷文档没关系。

---

## 一、它是什么（读的是仓库本身，不是二手介绍）

| 项 | 事实 |
|---|---|
| 仓库 | [`pbakaus/impeccable`](https://github.com/pbakaus/impeccable) —— 作者 Paul Bakaus（jQuery UI 那位） |
| 一句话 | *"The design language that makes your AI harness better at design."* |
| 装法 | `npx impeccable install`，然后在 AI 工具里用 `/impeccable <命令>` |
| 里面有什么 | **1 个 skill ＋ 24 条命令**（`polish` / `typeset` / `layout` / `colorize` / `distill` / `bolder` / `quieter` …）＋ **61 条确定性检测规则**（CLI 与浏览器插件都能跑，**不需要钥匙、不调模型**） |
| 依据文档 | `skill/reference/craft-floor.md`（工艺底线：对比度 / 间距 / 字号 / 状态 / 拒绝的套路）＋ `docs/STYLE.md`（**写作**那份：一长串"AI 味"词与句式，构建时会 fail） |
| 许可 | Apache-2.0 |

⚠️ **它长在"前端界面"上**：检测器认的是 HTML/CSS/React/Tailwind 那些信号
（紫色渐变、卡片套卡片、发光阴影、Inter 字体到处用…）。**印刷文档只占其中一小半。**

## 二、我拿它扫了这一份文稿（真跑，不是"看介绍")

```bash
git clone --depth 1 https://github.com/pbakaus/impeccable /tmp/impeccable
node /tmp/impeccable/cli/bin/cli.js detect docs/contest/submission.html
```

**扫之前 56 条，扫之后 51 条**（同一份文稿、同一把尺子）。区别在**种类**：

| 它报的 | 我怎么办 |
|---|---|
| `low-contrast` **8 条**（示意图里那几个箭头 `#a09889` 压在 `#fbfaf7` 上，2.7:1，需要 3:1） | ✅ **真问题，改了**：箭头换成 `#6f685d` ⇒ 这一类**清零** |
| `wide-tracking` 1 条（大标题 `letter-spacing: 1pt`） | ✅ **改了**（标题字距归零 —— 中文标题本来就不该拉字距） |
| `em-dash-overuse`（**38 个破折号**，advisory） | ✅ **改了**：19 处 `——` 砍到 6 处（同一句话改成逗号 / 冒号说）⇒ 这条 advisory **不再出现** |
| （不在检测器里，在 `craft-floor.md` 的"拒绝清单"）**左边一条色杠的告示牌** | ✅ **改了**：原来那几块"重点提示"是 `border-left: 3pt` 金色竖条 —— 正是它点名禁止的"侧边色条" ⇒ 改成**整块浅底**（没有竖条） |
| `justified-text` **37 条**（两端对齐没开连字符） | ⛔ **不改，故意的**：这条是给**拉丁文**写的（靠 `hyphens: auto` 防"白河"）；**中文印刷本来就是两端对齐**，而且中文不需要连字符。⇒ 我按它的**本意**处理：加上 `text-justify: inter-ideograph`（汉字之间分配空隙），下一条会说清 |
| `tight-leading` **14 条**（报 `line-height 0.18x`） | ⚠️ **判不出来，如实说**：报出来的 0.17/0.18/0.19 **正好等于** `line-height 的倍数 ÷ 字号(pt)`（1.6 ÷ 8.5 = 0.19、1.75 ÷ 10.5 = 0.17）——**像是把无单位的行距当成了 pt**。我在一个最小文档里复现不出来（同样的 `font-size: 8.5pt; line-height: 1.6` 扫下来是干净的），所以**不敢说它就是工具的 bug**，只能说：**我们这边每一处行距都在 1.5–1.75 之间，屏幕上也是对的**（这条没改，留着；真要较真可以给它提个 issue） |

**顺带记一句它的好处**：`docs/STYLE.md` 那份**写作**清单（禁 `delve` / `seamless` / `robust` / `elevate`
/ `in summary` / `moreover`…一长串"AI 味"）对我们写文稿**比设计那半更值钱** ——
它逼你"指名道姓、给数字、动词打头、长短句交替、别用开场白"。

## 四、这一版**没做**的（说清，不是"以后再说"）

* ⚠️ **没把 impeccable 装成这个仓库的 skill**（`npx impeccable install`）—— 那会改"我下次开机读什么"，
  属于**改自己**那一类（手册 §八 P1/P2），要主人点头。今天只是**把仓库 clone 到 `/tmp` 里跑了一次检测**，
  **一个字节都没进我们的仓库**。
* ⚠️ **没顺它那条 `/impeccable polish` 流程改造产品界面**（琥珀自己的界面）—— 那是另一件事：
  产品界面的规矩在我们手册里（`D3` 那一组 + `08-SPEC.md` §6），要不要请它来"挑刺"得另开一轮。
* ⚠️ **那张截图没换**（还是真机真账号那张）；文稿里没有"插画"，也没有它禁止的那些花样
  （渐变字 / 玻璃拟态 / 卡片套卡片 / 假图标），所以那几条**一条都没触发**。

## 五、要不要装它？（**等主人拍板**）

| 选项 | 说明 |
|---|---|
| **甲：不装**（今天的做法） | 需要时 clone 到 `/tmp` 跑一次检测；不改"我下次开机读什么" |
| **乙：装成 skill**（`npx impeccable install`） | 以后我写界面/文稿前会主动按那套规矩做；代价：它进了我每轮会读的地方，得留痕（改自己那类） |
| **丙：只用它的写作清单** | 把 `docs/STYLE.md` 的"AI 味"清单抄成我们自己的**文案自检**（不依赖它）—— 最轻 |

**我建议丙 ＋ 甲**：把那份**写作清单**抄进我们自己的规范（文案本来就有硬闸那一套），
设计检测**用的时候 clone 跑一次**；等哪天真要按它改造产品界面，再考虑乙。
