## 一、第 16 条：**浏览器那条路，终于有自动证据了**

### 1.1 这笔账为什么最该先还

`w.stalkerai.cn` 上那条流**曾经整整一段时间一次都没连上过**（客户端在 https 页面上拼出
`ws://`，被浏览器按混合内容拦掉），而当时**所有闸都是绿的** ——
因为验收用的是 node 探针，**探针把 `wss://` 写死了**，正好绕过了客户端自己算地址的那一行。
⇒ 手册因此加了 **V13**：**凡是客户端自己算出来的东西，闸要打在客户端这一侧。**
而"客户端这一侧"最硬的形态就是：**真开一个浏览器**。

### 1.2 `scripts/check-web-browser.mjs`（新）

```bash
HUPO_TOKEN=<令牌> node scripts/check-web-browser.mjs --shot /tmp/shot.png
```

它做两件事，**一件都不能省**：

| # | 做什么 | 为什么必须有它 |
|---|---|---|
| ① | 接 CDP，看**那个页面自己**建的 WebSocket：建了几个、断过几个、**收到几帧**、认出哪些事件类型 | 这正是 `ws://` 那类 bug 的**唯一可观察信号**（页面能开、接口能答，就那条流不通） |
| ② | `--shot` 存一张 **PNG 截图** | Flutter web 把字画在 canvas 上，**DOM 里没有文本** ⇒ "页面上到底写了什么"查 DOM 查不到，**看一眼**最诚实 |

**退出码分三种**（"环境不具备"不等于"路坏了"）：

```
0  路通了
2  没通（而且它会告诉你"这是 ws:// 那类 bug 的形状"）
3  环境不具备（没浏览器 / 没令牌）
```

⚠️ **令牌而不是口令**：脚本从 `HUPO_TOKEN` 拿令牌（可撤销），**不碰主人的口令**。
要一个令牌：用 `v2/services/core/src/auth.js` 的 `Auth.issue()` 发一个（本地发，别写进任何文件）。

### 1.3 ⚠️ 两个**花了四轮才挖出来**的事实（下一个碰本地存储的人省几小时）

第一次跑，这个检查**报"没通"** —— 而线上明明是通的。四轮才挖到底：

| 轮 | 现象 | 根因 |
|---|---|---|
| 1 | 0 个 WebSocket、截图是**登录页** | 我的"先开一次 → 灌令牌 → 刷新"赌输了：第一次导航还没 commit 时 `Runtime.evaluate` 落在**空源**上，`localStorage.setItem` 抛 `SecurityError`。⇒ 改用 CDP 的 `addScriptToEvaluateOnNewDocument`（下一份文档一开头就带令牌） |
| 2 | 令牌"就位"了，**还是 0 个 WebSocket** | **键名带前缀**：`shared_preferences_web` 里 `_defaultPrefix = 'flutter.'` ⇒ 真键是 **`flutter.hupo_auth_token`**，我灌的是裸名 |
| 3 | 两个键都在了，**还是 0** | **值也不是裸串**：插件 `_encodeValue = json.encode(value)`，读的时候 `json.decode` **解不开就静默返回 null** ⇒ App 当"没有令牌"。我灌的裸串一直解不开 |
| 4 | 换对之后 | ✅ 1 条 WebSocket、**61 帧**、认出 `user/echo / message/start / message/text / message/end / client/hello` |

⇒ **两条可复用的结论**（客户端本机存东西都走这个插件）：

```
键：localStorage['flutter.<key>']        ← 插件自动加 `flutter.` 前缀
值：localStorage[...] = JSON 字符串     ← json.encode 过的（带引号）
```

⚠️ 顺带说一句：**第 3 轮那种失败是静默的**（`_decodeValue` 解不开就返回 null，不抛），
所以"值灌错格式"在 App 那一侧**看不出任何异常** —— 只能靠**先把事实打出来**
（localStorage 的键名、页面的报错）才知道往哪查。这也是为什么检查里留了那两行诊断。

## 二、第 9 条：`$DSH_HOME/sessions/` 有上限了

### 2.1 ⚠️ 两条实测发现，都是"照直觉做就会删错东西"

| # | 发现 | 照直觉做会怎样 |
|---|---|---|
| 1 | 盘上是**两层**：`sessions/<项目>-<路径slug>--/<一条记录>/`。**顶层是按项目分的组** | 不分组地清 ⇒ 连**别的项目**和**这个 GUI 自己的可 resume 记录**（32MB）一起删掉（AGENTS §六.5） |
| 2 | DSH 是**原地追加** `session.v3.jsonl.zstd` ⇒ **目录的 mtime 比里面的文件还旧**（实测 16:20 vs 16:23） | 只看目录 mtime ⇒ 把**正在写的**那份看成"三分钟没动过" |
| 3 | `session.lock` 上有 **flock**：跑着的那份 `flock -n` 拿不到，结束的那份拿得到 | 只靠 mtime 判断"没人用" ⇒ 可能删掉正在跑的 |

⇒ 所以：**组目录永远不是候选**（默认只动 `HUPO_AGENT_CWD` 推出来的那一组）·
mtime 量的是**整棵树里最新的那个** · 再加一道 `flock` 探针（**三态**：锁着 / 没锁 / **不知道**，
不知道就退化成只看 mtime **并在输出里说出来**）。

### 2.2 三个文件

* `v2/services/core/src/prune.js` —— `planPrune`（**纯函数**，不碰磁盘）/ `scanEntries` / `applyPrune`（真删，`rm` 可注入）/ `probeLock` / `summarize` / `groupSlugFor`
* `scripts/prune-sessions.mjs` —— CLI：**默认只列出来**，要真删得显式 `--apply`（删数据，默认必须在安全那一侧）
* `serve.js` 接线 —— **开机顺手清自己那一组**（只在自己那组、且**不许阻断启动**：出任何事只记一句）

阈值（都写成有名字的常量 + 量级理由）：**保护窗 30 分钟**（=10× 单轮收口 180s）·
**保底 5 条**（=进程上限 4 + 1）· **保留 7 天** · **容量 512MiB** · **条数 300**。

### 2.3 ⚠️ 今天的实话：**一份都不用删**

```
$ node -e "…planPrune(scanEntries(自己那一组))…"
现在没有该清的旧记录，一份都不用动。
```

最老的记录才 3 天、40.6MB 全在阈值内。
⇒ 这笔账交付的是"**上限从此存在**"，**不是**"今天删了一批"。
要它今天就降下来，只能调小那 7 天 / 512MiB —— 而那会删到 3 天内的记录（**含这个 GUI 自己的会话**）：
**这件事该由主人定，不该由助手顺手改默认值。**

## 三、第 18 条：打了还没发出去的那句话，刷新不丢了

详见 `21-DRAFTS.md`（客户端同学写的）。这里只记**三处判断**：

| # | 判断 | 为什么 |
|---|---|---|
| 1 | 读回来时 `sent` **降成 `failed`** | 走到 `sent` 只说明 HTTP 200 到过、回执没来；刷新后回执**永远不会来** ⇒ 留 `sent` 屏幕上写「已送到」却**没有「重发」入口**：用户既不知到没到、也无法再试 = **说假话 + 违反 N11** |

| 3 | 两本账**不重叠** | `timeline_store` 管服务端事实（带号的），`draft_store` 管"我这边还没被认领的话" |
