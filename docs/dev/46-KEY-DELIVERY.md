# 46 · 钥匙怎么进来（三个入口 · 住哪 · 谁能读）

> 主人 2026-09-22：*"容器内也可以设置 key"* ⇒ 追问后拍板：
> **甲**（钥匙**落盘到卷里**，重建容器不丢）+ **"还要能从外面投进去（不动 root）"**。
>
> **它推翻了一条明确记过的事**：`build-tenant-image.sh` 里原来写着"钥匙**故意不在 `/data`**
> （那是卷、会落盘）"。⇒ 这一篇就是那次改动的契约，**连同代价一起写清**。

---

## 一、为什么改（不是洁癖，是疼）

原来钥匙只住在容器里的 **tmpfs**（`/run/hupo/creds.yaml`）。⇒ **容器一重建，钥匙就没了。**
2026-09-22 那次迁移（把单元补上产品层挂载）两台各重建了一次 ⇒
**主人之前贴过的钥匙当场作废，得重新贴一遍**。

而且这件事**只有"重建容器"才碰得到** —— 而重建容器恰好是这套东西**以后要经常做的事**
（换运行层、换镜像、改挂载表）。⇒ 每次都要用户重贴一次钥匙，是不能接受的。

---

## 二、钥匙住哪：**卷里**（`/data/creds.yaml`）

| 项 | 值 | 为什么 |
|---|---|---|
| 路径 | `<HUPO_DATA>/creds.yaml`（容器里就是 `/data/creds.yaml`） | 卷 = 只有重建**容器**才换，重建**机器**也还在 |
| 属主/权限 | **`root:root 0600`** | 读它的只有容器里的 root（服务 + 小代理）；**agent 是 uid 1000** |
| 写法 | **原子**（先 `.tmp` 再 `rename`）+ 写完 `chmod 0600` | 小代理**每次请求现读** ⇒ 直接写会让它读到**半个钥匙** |
| 谁能读 | 容器 root · 宿主上"他那台"自己（同一身份） | `agent(1000)` **读不到**；`/data` 是 root `0711` ⇒ 它连**列**都列不出来 |
| 谁能写 | 容器 root（服务 / 小代理 / `put-key`） | ⚠️ **agent 写不进去**（`/data` 没有写位）⇒ 它**换不掉**自己那把钥匙的**来源** |
| 中心（宿主服务） | **看不到** | 租户家目录 `0700` ⇒ `deploy` 连读都读不到（这条边界没动） |

### 2.1 🔴 它**没有**破坏决策 ①（agent 读不到自己的 key）

决策 ① 要的是"**agent 读不到自己的 key**"，不是"钥匙只能在内存里"。边界是
**uid 换手 + 权限位**，那两样一个都没动：

* agent 是 **uid 1000**（服务 spawn 时降权），而文件是 **root 0600**；
* `/data` 是 **root 0711**：agent 能**穿过去**（它自己那几格在下面），但**列不出、建不了**。

⚠️ **这两条必须真验**，而且要**挑一个存在的路径**去读 —— 拿一个不存在的路径只会得到
`ENOENT`，那证明的是"路径不存在"，不是"读不到"（这个项目栽过）。
判据：**agent 读它必须是 `EACCES`**，正对照是 **root 读得到**。

### 2.2 代价（如实写，不藏）

| 代价 | 说明 |
|---|---|
| **钥匙落盘了** | 从"只在内存 + tmpfs"变成"**在用户自己那台容器的盘上**"。谁能读到那块盘（宿主 root、或者将来给卷做备份/导出的人）就能拿到那把钥匙 |
| 镜像重建那次仍然会丢吗 | **不会** —— `/data` 是卷，不在镜像层里 |
| "不灵了"那把会留着吗 | **不会**：上游回 `AUTH` 时容器会把那个文件**删掉**（照旧，见 `serve.js` 那条 unlink）⇒ 它也就不会一直拿一把废钥匙去试 |
| 导出会不会把它带出去 | **不会**：导出的是一段文字（`export.js` 是纯函数、只看时间线），**不扫文件系统** |

## 三、三个入口（谁用哪个）

| # | 入口 | 谁用 | 要 root 吗 | 备注 |
|---|---|---|---|---|
| 1 | **网页上填**（照旧） | 用户自己 | 不要 | 中心当管道推给他那台容器；**中心内存里那一份仍然不落盘** |
| 2 | **盒内放**（`put-key`） | 主人（开发/救急） | 要（`podman exec`） | `podman exec -i <容器> /bin/node /app/code/src/put-key.mjs`，粘钥匙、回车、Ctrl-D |
| 3 | **本机投递**（丢一个文件） | 主人 | **不要** | 往 `<投递目录>/<租户名\|编号\|手机号>.key` 里写一把，宿主会替他送进那台容器 |

⚠️ 三个入口**最终都写同一个文件**（`/data/creds.yaml`）⇒ 谁是最后写的，谁生效。
没有"第二份真相"。

### 3.1 入口 2：盒内放（`src/put-key.mjs`，住在**产品层**）

* 盒子里**没有 `/bin/sh`** ⇒ 它就是一行 node（盒子里的 node 在 `/bin/node`）。
* 它**复用**网页那条路的同一套：字段名 `HUPO_MODEL_KEY`、原子写、`0600`（`tenant-shell.writeKeyFile`）。
* 空钥匙 / 带不可打印字符 ⇒ **拒**（和网页那条路同一条规矩：能被 HTTP 头带走的字符）。
* 打完只回一句"放在哪、不用重启"，**不回显钥匙**。
* 它住在**产品层** ⇒ 跟着自动更新走，改它**不用 root**。

### 3.2 入口 3：本机投递（`deploy` 自己的目录，**不用 root**）

```
<投递目录>/hupo-a.key        ← 用租户名
<投递目录>/u1.key            ← 用编号
<投递目录>/13800000000.key   ← 用手机号
```
* 默认投递目录：`~deploy/.hupo-keys`（`0700`）—— 只有 `deploy`（= 主人）放得进去。
  ⇒ **它不新增任何能力**：这台机器上能写那个目录的人，本来就能直接跑
  `scripts/...` 和 `podman exec`。
* 🔴 **送到才算送到**：文件**不会**一读到就删 —— 要等那一台**自报"我有钥匙了"**
  （`tunnel-ready.hasKey:true`）才删。那台没在跑 ⇒ 文件**留着**（主人一眼看得见，重试即可）。
  ⚠️ 为什么不能"读进内存就删"：**中心内存里那份不落盘**，宿主一重启就没了 ⇒
  会在"其实没送到"的情况下把主人的文件删掉（那是**丢东西**，不是省事）。
* **认不出的名字**（写错、`../`、没有 `.key` 后缀）⇒ 移到 `<投递目录>/.rejected/` 并**说清为什么**。
  **不许静默删掉** —— 那里面可能是一把真钥匙。
* 日志里**只**出现"谁投的、投给哪台、送到没有"，**永远不出现钥匙本身**。

## 四、宿主得如实知道"那一台现在有没有钥匙"

钥匙现在**在容器里**，而中心只有内存。⇒ 两个方向都要能听见：

| 什么时候 | 谁来说 |
|---|---|
| 用户在网页上填 ⇒ 中心推给容器 | 中心自己知道（它刚推的） |
| 主人用 `put-key` 在盒里放了一把 | **容器自己重新自报**（`tunnel-ready`）—— 见下面那条 |
| 那把被上游拒了 ⇒ 容器删掉它 | 容器自报 `hasKey:false`（已有） |
| 容器重建 / 重启 | 容器一连上就自报（已有） |

🔴 **新加的那一条**：容器要**盯着那个文件在不在**，一变就重新自报一次
（`presenceChanged`）。不这么做的话，主人用 `put-key` 放进去之后，
**宿主那一屏还会一直说"还没有钥匙"** —— 那就是页面在说假话。

⚠️ 而且"自报 `hasKey:true`"这一件事要**顺手把中心那本"这把用不了"的账清掉**：
那一把已经被删了（`AUTH` 那条路），现在盒里是**另一把**。
不清的话，用户明明换了一把好的，界面上还挂着"刷新一下重新填"。

## 五、判据（`scripts/check-key-delivery.sh`，每条都带负向对照）

| # | 验什么 | 负向对照 |
|---|---|---|
| 1 | 钥匙文件在**卷**里（`/data/creds.yaml`）、`0600 root` | 写到 `/run/hupo`（tmpfs）⇒ 判据必须红 |
| 2 | 🔴 **agent(1000) 读它 ⇒ `EACCES`** | 挑一个**存在**的路径（不许拿不存在的路径糊过去）；正对照：**root 读得到** |
| 3 | **agent 写不进去**（换不掉它） | 正对照：root 写得进去 |
| 4 | `put-key`：空钥匙 / 不可打印字符 ⇒ 拒 | 好钥匙 ⇒ 成，而且文件是 `0600` |
| 5 | 投递名：`../`、没有 `.key`、认不出的名字 ⇒ **拒绝并留证据** | 正常的三种名字（租户名 / 编号 / 手机号）⇒ 都能认出来 |
| 6 | 投进去的一把：**送到之后文件才被删** | 那台连不上 ⇒ 文件**还在**（不许先删） |
| 7 | 日志与账本里**不出现钥匙** | 判据自己合成一条"带钥匙的日志" ⇒ 抓得住 |
| 8 | 重建容器之后钥匙**还在**（这是这一篇存在的理由） | —— |

## 六、这一批**不需要 root**

入口 2、3 都住在**产品层**或**宿主服务**里 ⇒ 走一次 `build/verify/publish` 就生效
（`45-TENANT-UPDATE.md` 那条路）。**唯一要动 root 的事一件都没有。**

## 七、🔴 实测：这一批在**一个小时里连栽三层**（同一个病）

每一层单独看都"实现对了"，合起来就是**放钥匙的说放好了、用钥匙的还在看别的地方**。
三层都是同一个病的不同外衣：**这条规则住在不止一处，或者住在一个发布带不动的地方**。

| # | 我写的 | 现象 | 根因 |
|---|---|---|---|
| ① | 把"钥匙住哪"的规则写在**入口** `entry.mjs` 里 | 产品层发布之后，容器里那个服务**照样按 tmpfs 找** | **入口是镜像里生成的东西**（`build-tenant-image.sh` 写进 `$R/app/entry.mjs`）⇒ 那条改动**发布带不动** |
| ② | 把规则挪进产品层，但**默认值**写在 `watchForKey({ keyFile = adoptKeyFile() })` | 容器日志仍说"拿到凭据了"，而**卷里没有那个文件** | **默认值只在参数是 `undefined` 时生效** —— 而镜像里的旧入口是**显式**传 `keyFile: '/run/hupo/creds.yaml'` ⇒ 默认值被绕过。⇒ 归一必须写在**函数体里** |
| ③ | 看门那个（"钥匙在不在"）拿**第一拍看到的样子**当基线 | 钥匙在"报到之后、第一拍之前"出现 ⇒ **永远不提示宿主**，页面一直说"还没有钥匙" | 基线必须是**最后报给宿主的那句话**（`announcedKey`），不是"我第一次看到的样子" |

⇒ **从结构上断掉它**（这一批最后做的）：**镜像里只留一个薄加载器** ——
它只做三件（找产品层 / 把版本指纹塞进 env / 把产品层的真入口跑起来），
**其余全搬进产品层的 `src/entry.mjs`**。理由一句话：
**"改一次接线就要重造镜像"这件事，本身就是缺陷。**

⚠️ 顺带修的两处：
* **投递那条路要有界重试**：第一次推送可能根本没落地（那一台正在重连、或者刚被重建）
  —— "送过就算数"会让文件永远不删、钥匙永远不进容器、**而谁都不报错**。
  现在每 30 秒再送一次，直到它**自己说拿到了**（实测第 10 次送到）。
* **"我在宿主还是盒里"要显式**：原来靠"有没有通道"猜 ⇒ 冒烟跑（`--run`）没有通道，
  于是它按"我是宿主"起、横幅报了一个盒里不存在的投递目录（**在说假话**）。
  ⇒ 单元现在明确给 `HUPO_ROLE=tenant`。

### 7.1 真机验过的东西（2026-09-22）

| 验什么 | 结果 |
|---|---|
| 盒内 `put-key` 放一把 | ✅ 落在 `/data/creds.yaml`（`0:600`）；盒里那个服务按同一条规则找到它 |
| 🔴 **agent(uid 1000) 读它** | ✅ **`EACCES`**（正对照：root 读得到；agent 也**写不进**去） |
| **重建容器**（`podman rm -f` + 重启） | ✅ 钥匙**还在**（这一篇存在的理由） |
| 换了运行层（重造镜像 + 重建两台） | ✅ 钥匙**还在**（卷不动） |
| **本机投递**（`deploy` 身份，不用 root） | ✅ 送到之后**文件才被删**；中间失败会重试并**如实说** |
| 认不出的名字 | ✅ 挪进 `.rejected/` 并说清为什么（**没删**） |
| 日志 / 账本里出现钥匙 | ✅ 一条都没有 |
