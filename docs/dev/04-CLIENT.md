## 二、五条硬要求，以及为什么

### 2.1 四态，且**不许只靠颜色**

`queued / sent / confirmed / failed`，每态配 **图标 + 文字**。

为什么不能只靠颜色：色盲、屏幕反光、平板在阳台上——**颜色是最不可靠的通道**。
09 的原话是"界面把'发不出去'显示成'发出去了'"，那是 8/10 放弃点里最狠的一条。

### 2.2 ⚠️ `queued → confirmed` **必须允许**（测试抓出来的）

我一开始只留了 `queued → sent → confirmed`，被测试当场推翻：

> **WS 的回执完全可能比 HTTP 响应先到。**
> 禁掉这条直连之后，回执先到时会被当成"不允许的转移"丢掉，
> 而界面会**永远停在"已交出去"**。

### 2.3 排序键是 `(seq, tie)`，**不是时间戳**

本地发言借用"当前最大号 + tie=1" ⇒ 排在**已收到的之后、下一条服务端事件之前**。

**不许用时间戳**：本地发言是客户端钟、服务端事件是服务端钟，
**混钟当排序键会乱**——而现网是刻意避免混钟的。

### 2.4 回执"认领"本地那条，不是再插一条

`user/echo` 带着同一个 `messageId` 回来 ⇒ **认领**（把本地那条的号换成服务端的）。
不认领的话，用户会看到自己说的话**出现两遍**。

### 2.5 输入条**只重建按钮，不重建输入框**

> 探针里我每敲一个字就 `setState` 重建整页（含输入框）。
> 那是 Flutter 里一个**已知会把输入法合成搞乱**的写法——
> 而"打不了字的人能不能用"整条结论就压在输入法上。

⇒ 这里用 `ValueListenableBuilder` **只包住按钮**，`TextField` 全程不被重建。

另外：**输入条刻意没有 `enabled` 参数**——手册 D5.14 说"打字框永远不许锁"，
留个开关就等于留个"哪天有人顺手把它关掉"的机会。

## 四、⚠️ 这一批**没做**什么

| # | 没做 | 为什么 |
|---|---|---|
| 1 | **agent 运行时** | **说了话没人接**——现在只回自己的 `user/echo`，没有任何回答 |
| 2 | **200ms 本地应声** | 它是**助手侧**的话（"收到"）。没有 agent 就没有"谁在应声"，**编一句出来就是撒谎** |
| 3 | **浮窗 / 图标墙** | 那是**手机**形态（Z1–Z3）。web 先做整页，形态对了再做浮窗 |
| 4 | **收起态重发** | 没有收起态 |
| 5 | **任务 / 通知 / 记忆出口** | 那些要有 agent 才有内容 |
| 6 | **语音** | 输入法自带的那条路已经覆盖（v1.1） |
