## 一、怎么跑

```bash
bash scripts/check-scope-boundary.sh            # portable：复用 6 份测试（**不碰真机**）
bash scripts/check-scope-boundary.sh --live     # 再加"真机"那几条（⚠️ 这台机器**就是**线上机）
```

- 退出码 = 失败数（0 ⇒ 通过）。
- 末尾固定打印 **`通过 N · 失败 M`**；有跳过的会明写「跳过的**不是**过的」。
- 读不出读数 / 算不出来 ⇒ 该条**记失败**并在行里写 `不可算`（不许安静地绿）。

## 三、真机那几条怎么做到"改动很小、能自己收干净"

1. **探针 id 一律 `probe-` 前缀**（`probe-scope-<pid>`），而且脚本自己 assert 这个前缀。
2. **scope 落在临时目录**（`mktemp -d`）—— 不碰任何真实用户的世界；只有**上架那一下**会碰到**真共享库**
   （`<data>/published-apps/`），这正是判据六要的"全库搜"。
3. 跑完（`finally`，无论成败）：
   - 删掉真共享库里那个探针目录；
   - 把 `published-apps/audit.jsonl` **逐字节复原**（只认"原样 ＋ 探针自己那两行 publish/install"；
     掺进了别的进程写的行就**不截**，只删目录 —— 并如实说）；
   - **全库再搜一遍哨兵**＋核"没有任何名字带探针 id 的残留" —— **这是判据的一部分，不是收尾动作**。

## 五、发现（**只报不修**，这一批不改产品代码）

1. **判据六今天只是"闸"，不是"常驻断言"**：上架那一刻 `published.publish()` **不搜哨兵**
   （它只做出界申报 ＋ 逐字节核对 hash）；"发布时自带哨兵断言"是 `92` §③ **阶段 6** 的完工标志，**还没落地**。
   今天能保证零命中，靠的是**机制**（`.data/`／`.exp/` 的字节根本不进 `manifest.files`），
   而不是靠发布时那道扫描 —— 两者不是一回事，别把这条闸绿读成"发布路径自带断言"。
2. **判据三的"重启后"没有真重启**：线上服务正被用户用着，判据不重启它。
   如实说：这一条的实质是"**不存在读路**"（源码级两处证明），重启与不重启同结论；
   真要"重启后眼见为实"，得等有一条注入落点之后再补（那是阶段 5 的事）。
3. **`.exp/` 是"能上架拒"而不是"写不进去"**：工作区**允许**写 `.exp/`／`.data/`（设计如此），
   闸在出界那一侧（`readPacks` fail-closed）。所以"模型写无声明包"这件事**今天不会报错**，
   它只是**出不去**、也**不进每轮输入** —— 与 92 §② 第二条（默认最严）一致，**不是缺陷**。
4. **真机那一次上架会在共享库留一行审计**（`publish`）与一行 `install`（判据五要真装一次）：
   脚本把它们逐字节复原了。⚠️ 这两个动作在极短窗口里对 `discover()` 可见 ——
   所以这条闸**不该被当成高频定时任务**跑；它是"要验的时候跑一次"的闸。

## 六、没做成 / 不确定

1. **判据四的回退**：不可算（见 §四），**没做成**。
2. **判据三的"真重启"**：**没重启**（见 §五·2）。
3. **共享库并发**：脚本假设"跑的时候没有别人正好在发布"。若真有并发，审计账那一段会如实说
   "掺进了别的进程写的行 ⇒ 不截"，并**不会**误删别人的行；此时"逐字节复原"那一行会转成
   "探针那一行不在了"的正对照。
4. **没验的**：`--live` 只覆盖 `92 §④` 那一列；§④ 的**离线那一列**不归这条闸管
   （它已经由 `outbound-gate.test.js`／`outbound-defaults.test.js` 等钉住）。
