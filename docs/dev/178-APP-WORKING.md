# 178 · 某一间正有活在做：桌面上那一格右下角转着一个小圈

> **主人 2026-10-04 原话**：
> *「好了。如果某个小程序的聊天还在运行，我们应该给这个小程序有一个状态。
> 就是某项工作还在工作中。」*
>
> ⇒ 定案写进手册 `05-DECISIONS.md` 的 **`D4.28`**（升 **v2.43**）。

---

## 一、要的是什么（一句话）

他的小程序不只"在做 / 做好了"两种样子 —— 还有一种**做好了、而此刻正有活在里面跑**。
⇒ 桌面上那一格**右下角多一个转着的小圈**（＝"这一间现在在做一件事"）；
**点它照样打开**（这是**一个状态**，不是一道门）；活收口了，那个圈自己灭。

⚠️ 与 `175`（`D4.27`"在建"那一格）**是两件事**，**不许被画成同一件**：

| | 在建（`building` · `175`） | 在做（`working` · 本页） |
|---|---|---|
| 事实 | 入口那一份文件**不在** / **还是那页占位** | 这一间**有一件活开着**（活账上） |
| 样子 | 整格**灰底 ＋ 灰图形 ＋ 中间一个大圈** | 底**不变**，**右下角一个小圈**（琥珀色） |
| 点它 | **不打开**，只说一句「这个小程序还在做，做好了我告诉你」 | **照常打开** |
| 能不能同时 | **能**（边做边跑）—— 那时屏幕上是**两个圈**，位置与颜色分得开 | |

## 二、判据那条事实住哪（**只有一处**）

服务端每条 app 多一个 **`working`**（布尔）：

| 来源 | 判据 |
|---|---|
| `world.work.live()`（**这一间那本活账**） | 活账里**有**一条开着的（`waiting` / `running`）记录、它的 `scopeId` 就是这一格 ⇒ `true` |
| 谁来读 | `src/server.js` 的 `workingScopes(sub)`（一个 `Set<scopeId>`）—— `/api/apps`（公网那条）与 `/api/internal/apps`（盒子那条）**各算一次** |

🔴 **与"那件怎么样了"是同一本账**：`work_status` 那条工具读的也是 `world.work.live()`
⇒ 桌面上那一格亮着"在做"、和助手回答"那件还在跑"**不可能给出两个答案**。

### 谁算哪一侧（**这条差点栽在这儿**）

```
主人 / 单租户：  宿主自己那份世界  →  /api/apps          （workingScopes(claim.sub)）
租户（真用户）： 他盒子里那本活账  →  /internal/apps      （盒子自己算，宿主原样带回）
```

🔴 **宿主这一侧没有租户的活账**（2026-10-04 实测：`data/users/u2/` 下没有他那一份流水 ——
他的世界在他盒子里）。所以宿主那条 `/api/apps` **必须以盒子里那份为准**：

```js
working: typeof a.working === 'boolean' ? a.working : working.has(a.id)
```

⚠️ **写这一页的时候这里本来是错的**：那条口无条件用宿主自己那份 `Set` 去覆盖
（`working: working.has(a.id)`）⇒ 租户的格子上**永远不会亮**，
而**单租户判据全绿**（判据跑在主人那份世界上）。这就是"**验在哪一端**"那一课的原样重演
（`AGENTS.md` §四 `批 16` 的教训）。
⇒ 现在有一条**真隧道 ＋ 真内部口**的判据盯着它（判据 W3），
而且**故意**让宿主那一份说"闲的那一间在做"：出错了就是**指错一格**，不只是不亮。

### ⚠️ 拿不到 ⇒ 一律 `false`（fail-open）

活账读不出来（老部署 / 盒代理 / 身份不合法 / 那一层还没接）⇒ **一个都不亮**。
理由与 `175` 同一条：**"它还在做"这种假话最容易被当真**；
宁可晚一拍，也不许多亮一格。判据 W2 钉的就是它（含"清单照样出得来、不许 500"）。

⚠️ **不落盘**：`working` 是**算出来的**（`app.json` 里没有这个字段，`building` 同样）。
落了就是一个会漂的存量字段 —— 判据 W1 末尾那两句就是在钉这个。

## 三、桌面怎么知道要重拉

活账**开票 / 认领 / 收口**各叫一声 ⇒ 复用现成那条瞬态事件 **`app/installed`**
（它的语义本来就是"**桌面可能变了**"，客户端收到就重拉清单）：

* `src/worklog.js`：`#append()` 之后叫 `onChange(rec)`（**吞掉异常**：它是一条旁路，
  **绝不许**把开票 / 收口带走）；
* `src/worlds.js`：那一句接成 `timeline.emitTransient({ type: 'app/installed', appId: rec.scopeId })`。

⚠️ **如实说两条**：① 这条信号是**复用**的（不新造事件类型 ⇒ 老客户端也安全），
代价是"别的原因也会让桌面重拉一次"（一次很小的请求，无所谓）；
② 那个圈**自己不会走**（`CircularProgressIndicator` 永远在动）⇒
**判据里不许 `pumpAndSettle`**，泵固定几帧。

## 六、如实说（没做到 / 不确定的）

* ⚠️ **这一批服务端两边都要换**：`working` 在**宿主**（主人那份）与**盒子**（租户那份）**各算一次**
  ⇒ 产品层要重发、盒子空闲时自己重开；只重启宿主的话，**用户那一边不亮**。
* ⚠️ **"在做"说不清是哪一件**：这一格只知道"有事在做"，不知道做的是哪一件
  （要问就问助手 —— `work_status` 那条工具答的才是"哪几件"）。主人要的只是**一个状态**，
  所以这里就到此为止；哪天真要"格子上写清在做什么"，那是另一件事。
* ⚠️ **开票了但还没被认领**（`waiting`）也算"在做" —— 那正是"投出去了、还在办"，
  与主人的原话一致；**代价**：如果那一件**永远没人认领**，这个圈会一直亮到它被收口
  （收口那三条路都在：做完了 / 他说别做了 / 断了）。**今天没有"挂了多久就自动灭"这种规则**，
  也不该有（`#270` 那个"不设时长限制"是同一条口径）。
* ⚠️ **盒子老版本 ⇒ 那不亮**（盒代理不带这个字段 ⇒ 退回宿主那份 ⇒ 空）。
  这是**故意的** fail-open，不是漏做。
