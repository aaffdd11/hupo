# 38 · 把已建成的功能按用户切开（三人讨论）

> 主人 2026-09-21 原话（这一篇就是回答它）：
> *"原来就是我没有做这样的隔离，然后做了很多的功能，那现在呢我就需要把这些功能进行隔离，成为不同的用户，
> 所以有**一个主功能是登录功能和创建这个容器**，然后**子功能就是针对不同用户、各个用户他们自己的容器里面
> 的一些设置和那个这种对话聊天的修改**。"*
>
> 三位工程师独立作答（控制面 / 数据面 / 客户端+运维，互相看不到），**下面每条都经我自己复核过**。

---

## 一、边界：主功能（控制面）与子功能（用户那台）

| | 控制面（主功能） | 用户那台（子功能） |
|---|---|---|
| **拥有** | 登录（手机号+验证码）· 令牌（`sub`=真 userId）与撤销 · **`sessionId → userId` 路由**（与 `#agents` 同生共死）· 准入与配额 · **容器的起停与卷分配** · 审计 | 现在那串单例**全部各一份**：`Store`/`Timeline`/`Trash`/`Notice`/`Say`/`Dispatcher`+`Runtime`/`Ledger`+`sock`/`turn-status` · **`DSH_HOME`** · 对话正文 · 账本 · **他自己的 key** |
| 🔴 **不许** | **存任何对话正文、key、`DSH_HOME`** | 决定别人的事（登录、配额、谁能进） |

⚠️ **`tenants.js`（我刚写的）是同进程的过渡层，不是边界** —— 它那十条绿闸证明的是"数据分开取"，
**证明不了跨 uid 的边界**（控制面原话）。真边界是**每租户一个 OS 用户 + 容器**（已建好地基）。

---

## 二、切 / 不切（逐个模块）

| 项 | 判 | 理由 |
|---|---|---|
| `main.jsonl`（`Store`+`Timeline`） | **切** | `tenants.get(uid)` 已做（owner→`data/`、别人→`data/users/<uid>/`） |
| `Trash` · `Notice` 限频账 · `Say` 去重表 | **切** | 三者都 **seed 同一份日志** ⇒ 日志切了它们必须跟着切 |
| `ledger.jsonl` + `Ledger` + **域套接字** | **切** | 套接字路径由 `dataDir` 派生 ⇒ 天然跟走；**但 env 必须按 uid 注入** |
| 🔴 **agent 的键** | **切** | 见 §三①（**今天必撞**） |
| `status.json`（忙不忙） | **聚合** | 每人一份会让 `restart-core.sh` 读不懂 |
| `users.json` · `auth.json` · 令牌 · 临时码 | **不切** | 账号与认证天生全局 |
| 代码 · 镜像 · 人格 · 能力层 · `mcp-ledger-server.mjs` | **不切（只读）** | 无状态 |
| `DSH_HOME` · `agentCwd`/workspace | **切（硬要求）** | N21（键是绝对路径）+ §2.2 三条 |
| 客户端一屏缓存 · 草稿 · 档位设置 | **切** | 见 §八（**设备级 ≠ 用户级**） |

## 三、🔴 三个实测卡点（**接线之前必须先解决**）

### ① 所有人会撞**同一个 agent**（我自己验过代码）

```
dispatcher.js:310   const id = this.#timeline.id;        ← agent 会话的键
dispatcher.js:435   if (sessionId !== this.#timeline.id) return;   ← onEvict 也按它比
serve.js:200        scopeId: timeline.id,
```

我写 `tenants.js` 时**刻意**让每个人的 `timeline.id` 都叫 `'main'`（注释里写的理由是"目录已经把两人分开了"）
—— **那个理由只对了一半**：数据分开了，**键没分开**。共用一个 `AgentRuntime` 时
`runtime.get('main')` 对所有人返回**同一个 agent** ⇒ **甲说的话进乙的窗口**（静默串号，两边日志都"正常"）。

⇒ **修法**：键改成 **`uid/main`**（目录名与日志名都不用动），或让 timeline id 按用户取。
⇒ **判据（带负向对照）**：`runtime.snapshot()` 里必须**同时**看得到 `u1/main` 与 `u2/main`；
**把键改回 `main` ⇒ 只剩一个**（那就是"今天必撞"的证明）。

### ② 🔴 服务**没法以租户身份干活**（两个视角都实测到）

```
$ sudo -n -u hupo-a true
sudo: a password is required
$ sudo -n -l            → sudoers 里没有任何条目
```

⇒ 我契约 `37-MULTITENANT.md` §四写的"起法 `sudo -u hupo-a podman run`"**在服务身份下不成立**。
**这是"谁去建/谁来删容器"的洞**（见 §四）。

### ③ 宿主级的两个**全局**还得单独处理（控制面点名）

* **`ledger.sock`**：同进程过渡期它是全局的 ⇒ 甲的工具调用可能落到乙的账本（**串账**）；
* **`status.json`**：每秒写"忙不忙"，全局一份 ⇒ **甲忙会让乙也"忙"**（→ 重启脚本会等错人，或切错话）。
  ⇒ 聚合成"**任一忙就算忙**"（**宁等不切**），并同步改 `restart-core.sh` 的等待判据。

## 四、容器生命周期（**谁建、谁起、谁删**）

| 动作 | 谁做 | 形态 | 代价 |
|---|---|---|---|
| **起停**已存在的容器 | 服务（`deploy`） | **systemd 模板单元** `hupo-tenant@.service`（`User=%i`、`XDG_RUNTIME_DIR=/run/user/%i`）+ **polkit 规则**只放行 `deploy` 对 `hupo-tenant@hupo-a\|hupo-b.service` 的 start/stop ⇒ **免 sudo、免 root 助手** | polkit 规则**本身是把锁**（**要主人签**）· 要 `loginctl enable-linger hupo-a` · 镜像 tar **每租户各 `podman load`** |
| **建 / 删**用户与卷 | **只能 root** | (甲) root 小助手（socket-activated、白名单 uid、四个动词）＝**能自动开通**，代价是 `deploy` 手里多一把 root 钥匙；(乙) 主人**签一批**，人工开通 | ⚠️ 这正是 P1/P2 的那条线：**"能自动开通"和"助手拿不到 root"不能同时要** |

## 五、迁移与顺序（**不热切、不做一半**）

控制面给的六步（我认同，且与"主功能/子功能"的分法一致）：

1. `server.js` 里那处 `sub:'owner'` 改成**真 userId**（已经做了）；
2. **单例 → "按 userId 取一份"**（`tenants.js` 已备好取用层，**owner 仍走原来那一份、`data/` 原地不动**）；
3. **路由表**：每个 handler 首行按 `claim.sub` 取世界（14 条路由里 10 条要）；
4. **登录白名单先只放 owner**（此时线上行为与今天**逐字一致** —— 这是"可回退点"）；
5. **用第二个真号走完 §13.4 三道台阶**（容器能起 → 交叉读不到 → 搬家逐字节一致）；
6. 才开"两人同时在线"那道闸。

⚠️ **切换 = 整进程重启，不许热切**（热切时内存里的世界与盘上的会不一致）。
⚠️ **owner 不搬**也自洽；真要搬家作为**单独一次**、用**挂载**不复制 ⇒ 天然逐字节一致。

## 八、客户端 + 运维那一份（第三位）

> 一句话：**把"我是谁"做成缓存键与路由的第一个参数，并让"容器没就绪"挡住聊天** ——
> 否则切完，**每个人看到的还是同一个世界**。

### 8.1 读到的代码事实（他自己核过，我照收）

| 事实 | 意味着 |
|---|---|
| `chat_controller.dart:37-39`：两个 store **已经有 `namespace` 参数，但默认 `'single'`** | ⇒ **今天全站共用一份缓存**；改成传 `sub` 就行，**不用重写** |
| `ProcessLevelStore` 的键**写死、没有 namespace** | ⇒ 档位设置要么按人要么按设备，**要写明** |
| `logout()` **已经**走 `_invalidateLocal()`（`chat_controller.dart:278-290 / 497-502`） | ⇒ 清缓存那条路已经有了，接上 namespace 即可 |
| 🔴 客户端**没有任何地方解令牌的 `sub`** | ⇒ 得加：**只当缓存键用，不验签、不当权限**（验签是服务端的事） |
| 🔴 `Auth` **只能按 `jti` 撤**（`auth.js:366`），**没有"按用户撤全部"** | ⇒ 注销/改号时**撤不干净**（老令牌还能用） |
| `tenants.js` 的 `OWNER_ID='owner'` ⇒ **主人的目录就是 `data/` 根** | 🔴 **凡是按 uid 拼路径的代码（备份/删除/统计）都会"静默跳过主人"**（`data/users/owner` 不存在） |

### 8.2 不分命名空间的后果（他说得很具体，我认同）

**B 登录后会先看到 A 的整屏 + A 打了一半的草稿**；他一发，**那句话就进了 B 的账本**。
⇒ **退出（含 401）要撤令牌 + 清掉全部人的缓存键**（不是只清"自己那份" —— 共享设备上别人还看得见）；**档位不清**。

### 8.3 新用户"等容器"那一段（**今天服务端还没有这个字段**）

登录响应要**带上容器状态**（缺字段按"**就绪**"兼容 —— 别把老客户端挡在门外）：

| 状态 | 界面说 |
|---|---|
| 在建 | **如实说"正在开一个只属于你的空间"** + 可重试，**不许假进度条** |
| 太久 | **如实说"比平常久了"** + 可重试（"多久算太久"这个数**住代码**） |
| 失败 | **如实说"没建成，是我这边的问题"** + 可重试 |
| 就绪 | 才进聊天 |

### 8.4 运维（注销"少一步就是假删除"）

按 `sub` **撤全部令牌**（今天做不到）→ 容器 → 卷 → `data/users/<uid>/` → 他的 `DSH_HOME`（含 `sessions/`）→ `users.json` 那条（⚠️ **两个写者**：命令行删了、服务内存里还在 ⇒ **他还能登**）→ **踢掉已连的连接**。
⚠️ **`--dry-run` 先打印清单，主人 `sudo` 执行**（`deploy` 免密不了，删不掉）。
⚠️ 备份按人打包；磁盘 `N × 2.4M` + 每人一份 `DSH_HOME` + `sessions/` **只涨不降** ⇒ 要**按人配额**。

### 8.5 迁移顺序（他给的，与控制面那份**互相印证**）

1. **服务端先接线**：路由只从请求的 `sub` 取，未就绪明确回"未就绪"；
2. **再发客户端**：命名空间 + 清缓存 + 等待态 + 缺字段兼容；
3. **最后翻开关并作废旧令牌**（旧客户端撞 401 ⇒ 走既有的"清缓存回登录页"）；
4. **翻之前先备份**。

### 8.6 判据（他给的，**都很可执行**）

* 正：以 A 的令牌启动，缓存键里只出现 `…v1.<subA>`；
* **负**：换 B 启动 ⇒ 断言行上没有 A 的 seq 与文本、A 的键已清；再跑 `check-web-browser --shot` ⇒ **截图里没有 A**；
* 服务端：A 的时间线里没有 B 的 seq；用户改成别人 ⇒ 403；
* 等待态：造 `creating` ⇒ **有等待页、没有输入框**；改 `ready` ⇒ 消失；**断言没有百分比**；
* 注销：`--dry-run` 项数 = 实测项数；删后**登不进、目录不在**、`df` 回收 ≥ 卷大小（**删之前先能登** = 负向对照）；§13.4 搬家前后 **sha256 一致**。

### 8.7 ⚠️ 他与**已冻契约**冲突的一处（要主人裁）

他说 key **"可填，只经服务端写进他的空间"** —— 而契约 `37-MULTITENANT.md` §二② 冻的是
**"网页终端，用户自己在容器里配 ⇒ 不经过我们"**。**两条对不上**，这一条**只有主人能定**
（第三位的方案会让 key 经过我们；已冻的方案不经过）。
