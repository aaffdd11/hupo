# 07 · 卡住的一轮怎么收场（超时硬收口）

> **这一批建了什么**：一轮**卡住**时的那条路——到点收口、把话说圆、**把进程卸掉**、
> 并把**排队里还没轮到**的那些话也逐条收掉。
>
> 为什么它急：在这之前 **agent 卡住就是永远卡住**。用户等一条不会来的回答，
> 而手册事故一里那行"还有件事在处理"挂了 **68 分钟**。
>
> **手册依据**：**N19**「挂起必有超时，且必有合法收尾」·
> **N10**「超时必须伴随资源回收（**收气泡 ≠ 停 agent**）」·
> **N11**「拒绝要给人话 + 可重试」· `08-SPEC.md` §10.2「单轮硬收口 **180s**」
>
> **代码**：`session-translate.js`（收口）· `agent-runtime.js`（回收）· `dispatcher.js`（挂钟）
> **测试**：`test/deadline.test.js`（12 条，走**真 spawn、真 stdio**）

---

## 一、先量的三个事实（**不量就会设计错**）

### 1.1 一轮没结束时再发一句，DSH **接受并排队**

`/tmp/probe-queue.mjs` 实测（第一句让它慢慢数 30 个数，2.5 秒后发第二句）：

```
[+ 1116ms] << turn/start  turn=1
[+ 1122ms]    prompt①  →  {"messageId":"104bb551-…"}
[+ 3627ms] << agent/inbox/spliced  target=next-turn inserted=1 removed=0
[+ 3628ms]    prompt②  →  {"messageId":"d47e69ae-…"}      ← **接受了**
[+11245ms] << turn/end  turn=1
[+11247ms] << turn/start  turn=2                            ← 排队的这句现在才变成一轮
[+11677ms] << assistant/message turn=2  「收到了」
```

⇒ **结论直接决定设计**：如果我们超时把进程踢掉，
**排队那句会跟着一起没，而用户还在等**——用户看到的是一个永远等不到回答的气泡。

⇒ 所以 N19 在这个项目里**不只是"收当前这一轮"**，还要收**排队里那些**。

### 1.2 `turn/start` 可能**早于** `prompt()` 返回

```
[+ 1116ms] << turn/start  turn=1
[+ 1122ms]    prompt① →  {"messageId":…}
```

**帧比返回值先到。** ⇒ 投递记账必须**先记再投**。
反过来（等返回值再记）的话，`turn-start` 来"消费"投递时队列里还是空的——
于是那一条被**多算一次**，超时会漏收一句。

### 1.3 `assistant/message` 的 `content` 里还有 `tool-call` 块

```
"content": [{"type":"tool-call","id":"call_00_…","name":"bash","arguments":"{…}"}]
```

翻译层按 `type === 'text'` 过滤 ⇒ 它不会变成用户能看的正文。**这是对的**：
工具名是内部词。将来做 D7（"它在干什么"）时，这就是那个"人话表"要翻译的原料。

## 二、三件事，缺一件都不算做完

| # | 做什么 | 依据 | 不做会怎样 |
|---|---|---|---|
| ① | **收气泡** | N19 | 气泡永远停在"马上说完" |
| ② | **排队那些也收** | N19（§1.1 量出来的） | 用户等一条**永远不会来**的回答 |
| ③ | **停 agent** | **N10** | 卡住的进程 `running` 恒真，而 LRU 的规矩是"**跑着的不许卸**" ⇒ **永不淘汰**，永久占 4 个位置里的一个 |

### ⚠️ ① 里最容易漏的那一种：**一句话都没说**

卡住的样子常常是"一轮开了、但一个字都没说"。
旧实现（`forceClose`）在这种情况下是**删掉轮账、什么都不说**的：

```js
if (!rec?.writer) { if (turn !== null) this.#turns.delete(turn); return false; }
//                                                              ↑ 用户从此开始等
```

⇒ 现在 `turnDeadline()` **两种情形都必须留下话**（有 writer 就补一句，没 writer 就主动说一句）。

## 三、收尾理由是 `timeout`，不是 `failed`

`message/end.reason` 现在是 `completed | failed | timeout`。

⚠️ **这是往上线过的字段里加了一个值，所以要说清为什么安全**：

- 客户端判失败的口径是 **`reason !== 'completed'`**（`bubbles.dart:121`）——
  **不认识的新值自然落到"失败"那一档**，旧客户端不用改。
- 为什么值得加：`reason` 是时间线上"**为什么结束**"的记录
  （N4 记忆有出处、N7 不拿不真实的状态污染记录）。
  **卡住和断线是两件事**，都记成 `failed` 就查不出来了——
  而 03-DEVELOPMENT.md §5 那张表里，`failed` 是"网络错 / 超时"**共用**的一档。

## 四、顺手修掉的一个真坑：收口/卸载之间的**空窗**

`stop()` / `evictIfNeeded()` 早先是"**先回调收口，再从表里摘掉**"。
`onEvict` 是个 `await`——于是**空窗里表里还留着那个正在死的实例**，
而这期间来一条新消息，`runtime.agent(id)` 会把它**又发回给调用方**：
投递直接失败（用户看到"我接不上活"），而排查时看起来只是"偶尔抽风"。

⇒ 改成 **摘表 → 收口 → 卸**：

| 动作 | 管什么 |
|---|---|
| **摘表** | **别再把它派出去** |
| **收口** | **把话说圆** |
| **卸** | 回收内存与那个位置 |

⚠️ "先收口再卸"**没有变**（收口仍然在 dispose 之前）。变的只是"摘表"提前了——
它本来就跟收口不是同一件事。

> 这个坑是**测试抓出来的**：测试里"新 agent 活得好好的"那条断言挂了，
> 一查发现第二个 agent 是被**上一个 agent 的拆卸**顺手带走的。

## 五、另一件顺手补上的：**换了进程 ⇒ 轮账清空**

⚠️ **轮号在每个 agent 进程里都从 1 重新开始。**
而翻译层的 `#turns` 是按轮号存的。要是上一个进程的第 1 轮没被收干净，
新进程的第 1 轮就会**接到那条陈账上**——收口收到错的地方去。

⇒ `#ensureAgent()` 发现**换了实例**时，`TurnTranslator.reset()` 把轮账清空。
**这样"进程换了、轮账是空的"是构造上成立的**，不靠"记得清理"。

## 六、⚠️ 端到端测试抓出来的一个真 bug：**DSH 会话 id 撞车**

**这一节是这一批最重要的收获。** 它差点就这么上线了。

### 6.1 现象

超时硬收口 → 收口 → **卸掉 agent** → 用户再说一句 ⇒ 起了新 agent。
**新 agent 的第一句话就发不出去。**

```
① 起第一个 agent，说一句          prompt 成功
② 把它停掉（模拟超时硬收口）      runtime 里还剩：0
③ 用**同一个 runtime**再起一个
   prompt 失败：session "main.mu9rmdgzijr2" already exists
```

（复现脚本：`/tmp/probe-session-reuse.mjs`，跑一次十几秒。）

### 6.2 根因

三件事凑在一起：

| # | 事实 |
|---|---|
| 1 | DSH 的会话记录**落在 `$DSH_HOME/sessions/` 里、跨进程活着**（实测那目录下躺着 19 个 `main.<bootId>`） |
| 2 | `session/prompt` 对一个**已存在**的 id 直接报错——**SDK 只能 create，不能 resume** |
| 3 | 而 `dshSessionId` 早先是 `${会话名}.${bootId}`，**`bootId` 是整个 runtime 一份、永不改变** |

⇒ 同一个 runtime 里"卸掉再起"= **必然沿用同一个 id** = **必然撞**。

### 6.3 为什么之前没被发现

因为**在此之前没有任何一条路会在同一个 runtime 里换 agent**：

| 路 | 换 agent 吗 |
|---|---|
| 服务重启 | ✅ 换，但**也换了 `bootId`** ⇒ 不撞 |
| LRU 淘汰 | 换，但那之后**没有新投递** ⇒ 撞不上 |
| **超时硬收口** | ✅ 换，**且 `bootId` 不变** ⇒ **撞** ← 这一批新开的路 |

⇒ **新开一条"换实例"的路，就必须回头检查"实例身份"这件事的所有前提。**
这条教训值得单独记一笔。

### 6.4 修法与回归

```js
// 三级：会话名 . 启动代 . 第几个实例
#nextDshSessionId(sessionId) {
  this.#incarnation += 1;
  return `${sessionId}.${this.#bootId}.${this.#incarnation}`;
}
```

⚠️ **同时删掉了一条错的测试。** 原来有这么一条：

```js
test('★ 同一进程内，同一个会话每次拿到的是同一个 DSH id（否则记忆会散）', () => {
  assert.equal(rt.dshSessionId('main'), rt.dshSessionId('main'));
});
```

**它把"id 一样才不丢记忆"当成了事实——那是错的。**
记忆在**进程**里，不在 id 里；而 id 一样恰恰是撞车的原因。
⇒ 现在换成**反过来的**那一条（换实例必须换 id），并且**逐字记下为什么**。

### 6.5 还顺手让假 agent 学会这条规矩

假 agent 现在可以（用 `FAKE_SESSION_FILE`）**真的执行**"会话 id 只能 create"，
会话记录写在一个**跨进程共享的文件**里。

**为什么值得**：这个 bug 假 agent 原本抓不到（它不看会话 id），
所以它是靠**端到端真 agent**才浮出来的。现在 CI 里也抓得住了，
而且做过**变异验证**——把修复退回去，那条测试当场失败：

```
✖ 🔴★ 恢复时必须换一个 DSH 会话 id
  AssertionError: ★ 恢复投递必须成功——不许撞 already exists
```

### 6.6 ⚠️ 它带来的一个副作用（**明说，别假装没有**）

每换一个实例就多一条会话记录 ⇒ `$DSH_HOME/sessions/` **会一直涨**
（现在：该工作区 19 条 / 344K）。按 180 秒一次超时算，涨得很慢，但**它没有上限**。

⇒ **这是欠的账**：需要一个清理策略（按时间 / 按数量，且**不许删到正在用的那条**）。
在本批里**没做**，因为它牵扯到"哪些会话可以删"——那属于对账续做的地盘。

## 七、实现要点（都在 `dispatcher.js`）

| # | 做法 | 不这么做会怎样 |
|---|---|---|
| 1 | **一轮一个计时器**（`#deadlines` 是 Map），不是"全局一个" | 全局一个的话，后一轮开始会把前一轮的计时器顶掉 ⇒ 前一轮永久挂着 |
| 2 | 计时器 **`unref()`** | 忘记它：`npm test` 跑完不退出，SIGTERM 收工也要多等 |
| 3 | 投递队列**先记再投**（§1.2） | 见 §1.2 |
| 4 | 一轮开始**消费**一条投递 | 队列会越攒越长，超时时把早就答过的也算成"排队" |
| 5 | `turnDeadline(turn)` 返回 false ⇒ **什么都不做** | 那一轮早就正常收口了（只是慢）——乱动会把**一条好回答标成失败** |
| 6 | `turnDeadlineMs = 0` ⇒ 关掉，**但启动横幅必须喊出来** | 关掉之后卡住就是永远卡住，而现场看起来只是"它今天有点慢" |

**默认值 `180000` 住在 `config.js`**，理由也写在那儿：比它短的会切掉正常的慢活
（带工具的一轮实测十几秒很正常），比它长的用户已经在盯着屏幕等。

## 八、验收

```bash
cd v2/services/core && npm test        # 165 条（这一批占 13 条）
```

真 spawn、真 stdio 那一层验的是**进程到底有没有被卸掉**——
这件事 mock 掉就没意义了。13 条里点名几条：

| 测什么 | 为什么它必须存在 |
|---|---|
| 一轮开了、一个字没说 ⇒ 到点**必须有话** | 就是 §二里那个最容易漏的情形 |
| 说了半句再卡住 ⇒ 补一句、**不重复开头** | 快答/深答是同一个气泡（协议 R2） |
| **超时必须把 agent 卸掉** | N10。只验"气泡收了"等于没验 |
| **恢复时必须换 DSH 会话 id** | §六那个真 bug。做过**变异验证**（退回修复，它当场失败） |
| 卡住时又说了两句 ⇒ **排队那两句也要收** | §1.1 量出来的那条路 |
| 正常收口之后**不许**再被超时收一次 | 否则会把一条好回答标成失败 |
| 三句文案：没有内部词 + 说清怎么办 + **三句互不相同** | 文案本身也是验收对象（N11） |

### 8.1 真 agent 实测（**会花模型调用**，截止调成 8 秒以便看得见）

`/tmp/e2e-deadline.mjs`：说一句"用 bash 跑 `sleep 45`"，1.5 秒后再补两句，
等过截止时间。**这是唯一能证明"恢复之后它还能干活"的验法**
——而 §六那个 bug 正是这一步抓出来的。

```

[dispatcher] 第 1 轮超过 8000ms 没收口 —— 收口并卸下 agent

── 截止之后盘上有什么 ──
  seq= 1  user/echo             用 bash 跑 `sleep 45`，跑完回我三个字：好了。
  seq= 2  user/echo             等你跑完，再顺便告诉我今天是星期几。
  seq= 3  user/echo             还有，帮我把这句话记下来：紫水晶。
  seq= 4  message/start
  seq= 5  message/text          这件事我卡住了，没能给你答复。你可以再说一次。
  seq= 6  message/end   timeout
  seq= 7  message/start
  seq= 8  message/text          你刚才那句我没来得及做，就卡住了。再说一次吧。
  seq= 9  message/end   timeout
  seq=10  message/start
  seq=11  message/text          你刚才那句我没来得及做，就卡住了。再说一次吧。
  seq=12  message/end   timeout

runtime 里还剩几个 agent： 0

═══ 恢复：再说一句，看新的 agent 能不能好好答 ═══
它说： "收到了" ｜收尾理由： completed

  ✅ N19 到点有收尾（出现 timeout 收口）
  ✅ N19 收口说的是人话（有"卡住了"）
```

于是查出了 §六那个"会话 id 撞车"：**卡住一次之后，它就再也不理你了。**
如果只验前面五条（当时全绿），这个 bug 会直接上线。

## 九、这一批**没做**什么

| # | 没做 | 说明 |
|---|---|---|
| 1 | **对账续做** | 手册 D5.9「被打断的活会自己接着做」——**现在只是"告诉它断了"，不是"接着做"**。续做窗口 6h / ≤3 次 / 全局并发 1，都还没建 |
| 2 | **"挪走"成独立任务** | 手册 §10.2：一轮超过 **15s** 就该变成一个独立任务。没有这一步，续做也无从下手 |
| 3 | **卡住时到底卡在哪** | 现在只知道"这一轮超时了"。`tool/call` 已经在手上（§1.3），能说"卡在跑一条命令上"——但那是 D7 的活 |
| 4 | **上游真的挂了 vs 它自己想太久** | 两者现在都走 `timeout`。分开要能从工具/上游那头拿信号 |

⚠️ **明说砍了**：**不做**"超时了就把这一轮自动重投一遍"。
理由：重投会把**已经做过的副作用**（写文件、发命令）再做一遍，
而"哪些能做两遍"现在没有任何判据。**接着做**这件事属于第 1 条（对账续做），
它得先能回答"上一轮做到哪儿了"。
