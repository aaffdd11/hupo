## 二、`#121` 走偏了什么（以及要留的）

| 手册 | `#121` 做成了 | 判定 |

| 一条可见时间线 / 一条日志 / 一套号 | **每 scope 一份** `scope-<id>.jsonl` ＋ **各自编号** | ❌ **违反 P-l** |
| 一条 WS；多作用域对客户端透明 | **切房间就重连**、客户端自己选 `scope` | ❌ **违反 §四#3/#4** |

⇒ **留下**：`workspaces/<scope>`、每个 scope 一条会话（agent + cwd）、事件上的 `scopeId` 标签、A1–A7 里那些不冲突的判据。
⇒ **收回**：每间一个调度器 / 每 scope 一份日志与编号 / 每房间一条连接。

## 三、目标态契约

1. **调度器：每个用户一个**，**持有多条会话**（会话 = 一个 scope/房间）。宿主那层**只转发字节**（`37-MULTITENANT`）。
2. **一条可见时间线 = 一条日志**（P-l）：`scopeId` **只是事件上的标签**；编号**一条线**（那条日志已落盘最大 + 1）。
3. **一条 WS 连接**（§四#3）：客户端发**焦点**（"我正在看哪个图标"）；服务端把**焦点那条**的输出**现时投给用户**，
   其它会话的事件**照常进日志、但不实时提醒**。
4. **转交 / 未读 / 焦点告知**（§四②）：主对话**可以把活转给某间**，而且**用户看得见**（一句人话 + 事件带 `scopeId`）。

## 四、协议（**只加不改**）

| 面 | 怎么办 |
|---|---|
| `WS /api/stream` | **`&scope=` 作废**（带上只当"初始焦点"，兼容旧客户端）；新增**客户端→服务端**帧 `{"t":"focus","scope":"<id>"}`。服务端**一条连接**服务所有会话 |
| `POST /api/say` | 已有的 `scope` 字段**保留**，语义明确成"**这一句的归处提示**"（服务端可以据此定目标会话；**日志仍是一条**）。不带 ⇒ 主对话 |
| `GET /api/timeline` | 已有的 `?scope=` **保留**，语义 = "**只看这一间的事件**"（**视图过滤**，不是另一份日志）；不带 ⇒ 全部 |
| 事件 | 一律带 `scopeId`；**编号是全局那一条** |

## 五、判据（每条都要能反着验）

| # | 判据 | 反例（必须红）|
|---|---|---|
| **F1** | **一条日志**：两个不同 scope 的事件落在**同一个**日志文件里，**同一套编号**（不跳、不各从 1 起） | 每 scope 一份日志 / 各自编号 ⇒ 红 |

## 六、迁移（把并列收成一条）

- 把每份 `scope-<id>.jsonl` 的**事件按时间并回**那条日志，**重新统一编号**；**旧文件不删**（留作证据，改名为 `*.merged.jsonl` 或挪进 `evidence/`）。
- 🔴 **默认 dry-run**、**可重跑**（第二次跑：已并过的一律 `skipped`）、**逐字节可核对**（并之前先算 sha）。
- ⚠️ **编号会变**：并之前**先落一份快照**（时间线 + 各 scope 文件 sha），并**如实报告"哪些号变了"**。
- 迁移**只在盒子里跑**（数据在他盒子里）；宿主侧不留副本。
