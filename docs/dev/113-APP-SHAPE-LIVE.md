# 113 · 小程序的形状：**用户端是源代码部署，版本快照只在市场里**（主人 2026-09-26 定）

> ⚠️ **这一篇先记原话与形状**（父 agent 当场记下，免得只在对话里存在）。
> 待办：把它收敛成 `docs/handbook/05-DECISIONS.md` 的一条决策（＋ `CHANGELOG` 升版本 ＋ **重建开机清单**，因为手册是 strict），并把 `#159`/`#160` 的判据按它对齐。

## 一、主人原话（逐字）

> **"所谓的版本快照，只在市场中存在。不在用户端。用户a创建的，在他自己那里就是一段源代码部署，a推到市场，就是一个包，用户b使用，实际上是把包拉下来变成源代码部署。用户a和用户b后续的使用和部署，都是用的自己的，所以不需要什么压缩。最后，如果用户a做了新的，稳定了，他想发布，则可以再次发布。b也可以。"**

> **"发布作为功能点，不需要在对话中实现。"**

> （更早一句，同一件事的另一面）**"小程序做好了，发布到桌面，这个对于用户自己用的应该是不需要这样的。因为他自己开发过程原则上就是对当前这个版本进行内容修改、功能修改……否则的话用户不需要走这条发布的通道。"**

## 二、形状（照原话落）

| | 用户端（他自己那份） | 市场（分享那一侧） |
|---|---|---|
| 是什么 | **一段源代码部署**（他那间工作区里的活文件） | **一个包**（不可变、有版本、有血缘） |
| 怎么变 | 助手**直接改**那些文件 ⇒ 他屏幕上就该是新的（**不用发布、不用刷新**） | A"稳定了"**才**推一次 ⇒ 新的一包 |
| 别人怎么用 | —— | **把包拉下来 ⇒ 变成他自己那份源代码部署**（此后各用各的） |
| 尺寸/文件数那些上限 | 🔴 **不属于这一侧**（所以**不需要压缩**：主人原话） | 属于这一侧（包才有大小/文件数这回事） |
| 谁再发布 | —— | **A 能再发、B 也能再发** |

## 三、由此改掉的三件（**旧形状就是错的**）

1. 🔴 **"桌面上要能看见新内容 ⇒ 必须落一版"** —— 错。桌面点开的应当是**那间工作区的活文件**（`#160` 在做）。
2. 🔴 **把"包"的那套（不可变版本 + 单文件 256KB／总 2MB／40 个文件）挂在用户端** —— 错。它只属于**市场那一侧**。⇒ 奥数小站那次"扩建题库"卡在"压到 266KB > 单页 256KB"，**根子就是我们把它套在了用户端**（真机读数：`/api/apps` 里 `aoshu-bank` 一直是 v1、工作区里 `index.html` 474,555 B）。
3. 🔴 **"发布"是对话里的一个工具动作** —— 不对。**发布是界面上的一个功能点**（"作为功能点，不需要在对话中实现"）。⇒ 落地位置要与主人确认一次（候选：桌面图标那个面板／「发现」页里"我发出去的"那一块），**不许**再把"叫助手去发布"当成主路径。

## 四、与在飞两条的关系

- `#160`（桌面＝活的工作区）：**就是这一条的第一半** ✓（已通知它：活路**不许**用尺寸/文件数上限拒人，"变了"的通知不许说成"发布"）；
- `#159`（发布新版 ⇒ 正开着的人自己换上）：**归到市场那一侧**（别人拉的包更新）；顺手那条"**发布失败必须给你一句话**"照旧要有。
