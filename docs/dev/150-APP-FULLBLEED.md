# 150 · 小程序那一层：**铺满整屏 ＋ 留白挪进页面里**（主人 2026-10-01 报的两条）

> 🔴🔴 **2026-10-01 晚·更正：这一篇的"铺满整屏"那一半我把方向做反了，已经撤掉。**
> **主人报**：*「所有小程序打开后都无法点击聊天了。」*
> **根因**：Web 上小程序是**真的 DOM 元素**（那个 `<iframe>`），它**压在 Flutter 画布上面**
> ⇒ 平台视图一"铺满整屏"，画在画布上的**聊天浮窗就整个被它盖住** ——
> **点不着、也看不见**。也就是说，我让**小程序凌驾于聊天之上**了。
> **而规矩是反过来的**（主人 2026-10-01 原话）：
> > *「我设计本意是，聊天窗口是**凌驾于一切元素之上**的。它在桌面之上，在小程序之上。」*
> ⇒ **修法：平台视图的矩形不许盖到聊天浮窗的矩形** —— `bleed` 那个参数**整个删掉**，
> 留白改回**由壳一处让**（`MiniAppHost` 的 `Padding`），入口 URL 上那两条 `pt`/`pb`
> 壳**不再写**（服务端那条注入留着：**老客户端还在带**，照旧要认）。
> **判据也跟着反过来**：`test/widget/safe_area_test.dart` 那一格原来赌的是
> *"制品那一屏铺满整屏、底下不留聊天条那一条"* —— **它把缺陷钉住了**，
> 现在改成 **"平台视图的底边不许进到聊天条那一带"**（＋一条负向对照）。
> **保留下来的那一半**（下面那些照旧有效）：被盖住时**只压暗**（不缩小、不圆角）。
> ⚠️ **代价如实说**：底下那一条现在露出的是**壳的纸色**（聊天浮窗是磨砂的，
> 底下就是这一层）。这是"**聊天最上**"的必然结果，不是回退 ——
> 要让它跟小程序底色一致，是**另一件事**（得让页面把自己的底色报回来）。

> **主人原话**（连着两句）：
> ① *「我看到小程序不是铺盘整页并加一个内容padding以防被聊天窗口遮住，而是用了margin，
> 导致页面没铺满，底色不同。」*
> ② *「另外，在小程序里点开聊天，小程序自己也会被压缩一下，并且会显示出桌面。这个不对。」*

## 一、那两条到底是怎么来的（现场读数）

用**这一版真 Web 产物** ＋ 真 app 原点（临时制品库 ＋ 真签名 URL）搭了一次性探针：

| | 屏幕上是什么 | 根因 |
|---|---|---|
| **① 没铺满 / 底色不同** | 那个**白底**的假制品四周一圈是**我们的暖纸色**（尤其底下那一条，正是聊天条的位置） | `mini_app_host.dart` 把 **`Padding(top: 状态栏, bottom: 收起档聊天条高度)` 套在页面（iframe）外面** ⇒ 页面物理上变小了，露出容器的 `d.paper` |
| **② 被压缩 ＋ 露桌面** | 点开聊天（展开）那一瞬间，小程序**缩了一圈**，四边（尤其左右）露出**桌面** | `covered` 时叠了两样：`AnimatedScale(0.98)` ＋ 给 `Material` 加 `borderRadius: 16` ⇒ 那 2% 与四个圆角都把桌面露出来 |

## 二、改法：**那一层铺满；留白由壳写进页面自己身上**

主人那句话本身就是形状：**"铺满整页 ＋ 一个内容 padding"** ⇒ 把留白从
"页面外面的一圈 margin"挪到"**页面里面的 padding**"。

🔴 **关键决定：那两条留白由壳注入到页面 `body` 上，而不是叫每个作者自己留。**
理由：**已经做好的页面也一起对**（不用重发一版、不用作者记得，
"傻瓜式"那一条在容器这一层同样成立）。

| 谁 | 做什么 |
|---|---|
| **壳（Flutter）** | 打开一个**制品**时把两条数**追加**到入口 URL 上：`&pt=<状态栏>&pb=<收起档聊天条＋边距>`（`models/mini_frame.dart` 的 `miniEntryUrlWithInsets`，**字符串追加**——URL 上带着签名，重新编码会把签名改形状）。那一层**一个边距都不留**（`MiniAppHost.bleed = true`） |
| **app 原点（服务端）** | 端一版 HTML 时，按 `pt`/`pb` 往 `</head>` 前插一段 `<style id="hupo-shell-inset">`：`body{padding-top:Npx !important;padding-bottom:Mpx !important;box-sizing:border-box !important}`（`src/app-serve.js` 的 `injectShellInset`）。**没带那两个参数 ⇒ 一个字节都不注入**（老客户端照旧走它自己那套） |
| **内置那几屏**（设置 / 发现 /「我自己那台」） | 不是制品 ⇒ 照旧由壳内缩（`bleed: false`）。它们本来就是暖纸底，那一条内缩**看不见** |

**为什么 `!important` ＋ `box-sizing:border-box`**：页面自己写了 `body{padding:…}` 时也要压得住；
而写了 `height:100vh` 的页面，`border-box` 保证多出来的这条内边距**不会让它溢出**。

🔴 **那两个数是"只认数字"的**（URL 是页面自己也能改的东西）：
`shellInsetOf` 先 `Number` ＋ `round` ＋ 夹到 `0..400`，认不出来当 `0` ——
`1px;}body{display:none` 这种串**一个字符都跑不进 HTML 结构里**（判据 I3 钉着）。

**被盖住那一条**（第二条）：只留**压暗**（`AnimatedOpacity 0.55`）——
`AnimatedScale` 拿掉、被盖住时的 `borderRadius` 改回 `0`。
"看得出来被盖住"由**压暗 ＋ 聊天浮窗自己**负责（手册 §6.4 规则 2 那一版是
"压暗 ＋ 轻微缩小 ＋ 圆角加大"，**今天改了**）。

## 五、如实说（没做的 / 边界）

* 🔴 **老客户端（不送 `pt`/`pb`）＝ 老样子**：那一侧照旧把页面缩小一圈（不是这次的目标）。
  两个客户端混用期间，同一个小程序在两种壳里长得不一样 —— 这是**刻意的兼容**，不是漏了。
* ⚠️ **页面把内容放在 `position:fixed` 的贴底容器里时**，注入的 `body` padding 顶不动它
  —— 那一类页面底部仍会被聊天条压住。⇒ 这一条写进 `149` 给助手的标准里
  （**别把要紧的东西贴在底边**；正常文档流里的内容壳会给它让开）。
* ⚠️ **`pt`/`pb` 变了不会重载页面**（`viewId` 摘掉了它们）：**转屏之后页面里那两条内边距
  还是转之前的值**（要么它自己读 `env(safe-area-inset-*)`，要么转屏后重开一次）。
* ⚠️ **没说"内容 padding"是壳对页面唯一的干预**：壳只加那两条内边距，**别的样式一个都不碰**。
* 内置那几屏（设置/发现/我自己那台）**没有**跟着改成"铺满"：它们自己没有"页面底色"这个概念，
  底就是我们的暖纸 ⇒ 看不出区别，也就不动（少改一处少一处风险）。
