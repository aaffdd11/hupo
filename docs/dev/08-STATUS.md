# 08 · 状态取号（S2）：把「它正在做」从服务端一路做到屏幕上

> **这一批修的是什么**：`07-APPENDIX.md` §1.5 那条「**状态挂不上**」。
> 旧实现的 `dispatcher.js` 发 `messageId: ''` ⇒ 客户端按 id 找、**恒 null**
> ⇒ `message.status` 永远挂不上 ⇒ 过程可见性的**出口一直是死的**。
>
> **手册依据**：`04-ROADMAP.md` 批 1 的 **S2**（⚠️ 它是 **D7 的入口**）·
> **N19**（挂起必有收尾）· **N10**（沉默优于编造）· **N11**（拒绝要给人话 + 可重试）·
> 决策 **P-g**（瞬态不上时间线）· `03-DEVELOPMENT.md` §4.4（D7 四档）·
> **H4**（过程可见性必须有乱序保护 + 超时收敛）
>
> **代码**：`services/core/src/{dispatcher,session-translate}.js` ·
> `apps/mobile/lib/{models/process_words.dart,models/timeline.dart,widgets/bubbles.dart,screens/chat_screen.dart}`
> **测试**：服务端 **167**（这一批占 3）· 客户端 unit **46**（占 10）· widget **5**（全是新的）

## 一、⚠️ 先量了一个事实，它把设计整个改掉了

我原本以为 S2 是"**忘了填 id**"，准备照着补一个。补之前量了一下 —— **不是**。

### 1.1 实测：DSH 的状态**都落在消息生命周期之外**

`/tmp/probe-tools.log`、`/tmp/probe-queue.log`（真 `dsh --profile sdk`，两处一致）：

```
[+ 1115ms] << session.status  running     ← 比 turn/start **早约 1ms**
[+ 1116ms] << turn/start      turn=1
[+ 1123ms] << user/message    （我们的那句话）
[+ 5600ms] << assistant/message turn=1 step=1
[+11245ms] << turn/end        turn=1
[+11680ms] << session.status  idle        ← 比 turn/end **晚**
```

⇒ 收到 `running` 的时候**还没有轮**（更没有气泡）；收到 `idle` 的时候**轮已经收了**。

⇒ **"按 `messageId` 找那条气泡"这个形状，根本填不出值。**
`messageId: ''` 不是疏忽，是**那个字段没有可能的值**。

⚠️ 而这件事的代价不只是"没修好"——它还**把排查引到了错的方向**：
`07-APPENDIX.md` §1.5 记着有人据此判断成"没有 UI 读它"，
于是去界面里找，白找一圈。**一个假地址让两个人都看错了地方。**

### 1.2 ⇒ 地址改成**轮**

过程属于**一轮**（一次问答），不属于**一个气泡**——气泡是这一轮到了某个时刻才出现的。
所以 `message/status` 的地址是 `turn`。

> 这一点在批 3 做四档（步骤流水 / 推理原文）时**同样成立**：
> 步骤属于轮，不属于气泡。所以这不是权宜之计，是**长期正确的地址**。

## 二、三件事，缺一件都会退回原样

| # | 做什么 | 缺了会怎样 |
|---|---|---|
| ① | **服务端按轮寻址** | 客户端拿不到能用的地址（就是原来的样子） |
| ② | **客户端一张人话表** | 内部状态名上屏（违反人格硬规则第 6 条「不许提内部词」） |
| ③ | **屏幕上真的画出来** | 链子断在最后一米，**而 `test/unit` 全绿也发现不了** |

⚠️ ③ 是这一批唯一"必须搭起屏幕才能验"的一环 —— 见 §五。

### 2.1 一句话：「它正在做这件事…」

```
服务端  turn/start  ⇒  emitTransient({ type:'message/status', turn, state:'started' })
                            │
客户端  timeline     ⇒  _turnState = 'started'   （认不出来的状态**不认**）
                            │
        process_words ⇒  'started' → '它正在做这件事…'
                            │
        chat_screen   ⇒  时间线尾巴上多一行（`BusyLine`）
```

它补的是哪段空白：用户按下发送之后、**它出第一个字之前**，屏幕上唯一的变化
是自己那条气泡从"已交出去"变成"已收到"——然后就什么都没了。
**走查里 8/10 的放弃点就落在这儿**（"它到底收到没有"）。

## 三、⚠️ 顺手补掉的一个洞：`forceClose` 会**留下一轮永远不说话**

原来的 `forceClose` 是这样找要收的轮的：

```js
const turn = this.openTurn;      // ← 只找"**有 writer 的**那一轮"
```

于是这一类轮**它看不见**：

```
一轮开了 → 一个字都还没说 → 进程没了 / 被卸了
```

后果两头都坏：

| 坏在哪 | 后果 |
|---|---|
| **不说话** | 用户永远等一条不会来的回答（**N19 要挡的正是这个**） |
| **不从 `#turns` 里删** | 那一轮**永久残留**（泄漏），而 `openTurn` 永远找不到它 ⇒ 谁也清不掉 |

⇒ 现在 `forceClose` 遍历**所有**还没收尾的轮，而且**没有 writer 也要说一句**：

```js
forceClose(reason, { line })   // line = "一个字都没说"时说的那句
```

各条路的 `line` 不一样（都得是人话，且要说清怎么办）：

| 什么情况 | 对它说的话 |
|---|---|
| 进程死了 | 「刚才我断了，这条没做完。再说一次吧。」 |
| 接不上活 | 「我现在接不上活。你这句话我记下了，等我缓过来再说。」 |
| 被卸下 / 收工 | 「这条我没说完就断了。」 |

⚠️ **这几句以前是"瞬态 `error`"**——而**客户端今天不渲染瞬态 `error`**
⇒ 用户**什么都看不到**。现在它们**落盘、上时间线**，所以看得见。
（瞬态那条留着，是给"盘满了、落不下去"的场合兜底的——那正是瞬态存在的理由。）

## 四、H4：不许永久停在"它正在做…"

手册 **H4** 说得很难听但很准：

> 过程可见性没有乱序保护 / 超时收敛 ⇒ 卡住时**永久停在"在查资料"，比空白更坏**。

那一行提示只要亮着不灭，就是**在屏幕上说假话**。所以它有两个"必灭"条件：

| 什么时候灭 | 靠什么 |
|---|---|
| 这一轮收口了 | `message/end` |
| **它断了 / 接不上活** | 瞬态 `error` |
| 一轮开了但一句话没说就断了 | 上面 §三 那条落盘的交代 + `error` |

⚠️ 还有一条**很容易漏**：`_hasOpenAssistant` 那条兜底（给断线重连用的，
因为瞬态不落盘、重连不会补发）会在"气泡还开着、但它已经死了"的时候
**把提示点回来**。⇒ 所以多了一个 `_agentDead`：

```dart
String? get agentLine {
  if (_agentDead) return null;   // ← 知道它死了，就别再说"它正在做"
  ...
}
```

**乱序保护**（H4 的另一半）也在客户端：迟到的旧轮（`turn` 比见过的小）**直接丢掉**。

## 五、验收

```bash
cd v2/services/core && npm test                       # 167 条（这一批占 3）
cd v2/apps/mobile && flutter analyze && flutter test test/unit   # 46 条（占 10）
cd v2/apps/mobile && flutter test test/widget         # 5 条（**全是这一批新加的**）
```

### 5.1 ⚠️ 为什么非要加 `test/widget`（v2 的第一个）

`test/unit` 能证明的是**模型**产出了那句话（`timeline.agentLine`）。
而 S2 这个缺陷的原始形状恰恰是 **"链子断在中间、屏幕上看不出来"**——
拿模型测试去验它，等于**用会绿的那一半去证明坏的那一半没坏**。

⇒ 那 5 条 widget 测试搭起真屏幕、从**唯一那个入口**（`ChatController.ingest`）喂事实进去：

```
★ 一轮开了、还没出字 ⇒ 屏幕上真的有一行「它正在做…」
★ 它说出第一句之后，提示还在
🔴 收口之后提示必须消失（H4）
🔴 它断了 ⇒ 提示也得消失（H4）
  认不出来的状态 ⇒ 屏幕上**保持安静**（不许把内部词摆出来）
```

### 5.2 公网实测（真服务、真 agent、真浏览器协议）

从公网接上 `wss://w.stalkerai.cn/api/stream`，发一句话：

```
[+  234ms] << user/echo seq=25 "用一句话说今天星期几"
[+  255ms] POST /api/say → 200
[+ 1320ms] << message/status   turn=1  state=started  messageId=undefined  seq=undefined
[+ 3474ms] << message/start seq=26
[+ 3486ms] << message/text seq=27 "今天是星期日。"
[+ 3492ms] << message/end seq=28
```

三件事一眼可见：

| 看的 | 结果 |
|---|---|
| 地址是「轮」不是空串 | ✅ `turn=1`，`messageId` **压根不出现**（不再有假地址） |
| 它仍然是**瞬态** | ✅ `seq=undefined`（决策 P-g） |
| 它**真的补上了那段空白** | ✅ **比第一个字早 2.1 秒**（+1320ms vs +3474ms） |

### 5.3 兼容性：旧客户端会不会被这个改动弄坏

`message/status` 的负载变了（去掉了 `messageId`）。**结论：不会。** 理由是实测过的：

旧客户端的处理是 `_findMessage(event['messageId'])` —— `messageId` 变成 `undefined`
⇒ 传 `null` ⇒ `_findMessage` 返回 `null` ⇒ **当场 return**。
也就是说**旧客户端本来就是什么都不做**，现在依然什么都不做。
⇒ 行为逐字节没变。（何况它是个**瞬态**：不落盘、不重放，不在"字段冻结"管的那个范围内。）

## 六、一条被改掉的**错测试**（值得单独记）

`test/agent.test.js` 里原来有这么一条：

```js
assert.equal(dispatcher.translator.forceClose('failed'), false, '还没有气泡，没什么可收的');
```

**它把缺陷本身写成了断言。** "还没有气泡就没什么可收的"——而那正是
"一轮开了、一个字没说、然后没了 ⇒ 用户永远在等"这个 bug 的**辩护词**。

⇒ 现在换成反过来的那条，并且**在注释里写明它原先断言的是错的、错在哪**。

⚠️ 顺带一个教训：**那条测试失败的时候，`npm test` 挂了 300 秒才被杀掉。**
原因是它没有 `try/finally`，断言一失败 `runtime.shutdown()` 就没跑到
⇒ 假 agent 的子进程一直活着 ⇒ 整个套件被拖住。
⇒ 现在它包了 `finally`，并注明为什么那不是洁癖。
