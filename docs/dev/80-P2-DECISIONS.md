### P2-11 租户容器**没有 CPU 上限**（§六 #69）
* **是什么**：渲染租户单元那一段只有 `--pids-limit` 与 `--memory`，**没有 `--cpus`**；
  本机 **32 线程** ⇒ 一个租户里跑飞的 agent **能把整机 CPU 吃满**（内存那条挡住了，CPU 这条没有）。
* **选项**：① 渲染时加 `--cpus=`（值定多少**是容量策略**，你拍一个数，例如 2 或 4）
  ② 先明说"不设"（记账：一个租户能拖慢全机）
* **我的建议**：**①**，值给 **2**（本机 32 线程、两个租户 ⇒ 留足余量；一条命令改 `scripts/create-tenant-pool.sh`）。
  ⚠️ 只影响**以后新建**的容器（现在那两个不动）。
* **不拍的后果**：一个租户跑飞 ⇒ 主线（你自己那份）和别的租户一起被拖慢。

### P2-12 监控**只剩内存**（§六 #68）
* **是什么**：只有内存准入（而且本机每层 `memory.max=max` ⇒ **判据算不出来**）＋ OOM 那一处；
  **磁盘 / inode / fd 一个采样都没有**。手册 §十一 那张 80/88/92/95 分级闸是"目标态"。
* **选项**：① 做磁盘/inode/fd 采样 ＋ 按手册那张表分级告警 ② 先明说"只有内存那一条"
* **我的建议**：**①**（阈值不用你拍 —— 手册那张表已经定了；这是纯加法，不动运行时）。
  ✅ **2026-09-24 补**：**规则那一半已经就位**（`src/disk-grade.js` ＋ 4 条判据，含「与手册逐条对表」）⇒ 你说「做」我就只剩**接线**（5 分钟一次 ＋ 按级动作）；说「先不做」它也不碍事（**不改运行时**）。
* **不拍的后果**：盘写满/句柄耗尽那种事故**没有任何预兆**（`66` 那条"没有每用户磁盘配额"是它的兄弟）。
