# 24 · **延迟重启**：重启不许切断正在说的那一轮（欠账 21）

> 手册 `06-OPERATIONS.md` **§8.3「重启自己的正确姿势」**：
> ⚠️ 不要直接重启服务——那会把**正在说话的助手**连同这一轮回答一起杀掉，
> 用户会看到话说一半没了。要**延迟重启**，先把话说完。
>
> 而这一条以前**只是个告诫**：`restart-core.sh` 拿到 PID 就 `kill -TERM`，
> 谁在说话它不管。⇒ 这一批把它做成机制。
>
> **代码**：`v2/services/core/src/turn-status.js`（新）· `src/serve.js`（心跳接线）·
> `scripts/restart-core.sh`（默认等）· **测试**：`test/turn-status.test.js` **+6**

## 一、怎么知道"它手上还有话"

服务每秒钟算一次，变了就写进 `data/status.json`：

```json
{"busy":true,"openMessageId":"m_mua0p05x_2","pending":0,"turns":1,"updatedAt":1789920909593}
```

⚠️ **三个来源缺一不可**（这是这一批唯一踩到的坑）：

| 信号 | 意思 |
|---|---|
| `openMessageId` | 已经开始说了（有没收口的气泡） |
| `pending` | 话还没变成轮（`deliver` 收下了、还没轮到它） |
| `turns`（挂了几个超时计时器） | **轮已经宣布、但它一个字都还没说** |

**为什么第三个非有不可**：第一版只写了前两个。实测那一段空窗有**秒级**以上
（spawn agent + 建会话 + 喂背景），而那时**前两个都是空的** ⇒
重启会正好切在这段空窗里 —— **也就是这条功能最该防的那种情况**。
填上第三个之后真机再验：`busy:true, turns:1`，重启**等了 14 秒**才动手。

### 1.1 为什么用"心跳 + 一个文件"而不是"监听某个事件类型"

* "一轮在跑"的来源会变多（今天三个）；事件驱动那种写法，来源一变就得回去改一遍。
* 心跳只回答一个问题：**现在**手上有没有话。
* 而且那个文件**主人自己也能 `cat`** —— 排查时不用来问助手。

### 1.2 两个不好写对的地方

| # | 事 | 不做会怎样 |
|---|---|---|
| 1 | **写盘的时机**：变了就写，**忙就一直写**（闲着一条都不写） | 只在"变了"时写 ⇒ 忙的那段时间 `updatedAt` 不刷新 ⇒ 重启脚本把它当成**陈的**（以为服务死了）⇒ 照样重启、照样切话 |
| 2 | **陈了的状态不许再等** | 服务已经死了就没人更新它；拿一句旧话永远等下去 = **重启脚本卡死**，那比切一轮话更坏 |

## 二、`restart-core.sh` 的行为

```
scripts/restart-core.sh          # 默认：先等它说完（最多 180 秒），再重启
scripts/restart-core.sh --now    # 不等（**会切掉正在说的那一轮**）
scripts/restart-core.sh --fresh  # 清日志 + 重启
```

* 等的时候会**说出来**：`▶ 它手上还有话，等它说完（最多 180 秒）…` → `✓ 它说完了（等了 14 秒）`
* 上限到了就**照样重启**，并把这件事说出来（等一个卡住的服务更坏）。
* 那两个量（轮询间隔 / 最长等多久）是脚本里的**具名常量**，不散在代码里。
* ⚠️ 部署脚本 `deploy-web-v2.sh` 也走这个 ⇒ **部署同样不会切断用户正在等的那句话**。

## 三、验收

```
$ cd v2/services/core && npm test    → +6 条（`test/turn-status.test.js`）
```

| 闸 | 钉什么 |
|---|---|
| 🔴 三个来源缺一不可 | 少任何一个，"忙"就漏一段（含"轮在飞但没开口"那条回归） |
| 🔴 读不懂就当"不知道"，**不许**猜成"不忙" | 猜错的方向是"重启把话切了" |
| 🔴 陈了的状态不许再等 | 否则等一个死掉的服务 = 卡死 |
| 写盘时机 | 闲着不写、忙着一秒一刷 |
| 写不进去不抛 / start-stop 不泄漏 | 它只是旁路信息 |

**真机验收**（这一条比自动闸重要）：

```
闲着：{"busy":false,...,"updatedAt":…}
发一句要查天气的慢活（要调工具）：
      {"busy":true,"openMessageId":"m_…_2","pending":0,"turns":1}
同时跑 restart-core.sh：
      ▶ 它手上还有话，等它说完（最多 180 秒）…
      ✓ 它说完了（等了 14 秒）
      ▶ 停掉旧服务… ▶ 起新服务…
```

⇒ **"重启不再切断正在说的话"从一句告诫变成了机制。**
