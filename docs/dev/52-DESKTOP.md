# 52 · 桌面（底部一条）+ 聊天浮窗（四边 30 · 阴影 · 三档）

> **这一篇回答**：登录之后那一屏长什么样、为什么这么摆、以及**这一刀修掉了哪三个真根因**。
>
> **主人 2026-09-22 原话**：
> *"首先，页面底部是一个桌面。聊天窗口是一个左右上下 margin 为 30 的浮窗，有阴影。"*
> 问过之后他选：**桌面 = 屏幕最下面那一条**（不是整页底图）、**一进来是收起档**。
>
> 上一版（`50-DESKTOP-FLOATER.md`）**撞在可访问性硬闸上被回滚**；这一版是按 D3.5
> 重做的，并且把当时那三个根因都钉上了判据。

## 一、形状（从上到下）

```
┌──────────────────────────────────────────────┐
│  （通知浮条：最上面那一层，仍在 `Stack` 里）      │
│  ┌────────────────────────────────────────┐  │
│  │  聊天浮窗（抓手行 + 时间线 + 输入条）     │  │  ← 四边各留 **30**
│  │  三档：收起 / 半开 / 最大化              │  │     阴影 blur 32 · α.45 · offset(0,-6)
│  └────────────────────────────────────────┘  │
│                     ↕ 也是 30                 │
│  ┌────────────────────────────────────────┐  │
│  │ 桌面（图标一条，现在是「会话」一个）      │  │  ← 贴着屏幕底
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

| 元素 | 在哪 | 数值出处 |
|---|---|---|
| 四边边距 **30** | `FloaterMetrics.margin` | 手册 `08-SPEC.md` §10.1 阈值总表（**这一批改过**） |
| 阴影 | `chat_floater.dart` 的 `BoxShadow` | 同上（沿用：blur 32 · α.45 · offset(0,-6)） |
| 半开比例 | `FloaterMetrics.halfRatio` | 手册 §6.2「高度用**系数**表达」 |
| 图标格 ≥44 | `desktopIconBox` | D3.6 命中区 |
| 默认档 **收起** | `ChatScreen.initialTier` | 主人 2026-09-22 定 |

**两条铁律没变**：**Z1** 浮窗永远在最上（任何页面盖不住它）；**Z3** 盖住不是铺满（四边留边距）。
新增 **Z4**：**桌面在底部一条**，浮窗浮在它上面，两者之间也是同一个边距。

## 二、🔴 上一版死在哪，这一版怎么修的（三个根因，都值得记）

### 根因 1：浮窗高度**定死**，再把字塞进去（`798px` 纵向溢出）

上一版是 `屏高 − 边距` 当高度，里面再放 chrome + 时间线。字一放大，
chrome（抓手行 + 状态条 + 输入条）比容器还高 ⇒ `Expanded` 被挤到负数 ⇒ 溢出。
**那正是 D3.5 的反面**（容器跟字算，不是字跟容器）。

**这一版**：
- **收起档不写死高度** —— 它就是抓手行那点内容，高度由内容算（`SizedBox(height: null)`）；
- 半开/最大化用**比例**（系数，不是像素）；
- 高度由父层 `LayoutBuilder` **量好传进来** —— 所以不用在 `Positioned` 里套 `LayoutBuilder`
  （那个坑会把整棵树报 `ParentDataWidget` 错，见 `50` §二）。

### 根因 2：空屏**不可滚**，被挤扁就溢出（`168px`）

桌面占了 30 + 一条之后，浮窗能用的高度变小了。3.1 倍字号下：
空屏那一块只分到 **104px**，而它自己要 **272px** ⇒ 硬闸当场红。

**修法不是把字写小**，而是让它**没地方时能滚**（有地方时仍然居中）——
和那条 `ListView` 时间线是同一个姿势。⚠️ 这条**只在实测里才看得见**：
探针量出来 `_EmptyState` 的 `constraints: h<=104`、`size: (676, 104)`，而它想要 272。

### 根因 3：🔴 拖拽手势**绑在了整块浮窗上** ⇒ 吃掉时间线的滚动

第一版把 `Listener(onPointerMove: …)` 挂在整块浮窗外面，于是**往上拖时间线**
被当成"把窗口拉高"。这一条不是溢出，是**功能坏了**——
而且它当时**没有判据**：是 `accessibility_test` 里"重发那个入口"那条先红的
（它要把时间线拖到最老一条，拖不动 ⇒ 找不到「重发」）。

**修法**：手势**只绑抓手那一行**（手册 §6.3 的原话就是"竖向拖**抓手 / 标题行**"）；
整块浮窗那层仍然 `HitTestBehavior.opaque`，但它**只负责挡住**（点浮窗内部不许漏到桌面）。
⇒ 判据补了一条**回归**：拖时间线**不许**改浮窗高度。

### 根因 4（**闸没抓到，是量出来的**）：桌面那一条被缩成"内容那么宽"

`Column` 默认 `crossAxisAlignment: center` ⇒ `AppDesktop` 只拿到 **100px 宽**并居中，
而它该是**横跨整宽的底部一条**。⚠️ **截图上看不出来**（桌面底色与页面底色是同一个 `paper`），
是在真视口（1280×614）下量矩形才发现的：`桌面 = Rect.fromLTRB(590, 525, 690, 614)`。
⇒ 外层 `Column` 加 `crossAxisAlignment: stretch`，并补一条判据（`desk.width == screen.width`）。

> 📌 **这一条值得记的原因**：它说明"看一眼"**不能代替"量一下"** ——
> 颜色一样的时候，眼睛看不出一个 100px 的盒子和一个整宽的盒子。
