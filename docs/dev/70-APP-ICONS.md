# 70 · 小程序的图标库（**每个小程序都一定有一个默认 icon**）

> **主人 2026-09-23**：*"你要做一个 icon 库，给每个小程序创造一个默认 icon。"*
>
> 它服务的是**产品原则 2**（看不见的东西等于不存在）：桌面上一个空白方块，
> 用户既认不出那是什么，也不敢点。

---

## 一、动手之前是什么样（**三个真问题**）

| # | 事 | 后果 |
|---|---|---|
| ① | 库只有 **14 个名字**（dice/quiz/list/…） | 日常那些事（天气、吃药、菜谱、日历…）**一个都没有** ⇒ 只能硬塞一个不相干的 |
| ② | `app_create` **必须**给一个白名单里的名字，给不出/给错就**当场报错** | 造小程序的人（模型）一忘这一格，整件事就**失败**；它要是随手编一个，也失败 |
| ③ | 🔴 **那张表在服务端有两份**（`apps.js` 一份、`mcp-apps-server.mjs` 又抄了一份） | 而客户端那条"两张表不许漂"的判据**只对了其中一份** ⇒ 另一份漂了没人知道（本项目第一条纪律就是"同一份数字不许有两处"） |

## 二、这一版做成什么

| 项 | 定成什么 | 为什么 |
|---|---|---|
| **一处出处** | `v2/services/core/src/app-icons.js`（**唯一**）。`apps.js` 与 `mcp-apps-server.mjs` 都从它读；客户端那条判据也逐字读它 | 治 ③。加一个图标 = **两处各加一行**（服务端 + 客户端那张"名字→图形"表），有判据钉着不许漂 |
| **库多大** | **54 个**（原来 14 个**一个没删** + 扩了 40 个日常的） | 治 ① |
| **怎么挑** | `pickIcon(title, id)`：**先在名字里认词**（中英文都认，**55 组关键词**），认不出就按 id **稳定地**落在一个**中性子集**里 | ⚠️ 认不出时**不是**在整个库里乱落：一个叫"算一算"的小程序随机拿到"药"或"飞机"，比拿到一个中性记号更让人困惑 |
| **稳定** | 按 id 做 **FNV-1a** 哈希取模（**不用随机数**） | 同一个小程序在任何设备、任何时候都得是同一个图标 |
| **给不给都行** | `app_create` 的 `icon` **不再是必填**；给了白的照用，没给/给错**一律自动配**（`resolveIcon`） | 治 ②：**桌面上出现一个空白图标，比换一个相近的图标坏得多** |
| **如实回话** | 自动配过的时候，工具回执里带一句`（桌面上的图标我按名字配了一个：…）`，并把 `icon` **放进回执** | 不这么说，模型会以为它挑的那个生效了 |

## 三、挑图标的规矩（**顺序就是优先级**）

1. **具体词赢过笼统词**：`记账` → wallet，`记事` → note，`购物清单` → checklist。
2. **中英文都认**：`weather` / `todo` / `calculator` … 也在表里（模型的 id 常常是英文）。
3. 认不出 ⇒ **中性那十个**（note · list · star · book · checklist · photo · paint · document · clock · leaf）。
4. 空标题 / 怪 id / 非字符串 ⇒ 照样给得出（有判据：**任何输入都必须落在库里**）。

⚠️ **加一个图标要动两处**（这是刻意的，因为图形只在客户端那一层）：
服务端 `app-icons.js` 的 `ICONS` + 客户端 `widgets/mini_app_icons.dart` 的一行常量。
`test/unit/app_spec_test.dart` 会**逐字对**这两处，并额外钉一条：
**库里每个名字都得画得出自己的图形**（谁都不许落到"认不出"那个兜底图标上）。

## 四、判据（这一批 **+19 条**）

| 那一份 | 条数 | 钉的是什么 |
|---|---|---|
| `test/app-icons.test.js`（新） | 12 | 库干净（唯一/合法/≥40）· **老 14 个一个不许删** · 中性子集与关键词表**只指向库里的名字** · 认得出就挑得准（中英文 17 例）· **顺序对** · 认不出落中性且**稳定** · **任何输入都给得出** · 不同 id 一般落不同图标 · `resolveIcon` 三种情形 · **建小程序给错图标不抛错** · 白的照用（负向对照）· **一个字母都不给图标也给得出** |
| `test/apps.test.js`（改） | 1 | 原来那条"给错图标 ⇒ 抛错"**改了行为**，判据跟着改成"配出来的在库里" |
| `test/apps-chain.test.js`（改） | 1 | 🔴 **建成的回执里要带回 `icon`**（第一版漏了 ⇒ 工具那边会把 `undefined` 念给模型听） |
| `test/unit/app_spec_test.dart`（改） | 2 | 两张表逐字对（**改读新的唯一出处**）· **库里每个名字都有自己的图形**（不许落到兜底） |

## 五、真机验证（2026-09-23）

**走模型自己那条路**（域套接字 `data/users/u2/apps.sock`，协议一行一条 JSON），
**故意不给 `icon`**：

```jsonc
// 发：{ op:'create', app:{ id:'tianqi-probe', title:'看天气', entry:'index.html', files:{…} } }
// 收：{ ok:true, id:'tianqi-probe', version:1, title:'看天气',
//       icon:'weather',                      ← ★ 自动配的
//       rootHash:'46534992d2ab…' }
```

`op:'list'` 里那一条也确实是 `icon:"weather"`。
⇒ **"不给图标也一定有一个"这件事，在真机上成立**（不是只在小测试里成立）。

⚠️ **留在那儿的一个探针**：`tianqi-probe`（"看天气"）建在了**测试租户 u2 的桌面**上——
它是这次取证留下的，**没删**（那条套接字上没有"删掉一个小程序"这个动作）。
它在那位测试用户的桌面上会一直显示，**主人的世界里没有它**。

## 六、这一版**没做**的（明说）

| 没做 | 为什么 |
|---|---|
| 让造它的人**画一张图**（PNG/SVG 上传） | 制品是"一整段 HTML、不许引外部资源"（`59-USER-APPS.md`）；图标走**同一张白名单**最省事也最安全。真要自定义图形，是另一条决策 |
| 用**彩色 emoji** 当图标 | emoji 是字体渲染、**没法 tree-shake**、各平台长得不一样；而 `Icons.*` 是常量、跟主题走、线上画得出来（`52-DESKTOP.md` §6.3 那个坑） |
| 按**分类**给图标（用户自己选分类） | 现在没有"分类"这个概念；名字里认词已经够用（而且不用多问用户一件事） |
| 让用户**自己换图标** | 那要一个新界面 + 一个新的写入口；先让"每个都有"这件事成立 |
