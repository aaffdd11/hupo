## 二、🔴 实测：语音那把 key **不能**给图像/视频用

**这一条不是推断，是当天在本机真打上游量出来的**（`scripts/check-ark-image.mjs --preflight`；
这一档**不花钱**：模型名是编的、请求走不到业务）。
拿的是盒子里那份**真的语音凭据**（`v2/services/core/data/creds/u2.yaml`；**值一个字符都没打印、没落盘**），
按方舟那套 `Authorization: Bearer` 发到 `ark.cn-beijing.volces.com`：

| 拿哪一样去当方舟钥匙 | 上游回话（**原话照抄**） |
|---|---|
| 语音**新版 API Key**（36 位 UUID 形状） | `401 AuthenticationError: The API key doesn't exist.` |
| 语音**旧版 Access Token**（60 位） | `401 AuthenticationError: The API key format is incorrect.` |
| 语音 **App ID**（47 位） | `401 AuthenticationError: The API key format is incorrect.` |

⇒ 形状对的那把（UUID）方舟也**不认**（"这把钥匙不存在"）。
**两组凭据是两套东西**，不是"同一把的两种写法"：

| | 语音（豆包语音） | 图像 / 视频（火山方舟） |
|---|---|---|
| 主机 | `openspeech.bytedance.com` | `ark.cn-beijing.volces.com` |
| 鉴权 | `X-Api-App-Key`(AppID) ＋ `X-Api-Access-Key`(Token)，或语音控制台那把 API Key（`X-Api-Key`） | `Authorization: Bearer <方舟 API Key>` |
| 钥匙从哪拿 | 语音技术 →「API Key 管理」/ 应用管理 | 方舟 →「API Key 管理」 |

⇒ **"语音那把顺手也给图像视频用"这条路是死的。**
⚠️ 反向（方舟 key 拿去当语音用）**没测过**，也不建议试：
语音那条链的协议是自成一体的（`asr-doubao.js`），换钥匙等于换平台。

⚠️ **顺带如实记一笔**：方舟侧确实有"语音模型"的接入文档
（`docs.volcengine.com/docs/ark/agent-plan-*-voice-model`），
但**它能不能顶掉我们现在"边说边出字"的实时识别、以及是不是同一把 key —— 没核实过**。
⇒ 若哪天要"真·一个 key"，那是一条**要重新调研的路**，不是改个字段。

## 三、【已成立】图像与视频**已经是同一把**钥匙

主人要的"最简便"，**图像＋视频这一半早就做到了**：

- 规则唯一出处：`src/creds.mjs` 的 `sharedKeyOf()` —— 自己那一栏空着就**明着借**对方那一栏；
  自己那栏有就用自己的（他要真给视频单独一把也照他）。
- 口径：`credStatus()` 里 `image` / `video` 两格的意思是"**这条路现在能不能用**"
  ⇒ 只贴一栏时两格都 `true`（否则页面会说"还没填"而其实能用 = 页面在说假话）。
- 界面：视频那一屏现在写的是「**不用填 —— 跟「图片」是同一个 API Key。**」
- 判据：`test/video-use.test.js` **S1–S5**（借/对称/自己优先且看真 `Authorization` 头/两栏都空一个字节不发/**别人那份借不到**）
  ＋ `test/creds.test.js` 的 `sharedKeyOf` 四条边界。

⇒ **所以"最少"就是两把：方舟一把（管图像＋视频）＋ 语音一把。** 已经是能省到的下限。
