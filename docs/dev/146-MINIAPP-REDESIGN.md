## 〇·补 · **主人 2026-09-30 给了四样能力**（方向已定 · 这一节在最前面）

> **他的原话**：*「我想你考虑一下，应用是一个聊天和一个桌面系统。桌面可以创建小程序，
> 我们也叫 app，也叫小应用，指的同一个东西。它可以**访问网站**，可以有**自动化任务**
> （注册制，在设置里可以看到也可以关闭），可以**访问自己的 agent**（通过接口），
> 有**自己的存储**。对吧？」*

**对。** 而且比这更进一步：**这四样里的第一样，平台里已经有一条在跑** ——
就是"问它一句"（`ask`）：

| 那一刻 | 盘上/代码里的形状 | 它保证了什么 |
|---|---|---|
| 制品**声明** | `permissions: ["ask"]` | 没声明 ⇒ **403**「这个小程序没说要问话」 |
| 主人**允许** | `apps.grants(id)`（`grant.json`：`{"permissions":["ask"],"at":…}`） | 没允许 ⇒ **403**「你还没允许它用你的钥匙」 |
| **限额** | `askQuota()`（`ask.json`：`{"day":"…","n":1,"lastAt":…}`） | 超额 ⇒ **429 ＋ 原因**（口径在代码里） |
| **先记再花** | `bumpAsk()` | 不会"花了没记" |
| **两端一份判定** | 盒子那份走**同一个** `checkAppAsk()`（经隧道） | 宿主与盒子**不可能分叉** |

⇒ **所以这次不是"发明一套权限系统"，而是把 `ask` 这条先例推广到另外三样**
（存储 / 访问网站 / 自动化任务）。这条先例就是"**注册制：声明 → 你允许 → 限额 → 留痕**"。

### 四条能力逐条落到架构上

| 能力 | 今天 | 要补什么 | 跑在哪儿 | 代价 / 风险 |
|---|---|---|---|---|
| **自己的存储** | ✗（不透明源，`localStorage` 抛错） | 壳侧**一格库**（每 app 按人一个文件）＋ 受限 op（第一步只给 KV） | 服务端 / 他盒子里 | 上限＋删除（配额那条账 `#66`） |
| **访问网站** | ✗（CSP `connect-src 'none'`） | **声明要访问的域名** ⇒ `connect-src` 白名单 ＋ 留痕（复用 `egress-log`）＋ 返回体上限 | 浏览器 / WebView **直连**（前提：app 有自己的源） | 出网＝钱与风险（`#65` 那条账） |
| **自动化任务（注册制）** | ✗ | 制品里声明 `tasks` ⇒ **设置里可看可关** ＋ 调度器 ＋ 超时/重试/限额；**结果回到那一间的对话**（"我去做，做完叫你"那条已经在跑 ✓） | **他自己的盒子里**（串行限流：768MB） | 与 `#66`/`#67` 同族：配额与闲置策略 |
| **访问自己的 agent** | ✅ **一半**（`app-ask` 就是它） | 从"问一句"升级成**一条正式接口**（按 app 签名 / 限流 / 预算），并**两端都通** | 服务端 → 那一间 | 每次调用都花钱 ⇒ 预算 ＋ 留痕 |

### 我只改两处用词（其余照他说的做）

* 🔧 「访问网站」写成「**声明它能访问哪些网站**」——"随便上"与"声明＋看得见＋留痕"是两种产品；
  后者才让"在设置里关掉它"这句话成立。
* 🔧 「自动化任务」写成「**它注册一个任务，你允许了它才会跑**」，而且**跑在你自己的盒子里**
  （不是我们的服务器），结果**回到那一间的对话**里。

### 这四样一起意味着三件"地基"活（先说清，不然会做成半拉子）

1. **每个 app 自己的源**（一 app 一域名 ＋ 泛域名证书 ＋ 按 Host 路由）——
   它是"访问网站 ＋ 两端一致 ＋ 每 app 数据隔离"的**共同地基**（不做它，网页与安卓永远不一致）。
2. **一张"每个 app 要什么"的设置页**（声明 → 你现在允许了没有 → 关掉）。
3. **配额与限额**（存储上限 · 每天任务次数 · 单次任务时长 · agent 调用预算）——
   没有它，四样里任何一样都能把盒子撑爆（`#66` 今天还开着）。

### 建议的先后（每步都能单独收尾）

| # | 做什么 | 为什么这个顺序 |
|---|---|---|
| 1 | **存储 ＋ 访问网站 ＋ 那张设置页**（**含地基**：自己的源 / 配额） | 最小闭环：一个"能记住进度、能取一次网页数据"的小程序；地基放在这一步，才不会让 2/3 返工 |
| 2 | **自动化任务**（注册制 ＋ 调度 ＋ 结果回到对话） | 它要地基（配额/自己的源）先立住 |
| 3 | **访问自己的 agent**（`app-ask` 正式化：签名接口 ＋ 预算 ＋ 两端） | 今天有一半，收口最容易 |

## 一、先把今天的事实摆齐（都是查来的）

| 那一层 | 今天是什么 | 出处 |
|---|---|---|
| **制品** | 「一版 = 一个目录」：`<app>/versions/<N>/{manifest.json,index.html}`；`current.json` 只是**版本指针** | `data/hupo/apps/…` 实测 |
| **在哪跑** | **Web**：`<iframe sandbox="allow-scripts">`（**不透明源**）· **Android**：普通 `WebView`（另一个原点，**不装桥**）· **iOS**：没有 | `mini_runtime_web/native.dart` · §14.1 |
| **怎么取** | 另一个原点（`apps.stalkerai.cn`）· **签名短时效入口**（绑人＋绑版本＋绑到期）· `/a/<id>/<version>/<rel>`（不可变快照）＋ `/w/<id>/<rel>`（活的工作区） | `app-serve.js` |
| **它的 CSP** | `default-src 'none' · script-src 'unsafe-inline' · style-src 'unsafe-inline' · img-src data: blob: · connect-src 'none' · base-uri 'none' · form-action 'none'` | `cspFor()` |
| **它有什么能力** | **只有一条**：Web 上 `postMessage {kind:'ask'}` ⇒ 壳替它问助手（用看的人的钥匙）· **Android 连这条都没有** | §14.1·补 |

## 二、结构性矛盾（一句话）

> 🔴 **今天这套架构用「物理隔离」换安全**（不透明源 ＋ 断网 ＋ 单文件），
> 而"**要存东西**"「**要取数据**」这两件事**在物理上就不可能**加进来 ——
> 它们不是"顺手补一个 API"，而是**和那条边界打架**。

⇒ 所以"重新设计"的真问题不是"加不加 SQLite"，而是：

> **我们要不要继续用"物理隔离"当安全模型，还是换成"能力授权"？**

（能力授权 ＝ **默认什么都没有**；制品里**声明**要什么 ⇒ 装的时候看得见 ⇒ 壳按声明**逐条给**。）

## 三、四条路（我摆开，每条都写清代价）

| | 路 A：**现状 ＋ 能力口** | 路 B：**一 app 一个源** | 路 C：**app 不是页面，是数据** | 路 D：**app 跑在他盒子里** |
|---|---|---|---|---|
| 一句话 | 沙箱不动，能力全走**壳的协议**（`kv.*`/`sql.*`/`net.*`/`ask`） | 每个 app 一个**自己的域名**（`<id>.apps.stalkerai.cn`）＋ `allow-same-origin` ⇒ 浏览器原生能力全活 | app 变成**声明式清单**（表单/列表/图表），**壳渲染** | app 的**后端**跑在他容器里（页面只是前端） |
| 存储 | 我们写（壳侧 SQLite，见 `B50`） | **浏览器原生**：OPFS / IndexedDB / WASM-SQLite 随它用 | 壳管（天然有） | 他盒子里随便（真数据库、真文件） |
| 取数据 | 我们写代理（白名单＋留痕） | **fetch 原生**（白名单靠 CSP `connect-src`） | ✗ 只能壳给 | 随便（能装包、能定时） |
| 表达力 | 高（还是 HTML/JS） | **最高**（就是一个真网站） | **低**（只能摆几种控件） | 最高（前后端都他自己的） |
| 我们少写/多写 | **多写**（每个能力一条协议＋两端实现） | **少写**（交给浏览器） | 少写 | 多写（运维：崩溃/端口/更新） |
| 两端一致 | 差（Android 没桥 ⇒ 能力只能在网页给） | **好**（两端都是普通网页 API） | **最好**（壳渲染，两端一模一样） | 好（前端两端一致＋后端同一个） |
| 安全面 | **最小**（令牌永不出壳；每件事可留痕） | **变大**（出网/存储/配额/滥用要自己管；同源邻居问题**消失**——每 app 自己的源） | 小 | 中（他的代码在容器里跑） |
| 主要成本 | 协议会越写越长；**离线不行**；单文件 HTML 会胖 | **基建**：泛域名证书 ＋ 按 Host 路由 ＋ 每 app 配额/清理 | 表达力换安全 ⇒ 做不成"想要什么生成什么" | **容器内存**（今天一台 `dsh web` ≈390MB，盒子 768MB）＋ 运维 |

## 四、我推荐的形状：**分档 ＋ 一张能力清单**（主轴）

**主轴一句话**：

> **一个小程序 ＝ 一份制品（文件） ＋ 一格数据 ＋ 一张能力清单**；
> 「在哪儿跑」只是**运行档**，能力**由清单声明、由壳按人授予**。

**能力清单**（制品里一节，随签名入口一起下发；**默认 ∅ ⇒ 与今天的沙箱完全等价**）：

| 声明 | 壳给什么 | 今天能不能做 |
|---|---|---|
| （什么都不写） | 就是今天的沙箱：能算、能画、**不能存、不能连** | ✅ 已等价 |
| `storage: kv`（或 `sql`） | **壳侧一格库**（每 app 按人一个文件）＋ 受限 op | 就是 `B50` 那条 |
| `net: [域名…]` | **壳代理**：白名单 ＋ 留痕（复用 `egress-log`）＋ 返回体上限 | 零件已有（`egress-log` · `outbound` 申报） |
| `ask: true` | 那条"替我问他一句"（今天 Web 只有这条） | ✅ 有（两端补齐是另一件事） |
| `service: true` | 在**他盒子里**起一格（路 D 那一档） | 单开一档，不做默认 |

**为什么这样切**：把安全从"**物理隔离**"换成"**能力授权**"，才是**能长大的形状** ——
物理隔离那条边界今天已经挡掉了"存储/网络"，而能力清单是"**加一条只写一行**"的形状，
并且**装之前用户看得见这个 app 要什么**（Android 权限那一套）。

## 五、想清楚一条硬要求之后，结论变了（**这一条是这一轮最值钱的思考**）

我本来倾向"**先不给 app 自己的源**，能力都走壳的协议"（路 A）—— 理由是我们少踩基建的坑。
但把"**两端一致**"当作硬要求（他今天已经因为"手机上能、网页上不能"吃过两次亏）之后，
发现它和路 A **冲突**：

> 🔴 **Android 那一侧不许装桥**（铁律，判据扫源码）⇒ WebView 与壳之间**没有可控通道** ⇒
> 路 A 的每一条能力**都只能在网页上给** ⇒ **小程序在两端能力不同**（今天就如此：`ask` 只有网页有）。
> 除非我们**破铁律去装一条窄桥**（我不建议），或者 —— **让 app 自己发请求**（fetch 在 WebView 里本来就能用）。

⇒ 所以真要"两端一个样"，**必须给每个 app 一条"自己发请求"的路**：即**路 B 那个"自己的源"**，
再加上一个**按人按 app 签名的受限接口**（签名我们已经有那一套）。这条一给，
存储（OPFS/IndexedDB/SQLite-WASM）与取数（fetch）**两端同时活**，而且我们**少写一半协议**。

⇒ **我的推荐是**：
**路 B 当骨架（一 app 一源 ＋ 声明式能力清单）**，但**能力清单照旧逐条授予**；
`storage` 先用**壳侧 SQLite**那一档落地（`B50`），把"给不给浏览器原生存储"留到第二步看实际需要再放开。

## 六、我建议**砍**的（明说，不留"以后再说"）

1. **不给 iOS 运行时** —— 保持 `kNativeMiniRuntimeIOS = false`（Apple 4.7.4，那条铁律照旧）。
2. **不做"app 直连外网"** —— 只给**壳代理 ＋ 白名单 ＋ 留痕**（出网是钱与风险的入口，而白名单那条账 `#65` 今天还开着）。
3. **不做"默认给他一个后端"**（路 D 只作为"重 app"的一档，且要配额那条账 `#66` 先解决）。
4. **不做"大文件 / 长任务"** —— 盒子 768MB ＋ 没配额 ⇒ 先解决配额。
5. **不装任何原生桥**（包括"就一条 postMessage 的窄桥"）—— 铁律是花过代价换来的。

## 七、第一批落地（都能一两轮做完，且**每一步都有判据**）

| # | 做什么 | 判据（不看源码看行为） |
|---|---|---|
| 1 | **能力清单**进制品（`manifest.json` 一节）＋ 随入口签名下发 ＋ **发布时看得见** | 没声明 ⇒ 调那条能力**必须失败**；声明了才通 |
| 2 | **壳侧 SQLite（`B50`）**：每 app 按人一个库、**先只给 KV**、上限 ＋ 删除 | 换设备还在（按人存）· 删 app ⇒ 库一起没 · 触上限 ⇒ **如实拒**（不许静默写坏） |
| 3 | **`net` 代理**：白名单 ＋ 留痕（复用 `egress-log`）＋ 返回体上限 | 白名单外 ⇒ 拒（判据）；留痕里只有域名/时间/量，**没有正文** |
| 4 | 🔴 **给 app 自己的源**（路 B 的第一块砖）：泛域名证书 ＋ 按 Host 路由 ＋ **每 app 配额/清理** | 一个 app 读不到另一个 app 的存储（**同源邻居这条要能反着验**） |
| 5 | **两端补齐**：Android 那一侧也能 `ask`/`storage`（走"自己的源 ＋ 签名接口"，**不装桥**） | 同一份制品在网页与安卓上能力**逐条一样** |

## 八、要他拍的三点

1. **安全模型**：换成"**能力授权（清单 ＋ 逐条授予）**"—— 还是继续用"物理隔离"？（我建议换。）
2. **要不要给每个 app 一个自己的源**（路 B 那块砖）？（我建议要 —— 不然"两端一致"这条硬要求永远做不到。）
3. **`storage` 第一步给到哪儿**：**壳侧 KV**（我建议，够进度/历史/最高分）还是**浏览器原生**（OPFS/IndexedDB，灵活但要管配额与清理）？
