## 〇、主人的命题（本契约的总纲）

**原话（逐字）**：

> "**不是人用统一的 app，而是 app 为了人的需求而存在和改善**。然而同类型的、**底层数据或公开数据大抵相似**
> （比如新闻），**底层数据结构也大抵相似**；但**分析方法、用户私密内容却又有所不同**。"

这一句把契约切成**两半**，而且这两半必须**分开写、分开检查**：

| | **趋同的那一半**（可共享／可复用的骨架） | **分叉的那一半**（各人各样） |
|---|---|---|
| 是什么 | 清单形状 · 工作区布局 · 公开源的**字段语义** · 制品口契约 · 权限白名单 | **分析方法**（怎么算、怎么排、怎么讲）· **用户的私密内容**（值）· 界面 |
| 谁定 | **平台写死**（母体） | **AI 在实例房间里现场发挥**（85:34、89:61） |
| 为什么能共享 | 因为公开数据**形状**大抵相同 | 因为**需求**不同、**数据**是各人的 |
| 今天的落点 | 部分有（见 §三·3.3） | 无契约（见 §三·Q3.1／Q3.2） |

⇒ **本契约的其余九节，就是在回答"这两半的边界画在哪、怎么检查它没越界"。**

## 一、范围与不变量（**哪些是冻死的**）

### 1.1 管什么、不管什么

| | 内容 |
|---|---|
| **管** | 一个 app 的**形状**（清单／工作区／数据边界／能力面）；**装／升／发／推**四条路上的**可检查条件**；**血缘**与**市场**的登记口径 |
| **不管** | **语义**（"这个 app 解决什么"、"迁对了没有"）—— 平台只保证**结构能检查、数据有快照、过程有记录、能回退**（85:71） |

## 二、一个 app 是什么

### 2.1 定义（**注册制**，不是"盘上几个文件"）

> **一个 app = 一条登记在册的记录** = `id`（桌上那张脸）＋ `rootHash`（内容）＋ **血缘边**（第三维）＋
> **它现在满足哪版契约** ＋ **权限** ＋ **数据边界**。（85 §二·2；89:89-90）

**三条不许互替**（89 R3，`89:89-90`）：

| 维 | 是什么 | 谁在用 | 不许拿它当别的用 |
|---|---|---|---|
| `id` | 别名／桌上那张脸 | **客户端按 `id` 认人**（`app_spec.dart:39`、`published.js:13-15`） | **不拆 `id`**（拆了就"每改一次就不是这个 app"） |
| `rootHash` | **内容**（`apps.js:156-160`，排序后拼 `path\nhash\n` 再算一次） | 发布回读、装上的"可核起点" | 不许进身份（否则改一个字就换了个 app） |
| **血缘** | **祖先边** `(base rootHash, 被改文件清单)` | 市场信用、回流 | 不许用自称的 `parent` 代替（89 R4） |

**判据 Q2.1**：一个 app 在**两个不同用户**的桌面上都能跑，且**各自能继续改**（85 F4）。
**反着验**：若两处跑的必须是**同一份代码**才跑得起来 ⇒ 说明这三条被混成了一条 ⇒ 红。

### 2.2 清单字段（**今天真有的**）

`apps.create()` 写下的 `manifest.json`（`apps.js:349-364`）：

| 字段 | 谁写 | 谁读 | 备注 |
|---|---|---|---|
| `schema` | `apps.js:27`（`SCHEMA`） | 无读取方 | **加字段要能分辨**，所以它进 manifest |
| `id` / `version` / `title` / `icon` / `entry` | `apps.js:301-318` | 客户端 `app_spec.dart:61-92` | `icon` 只认白名单（`app-icons.js`），**给了白的就用、认不出就自动配一个**（`apps.js:312-316`） |
| `files[]`（`path`/`sha256`/`bytes`） | `apps.js:356` | `apps.js:394-406`（读时逐字节核） | |
| `rootHash` | `apps.js:357` | **`/api/apps` 带出去（`server.js:876-890`），但客户端丢掉**（`app_spec.dart` 无此字段；`grep rootHash v2/apps/mobile/lib` = **0**） | ⇒ **"可核起点"今天到了线路上，没到人眼前** |
| `permissions[]` | `apps.js:358` | `apps.js:416-447`（授予） | 白名单今天**只有 `ask`**（`apps.js:63`） |
| `minShellVersion` | **`apps.js:359` 写死 `1`**（调用方给什么都进不去） | **无读取方**（客户端 `grep` = 0） | ⇒ 见 §9 冲突 4：`08-SPEC.md:1352` 那条规则**既无生产者也无消费者** |
| `createdBy` / `createdTurn` | `apps.js:296-297, 360-361` | `apps.js:380`（审计） | 值域只有 `user` \| `agent`（`apps.js:339`） |
| `createdAt` / `bytes` | `apps.js:362-363` | 清单页 | |

**工作区自己那份清单**是**另一个文件**：`.hupo.json`（`workspace.js:49`、`workspace.js:275-299`），
记 `kind: 'hupo-workspace'`、`title`、`entry`、**`placeholder`（含 hash）**、`createdAt`。
它**不是制品**（`read()` 跳过所有 `.` 开头，`workspace.js:395`），也和模型写的文件**撞不了名**（`workspace.js:332-333`）。

### 2.3 工作区布局（**已有**）

```
/data/                          ← 这个人（他的容器）的整个世界（02-ARCHITECTURE.md §2.1）
  main/                         ← 主目录（顶层对话的 root；**不是 home、不是 /data**）
  workspaces/<scope>/           ← 一个图标一间房（workspace.js:59-67；scope = 那个 app 的 id）
    .hupo.json                  ← 这间房自己的账（workspace.js:49）
  hupo/apps/<id>/               ← 制品库（**快照**，不是干活的地方）
    current.json                ← 指针（apps.js:378）
    versions/<n>/manifest.json  ← 不可变版本
    grant.json / ask.json       ← 授权与配额（apps.js:416-489）
    .removed/<id>-<at>/         ← 卸载＝**软删**（apps.js:494-506）
  hupo/apps/audit.jsonl         ← 只追加（apps.js:208-222）
```

**保留字**：`main` 不许当 scope（`workspace.js:57`、`workspace.js:88-90`）。

**判据 Q2.2**：造一个 app ⇒ 它的源码与产物**只**出现在 `<dir>/workspaces/<scope>/` 里。
**反着验**：写进 `/data/main` ⇒ 红（`83` A1）。
**判据 Q2.3**：制品库那份是**快照** —— 工作区改了**没发布** ⇒ 线上**不变**。
**反着验**：让线上直接读工作区 ⇒ 红（`83` A5）。机制出处：`snapshotWorkspace` **从工作区读**（`workspace.js:420-445`）。

### 2.4 数据边界（**今天只有一个隐式格子**）

**今天的事实**：制品快照 = "工作区里**除 `.` 开头之外**的全部文件"（`workspace.js:387-401`，跳过在 `:395`；`snapshotWorkspace` 在 `:433` 调它）。

⇒ **边界完全落在一个命名习惯上**：想让一样东西**不**进制品，它的路径必须以 `.` 开头。
这个格子**没有名字、没有声明、没有闸**（89 §②2：数据账与缓存无名、无声明）。

**判据 Q2.4（今天就能跑）**：在工作区写一个 `notes.json`（不带点）⇒ 发布 ⇒ 它**进了共享库**。
**反着验**：写 `.notes.json` ⇒ 它**不进**。
⇒ 这一对读数就是"边界是隐式的"的**证据**；见 §三 Q3.3 要把它变成**显式**的。

### 2.5 能调的平台能力（**面越小越好**）

| 能力 | 谁能调 | 闸 | 出处 |
|---|---|---|---|
| `ask`（用**看的人**的钥匙问一句） | **制品**，但必须**声明 + 看的人授予 + 配额** | 四道闸在中心；花在**他自己的环境**里；**制品永远拿不到钥匙** | `apps.js:63`（白名单）· `apps.js:416-489`（授予与配额）· `08-SPEC.md:177` · `app-ask.js:9-15` |
| `ask` 的形状 | **直连模型，没有工具** | 因为 `policy`（来源分级→能力档）本轮不建（`02-ARCHITECTURE.md:415`），**把别人写的话丢给全权执行体**是最怕的形状 | `app-ask.js:12-15, 53-95` |
| 画图 | **助手工具**（借住在小程序那条通道上） | **不是**给制品的；"他明说才许生成" | `apps-socket.js:118-139` |
| 其余一切 | **没有**（fail-closed） | `N2` 制品不能自授权；白名单外的权限一律拒 | `apps.js:302-309` |

**判据 Q2.5**：制品**自己发不出任何请求**（CSP `connect-src 'none'`，`app-serve.js:48`）。
**反着验**：给制品一条能自己出网的路 ⇒ 红（`08-SPEC.md:1334`）。
**判据 Q2.6**：制品**拿不到钥匙**。
**反着验**：制品字节里搜哨兵串（见 §三 Q3.4）⇒ 命中即红。

### 2.6 分栏：**必须写死可检查的** vs **留给 AI 现场发挥的**

| | **必须写死、可检查、fail-closed**（平台） | **留给 AI 现场发挥**（在实例房间里） |
|---|---|---|
| 清单 | `id` 形状（`apps.js:101-107`）· 版本不可变 · `rootHash` · 权限白名单 · 路径白名单 | `title` · `icon`（在白名单里挑）· 它**解决什么**的叙述 |
| 工作区 | 目录形状 · `.hupo.json` · `main`/`workspaces` 平行 | **里面写什么文件、怎么组织** |
| 数据 | **形状声明**（键名／类型／空值口径／去重键）＋ `.` 格子的命名 | **分析方法** · **值** · 界面 · 排版 · 话术 |
| 升级 | 快照 · 判据 · 一步回退 · 人话报告 | **旧数据 → 新契约的跃迁脚本**（85:34、89:61） |
| 出网 | 制品口 CSP `connect-src 'none'`；要问话只能走 `ask` | 问什么、怎么用回答 |

**约束的形状**（89:62）：AI 的发挥**落在工作区里、有 hash、随版本冻结、能回退**；
**禁 N×N mapping**（85:68）。

**判据 Q2.7**（**本节最要紧的一条**）：**"它解决什么"必须是版本内一份固定名、被 hash 盖住的文件**
（89:64-65）—— 否则**发现页两个新闻 app 会逐字段相同**，只有值不同 = 即病（89 R2 反例）。
**反着验**：删掉那份文件，两个同类 app 的清单**逐字段相同** ⇒ 红。
**状态：【要建】**（今天 manifest 里没有这个字段，`apps.js:349-364`）。
**⚠️ 不许**把它做成 manifest 的一个**字段**（那会把所有人拉回同一份 app，89 R2 反例）——
它是**制品里的一份文件**，随 `rootHash` 一起冻结。

## 三、数据：**什么趋同，什么分叉**（主人的命题落在这里）

### 3.1 为什么必须分开写

**同类型的公开数据（比如新闻）底层结构大抵相似** ⇒ 骨架可以共享；
**分析方法与用户私密内容不同** ⇒ 这两样一旦被"共享骨架"顺手复制走，就是**私密数据发布事故**（89:127-128）。

### 7.1 七步（主人说的形状：85 F3 · 89 §⑤末 · `85:63`）
