# 82 · 开发者模式（把某个用户的盒子里那台 DSH 露到他自己域名上）

> 主人 2026-09-24 原话：「你现在给我一个**开发者模式**，也就是说，我想配置某个用户为开发者，
> 然后他的 docker 里的 dsh，就会端口暴露出来，我可以通过 **`dsh19145526557.stalkerai.cn`** 来访问。」
> 我提的两个选择，主人均取**甲** ⇒ ① **保留 DSH 自己的令牌登录（锁着）** ② **只有 `owner` 能翻这个开关**。

---

## 一、它跟「只出不进」的关系（**先写这条，免得以后读成没规矩**）

主人在同一天先定过：「**docker 里的 dsh，不可能有任何外部访问，只有它访问外部**」。
开发者模式是那条规矩的**例外**，所以必须满足三条，否则就是没规矩：

1. **默认关**：没被标成开发者的用户，今天怎么样以后还怎么样（盒子无门）。
2. **按人**：开关挂在**某个用户**身上，不是全局开关。
3. **能当场收回**：标记一关，**不需要重启**就进不去了。

⚠️ 还有一条**实现上的硬约束**：**盒子本身仍然不开端口**（不用 `podman -p`，不往宿主捅口）。
"暴露"靠的是：VPS 上的门牌号 → 隧道 → **我们自己的中继** → 现有那条管道 → 容器内**回环**上的 `dsh web`。
⇒ 在**盒子这一侧**，"只出不进"依然成立；多出来的只是"VPS 上多了一个门牌号"。

## 二、为什么必须给它一个独立域名（这条天生吻合，别再试路径式）

那台界面把 API 算在 **`location.origin` 的根**上（三重证据见 `81-HARNESS-ENTRY.md` §二），
所以它本来就需要**一个独占门牌号**。主人要的 `dsh<手机号>.stalkerai.cn` 正好就是那个形状。

## 三、开关落在哪

`data/users.json` 现在是 **手机号 → `{id, createdAt}`**（实测：`owner` / `u1` / `u2` 三条都只有这两个字段）。

- 记录加一个可选字段 **`dev: true`**；
- 服务端加 **`isDev(id)`** 与 **`setDev(phone, on|off)`**（原子写盘照 `users.js` 现有那套）；
- 🔴 **每个请求都现查这个标记**（不是启动时查一次）⇒ 关掉 ⇒ **当场**拒；
- 🔴 **只有 `owner` 身份能翻**（别人拿来 ⇒ 403）。翻一次**记一笔账**（谁、什么时候、开了谁）。

## 四、露出来的形状

```
浏览器 → https://dsh<手机号>.stalkerai.cn        （VPS：nginx + 证书）
       → VPS 上的 visitor（stcp）
       → 本机一个**每开发者专用**的 loopback 端口（我们的中继）
       → 现有那条管道（域套接字）
       → 容器里的壳（只在隧道那条可信口上接）
       → 容器内 127.0.0.1 上的 dsh web
```

| 层 | 做什么 | 备注 |
|---|---|---|
| DNS | **不用动** | `stalkerai.cn` 是泛解析（实测：随机名字也解析到 VPS）|
| 证书 | 每个开发者用户**一张单名证书** | `certbot certonly --nginx -d dsh<手机号>.stalkerai.cn`。⚠️ 现有证书都是单名的（实测）；要一劳永逸得签泛域名 `*.stalkerai.cn`，那需要 DNS 服务商 API（或每 90 天手工加 TXT）⇒ **先按人签** |
| VPS nginx | 一个 conf：`:80 → 301`、`:443 ssl` + 证书 + `proxy_pass 127.0.0.1:<visitor口>` | 照 `59-USER-APPS.md` §九 那套现成配方，**不碰任何已有 conf** |
| 隧道 | VPS 侧一个 visitor（stcp）+ 本机 frpc 一段 + `scripts/start-tunnels.sh` 加一条 | 与本机其它隧道同构 |
| 本机中继 | 每个开发者用户一个专用端口 → 现有管道 → 容器 | 端口与人的对应关系**落配置**（不写死）|
| 容器 | 懒起 **`dsh web --host 127.0.0.1 --port 0 --no-open`**（**只回环**）+ 壳转发 | 这批要用到的转发机制与 81 篇 §二/§三 那批事实同源，**别重新推一遍** |
| 鉴权 | 🔴 **保留 DSH 自己的令牌**（`/?token=…` 才种 cookie，否则 401） | **不做免登** —— 中继**不许**替浏览器拿 cookie |

## 五、判据（每条都要能反着验）

| # | 判据 | 反例（必须红） |
|---|---|---|
| D1 | 没被标 `dev` 的用户 ⇒ 那个域名**连不上** | 给一个没标记的人开域名 ⇒ 必须拒 |
| D2 | 标了 + 带对的令牌 ⇒ **200**，页面里有 `__DSH_BOOT__` | —— |
| D3 | 标了但**不带令牌** ⇒ **401**（锁还在） | 把锁摘掉 ⇒ 这条当场红 |
| D4 | 把标记**关掉** ⇒ **当场**拒（不是等重启）| 只在启动时读标记 ⇒ 这条红 |
| D5 | 只有 `owner` 能翻标记 | 拿 `u2` 的令牌去翻 ⇒ **403** |
| D6 | 盒子侧**没有**宿主端口（没有 `-p`） | 有人图省事 `podman -p` ⇒ 这条红 |
| D7 | **真图**：对活系统 `curl -sI https://dsh<手机号>.stalkerai.cn/` ⇒ **401**；带令牌 ⇒ **200** 且含 `__DSH_BOOT__` | —— |
| D8 | 容器里的 `dsh web` **只听回环**（不是 `0.0.0.0`）| 听 `0.0.0.0` ⇒ 这条红 |

## 六、明确**不做**的事

1. **不默认开、不给所有人开**（开关必须落在具体某个人身上）。
2. **不因为"方便"就把锁摘掉**（主人选了甲：锁着）。
3. **不在容器上 `podman -p`**（盒子始终无门）。
4. **不让中继自作主张免登**。
5. **不把开关做成"谁能翻都行"**（只有 `owner`）。
