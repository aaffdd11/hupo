## 一、⚠️ 为什么这件事值得单独一批

因为**人格坏掉的时候，什么都不会报错**。

agent 照样起、照样答、照样能干活——只是「说话不是它该有的样子」。
而那种故障在屏幕上的样子是：**它听起来像个通用编码助手**。

⇒ 这是本仓库反复栽的那同一个形状：**静默降级**。
（和"没设 `HUPO_PERSONA` 也能跑"、"`webRoot` 不存在也能跑"、"recap 读不到也照样说话"是同一类。）

**实测的"前"**（换人格之前，公网抓到的原文）：

```
seq=19  message/text  "你好！我是运行在 DeepSeek Harness 里的
seq=23  message/text  "你好！我是运行在 DeepSeek Harness 里的
```

**实测的"后"**：

```
seq=29  user/echo     "你是谁？一句话。"
seq=31  message/text  "我是助手，你的私人助理。"
```

⇒ 一句"运行在 DeepSeek Harness 里"同时踩了两条：
**它不是编码助手**、而且**那是内部词**。

## 三、⚠️ 十条里第 9 条**当年故意没写**（这一条要单独说）

手册 §12.4 第 9 条是：

> **被打断的活会自己接着做**

**它今天不成立。** `07-TIMEOUT.md` 已经做到"**告诉它断了**"，但"**接着做**"没有——
对账续做还没建（第 ④ 条）。

⇒ 如果照写，助手会对主人说「这件事我放到后台去做，完了告诉你」——
**而那正是手册事故一的形状**（那行"还有件事在处理"挂了 68 分钟）。

⇒ 所以人格里写的是**实话**，而且**主动把这件事说给模型听**：

```
⚠️ **不许承诺你现在做不到的事。** 比如「这件事我放到后台去做，完了告诉你」——
现在**没有后台**，也没有任何东西会替你把断掉的活接上。
被重启打断的活就是断了：**直说**，然后问他要不要重来。
```

⚠️ **这是"明说砍了"而不是"排后"**：规则 9 是**目标**，
等第 ④ 条落地时，这一条连同它的测试一起改。
`test/persona.test.js` 里有一条测试专门钉住这个偏离（**断言它现在不在**），
免得下一个人"顺手补齐"时把谎话装进去。

## 四、闸的设计：只查**模型会读到的那些字**

第一版闸写成"拿整个文件 grep 禁用词"，结果**四条测试当场红**——
红的不是人格，是**我自己写在文件头上的解释**：

```yaml
# ⚠️ 它是从判定重写的，不是抄的。旧那份里有今天不成立的话：
#   · "sudo 免密 —— 你能改"     ← 实测要密码
#   · "直接动手"                  ← 手册 §13.2 点名要它 = 0
```

⇒ **这种闸会被绕过**：想加一句"直接动手"的人，只要把解释删掉就行了。

⇒ 改成只提取**两个 block scalar 的内容**（`personaPrefix` / `personaSuffix`），
那才是喂进模型的东西——**YAML 注释不进 prompt**（patch 是 DSH 解析的）。
在注释里引用一句被禁的话（"就是因为这句才禁它"）是完全合理的。

⚠️ 而"只提取正文"这个逻辑本身也得防它坏掉：所以有一条**负向对照**——
断言提取出来的正文 **> 800 字** 且含「先应一声」。
（提取逻辑哪天返回空串，所有"不许包含"的断言都会**自动通过**。）

**变异验证**：往正文里塞一句「直接动手」，闸当场红。✅

## 十、补 · v1.6：第 10 条「**被拦住时不许把话题带走**」

> **这一条是主人问出来的**：「拦住的是否提示换个话题？」
> 查下来——**一处都没有**（全仓搜不出「换个话题 / 聊点别的」），
> 但**规矩只覆盖了一半**。

### 10.1 缺口在哪

第 2 条（不许留客式追问）管的是「**把话头留给用户**」——
「要不要我…」「还想了解什么」。它**管不到**「**把话题从这件事上引开**」：

```
这个我们先放一放，要不我们聊点别的？
```

后者对 **H1 那位用户更坏**：他分不清是**这件事不行**、**它没听懂**、
还是**要他自己按一下** ⇒ 于是**再问一遍**，或者干脆**不敢再问**。
而这正是 D2 划的红线（"每 30 天要打一次电话"那类流失）。

### 10.2 现在的第 10 条：三种"拦住"，三种话

| 哪一种 | 该说 |
|---|---|
| **要他自己按一下**（改配置 / 人格 / 开机单元） | 「这事得你按一下，改动和命令我准备好了」+ **一句话说清他该跑哪一步** |
| **做不到**（要 `sudo`、要他本人去点某个界面） | **直说做不到** + 他还能怎么办（**不许假装能做** —— D2.1） |
| **不该做** | 一句人话讲清为什么 + **换个说法还能不能试**（**N11**） |

⇒ 三者**都不是**"换个话题"。

### 10.3 顺手修的一处**自相矛盾**（这条是查第 10 条时撞见的）

人格「主人让你改这个系统的时候」：

* 第 2 条：「把**改动和命令**准备好，让主人自己上机器按那一下」
* 第 5 条：「回话**只说结果**…**不要贴代码、不要贴命令**、不要讲实现」

读字面 = 「**我得跑一条命令，但它不肯告诉我是什么**」 ⇒ P2 那条路直接废掉。
⇒ 第 5 条补上例外：**"但要一句话说清他该跑哪一步"**。
（"只贴结果"的意思是**别把实现和 diff 倒给他**，不是"连他该做什么都不说"。）

### 10.4 验收

```
$ cd v2/services/core && npm test     → 271 passed（269 → 271，+2）
$ bash scripts/check-persona.sh       → ✅ 真 dsh 抓出来的系统提示里，
                                          新规则**与其点名的反例**都在
```

⚠️ **两条闸，两道**（这正是 V13 那条纪律的用法）：

| 闸 | 管什么 |
|---|---|
| `test/persona.test.js` | 从 `personaSuffix` 里取出来的**payload**里有这几句 |
| `scripts/check-persona.sh` | **真起一个 dsh**，抓 `system/message` —— 证明它**真的进了模型上下文** |

`check-persona.sh` 的清单这次也加了两条（`换个话题吧` / `要一句话说清他该跑哪一步`）——
因为**文件里有 ≠ 进了 prompt**，而这一条恰恰是"文件里有"最容易被静默丢掉的那类内容。

### 10.5 生效时机（**不用重启**）

`personaPath` 是**每次 spawn 时**当 `--patch` 传进去的（`agent-runtime.js`）
⇒ 这份改动**下一条新开的对话就是新规矩**；已经在跑的那个 agent 还用着旧的那份，
被淘汰后自然换成新的。
