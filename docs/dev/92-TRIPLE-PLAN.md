## ① 结论：不是「能力＋经验＋数据」三层

**判：不是三个并列的层／柜子／概念。** 应改述为：

> ### 一条硬边界 · 两格载体 · 三条出去律 · 一个 kind 声明（＋撤回一条边属性）

| 件 | 是什么 |
|---|---|
| **硬边界** | 在不在制品快照里。唯一机械机制 = 路径**任一段**以 `.` 开头（读侧 `workspace.js:406`；写侧 `apps.js:148,381`）。它只产出**两格** |
| **三条出去律** | 随制品走（能力体）／**作者**逐条声明才出（经验包）／**收方**一对一同意且可撤回（数据包）。**出去律是路，不是格** |
| **一个声明** | `.exp/<pack>/pack.json`、`.data/<pack>/pack.json` 里的 `outbound`；**读不到 ⇒ fail-closed** |
| **撤回** | **不是**第四条出去律，是数据**交付边**的属性 |

**为什么**：① 今天 `src/` 里 `.data`／`.exp` **零机制** —— 只在拒绝文案与三处注释（`apps.js:141,151,380`），
`workspace.js:406` 只按 `.` 一刀切 ⇒ 机械判据只产出两格，**第三格今天不可判**。② 91 §7.3.5 自认
"经验一编译进制品就按能力体算" ⇒ **"层由载体唯一决定"与"编译后换层"不能同真** ⇒ 层是**角色**。
③ 91 §1.1 明写平台不判语义 ⇒ 按内容判层不可反着验。

**共识**：五席在 R2／R3 都接受"载体两格、出去律三条"，并同意 **"三层"作为角色名保留**，
但**条款必须挂在"边界"与"出去律／谁点头"上**。

**保留的反方意见**（不许读成一致）：
1. **领域建模 R1** 主张软分界 = "方法（给 AI）vs 值（给运行时）"，**R2 自行撤回**（语义不可判）。
2. **平台 R1** 主张"两个布尔 ＋ 第四格 `value∧exec` 必须为空"，**被其余四席点名驳回**（`value` 是语义谓词；
   且 §7.3.5 那一刻第四格**非空且合法**），**R2 自行撤回** ⇒ 只记入"被驳回的选项"，**不入契约**。
3. **安全 R1** 主张"经验／数据 = 同一概念同字段两取值"，**R2 改口**：载体同构，**但同意主体不同**
   （作者点头 vs 收方同意且可撤回）⇒ 条款必须分开。本计划按 **"载体合、条款分"** 落地。
4. **领域建模 D2「出去规则跟内容走」vs 安全「跟声明走」**：真分歧是"内容是否可判"。本计划取**跟声明走**
   （可反着验），**领域建模的反对意见保留**。
5. **缓存要不要一层**：演进 R1 讨过一层，**R2 撤回**；其余席一致：派生品，判据是"**删了能重算**"。

**另：91 丢了第四类。** 90 Q1.10 自己写着"制品 ≠ 数据 ≠ **缓存**"，而 91 §2.1 问 4 把缓存／记忆／账／
`.hupo.json` 一律塞进"未归类"。本计划给它们一个取值：**`outbound = never`（永不出）**。

## ② 判层规则（一眼可判、可自动化）

**两步，都不读内容**：

| 步 | 问 | 答 |
|---|---|---|
| **1** | 路径**任一段**以 `.` 开头吗？ | 否 ⇒ **能力体**（进快照、在制品口执行、唯一过大契约） |
| **2** | 是 ⇒ 读**声明** | `outbound=share`（＋锚）⇒ **经验包**；`outbound=one-to-one` ⇒ **数据包**；`never` ⇒ 缓存／记忆／账；**读不到声明或其他 `.` 散文件 ⇒ 未归类 = 永不出**（fail-closed） |

**三条硬规矩**：
1. **目录名不承重，声明承重**：`mv .exp/x .data/x`（内容与声明不动）⇒ 谁能取、谁点头、上架结论**逐条不变**；
   **变 ⇒ 目录名在承重 ⇒ 红**。（安全 R3；产品 R2 那句"今天一样 ⇒ 今天三层是假的"是同一结论。）
2. **默认最严**：未声明一律按数据包。**91 今天反着来**（按目录判、默认宽松）。
3. **可分享必须带锚**：`share:true` 而缺来源 `rootHash`／输入账／同意记录 ⇒ **不出去**。
   声明不可核 = 把上架闸降级成**作者自证**（安全 R2）。

## ④ 判据总表（离线／真机）

| 离线（不碰真机） | 真机（这台机器上真装真跑） |
|---|---|
| 只看路径即可判层；`.data/x` 写得进、发布后共享库搜不到 | 真实 scope 放 `.data/a.json` 再上架 ⇒ `manifest.files[]` **无它** |
| `.data/x`／`.exp/x` 直投 `apps.create` ⇒ 拒，盘上零残留 | 删 `.exp/` ⇒ 能力体**照开**（91 §7.2.1） |
| **同字节分放两格（声明不动）⇒ 出去结论必须相同** | 模型写无声明 `.exp/` 包 ⇒ 重启后**不自动生效** |
| `share:true` 无锚 ⇒ 拒；补锚 ⇒ 过；删锚 ⇒ 又拒 | 收到别人的经验包 ⇒ 不自动生效、能回退（逐字节等于应用前） |
| 出界口只许一条；冒出第二个 ⇒ 红 | 装一次 ⇒ 改过的本地那份**有副本、可一步退**（今天 **必红**，除非阶段 1 落定） |
| `share:false`／`.data/` 哨兵 ⇒ 共享库／制品口零命中 | 上架一次 ⇒ 共享库全库搜数据哨兵与令牌 ⇒ 零命中 |
| 无同意 ⇒ 交付失败；回执里没有"已删除" | 助手自己想到要做小程序（用户没明说）⇒ 拒（回归 `apps-consent.js`） |

> 🔴 两条纪律：读不出字段 ⇒ 如实报 **`不可算`**，**不许安静地绿**；
> **不许用写死关键参数的旁路工具验收客户端自己算出来的东西**（`08-SPEC.md` V13）。

## ⑤ 风险与最可能做坏的地方

1. 🔴 **闸只在脏树上**（本轮核过 `git status`）：`apps.js`／`workspace.js`／`apps-socket.js`／`worlds.js`／
   `mcp-apps-server.mjs`／`check-docs.mjs` 全是 `M`，91 与两份新测试是 `??`。**一次 checkout 就归零**；
   归零后 `.data/`／`.exp/` 能顺老路进制品与共享库 —— **公开面只增、收不回**。
2. **判层靠模型写目录**：写错格子**没有闸能发现**（**未核实**）。
3. **`.exp/` 是 N25 的新入口**：cwd 即 scope；91 只防"经验→记忆"与"收别人的包不自动生效"，
   **没防自己长的那份自动生效**。
4. **声明不可核**：`.exp/notes.json` 放受版权记录 + `share:true` ⇒ **今天全绿**
   （§7.1.2 只搜"数据的副本"，不搜"数据本身"）。
5. **血缘只盖能力体**：fork 后真正漂开的是**方法**，方法没有可对账的边；且**没有"实例版本"** ⇒
   能力体换版后经验还适不适用，**零判据**。这是长期腐化的主路径。
6. **缓存／记忆／账**：不同出去律挤在同一"未归类"格 ⇒ **每加一条出去律就多开一个目录**，层数随规则数膨胀。
7. **一对一通道未建却扛着版权**：拦不住再传 ⇒ 版权只换留痕（91 §6.4.4 自认）。
8. **跨库 join**：`share:true` + 稳定 app id + 公开署名 = 跨用户关联链；91 §7.4 只写"一对一"，没写这个关联面。
9. **最该被激励的那层信用最薄**：可核起点与血缘只盖能力体 ⇒ 经验一上架，第三方**核不出**它是谁的、
   长在哪个 base 上；而共享库 index 又**无装上数、无"跑过"字段** ⇒ 使用**零可核**。
   ⇒ **市场卖代码，不卖经验。**
