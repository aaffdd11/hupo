## 一、两样设置的身份与规则（`lib/models/appearance.dart`，新）

纯 Dart，**不 import `material`**（楼层闸），照 `models/tool_row.dart` / `chat_view.dart` 的写法。

| 东西 | 规则 | 依据 |
|---|---|---|
| `ChatAppearance` | `light` / `dark` / `system` 三档；`wire` 是**存在盘上的 token（冻结）**，`label` 是屏幕上那三个词（亮 / 暗 / 跟随系统） | DSH `THEME_PREFERENCES = ["light","dark","system"]` |
| 默认档 | **`system`（跟随系统）** | DSH `DEFAULT_PREFERENCE = "system"` |
| `chatAppearanceOf(Object?)` | **认不出来一律当 `system`**，绝不抛 | 见下面"为什么"那一格 |
| `chatFontSizeOf(Object?)` | 整数夹进 **12–17**；默认 **14**；非整数 / 垃圾 / 别的类型 ⇒ 默认档；**绝不抛** | DSH `FONT_SIZE_MIN/MAX/DEFAULT`、`step(1)` |
| `ChatAppearanceSettings` | 一个值类，装"外观 ＋ 字号"两样，`scale` 是**推出来**的 `DshContentScale`（不另存第二份） | 一个设置的两个轴（DSH 设置里就是相邻两行） |
| `resolve({platformDark})` | 把偏好对着**设备亮度**解成一份具体色板 | DSH 的 `bootThemeScript` 那三行逐字 |

### 1.1 🔴 认不出来的值为什么退回 `system`（**派活单点名要一个说法**）

1. **`system` 就是这条轴本来的默认**（DSH 的 `DEFAULT_PREFERENCE`）——坏值退回默认，
   不额外发明第二个默认；
2. **它是唯一一个不会替用户拿主意的档**：它跟着设备走，而设备那一档是**用户自己在系统里设的**。
   退回 `light` 的后果是"他在暗色设备上打开，我们**悄悄把他按回亮色**"——页面违背他刚做过的选择；
3. 退回 `system` 最坏只是"跟着设备"，**没有任何一种设备状态下它是错的**。

⇒ fail-closed 在这里的意思是"**退回一个绝不会说谎的档**"，不是"关掉功能"。
（与 `process_levels.dart` 那条"认不出来 ⇒ 默认档"是同一个形状，只是这里的默认档
恰好是"跟随设备"。）

### 1.2 两个轴**各退各的**（盘上那个串坏了一半）

盘上存的是**一个** key（§二），编码 `"<wire>|<字号>"`（例 `dark|16`）。
解的时候两半**分开退回**：`"dark|坏了"` ⇒ 暗 ＋ 默认字号 14。
理由：坏的是哪一半就只丢哪一半——**用户刚选的暗色不该因为字号那一格脏了就白选**。

⚠️ 唯一的宽容：`int.tryParse` 允许前后空白（`"15 "` ⇒ 15），那是 Dart 自己的口径，
数字一个不少；`"15px"` / `"14.5"` / `"abc"` 一律回默认档（**不猜**）。

## 二、存在哪（`lib/services/appearance_store.dart`，新）

三条纪律照 `process_level_store.dart` / `chat_view_store.dart`（同一个形状，**不另造一套**）：

| # | 纪律 | 这里的意思 |
|---|---|---|
| 1 | **坏了一律当默认值** | `system` ＋ 14 字；读不出来最多是"回到默认外观"，**绝不能因此让聊天打不开** |
| 2 | **读不出来不抛** | 插件不可用 / 字符串被改坏 / 旧版本写的 token ⇒ 全走 `chatAppearanceSettingsOf()` |
| 3 | **按设备存、不按账号存** | 亮暗与字号是**看这块屏的人的**偏好，不是隐私数据（时间线 / 草稿才是）；换个人登录不用清 |

⚠️ **为什么它按设备、恰恰不该跟着账号走**：同一个人换一台设备，屏幕可能一个亮一个暗
（DSH 那把选择器也住在客户端 `localStorage` 里，不是会话里的东西）。

⚠️ **只用一个 key**（`hupo_chat_appearance`）：两样是"一个设置的两个轴"⇒
要么两份都是新的、要么两份都退回默认，**不会出现"外观是今天的、字号是上一版留下的"**。

## 三、往下传（`lib/widgets/appearance_scope.dart`，新 ＋ `dsh_look.dart` 一改）

```
ChatScreen.build
├─ 解析：偏好 ＋ MediaQuery.platformBrightness ⇒ DshVariant（亮/暗，**只有一个**）
├─ 字号：ChatAppearanceSettings.scale ⇒ DshContentScale
└─ AppearanceScope（InheritedWidget：variant ＋ scale ＋ 当前偏好 ＋ 两个写回口）
   └─ 浮窗（Theme(data: chatThemeOf(variant)) ⇒ Material(bgLayer1) ⇒ 里面那一整棵）
      └─ 每一个用 token 的控件：DshLook.of(context)（**唯一取值口**）
```

三条设计上的话：

1. **解析在 `ChatScreen.build` 里做**（不放在 scope 里）：用户在系统里切了暗色，
   `MediaQuery` 一变这一屏就重建 ⇒ `system` **当场**跟着变，不用重开；
2. **`system` 的解析只有一处**：往下传的 `DshVariant` **永远是亮的或暗的**，
   不会有第三个值漏到控件那一层；
3. 🔴 **浮窗里面那一整棵套了一个 `Theme`**（`chatThemeOf`）。这一条最要紧，理由见 §3.1。

### 3.1 为什么非要那层 `Theme` 不可（这一批最容易踩的一处）

聊天窗口里**绝大多数控件不是直接读 DSH token 的**：气泡、输入框、状态条、分隔线读的都是
`Theme.of(context)`（全站那套暖白纸）。⇒ 只把浮窗那块底换成暗色、里面这些控件照旧拿暖白纸主题，
结果是**近黑的字压在近黑的底上**——屏幕上就是"字没了"。
而且这种坏法 `find.text` **照样找得到**（字还在树里）：**判据全绿、屏幕是黑的**。

⇒ 修法是**结构性**的：把窗口里面那一整棵套上 `chatThemeOf(variant)`，
于是"里面的 Material 控件跟着窗口走"由结构保证，不靠人记得改每一处。

⚠️ 它**只改颜色**：字号阶梯照抄 `Typography.material2021()`（和全站同一个来源、同一套尺寸）
⇒ 套上它**不会**让任何一行字变大变小，也就不会把五档字号那道硬闸的读数弄脏。

### 3.2 `DshLook.of` 是唯一的取值口

`widgets/dsh_look.dart` 的 `DshLook.of(context)` 改成：**有 scope 就照它来，没有就退回老规矩**
（跟着 `Theme` 的亮暗、字号走默认档）。⇒ 批次 1–3 那些"单看某一块"的判据**一字不用改**。

## 四、设置那两行（`lib/screens/settings_screen.dart`）

「这块窗口」是一张新卡，挂在**第一屏（聊天）**的可滚内容里、「这个助手」那张卡**上面**
（它是关于**这一扇窗**的设置，不属于那四样钥匙）。

| 行 | 形状 | 依据 |
|---|---|---|
| **外观** | 三选一（亮 / 暗 / 跟随系统）；选中那一档**带一个勾 ＋ 字更实**（不许只靠颜色） | DSH 的 color scheme 那一项 |
| **字号** | 一个步进器（− / 数字 / ＋），下面一行**实时预览**——那一行字**就按当前字号画** | DSH 的 content font size（stepper） |

🔴 三条不许破：

* **当前值看得出来、而且不只靠颜色**（同 `bubbles.dart` 四态那条：色盲 / 屏幕反光下颜色最不可靠）；
* **预览是真的**：`dshTextStyle(scale.content, …)` ⇒ 改一下立刻看得见，不是一张静止的图；
* **到边界就按不动**（12 时"小一点"、17 时"大一点"是灰的）：夹住不许假装还能再小，
  也**不许画一个按了没反应的键**。⚠️ 这与"界面上不许出现按不动的东西"不冲突：
  那是"做不到的事不许摆出来"，这里是**做得到、但已经到头了**（发送键没字时也是灰的，同一条）。

⚠️ **状态不住在设置页**：住 `ChatScreen`（`_appearance`），设置页只是入口 ⇒
一份状态、两处看得到（设置页那两行 ＋ 聊天面每一个用 token 的控件）。
改完由**同一个 `setState`** 既写盘又重建那一棵子树 ⇒ **当场生效、不重连**。

⚠️ 全部用户文案住在**已有的** `models/space_words.dart`（那三个词住 `appearance.dart` 的枚举上，
与 `chat_view.dart` 的 `tab`、`process_levels.dart` 的 `title` 同一条纪律），并且**进了禁用词那道扫描**。

## 五、🔴 边界：改了哪些面、哪些**故意**留在暖白纸那套

这一批重做的是**聊天窗口**，不是整个产品。

### 5.1 跟着"外观"走的面（**都是聊天窗口里面**）

| 面 | 怎么跟 |

| 工具行 / 系统提示词 / 用量 / 过程折叠（`tool_row_view.dart`） | 走 `DshLook` ⇒ 色板 ＋ **用户字号轴** |

| 气泡（`bubbles.dart`） | 正文跟用户字号轴（`calc(16px + Δ)`）；颜色由 `chatThemeOf` 的 `specific-bubble` / `bg-layer-2` / 失败那档罩色给出 |

### 5.2 **故意没动**的面（**留在暖白纸**那套 `models/design.dart`）

| 面 | 为什么 |
|---|---|
| **桌面图标墙**（`app_desktop.dart`） | 它是**桌面**，不是聊天窗口。整机暗色是另一件事（见 5.3） |
| **首页 / 登录页 / 等待屏 / 填钥匙屏** | 未登录那一段与聊天无关；它们现在也读不到那个 scope |
| **小程序容器那一圈壳**（`mini_app_host.dart` / `mini_app_frame.dart`） | 那是**别人页面**的容器，不该被我们的外观设置染色 |
| **设置页自己**（`settings_screen.dart` 的卡片 / 表单项） | 它是**小程序**，不是聊天面。它只把"那两行 + 一行预览"画出来 |
| `lib/models/design.dart` | 一个字节没动（暖白纸那套品牌色照旧） |

⚠️ **上一批的"多选态"那两样刻意留着暖色**（`d.selectWash` 罩色 / `d.accent` 圈边 / 那个勾）：
那是批 3 的选中语义，这一批不碰（要一起换是另一条判断，得单独量）。

### 5.3 ⚠️ **整机暗色要主人先拍一句**（这一批明确没做）

要"整个产品跟着暗"，等于给 `models/design.dart` 那套**暖白纸品牌色**（纸底 / 陶土红 / 近黑正文）
**发明一份暗色版**——那是**品牌决定**，不是一次重构：暖白纸是主人一路挑出来的，
暗色版长什么样（红要不要换、反差够不够）**没人拍过板**。
⇒ 这一批只把**已经有暗色 token 的那一扇窗**（DSH 的色板，`116` 就落进代码了）接上开关。
**要整机暗色，请主人说一句**，那是下一批的事（工作量在"挑一套暗色品牌色"＋逐屏走查，不在接线）。

### 6.1 负向对照（每条判据都反着验过）

* **默认那一档就是错的** ⇒ 暗色那条正例不算数（所以先断言默认是亮色）；
* **坏值不许当值**：`Dark` / `LIGHT` / `' dark'` / `7` / `true` / list / map ⇒ 一律 `system`；
* **不许四舍五入**：`14.5` / `13.0001` / `NaN` / `Infinity` ⇒ 默认 14，不是 15；
* **一半坏了不许全丢**：`dark|坏了` ⇒ 暗 ＋ 14；
* **越界不许原样上屏**：`system|999` ⇒ 17；
* **点了"大一点"而聊天里的字没变** ⇒ widget 那条当场红（并且连接数不许变成 2）。

| 2 | ⚠️ **一条刀刃一样的既存脆弱**（不是这一批引入的，但这一批踩到了） | `accessibility_test` 的 `_toTop` 用一次 `drag` 把时间线拉回最上面，而 `_followBottom` 在"离底 < `followSlack`(160)"时会**动画拉回底部**。`_foldedOnly` 那一屏的 `maxScrollExtent` 恰好是 **162**（只比 160 大 2 像素）⇒ 我第一版把输入条字号写成 14（比原来的 16 矮 6 像素）之后它掉到 156，**那两条判据当场红**（红的是"夹具没停在最上面"，不是布局坏了）。修法是**把输入条的默认字号改回 16**（`DshTypes.base` ＋ Δ = 原来的 `bodyLarge`，**默认档逐像素相同**）。⇒ 记在这里：**时间线短到 160 上下时，`_toTop` 的读数会翻**；下一个人动输入条高度之前先看一眼这一条 |
| 3 | **第一帧可能是默认外观** | 读盘是异步的（同 `ChatViewStore` / `ProcessLevelStore`）：冷启动第一帧可能先画亮色/14，读到之后才换。这是**刻意**的取舍（"先等盘、再画第一帧"会让冷启动多一帧空白） |
| 4 | **`system` 只跟"设备亮度"，不跟"时段"** | DSH 也是跟着 `prefers-color-scheme`；我们没有"到点自动换"这种东西（也没打算做） |
| 5 | **`process_view.dart`（步骤流水 / 推理原文）的字号没跟用户轴** | 颜色跟着 `chatThemeOf` 走了（不会黑字压黑底），但它的字号仍然只跟**系统缩放**。派活单没点它；两轴都接是下一刀（要么现在说，要么明确不做） |

## 九、明确不做的（现在就说清，不留"以后"）

| # | 不做 | 为什么 |
|---|---|---|
| 1 | **整机暗色**（首页 / 登录 / 桌面 / 小程序容器） | 要给暖白纸品牌色**发明**一份暗色版 —— **要主人拍一句**（§5.3） |
| 2 | **自动**（到点变暗 / 跟日出日落） | DSH 都没有；"自动"又是一个用户看不见的判据 |
| 3 | 字号**连续可调**（滑杆 / 任意像素） | DSH 是**整数步进 1**（`step(1)`）⇒ 照它；连续可调会让每一档都得重新量布局 |
| 4 | **字号影响菜单 / 设置页 / 桌面** | DSH 原话是"只影响会话内容"（`B-render.md` §3.1）；那也正是这一批的边界 |
| 5 | 主题**按账号同步**（换设备也一致） | 它不是隐私数据、而是**这块屏**的偏好；DSH 也住在本地 `localStorage`（同步要另一条路与一套冲突规则） |
