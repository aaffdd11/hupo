# 137 · **桌面那一墙图标：按页面宽度等宽排列（每一行铺满）**

> **主人 2026-09-29 原话**：*「app排布要根据页面宽度等宽排列」*
> 问过之后他选的是**每行都铺满**：
> *"1280 宽、7 个图标 ⇒ 一行 7 格铺满（图标大小不变，只是它们之间的距离变大）；
> 图标很多时一行的格数自己变多。窄屏（手机）仍是四列左右。"*

---

## 一、改前是什么样（量过的）

```
1280 宽（宽屏）：
  ┌────────────────────────────────────────────────────────────┐
  │  ▣ ▣ ▣ ▣ ▣ ▣ ▣                                            │   ← 全挤在左边
  │  设置 发现 …                                                │      右边空着一大半
  └────────────────────────────────────────────────────────────┘
```
旧规则：**固定 4 列** ＋ 一格宽 `clamp(图标格+10, 96)` ⇒ 宽屏上 7 个图标
只占 **7×96 + 6×20 ≈ 790** 里的一小半（`tileWidth` 到 96 就封顶了，剩下的宽全空着）。

## 二、现在（`models/desktop_grid.dart` —— 纯函数）

```
1280 宽：
  ┌────────────────────────────────────────────────────────────┐
  │ ▣   ▣   ▣   ▣   ▣   ▣   ▣                                  │   ← 一行铺满（间距被拉开）
  └────────────────────────────────────────────────────────────┘
      ← 左边贴着留白，右边也贴着留白，相邻间距**一样宽** →

390 宽（手机）：
  ┌──────────────────────┐
  │  ▣  ▣  ▣  ▣          │   ← 一行 4 格（放不下 5 格）
  │      ▣  ▣  ▣         │   ← 第二行 3 格：**那一组居中**（间距照旧，不拉大）
  └──────────────────────┘
```

| 规矩 | 落地 |
|---|---|
| ① 一行的格数 | `min(放得下几格, 图标个数)`；"放得下几格"按**最小间距**（`desktopTileMinGap`）算 ⇒ 放不下就换行，**不挤** |
| ② 每格**等宽** | `(可用宽 − 间距×(格数−1)) / 格数` ⇒ 一行**正好铺满**（`cols*slot + (cols-1)*gap == 可用宽`） |
| ③ 图标**多大不变** | `desktopIconBox` 一个像素没动（只是它外面那格的宽度变了） |
| ④ 末行不满 | 那**一组居中**（用同一条间距 —— 拉大会让两行的观感不一样） |
| ⚠️ **为什么最小间距是 20** | 取 16 时 390 宽会算出**5 格**（每格只比图标格宽 1 像素 —— 挤）；取 20 ⇒ **4 格**，与"手机仍是四列左右"对得上。⚠️ 数值住代码 |

⚠️ 原来那两个常量 `desktopTileMax`（一格最多 96）与 `desktopTileSlack` **没有了** ——
"封顶"和"铺满"是打架的，主人选的是铺满。

* 相邻两格的距离**一样宽**；

## 四、没做的（**明说**）

* **图标本身没变大**：宽屏上只有"距离拉开"，图标还是 64。主人那句话里说的是"等宽排列"，
  不是"图标随屏变大"；要变大是另一件事（而且它会牵动 `miniAppIconOfBox` 那个打开动画的比例）。
* **末行没有"拉大间距铺满"**：那一组是**居中**的（同一行内间距一样）。
  两种都说得通，选靠中是因为两行观感一致；他要另一种说一声。
* **没做"拖动排序 / 分页"**：一墙就是一墙（多了就换行 + 上下滚）。
