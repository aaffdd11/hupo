## 二、存到哪（**三种人三个落点**，别读成一套）

| 谁 | 「聊天」那一把 | 其余三样 |
|---|---|---|
| **主人**（`kind:'local'`，他这一份就在本机） | 写 **DSH 自己那份凭据**（`$DSH_HOME/.credentials.yaml` 的 `refs.DEEPSEEK_API_KEY`）—— 见 §三 | `data/creds/<他的 id>.yaml` |
| **租户**（有自己一台容器） | **已有的那条路**：`channel.pushKey` → 他盒子的卷（`46-KEY-DELIVERY.md`） | 同上（**中心这份按人存档**） |
| ⚠️ 为什么其余三样**不进盒子** | 盒子那边 `writeKeyFile` 是**整份重写**（只写 `HUPO_MODEL_KEY` 一行）⇒ 下一次送钥匙就把它们抹掉。要真进盒子得改**产品层**（那是部署期，要主人签字）⇒ **今天不进**，页面也**如实说"先收着"** | |

**存档的形状**（`src/creds-store.js`）：
`<HUPO_DATA>/creds/<sub>.yaml`，一行一个 `名字: 值`，**0600**、原子写（先 `.tmp` 再 `rename`）。
⚠️ 文件名里的 `sub` **要洗**（`^[A-Za-z0-9_-]{1,64}$`）——它虽然来自验签令牌，
但"拿它拼路径"这件事必须自己再挡一道（`../` 那类输入绝不许走到文件系统）。

## 三、🔴 「语言那一把」写进 DSH 那份凭据（**主人 2026-09-24 点头的那一条**）

**事实**（读 DSH 自己的代码，不是猜的）：

* 那份文件是 `version: 1` + `refs:`（名字 → 字符串）＋ `records:`（`<scope>/<id>` → `{kind, payload}`）；
* 这台机器实测：`refs.DEEPSEEK_API_KEY` **就是那把钥匙**；
  而 `records` 里那条是 **`client-connection/browser-session` / `kind: grant`**
  —— 那是**浏览器的会话授权**，**与钥匙无关**。

⇒ 换钥匙**只动 `refs` 里那一行**（`src/owner-creds.js`），三条纪律：

| # | 纪律 | 判据 |
|---|---|---|
| 1 | **先备份**（同目录 `.bak.<时间>`，0600）—— 这是全机器最要紧的一个文件 | 备份写不出来 ⇒ **一步都不往下走** |
| 2 | **外科式**：只替换那一行，**`records` 逐字节不许变** | `recordsOf(before) == recordsOf(after)` |
| 3 | **原子写 + 写完自己核**；核不过 ⇒ **把原来那份放回去** 并如实报错 | 判据里用一个"写下去就坏"的假 fs 验它真的还原 |

⚠️ **认不出那份文件的格式**（预发布那种扁平格式 / 空文件）⇒ **宁可不写**，
回一句 `unexpected-format` —— 也不要把主人的凭据文件写坏。

## 四、服务端那两条路（**老的协议一个字没动**）

| 路 | 做什么 | 为什么这么设计 |
|---|---|---|
| `POST /api/model-key`（**老路**） | 只写语言那一把 | **协议冻结**：老客户端还在跑，一个字节都不许改 |
| `POST /api/creds`（**新路**） | 一次写**一屏**的字段（`{creds:{…}}`） | 语音那三样**必须一起写**（分开写会出现"填了两样"的半截状态） |
| `GET /api/space` | 多回一块 `creds:{model,voice,image,video}` | 🔴 **只有"有没有"**，**永远不回值**（那是密钥那条路）。加字段安全（**加不破**） |

⚠️ **语音"有没有"＝三样齐了才算有**（只有 appid 一样发不出请求）——
这条规则**只住一处**（`src/creds.mjs` 的 `credStatus`），服务端与页面说的是同一个数。

⚠️ **顺手修掉一处假话**：`/api/space` 对主人原来只回 `{kind:'local'}`（没有 `hasKey`）
⇒ 他那屏只能显示"还没有填"，**而他其实有一把能用的钥匙**。
现在照实报（读那份凭据里那个 ref 在不在）；`keyBad` 恒 `false` ——
**我们不知道**它灵不灵（那要真发一次请求才知道），而"不知道"不许写成"不灵"。

## 五、🔴 写下去的顺序是**有讲究的**（不是审美）

盒子那边读文件的是 `model-proxy.js` 的 `parseKey`：这份文件"像 YAML"时，
它取**第一个名字里带 `KEY`/`TOKEN`/`SECRET` 的那一行**。
而语音那三样里就带 `SECRET` ⇒ **把 `HUPO_VOICE_SECRET_KEY` 写在前面，
模型那一把就会被换成一把语音密钥**（现象只是上游回鉴权失败，看日志完全看不出原因）。

两道防线（**都有判据**）：

1. `src/creds.mjs` 写文件时**固定按 `CRED_ORDER`**（语言那一把最先），
   而且**旧文件里顺序错了也会被纠正**；
2. `parseKey` 改成**先认名字**：`HUPO_MODEL_KEY` 在就一定是它 ——
   这样"顺序"不再决定"哪一把是模型钥匙"。

* 四个 tab ＝ `TabBar(isScrollable: true)`（字放到最大时**横向能滚**，不挤成一团）；
  每一屏**自己是一个可滚的 `ListView`**（大字下不许溢出）。
* 每一屏四件：**这一样管什么** → **现在有没有**（三种状态分开说）→
  **边界句**（收下了 ≠ 现在就生效）→ **填的那一块**。
* **聊天那一屏是老表单**（`KeyForm`：带粘贴、带"取消注册"）；其余三屏用新 `CredForm`
  （字段可以是**一串**（图片/视频）或**三样**（语音），一次提交写整屏）。
* ⚠️ **关于 / 退出登录挂在第一屏（聊天）的可滚内容底下**，**不做固定页脚**：
  固定页脚在 3.1 倍字下会把上面挤爆（D3.5 那道硬闸当场判红）。
* ⚠️ **每一屏给了一个 key**（`credTab:<名字>`）：`TabBarView` 自己也是一个 `Scrollable`

## 九、图片生成那条路（P1-27 前半 · 2026-09-24）

主人原话：*"图片用seedream，volcengine的。"*

### 9.1 事实从哪来（**不许猜接口**）

官方那两页（`ark.volcengine.com/.../image-generation-api`）是**前端渲染**的 ——
抓回来只有"火山方舟"四个字。⇒ 正文取自一份**第三方速查**
（GitHub 上的 `doubao-seedream-image-skill/references/api-quickref.md`）：

| 项 | 值 |
|---|---|
| 端点 | `POST https://ark.cn-beijing.volces.com/api/v3/images/generations` |
| 鉴权 | `Authorization: Bearer <ARK API key>` |
| 载荷 | `{model, prompt, size, response_format, watermark}` |
| 回的地址 | **临时**的（速查说 24 小时）⇒ 界面上明说"想要就存下来" |

⚠️ **第三方速查不算权威**，所以：① 端点与模型名**都能配**
（`HUPO_IMAGE_URL` / `HUPO_IMAGE_MODEL` / `HUPO_IMAGE_SIZE`），**不写死在调用逻辑里**；
② 真打一次、以**那次回话**为准（见 §9.4）。

### 9.2 形状

```
配置页「图片」那一屏： 填钥匙（`HUPO_IMAGE_KEY`）＋ 一个「试一张」
   └─► POST /api/image {prompt}
          └─► serve.js 取**他自己**那把（`data/creds/<他>.yaml`）
                 └─► `src/image.js` 打火山（Bearer）
                        └─► 回 `{ok, urls}` 或 400/409/502 ＋ **一句人话**
```
* 🔴 **钥匙不进回执、不进日志**（这条路上唯一的秘密）；上游原话也**不回显**（里面可能有带签名的地址）。
* **每一种"不行"分开说**：没填钥匙（409）· 那句话是空的/太长（400）· 钥匙不灵（502 `bad-key`）·
  连不上（502 `unreachable`）· 画太久（502 `timeout`）· 它回话里没有图（502 `no-image`）。
* 判据 **7 条**（`test/image.test.js`）：纯函数逐条 · **回执里没有钥匙** ·
  四种失败分开 · 每一句人话都不一样且过内部词表 · 路由 404/400/409/200（**回执只有地址**）·
  上游说钥匙不灵 ⇒ 502 且**带出原因**。⚠️ 测试**不联网、不花钱**（`fetch` 是注入的）。

### 9.3 界面（`lib/widgets/image_try.dart`）

* 「试一张」＝ 一句提示词（**不遮** —— 它不是秘密）＋ 一个按钮 ＋ **真把图画出来**（`Image.network`）。
* 🔴 **失败那句话由服务端给**（他才知道上游说了什么）—— 客户端**不许自己编**；判据钉着这一条。
* 空输入 ⇒ **一次都不发**（省一次请求，也省一次钱）。
* 取不到图 ⇒ 说一句实话（地址过期了那种），**不留一块空白让人猜**。
* 那一块**只在填了钥匙、而且接了线时**才画（不给一个点了没用的按钮）。
* 图片那一句边界话也**跟着事实变**：填了 ⇒「在下面写一句想要什么图，我就能给你画」；
  没填 ⇒「填上它，我才能给你画图」；**租户** ⇒「先收着。你这台还没接上」。

### 9.4 线上取证（2026-09-24 · 指纹 `d35b5f337d6b`）

| 验什么 | 怎么验 | 结果 |
|---|---|---|
| 端点 / 鉴权形状对不对 | **故意用一把假钥匙**真打一次火山 | `AuthenticationError: The API key format is incorrect` ⇒ 端点与 `Bearer` 形状**都对**（它嫌的是钥匙本身） |
| 我们认不认得它的回话 | 同上 | `why=bad-key`（映射对了）＋ 上游原话截断带出（110ms） |
| 线上那条真路（没填钥匙） | 带令牌 `POST /api/image` | **409** ＋「还没填画图那一把钥匙 —— 在上面填一串，再试一次。」 |
| 空话 | 同上 | **400** ＋「先写一句想要什么图。」 |

⚠️ **没验到的（明说）**：**真画出一张图**要**主人自己那把 ARK key**
（填在配置页「图片」那一屏）—— 填完按「试一张」就是端到端那一趟。

### 9.5 ✅ **和聊天打通**（P1-27 后半 · 2026-09-24 主人：*"图片需要打通"*）

```
他："给我画一张……"
   └─► 助手（模型）手里的工具 `image_generate`（⚠️ **借住**在小程序那条 MCP 上）
          └─► 域套接字 `apps.sock` 的 `draw` op
```

  判据只读**服务端自己记的当轮输入**（不看请求里的任何字段）；**没有"他那句话"⇒ 一定拒**
  （助手自己发起的轮、开机那几秒都在这档）。⚠️ 这条**产品规则**还没请主人拍过（**B8**），
  取的是**保守默认**：认不出就拒，并在话里告诉他该怎么说。
  ⚠️ 规则的形状（**两种**，第一版只认"画"这个字，把"我画了个图给你看"也放进来了 —— 判据当场抓住）：
  ① 对我提要求 ＋ 一个动手的动作（"帮我画…""给我生成一张…"）；② 祈使句开头（"画一张…"）。
* **借住**在小程序那条通道上（形状一样：工具只递请求、动手与花钱的只有服务端那一处）。
  ⚠️ **为什么不新开一条 MCP**：能力层 `hupo-capabilities.yml` 是 **strict** ⇒
  加一条要主人重建开机清单。⇒ 先借住，**下次重建时再拆出去**（`77-BLOCKERS.md` 记着）。
* **界面上**：回话里带着图片地址 ⇒ **画在气泡里**（`imageUrlsIn` 是纯函数：
  后缀 / `format=` / `data:image` 才认，**认不出就一个字都不动**）；
  整行都是地址的那种行**不重复显示**（图就在下面），句子里的地址**留着**；
  取不到图 ⇒ 说一句实话（临时地址过期了），**不留空白**。
* 判据：服务端 **+9**（工具清单十件 · `draw` 的六种情形 · **拒了就不许花** · 闸的真值表）
  ＋ 客户端 **+6**（认地址四种情形 ＋ 气泡里真画出来／负向对照）。服务端 **819 全过** ·
  客户端硬闸 **全过**。
