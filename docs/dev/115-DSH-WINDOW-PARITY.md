## 〇、一句话

DSH 的窗口不是一个"聊天框"，是**一个会话的工作台**：左边一列工作区/会话树，中间一条**它的会话协议原样投影**
（系统提示词、上下文注入、推理、每一次工具调用与结果、重试、压缩、用量、文件交付…都各是一行、
各有折叠与动作），右边一个可开可合的文件/文档栏，底下是**队列/插话**两档语义的输入区，
顶上还有一个 **Trajectory**（把同一条会话摊成一张表）。

⇒ 而我们的窗口是**另一条东西**：18.7k 行 Flutter，画的是**被我们翻译过、并且被重新配过音**的
5 种过程事件（`message/status` · `step/*` · `reasoning/delta` · `plan/updated` ＋ 通知），
**工具名、callId、入参、用量、系统提示词结构上不发**，而且内部词上屏是缺陷（`D1.1`）。

**⇒ "几乎一样"不是换皮，是换信息模型。** 这不是我猜的 —— 下面逐项对表。

## 一、DSH 窗口长什么样（真机看到的）

### 1.1 区域（`A-layout.md` §1）

```
grid-template-columns: <左栏>px minmax(0,1fr) <右栏>px    （过渡 .3s cubic-bezier(.4,0,.2,1)）
┌────────────┬───────────────────────────────────────┬──────────────┐
│ 左栏 280   │  会话头：标题 · 模式 · [Chat│Trajectory] │ 右栏 0 或    │
│ （最窄 56）│  ─────────────────────────────────────  │ 300–70%vw   │
│ 品牌        │  transcript（内容宽 clamp(680,64%,920)） │ 文件 / 预览  │
│ New Session │      … 各一行 …                        │ 可全屏/分栏  │
│ Workspaces  │  ─────────────────────────────────────  │              │
│  工作区树    │  输入区（sticky 贴底，36px 渐隐）        │              │
│ Settings    │  状态：83 轮 3057 步 · 263 tok/s · 缓存  │              │
└────────────┴───────────────────────────────────────┴──────────────┘
```

- 断点：**<1024 自动收左栏**；**<768 右栏自动全屏**；中间永远给内容留 400px。
- 没有顶部菜单栏、没有状态栏、没有别的活动栏 —— 就这三列。
- 会话头右边那三个小按钮：右栏展开 /（模型·权限选择器）/ `⋯` 菜单。

### 1.2 左栏（`A-layout.md` §2）

| 件 | 内容 |
|---|---|
| `New Session` | 38px 高、圆角 12 的整条按钮 |
| `Workspaces` | 一行标题 + 搜索 / 展开收拢 / 新建 三个小按钮 |
| **工作区行** 34px | 文件夹图标（悬停换成箭头）· 名字 · 悬停出 `…`（重命名/删除工作区）和 `+`（在这一间新建会话）；悬停卡显示**完整路径**与"创建于…" |
| **会话行** 32px | 一个状态点（等审批/运行中/N 个子代理在跑/已完成/空闲，**有优先级**）· 标题 · 可选"有定时任务"图标 · 相对时间（悬停时被 `…` 换成 重命名/分叉/归档） |
| 展开规则 | 一个工作区先露 **5 条** + "展开其余 N 个会话" |
| 搜索 | 就地展开成输入框；标题/工作区**即时**匹配，正文匹配走宿主（250ms 防抖、最多 20 条、带片段） |
| 底部 | `Settings` |

### 1.3 transcript 能画出来的每一行（`B-render.md` §1，**14＋4 种**）

| 行 | 它是什么 | 默认形态与动作 |
|---|---|---|
| `user` | 人的话 | 右对齐气泡；复制；`clock:"start"` |
| `steering` | 运行中插进去的话 | 同一个气泡组件 |
| `assistant-step` | 一步的输出 | **Markdown 逐块**：text / reasoning / image / tool-call（tool-call 交给工具行）/ 未知块（JSON）；被中断加 `已停止` |
| `system-prompt` | **模型看到的系统提示词** | 默认折叠的 disclosure，展开是**逐字原文**（141px 滚动窗） |
| `context` | 上下文注入 | 折叠行；六种形态（instructions/catalog/snapshot/notice/relay/recall），recall 那行会写"保留 N 条 · 省略 M 条" |
| `model-retry` | 重试 | 原生 `<details>`，倒计时 250ms 一跳；`（3/5）· 12s` |
| `turn-error` | 本轮失败 | 已知 code 有人话（如"API 密钥无效"），否则是脱敏后的上游消息 |
| `turn-max-tokens` | 撞上输出上限 | 一句 + "发『继续』" |
| `compaction` / `manual-compaction` | 上下文压缩 | "已压缩 N 条历史记录（约 M tokens）"；**被遮住的历史仍留在上面**；给模型的那段信封**永不渲染** |
| `command` | `/` 指令 | 名字 + 结果摘要，正文进 `<pre>`（≤260px） |
| **`turn-process`** | **紧凑模式的折叠控件** | 一个 33px 通栏按钮，标签 = `N 次工具调用 · M 条消息 · K 个 subagent`（0 的段省略；三样全 0 ⇒「已思考」） |
| `turn-tail` | 一轮的页脚 | 复制 · 赞/踩（反馈）· 分叉 · **用量**（`用量 16.1M tok`）· **用时**（`用时 23m 44s`）· 时间戳；**最新一轮常显动作，老的悬停才显** |
| `unknown` | 认不出的 surface | 标着"未知 surface 事件：{type}"的 JSON 块 |
| `tool-call` | 一次工具调用 | 见下 |
| `workflow-run` / `command-input` / 状态行 | 工作流、`/goal` 的输入气泡、`深度求索中...`、`加载更早`、`回到底部`、右侧**轮次导航条**（每轮一个刻度，10px 间距；点没加载的那一轮会**翻页到那一轮**） | |

**工具行**（`dsh-client-ui-tool`）：是**一棵树**（子调用递归），每个工具家族有自己那张卡：
bash（终端卡，带 gutter/行号）· read（带**行号与 diff**）· search（命中列表）· web（favicon + 标题 + 摘要）·
write/edit（**逐行 diff**）· present（文件 chips）· todo（清单）· subagent（子会话）…
每张卡：一眼能看出**用了哪个工具、对什么、成没成**，展开看**原样输出**；卡上就有复制；认不出的工具走通用卡。
⇒ **工具名与入参在 DSH 的窗口里是给人看的**（`Bash · Commit the stray piece separately`、`write {"content": …}`）。

### 1.4 Trajectory（第二个 tab，`B-render.md` §1.5 + 截图）

把同一条会话摊成一张**表**：列是 `Turns | Calls | Input | Model | Tools | …`，行是
`TOOL / ASSISTANT / USER`（左侧彩色小标签）+ 工具名 + 截断的入参 + 助手文字；
上面一条**时间直方图**（Model / Tools 两条轨道）、`Duration` 与 `Search`；
没有时长的行**留空，绝不编一个时长**。

### 1.5 输入区（`B-render.md` §3）

- **常驻一个 Lexical 编辑器**（无会话/有会话**同一个 DOM**）；占位：`发消息或创建任务, / 调用指令, @ 文件或对话`。
- 左端 `+`（附件）· 权限档 chip（`Workspace Write` / `Full access`）· 模型 chip（`DeepSeek-V41-Flash · High`）· 发送/停止（**同一个位置互换**）。
- **繁忙时的语义两档**（设置里可选）：**排队发送**（Queue）/ **插话发送**（Steer）；
  `Enter` 与主按钮用同一档，`Cmd/Ctrl+Enter` 用另一档。排队消息进 **QueueDock**（一条内联显示、两条以上折叠），
  每行可 编辑 / 删除 / 插话发送。
- `/` 指令与 `@` 引用（文件/文件夹/会话）各有一套弹出菜单。
- **审批与提问会临时接管输入区**（不是弹一个居中对话框就完事）。
- 状态胶囊：`{轮} 轮 {步} 步`（步数为 0 且没有 token ⇒ 整行不画）、`用量`、`缓存命中 N%`。

### 1.6 设置（截图 `shot-9-settings.png`）

模态；左导航 `General / Models / Plugins / Agent presets`；General 里逐行 = 标签 + 说明 + 控件：
`Permission`（默认权限档）· `Language` · `Appearance`（Light/Dark/System 三张大卡）·
`Font size`（12–17，**只影响会话正文**）· `Conversation display`（**标准/紧凑，默认紧凑**）·
`Send behavior while busy`（Queue/Steer）。右上角 `Open configuration file`。

### 1.7 视觉（`A-layout.md` §4 + `B-render.md`）

三套 token：`--dsw-static-*`（原色板）→ `--dsw-alias-*`（语义，**亮/暗两套**）→ `--dsh-*`（运行时）。
**两处最容易看错**：① 亮色主题的 `bg-layer-1/2/3` **全是纯白**，层次只靠 **0.5px 描边 + 两层柔光阴影**；
② `--dsw-alias-brand-primary` 亮色是**近黑**、暗色是**近白**，真正的蓝是 `--dsw-alias-link`。
字体：系统栈 + 代码栈；正文默认 14px，**字号是用户可调的 12–17**（正文/表格/代码三档跟着算）。
`superellipse(1.5)` 圆角；滚动条 8px；`prefers-reduced-motion` 每个动画模块都认。
**我们的窗口现在是完全另一套**（暖白纸感 `#F8F5EE` + 朱红 `#C8452F` + 圆角 18）。

## 二、它的"信息处理方式"（这一节是主人那句"也应该一样"的核心）

`B-render.md` §2 逐条给了出处；这里是最值钱的十二条：

| # | 规矩 |
|---|---|
| 1 | **一轮 = `turn/start` … `turn/end`**；每个节点挂在 `turn/step` 上（合成行有固定偏移，插进去**不许改变既有行的相对顺序**） |
| 2 | **默认紧凑**：`turn/end` 时，**最后一步**只有在"有正文/图片/未知块、且没有工具调用块"时才成为**最终正文边界**；它之前的推理、工具、重试、较早正文、上下文注入**一起收起** |
| 3 | **折叠门里有历史条件**：只要"加载更早"还在（`hasMore`），**不画折叠控件、不藏任何成员** —— 不许藏用户还看不到的东西 |
| 4 | **计数**：工具调用与 subagent **互斥**（`subagent*` 才算 subagent）；消息数只数**边界之前**有回复内容的助手消息；系统提示词与上下文注入**不加计数**；三样全 0 才写「已思考」 |
| 5 | **藏起来的行不卸载**（`hidden="until-found"` + `beforematch`）⇒ 浏览器 Ctrl-F 还能找到；**自动折叠不许吃掉键盘焦点**（会吃掉就不折） |
| 6 | **token 用量宁可不显示也不许给半个**：窗里没有 `turn/start`、或**任何一次尝试的用量不精确**（安全整数、`推理≤输出`、缓存桶要么全有要么全省…）⇒ **整块详情不画**；**全树没有"花了多少钱"这个东西，只有 token** |
| 7 | **分页 50 条一页**，切口回退到 `min(seq, sourceEventSeqs)` ⇒ **一页永不把一条消息和它用过的工具调用切开**；轮次导航比窗口**宽**（没加载的轮也有刻度，点了先翻页到那一轮） |
| 8 | **滚动归属**：500ms 采样、离底 25px 算"跟着"、阅读线 = `顶部 + min(96, 20%高)`；贴底时新内容立即接管，**手一划就交还控制权**（哪怕还在阈值内），高度变化就保住当前位置 |
| 9 | **乐观提交**：点发送的**同一帧**就把本地那条挂上（`placement` 由"是否在跑 + Queue/Steer"定），回显在权威记录到达后**一帧**退休；失败的**保留草稿**；宿主按 `requestId` 幂等 |
| 10 | **助手流有结算契约**：`settle-assistant` 一下同时"撤掉临时行 + 加上持久行"（原子），放弃的那次只结算不加行 |
| 11 | **复制**：每条用户/助手一条；助手那条 = **最后那条助手消息的可见文本块拼起来**（不含工具）；复制成功图标**亮 1000ms**。**没有编辑、没有单条重试、没有逐行 JSON 导出** |
| 12 | **每个 README 都有"已知限制"**（`B-render.md` §4 逐条抄了）：比如 token 行在窗口缺 `turn/start` 时干脆不显示、进行中的 Trajectory 行**绝不编时长**、工具行的 `run_code` 递归今天**只走一层** |

## 三、"前后端分离"到底分离到什么程度（`C-protocol.md`）

**分离是真的，而且有文档化的"只吃 API 的前端"这条路**（`C-protocol.md` §7）：

| 件 | 事实 |
|---|---|
| 拿身份 | `GET /?token=<一次性>` ⇒ `303` + `Set-Cookie`（HttpOnly/SameSite=Strict；**没有 Secure**，本机 HTTP）；**没有 bearer、没有登录页、没有 logout** |
| 事件流 | **一条 WS `/api/remote.mux`**，里面复用所有逻辑流：`session/follow`（会话事件流）· `session/control`（队列/任务/投影）· `workspace/follow` · `workspaceFiles/changes` · `$events` |
| 命令 | `POST /api/<方法>`，体 `{type:'client-request',rpcId,method,payload:{args}}`；**16 个 `session/*`** ＋ workspace/settings/credentials/agentPresets/llm/… |
| 审批与提问 | **不是 RPC，是 waterfall**：`$events` 推 `approval/request` / `user-questions/request`，答案 `POST /api/$events/result`；**fail-closed** |
| 事件模型 | `{type, seq, time, data, surfaceOp?, sourceEventSeqs?}`；**56 种已知类型**；**只有 `assistant/live-chunk` 不是持久的**；四种 surface 事件带替换窗口 |
| 状态归属 | 服务端：会话日志（唯一真相）、投影（`asOfSeq`，可以旧但**绝不超前**）、队列、任务、子代理目录、设置/凭据。客户端：事件窗口、队列快照、乐观回显（**只在内存**） |
| 重载 | **先 follow 再翻页**（绝不"先翻页再订阅"）；断线**没有 since 游标** —— 重开 follow + 用翻页补缝；退避 500ms→10s、抖动 50–100% |
| 前端本身的形状 | 51 个客户端插件（各是一个 `lib/client.js`）；`window.__DSH_BOOT__` 里**没有**版本/插件清单/工作区/locale/token；**`/plugins/*` 完全不鉴权**；HMR 走 SSE |
| 别人的前端能不能接 | 文档明说可以：`ClientTransportHooks`、"shell-owned compositions provide equivalent Remote streams"、"a shell-owned carrier can render the same rows without a Web server"、"Its Client face can be reused by Web or a future TUI" |
| **最大的坑** | **命令面是构建期产物**：没有运行时的能力清单/发现接口，外来前端只能**把生成的类型表 vendor 进去**，或者靠观察 `/api/remote.mux` 反推 |

## 四、我们的窗口现在是什么（`D-ours.md`）

- **18,732 行** Flutter（`v2/apps/mobile/lib/`）· 服务端 **38,081 行**（`v2/services/core/src/`）。
- 形态：桌面铺满整屏 + **底部一条浮窗**（Z1 永远最上、四边 30、抓手在上边框正中）；三档（收起/半开/展开）。
- 行：用户气泡（四态）· 助手气泡（Markdown 之外基本是纯文本 + 图片 + 出处）· **推理原文**（只在"它心里想的"那一档，
  挂在气泡下）· 分隔线 · 通知卡 · **步骤流水**（把人话状态一行一条）· 忙行 · 更早提示 · 空态 · 多选底栏。
- **我们收到的过程信息只有 5 种**（+通知/计划/派活）：`message/status{turn,state}` · `step/start`/`step/end` ·
  `reasoning/delta` · `plan/updated` · `job/*`。**工具名、callId、入参、工具输出、系统提示词、上下文注入、
  用量、diff、文件交付、子代理、Trajectory、会话列表、右栏 —— 一个都没有**（`session-translate.js` 刻意只发类别，
  `TOOL_STEP_STATE` 把工具名映射成"在查资料/在读东西/在写/在动手做/在琢磨"）。
- **内部词上屏 = 缺陷**（`D1.1` + `forbidden_words.dart` 硬表：工作区/会话/工具/模型/上下文/系统提示/`bash`/subagent…）。
- 原始保真度**只有一处**：桌面内置的**「我自己那台」**（`HarnessPane`）—— 它把 DSH 的 `session.event`
  **原样**画成终端（未知类型画"类型 + 一小段 JSON"，判据 H8），并且明写"在这儿说话的不是琥珀"。

## 五、逐项差距表

| DSH 有 | 我们有吗 | 差在哪 / 为什么 |
|---|---|---|
| 左栏：工作区树 + 会话树 + 搜索 + 重命名/分叉/归档 | 半有 | 我们是**桌面图标墙**（一个图标 = 一间房），没有"会话列表"（`#155` 定了一间一条会话 ⇒ 也没有可列的东西）；改名有（图标菜单），分叉/归档没有 |
| 右栏：文件树 / 文档预览（代码·Markdown·图片·PDF·HTML） | **没有** | 我们连"这一轮改了哪些文件"都不发 |
| transcript：系统提示词行 | **没有** | 只在「我自己那台」里原样出现；聊天窗口这一侧结构上不发 |
| transcript：上下文注入（含"保留 N 条 · 省略 M 条"） | **没有** | 同上 |
| transcript：**每次工具调用一行**（工具名 + 人话标题 + 原样输出 + 每卡复制） | **没有** | `TOOL_STEP_STATE` 只把它压成一个状态词；**这是最大的一处信息损失** |
| transcript：write/edit 的 **逐行 diff** | **没有** | 同上 |
| transcript：重试 / 本轮失败 / 撞输出上限 / 压缩 | 半有 | 我们有 `error` 帧但**刻意不上屏**（`dispatcher.js` 自己写着"客户端今天不渲染"）；压缩/上限没有 |
| transcript：**每轮用量与用时** | **没有** | 我们只记在服务端账本（`usage.jsonl`），不上屏 |
| transcript：**过程折叠控件**（"N 次工具调用 · M 条消息"） | 半有 | 我们有「过程」四档（安静/在做什么/步骤流水/它心里想的）与步骤流水，但**没有"一轮一折 + 计数"** |

| 输入区：Queue / Steer 两档 + QueueDock（可编辑/删除/插话） | **没有** | 我们繁忙时只有一句"它现在忙不过来，过一会儿再发一次"（`SayBusy`） |

| 审批 / 提问**接管输入区** | 半有 | 我们有"派活问一句"那张确认卡（`job/ask`）与二次确认弹窗，但没有一般化的审批/提问通道 |

## 六、"几乎一样"的三条路（**要主人挑一条**）

### 甲 · **直接用 DSH 的窗口**（最像、最省、但换掉了产品形态）

把每个房间那条**已经存在的** `dsh --profile web`（开发者入口今天跑的就是它）变成产品的聊天窗口：
宿主经隧道把它送到浏览器（今天 `dsh<手机号>.stalkerai.cn` 就是这么做的），或者嵌进桌面那一层。

- **像度**：100% —— 它就是 DSH 的窗口（内容/功能/信息处理**自动**一样）。
- **代价（四条，每条都硬）**：
  1. **它说的是"那台 DSH 本人"，不是琥珀**（`--profile web` 的会话 agent 是 DSH 自己的 preset；
     看板上也明写着"在这儿说话的不是琥珀"）⇒ 主人要的到底是**琥珀的窗口**还是**那台机器的窗口**，这是产品定义问题；
  2. **内部词全部上屏**（`bash`/`write`/系统提示词/`token`/provider）⇒ 与 `D1.1`（内部词＝缺陷）**正面冲突**；
  3. **一个房间同时只能有一台**：DSH 的会话有**写租约**（B46 真机撞过 `is already owned by an active write handle`），
     而产品的调度器（`dsh --profile sdk`）也在用同一条会话 ⇒ 要么二选一，要么继续"让开"（今天那个 `yieldRoom` 补丁）；
  4. **资源**：一台 `dsh web` ≈ 390MB（B43 真机），我们每房间一台 ⇒ 768MB 的盒子装不下第二间。
- **判据**（真机、可反着验）：同一间里"产品说话"与"DSH 窗口说话"是**同一条会话**；同时只有一台；
  盒子里 `oom_kill` 不涨；窗口里的每一句都能在会话日志里找到同一 `seq`。

### 乙 · **我们的前端改接 DSH 的协议**（前端保真度最高的一路，工程量最大）

客户端（Flutter 或换 Web）直接实现 `session/follow` + `/api/remote.mux` + 56 种事件 + 51 个插件的等价物。

- **像度**：理论上可以到"逐像素 + 逐行为"（有 129,521 行编译后前端代码当参照，且**未压缩、带 `//#region`**）。
- **代价**：DSH 浏览器端 ≈ **129.5k 行**（41 个 `client-ui-*` ＋ 47 个 `client-*` ＋ 5 个 `api-*`）；
  我们客户端现在**18.7k 行**。就算只做"壳 + transcript + 工具卡 + 输入区 + 右栏"，也是**数周到数月**；
  而且 Flutter 侧要重做 Lexical 编辑器、Markdown+代码高亮、diff/终端/图片/PDF 预览这些**本来就有的轮子**。
- **一条小的变体**：**把 DSH 的前端 bundle 原样嵌进我们的页面**（`/plugins/*` 不鉴权、`__DSH_BOOT__` 由 `dsh web` 注入）
  —— 但这仍然需要一个 `dsh web` 进程 ⇒ 回到甲的代价 3/4。

### 丙 · **对齐"内容与信息处理方式"，视觉与形态仍是我们自己的**（我建议这条）

不改"琥珀的声音"、也不拆桌面/浮窗；把**被我们藏起来的信息**按 DSH 那套规矩补齐（分层、折叠、可核）：

| 期 | 做什么 | 判据（每条都能反着验） |
|---|---|---|
| 丙-1 | **工具行**：服务端把 `tool/call`·`tool/result` 的**类别 + 人话标题 + 成败 + 一行摘要**发上来（**仍不发工具名/入参原文**，除非主人点头），客户端画成独立行 | 一次 `bash` ⇒ 屏幕上多一行、有标题、有成败；认不出的类别沉底；反例：把工具名塞进线上文案 ⇒ 禁用词闸红 |
| 丙-2 | **一轮一折 + 计数**（"N 次工具调用 · M 条消息"）＋ **历史未加载完就不折** | 一轮结束后过程收起、计数对得上；`hasMore` 时不许折 |
| 丙-3 | **每轮用量与用时**（token 三桶 + 缓存命中；**不精确就整块不画**，且**只给 token 不给钱**） | 窗口里出现 `用量 …/用时 …`；上游缺一桶 ⇒ 那一行不画 |
| 丙-4 | **繁忙两档**：Queue / Steer（排队消息可见、可撤） | 运行中再发一句 ⇒ 进队列条不打断；可撤；`Enter`/`Cmd+Enter` 两档 |
| 丙-5 | **系统提示词 / 上下文注入行**（默认折叠、展开逐字） | 展开能读到模型真看到的那段；折叠时不占屏 |
| 丙-6 | **右栏**（这一轮改了哪些文件 + 预览） | 点"改了哪些文件"⇒ 打开右栏看到 diff |
| 丙-7 | **Trajectory 视图**（同一条会话摊成表） | 两个 tab；表里每一行都能对回一条事件 |
| 丙-8 | 设置里加 **外观/字号/对话显示（标准·紧凑）/繁忙行为** | 字号 12–17 只影响正文；紧凑/标准可切 |

## 七、与已有决策**正面冲突**的几条（**必须主人拍**）

1. **内部词**：`D1.1` 说"界面上出现工作区/工具/模型/会话/系统提示 = 缺陷"。而 DSH 的窗口里这些**就是内容**。
   ⇒ 甲/乙 等于废掉 `D1.1`；丙 只能做到"人话化之后的信息对齐"（**工具名不上屏**）。
2. **这是谁的窗口**：产品现在的聊天 = **琥珀在说话**（服务端把工具轨迹翻译成"在查资料/在写"，回答由主 agent 出口）；
   DSH 的窗口 = **把那条会话原样摊开**。甲 = 后者，且那句话明写"不是琥珀"。
3. **一间一条会话**（`#155`）：DSH 的窗口按"一条会话一个写租约"工作；我们已经有 `yieldRoom` 让开补丁（B46）。
   甲／乙变体都会把这个问题从"补丁"变成"设计"。
4. **浮窗铁律 Z1–Z5**（聊天永远最上、桌面铺满、被盖住不重建）：DSH 是三列工作台、没有浮窗。
   要做成 DSH 那样，浮窗要么被砍、要么变成"工作台里的一栏"。
5. **成本/资源**：一台 `dsh web` ≈ 390MB、盒子 768MB。甲 = 每间一台 ⇒ **要先扩内存或砍并发**（这是花钱的决定）。
