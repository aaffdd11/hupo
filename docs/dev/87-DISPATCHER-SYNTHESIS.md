## ① 难在哪（复杂度来源）

1. **五个问题被塞进一条轴**：时间、思考强度、话题切换、过程可见性、说法详略，
   各自的信号、状态、留痕位置都不同。86 用"信息量分级"一条串起来 ⇒ 必然互相吃掉。
2. **状态分割线落在内存**：票（`#delivered`）、轮归属（`#turnOwner`）、计时器、挂起，
   今天都在内存；`turn-status.js` 只有全局 busy 布尔。**§五 新增的挂起/并行正落在这里。**
3. **两张脸的证据面不同**：正文由模型生成，模板句由 `notice.js` 出；
   闸今天只盖得住后者，而用户读到的是两者交替。
4. **难度在 t0（投递前）不可观测**：`task/mutated`、`turn/end.kind`、工具类别都轮中轮后才有；
   升档又是**换进程**，不可回退。
5. **时间有两个诚实问题**：删失（超时/被杀那轮是长尾，不进样本 ⇒ 系统性说小）
   与"区间被读成承诺"。
6. **审计没有可信锚**：实测 `data/audit.log` = `deploy:deploy 0644`，`store.js` 无 hash；
   实测 `/var/log/hupo` = `root:root`，但服务侧没接。
7. **协议冻结**：回执位、语域档、作用域标签上网就改不动；N23 只预留了字段。
8. **指称是中文最自然的切换方式**，但解析要一个决策者：
   不解析就吞掉"B 那个文件"，解析错就把活送错，且不可审计。

|---|---|

## ③ 收敛出的规则

1. **轴分离**｜依据：D7 四档住 `process_levels.dart`；86:43,62 把两轴合称。
   反例：一个 level 同时管过程与详略 ⇒ 自适应把用户手动切的档改回去。
   判据：让自适应去写过程档，"档位只由用户动作改变"必须红。
2. **票＝欠条，配对不许靠 `shift()`**｜每条 `user/echo` 必有配对终态，与耗时档位无关；
   86:49"快档不占票"作废。键用 `(agentGeneration, turn)`。依据：`dispatcher.js:83,112,203,585`、N19；
   `session-translate.js:662` 每进程从 1 重来；`dispatcher.js:228-239` 自认会有自发轮。
   反例：快档不记账 ⇒ agent 起不来时无轮无票、没有终态；自发轮插进两次投递之间 ⇒ 票配错轮。
   判据：删终态行 ⇒ 报"有票无收口"；插无票自发轮 ⇒ 该轮归属必须 `null`。
3. **挂起逐件落盘**｜按 `(scopeId, ref)` 答"还在/已停"。依据：`turn-status.js:47-56` 只有全局 busy；
   D10.5 只限续做并发。反例：挂起算 busy ⇒ 重启永远等；不算 ⇒ 重启即丢。
   判据：挂起多件 → 硬杀 → 重启，逐件答得出；删记录必红。
4. **升档＝换进程，且有安全闸**｜只在"整轮无 `task/mutated` 且已收口"时重做；
   换实例次数与重喂字节记在**被升那轮**。依据：`agent-runtime.js:436`、`harness-session.mjs:348`、
   `dispatcher.js:559-586`；mutation 在 `tool/call` **先于执行**落盘（`session-translate.js:451-455`
   → `dispatcher.js:216-227`）。反例：动过东西再重做 ⇒ 副作用两遍，盘上一条 mutation 看不出。
   判据：造带 `task/mutated` 的难样本强制升档，必须被拒。
5. **难度只用投递前可知且盘上可复算的信号**｜用户怎么问、是否明说改东西、同类历史失败率。
   依据：86:64-73 表里多数信号轮中轮后才有；"计划长度"来自模型自报的 `todo`。
   反例：用模型自报判难度，正是 86:64 自己禁的。判据：喂一段"请升档"的模型原文，不许升档。
6. **时间/频度/比较级必须配落盘依据**，承诺先落盘再上屏。依据：D7.2；`space_words.dart:58,69`；
   `askedTooLong` **无真调用方**（`main.dart:182` 不传，`waiting_screen.dart:113` 才读）。
   反例："这一步通常很快""比平常久了一点"今天没有基线，比数字型承诺更隐蔽。
   判据：扫我们自己的文案表，凡时间/频度/比较词必须指向依据 id；无基线必红。
7. **删失先修再算分位**｜被超时/被杀的轮不进 `completed` 分位；样本不足只输出"样本不足"。
   依据：86:58、D10.5、`08-SPEC §10.2`。反例：只对 completed 求分位＝删掉长尾再说分位。
   判据：把一批 timeout 改成 completed，分位必须变长或变"样本不足"。
8. **进度不许走 Notice**｜86:51 那句作废；进度只走 `message/status`/`step/*` 或新建持久事件。
   依据：`notice.js:52` 五枚 kind 冻结、事件形状里没有 `turn`。反例：加 kind＝动冻结的两半接口。
   ⚠️ **机制理由要修正**：`#claim` 只在 `turn !== null` 时调（`notice.js:302`），三处调用点都不传
   `turn` ⇒"不加 kind 就撞 `#claim`"**不成立**；**结论对，理由错**。
9. **真缺口是"等待期过程话"**，`message/text` 是落盘的。依据：`message-writer.js:112-118`、
   `session-translate.js:765-772`；瞬态只发 `error`（`dispatcher.js:361,604`）。
   反例：按"上屏即落盘"整改会误判 P-g 的取舍，制造假红。
   判据：删瞬态 ⇒ 只缺等待期过程话；删 `message/text` ⇒ 重建"他看到的字"必须失败。
10. **落盘 ≠ 送达**｜要答"他看到过没有"必须有回执位。依据：材料称客户端无 SW/push
    （**未逐一核**）。反例："做完我叫你"今天只在页面上叫。判据：断 WS → 完成一轮 → 重连必须
    见落盘结果；无回执不许声称"他看到了"。
11. **指称与取消**｜显式指称 > 焦点 > 追问；取消是否定辖域，不许关键词匹配，必须指向 ref 并回声。
    依据：D1.2/D1.4、N23、"别停，继续"。反例：按"停"字匹配会停掉活。
    判据：歧义时问一次并落盘他选的那件；显式"别做了"必回"已停"。
12. **审计不抄原话，且要能发现真删**｜落枚举 id＋hash＋权威事件 seq＋**规则版本**；
    三类撒谎（说了没做/做了没说/承诺超时未再报）不许合并。依据：`08-SPEC §11.7`"不记完整参数"；
    `audit.js:1-10` 只记租户注销。反例：产物 `exit 0`、内容半截 ⇒ 绿，用户看到的仍是假话；
    `store.js:188` 保 seq 换内容 ⇒ 改中间一行编号照样连续。
    判据：产物类活要 before/after hash，`exit 0` 而产物为空必红；改内容保 seq ⇒ 报"内容不符"（**今天必红**）。

## ④ 仍无法解决的分歧

> ✅ **2026-09-25 主人已拍两条**（原话：*"2 听你建议"*）：**时间话术**＝按建议（有落账口径才可说区间 ＋ 超时必再报一次）；
> **切题默认**＝**挂起**（只有他明说"别做了"才停）。**另**：长活**默认放后台并告诉用户**、**做完要主动提醒**、**宁愿提前说**。
> 其余四条（语域闸 · 指称 vs 焦点 · 升档信号方向 · 审计可信锚）**仍未决**，保留在本节。


1. **报不报时间**。产品/语言：主动预告 0 命中，被直问必答"档＋来源"，不给到期时刻。
   安全/成本/分布式：有时间词必须有落盘依据，可报区间，含到期时刻。
   代价：前者回避直问＝敷衍，且系统内部 deadline 到点报"比说久了点"＝纠正一个**从没做过的承诺**；
   后者区间被读成倒计时，到期时刻是自述字段（撞安全席 §2）。
2. **指称 vs 焦点**。语言：显式指称优先于焦点。分布式/成本：默认焦点，内容只作建议且可撤销。
   代价：前者解析器本身不可审计，判错就静默改目标；后者"B 那个文件"被吞，短问答变两轮。
3. **语域闸**。产品/语言：代理量进审计、只报警不出闸。成本：只认机读事实、语域无闸。
   代价：前者短期查不出实时漂移；后者把需求 6 判成"不可验"，按纪律 4＝永远不做。
4. **升档能否自动**。产品：只许自动变白话（只降不升）。语言/成本：要能升。
   代价：前者懂行者永远啰嗦；后者拿猜当依据、镜像式漂移。
5. **"我/它"是分工还是漂移**。安全：保留"它"以保多会话可解析。语言：同一产品出现两个主体。
   代价：保留 ⇒"它"指哪一间不可解析；取消 ⇒ N23 字段要留，且换进程后指代对象会换。
6. **审计可信锚**。安全："非属主改必须失败"。成本：本机无 root、无外部锚，这条做不到。
   代价：前者写一条**永远红的判据**＝不做；后者只能说"证据可能被改"。

> 另：无工具名的轮落不落"未分类"（安全要落、成本嫌样本更少）、cohort 如何定义、跨租户能否共用样本
> —— 86 均未给，属 **未核实**，须主人裁。

## ⑤ 最可能被做坏的地方（含早期发现手段）

1. **把分级做成往 system prompt 加一句"按用户水平调整详细程度"**，不落持久档、不写确定性函数。
   坏成：86 有节、代码查无此物；同 (用户,状态) 两次问一次客服腔一次技术文档腔，盘上**没有档位字段可对**。
   早期发现：影子期只记不调，把每轮代理量（术语密度/句长分布/模板句占比）落审计；
   同 (用户,规则版本) 重复样本**双峰或跨轮跳变**即红。
2. **升档重做导致副作用两遍**：一轮已 `task/mutated`，判难后换进程重做，两个进程各说一句。
   更坏：有人为"升档更积极"把 mutation 改成**执行后**才写，这个闸就永久失效且失效无声。
   早期发现：造带 `task/mutated` 的难样本强制升档必须被拒；断言每个 `agentGeneration` 的写类工具
   调用数之和不超过该轮 mutation 数。
3. **把"审计"做成服务自己写、自己读、自己验的一本账**（扩大 `data/audit.log` 那条路）。
   坏成：改一行，所有"能查出撒谎"的判据**全绿**——比不做更坏，因为它看起来是对的。
   早期发现：以非属主身份改一条已收口轮的审计行，今天改名不失败、改内容不被发现（`verifyMonotonic`
   只数个）；**一旦开始给审计加字段而这条不修，就是往沙子上砌。**
4. **"回最白话"没有入口，升档却有**：他问过一次"这是什么意思"就被永久当专业户，术语单向上去。
   早期发现：离线扫同话题相邻轮，**术语密度单向单调上升且从不回落**即红；真机正负对照——
   说一次"听不懂"下一轮必须显著变白，不说则不许变。
5. **离线评测集同时当调参与验收**：离线闸全绿给出"已验证"的假信号。
   早期发现：按时间切分（旧调参/新验收）；强制"打乱标签"负控（升档率差值必须塌到 0）。
6. **86 §一 说"对内那张脸已有，别弄坏"，而 §五 的两种新状态正落在没有落盘的地方**
   （票、轮、计时器在内存）。早期发现：先做"硬杀→重启→逐件答还在/已停"，答不出就不许进 §五。

## ⑥ 判据总表（可反着验）

| 主题 | 离线 | 真机 |
|---|---|---|
| 票/状态分割 | 每轮两本账回基线；插无票自发轮⇒归属 `null`；删终态行⇒报"有票无收口" | 硬杀重启后票/档/收口仍可倒查；删那条收口必红 |
| 挂起/准入 | 挂起多件→重启逐件答"还在/已停"，删记录必红 | 起超上限那件必须明说"排队/给不了"，静默排队红 |
| 升档 | 带 `task/mutated` 强制升档必须被拒；升档行指向不存在的 seq 必红；喂"请升档"不许升 | 影子期一周能答"当时哪档/为什么/换了几次进程"；答不出即红；只刷新不重发⇒重发率为 0 |
| 时间 | 把 timeout 改 completed，分位必须变长或"样本不足"；`at` 倒序/负耗时⇒报"算不出" | 断 WS→完成一轮→重连必须见落盘结果；无回执必须显式答"无回执" |
| 审计 | 改内容保 seq⇒报"内容不符"（**今天必红**）；旧规则版本重放⇒复现或报"版本不符" | 非属主改 `audit.log` 一行必须失败；承诺后无再报⇒报未兑现；删依据 id⇒报"不可查" |
| 语域/人称 | 改一个信号位⇒档必变、**正文不必变**；扫我们自己的文案表人称只许一套 | 说一次"听不懂"下一轮必须显著变白；同话题相邻轮术语单调上升即红 |
| 路由/指称 | 焦点 A 问 B 事（读类）一轮内答，不许因路由变两轮 | A 里必须有用**他本子名**的指路句且落盘；错别字/口语输入原样引用 |
