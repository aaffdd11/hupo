## 一、怎么查的（**方法比结论重要**）

三路**只读**子 agent 并行，各自不许改任何文件，只许读代码/读手册/读真机：

| # | 查什么 | 判据 |
|---|---|---|
| ① | **手册 vs 代码**：`docs/handbook/**` 里每一条"现状"断言，回到 `v2/**` 与 `scripts/**` 去对 | 每条都要能指到**文件:行**；指不到的算"手册在说假话" |
| ② | **账本 vs 事实**：`00-PROGRESS.md` §六 / `PROGRESS-HISTORY.md` §六 / `63-OWNER-DECISIONS.md` 里每条账，回到代码与真机对 | 已有两种说法的 = 账坏了；已经还了还挂着的 = 账没搬走 |
| ③ | **容器与运维的现状**：隔离、出网、配额、回收、监控、容量 | 只信**实测**（`ps` / `podman inspect` / `cgroup` 文件 / 全仓 `grep`），不信文档 |

⚠️ **为什么用只读子 agent**：这一批要动的是**手册**（`strict` 条目 ⇒ 要重建开机清单）。
先让"查"和"改"分开，**查的人不许顺手改**，否则"改了什么"和"本来是什么"就分不清了。

## 二、🔴 查出来的问题（**按严重度排**）

### 🔴 1. 容器**出网零限制**（新账 **#65**）

- **手册说**：`08-SPEC.md` §4.2 那一行写着【有效】的「**白名单 + 审计**」。
- **代码事实**（三处独立取证，全是空）：
  - 渲染出来的租户单元里**没有 `--network`**；
  - 全仓 `iptables` / `nftables` / 出口白名单 / 出口代理 **0 命中**；
  - `src/model-proxy.mjs` 只转发**默认上游**，不做任何出口约束。
- ⇒ 今天容器**可以任意外联**：agent 能往外发任意请求。
- ⇒ **这一条最重**，因为它的坏形态不是"报错"，是**读它的人以为容器出不去，于是不设防**。
- **已经改的**：手册那一行改成「**目标态 · 今天没实现**」。
- **要做的**：出口只放通模型 API 域名（`--network` + 代理/防火墙白名单）+ 请求审计。
  ⚠️ 这动的是**部署期**的东西（宿主网络 / 单元）⇒ 按 **P1/P2 要主人签字**。

### 🔴 2. **没有每用户磁盘配额**（新账 **#66**）

- 一人一台**共用宿主盘** ⇒ **谁写满拖垮全机**（本项目「最贵事故」那一类）。
- 取证：全仓 `xfs_quota` / 单 LV / 卷大小扫描 **0 命中**；只有按镜像字节估**台数**
  （`lib/tenant-capacity.sh`）与 `remove-tenant.sh` 里一次 `du -sh` **报告**（不是闸）。
  `38-ISOLATION-SPLIT.md` 自己写着"要按人配额" —— **写了，没做**。
- **要做的**：每卷 quota（例如 xfs project quota）+ 定期扫 volume 大小 + **满时明确拒**
  （不许静默写坏）。

### ⚠️ 3. **闲置回收的代码在、产品里零调用者**（新账 **#67**）

- `src/config.js` 的旋钮 `agentIdleEvictMs`（30 分钟）与 `src/agent-runtime.js` 的
  `evictIfNeeded()` **都在**，但**只有 `test/` 调它**；而租户单元是 `Restart=always`
  ⇒ **容器永不停**（只有 `remove-tenant.sh` 手工删）。
- ⇒ 结果：**没人用的那台照样占着内存**，而"回收"这件事看起来"已经做了"。

### ⚠️ 4. **监控只剩内存，而本机连内存都算不出**（新账 **#68**）

- 只有 `src/admission.js`（0.75 准入）与 `src/oom.js`（读 cgroup `memory.events`）。
- CPU / 磁盘 / inode / fd **没有任何采样或闸**；而本机**每一层 `memory.max` 都是 `max`**
  ⇒ 准入那条判据在本机**算不出来**（只能如实说"算不出判据"）。
- 手册 §十一 自己标着那些是「目标态（当前多数未实现）」——**标着不等于有人做**。

### ⚠️ 5. 容量上限是**策略常数**，不是按磁盘算的

- `max_tenants=8` 是人写的常数（这一条**已经**在 2026-09-23 的 #35 里还了：
  算式收进 `lib/tenant-capacity.sh`，`set-tenant-limit.sh` 能算能写）。
- 仍然要记住的两点：**算式按镜像字节估**，**不含卷/日志的增长**；
  实测物理上限与策略建议值**都远大于 8** ⇒ **要不要改是容量策略决定，不是技术缺陷**。

### ❌ 6. 手册里有"照着做会做错事"的句子（**已逐条改真**）

| 形状 | 有几处 | 后果 |
|---|---|---|
| **幽灵路由**（表里有、代码里没有） | **6 条** | 照它写客户端 ⇒ 404 |
| **幽灵字段**（`/api/say` 的 `conversationId`） | 1 个 | 两侧代码都没有，抄进客户端就是白发 |
| **幽灵事件**（`miniapp/load-failed` · `audit/notice`） | 2 个 | 等一个永远不会来的信号 |
| **在跑但没进表的路由** | **8 组** | 别处看不见它们，等于没有契约 |
| **在跑但没进表的事件** | **4 类**（`task/resumed` · `notice/urgent` · 三条墓碑 · `plan/updated`） | 同上 |
| **表里有、代码里没有的 UI 参数** | 3 处（内阴影 · 档位 `200ms` · 宽屏 `720`） | 照表去调，永远调不出效果 |
| **过期的数** | 甩的阈值（表 `650` / 代码 `700`） | 判据与实现两套口径 |
| **和别的节打架的行** | 水波那一行（特效早已按主人要求删掉） | 同一份手册两个答案 |

### 🔴 7. `59-USER-APPS.md` 说"授权/撤权工具是**故意没挂**的"

- **事实**：**它们是挂着的，而且有判据**（`app_grant` / `app_revoke`）。
- ⇒ 这条最阴：**照它做的人会去"补一个已经有的能力"**，多半就是**把能用的东西删掉**。
- **已经改的**：改成实话。

### ⚠️ 8. 账本里**同一件事有两种说法**

- `PROGRESS-HISTORY.md` §六：**8 个编号各有两行**（一行"没还"、一行"已经怎么还的"）：
  #19 · #23 · #30 · #33 · #35 · #42 · #46 · #47。
- ⇒ 已合成一条（只留"怎么还的"那一行），并加了一句说明。
- `00-PROGRESS.md` #49 / #58 的**措辞过期**（复核后改真，见下）。

### ⚠️ 9. 复核时**顺手查实的两件真事**（原来只是推测）

1. **#49（口令进过命令行）**：死 scope **只剩 1 个**（description 里仍带着那句字面量）；
   而 **user journal 里带口令的行实测 81 行**（7 行字面量 + 74 行"倒着写 + `rev`"，
   最早 2026-09-21、最晚当天）。⚠️ `journalctl --vacuum-*` 只能**整段时间**删，
   会连别的项目的日志一起删 ⇒ **我没动 journal**（如实记，不许偷偷"清理"）。
2. **#58（frp 隧道）**：**不是四条都手动** —— `frpc-dsh-u` 与 `frpc-finart-v` **有单元**；
   只有 `frpc-w`（线上壳）与 `frpc-apps`（制品口）是手动起的。
   ⇒ "重启机器之后不会自己回来"的是**那两条**，而它们**恰好就是最要紧的两条**。

## 六、这一批得出的一条纪律（**加进手册维护纪律**）

> **写"现状"的行，写的时候就对一次代码。**
>
> 手册里那些假话**不是文风问题**，是"抄进来的那一版当时是真的"。
> 而 L2（决策与判据）**唯一有约束力** ⇒ 它说错一句，下一个人就会照着做错一件事。
> ⇒ 对不上的东西写进 `docs/dev/`（L3 允许冷、允许旧），**别写进手册正文**。
