# 112 · 他自己那一份 = 活的工作区（**用户端没有"版本快照"这回事**）

> **主人 2026-09-26 定的产品形状**（原话）：
>
> *"小程序做好了，发布到桌面，这个对于用户自己用的应该是不需要这样的。因为他自己开发过程原则上就是对
> **当前这个版本**进行内容修改、功能修改等等……只不过它跟原来的那个版本不一样的话呢，对于市场来说
> 它可能是有更新，用户可以重新去更新，否则的话用户不需要走这条发布的通道。"*
>
> 同一天稍后他把整条边界也定死了（原话）：
>
> *"所谓的版本快照，只在市场中存在。不在用户端。用户 a 创建的，在他自己那里就是一段源代码部署；
> a 推到市场，就是一个包；用户 b 使用，实际上是把包拉下来变成源代码部署。用户 a 和用户 b 后续的
> 使用和部署，都是用的自己的，所以不需要什么压缩。最后，如果用户 a 做了新的，稳定了，他想发布，
> 则可以再次发布。b 也可以。"*
>
> ⇒ 一句话：**用户端 = 源代码部署（活的工作区）；"版本 / 快照 / 压缩"只属于"包"（市场那一侧）。**

---

## 一、这一批做了什么（一句话）

**桌面那一格（"我自己的小程序"）打开的是他正在改的那一间工作区**，不是某一版制品快照。
他（或助手在那个目录里）改完 ⇒ **屏幕上自己就是新的** —— 不要求"落一版"、不要求刷新。

```
用户端（他自己那一份）                     市场那一侧（别人 / 发布）
  workspaces/<id>/…  ← 活文件                published-apps/<authorHash>/<id>/versions/<n>/…
  /w/<id>/<rel>   ← 桌面那一格取的就是它      /a/<id>/<version>/<rel>  ← 一行没动
  app/workspace-changed（瞬态：该重取一次了）  app_publish / 血缘 / 回滚 /「发现」← 一行没动
```

**没有动的**：`app_publish` · 版本快照（`apps.js` 的 `versions/<n>/`）· 血缘 · 回滚 ·「发现」·
`/a/<id>/<version>/<rel>` 这条制品读法（**逐字没动**）。

## 二、边界（**主人定的，不是疏漏**）

> 形状与主人原话的逐字记录另有一份：`docs/dev/113-APP-SHAPE-LIVE.md`（父 agent 记的）。
> 这一节是它在**这一批代码上的落点**。

| | 用户端（活的工作区） | 包（市场那一侧） |
|---|---|---|
| 是什么 | **源代码部署**：`workspaces/<id>/` 里现在那些字节 | **一个包**：某一版**不可变**快照 |
| 怎么取 | `GET /w/<id>/<rel>`（签名 URL，**另一个原点**） | `GET /a/<id>/<version>/<rel>`（签名 URL，同一个原点） |
| 尺寸 / 文件数上限 | 🔴 **不查**（`apps.js` 里那几个上限**走不到这条路上**） | ✅ 查（单文件 / 整版 / 文件数，住 `apps.js`） |
| "变了"意味着 | **他自己屏幕上该重取一次**（`app/workspace-changed`，瞬态） | 别人可以来更新（那是发布那条通道的事） |

🔴 **"活路不查尺寸/文件数"有判据钉着**（V6）：同一个目录直接写盘（助手在那个目录里干活就是这个形状）
⇒ 活地址照给（V6 ①）；同一个目录**快照成包** ⇒ 当场拒（V6 ③，`/文件太多|太大/`）。
**变异**：把单文件上限加回 `AppWorkspaces.readLive` ⇒ V6 当场红（实测读数见 §五）。

⚠️ **`/api/apps` 里的 `version` 字段照旧给**（协议字段一旦上线就冻结，老客户端还在跑）——
但它**不再是"能看见新内容"的前提**：活地址那条路压根不看它。

## 三、活地址（`/w/`）怎么取

### 3.1 形状与签名

```
GET http://<apps 那个原点>/w/<id>/<rel>?u=<sub>&e=<到期>&s=<HMAC>
```

- 🔴 **签名照旧**：同一把键（`apps-signing.key`）· 同一个 TTL · 同一个 `signEntry`/`verifyEntry` ·
  **同样四道验**（格式 / 到期 / 绑的人 / 内容对得上）。
- 🔴 变的只有 payload 里"取的是哪一份"那一格：活地址用**哨兵 `live`**（不是版本号）。
  顺带得到**域分离**：制品 URL 的签名拿到活地址上过不了，反之亦然（V1 ⑤）。
- 🔴 **入口只有一个**：那一间清单里的 `entry`（默认 `index.html`）；认不出的 entry 退回 `index.html`
  （绝不拼一条取不到的路）。
- 🔴 **顺序**：验签 → **白名单** → 碰库（宿主/盒里）→ 读那一个文件。
  反例钉在 V2：白名单不过 / 验签不过 ⇒ **连库都不碰**（更别说去 dial 盒子）。
- `/api/apps` 的 `entryUrl` 改签 `/w/`（**字段语义没变**：仍是"打开这个 app 的那条签名 URL"）⇒
  **老客户端不用改**也能打开（它只认"这是个 http URL"）。

### 3.2 以盒子为准（B15 同一条规矩）

- **主人 / 单租户** ⇒ 本机那一间（`worlds.worldFor(sub).workspaces`）；
- **租户** ⇒ 经**现有隧道**读**他盒子里**那份（新内部口 `/internal/workspace-live`，
  与 `/internal/artifact` 同前缀、同信任模型：**只在可信 UDS 上接**，公网口 404 且不碰库）；
- 🔴 **盒子不通 ⇒ 如实 503**（"这个现在打不开，等会儿再试试。"）——
  **绝不**退回制品那一版，也**绝不**说"没这个文件"（他有，只是那台没应）。

### 3.3 bootstrap：老 app 没有工作区时

真机读数逼出来的：主人那三个 app（`dice` / `wenda` / `coin`）**早于"一个图标 = 一个工作区"**
（契约 83）就存在 ⇒ `data/workspaces/` **根本不存在**；而 `roomFor()` 又会在
"制品库里有、工作区还没建"时建一个**空目录**。

⇒ `readLiveApp()`（`src/workspace.js`）在**没有那一间清单**（`.hupo.json`）时，
从**当前那一版**镜像一次（`mirrorArtifactIntoWorkspace` —— 走的是同一条"装上来"的写路）。

🔴 **只此一次**：镜像完清单就在了 ⇒ 之后**绝不再拿旧版顶替**——
他删掉的文件就是删掉了（V1·补 ③ 钉着：删了 ⇒ 404，不许把旧版画回来）。
⚠️ 这一刀**只是 bootstrap**（把一个还没有工作区的老 app 领进来），**不是版本机制**。

## 四、白名单（**写清单：允许什么、拒绝什么**）

规则只有一处：`src/app-live.js` 的 `checkLiveRel()`（两侧共用；调用方两道都过）。

✅ **允许**：那一间工作区里（含子目录）**不以 `.` 开头**、且不在拒绝表里的文件。
入口只有一个（§3.1）。

❌ **拒绝**（一条都不许放行）：

| 拒什么 | 为什么 |
|---|---|
| `..` / 绝对路径 / 反斜杠 / 空段 / `.` / 控制字符 / 超长路径 | `checkRelPath` 那道（越界 = 把整台机器交出去） |
| **任何一段以 `.` 开头**：`.hupo.json` · `.data/` · `.exp/` · `.removed/` · `.tmp-*` | 那是**工作区自己的账 / 他的数据 / 经验 / 回收处 / 原子写的中间文件** —— 都不进沙箱 |
| `build/`（`LIVE_DENIED_SEGMENTS`） | 那不是页面的一部分（造它的时候中间产出的东西） |
| 解析之后跑出那一间目录（第二道） | 防符号链接 / `..` 那种绕过（`readLive` 里 `nodePath.resolve` 之后再比一次） |

**判据 V2**：`index.html` 与 `assets/app.js` 取得到；`../etc/passwd` · `.hupo.json` · `build/x.js`
⇒ 404 **且 resolver 一次都没被叫**（原样发路径，不让 `fetch` 把 `..` 规范化掉）。
**变异**：把两道白名单都拿掉 ⇒ `.hupo.json` 回 **200**（工作区自己的账被递进沙箱）⇒ 当场红。

## 五、"内容变了"那条通知（**只服务"正开着的人自己屏幕上要变"**）

⚠️ **它不是"发布"**：没有任何版本、没有血缘、别人那边什么都不动。

- 帧：`app/workspace-changed`，形状 `{type, id, at}`（**只有这三样**：没有签名 URL、没有内容）。
- **瞬态**（`Timeline.emitTransient`）：不占号、不落盘 ⇒ 重连/补发**不会**把它再送一遍
  （它不是"盘上的事实"，是"现在这一刻"）。
- **按焦点路由**：`Worlds.emitLiveChange()` 用那一间的 `ScopeView` 盖 `scopeId`，
  实时那一侧 `eventInScope(event, focus)` 筛 ⇒ **只有正开着这一间的那条连接收得到**
  （别的 app / 没开着的收不到）。
- **谁看着盘**（`createLiveWatcher` · `fs.watch` recursive）：
  🔴 他改那一份的**主要方式**是让助手在**那个目录里干活**（工作区就是 agent 的 cwd）——
  那是**直接的 `write` 系统调用**，不经过我们任何函数。⇒ 只能**看着盘**；
  挂在 `AppWorkspaces.write()` 上的话，"改完屏幕上就变"只对 `app_create` 那条路成立。
  - **宿主**：只看**数据真在本机**的那些人（主人 / 单租户）；租户那份在盒里，宿主看它等于看着一个假地方；
  - **盒里**：看自己那一份 ＋ **经既有那条 `notifyHost`** 报给宿主（用户那一屏连的是宿主）。
    ⚠️ `notifyHost` 原来是一次性的：连接恰好在重连就**丢了** ⇒ 现在**排队补发**
    （同 type+scope 只留最后一条，连上就 flush；`tenant-tunnel-agent.mjs`）。
  - 只有白名单里的路径会叫（`.hupo.json` / `build/` / 临时文件被写 ⇒ 一次都不叫）；
    同一间连着写 ⇒ 合一合（`LIVE_WATCH_DEBOUNCE_MS`）。
  - 🔴 `fs.watch` 的句柄 **`unref()`**：不许它撑住收工那一路（B38 的顺序一个字没动）。

**判据 V4**：真 `Worlds` ＋ 真 `fs.watch` ＋ **两条真 WS 连接**（一条 `scope=dice`、一条主线）：
直接写 `workspaces/dice/index.html` ⇒ 只有 dice 那条收到（**别的 app / 主线收不到**）；
那一帧 `seq === undefined` 且**不在** `timeline.readAll()` 里（瞬态）；
写 `.hupo.json` ⇒ 一个字节都不推。
**变异**：把实时那一侧的焦点路由拿掉（"见谁都发"）⇒ 别的连接也收到了那一帧 ⇒ 当场红。

## 六、客户端那半（**已接** —— 复用 `#159` 的换帧那套）

🔴 **与 `#159` 那条的分工**（别混成一条）：
- `app/update-available`：**持久**、带版本号 ⇒ 要判"比我新吗"、要按 `(id, 版本)` 去重；
- `app/workspace-changed`：**瞬态**、**不带版本号** ⇒ **不判版本**，收到就重取。

## 九、明确不做（**说砍就砍，不说"以后再说"**）

- **不做**：让沙箱页面自己加载同目录/子目录的**子资源**（CSP 仍是 `default-src 'none'` +
  `script-src 'unsafe-inline'`，一个字没放宽）。要子资源的话，页面得自己把签名串拼到 URL 上
  （服务端**每次请求都要签名**，绝不为了子资源开一个"不验签的读"）。
- **不做**：用户端的版本 / 快照 / 压缩 / 回滚（**主人定的**：那是"包"那一侧的事）。
- **不做**：把 `workspaces.write()` 上那几个上限（文件数 / 单文件 / 整版）也搬到活路 ——
  它们是**包**那一侧的规矩（V6 的对照那一半钉着）。
- **不做**：把"活地址"套到**别人发出来的包**上（市场那一侧照旧：`/a/<version>/` ＋ `app_publish`）。
