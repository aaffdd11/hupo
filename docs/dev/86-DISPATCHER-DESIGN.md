# 86 · 调度器深度规划（拟人对外 · 严谨对内 · 时间 · 思考强度 · 话题切换）

> 主人 2026-09-25：*"调度器非常关键。给用户看到的要非常拟人，实际干活的又要非常严谨。
> 调度的时候又要考虑时间消耗，长时间的要提醒用户等待，短时间的又需要快速回答，

> 十分的复杂。**要做好深度规划再继续。**"*

## 一、第一原则：**两张脸，一个字都不许串**

| | 对用户那张脸（拟人） | 对内那张脸（严谨） |
|---|---|---|
| 说话 | 短、具体、说人话；说清**在做什么 / 还要多久 / 卡在哪 / 你可以怎么办** | 状态机、票、编号、收口、超时、重试、审计 —— **一行都不许含糊** |
| 依据 | 只由**翻译层**从内部状态生成（`session-translate.js` / `notice.js` 那套是唯一的出口） | 事件流与落盘日志是唯一事实 |
| 禁止 | 内部词上屏（禁词闸）；**承诺做不到的事**；说完就静默（要做完、要有收口） | 猜、吞错、静默降级 |

🔴 **"拟人"不等于"讨好"**：**不许说"马上就好"而实际要十分钟**。拟人 = **像一个靠谱的人那样交代**，
不是像客服那样安抚。所以下面每一条时间承诺都必须**由实测依据算出来**（§三）。

## 二、内部那张脸：调度器到底在管什么

```
一个用户 = 一个调度器（手册 §四）
   ├─ 会话 A（= 一个图标/房间）：自己的 agent、自己的 cwd、自己的工作区
   ├─ 会话 B …
   └─ 一条可见时间线（一条日志、一套编号 · 05-DECISIONS P-l）
        ▲ 焦点（用户在"看"哪条）≠ 目标（这一句"要干"哪件）—— 两者可以不同
```

调度器要同时管五件事（**现在只有第 1 件**）：

| # | 管什么 | 现状 |
|---|---|---|
| 1 | **派活**：这句话归哪条会话（84-C 的焦点路由 + 转交）| 🚧 |
| 2 | **时间**：这活要多久、要不要先告诉用户等、超了怎么办（§三）| ❌ |
| 3 | **力气**：这活值多少思考强度（§四）| ❌（现在固定 `effort=low`）|
| 4 | **换题**：用户插问 / 打断 / 回来（§五）| ❌ |
| 5 | **收口**：每条会话的票、编号、失败重试、审计（已有，别弄坏）| ✅ |

## 三、时间维度（"要不要让他等"）

**分级（阈值住代码，不写进文档 —— 手册纪律）**：

| 档 | 典型 | 对用户说的那句 | 内部动作 |
|---|---|---|---|
| **快** | 一句话/查一下 | 直接答（不预告） | 不占票、不提醒 |
| **中** | 多步、要跑几个工具 | 「我去做，一会儿给你」 | 占票；超时线设短；**失败必收口** |
| **长** | 要写文件/多轮 | 「这个要几分钟，你可以先走，做完我叫你」 | 占票 + **进度通知**（已有的 `Notice` 通道）|
| **超长/后台** | 大活 | 「我放到后面做，做完叫你」 | 进"挂起"（§五），**不阻塞**用户 |

**"要多久"凭什么估（关键）**：
1. 🔴 **不许拿模型自报当依据**（它说"很快"没有约束力）；
2. 依据是**同类活的历史实测**（同类工具/同类步数的耗时分布 —— **第 90 分位**，不是平均）；
3. 冷启动（没历史）⇒ **按保守档说**（"要几分钟"），宁多说不少说；
4. **说完必须兑现**：到点了没做完 ⇒ **再报一次**（"比我说久了点，还在做"）——**这是信任的根**。

**预算**：每条会话有**时间预算**与**轮次预算**；超了**如实说 + 给三个选项**（继续等 / 先停下 / 转后台）。

## 四、力气维度（按难度调"思考强度"）

**不许让模型自己说自己难**（它要么都说难、要么都说简单）⇒ **用可观察的信号**：

| 信号 | 含义 |
|---|---|
| 用户怎么问 | "是什么" vs "帮我改/做一个"（写 > 读）|
| 需不需要工具、几种工具 | 纯答 < 只读 < 读+写 < 多工具 |
| 上一步的结果 | 失败/报错/自己说"我需要先看…" ⇒ 升档 |
| 计划长度 | 它先列了 5 步 ⇒ 升档 |
| 同类活的历史 | 同类失败的比率高 ⇒ 一开始就升档 |

**策略（先便宜后贵）**：默认低档 → 触发升档条件才升（升档要**留痕**：审计一行"为什么升"）。
**反向也要有**：简单活**不许**一开始就高档（省时省钱是产品指标，不是省钱癖）。
**可见性**：用户不需要知道档位；但**他等久了要能解释**（"我在仔细算这个"而不是"我卡住了"）。

## 五、话题切换（最容易做坏的一处）

**三种形态**（不许混为一谈）：

| 形态 | 用户想干什么 | 调度器该干 |
|---|---|---|
| **插问**（问一句别的再回来）| 不想丢掉正在跑的活 | 走**轻量通道**：**不打断**在飞的长活；答完给一句"刚才那件还在做" |
| **打断**（目标换了）| 那件不要了 | **显式取消** + 一句"我把刚才那件停了"（**不许静默丢**）|
| **并行新话题** | 两件都要 | 旧活进**挂起**（有票、有状态、可回来），新活开新会话 |

**两条硬规矩**：
1. 🔴 **一件活只有三种结局**：做完 / 被明确取消 / 挂着等。**没有"消失"**（宁多问一句）。
2. 🔴 **他回来时一定要能接上**：给一句"刚才那件：还在做 / 已停 / 做完了"，并且**在哪条会话里说得清**。

**焦点 ≠ 目标**：他**看着 A**、问的可能是 **B 的事** ⇒ 派活的依据是**内容 + 焦点**，不是焦点单独说了算（84-C 的默认规则要在这里再核一遍）。

## 六、落地顺序（每期都能单独验）

| 期 | 做什么 | 判据（真机样本为主）|
|---|---|---|
| **P1** | **时间分级 + 等待话术 + 兑现**（先不做预估，用保守档）| 长活：用户收到"要几分钟"· 超时再报一次 · **短活不许预告**（别啰嗦）|
| **P2** | **难度 → 思考强度**（先便宜后贵 + 升档留痕）| 易样本**不许**升档 · 难样本**能**升 · 每次升档审计可查 |
| **P3** | **话题切换三形态** | 插问不打断在飞的活 · 打断有"已停"一句 · 回来能接上 |
| **P4** | **耗时预估**（同类历史分布，第 90 分位）| 预估 vs 实测的偏差分布**如实报**；差太多要能看出来 |
| **P5** | 手册升版（`08-SPEC` 阈值总表 + 接口表；`05-DECISIONS` 记决策）| 两条防漂闸绿 |

## 七、明确**不做**的

1. **不许**为了让用户舒服而**说没发生的事**（"马上好"、"已经做完"）；
2. **不许**拿模型自报当时间/难度依据；
3. **不许**静默取消、静默丢活、静默降档；
4. **不许**新造"对用户说话"的通道（走 `Notice`/翻译层那一条出口）；
5. **不许**把阈值写进文档（住代码；文档只说"分级存在"）。
