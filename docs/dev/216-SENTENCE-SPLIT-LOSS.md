## 一、这段字是怎么从嘴里到框里的（现在的实现，逐段）

```
① 按下圆圈
     └ 客户端开麦克风（Web：AudioContext＋ScriptProcessor；安卓：AudioRecord 16k 单声道）
     └ 同时开一条 /api/asr 的连接（令牌走子协议，不进 URL）
     └ 🔴 音频**先在本机攒着**（`AsrOutbox`）：连接一握上手就按顺序补发
        ⇒ "开头那两个字没采到"那一族就是这么堵的（dev/197、198）

② 服务端 `src/asr.js`（这一跳：浏览器 ⇄ 我们）＋ `src/asr-doubao.js`（下一跳：我们 ⇄ 豆包）
     └ 浏览器说 `asr/start` ⇒ 去连豆包（**握上手才回 `asr/ready`**）
     └ 音频按 16k 单声道 PCM 送上去

③ 🔴 **豆包按"一句"回字，不是按整段**
     └ `result.text` / `result.utterances` **只管当前这一句**：说第二句时第一句就不在回话里
     └ 它还会**把同一句重新划一遍**（起点往前挪、区间叠着），字会越改越准

④ 🔴 **盒子里那台"接段"的机器**（`createSegmentTracker`，`src/asr-doubao.js`）
     └ 给每一句编一个**段号**（0、1、2…＝`done.length`），把说定的句子攒进 `done`
     └ 判"这是新的一句，还是同一句又准了一点"：
        · **音频时间**：区间叠着 ⇒ 同一句在改；接不上 ⇒ 换句
        · **字的相似度**（`looksLikeSame`：短的整段是长的开头，或共同前缀 ≥ 一半）
     └ 收尾时 `whole()` = 前面几段 ＋ 正在长的这一段（`asr/end` 带的就是它）

⑤ 客户端 `Hearing`（`lib/models/hearing_session.dart`）
     └ 收到 `asr/partial{这一句的字, 段号}` / `asr/final{…}` ⇒ **按段号存**：
        · 段号没变 ⇒ **换掉**那一段（同一句又准了一点）
        · 段号变了 ⇒ **接在后面**（新的一句）
     └ 框里显示 = `settled`（前面几轮）＋ 按段号拼起来的这一轮

⑥ 那个框（`VoiceBar`）显示的是控制器算好的 `composeText`
     └ `_voiceBase`（开录前框里已有的字）＋ `Hearing.text`
     └ 他一动手改字 ⇒ 语音从此不再往框里写（发他手上那份）

⑦ 按停 ⇒ 盒子发一条收尾（**整段**）⇒ 客户端把整段发出去（只发一次）
```

## 二、两处会丢字的地方（这一趟堵的就是它们）

### (1) 接段那一层：**"起点一样"被当成了"同一句"**（服务端）

原来那条判据是：

```js
(cur === '' && done.length > 0 && span && doneSpan)
  && (sameStart(doneSpan, span)                     // ← 起点一模一样：**单凭它就替换**
      || (overlaps(doneSpan, span) && looksLikeSame(...)))
```

🔴 `sameStart` 那一支**没看字**。而上游**重新划句**的时候，**新的一句完全可能报出
与上一句一样的起点**（区间还叠着）⇒ 被判成"上一句又准了一点" ⇒
**把上一段整段替换掉** ⇒ 客户端收到 `final{新的一句, 段号还是 0}` ⇒ 段号没变 ⇒
**把 0 号段换掉** ⇒ 框里那半句**当场没了**；收尾拼出来的整段也少了它。

**改法**：两样**都要** —— 时间上像同一句（起点一样 **或** 区间叠着）**而且**字像同一句：

```js
&& (sameStart(doneSpan, span) || overlaps(doneSpan, span))
&& looksLikeSame(done[done.length - 1], text)
```

判据 `test/asr-doubao.test.js` **D13**：新的一句报出同一个起点 ⇒ 必须另起一段、
`whole()` 里前半句一个都不许少；两条负向对照（同一句的修订照旧替换；区间没叠的两句照旧分开）。

### (2) 收一轮那一跳：**无条件相信服务端那条"整段"**（客户端）

`Hearing.roundDone()` 原来写的是 `settled: _joined(settled, s)` —— `s` 就是服务端那条整段。
它一旦短了（(1) 那种合并发生之后），**框里的字当场变短**。

**改法**：**接上去、再比长度**——

```dart
final joined = s.isEmpty ? base : _joined(settled, s);   // 接上（重叠那一段去掉、不重复）
final best = joined.length >= base.length ? joined : base; // 接完还短 ⇒ 用手上那份
```

⚠️ **不是简单的"两份挑长的"**：服务端那条整段有时只带**新那一句**，
"挑长的"会把新那一句丢掉（判据里专门留了这条负向对照）。
⇒ 结论那条不变量：**框里的字在一场里只许变长，不许变短**。

判据 `test/unit/hearing_session_test.dart`：收一轮时服务端那份少了前半句 ⇒ 手上那份留着；
两条负向对照（服务端更全 ⇒ 用它的；几轮接着攒前后都不丢）。

## 二·补 真正那一环：`cur` 被**整句覆盖**（2026-10-07 第二刀）

> 主人看过第一刀的报告之后：**"前面的句子还是会被清理。"** ⇒ 说明 §二(1)(2) 那两处
> **不是（至少不只是）根子**。接着往下读，真正的洞在这儿 ——

接段那台机器里，**"这是不是新的一句"**原来**先看时间**：

```js
const fresh = cur !== '' && (curSpan && span ? !overlaps(curSpan, span) : !looksLikeSame(cur, text));
if (fresh) { done.push(cur); ... }   // 只有"判定换句"才把上一句**收进** done
cur = text;                          // ← 🔴 无条件覆盖
```

🔴 **只要 `fresh` 判成 false，`cur` 就被直接覆盖，而上一句从来没进过 `done`。**

什么时候会误判成 false？**上游重新划句的时候，新的一句会报出与上一句叠着的区间**
（真读数那一族：`我们` 4382-5322 → `我们出去` 4522-4602 是**同一句的修订**；
但**新的一句**同样可能落在上一句的区间里）。那时：

```
上一句「今天天气不错。」→ cur（没进 done）
新一句「我想出去走走。」→ 区间叠着 ⇒ fresh=false ⇒ cur = 新一句   ← 上一句**没了**
        ⇒ 发给客户端的是 partial{新一句, index: 0}（**段号没变**）
        ⇒ 客户端按段号替换 ⇒ 框里那半句**当场消失**（收尾的整段也少了它）
```

**改法（两处，一主一防）**：

1. 🔴 **服务端：字说了算。** 换句与否的主判据改成**字**（`sameSentence`：
   一句包含另一句，或共同前缀够长）；**时间只能"补充说它换了"，不能反过来把
   "换句"否掉**：
   ```js
   const same = sameSentence(cur, text);
   const fresh = cur !== '' && (!same || (curSpan && span ? !overlaps(curSpan, span) : false));
   ```
   ⚠️ 保留一条退路：**一小截（≤3 个字）被换掉**算"说错了重来"（真帧里就有 `嗯` → `今天`），
   不然会把那一小截留成一句、后面接成"嗯今天…"。判据 **D14**（＋两条负向对照）。
2. 🔴 **客户端：覆盖是不可逆的，所以加一道防线。** 同一个段号又送来一份字时，
   **只有"像同一句"才允许覆盖**（`sameWords`）；否则**另起一段接在后面** ——
   段号被复用也**绝不会**把他说过的那句抹掉。判据在 `hearing_session_test.dart`。

**这两条合起来那句不变量**：**框里的字在一场里只许变长，不许变短**（服务端不丢 ＋ 客户端不覆盖）。
