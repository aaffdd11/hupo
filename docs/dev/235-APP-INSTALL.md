## 三、路上补的两处**真缺陷**（都不是这次新写的，是查出来的）

### 3.1 `net` / `tasks` 在"推进盒子"那条路上被丢掉了

`boxPushApp()` 发的 payload 里**没有 `net`**，盒子那侧 `POST /internal/app` 也**没收**它
⇒ 推/迁过去的 app 就算声明了联网，**盒里那一版清单里的 `net` 是空的**：两边都以为配好了，
到了屏幕上就是"取不到数据"。**声明是清单的一部分**，运输时丢它就是让制品在盒子那头变成另一样东西。

**改**：`src/apps-box.js` 的 payload、`src/server.js` 的 `POST /internal/app`、
`src/apps-migrate.js` 的 `migrateAppsToBox` 三处一起带上（形状仍由盒子自己的 `Apps.create()` 校验）。
判据：`test/apps-box.test.js` 的「迁移也把 net/tasks 带过去」。

### 3.2 小程序页面里两处"看一眼屏幕才发现"的

| 现象 | 根因 | 改法 |
|---|---|---|
| 整页发暗、点哪儿都没反应 | `.overlay{display:flex}` 是**作者样式**，盖住了浏览器默认的 `[hidden]{display:none}` ⇒ 那个空弹层**永远盖在页面上**（而 JS 一切正常） | 补 `.overlay[hidden]{display:none}` |
| 「交易通道」那一格显示"那台回了 200" | `/api/ctp/trade/status` 里的 `ok` 是**"交易网关自己 ok 不 ok"**（休市时就是 `false`），不是回执信封；页面把 `ok:false` 一律当失败 | 只有**带了原因**的 `ok:false`（`error`/`text`/`detail`）才算失败 |

⚠️ 这两条**纯逻辑闸一条都抓不到** —— 它们是"看一眼屏幕/读一遍原始读数"抓到的（`V13` 那条纪律）。

## 四、为什么必须新开一条「装一版」的路

**小程序库以盒子为准**（`B15`，主人 2026-09-25 拍板）：他桌面上那一格是**他盒子里**那一份。
而宿主**看不到**盒子的卷，也**不许**用 root 去写容器的卷（`81-HARNESS-ENTRY.md` §9.3）
⇒ 那条隧道**只有正在跑的那个服务手上有**。

原来能做到"推一版进去"的只有 `migrate-apps-to-box.mjs`（存量搬迁），它有两个毛病：
① **盒里已有同名时是"冲突不动"**（那是搬迁的规矩：不许盖掉他手里那份）⇒ **改不动**；
② 就是 §3.1 那个丢声明的毛病。

**现在多一条 `install`**（维护口 `apps-migrate.sock` 上第三个作业）：

```bash
node scripts/install-app-into-user.mjs apps-src/futures-trade --user u2 --apply
```

* 字节由**调用方**给（不再要求先往宿主那份旧库里放一份）；
* 落点仍是**盒子自己的 `Apps.create()`**（版本号/清单/权限/审计语义与助手在盒里造 app **逐字相同**）；
* 盒里已有同名 ⇒ **照装成新的一版**（老那一版原样留着，"版本不可变"在盒子那一侧仍成立）；
* 装完**读回来核**（逐个 sha256 + rootHash）——回执里 `verified:true` 才算到盒里了；
* **默认只看**（`--apply` 才动）；制品自查有 `errors` 时**拒装**（要照装得写 `--force`）。

⚠️ **权限那一层没变**：这条口是 `<data>/apps-migrate.sock`（**0600**、`deploy` 才能开）
—— 与 `push` 同一条授权模型（运营方工具），不是给了小程序或助手什么新能力。
