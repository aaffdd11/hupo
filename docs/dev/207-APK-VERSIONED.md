# 207 · **安装包的名字（和下载链接）带版本号**

> **主人原话**（2026-10-06 晚，接在"打完包"之后）：*「apk命名方式，我们也要用版本号来。
> 就是下载链接也要增加版本号。」*

---

## 一、改前改后

| | 改前 | 改后 |
|---|---|---|
| 发出去的文件 | `hupo-chat.apk`（**一个稳定名**，每次覆盖） | **`hupo-chat-<版本>.apk`**（如 `hupo-chat-2.0.0-702.apk`，**留档不覆盖**）＋ **同一份字节**再存一个稳定名 `hupo-chat.apk` |
| 首页那颗「下载安卓版」指哪 | 稳定名 | **带版本那一份**（构建期喂进去的 `--dart-define=HUPO_APK_NAME`） |
| 老客户端（已装在手机上的那些） | 指稳定名 | **照旧**（稳定名每次都刷新 ⇒ 那条链接不断） |

⚠️ **`+` 换成 `-`**：版本名是 `2.0.0+702`，文件名用 **`2.0.0-702`** —— `+` 在 URL 路径里虽然合法，
但各类下载器 / 代理 / 分享链对它的处理不一致；版本号一位不少。

---

## 二、那一处规则只住在一个地方（**四条**分工）

```
build-apk.sh     ← 🔴 唯一算名字的地方：APK_FILE="hupo-chat-${BUILD_NAME//+/-}.apk"
                   ① 写进 data/apk-build.json 的 "file"
                   ② --dart-define=HUPO_APK_NAME=$APK_FILE（喂进编译期）
publish-apk.sh   ← 从账里读 "file" 发那一份 ＋ 把稳定名也刷成同一份字节（两条链接都在线核）
deploy-web-v2.sh ← 从账里读 "file"，构建网页时喂同一个 define（首页那颗按钮指的就是它）
server_address.dart ← 只 read define（默认值 = 稳定名）
```

🔴 **为什么非要把换算收在一处**：三个脚本各拼一次 `+`→`-`，迟早会漂（这个项目里
"同一份数字两处"栽过很多次）。判据里有一条**负向对照**：`publish-apk.sh` / `deploy-web-v2.sh`
里**不许**再出现那处换算。

## 三、判据

| # | 判据 | 钉什么 |
|---|---|---|
| A | `test/unit/server_address_test.dart` 的 **④**（两条） | ① **默认值就是稳定名**（VM 判据、没喂 define 的构建 ⇒ 老行为一个字没变）＋ 带版本的路径能拼出一条**带版本**的绝对地址；② 三条脚本的分工：`build-apk.sh` 里看得见那处换算 ＋ 名字写进账里 ＋ 那条命令带着 define；`publish-apk.sh` 从账里读、**同时**刷稳定名、**两条链接都核**；`deploy-web-v2.sh` 也带着 define；🔴 **负向对照**：另外两个脚本里不许再出现那处换算 |
| B | 发布脚本自己那条闸（原来就有） | 真下载一遍：200 ＋ 类型 ＋ `attachment` ＋ **逐字节一样**（现在**两个名字各来一遍**） |
| C | 打包脚本自己那条闸（原来就有） | 包里找得到编译期那个地址 ＋ 签名是**正式那把**（不是 debug） |

**变异验证**：把 `--dart-define=HUPO_APK_NAME=` 从 `deploy-web-v2.sh` 里拿掉 ⇒ 判据 A-② 当场红；
在 `publish-apk.sh` 里再算一遍 `${BUILD_NAME//+/-}` ⇒ 负向对照那条红。

## 四·补 · **后来又打了一颗（`2.0.0+707`）＋ 一处要写清的事实**

* `2.0.0+707`（2026-10-07 00:03 打的）：与 `703` **功能完全一样** —— 那之间**客户端一个字节没改**
  （改的全是服务端那条"响应慢"的线：会话翻页 ＋ agent 预热 ＋ 文档）。两条链接**都核过**：
  `HEAD /hupo-chat-2.0.0-707.apk` → **200** · 55,258,998 字节 · sha256 `7ca40967f016…`；
  稳定名 `/hupo-chat.apk` → **200** · **同一份字节**（发布脚本两个名字各下载了一遍、各比了一次）。
* 🔴 **事实（免得以后有人验错了地方）**：**那颗「下载安卓版」按钮只在网页上**——
  `models/entry_screen.dart` 的 `landingFirstFor({required bool isWeb}) => isWeb`，
  而那个首页面**在安卓包里被整棵编译掉了** ⇒ 安卓包的 `libapp.so` 里**根本没有 `.apk` 这个字**。
  ⇒ **要验"链接里带版本号"，验的是线上网页产物**（`main.<指纹>.dart.js` 里找得到
  `hupo-chat-<版本>.apk`），**不是**安卓包。
  （对照：`w.stalkerai.cn` / `bearer` / `/api/say` 这些字在安卓包里都找得到 —— 所以
   "搜不到 `.apk`" 不是搜法的问题，是那一段真的不在包里。）
* ⚠️ 安卓包里**该有的那两样**仍然每次都真读一遍：暂停那句（`现在不做语义检查`，UTF-16LE）
  ＋ 预热那几个符号（`warmHearing` / `warmNativeHearing` / `_takeWarm`）。

## 五、如实说

* ⚠️ **老客户端不会被改**：装在他手机上的那些（`+692`/`+700`/`+702`）里那个常量还是
  `/hupo-chat.apk` ⇒ 它们那颗按钮**照旧能下到最新那一颗**（稳定名每次发布都刷新）。
  要它们也显示带版本的链接，得**再装一次**新包。
* ⚠️ **网页那颗按钮**里的版本号是"**部署网页那一刻，线上是哪一版包**"。之后再打新包、
  而没重新部署网页 ⇒ 那颗按钮还指着**上一版**（那一份文件仍在，点得下去、也能装上）。
  想要它立刻指到最新 ⇒ 跑一次 `scripts/deploy-web-v2.sh`。
* ⚠️ **带版本的那些是留档，会越攒越多**（每颗 55 MB）。要清是另一件事（`publish-apk.sh`
  只负责发，不负责删）。
* ⚠️ 1.0 那个包（`hupo.apk`）**原样不动**（老链接不许 404、也不许被 2.0 顶掉）。

## ★ 2026-10-07 补：**断点续传**（主人：*"下载速度比较慢，我看是否还不支持断点续传？"*）

**查出来的事实**：以前那条静态路**根本不看 `Range`** —— 一律 `200` ＋ 整个文件
⇒ 网断一下就**从头下**（55 MB 的包尤其疼）。真读数（改前）：`curl -r 0-1023` 回的是
`HTTP/2 200` ＋ `content-length: 55258998`（整份），也没有 `accept-ranges`。

**改法**（`src/server.js` 的静态那一段 ＋ 一个纯函数 `parseRange`）：

* 单段 `Range` ⇒ **`206` ＋ `Content-Range`**；**所有**静态回话都带 `accept-ranges: bytes`；
* `bytes=a-b` / `bytes=a-` / `bytes=-n`（最后 n 个）都认；**多段**（带逗号）按标准**忽略**、
  回整份 `200`；越界 ⇒ **`416` ＋ `bytes */总长`**；
* 🔴 `If-Range` 对不上（文件换过一代）⇒ **回整份**（绝不把两代字节拼在一起）；
* ⚠️ **预压那一份（br/gz）不参与续传**：`Range` 是对**字节**说的，有人要 Range 时
  **退回原文件**（identity），这样"第几到第几字节"才说得清；
* 判据：`test/server.test.js`（206 ＋ 那一段字节 · 尾巴 · 416 · 多段回整份 · `If-Range` 过期回整份）。

**实测**：本机 `206 Partial Content` ＋ `accept-ranges: bytes` ✓；**公网也回 `HTTP/2 206`** ✓
（nginx 那一层没吃掉它）。

## 速度慢在哪（同一颗包，各 10 秒窗口）

| 从哪下 | 速度 | 55 MB 要多久 |
|---|---|---|
| **本机**（127.0.0.1:8020） | **400 MB/s** | 不到 1 秒 |
| **公网**（w.stalkerai.cn，经 nginx ＋ 隧道） | **209 KB/s** | **约 4 分半** |

⇒ **这台机器不慢，瓶颈在公网那一段。** 能立刻做的只有一件：**让包变小** ——
这一颗是**三合一**（`x86_64 18.3 MB ＋ arm64-v8a 17.2 MB ＋ armeabi-v7a 14.7 MB`），
而 Flutter 那条命令**没写 `--target-platform`** ⇒ 三个 ABI 全打进一个包。
**只打 `android-arm64`** ⇒ 包大约 **20 MB** ⇒ 同样这条隧道下**约 1 分半**。
⚠️ 代价：**老的 32 位手机装不上**（他的手机是 64 位）—— 这是产品取舍，**要问过他**。
