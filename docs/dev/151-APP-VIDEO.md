## 一、它为什么和图片**不是**同一条形状

| | 图片（`image.js`） | 视频（这一份） |
|---|---|---|
| 上游 | 同步：要一张，几十秒，**当场回地址** | **异步**：建任务 ⇒ 几十秒到几分钟 ⇒ 查状态 |
| 工具那一下 | 一次调用拿到图 | 一次调用只拿到**任务号** |
| 结果怎么回来 | 模型把地址放进回话里 | **壳那一侧的巡场**收回来、**说进他问的那一间** |
| 钱 | 一张的钱 | **贵得多** ⇒ 额度更硬（一次只许一条在飞） |

⇒ 所以这一片多了两样东西：**一本账**（`video-tasks.js` 的 `VideoBook`）与**一个巡场**
（`createVideoRunner`，`serve.js` 里起的那个定时器）。

## 二、形状（一条一条）

| 那一刻 | 发生什么 |
|---|---|
| **他明说** | 认得出"要一段视频"的说法才放行（`asksToMakeVideo`：`ASK ＋ MAKE ＋ VIDEO` 或祈使句开头；**保守默认**，认不出就拒并告诉他该怎么说） |
| **工具** | `mcp__video__video_generate`（新的一条 MCP：`mcp-video-server.mjs` ＋ 能力层里 `mcp-video` 那一块）—— 它**不写盘、不花钱**，只经**同一条域套接字**把请求递给服务端 |
| **服务端** | `apps-socket.js` 的 `video` op：**闸** → `ctx.startVideo`（`video-use.js`）→ 建任务（`createVideoTask`）→ **记进账**（`VideoBook`）→ 回任务号 |
| **记账** | 用量账本里 **`kind: 'video'` ＋ `videos: 1`**（交出去一段算一笔；钱是按段花的） |
| **巡场** | 每 `TICK_MS`（10 秒）看一遍在飞的那几条：`succeeded` ⇒ **往他问的那一间说一句带地址**；`failed/cancelled/expired` ⇒ 如实说一句；`queued/running/unknown` ⇒ **一句都不说**（不许每 10 秒喊一次）；等过头（`MAX_WAIT_MS`，15 分钟）⇒ 放下 ＋ 说"还在做" |
| **界面上** | 回话里带视频地址 ⇒ 气泡里画一个**能点的框**（`video_links.dart` 认地址；`bubbles.dart` 的 `_videoRows`）；**不自动播**（几十 MB，自己加载 = 花他流量），点开交给系统打开 |
| **限额** | 🔴 **同一个人一次只许一条在飞**（`MAX_PENDING_PER_USER = 1`；多了当场拒并告诉他"上一段还在做"）· 一次 tick 最多查 `MAX_CHECKS_PER_TICK` 条 · 等的时间有上限 |
| **重启** | 账在盘上（`<他那一格>/video-tasks.json`，0600、原子写）⇒ **重启之后还认得那几条在飞的**（不然他花了钱、我们却忘了去收） |

🔴 **`safeVideoTaskId`**（只认 `[A-Za-z0-9._-]`，长度也夹住）**是安全边界**：那个 id 会拼进
"查任务"那条 URL ⇒ 上游回一个带 `/` 或空格的 id 就等于让我们去请求**另一个地址**。
形状不认 ⇒ **连请求都不发**（判据 V9）。

* 🔴 **真跑一次还没有**（缺他那把钥匙）—— 这一片到今天为止是"**代码 ＋ 判据 ＋ 部署**"，
  **没有**一张真生成的视频。⚠️ 不许把这一片说成"验过了"。
* **取消 / 删除任务**没做（上游有那条口）：现在只能等它自己好、或者等我们放下它。
* **参数是写死的三个**（`--ratio` / `--duration` / `--watermark`）：他想说"竖屏 9:16、10 秒"
  现在还得模型自己往里塞 —— 以后要么给工具加参数，要么让工具读他原话里的要求。
* **不在聊天里直接播**（点开交给系统）：网页那一侧要内嵌播放得引一个播放器（那是另一件事）。
* **一段在飞的时候不许再要一段**：这是**钱的闸**，不是技术限制（上游允许排队）。
* **迷你程序（小程序）那一侧没有视频能力**：这一片是"聊天里让他做一段视频"，
  不是小程序的第六条能力（要加得单独谈）。
