## 二、🔴 改之前实测到的两处不一致

量的方法：`ChatFloater` 摆在 390 宽的一条里（`test/widget/voice_buttons_test.dart`
的泵法），把**每一颗**的命中格与**那一块看得见的面**（`_auxFace` 那个 `Container`）
的矩形都打出来。读数：

| 项 | 改前 | 改后 |
|---|---|---|
| 端点可见留白（左 / 右） | **2 / 10** ❌ | **10 / 10** ✅ |
| 左列上块（＝「清单」的面） | `515..545` | `522..552` |
| 左列下块（＝「键盘」的面） | `563..593` | `556..586` |
| 右列上块（＝「展开」的面） | `522..552` | `522..552` |
| 右列下块（＝「播放」的面） | `556..586` | `556..586` |
| 左列两块之间的缝 | **18** ❌ | **4** ✅ |
| 右列两块之间的缝 | 4 | 4 |
| 左列两块合起来的高度 | **78** ❌ | **64** ✅（= 那颗圆圈的直径） |
| 四块的面 / 命中格 | 40×30 / 44×44 | 一样（**没动**） |

⇒ 两处不一样，**都不是"某一次写错了"，是两边各按各的规矩长出来的**：

1. **左右留白**：右边那一列后面一直挂着一个 `SizedBox(width: d.gapS)`，
   而左边那列**紧贴这一行的左端**（面在自己那一格里还要内缩 2）
   ⇒ 左端 **2**、右端 **2 + 8 = 10**。
2. **上下位**：右列两块是**贴内沿**摆的（上块贴下沿、下块贴上沿）⇒ 缝 4、
   合起来 64 —— 那正是 2026-10-05 主人定的"两块合起来跟录音那颗圆圈一样高"；
   而左列两块是各自**居中**摆的 ⇒ 缝 18、合起来 78。
   ⇒ 屏幕上左边那两颗比右边那两颗**散得开**，四颗的上沿/下沿没有一条对得上。

## 三、改成什么样（两条，都在同一个文件里）

| # | 改什么 | 怎么改 |
|---|---|---|
| ① | **左右留白一致** | 左列**前面也加一个** `SizedBox(width: d.gapS)`（右端那个不动）⇒ 两端各 8，再加上面那 2px 的内缩 ⇒ **两端都是 10** |
| ② | **四颗的上下位一致** | 左列两块**跟右列同一个规矩**：上块的面**贴下沿**、下块的面**贴上沿** ⇒ 四块的面逐像素对齐（上沿 `522`、下沿 `586`），两列的缝都是 4，两列各自 64 |

⚠️ **只留白与摆位在动**：面的大小（40×30）、圆角（9）、那一圈琥珀（`accent` / 1.5）、
底色（纸的白 / 开着变琥珀）、图形（墨色 18）、命中格（44×44）**一个像素都没改**
—— "风格统一"那一半本来就已经是一套（四颗都走 `_auxFace`）。

### 3.1 🔴 顺手把"四颗"收成一个出处

原来四颗按钮**各自拼一遍**同一套壳子（`Tooltip` ＋ `Semantics` ＋ `TextButton`
＋ `SizedBox` ＋ `Align` ＋ `_auxFace`，四份），差别就在"面贴着哪条内沿"。
这次的毛病（左右两列摆法不一样）正是这种"四份长得像但各写各的"必然会出的东西
⇒ 新增 **`_auxButton(...)`**：四颗**一律从它出去**，只传
`alignBottom`（上块 / 下块）与那一点各不相同的部分（key / tooltip / 读屏名 / 图形 / 是否亮着）。
以后再加一颗，**不可能又长出一个样子**。

⚠️ 一处例外如实写下来：**只有一颗**的时候（判据里会出现"上层只给了清单、没给键盘"）
面**居中**（`centred: true`，与那颗圆圈同心）—— 成对时一律走"往中间靠"那条。
生产里两颗都在（`chat_screen` 两个都传），这条只服务"单看浮窗"的那些判据。

## 四、判据

- `test/widget/voice_buttons_test.dart` **⑥（新）**：① 四块的面**同一个尺寸**；
  ② 左列的上下沿 == 右列的上下沿（**逐像素**，0.5 容差）；③ 两列的缝都是 `voiceAuxGap`；
  ④ 最上一块 / 最下一块与那颗圆圈（`voiceCircleBox`）**上下齐平**；
  ⑤ 两端可见留白**相等**（带"量得出东西"的负向对照：`leftGap > 0`）。
- 🔴 **变异验证**（判据不是空转）：把「清单」那颗改回 **居中** ⇒ 当场红
  （`上排两颗的上沿没对齐（515.0 vs 522.0）`）；把左端那个 `gapS` 拿掉 ⇒ 当场红
  （`两端留白不等：左 2.0 / 右 10.0`）。两处都逐字节还原过。
- 原有那几条照旧绿：④"打开聊天窗口那一下圆圈一个像素都不许动" ·
  ⑤"那一列两块合起来 = 录音那颗的高度" · `keyboard_button_test`（键盘在清单下面、
  左对齐、命中区 ≥44） · `work_list_test`（清单在最左）。
