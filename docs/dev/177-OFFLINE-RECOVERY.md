# 177 · 网回来之后，那条"没发出去"自己走掉（并且自己重发一次）

> **主人 2026-10-04 原话**：
> *「网没通，这条没发出去，这个状态在恢复后依然还在。」*

---

## 一、原来是坏的（两条都坏）

那条流的状态一变，客户端只处理一种情况（`chat_controller.dart` 的 `states.listen`）：

```dart
_conn = st;
if (st == ConnState.unauthorized) { ... }   // 只有"令牌不行"这一种
```

⇒ **连回来（`connected`）什么都没做**：

| 症状 | 为什么 |
|---|---|
| 顶上一直挂着「**网没通，这条没发出去**」 | `_lastError` 只在 `unauthorized` 那一支里被动过 ⇒ 网回来了它还在（**屏幕上说假话**） |
| 那一条一直写着「**没发出去**」 | 没有任何东西会在连回来时替他把那一句再走一次 —— 只能他自己去按「重发」 |

`SayNetworkError` 那条分支留下的就是这两样（`_lastError = '网没通，这条没发出去'` ＋ 那条落 `failed`）。

---

## 二、改成什么样（**客户端一处**）

`lib/services/chat_controller.dart`：

1. **记下来"哪几句是因为网没通才没发出去的"**：`final Set<String> _networkFailed`，
   只有 `SayNetworkError()` 那一支把 `messageId` 放进去。
   ⚠️ **别的失败一概不放**：忙不过来（`SayBusy`）／太频繁（`SayLocked`）／被拒（`SayRejected`）／
   反问（`SayAsk`）／登录过期 —— **那不是网的事**。
2. **连回来那一下**（`st == ConnState.connected`）：
   - 如果顶上那句是"网没通"这一类（`_lastErrorIsNetwork`）⇒ **清掉**（它已经不真了）；
   - `unawaited(_retryNetworkFailed())` —— 把那一串**自己再走一次**（一次一条，别在刚连上那一瞬间打一串）。
3. 发成功了（`SayOk`）⇒ 把这条从那一串里去掉，并顺手撤掉那句陈旧的"网没通"。
4. 退出登录 / 换人 ⇒ 那一串跟着这一份世界一起清掉。

### 🔴 为什么**敢**自动重发

重发走的是**同一个 `messageId`**，而服务端按它**幂等**（重复那一次回 `duplicate`，
**不落盘、不重放**）⇒ **不会让 agent 干两遍**。
这条性质是既有的（`resend()` 抬头上那句注释就写着"必须用同一个 messageId"），
这一次只是**在网回来的那一刻替他把这件事做了**。

## 四、没动的（明说）

- **`failed` 那一档本身没动**：它仍旧**有自己的长相 ＋ 重发入口**（`03-DEVELOPMENT.md` 那一行），
  只是"网没通"这一种会在网回来时**自己先试一次**。
- **令牌照旧只在 401 时清**（B1 那条修法一个字没动）—— 这一批**只清那句错误话**，不碰令牌。
- **服务端一个字没动**（幂等本来就是它那边的性质）。
- ⚠️ **只重发"网没通"这一种**：别的失败仍旧要他自己按「重发」——
  那几种重试要么白打服务端，要么根本没意义。
