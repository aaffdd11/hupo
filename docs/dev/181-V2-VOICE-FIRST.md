## 一、一句话：要加的是"**听懂那一层**"，不是一个新的输入框

```
今天：  按下麦 → 转文字 → 【输入框】 ——（他按发送）→  助手
V2.0：  按下麦 → 转文字 → 【听懂那一层：读一遍 / 不确定就问 / 补顺】
                                      ↓ 差不多了
                              【临时那一格：我听到的是「…」】→ 自动发出 → 助手
```

* **输入框收起来**（不在屏幕上占位置了）；原来那一条横条上站着的是**"临时那一格"**。
* **它不是替用户写话**，是**把他说的话听清、问清、理顺** —— 然后**原话（理顺版）**发出去。
* **不吹毛求疵**：意思对、读得通 ⇒ 走。**最多问两轮**，问不完就按已经确定的那一份发，
  并在屏幕上如实说"我按这个发了，不对你说一声"。

## 三、听懂那一层怎么工作（**它的输入输出只有四样**）

新增一条口（盒子里）：`POST /api/hear` —— **只听他自己的话**（登录态 ＋ 只读服务端自己记的
他这一轮说的那句，与 `D4.25` 那条闸同一条纪律：请求里带什么都不看）。

它交给模型的是一个**很短的任务**，拿回来的是一段**结构化的东西**：

| 字段 | 是什么 | 例子 |
|---|---|---|
| `heard` | 我听到的（**理顺版**：补标点、顺语序，**不加意思**） | 「帮我把上周的账整理一下。」 |
| `ask` | 要问回去的一句（**没有 = 不用问**） | 「是**上周**还是**上个月**？」 |
| `fact` | 我在不确定什么（**给我们看，不给他看**：它是内部字段） | `time-range-ambiguous` |
| `scene` | 这一句像是要干什么（要小程序 / 干活 / 就是聊天） | `make-app` |

**规则（这一层的地基，写死）**：

1. 🔴 **只许"听他说的"，不许"替他多要"**：`heard` 里**不许出现他没说过的要求**。
   想要更多（"要不要存数据？要不要每天提醒？"）**必须走 `ask` 问出来**，
   **他答了**才算他的意思（这一条保住 `D4.25`"他明说才许写"那条闸的意义）。
2. **一次问一件**（不摆一串问题）；问的话**要能在电话里听懂**（短句、不含内部词）。
3. **最多两轮**；两轮还没问全 ⇒ 用当前这份发，并如实说一句。
4. **`heard` 为空 / 模型答得不成形 / 代理不通** ⇒ **不硬发**：屏幕上留一句
   「这句我没听清，你再说一遍」，把已听到的那半留着（`AGENTS.md`：不许安静地假成功）。
5. **`scene = make-app`** ⇒ 允许它多问**一点点**（这正是主人说的"多问一点点"），
   但仍然一次一件、最多两轮。

## 四、界面上长什么样（**输入框那一格换成什么**）

| 状态 | 屏幕上 | 声音 |
|---|---|---|
| 待命 | 那一格是**一颗大麦**（今天那颗的样子）＋ 一句"说点什么" | —— |
| 正在听 | 电平轴 ＋「听得到声音」＋ 走时（今天就有） | —— |
| 正在听懂 | 那一格变成**流式的文字**（他说的话一行行长出来，**边听边显示**） | —— |
| 它要问一句 | 那句话**流式显示**在那一格上 ＋ **同时念出来** | 语音提问 |
| 他答完 ⇒ 差不多了 | 那一格显示**最终那一份**「我听到的是：…」，**停半拍**（见 §六 第三问），然后**自动发送**（那一格随即收成平时那条时间线） | 可以一并念一遍 |
| 听不清 / 说不清 | 那一格留着那句话 ＋ 一颗**「就这样发」**（给他的兜底；**按得了字的人**与按不了字的人都按得动按钮） | 念那一句 |

⚠️ **不许出现按不动的东西**（`AGENTS.md` §六 第 4 条）：念不出来的时候（手机上、没配语音）
**不画那颗喇叭**，只出文字，并用一句人话说清"这台现在念不出来"。

## 六、要你拍板的三处（**一件一件来，先答第一问**）

| # | 问题 | 选 | 代价 |
|---|---|---|---|
| **一** | **手机上要不要"它会说话"**（今天只有网页能出声；安卓包念不出来） | **甲：用手机自带的声音**（系统 TTS 插件，离线、不花钱、音色是手机那个）｜**乙：用火山那套语音合成**（要开通、要挑音色、按量计费，音色比系统好听）｜**丙：手机上先不念**（只有文字问，界面如实说"这台念不出来"） | 甲＝装一个插件；乙＝你要去后台开通 + 一把新凭据；丙＝手机上"语音提问"这半就是缺的 |
| **二** | **打字那条路留不留** | **甲：留着**（键盘档还是输入框，语音档才是这一套）｜**乙：一起收掉**（屏幕上只剩麦） | 乙更接近你说的"纯语音"，但**麦克风坏了 / 环境太吵**时他没有任何退路 |
| **三** | **自动发送前要不要那半拍** | **甲：要**（最终那一份显示约 1 秒再发，他这半拍里能喊停）｜**乙：不要**（显示完立刻发） | 甲慢半拍；乙快，但**听错了也照样发出去**（发出去就是真干活） |

⚠️ **我建议**（只是建议，你说了算）：**一＝甲**（先用手机自带的，不花钱、先跑起来；
哪天真嫌音色不好再开乙）· **二＝甲**（打字留着当退路，语音档才是新形状）· **三＝甲**（半拍）。

## 七、如实说（方案里我不确定的）

* ⚠️ **每一轮要多久**：听写（今天就有）＋ 一次不吃思考的模型（实测过 `app-ask` 那条路，
  一般是**一到两秒**）＋ 念出来（设备合成器，几乎立刻）。⇒ **一轮大约两三秒**；
  两轮就是五六秒。**这是"听完先问一句"的固有代价**，不是没优化好。
* ⚠️ **"听懂"这件事本身会出错**：模型可能把"不要提醒我"听成"要提醒我"。
  ⇒ 上面那三条规则（不许替他多要 / 问出来 / 显示最终稿 ＋ 半拍）就是为了让**错了也看得见**。
* ⚠️ **它跟"限制档"等等都不搭界**：这一层**只说话、不动手**（它没有工具、没有手）。
* ⚠️ **它跟 `D4.25`"他明说才许写"的关系**：发出去的仍然是他**自己那句话**（理顺版），
  只是中间多了"问一句、他答一句"——**"明说"这条线一个字没松**（助手自己发起的那一轮照旧拒）。
* ⚠️ **没排在 V2.0 第一件里的**（但迟早要）：**"一直开着听"**（不用按麦）—— 那涉及一直录音、
  误触发、耗电，是另一件事；**换音色 / 换声音品牌**；**多语言**。
