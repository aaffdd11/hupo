# 83 · 一个图标 = 一个工作区 = 一条对话（小程序与工作区对齐）

> 主人 2026-09-25：*"当我做一个 app 的时候，本质上是一个工作区。这一点你一定要确保。
> 那么你制作小程序，就是在那个工作区里面开。"* → *"我同意你的，而且**对话也是分家的**。"*

---

## 一、依据（**这不是新概念，是手册早就定下的，只是没接上**）

`docs/handbook/02-ARCHITECTURE.md` §2.1 原文：

```
/data/                          ← 容器内，这个用户的整个世界
  main/                         ← 主目录（顶层对话的 workspace root）
  workspaces/
    <scope-name>/               ← 子工作区（= 桌面上的一个图标）
  hupo/                         ← hupo 的地盘，不在任何 workspace root 里
    apps/                       ← 生成的小程序制品
$DSH_HOME/                      ← 这份专属 DSH 的（会话历史按 root 分区）
```

三条硬规则（§2.2）**一个字都不许动**：

1. **主目录 root 不许是 home**（否则 `~/.dsh/.credentials.yaml`、`~/.ssh/id_rsa` 会被读到、`~/.bashrc` 会被写到）；
2. **主目录 root 不许包含 `workspaces/`**（必须**平行** ⇒ 主目录的 agent 写不进子工作区）；
3. **每个用户一份 `DSH_HOME`**（会话存储的键是**绝对路径** ⇒ 同名工作区会撞进同一份记忆）。

⇒ **`workspaces/<scope-name>` 那句括号就是主人这句话**："= 桌面上的一个图标"。

## 二、今天实际是什么样（进盒子看的，2026-09-24，u2 那台）

| 事实 | 说明 |
|---|---|
| `/data/workspaces` | **空的** —— 没有任何东西在建子工作区 |
| `/data/main/city-weather/index.html` | **6.7KB 的单文件小程序躺在主目录里**，没有清单 |
| `/data/hupo/apps` | **不存在**（制品库空）|
| 事件里的 `scopeId` | **恒为 `'main'`**（`worlds.js`），timeline 也只有一个 `'main'` |
| agent 的 cwd | 每人一个（`<dir>/main`），**不随 app 变** |

⇒ **今天"做一个小程序"= agent 在主目录里建了个文件夹**：既没进子工作区，也没进制品库，对话也全糊在一条里。

## 三、契约（目标态）

| # | 是什么 | 怎么算对 |
|---|---|---|
| 1 | **一个图标 = 一个子工作区**：`/data/workspaces/<scope>/`（scope = 那个 app 的 id） | 源码与产物都住它里面 |
| 2 | **主线仍在 `/data/main`**：不属于任何 app 的对话（琥珀那个默认房间） | 不受影响 |
| 3 | 🔴 **对话按 scope 分家**：事件带 `scopeId`（原来是恒 `'main'`）；每个 scope 有**自己的 DSH 会话**（cwd = 那个工作区 ⇒ DSH 自己按工作区分组，界面也按工作区分） | 在 A 房间里说的话，B 房间**看不到** |
| 4 | **建工作区由服务端那一刀做**（不靠模型记得）：造 app 的第一步 = `mkdir /data/workspaces/<scope>` ＋ 登记，**再把这一轮的 cwd 换过去** | 反例：模型忘了建 ⇒ 文件又躺回主目录 |
| 5 | **制品库是快照**：`/data/hupo/apps/<id>/versions/<n>/` 从工作区**拷产物**进去交清单与版本号；它**不是**干活的地方 | 改了不发布 ⇒ 线上不变 |
| 6 | **迁移**：`/data/main/city-weather/` → `/data/workspaces/city-weather/`（内容不变），并补登记成一个 app | 搬完主目录里**不许**再有它 |
| 7 | 三条硬规则原样（见 §一） | 有判据（见 §四 A7）|

## 四、判据（每条都要能反着验）

| # | 判据 | 反例（必须红）|
|---|---|---|
| A1 | 造一个 app ⇒ 它的文件**只**出现在它自己的工作区里 | 写进 `/data/main` ⇒ 红 |
| A2 | 每个 scope 有**自己的** DSH 会话（按工作区分组） | 两个 app 落进同一个 slug ⇒ 红 |
| A3 | **对话分家**：A 房间说的一句，B 房间的流里**不许出现** | 共用一个 timeline ⇒ 红 |
| A4 | 主线（`main`）**不受影响**（老对话还在、还能说） | 分了家把主线弄坏 ⇒ 红 |
| A5 | 制品库那份是**快照**：工作区改了没发布 ⇒ 线上小程序**不变**；发布了 ⇒ 变 | 直接线上读工作区 ⇒ 红 |
| A6 | 迁移后 `city-weather` 内容**逐字节不变**，且它有了自己的 scope | 搬丢了 / 主目录里还有 ⇒ 红 |
| A7 | 三条硬规则仍在（root 不是 home、main 与 workspaces 平行、每人一份 DSH_HOME） | 把 workspaces 挪进 main ⇒ 红 |

## 五、⚠️ 一处要主人定的（UX）

**"进去某个 app 的对话"怎么进？**

| 选项 | 形状 | 代价 |
|---|---|---|
| **甲** | **跟着图标走**：打开某个小程序时，**下面那条聊天就是它的对话**（在哪个房间说话，就是跟哪个房间聊） | App 要记住"当前房间"；切图标 = 切对话 |
| **乙** | **一个会话列表**（主对话 ＋ 每个图标一条），点哪条进哪条 | 多一层界面；与"桌面即房间"的直觉稍远 |
| **丙** | 两者都要（甲为主，乙当总览） | 做两遍 |
