# 217 · 临时的"帧形状"诊断（只记数字、不记正文）

> 主人 2026-10-07 连着报了三次"字不对"，而我连着几刀都是**猜**的。
> ⇒ 先在服务端加一条**只看形状**的日志，把"上游每一帧到底是什么形状"量出来。

## 一、它记什么（**一个字的正文都不记**）

`src/asr-doubao.js` 里，每收到一帧上游回话就记一行：

```
asr 帧形状 #12 · 3400ms · 字 27 · 与上一帧共同开头 21 · 含上一帧 是 · 被上一帧含 否 · 段 1 · 定稿 否 · 起点 0
```

| 字段 | 它回答什么 |
|---|---|
| `字 N` | 这一帧带了多少字 |
| `与上一帧共同开头 K` | 与上一帧逐字比，开头相同多少个字 |
| `含上一帧` | 这一帧是不是**把上一帧包在里面**（＝ 累积式上游） |
| `被上一帧含` | 反过来（＝ 回声 / 迟到的旧帧） |
| `段` | `utterances` 有几条 |
| `定稿` | 这一帧有没有 `definite: true` |
| `起点` | 第一条分句的 `start_time`（有没有时间） |

**正文一个字符都不进日志**（项目规矩：日志只记"多少秒、多大"，不记内容）。

## 二、怎么读

* **累积式**（官方文档说的那种）⇒ `字` 一路变大、`含上一帧 是`、`共同开头 == 上一帧的字数`；
* **只给当前这一句** ⇒ `含上一帧 否`、`共同开头 很小`；
* **回声 / 迟到的旧帧** ⇒ `被上一帧含 是`；
* **上游到底给不给 `definite`** ⇒ 看 `定稿` 那一列有没有出现过"是"。
