# 41 · 特殊验证码：拿它就能建号登录

> 主人 2026-09-21：*"给我一个特殊验证码，……就可以创建账号和登录。"*
>
> 🔴 **值不写在这一份里** —— 它是**登录旁路**（知道的人就能建号、占一台盒子）。
> 按 `AGENTS.md` §六 第 1 条：**不许写进任何会显示给别人的地方**（文档、日志都算）。
> ⚠️ **这一份曾经把值写在标题、正文和判据里**（2026-09-21 … 2026-10-09），
> 而且那几版**已经在 git 历史里** ⇒ **光抹掉当前版本不等于安全**：
> **真正的处置是"换掉那个码"**（见 §五）。

## 一、怎么做的

* **码放在机器本地**：`v2/services/core/data/tenants.env` 里 `HUPO_DEV_CODE=<那个值>`
  （`restart-core.sh` 会读它；**不进仓库**）。
* 🔴 **屏上不写它** —— 这正是主人上一条指令要的（"验证码为掩码"）。
  屏上只有【获取验证码】按钮；按下去服务端如实回 `503 no-sms`（还没接短信）。
  ⇒ **码靠人告诉人**（主人告诉要用的人），**不靠页面**。
* 用**那个码** ＋ 任意合法手机号 ⇒ `POST /api/login` 建号（没见过的号就**新开一个账号**）并发令牌。

## 二、⚠️ 开这个码之前，先修了一条**安全边界**

新号在 `HUPO_TENANT_MAP` 里**没有对应租户**，而原来的代码把"没有租户"当成
`kind:'local'` —— 而 `local` 的语义是"**本机那份 = 主人那一份**"
⇒ **新用户会被当成主人那份语义**（多租户要防的第一件事）。

⇒ 改成两条：

| # | 判据 |
|---|---|
| 1 | **只有 `owner` 才是 `local`**；别的号在表里没有租户 ⇒ `{kind:'tenant', state:'preparing', unassigned:true}` ⇒ 客户端给**等待屏**（不进聊天） |
| 2 | 🔴 **宿主只服务主人**：不是主人、又没有租户 ⇒ `/api/*` 与 `/api/stream` 一律 **`503 space-not-ready`**，**不许落在宿主上被本机那个世界接着** |

## 三、实测（2026-09-21）

| # | 判据 | 读数 |
|---|---|---|
| 1 | **那个码** ＋ 新手机号 ⇒ 建号登录 | ✅ 令牌的 `sub` 是 **`u1`**（第一个新号） |
| 2 | 那个号的 `space` | ✅ `{"kind":"tenant","state":"ready","hasKey":false}` ⇒ 客户端给**填钥匙**那屏 |
| 3 | 那个号的 `/api/health` | ✅ **`seq:0`** —— **由他那台容器回答**（`u1 → hupo-a`） |
| 4 | **负向对照**：主人 | ✅ `{"kind":"local"}` · **`seq:86`**（本机那份，没被转走） |
| 5 | **负向对照**：乱码登录 | ✅ **401**（那个码不是万能的） |

⇒ **整条链通了**：新号 → 他的容器 → 他填钥匙 → 能答话。

## 四、⚠️ 两条要记住的

1. **池子只有两个**（`hupo-a`/`hupo-b`）：第 1、2 个新号各得一台；
   **第 3 个号**没有租户 ⇒ 他会停在**等待屏**（服务端如实回 `unassigned`）。
   要放更多人 ⇒ 先把池子做大（`scripts/create-tenant-pool.sh` 加用户）。
2. **接真短信通道时**：把 `HUPO_DEV_CODE` 拿掉，并给 `/api/send-code` 加**按手机号限频**。
