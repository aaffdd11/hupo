# 40 · 登录：验证码是掩码，而且要有"获取验证码"那个按钮

> 主人 2026-09-21 原话：
> *"验证码为掩码，不能写在上面。所以人们并不知道如何登录。因为找不到获取验证码的按钮。"*

## 一、🔴 它反转了一条**既有判据**（这条最要紧）

登录那一屏原来钉的是：**"临时验证码必须如实说"** —— 也就是把 `123456` **写在屏上**
（`test/widget/login_test.dart` 里那条）。当时的理由是"没有短信，不如如实说"。

**主人推翻了它。** 理由本身是对的、而且更硬：

> 写在屏上 = **谁看见谁就能进** —— 那"验证码"这三个字就变成了**摆设**。

⇒ **新的判据**（这条判据现在是**反的**，改的人别改回去）：

| # | 判据 |
|---|---|
| 1 | 🔴 **屏上不许出现那串码**（`textContaining('123456')` 必须为空） |
| 2 | 🔴 也不许用"临时码"这种说法**告诉他在哪拿** |
| 3 | ★ **必须有【获取验证码】那个按钮** —— 没有按钮 = 人们不知道该怎么登录（主人点名的就是这一条） |
| 4 | ★ 按了之后**如实说**"还没接短信"（`503 no-sms`），**码不回界面** |

⚠️ 判据 3 是**产品缺口**，不是文风：原来的屏上有"码"这个输入框，却**没有任何地方能拿到它**。

## 二、服务端 `/api/send-code`

* **公开路由**（用户还没登录）；
* 手机号形状不对 ⇒ `400 bad-phone`；
* 这台部署**没有短信通道** ⇒ `503 no-sms` + 一句人话；
* 🔴 **绝不把码回给界面**（哪怕只是"临时码"）。

⚠️ **接上真短信通道时必须同时加"按手机号的限频"** —— 不然这个公开口就是一把**免费短信的刷子**。
（现在没接通道，所以还没有限频；**这条留在这里，别忘**。）

## 三、改了哪几处

| 处 | 改了什么 |

| `test/widget/login_test.dart` | 那条判据**反转**（见上表四条） |

## 四、和"登录开关"的关系

关掉/打开手机号登录是**另一件事**（`00-PROGRESS.md` §8.5）。
这一篇只保证：**开关打开之后，用户知道去哪儿拿码**，而**码不在屏上**。
