## 二、改法（两份实现同一个顺序）

**原来**：连上 → 说 `asr/start` → **等 `asr/ready`** → 才要麦克风 → 才接音频图。

**现在**：连上 → 说 `asr/start` → 🔴 **立刻要麦克风、立刻接音频图、音频立刻往对面送**
→ 回头再看对面那个结论（失败就把麦克风收掉、如实说）。

⚠️ **为什么敢先送**：服务端那一侧**本来就会**把"握上手之前到的音频"攒住、握上手立刻补发
（`src/asr-doubao.js` 的队列 ＋ 判据 `test/asr.test.js`「连上之前推的音频不丢（先攒着，握上手就补发）」）
—— 那条路以前**没有客户端走过**，这一趟才第一次用上。

**真读数（这条路的端到端）**：`/tmp/asr-early.mjs` 照"不等 ready、连上就发"跑一遍，
6.6 秒两句音频 ⇒ 一路 `partial`（段号 0 → 1）→ `final` → `asr/end` **带着整段**，
而且**最开头那条半句仍然在里面**（脚本自己断言 `end.text.includes(第一句)` = ✅）。

⚠️ **代价如实认下**：这台要是**没配钥匙**，他会**先看到权限框、再看到"还没配好"**
（原来那一下是"先问能不能听、能听才碰麦克风"）。宁可多弹一次框，也不许弄丢开头那几个字。
